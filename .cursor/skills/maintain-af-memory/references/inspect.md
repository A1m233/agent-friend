# 查看记忆与核对来源

- **AF 会话中**：用 `recall_past_chats` 搜主题，按结果的 `session_id` 用 `read_conversation` 核对普通对话；内心活动用 `read_inner_activity`。检索结果有数量限制，缺少结果不能证明库里没有这条记忆。想查库存或实际变更，使用当前可访问的记忆面板或宿主提供的维护工具。
- **项目 Codex 或桌面维护者**：在用户指定的 AF 实例打开「记忆面板」。已启用 Inspector 的 Bridge 可用 `GET /v1/memory/semantic?kind=ordinary&limit=50&offset=0` 分页查看普通事实；`GET /v1/memory/episodic` 看经历，`GET /v1/memory/core-profile?persona_id=…` 看核心资料，`GET /v1/memory/semantic-changes` 看新增和退役成员。用目标实例实际提供的地址。使用离线快照时标明快照时间。
- 针对争议事实，记录其 ID、层、适用对象、有效状态及来源引用，回查原回合中**谁说了什么**。变更组或同一条经历可能关联多条事实，每个命题分别取证。找不到支持原命题的发言时，标为「来源待核实」；用户本轮明确给出的纠正可独立作为新证据。报告引用足以判断的最短片段。

核对发言者时也查触发来源。原始事件有 `payload.request_source.kind=scheduled_task` 时，区分用户先前设定任务和宿主本轮发起任务。AF 的 `read_conversation` 会过滤这种合成输入。只有聊天视图时，将本轮是否人工发言标为待核。

解析 `provenance` 时逐个核对引用：直接事件引用可定位原发言；旧记录若只有经历 ID，先查对应 Episodic 的 `source_ref`，再沿 `session#first..last` 核对原回合。来源列表为空时，也可查看关联变更组或独立原话。报告分别写明找到的引用、实际读到的原话，以及该原话能支持的具体命题。

## 全量检查与续查

固定用户指定实例、检查层和本次清单，记录用户明确指出的条目或场景，按接口返回的下一页位置读到末尾。按 ID 留下「保留、调整、待核」的判断及简短理由，涉及调整时再记录执行与核验状态。同一理由和处置可成组记录，保留完整 ID 对应关系。保留普通事实的理由要说明长期用途，来源或分层有疑点的条目继续查证。

分开统计已读、已完成判断、已核验修改和剩余项目。随检查保留可恢复的清单位置、上述判断、未决证据与已提交回执。上下文压缩或继续会话后，读取进度并刷新未完成项的状态，从剩余项继续。完成前将清单 ID 与判断记录对账，补查遗漏。接口只能提供抽样或部分层时，报告实际可覆盖范围和缺口。
