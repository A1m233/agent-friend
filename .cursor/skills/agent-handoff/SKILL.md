# Agent Handoff

只读整理当前需求的接力点，产出 transfer prompt 和收尾清单。交接文本需要准确描述现状；未提交、未推送、文档仍在讨论或尚未创建，都可以交接。

本 skill 不执行 commit、push、stash、checkout、worktree 删除、文档更新或创建新会话。用户另行授权这些操作时，交回各自工作流处理；交接请求本身不增加权限。

## 确认任务与状态来源

1. 从当前对话、分支和需求目录定位正在交付的需求，不能仅因仓库存在某份 `requirement.md` 就认定当前任务属于该需求。阶段 1 尚未落文档时，以已知讨论和计划路径交接。
2. 阅读个人 `feature-delivery` 的 `references/artifact-contracts.md`，由它统一决定产物状态、续传阶段和回溯规则；路径和本地化状态按项目约定解析。只读取所需契约，不执行需求流程的分支或写入步骤。
3. 读取实际存在的 requirement、design、progress，分别记录状态和接力点。缺失、状态不明或正文与对话不一致时明确标注，不能套用“全部 Confirmed”或“已经完成”的模板。

若任务对象无法唯一确定，先整理已知交接信息并指出需要辨明的对象；接收者在确定对象前不能继续对应实现。普通对话不属于本 skill 时，按用户请求产出通用交接。

## 只读收集

- 仓库根、当前 worktree 绝对路径、分支和 HEAD：使用 `git rev-parse --show-toplevel`、`git branch --show-current`、`git rev-parse HEAD` 和 `git worktree list --porcelain`；不依赖 `.claude` 等目录名称判断 worktree。
- 已暂存、未暂存和未跟踪文件：使用 `git status --short`。列明本次需求涉及的路径、其他改动及归属未明项，不替用户选择 commit 或 stash。
- 本地可见的 upstream 与 ahead/behind：使用 `git status --porcelain=v2 --branch` 等结构化输出，不匹配英文提示句。未 fetch 的结果只代表本地跟踪引用；没有 upstream 或无法确认远端最新状态时照实说明。
- 文档外信息：已确认或拒绝的方向、尚未落盘的讨论、已完成但未登记的验证、环境限制、正在运行的任务，以及下一步需要的具体证据。
- 授权：记录用户已经明确授予的动作、范围与有效边界，以及仍需授权的动作。已有授权在同一任务和范围内不因接力失效；不得把一次 LLM 调用授权扩大为后续所有调用，也不得把文档确认当作代码、发布或删除授权。

`progress.md` 缺失或进度记录落后时，把实际进度及待补记内容直接放进交接文本。它们是待办事实，不要求用户回答“是否仍要 handoff”，也不先改文档再产文本。

## 接力位置与可用性

| 接力方式 | 提示词与收尾清单需要说明 |
| --- | --- |
| 同一 worktree | 指向现有绝对路径；未提交与未跟踪内容只在该目录可见。保留 worktree，原 agent 停止写入后再让接收者继续，避免并发修改。无需先 commit 或 push。 |
| 其他 checkout 或另一台机器 | 记录源 HEAD、接收端已知路径及需要传递的未提交、未跟踪、未推送内容。尚未传递时仍产出文本，但明确接收端缺哪些输入、哪一步暂不能开始；不能声称 Git clone/pull 会带上这些本机内容。 |
| 原 agent 还会回来收尾（原模式 B） | 指明双方共用的 worktree 和恢复接力点；保留该目录。回来时重新读取实际状态，不预设对方已经 push，也不自动 pull 或覆盖。 |

用户未指定接力位置时，提示词默认指向当前 worktree 并写明该假设。是否改用其他位置是可后补信息，不阻塞产出文本。

同一分支通常不能在同一仓库的两个 worktree 同时检出；需要迁移时由后续获得授权的 Git 操作处理。不要建议为生成交接先删除现有 worktree；有未传递内容时尤其需要保留来源。

## 输出模板

按实际情况删去无关项；已知事实直接填写，未知项写明待核实。文档正文和通用规则只给路径，重点保留接收者从现有文件读不到的信息。

```text
仓库：<源仓库绝对路径>
接力位置：<当前 worktree / 接收端路径待确认；是否需要迁移>
分支与 HEAD：<实际分支或 detached HEAD、commit>
Git 状态：<已暂存 / 未暂存 / 未跟踪路径；upstream 与本地观测到的同步状态>
需求：<编号或 slug；需求目录或尚未创建的计划路径>

产物状态：
- requirement：<路径、实际状态或未创建>
- design：<路径、实际状态或未创建>
- progress：<路径、实际状态或未创建；需要补记的进度>

接力点：<按 artifact contract 恢复的阶段；先做什么>
已有授权：<用户已明确授权的动作与范围；无授权证据时照实说明>
仍待决定或授权：<仅列会影响下一步的事项>
接收端尚缺的内容：<路径或证据；迁移未完成时说明受阻步骤>

文档外必须知道的信息：
1. <已确认的偏好、拒绝的方案或未落盘讨论>
2. <已执行的动作、验证结果、正在运行的任务及所有者>
3. <环境限制、未验证项和具体下一步>

接手时读取项目规则、feature-delivery 及上述产物，按当前状态续传。
```

收尾清单只列与本次接力相关的未完成事项，例如：

- 把 transfer prompt 交给接收者，并确认接力目录。
- 原 agent 停止对交接范围写入，保留仍承载未传递内容的 worktree。
- 跨机器时，列出待用户或已授权工作流传递的内容，以及传递后的核对步骤。
- 标明由接收者继续补记的进度、未完成验证和待决定事项。

清单中的待办不等于已完成，也不授权本 skill 执行其中的写入或外部操作。
