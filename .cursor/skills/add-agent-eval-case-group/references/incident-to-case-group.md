# 从事故到 Case Group

本参考负责分析方法；它不规定具体 YAML 字段。目标是保留真实事故的因果结构，同时把复合问题拆成能稳定回归的行为契约。

## 1. 先定义证据单位

区分三类对象：

- **Incident**：一次真实发生的会话事故，保存 provenance、上下文、附件、工具事件、错误输出和运行身份。
- **Contract**：希望 Agent 长期保持的一条稳定行为约束。
- **Case**：在可控输入下检验 contract 的一次任务；同一 case 应尽量只承担一个主要判分维度。

Incident 不等于 contract。一个复合 incident 可以通过统一 `source` 分散到多个 contract；一个 contract 也可以收纳来自多个 incident 的同类 case。

## 2. 建立最小充分证据链

按时间重建：

1. 用户原始目标和事实前提。
2. 相关 user/assistant 历史消息。
3. 附件原件及元数据。
4. 历史与当前轮工具 request/result。
5. 被测轮的模型、surface、runtime 时间和系统行为版本。
6. 原始错误输出。
7. 可核验真相与哪些内容其实无法确认。

“最小”指删除无关噪音；“充分”指仍能保留导致行为变化的条件。先前 assistant 主动把对话框成“测试我是否会编”“我算及格了吗”等自我叙事，可能是后续自我评价的促成因素，不能因它不是 user 指令就自动丢弃。历史搜索结果即使为空，也可能改变下一轮是否再次搜索和如何解释图片。

若冷启动、缓存、超长上下文或压缩可能影响结果，把它们作为单独实验维度，不与主要行为契约混成同一断言。

## 3. 复合根因矩阵

对每个独立错误填一行，而不是给整个回复贴一个总标签：

| 字段 | 问题 |
| --- | --- |
| Failure | 用户实际看见的错误行为是什么？ |
| Evidence | 哪段原始输入/输出直接证明它？有哪些反证？ |
| Layer | 属于感知、证据归因、推理、工具路由、会话自我条件化、表达还是判分缺口？ |
| Trigger | 缺少它时，错误是否大概率不出现？ |
| Contributor | 它是否只提高错误概率或改变表现形式？ |
| Systemic weakness | 哪个可跨 case 复发的约束缺口允许它发生？ |
| Eval gap | 当前 case/harness/judge 为什么没有发现它？ |
| Confidence | 因果是 confirmed、probable、possible 还是 unknown？ |
| Counterfactual | 什么最小变化能区分剩余判断？ |
| Contract owner | 哪条稳定行为契约应该负责？ |

常见误区：

- OCR 正确不代表整体图片理解正确。还要区分直接可见、画面推断和图片外知识。
- 页面展示了账号/标题/播放量，不代表页面就是内容原始来源；“承载页面”和“来源”是不同语义。
- 截图在“较常见的一种说法如下”处截断，不支持补出屏外列表或后文。
- “模型为了显得专业所以……”是因果/动机故事，不是图片事实；没有证据时只能标为解释性推测。
- “你是在测试我吗”即使是问句，也可能是用户意图投射；不要因为它不是陈述句就从分析中漏掉。
- 同一输出中出现多个错误，不代表它们共享一个根因。

## 4. 用反事实而不是直觉确认原因

对每个候选原因设计最小隔离：

- 去掉先前 assistant 的自我评价，只保留用户事实与图片。
- 保留图片，移除历史空搜索；或保留空搜索，换成明确无关图片。
- 保留页面截图，但明确询问“页面信息”和“内容出处”的区别。
- 裁切到可见文本边界，测试是否补写屏外内容。
- 提供同样清晰的可见事实作为 control，确认约束没有导致普遍拒识。

多轮重复结果用于估计稳定性和发现表现簇。它不能单独证明某个 prompt、缓存或历史事件导致了错误；因果仍需对照或反事实。

## 5. 组成 Case Group

### Anchor replay

保留真实事故的关键链路、原始附件与错误轮。它回答“真实问题能否在受控环境中重现”。Anchor 可以较长，但必须说明每段历史为什么保留。

### Isolation cases

每个独立根因至少考虑一个小 case。只有在两个行为无法合理分离时才共享 judge。例：

- 图片截断后的屏外补写。
- 承载页面被断言为原始出处。
- 无证据的模型动机/因果故事。
- 对用户测试意图的主动投射。
- assistant 历史自我设定导致的“我通过了测试”叙事。

Isolation 不必机械覆盖所有标签；优先固化高影响、可稳定判断、可跨事故复用的行为。

### Controls

至少检查一种不该被约束误伤的正确行为：

- 准确复述图片中真正可见的账号、标题或数字。
- 明确标注“从截图可见”，但不提升为外部来源事实。
- 用户明确询问评测目的时，可以自然回应，而不是一律禁止谈“测试”。
- 有可靠工具证据时，可以给出来源归因。

## 6. 选择判分方式

优先级：

1. 可观察的工具调用/顺序。
2. 确定性事实锚点与明确禁项。
3. 有局部语义边界的 deterministic judge。
4. 人工 transcript 复核。

不要用过宽禁词表达抽象价值。例如全面禁止“可能”“测试”“来源”会误杀合理回答。若错误只能靠上下文语义区分，先把 case 设计得更隔离，再决定是否需要小型 judge 扩展。

每条 judge 都做三点校准：原始错误输出应失败、不同措辞的合理输出应通过、相邻 control 不应误判。

## 7. 记录剩余不确定性

清楚区分：

- 已由 fixture 固定的事实。
- 已由 deterministic test 固定的机制。
- 只在单次真实模型运行中观察到的行为。
- 需要重复运行才能估计的概率。
- 当前 harness 尚不能表达的上下文。

如果缺少重复采样能力，把推荐次数、模型、温度/缓存等条件记为验证缺口；不要把单次 pass 写成“问题已解决”。
