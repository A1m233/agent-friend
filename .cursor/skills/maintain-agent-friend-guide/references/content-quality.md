# 内容质量规范

## 面向用户

- 只写用户要完成什么、去哪里操作、需要哪些字段、何时生效和失败时怎么办。
- 不写模块、类、函数、内部服务名、环境变量名、打包路径、Git 流程或维护者指令。
- 使用当前产品界面中的中文名称；第三方专有名词保留官方写法。
- 清楚标记必须、可选、占位、暂不支持和供应商侧前置条件。

## 按能力组织

- 顶层 reference 按模型、搜索、地点、天气、语音等用户任务类型划分。
- 供应商在对应能力页中陈列；新增同类供应商时扩展原页面。
- 只有出现新的用户任务类型时才新增顶层 reference。
- 不在多个 reference 重复完整申请流程；跨主题用相对路径指向唯一事实来源。

## 凭据页面模板

每种能力至少覆盖：

1. 能力用途与是否可选；
2. agent-friend 需要的字段；
3. 官方控制台或文档链接；
4. 最短申请步骤；
5. agent-friend 中的配置位置；
6. 保存后如何生效；
7. 缺失或错误时的降级/错误表现；
8. secret 安全提醒。

不要承诺第三方价格、免费额度、审核时间或页面层级长期不变。

## Secret 与隐私

- 文档、命令示例、截图和测试中不得出现真实 Key、Token、Cookie、迁移码或用户私人数据。
- 不要求用户把 Key 发到聊天；统一引导到产品凭据设置。
- 诊断包说明必须提示：普通隐私内容不会被完全自动清除，附件和渲染截图需要额外谨慎。

## 发布前语义检查

- 每个结论都能落到当前产品用户可见证据或供应商官方来源。
- 当前实现没有的能力不能写成已支持。
- `SKILL.md` 只保留路由和回答边界，详细事实放 reference。
- `getting-started.md` 保持非空占位，且首期不进入普通问题路由。
