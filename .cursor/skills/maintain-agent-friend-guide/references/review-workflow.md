# 只读复核流程

## 1. 建立目标状态

1. 从公开 `metadata/source.json` 读取 `reviewed_product_commit`。
2. 读取当前产品 `HEAD`、tracked diff 和 untracked 文件摘要。
3. clean 时目标是 `HEAD`；dirty 时目标是只读 overlay，结论必须标注“预览”。
4. baseline 缺失、不可达或不是目标祖先时，不自行选择“最近提交”。

## 2. 阅读真实变化

从 baseline 到目标阅读 diff，并在需要时沿调用方、测试和用户界面继续核对：

- 能力、限制或状态是否变化；
- 用户操作路径或可见文案是否变化；
- 设置字段、必需性、生效和降级是否变化；
- provider、凭据申请或错误表现是否变化；
- 数据存储、删除、迁移、诊断或隐私边界是否变化；
- 安装和兼容边界是否影响用户求助答案。

路径关键词只能帮助找入口，不能代替语义判断。

## 3. 与公开知识比对

- 逐项对照 `reference-map.md`。
- 无用户影响的重构、测试整理、格式变化或等价替换可判“无需更新”。
- 有用户影响时，写明变化前后事实、影响 reference 和建议文案范围。
- 证据冲突或不足时结论为“无法判断”，列出需要的额外证据。

## 输出格式

```text
目标状态：<commit；dirty 时说明 overlay>
公开基线：<reviewed_product_commit>
结论：需要更新 | 无需更新 | 无法判断
关键证据：
- <用户可见事实与代码/界面入口>
受影响 reference：
- <path + 拟改事实；无则写“无”>
未决项：<无或具体缺口>
```

`manual` 模式检查完成后暂停，只有用户明确同意执行更新才能开始写文件。
`merge-main-and-push` 模式在“需要更新”时直接继续，在“无需更新”时返回交付流程，在“无法判断”时停止并报告。
