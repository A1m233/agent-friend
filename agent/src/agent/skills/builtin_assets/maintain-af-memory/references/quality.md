# 记忆质量判据与案例

对每条普通 Semantic，分别判断来源是否支持、是否具有跨会话长期价值、应放哪一层，以及当前是否仍有效。拟保留或替换的正文要能说明今后会在什么场景帮助理解用户或处理任务。仅能帮助回顾或恢复某次执行的内容，按具体事件、任务状态或执行记录处理。

修正主语、补上日期或改成「助手当时报告」会改善来源与时效表述，长期价值仍需独立判断。原记录和拟替代正文使用同一准入标准。

| 判断 | 值得保留的记忆 | 值得复查的记忆 |
| --- | --- | --- |
| 来源与归属 | 用户直接表达或确认的要求；助手自己的动作、承诺注明主体 | 助手对性格的评价被记成用户自述；一次复述刷新了旧事实 |
| 适用范围与期限 | 规则写清在什么场景、遇到什么条件、应该怎么做 | 把一次放行、一次命名或单次任务的限时要求推广成长期偏好 |
| 放在哪一层 | Core 放符合宿主字段的当前身份或关系；普通 Semantic 放跨会话仍有用的事实和约定；Episodic 放值得回顾的具体事件 | 把本次血量、资源数量、步骤或完成回执长期保存；同一事件的账号明细和汇总反复陈述同一结果 |
| 状态与重复 | 新安排取代旧安排时能追溯变化；保留不同账号、时间或适用范围的差异 | 过期状态仍作为当前待办，或同一事实换几种措辞重复生效。文字相似只用于找候选，合并前核对事实和范围 |

旧记录说「上次读错血量」，这次用户说「这个游戏里读数与血条冲突时先核对」。前者是经历，后者是可复用规则。恢复某次任务才需要的读数留给存档或任务记录，当天日常完成后可以结束旧的暂缓状态，单纯完成任务不产生新的长期偏好。账号明细和汇总分别判断，一次结算中不同账号的资源数均属于当次执行信息。

当前上下文已有的 Core 信息可能与普通事实重复，而普通事实还包含另一个账号的消歧信息。按命题标明重复部分和独有部分，保留有依据的区别。分层判断用于决定普通 Semantic 的保留与调整，不因此读取 Episodic 或扩展到其他层的维护。

个人经历、健康史、身份消歧等具体事实也可能有长期价值，按实际用途判断。缺少来源时保留待核结论，不能仅凭缺证认定事实错误。
