# 使用 agent-friend

## 读取网页和平台链接

- 可以直接把公开网页或 PDF 链接交给 Echo，说明要核对的问题。支持直接链接读取的版本也可以继续打开其它工具找到的链接，不必先重复搜索登记来源。
- 小红书或 Bilibili 的受支持链接可交给平台读取能力处理。是否需要登录、内容令牌，或能否取得正文、字幕，仍取决于平台和当前可用能力。
- 网页打不开、只得到摘要或正文为空，不表示已经读过全文。静态网页读取不能代替登录、验证码或需要动态交互的浏览器操作。
- 旧版本若提示链接不在已有来源中，可以先将准确链接直接发到当前对话；持续出现时更新产品。使用指南更新不会自动升级网页读取能力。

## 让 Echo 查看本地图片

以下适用于已提供“读取图片”能力的版本。统一会话文件附件也通过按需读取来查看上传图片；上传文件本身不证明模型已看过图片。

- 告诉 Echo 图片的位置和要观察的问题，例如“看看这张本地流程图哪里不清楚”。出现本地文件授权卡片时，核对文件范围及“读取图片”权限后再决定是否允许。读取文本的授权不包含读取图片。
- 对于已上传到当前会话的图片，Echo 可以直接按该上传来源读取，无需授予外部文件夹访问权限。
- 当前可用模型及自定义连接条件见[模型与凭据](model-credentials.md#本地图片读取的模型支持)。图片由当前会话模型查看，不会自动调用另一个视觉模型。
- 本地读取支持静态 PNG、JPEG、WebP；每张最多 8 MiB、1600 万像素、单边最多 8192 像素，每次读取一张。动画、损坏图片、远程图片链接和桌面截图不属于这项能力。
- 对话较长时，早先图片可能暂时移出当前模型上下文。可以让 Echo 恢复之前读过的图片继续观察；有保存的快照时不必重新读取已变化的原文件。快照不可用或当前模型不支持时，需要补充有效图片或切换兼容模型。
- 本地读取的限制与在输入框添加附件的限制不同；图片发送及保存方式见[数据与隐私](data-and-privacy.md#本地图片读取)。

## 主窗口与系统托盘

- agent-friend 的主窗口左侧包含全局搜索、新对话、IM 接入、设置和历史会话；提供任务管理的版本还包含“定时任务”。右侧显示当前选择的对话或功能页面，切换页面后原会话仍会保留，重新选择会话即可继续。
- “新对话”会真正开始一段新会话；从托盘选择“新对话”也使用相同语义。
- 托盘右键菜单可打开 agent-friend、新建对话、进入 IM 接入、设置或帮助与反馈，也可以显示或隐藏桌宠以及退出应用。
- 双击托盘图标与选择“打开 agent-friend”一致：打开主窗口并回到最近使用的有效会话；没有可恢复会话时显示新对话首页。
- 托盘中的桌宠动作会根据当前状态显示为“隐藏桌宠”或“显示桌宠”。

## 对话与会话

- 提供拒绝提示的版本中，模型拒绝回答时会保留拒绝说明，并显示“模型拒绝了这次请求”。这不代表网络故障，也不代表请求的任务已经完成；重新打开历史会话仍可查看保存的说明。
- 提供回答来源的版本中，模型返回的网页来源会在对应消息下显示链接。支持文件链接菜单的版本也能定位具有可靠本地地址的来源；只有文件名或远端标识、没有可定位地址的文件引用，以及无法安全打开的来源仍显示“当前无法打开”，不表示文件已经下载到本机。QQ 等文本入口可能显示来源说明；语音只朗读回答正文。旧消息没有保存来源时无法补回，更新指南本身不会改变已安装版本的显示能力。

- 提供会话内存治理的版本会释放闲置会话暂时占用的运行内存，历史消息仍保存在本机。当前打开、正在加载、排队或执行任务、等待授权及仍有工具活动的会话会受到保护，不计入闲置会话的回收预算。重新打开已释放的会话时可能需要恢复数据；释放内存不等于删除会话，也不保证每次发送消息都能立即开始模型请求。

- 提供“执行过程”折叠的较新版本中，任务运行期间保持展开，用时行不提供折叠按钮；正常结束后，可识别的执行过程自动收起，再允许手动展开。失败或中断时默认保持展开，可手动收起执行过程，末尾回复和错误提示仍保留。搜索或引用定位会临时展开命中的过程内容，定位高亮结束后恢复原来的折叠状态，不会永久改变手动选择。较早版本可能仍允许在运行中折叠，或在定位后保持展开；使用指南更新不会自动改变已安装版本的交互。

- 任务中断后，提供“继续任务”的版本可以从已有结果继续剩余工作；正在重试时无需重复发送。不同版本的恢复入口和限制见[模型请求失败](troubleshooting.md#模型请求失败)。

- Echo 在不同会话、语音、QQ、提醒和人格编辑中保持同一朋友身份。开始新会话不代表换了另一个 Echo，也不代表它能自动知道全部历史细节；缺少可用记录时仍需确认。
- 回复期间可以先编辑下一条草稿、添加或移除附件及使用语音输入；当前任务完成前仍不能再次发送，按回车可在草稿中换行。模型与思考强度选择在当前较新界面的执行期间暂不可用，等本轮结束后再调整；部分较早版本允许预选下一轮配置，以实际界面为准。

- 在对话页输入内容并发送。准备和生成过程中都可以停止当前回复。较新版本会区分这条输入是否已经被接收：接收前停止或准备失败时，输入会回到草稿，并保留你后来补写的内容；已经接收的输入仍保留在会话里。较早版本可能仍保留发送时显示的消息；重试前先检查会话和草稿，避免重复发送。停止时也会保留已经生成的内容；提供用时行的界面会在该行显示“xx 后被停止”，缺少可靠用时时显示“已停止，用时未知”。较早界面可能仍显示独立的“已停止回答”提示。刷新或重新打开会话后，已保存的停止状态仍会保留。
- 侧栏会区分正在运行和等待处理的会话。切换到其它会话不会停止后台任务；重新打开原会话时，输入区、侧栏和当前活动会恢复到同一状态，后续内容仍会进入原会话。
- 只要整轮任务仍在等待、运行或取消，属于这一轮的 Echo 消息底部不会显示完成时间戳、复制等完成操作；这与运行中实时增长的用时不同。某条消息、工具或本地命令已经结束，只代表当前步骤完成；Echo 仍可能继续调用其它工具或整理最终回复。同一会话会集中突出一个当前主要活动：优先处理文件或命令授权，其次是平台登录请求、运行中命令，再展示整理较长对话、普通工具或模型处理状态；其它活动仍作为记录保留，可按需查看详情。
- 停止请求已被接受、但任务还在清理时，页面会显示“正在取消当前任务，任务尚未结束…”，并在真正结束前阻止再次发送。如果当前会话正由语音、QQ 或其它入口处理，桌面输入区会提示从原入口处理或等待完成，并且不会显示无效的桌面停止按钮。
- 可以选中一条已完成的自己或 Echo 消息中的连续正文，然后选择“引用”。同一草稿可按顺序加入多条引用，输入区会把它们收在“几个已选文本”的入口中；打开入口可以查看原文、辨认来源并逐条移除。支持点击定位的较新版本中，点击输入区的引用条目会收起浮层、跳回来源消息，并使用与搜索定位相同的高亮效果标出准确片段；引用仍保留在草稿中。较早版本的草稿引用可能只能预览和移除。工具活动、提醒卡片和附件本体不属于可引用正文。
- 引用本身就是有效输入，正文为空时也可以发送。提供引用后自动聚焦的版本中，点击“引用”后输入框会获得焦点；当前可发送时，可以直接按 Enter 发出引用，也可以先补充文字。发送后，引用原文和来源关系会随消息一起保存；重新打开会话仍可查看。点击历史消息中的引用会尝试回到来源并高亮准确片段；来源不可定位时仍保留当时的引用快照，不会跳到未经确认的相似文字。
- 在产品已接入的 QQ 单聊中，QQ 客户端原生的单条整消息引用也会进入同一套会话上下文。QQ 引用不等同于桌面端的多引用或精确片段选择；平台没有提供原文且产品也无法从已有消息恢复时，会明确保留“引用原文不可用”的状态。
- 在第一段回复内容出现前，页面会显示当前准备状态：通常先显示“正在准备回答…”，模型连接重试、推理或处理时会切换为对应说明。已经有文字或工具结果时，后续模型等待提示出现在内容下方，不固定占据顶部用时行；任务结束后不留下旧加载提示。准备时间较长或一段时间没有新活动时，提示会明确说明模型可能仍在处理，也可能已经停滞；这不是已经失败的结论，可以继续等待或停止当前回复。
- 较新版本中，模型连接中断、凭据错误，以及任务失败、过期或未执行等系统提示会用独立圆角卡片显示，与 Echo 的回复正文区分。已返回的正文仍会保留；卡片提供“打开凭据设置”或“继续整理”等操作时，可按具体提示处理。不同错误的处理方法见[常见排查](troubleshooting.md)。
- 长会话需要整理上下文时，对话页会显示“正在整理较长对话…”；成功后保留一条“已整理较长对话”记录，刷新或重新打开会话后仍可见。该记录只说明已完成整理，不展示摘要正文、精确 token 或进度百分比。
- 支持任务中途整理的版本可以在同一个长任务内整理上下文后继续，不要求人为发送新消息划分轮次。整理失败时原历史和已完成结果仍保留；出现“压缩后继续”后可在原会话尝试恢复。进行中无需重复点击，主动停止不会自动重启任务。结果未知或仍在运行的外部动作应先核实，不能因为整理过上下文就重复执行。
- 通过 QQ 对话时，整理状态只作为同一条流式消息的临时进度；回复正文开始后会立即替换它，不另留一条完成提示。
- 需要修改当前会话最后一条可编辑的用户消息时，点击消息旁的编辑按钮。原消息仍保持只读，文字和附件会回填到底部输入框，输入框上方会提示正在编辑哪条消息。
- 编辑时可以继续调整附件、切换模型或使用语音输入。关闭编辑状态会恢复进入编辑前的普通草稿；提交后，修改后的消息会成为当前版本，并重新生成其后的回复。
- 新建对话草稿时会采用设置页当时保存的默认模型和最新已应用的人格；草稿一旦建立，之后修改默认模型不会偷偷改变这个草稿。
- 历史会话可继续、重命名、归档或删除；归档会话可在“设置 → 已归档对话”中恢复。
- 长会话先显示最近部分；向上滚动接近顶部时会自动加载更早的消息，并保留当前阅读位置。加载失败时可点击重试，全部加载后显示“已到最早的消息”。较早版本可能仍需点击“加载更早的消息”按钮；暂未显示的消息不代表被删除。
- Bridge、应用或电脑重启后，历史会话会恢复已经完整采用的模型上下文和该会话自己的模型选择，再从同一段对话继续。若退出发生在回复或工具处理中，不会为了“接着跑”自动重复执行原工具；本地命令在中断前已经保存的部分输出会作为“不完整、结果未知”的执行证据交给 Echo，供它判断下一步。
- 全局搜索用于查找不同会话中的内容，并可跳转到命中的会话位置。点击侧栏“搜索全部对话”即可打开；显示新快捷键的版本可用 Windows 的 Ctrl+Shift+F 或 macOS 的 Command+Shift+F。较早版本可能使用 Ctrl+F 或 Command+F，以入口旁的提示为准；指南更新不会改变已安装版本的快捷键。新快捷键版本不再用 Ctrl+F 打开全局搜索，这不代表已经提供会话内搜索。
- 删除与“清空全部归档”是永久操作，确认前先检查目标范围。

## 打开消息中的文件链接

以下适用于已提供文件链接菜单的桌面版本；指南更新本身不会为旧版增加此能力。

- 对已显示为可点击链接的本地文件，左键会打开所在文件夹，并在系统支持时选中文件；右键可选择“打开所在文件夹”或“复制完整路径”。目录链接会打开目录自身。定位文件不等于用默认程序打开、执行或编辑该文件。
- 聊天正文、展开后的执行过程、可识别的回答来源，以及设置中的人格正文和候选预览使用相同操作。支持常见文件路径和文件地址；相对路径需要对应内容的可靠目录，无法确定时会提示原因。
- 消息附件和输入区已上传附件可通过右键定位应用保存的文件副本，位置可能与上传前的原文件不同。图片左键仍保留图片预览。
- 链接文字与地址不一致时，以实际链接地址为准。普通路径文字、行内代码和代码块不会自动变成链接；只有文件名、没有可用位置的远端来源不会被当成本地文件打开。
- 文件链接获得键盘焦点后，可用 Shift+F10 打开菜单。网页等外部链接保持相应打开方式；无法打开时，按[文件链接排查](troubleshooting.md#文件链接打不开或找不到文件)处理。

## 执行过程与用时

以下说明适用于已提供用时行的对话界面；较早版本没有该入口时，以当前界面为准。

- 刚发送或仍在排队时只显示等待提示，不显示计时行。实际开始后，顶部显示“已进行 xx”；结束后用时固定，成功完成显示“用时 xx”，停止后显示“xx 后被停止”。计时包含模型、工具、重试和等待授权的时间，不包含开始前排队；发出停止请求但尚未真正结束时仍继续计时。
- 用时依据这轮已保存的实际运行时间。切换会话、切换模型或重新打开后，不会重新从零累计。旧记录或异常中断缺少可靠时间时明确显示“用时未知”，不会用零秒或停机期间的时间补齐。
- 用时旁出现箭头时，可以点击展开或收起这轮执行过程。运行时默认展开；只有本轮成功完成且有可保留在外的收尾正文时，才默认收起过程。你在当前界面中手动选择的展开或收起状态会保留；刷新后重新按这轮记录决定默认状态。
- 最终回答、无法可靠归类为执行过程的文字和需要处理的授权等内容不会因过程折叠而消失。失败、停止或缺少可靠收尾正文时不会自动收起；手动收起后，仍在进行的等待或取消提示也保持可见。
- 是否可折叠取决于这轮自身的记录，切换当前模型不会重新解释之前的回复。较新界面中，即使模型没有明确区分过程与最终回答，只要这轮已可靠地成功结束、消息记录完整，也可以保留最后一条回答，收起此前的文字和普通工具过程。失败、停止、记录冲突或末尾仍有工具时保持展开。没有可收起的过程，或旧会话缺少必要记录时，用时旁不会出现箭头。
- 提供统一折叠行为的较新版本中，内置模型和自定义连接使用相同规则。模型只区分了部分过程文字、没有明确标出最终回答时，正常结束后也可以收起普通工具和已识别的过程，最后一条正文仍显示在外；无法可靠归类的文字继续可见。较早版本在这种情况下可能保持展开，仅支持 Responses 协议并不保证会自动折叠。
- 搜索或点击引用命中收起的过程文字时，会先展开再定位；展开后的文字仍可选择引用。整条消息复制仍包含原来可复制的完整内容，不会因视觉收起而只复制最终回答。
- 执行过程折叠只改变桌面对话展示，不把 QQ、语音或长期记忆统一改成只接收最终回答。

## 模型与附件

- 在对话输入区打开显示“当前模型 · 当前推理强度”的入口。将指针移到“模型”或“推理强度”上，右侧会展开对应选项；选择后菜单会保持打开，便于连续比较和调整。点击菜单外部、再次点击入口或按 Escape 可关闭。
- 模型与推理强度按当前会话保存，切换成功后从下一条回复开始生效，不会修改设置页中的默认模型。设置页中的“默认对话模型”只决定之后新建对话草稿的初始模型；保存它不会重启服务，也不会改变当前会话或已经打开的草稿。
- 提供通知位置调整的版本中，切换成功后直接查看输入区的模型与推理强度，不再弹出成功通知；失败仍会提示。公共浮动通知显示在窗口顶部中央，较早版本可能仍在右下角。
- 切换模型时，推理强度会改为目标模型的产品默认值；当前版本不会跨会话记住某个模型上次使用的档位。正在生成回复或提交配置时，需要等待当前操作结束再调整。
- 内置模型显示产品已接入的推理选项。固定开启的模型会显示“固定开启”，不支持调节时会显示对应只读状态。自定义连接的档位是建议值，具体支持情况由服务决定，详见[模型凭据](model-credentials.md#推理强度)。
- 通过 QQ 对话时，每轮回复后的“菜单”也会显示当前模型和推理强度。第一排可切换模型或调整推理强度，第二排用于切换会话；QQ 与桌面端修改的是同一份会话配置。
- 提供自定义模型菜单的较新版本中，QQ 模型列表也包含桌面端保存的自定义连接，以“连接名 · 模型名”区分；再次打开菜单会读取最新配置。自定义推理强度可选择“服务默认”或建议值；其它值请在桌面端填写，QQ 菜单会显示当前设置。
- 自定义连接或模型被删除后，QQ 提示模型已不可用；旧菜单中的选择不会生效，请重新打开菜单选择其它模型。较早版本可能不列出自定义模型，或显示一长串内部编号；可先在桌面端切换，并更新到提供此修复的版本。
- 提供统一会话文件附件的版本中，通过 QQ 发送普通文件附件时，产品会按 3 秒到达静默收集附件：相邻附件在 3 秒内到达就继续并入同一批，因此一次选择的多张图片即使被 QQ 拆成多条事件，通常仍只形成一轮，且整批不设固定总等待上限。第一条纯文字若在批次仍开放时到达，会与全部附件一起交给 Echo；连续 3 秒没有新附件或配文后，附件批次单独成轮。QQ 没有提供可用的一次发送批次号，所以两次独立附件发送若间隔也不到 3 秒，仍可能被合并；GIF 等普通文件也参与等待，语音继续使用独立处理流程；旧版本可能只合并部分格式。
- 模型按调用渠道分组展示。尚未配置对应凭据的模型仍然可见，但不会切换成功；根据提示可以直接前往对应凭据组。
- 当前开放 DeepSeek 与 Kimi 模型；OpenRouter 暂不维护，模型选择和凭据入口已隐藏。模型列表与推理档位见[模型凭据](model-credentials.md)。
- 提供统一会话文件附件的版本允许添加任意类型的文件，包括文本、图片、PDF、Office 文件、压缩包、GIF 和未知格式。文件能保存不代表已有工具能解析；上传脚本或程序也不表示允许自动执行。
- 发送后，附件会自动准备到当前会话工作目录。Echo 先收到文件来源、名称和读取位置，按任务读取正文或图片；不会因为发送消息就自动把整份文件内容交给模型。无需在新附件发送后额外要求先列出或准备文件。
- 单轮最多 10 个附件，单文件最多 100 MiB，总计最多 100 MiB；工作目录还受容量限制。接收文件需要可用的本地文件处理能力及模型工具调用能力，与模型能否看图分开判断。
- 文件上传成功后可以只发送附件，也可以补充文字。上传中、上传失败或文件处理不可用时，先按提示处理；移除所有附件且没有文字或引用时，发送按钮会禁用。
- 切换模型不再按原生图片或文档格式要求移除附件。新模型仍须具备工具调用能力；需要看图时，另按[图片读取支持条件](model-credentials.md#本地图片读取的模型支持)判断。
- 较早版本可能仍限制文件类型、自动发送图片或 TXT 正文，或仅对 PDF 提供按需读取。以实际界面为准；更新指南不会自动升级这些能力。

### 在后续对话中继续读取上传的文件

统一会话文件附件对所有类型都采用按需读取；较早提供此能力的版本可能仅适用于 PDF。处理 PDF 时，Echo 按任务读取需要的页或片段，不会自动发送整份 PDF 或抽取全文。可以明确指定页码；处理整份文档时，请让 Echo 说明已覆盖范围。扫描页、布局和图表需要当前模型支持本地看图；只能取得文字时不能视为已经理解图像。缺少视觉能力时可切换支持的模型，不会自动转交另一个模型或改为整份发送。实际读取结果仍占用模型上下文，大文件不代表全文已读完。

以下适用于已提供会话文件能力的版本；指南更新不会自动为旧版增加此能力。

- 可以在原会话中说“继续读取之前上传的 PDF”或“列出这个会话上传的文件”。即使较长对话已整理上下文，或应用已重启，仍可从当前会话保留的上传记录重新找到文件。
- Echo 会核对上传来源和文件完整性，再把需要处理的旧文件准备到当前会话的工作目录；统一会话文件附件会在发送新附件时自动完成准备。同名附件会分别保留；其它会话上传的文件不会混入这份列表。
- 工作目录中的输入文件是只读副本。需要修改、转换或提取内容时，应另存处理结果。大文件可按问题分段读取，不会仅为了保留访问能力而每轮自动重新发送整份文件。
- 准备文件受工作目录容量限制：单文件最多 100 MiB，目录总量最多 1 GiB、最多 2,000 个文件。它们是写入前检查，并非命令运行期间的实时磁盘配额，也不替代模型或上传入口的限制。
- 本地保存的附件原件缺失或校验失败时，需要重新上传或恢复原件；不能把下载、文档等目录中的同名文件直接当作原附件。具体处理见[常见排查](troubleshooting.md#之前上传的文件无法继续读取)。

### 自定义模型与附件

提供统一会话文件附件的版本不再要求自定义连接声明“图片输入”或“文档输入”，旧连接可以继续使用。文件接收与工具按需看图分开判断；远端模型是否真正支持图片仍以服务的实际响应为准。较早版本若仍显示两个开关，应遵循该版本界面。详细说明见[模型凭据](model-credentials.md#自定义连接byok)。

## 长期记忆

- 可以直接告诉 Echo 希望它长期记住的稳定信息，例如希望被怎样称呼、当前住处，或彼此当前的关系。此类信息会作为核心身份资料参与后续交流。
- 其他对未来有帮助的事实会作为普通长期记忆，在与当前问题相关时参与回答；不保证每条信息都永久保存或每次都被召回。
- 当前信息发生变化时，明确说明新的现状和需要更正的内容。Echo 会尝试用新事实替换旧的当前事实，同时保留必要的历史线索。
- 核心身份资料会谨慎更新；表达含糊、只是临时状态，或说的是第三方时，不应把它当作你的当前身份资料。
- 提供故障期记忆保护的版本中，失败轮次的素材会先保存在本机，等待后续正常交流分批处理；持续失败时会继续等待。仅重启、关闭应用或空闲等待不会主动补发积压，因此失败后新说的信息可能暂时还没有成为可召回的长期记忆。不会因为前台切换了模型就自动更换记忆使用的模型。

- 提供记忆等待调整的版本中，后台提取和整理记忆的每一步可以等待完整模型结果最多 10 分钟；这不是整段记忆处理的总时限，也不保证在此时间内一定更新成功。普通对话的等待规则不因此改变。持续未更新时，见[记忆没有更新](troubleshooting.md#记忆没有更新)。

## 人格

1. 打开“设置 → 人格”。
2. 用自然语言描述希望修改的性格、表达方式或相处习惯。
3. 查看候选结果与变更差异。
4. 确认后应用；不满意可以继续讨论、撤销最近变更或重置。

人格变更从后续新一轮交流开始生效，不会重写历史消息。

“设置 → 人格”中的“沉浸式交流”默认开启。关闭后，Echo 在身份、上下文压缩、过去对话来源或外部资料来源与当前问题相关时会坦诚说明；切换从下一轮交流开始生效。详细边界见 `settings-reference.md`。

## 待办与提醒

- 可以直接请 Echo 创建、查看、更新、完成、取消或重新打开待办，也可以为待办设置提醒。
- 创建提醒只会安排未来的到期时间；到期后，提醒卡片和 Echo 的补充回复会一起保存在一段对应会话中，稍后重新打开仍可查看。
- 如果 QQ 已绑定一个或多个会话，提醒到期时只在这些有效绑定对应的会话中，选择最近收到用户消息的一段；这条消息可以从桌面对话或 QQ 发出。未绑定 QQ 的其它会话不会因此成为提醒归属。没有有效绑定时，提醒保存在创建提醒时所在的会话，也不会向其它绑定广播。
- 提供“通知”设置的版本在“设置 → 通知 → 待办提醒”调整“提醒发送方式”；较早版本仍可能位于“通用”。它只控制是否额外通过 QQ 和桌宠提醒，不会关闭对应会话中的历史。QQ 暂时离线也不会改变提醒历史归属，只会影响 QQ 是否实际收到消息。
- 同一请求需要完成、取消或重新打开多个待办时，可以一次说明全部目标；Echo 会逐项执行并保留每一项的结果。
- 如果部分待办已被其他操作更新，成功项会保留，失败项会单独说明；根据最新列表确认后再重试失败项。

## 定时任务

以下适用于提供“定时任务”页面和固定目标会话的版本。较早版本可能只有对话管理入口，并为每次执行创建独立对话；更新指南不会自动升级应用。

- 从主窗口左侧或桌宠操作栏的时钟按钮打开“定时任务”。可以新建、查看、编辑、暂停、恢复、删除或立即运行任务；操作图标悬停后会显示说明。列表和运行历史向下滚动会继续加载。
- 新建时填写任务名称和发送内容，可添加附件，选择“执行一次”“每天”“工作日”或“每周”及相应时间。时区自动采用本机设置，可在下次执行预览中核对；当前表单不提供每月和固定小时间隔的新建选项。
- 目标可以选择已有会话，也可以新建并填写会话名称。新会话只在创建任务时建立一次，之后每次都向这个固定会话发送请求，沿用其中的上下文；可以在普通历史列表查看并继续交流。
- “更多设置”中可调整模型、思考强度、访问权限及可选 Skill。未单独调整的模型和权限跟随目标会话；单独选择只影响任务请求，不改变会话自身配置。调整思考强度时会同时固定当前所选模型。
- 同一会话中的请求依次处理，前一轮未结束时，定时请求可能等待。普通聊天暂不提供手动发送入队交互。同一个定时任务不会同时运行两次；前一次仍在进行或等待批准时，新计划点会被跳过，原因保留在运行历史中。
- 定时发送的用户消息上方显示任务来源，点击任务名称可打开详情；运行历史中的“查看消息”可定位对应消息。已经删除的任务仍可从历史来源查看保留的只读信息，删除不撤销过去产生的外部结果。
- 归档目标会话会暂停任务，恢复会话不会自动恢复任务，需要显式恢复。目标已删除或旧任务没有有效目标时，应先处理目标配置，任务不会自行换一个会话执行。
- 应用完全退出或电脑休眠期间不会执行任务。恢复后只会考虑过去 7 天内最近一个错过的计划点，并且最多补运行一次；更早的计划不会逐个补跑。应用关闭前已进入等待或执行的请求会标记为中断，不会自动重放。
- 任务绑定的 Skill 在运行时仍需可用；已删除、来源冲突或不可读取时，本次运行会失败，不会偷偷换用同名内容。定时任务不继承以前的一次性批准，按本轮实际访问权限处理文件与命令授权。
- 仍可请 Echo 管理任务并查询历史；以已保存的任务配置和运行记录为准，不要把口头答应当成已经创建。

## 桌宠

- 在“设置 → 桌宠”选择角色模型并调整显示比例。
- 常规比例和迷你状态比例可分别设置。
- 支持导入符合界面要求的 Spine 3.8 模型文件夹；导入前保留原始模型备份。需要从 Ark-Models 选择并安装明日方舟基建小人时，参照[明日方舟 Spine 桌宠模型安装指南](arknights-avatar-models.md)。
- Windows 用户可以按需开启“显示器恢复保护”；它默认关闭，开启后会在息屏恢复期间暂时隐藏桌宠并检查画面是否安全。

### 桌宠通知与操作栏

以下适用于提供“通知”设置的版本；旧版本缺少相应入口时，可更新 agent-friend。

- 会话有新回复、需要授权处理、异常结束或待办到期时，可以通过桌宠气泡报信。会话和待办通知会单独显示来源名称；气泡用于提示状态，完整回复和任务结果仍在对应会话中，是否提示由[通知设置](settings-reference.md#通知)控制。
- 点击“查看”回到对应会话；较新版本会在打开成功后自动关闭该气泡，打开失败则保留，方便重试。较早版本可能仍需手动关闭。较长正文可以“展开”，展开不会关闭气泡。关闭按钮只关闭该气泡，不会停止任务或删除会话历史。
- 多条通知会排队，关闭一条后，后续通知可以补位。关闭操作带来的补位不会播放提示音，其他新通知仍按声音设置处理；同一条通知重新显示也不会重复响铃。
- 提供故障期负载保护的版本中，任务失败通知直接使用本地状态文案，不再为了润色这条失败通知额外调用模型；其它需要生成文字的通知仍可能产生模型用量。
- 操作栏通常在桌宠上方，气泡在操作栏外侧。靠近屏幕边缘时，两者会随可用空间换到下方或侧边，操作栏也可能变为竖排。
- 操作栏按钮较多时，可以使用“上一页”“下一页”或把鼠标放在操作栏上滚动翻页；横向或纵向滚动都可用，首末页不循环。停留页会保存，操作栏再次出现或应用重启后可以恢复。

## 语音

- 点击输入区的麦克风开始语音输入，识别结果会写入当前草稿，仍可编辑后再发送。
- 提供混合输入修复的版本中，麦克风开启时也可以改字、删除或清空草稿，后续语音会保留这些修改。需要在中间补写时，先把光标移到目标位置再继续说话；中文输入法选词期间，新的识别内容会等到选词结束后写入。
- 如果出现“语音续写无法对齐”的提示，先检查保留的草稿，再重新点击麦克风，补说尚未写入的内容。较早版本若在改字后重复插入旧文字，可先停止语音输入再修改，然后重新开启语音输入。
- 语音通话是独立的连续通话能力，首次使用会说明麦克风与公网连接需求。
- 只在用户主动使用语音功能时申请或使用麦克风权限。
- 配置方法见 `voice-credentials.md`。

## Skill

- 在 Skill 管理入口查看内置、agent-friend 个人和共享个人 Skill。普通会话不扫描当前文件夹或代码仓库中的项目级 Skill。
- 提供内置 `pdf` 和 `screenshot` 的较新 Windows 版本中，可以让 Echo 创建、读取和检查 PDF，或按你的要求截图。相关文件访问与脚本执行仍须经过正常授权；截图后是否能由模型看图，另受[本地图片读取](#让-echo-查看本地图片)的模型支持条件限制。
- 这些 Windows 安装版自带 PDF 所需的 Python 基础依赖、PDF 渲染工具和 PowerShell 7，无需先安装 Codex 或这些系统工具；基础能力可离线使用，额外依赖和联网任务仍可能需要网络。旧版本若没有这些内置 Skill，应先更新 agent-friend，不能仅凭使用指南已更新就认为程序具备新能力。
- 内置的 agent-friend 使用指南由产品方维护，与用户自行安装的 GitHub Skill 更新方式不同。桌面端联网时会低频检查受信更新；完整 Guide 通过验证后从后续新一轮开始使用，同一轮不会中途切换。离线或更新失败时继续使用安装包内版本或最近一次有效版本。更新包中的脚本不会因为下载或切换而自动运行；实际运行仍需经过正常授权。
- 安装第三方 Skill 前先确认来源可信；Skill 可能包含会影响 agent 行为的说明或脚本。
- 可以把 GitHub 仓库或其中的 Skill 目录地址交给 Echo，请它安装到 agent-friend 的个人 Skill。安装会经过本地文件和联网授权，不会覆盖同名的已有目录；catalog 刷新后，新 Skill 通常从下一轮开始可用。
- 已经由 agent-friend 安装并记录来源的 GitHub Skill，可以直接让 Echo 更新同名 Skill。更新只会继续使用记录中的同一仓库和目录；不会切换到另一个来源，也不会在后台自动检查或更新。
- 支持版本策略的较新版本中，可以明确说“持续跟随 main 分支”或“固定在这个版本”。跟踪分支决定以后更新检查哪里，实际安装的提交号用于核验；仅提供历史提交供参考不表示要永久固定。固定后普通更新保持该版本，并明确说明没有检查分支最新内容；需要恢复跟踪时，请指定分支，或恢复此前保存的分支。
- 这些版本的更新结果会说明跟踪或固定状态、实际安装提交，以及本次检查范围。“内容相同”只表示所检查范围内没有内容变化；明确改变跟踪或固定策略时，即使内容相同也会保存策略。历史来源意图不明时会保持原来源，只有你明确选择后才转换，不会自行改为 main。较早版本没有这些说明时，不要仅凭“已经最新”推断检查了分支头，可先更新 agent-friend 再核对。
- 更新会先在临时候选中检查完整 Skill，再替换现有版本。下载、内容校验或替换失败时，旧版本和来源记录会保留；内容没有变化时也不会重写现有版本。
- 在支持同轮更新的版本中，已有 Skill 经上述更新流程成功更新后，可以在同一条请求中继续使用：本轮已经加载过的 Skill 会自动加载新版；尚未加载的 Skill 在后续使用时读取新版，无需再发一条消息。已经运行的旧版操作不会被中途替换或自动重做。若更新成功但新版加载失败，Echo 会说明原因，不能把旧版的执行结果当作新版结果。较旧安装版本若仍提示下一轮重试，可以新发一条消息继续，或更新 agent-friend。
- 如果现有 Skill 有本地修改，或同名目录是早期安装且没有来源记录，Echo 会先说明 Skill 名称、来源、内容摘要，以及替换整个目录会丢失本地内容的风险，并在同一任务中发起精确替换。使用“每次授权”时，由授权卡让你作出这一次决定；使用“本会话无需授权”时，这类普通替换会按当前会话的选择直接继续，不再重复弹卡。不同来源与记录冲突、候选校验失败或替换期间内容又发生变化时仍会停止，不会强制覆盖。
- Skill 是否可用与是否已经启用是两件事，按管理界面的状态和提示处理。

## 表格与 Word 文档

- 提供内置 `spreadsheet` 和 `doc` 的较新 Windows 版本支持 XLSX、CSV、TSV 表格及 DOCX 文档的基础读取、创建和编辑。可以在 Skill 管理入口确认是否具备这两项 Skill；更新使用指南不会自动补齐旧版程序的能力。
- 上传文件后，说明要读取的工作表、行列或段落，例如“读取预算表的支出工作表，汇总各类别金额”或“提取这份 Word 的正文和表格”。只需阅读时可明确要求保留原件；需要修改时，可指定将结果另存为新文件并核对生成内容。
- 这些 Windows 版本自带基础处理依赖，无需先安装系统 Python、Codex 或 Microsoft Office。文件访问与脚本执行仍遵守当前会话的授权模式；额外依赖或联网任务可能需要网络。
- XLSX 的公式表达式与缓存结果是不同内容。缓存可能缺失或过期，基础处理不会重新计算公式，不能把读取到的缓存当作最新计算结果；需要重算时请在支持计算的表格软件中完成。
- 本期基础能力不包括 Office 页面渲染、PPT 处理、旧 XLS/DOC 格式转换、宏执行或加密文档解密，也不保证复杂排版完全保真。文字和表格提取不代表已经检查页面布局；生成或修改的文档有排版要求时，请在本地办公软件中检查。

## 本地命令与 Skill 脚本

- 当任务需要运行本地命令、访问本地文件或执行 Skill 脚本时，输入框上方会一次显示一个待处理授权。授权卡会列出发起原因、完整命令或文件范围、工作目录、模式与超时、执行级别，以及文件和网络权限；处理当前项后，下一项会在同一位置出现。
- 输入区的授权模式入口只提供“每次授权（推荐）”和“本会话无需授权”两档。新对话默认使用“每次授权”，但发送第一条消息前也可以先选择“本会话无需授权”；确认后，选择会随首条消息应用到刚创建的会话。每段已创建会话单独保存自己的选择，重新启动应用、重新打开历史会话或恢复归档会话后仍会保留，但不会成为其它会话或全局的默认值。
- 每次从“每次授权”进入“本会话无需授权”都会重新显示风险确认。开启后，当前会话后续新产生的普通文件与命令请求可以不再逐项询问，包括明确标为“宿主用户（文件和网络不受限）”的请求；Agent 仍只能使用每个请求中写明的路径、命令、联网能力和执行级别，普通沙箱命令不会因此升级。
- 授权卡提供“拒绝”“仅本次允许”和“本会话无需授权”。成功切换到免授权后，已经等待的普通请求会按各自显示的完整范围自动允许，能够明确识别的灾难性请求仍会拒绝；授权卡不再继续显示。从某张卡片开启免授权时，当前卡片只批准它展示的精确请求，其它等待项也按同一安全策略收敛。
- 提交命令卡上的“仅本次允许”后，按钮会显示“处理中…”并暂时禁用，成功确认后旧授权卡会退出。等待期间无需重复点击；提交失败或请求已失效时会显示提示，处理方法见[本地命令排查](troubleshooting.md#本地命令或-skill-脚本无法运行)。
- “本会话无需授权”会在输入区持续以高风险状态显示。完成连续操作后，可以直接切回“每次授权”，无需再次确认；已经开始的操作不会被追溯撤销。
- 即使开启免授权，agent-friend 仍可能拒绝能够明确识别的灾难性动作，例如清除磁盘或分区、强制递归删除关键根目录，以及强制递归删除目标无法确定的范围。确实需要检查这类请求时，先切回“每次授权”，重新发起并只确认当前精确操作。
- 对话中的普通工具活动默认显示为紧凑摘要，连续步骤会合并成一组。需要核对某一步时，展开该项查看完整参数和结果；授权按钮不在历史活动中。提供展开高度限制的版本会在步骤区域内滚动显示较长内容，单个步骤和整组步骤都不会无限撑长页面；内容仍可继续滚动查看，未被删减。较早版本可能仍直接延长页面。
- 支持原调用恢复的版本中，可以让 Echo 在当前会话里查找之前的工具调用，核对原参数和结果。查找只读取仍有效的历史，不会重新执行原操作，也不会恢复旧授权。缺少结果只表示执行状态未知；参数或结果较长时可能需要分段读取。
- 普通会话不需要先选择项目或工作区。没有指定目录时，agent-friend 会使用当前会话自己的命令目录；实际目录来源和权限会显示在授权卡中，历史详情可从对应活动项展开查看。
- Python 任务会自动使用 agent-friend 自带的“产品 Python”和当前会话的隔离环境，不会从系统 `PATH`、用户虚拟环境或全局 Python 包中选择解释器。授权卡会显示执行环境；依赖安装还会标记“依赖操作”。
- 当前会话安装的 Python 依赖会在后续轮次保留，不会写入系统 Python、用户 Python 或产品基础环境。不同会话的可写依赖环境彼此隔离；归档会话会保留环境，永久删除会话或清空对应归档会话时会清理该会话环境。
- 从公开包源安装依赖需要文件可写和联网授权；使用已经获准读取的本地 `.whl` 时不需要联网授权。首期只接受兼容 wheel，不支持源码构建、editable、VCS/URL 安装、requirements 文件或自定义包索引。
- 确认前检查准确命令、执行目录、文件系统范围、是否允许联网，以及发起原因。
- 每个实际决定仍只对当前这一次精确请求有效；“本会话无需授权”改变的是后续请求是否需要逐项询问，不会把某次命令、路径或文件范围变成长期白名单。拒绝后命令不会运行，agent 也不会改用未受治理的方式重试。
- 普通命令默认在 Codex 沙箱中运行。如果授权明确标为“宿主用户（文件和网络不受限）”，表示它将以当前桌面用户身份直接启动，并继承当前用户环境；只对来源和参数都可信的桌面程序允许该级别。
- 普通命令运行期间，没有更优先的授权或平台登录请求时，输入框上方会显示运行状态和停止入口；长时间构建不需要反复发送消息查询。命令结束后可展开对话中的对应活动项查看退出码或失败详情；命令结束只表示这一步完成，Echo 仍可能继续整理结果并生成本轮回复。
- 需要输入的交互式命令会返回当前任务专用的进程句柄，后续输入和等待仍受当前任务约束，不能在其它会话中复用。
- 当 Echo 已明确需要放弃、重启或替换一个仍在运行的当前任务命令时，它可以只结束对应的命令及其子进程。活动项确认显示“Agent 已终止”后，才表示原命令已经结束；随后发起的替代命令仍是一次新的精确请求，并按当前授权模式处理。
- Skill 脚本从本轮已启用 Skill 的固定内容快照执行。批准后再修改原 Skill 文件，不会改变这次已经批准的脚本内容。
- Skill 启用状态和本地文件授权只对发起它们的当前用户轮有效。进入下一轮或重启应用后，历史中的“已加载”“已允许”卡片只是记录；继续相关任务时，Echo 应重新启用 Skill 或发起新的文件授权，不能复用上一轮的临时授权。
- 提供沙箱自动恢复的版本中，Windows 普通命令按当前授权模式获准后，会在原操作内准备或修复沙箱；需要时确认系统管理员窗口。恢复成功后继续当前操作，一般无需另发“继续”。正在运行的健康命令会被保留，无法确认是否已执行的命令不会自动重放。较早版本仍需先到“设置 → 系统权限”准备“Windows 命令沙箱”。准备环境不等于批准具体命令；agent-friend 已携带所需组件，不要求另行安装或登录 Codex。
- 使用产品 Python 同样不要求安装系统 Python、修改应用执行别名或手工创建虚拟环境。产品执行环境不可用时，普通聊天仍可继续；按明确错误提示更新或修复 agent-friend 后再重新发起命令。
- 提供上述内置环境的版本中，普通 PowerShell 7 命令会优先使用产品自带版本，沙箱和“宿主用户”执行仍遵守各自的授权范围。生成 PDF 或截图时说明保存位置，并确认目标目录在本次授权范围内。
- 停止当前回复或取消任务时，agent-friend 会终止该任务仍在运行的命令和子进程。

## 正常打开桌面应用

- 支持这项能力的 Windows 桌面版本可以让 Echo 正常打开已确认的本地应用。授权卡标题是“打开桌面应用”，会列出准确程序、参数和工作目录，并说明应用将继续保留。
- 正常打开的应用由当前用户桌面管理，不会因为任务结束、取消或退出 agent-friend 被连带关闭。已经由你打开的可用实例应优先复用；取消任务不代表关闭这些应用。
- “已提交打开请求”只表示系统接受请求，窗口或应用业务是否就绪仍需检查。出现“启动结果未知”时，应用可能已经打开，先检查已有窗口，不要直接重复启动。模拟器还需要核对实例和设备连接。
- 正常打开请求同样遵循本会话的授权模式，程序的文件和网络访问不受命令沙箱限制。它没有后台命令的停止按钮；需要关闭时，明确说明目标，让 Echo 按应用支持的正常关闭方式处理。
- 当前仅支持 Windows 交互桌面上的本地 exe。入口没有这项能力、桌面不可用或组件校验失败时，应根据错误检查或更新当前版本，也可自行打开应用后继续后续操作；不要通过重复受管命令启动来规避限制。

## 后台在线

“设置 → 通用”可选择跟随系统、仅接通电源或始终保持后台在线。该设置只在 agent 执行任务或 QQ 在线等需要持续运行的状态下阻止系统空闲睡眠；不会阻止显示器关闭，也不能覆盖合盖或系统强制睡眠。
