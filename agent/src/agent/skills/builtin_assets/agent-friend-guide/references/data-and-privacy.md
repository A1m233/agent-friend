# 数据与隐私

## 本地数据位置

agent-friend 的会话、记忆、人格和其他用户资产默认保存在系统用户数据目录：

- Windows：`%APPDATA%/agent-friend/`
- macOS：`~/Library/Application Support/agent-friend/`
- Linux：`$XDG_DATA_HOME/agent-friend/`，未设置时通常是 `~/.local/share/agent-friend/`

桌宠模型也属于用户资产，统一放在用户数据目录的 `avatar-models/` 下：

- 用户导入的 Spine 3.8 模型目录是 `<用户数据目录>/avatar-models/user/spine38/`；其中每个一级子目录代表一个模型。
- Agent 需要为当前桌面实例安装模型时，优先在应用日志目录的 `tauri.log` 中查找最近一条 `avatar models: assets_dir="..."`，把该行给出的实际模型资源根目录追加 `user/spine38` 作为安装目标。日志只需在本机读取，不需要用户粘贴或公开整份文件。
- 当前日志不存在、没有这条记录或无法读取时，再请用户前往“设置 → 桌宠 → 打开 Spine 3.8 模型目录”，从文件管理器地址栏复制完整路径。不要只根据用户名或系统默认目录猜测当前实例的实际路径。

Windows 日志默认位于 `%LOCALAPPDATA%/agent-friend/Logs/`。不要在应用运行时手工移动或修改数据文件；迁移电脑时使用设置页的迁移功能。

普通本地命令可以使用当前会话自己的受管命令目录。该目录会在同一会话的后续任务中保留；归档会话不会删除它，永久删除会话或清空对应归档会话时会一并删除。

Python 任务还会为当前会话保留独立的依赖环境。产品自带的 Python 基础环境和下载缓存可以由多个会话复用，但各会话不会共享可写的依赖目录。删除会话时会清理对应的会话环境；提供环境重建修复的版本在恢复失败时，可能保留旧环境副本用于排查，重启或删除会话不保证同时清除这些副本。为减少重复下载而保留的共享缓存会按产品的磁盘治理规则统一清理。不要手工修改这些受管环境或把它们当作个人 Python 安装使用。

提供统一会话文件附件的版本会在发送时自动在当前会话命令目录中保存上传附件的独立只读输入副本，用于后续读取和处理；较早的会话文件能力可能在读取时才准备副本。副本不会取代本地附件原件；永久删除会话时会随命令目录清理。归档或重启不会自动删除它们。

## 生成图片的数据

- 提供模型图片接收能力的版本会把有效生成图片保存为本机受管原件，并与对应会话关联；归档保留这些内容。应用仍在使用的图片文件不应手工删除或修改，否则历史中的图片可能无法访问。
- 后续对话默认保留图片来源和可访问关系，不因历史加载自动把图片正文重新发送给模型；当你要求继续查看或处理图片时，实际读取的图片仍可能交给当前支持看图的模型。
- 通过 QQ 交付时，图片会上传到 QQ 平台并发送给对应私聊；是否显示及平台留存受 QQ 服务影响。本地删除内容不代表 QQ 已收取的图片也被撤回。
- 分享会话、备份或诊断材料前，应把生成图片与其他私人附件一起检查；模型生成的内容也可能包含你提供的私人信息。

## 会话恢复数据

- 提供历史召回优化的版本会在本地维护可重建的检索副本，其中可能包含对话正文和来源信息，属于同一用户数据与隐私边界。副本用于加快查找历史，不会因此新增向外部服务上传聊天的流程；实际用于回答的历史内容仍可能发送给所选模型。编辑后的失效内容不会继续用于召回，归档会保留历史及检索能力；永久删除会话时会清理对应副本，已删除会话不会再作为历史来源。
- 提供会话存储治理的版本会减少新增恢复数据的重复保存，不会因此删除历史消息。升级后仍可读取旧格式会话；旧文件不保证自动缩小。
- 数据兼容以新版本读取旧数据为方向，不保证旧版本能读取新版本写入的会话数据。需要降级时，先备份用户数据，并确认目标版本是否能读取；不要直接用旧版本覆盖或改写新格式数据。
- 为了在应用或电脑重启后继续同一段对话，本机会保存模型在已完成轮次中实际采用的上下文顺序。除用户和 Echo 的消息外，其中可能包含工具调用与结果、当时召回的长期记忆、启用的 Skill 内容，以及日期、交互入口和权限状态等只提供给模型的上下文。
- 这些恢复数据与原会话保存在同一用户数据和访问边界内，不会写入设置页保存的 API Key、访问令牌、Cookie 或系统权限凭据。普通对话正文中由用户主动发送的敏感信息仍会作为会话内容保存，因此不要在聊天中粘贴密钥。
- 归档会话会保留恢复数据；永久删除单个会话或清空对应归档会话时会一并删除。产品不会为这部分数据设置一套独立于会话的保留期限。
- 本地命令在取消、应用退出或运行时失联前已经保存的部分输出，也可能作为该会话的执行证据暂存，用于在恢复时说明中断前发生了什么。证据有大小限制并会明确标记为不完整，但仍可能包含命令打印的敏感信息；归档会话会保留，永久删除会话时会一并清理。
- 升级前创建的旧会话会在首次继续使用时建立新的本地恢复基线。旧版本没有保存的模型专用上下文无法补回，因此第一次继续旧会话时不保证复用升级前的完整模型前缀；从新基线开始的已完成轮次可以按当前恢复能力继续。
- 提供长会话本地复用的版本会额外保存用于历史展示和执行恢复的会话副本，可能包含消息、工具输出及模型专用上下文，并占用额外磁盘空间。这些内容留在本机用户数据的访问边界内；备份或分享相关数据时仍应按私人会话处理。
- 这些副本不能代替原始会话文件，也不是独立备份。归档会保留相关数据，永久删除会话时按会话删除流程清理对应副本；这不承诺安全擦除或故障下立即没有残留。副本不可用或来源变化时可能重新准备或提示错误，不应靠删除原始历史来强制重建。
- 本地恢复相同上下文并不保证模型供应商仍保留远端 Prompt Cache；供应商缓存过期或被淘汰时，回答仍可继续，但缓存读取量可能为零。

## 延后处理的记忆素材

提供故障期记忆保护的版本会在本地保存尚未处理完的对话片段及其来源，其中可能包含私人聊天内容。素材会在后续正常交流时分批送往已配置的记忆模型处理；处理成功或对应来源被删除后，待处理记录会清除。仅重启或退出应用不会自动补发积压；归档会话会保留素材，永久删除会话会清理其待处理素材。不要把“尚未成为长期记忆”理解为“本机没有保存”。

提供记忆正确性修复的版本会保留无法安全处理的单条素材及失败状态，同时允许其他正常素材继续；这些暂停的素材不会自动删除或修复。编辑撤销来源时，与该来源直接关联的当前及历史记忆会停止用于后续查询，但可能保留追溯记录；这不等同于物理擦除，也不会自动恢复更早的事实。

## 会话授权状态与执行记录

- 在支持的桌面系统上，AF 醒来时可得到最近一次系统输入的时间，不包含按键内容、鼠标轨迹或正在使用的应用。缺少近期可靠观测时该时间未知。
- 自主活动与普通聊天共用人格和记忆。AF 的独立经历可以被之后的交流用到。回看旧消息不会被当作今天再次确认用户事实，仍可通过现有的记忆管理方式纠正或遗忘内容。
- 自主陪伴的授权模式单独保存在本地设置中。默认“帮我审批”在执行需要权限的操作前检查内容。自主活动审批未通过时会停下或选择其他做法。
- “完全授权”允许 AF 直接执行支持的文件、命令和桌面应用操作，包括修改或删除文件。系统权限与产品保护仍然生效。
- 主动消息记录在选定的普通会话中。分享文本或单张图片时默认通知该会话绑定的本人 QQ 私聊，可明确要求仅留桌面，删除本地记录不能撤回平台已发送的消息。

## 桌宠通知与记忆

以下适用于提供“通知”设置的版本。

- 需要模型生成自然语言短通知时，会把当前人格、与通知相关的有限事件信息和召回记忆交给“新对话默认模型”处理，可能带来普通会话之外的额外模型用量。生成会话回复通知时，新版本也会把这次完整回复交给该模型，用于生成简短提示。提供故障期负载保护的版本中，任务失败通知直接使用本地文案，不为润色这条通知调用模型。通知不会替换原会话中的完整回复；是否发送桌宠提示可在[通知设置](settings-reference.md#通知)调整。
- 通知实际通过气泡显示后，本机会记录通知发生时间、事项和实际显示文字，供后续相关交流回忆。这表示“已经显示过”，不表示你已经阅读、同意或处理；关闭气泡不会删除已经保存的通知记忆。
- 记忆中这类通知的发生时间会以带时区偏移的当地时间呈现。已保存通知正文中的引用、时间和说法保持原样；显示时间转换不会改写过去实际显示过的文字。

## 自定义提示音

提供“选择音频”的版本会把导入音频另存到本机用户数据目录。原始文件不会被移动或删除，导入后也不必保留原文件。该操作不上传音频，也不需要把音频发送给模型。

保存的自定义提示音随应用的备份与迁移保存；迁移包可能因此包含你导入的音频内容。更换音源或恢复默认会清理应用不再使用的提示音副本，但已有迁移包或回滚备份仍可能保留原音频。操作入口与限制见[通知设置](settings-reference.md#通知)。

## 定时任务数据

- 定时任务的名称、发送内容、附件引用、时间规则、状态和每次运行历史保存在本机用户数据中。提供固定目标会话的版本会把每次执行写入所选会话，回复、工具步骤和最终结果可在普通历史列表查看；较早版本的独立运行可能仍不在该列表中显示。
- 任务保存的附件会保留供后续执行使用，不能假定关闭表单或清理普通草稿就已删除附件副本。删除定时任务不会自动抹掉已有会话消息、运行事实或外部副作用。
- 任务开始执行时，保存的内容会交给本轮采用的模型处理，并沿用目标会话的上下文；附件由模型按需读取。如果任务使用联网工具、第三方平台或本地命令，相应的数据处理与授权边界和普通对话一致。
- 应用完全退出后不会留下独立的定时任务后台服务。系统休眠期间也不会在本机执行任务；应用恢复后按近期错过规则处理。

## 凭据

- 在设置页保存的 API Key 会进入系统安全凭据存储，界面不会再次显示明文。
- 不要在普通对话中粘贴 Key，也不要把带 Key 的截图或配置文件公开。
- 怀疑泄露时，到对应供应商控制台撤销并重建。

## 模型附件

- 提供统一会话文件附件的版本先向当前模型发送文件名称、类型、大小和来源等信息，原件保存在本机。TXT、图片、PDF 及其它类型都不会仅因发送消息而自动投递正文或图像；工具实际读取的文字或图片仍会发送给当前模型。“本地文件处理”不表示内容永远只留在电脑上。旧版可能直接发送图片、TXT 正文、完整 PDF 或抽取全文，更新指南不会改变已安装程序的投递方式。
- 附件原件保存在本机用户数据中，是继续历史对话时的主要来源。工作副本不可用时，可以从原会话保存的有效原件重新准备；文件缺失或校验失败需要恢复原件或重新上传。
- 统一会话文件附件不再为用户附件自动创建模型服务的远端文件副本。工具读取的内容仍可能由当前服务处理和保留；旧版已经发送或上传的内容不会因升级或删除本地附件而被追溯撤回，保留与删除政策以对应服务为准。
- 不要向任何第三方模型发送不希望其处理的敏感图片；发送前先确认当前选择的模型和调用渠道。

## 本地图片读取

以下适用于已提供“读取图片”能力的版本。

- 允许 Echo 读取本地图片后，图片内容会作为工具结果发送给当前会话选择的模型服务；“本地读取”不表示图片只在电脑上处理。授权前应确认图片内容和当前模型渠道。
- 本机会保存读取当时的图片快照，以便继续或恢复会话。修改、移动或删除原文件不会自动删除这份快照；归档会话也会保留关联。永久删除所有引用该快照的会话后，快照会按产品的资产清理规则清理，不保证立即删除。
- 这项工具随模型请求发送实际读取的图片。模型服务对请求数据的处理取决于其政策；本地删除不保证撤回已经发送的数据。
- 长对话中暂时不向模型提供某张图片，并不表示本地快照已经删除；快照失效时会明确说明无法继续查看。

## 数据迁移

- 迁移包是加密文件，可包含会话、记忆、人格、设置、系统凭据、QQ 绑定和用户模型。
- 12 词迁移码不会写入迁移包，必须与文件分开保存；丢失后无法恢复该迁移包。
- 首版仅支持 Windows 到 Windows。
- 恢复会整体替换目标电脑的相关数据，不会合并。
- 替换前会创建并验证回滚备份；应用只保留最近一份，除非用户主动删除，不会按时间自动删除。

## 诊断包

- 诊断 ZIP 只保存到本机下载目录，不会自动上传。
- 选中的会话可能包含私人聊天内容以及工具参数和结果。提供完整导出的版本默认采集每个所选会话的全部已保存轮次，也可以取消“采集全部轮次”，改选最近 1～100 轮；包括正在进行一轮已经保存的内容。会话与本机保留的日志不再按导出体积截断，大包可能耗时较长。旧版本可能默认最近 10 轮并受采集体积上限限制，请以当前界面和导出结果为准。
- 系统会过滤可识别的凭据、内部快照正文和模型私有推理，但不会替用户删除所有普通隐私信息。已被删除或轮转淘汰的历史、当时未成功采集的截图，不能通过再次导出补回。
- 诊断包会包含桌面实例治理摘要，用于判断本次启动是新建、唤醒已有实例、被拒绝还是从异常残留中恢复。摘要不包含聊天正文或凭据，但可能包含进程编号、程序路径、安装目录或开发工作目录；这些路径可能带有系统用户名。
- 诊断包会记录受管执行环境的版本、内容身份、健康状态、会话环境数量和失败类别，帮助区分产品环境损坏、依赖失败与普通命令问题。该摘要不包含用户脚本正文、用户文件正文、包索引凭据或完整命令输出。
- 原始附件默认不包含；开启后可能加入私人图片和文档。只收集本次采集范围内引用且完整性校验通过的原件；提供完整导出的版本不设附件原件导出体积上限。
- 渲染证据可能包含完整桌面截图和桌宠内部截图，敏感程度很高。手动采集的截图需要你在生成诊断包时确认包含；显示器从息屏恢复或 Windows 渲染进程异常时自动保存的最近一次事故证据，会在你主动生成诊断包时自动包含，无需提前开启。

把诊断包交给任何人之前，按私人文件处理并逐项确认内容。无需分享的附件、手动截图和原始崩溃转储不要勾选；如果刚发生过息屏恢复或渲染进程异常，还要留意诊断包可能自动包含该次完整桌面截图。

### Windows 应用崩溃记录

Windows 0.4.1 起会默认在本机保留有限的应用异常与退出记录，并尝试为受支持的故障保存崩溃转储，无需提前开启调试。重启后仍可在“设置 → 帮助与反馈”导出尚未过期的记录，无需选择聊天会话。记录和转储不会自动上传；更新指南不会为旧安装版本补上这项能力。

默认诊断包只加入崩溃摘要、记录覆盖情况和采集错误，不加入原始转储。摘要用于说明发生时间、应用版本、异常或退出状态及证据是否可用，不包含转储中的内存正文。原始转储可能保存故障时内存中的聊天、凭据等私人内容，无法自动脱敏。只有为进一步定位而选择“包含原始崩溃转储”时才会加入可用转储；它独立于原始附件和渲染截图选项，每次生成后都会恢复为未选中。分享前须按高敏感私人文件处理，普通摘要的过滤规则不适用于原始转储。

原始转储按 14 天、最多 5 份、合计 256 MiB 的限制保留，单份最多 128 MiB；摘要记录按 30 天、最多 100 份保留。达到数量或容量限制时可能提前淘汰旧记录，清理在应用处理记录时执行，不保证期限一到立即删除。已生成的诊断 ZIP 不随这些记录一起自动清理。

提供诊断结果分类修复的版本会将此前运行缺少完整退出结果的情况作为历史证据说明保留，不再仅因这一缺口将本次导出标为部分失败。该分类不会删除历史记录，也不会补回缺失现场；提示含义见[诊断包排查](troubleshooting.md#诊断包提示部分内容获取失败)。

并非每次异常都能留下转储。强制结束、部分系统快速终止或电脑突然断电时，可能只有退出或“原因未知”的记录；权限、空间不足或采集失败也会造成缺口。已有记录不等于每条都是导致整个应用退出的崩溃，没有记录也不能证明没有发生故障。已淘汰、未成功采集或旧版本没有保存的现场无法通过重新导出补回。

### 启动加载时间记录

提供启动时间记录的版本会自动保留主要加载阶段、安装文件校验的汇总耗时与规模，以及对话界面准备好的时间点。这些新增记录不包含聊天正文、凭据或逐个文件的私人路径，不会自动上传；主动生成诊断包时可一并导出，无需选择聊天会话。窗口出现、界面准备好和模型开始回复是不同的时间点。

正常启动后的诊断包也可能带回此前失败或中断启动留下的记录。记录沿用本地日志的保留范围，旧版本没有记录、日志已轮转删除或退出前未保存的部分无法补回。整份诊断包仍可能包含其它私人内容，应按上述分享边界检查。

### Windows 沙箱故障记录

提供独立沙箱故障记录的版本，会在本机保留初始化或执行失败、状态检查及手动修复的相关证据，无需提前开启调试。修复成功或正常重启后，尚未过期的记录仍可随你主动生成的诊断包导出；无需选择聊天会话。记录不包含完整命令、密码、脚本或用户文件正文，也不会自动上传。

记录最多保留 30 天、32 份，每份有体积限制；达到限制时可能提前淘汰旧记录。导出结果会说明可识别的缺失或淘汰情况，异常退出前未保存的末尾仍可能丢失。旧安装版本可能没有这项能力，缺少记录不能证明没有故障。

### 模型调用诊断记录

提供细分错误诊断的版本会在本地日志中记录调用所属业务、错误类别、请求尝试和重试停止原因，并用摘要关联会话、任务和服务请求。这类新增记录不保存原始错误正文、完整请求、凭据或聊天内容，可能随主动生成的诊断包导出，不会自动上传。

提供协议异常诊断的版本，还会记录受限的异常事件类型、必要结构摘要、失败阶段和关联标识，帮助定位返回内容无法处理的问题。这类新增记录不保存原始响应、正文、工具参数与结果正文或模型推理内容；异常或过长的标识会被隐藏或替换为摘要，并标明信息缺失。记录沿用本地日志的保留范围，已轮转删除或旧版本未记录的信息无法补回；整份诊断包仍可能包含其它私人内容。

一次业务调用可能包含多次发送尝试；准备重试也不等于请求已发出。记录的发送尝试不能证明服务端已收到，更不能代表中转服务内部的实际请求次数。旧版本或缺失记录不能证明没有请求或故障。整份诊断包仍可能包含其他私人内容，分享前需要检查。

### 会话读写诊断记录

支持会话读写诊断记录的版本，本地日志中可能包含操作类型、会话标识摘要、等待与处理耗时、数据规模以及错误类别，用于排查历史加载缓慢或保存失败。这类记录可能随你主动生成的诊断包一起导出，不会自动上传。

这类读写观测本身不记录聊天正文、工具参数或输出、凭据，也不记录原始会话标识或文件路径。这不代表整份日志或诊断包不含私人内容；分享前仍需按上面的诊断包说明检查。旧版本或旧诊断包可能没有这些记录，缺少记录不能证明没有发生读写问题。

### 桌宠输入诊断记录

提供桌宠输入诊断记录的安装版本，会默认在本机保存用于排查鼠标命中、显示缩放和点击穿透问题的有限状态记录，无需提前开启调试。记录可能包含发生时间、应用版本、窗口尺寸、缩放状态，以及状态变化时少量鼠标坐标；不会因此新增聊天正文、按键、剪贴板、其他应用内容、截图或录屏采集，也不会自动上传。

普通输入历史最多保留 7 天、16 MiB；识别出的异常记录独立保留，最多 30 天、32 份、合计 8 MiB，达到相应限制时会提前淘汰旧记录。主动生成诊断包时会包含仍可读取的记录，无需选择聊天会话。异常退出可能丢失尚未保存的末尾记录，生成成功不代表故障现场完整。旧安装版本或旧诊断包可能尚无这类记录。

### 桌宠显示异常运行记录

提供“桌宠显示异常记录”的 Windows 安装版本，会默认在本机保留有限的页面运行、绘制进展、窗口操作及相关进程状态，便于排查闪烁或卡住。记录包含时间、应用版本和实例标识，不因此新增截图、聊天正文、键盘输入或连续鼠标轨迹采集，也不会自动上传。

普通历史最多保留 7 天、16 MiB；自动信号或手工标记保留的片段独立保存，最多 30 天、32 份、合计 8 MiB，达到限制会提前淘汰旧记录。手工标记确认已保存后，应用继续运行时还会补充约 10 秒后续记录；不需要为此等待才能退出。正常退出和重启后，主动生成诊断包可包含仍可读取的旧记录，无需选择聊天会话。

记录可能因磁盘失败、拥塞、截断、淘汰或异常退出而不完整。绘制仍在推进不表示屏幕显示一定正常，缺少异常信号也不表示没有闪烁。旧版本和旧诊断包可能尚无这些记录。整份诊断包仍可能包含上文所述的其他隐私内容，分享前应检查。

## 安装器诊断日志

- 安装程序在安装前检查失败时，会把诊断日志保存在当前 Windows 用户的临时目录，并在提示框中显示完整位置。
- 这份日志用于记录安装包版本、安装位置、失败阶段，以及临时检查程序的路径和执行后存在状态；不需要启动 agent-friend，也不包含会话、附件或设置页中保存的 API Key。
- 日志中的本机路径可能包含 Windows 用户名、安装包存放位置和自定义安装目录。发送给开发者前仍应按私人文件检查，不要公开发布。
- 问题排查结束后可以删除对应的 `agent-friend-installer-<构建编号>.log`；删除它不会影响已安装的 agent-friend 或用户数据。

### 命令沙箱故障记录

提供这项诊断的版本会在本机保留有限的初始化、修复、助手加载和网络决策记录，并随主动生成的诊断包导出，不会自动上传。记录包括时间、构建与操作标识的摘要、故障阶段、错误类别、可取得的系统错误码以及代理来源类别。

这项记录最多保留 128 条事件，文件上限 64 KiB；已知的待修复状态单独保留，避免旧事件淘汰后误认为已恢复。记录不包含命令正文、目标域名、完整环境、账户密码或凭据密文。异常退出可能丢失尚未保存的末尾事件，旧版本也可能没有记录；这些限制不改变整份诊断包仍可能包含私人内容的事实。

## 消息展示记录与 B 站互动

提供展示感知的版本会在本机记录具体消息的展示范围、时间及对应内容版本，供 AF 判断是否联系。记录不代表你已阅读或理解，不会因此新增截图、按键内容或鼠标轨迹采集。永久删除会话时会清理对应的展示记录。

B 站登录信息保存在系统安全凭据存储中，退出 AF 的账号会清除产品保存的登录信息。你通过对话提供的本人 UID 属于核心身份记忆，和 AF 的登录账号分开；可通过现有记忆管理或对话纠正、撤回。

查阅评论时，平台返回的公开作者信息和正文可能进入会话工具记录及模型上下文；发表评论和 @ 会把最终正文提交到 B 站。没有独立的互动收件箱或持续同步缓存，普通会话和执行记录仍会保留。删除本机记录或退出账号不能撤回已经提交到平台的内容。
