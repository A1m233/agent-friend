# 模型凭据

agent-friend 提供 DeepSeek、Kimi 内置渠道，以及支持 OpenAI 兼容接口的自定义连接。使用某个渠道前，需要配置对应的 API Key，并确保账号有可用额度。OpenRouter 暂不维护，模型选择与凭据设置入口已隐藏。

初始默认对话模型是 DeepSeek Flash，思考默认关闭；初始默认记忆模型也是 DeepSeek Flash，使用“最高”思考强度。已经在设置中主动选择过模型时，升级不会覆盖已有选择。

“默认对话模型”只决定之后新建对话草稿的初始模型。修改并保存时不会重启服务，也不会改变当前会话或已经打开但尚未发送的草稿；当前会话可以在输入区单独切换模型。

保存或更换 DeepSeek、Kimi API Key 时，agent-friend 会先在线校验候选 Key，但不会生成模型回答。校验成功后才替换原配置，并自动应用到对话服务；明确校验失败时会保留原配置并显示失败原因。如果网络或渠道服务暂时不可用，页面会让你选择稍后重试，或确认“仍然保存”。确认保存的 Key 会显示“已配置”，可以之后点击“校验当前凭据”；校验成功时显示“已配置 · 已验证”。

## DeepSeek API Key

1. 登录 [DeepSeek 开放平台](https://platform.deepseek.com/)。
2. 打开 [API Keys](https://platform.deepseek.com/api_keys)。
3. 创建一个新 Key，并在页面只显示完整值时立即妥善保存。
4. 在 agent-friend 打开“设置 → 模型与凭据 → DeepSeek”，粘贴并保存。
5. 等待页面完成校验和应用。显示“已配置 · 已验证”后即可选择 DeepSeek 模型使用。

agent-friend 当前提供以下 DeepSeek 模型：

- DeepSeek Flash：文本、工具调用以及 JPEG、PNG、WebP 图片；
- DeepSeek V4 Pro：文本对话和工具调用。

这两款模型都可在当前会话选择“关闭 / 低 / 高 / 最高”推理强度，默认关闭。切换模型时会先采用目标模型的默认档位，之后可以继续调整。

提供统一会话文件附件的版本按应用统一限制接收任意类型文件，DeepSeek Flash 可在任务需要时读取图片。纯文本模型可通过工具读取文字，但不会因此获得看图能力。接收大小与图片读取大小是不同限制，详见[模型与附件](using-agent-friend.md#模型与附件)。

旧的 V4 Flash 与 V4 Flash Vision 已从可选列表移除。已有默认设置和历史会话保留原来的选择，不会自动迁移；继续使用旧型号时会报模型不可用。请在对应默认设置或当前会话中手动选择 DeepSeek Flash，再继续使用。自定义连接中的同名模型不受内置型号移除影响。较早安装版本的型号和初始默认值可能不同，以实际界面为准。

官方文档：[DeepSeek API 文档](https://api-docs.deepseek.com/zh-cn/)。

## Kimi API Key

1. 登录 [Kimi 开放平台](https://platform.kimi.ai/)。
2. 打开 [API Keys](https://platform.kimi.ai/console/api-keys)。
3. 选择项目并创建 Key，保存页面展示的完整值。
4. 在 agent-friend 打开“设置 → 模型与凭据 → Kimi”，粘贴并保存。
5. 等待页面完成校验和应用。显示“已配置 · 已验证”后即可选择 Kimi 模型使用。

`platform.kimi.ai` 与其他 Kimi 平台的 Key 不一定通用，应从上面的开放平台创建。官方文档：[Kimi API 概览](https://platform.kimi.ai/docs/api/overview)。

Kimi K3（模型列表显示为 `kimi-k3`）支持文本对话和工具调用；当前会话可选择“低 / 高 / 最高”推理强度，默认“最高”，不提供关闭档位。提供统一会话文件附件且本地文件处理可用的版本允许上传任意类型文件，再由工具按需读取可处理的文字；K3 在当前内置配置中仍未开放看图工具。旧版本可能只允许 PDF 或没有文件入口。新增 K3 不会改变原有默认模型。

Kimi 2.6 与 Kimi 2.5 支持在当前会话关闭或开启推理，默认开启；Kimi 2.7 Code 与 Kimi 2.7 Code Highspeed 固定开启推理，不提供关闭或强度档位。

## 自定义连接（BYOK）

在“设置 → 模型与凭据 → 模型 → 自定义连接”添加连接，使用你自己的服务地址和 API Key。较早版本没有此入口，是否提供以实际界面为准。

1. 填写连接名称、Base URL 和 API Key，并按服务文档选择 Chat Completions 或 Responses 协议。Base URL 通常包含 `/v1`；不要把生成请求的完整路径当作 Base URL。
2. 点击“获取模型列表”，搜索并勾选模型；服务没有列表接口或列表不完整时，也可以手动填写准确的模型名称。获取列表无需先保存，不生成回答。
3. 检查上下文预算。页面会显示服务返回值或参考目录来源；没有可靠数值时需要补充。此预算用于控制历史压缩，参考数值不保证等于服务实际限制。
4. 提供统一会话文件附件的版本无需声明图片或文档输入能力，页面已移除这两个选项，旧连接仍可加载。接收文件需要工具调用和本地文件处理；按需看图是否成功取决于服务与模型的实际支持。旧版本可能仍显示这两个开关。
5. 点击“测试模型”检查生成和工具往返。测试使用当前草稿，最多发送三次小请求，可能产生服务费用；它不测量最大上下文，也不能证明所有附件或长对话都可用。修改地址、密钥或协议后应重新获取列表和测试。
6. 保存连接，再在默认对话、记忆或当前会话中选择其中的模型。保存本身不生成回答；尚未保存的草稿不会替换正在使用的连接。

自定义连接仅支持 OpenAI 兼容的两种协议，不直接支持 Anthropic Messages 等其它格式。API Key 应从你选定服务的官方控制台申请，地址、模型名、额度和协议以该服务文档为准；不同服务的 Key 不能混用。

### 推理强度

默认对话模型、记忆模型和当前会话均可设置推理强度。自定义模型提供常见值参考，也允许填写服务接受的其它值；没有标准的推理档位发现列表，不能从“获取模型列表”推断可用档位。

“服务默认”表示不发送推理参数，和显式填写 `none` 不同。填写的值按所选 OpenAI 协议发送：Chat Completions 使用 `reasoning_effort`，Responses 使用 `reasoning.effort`。是否支持具体值由服务判断；被拒绝时应修改强度或使用服务默认。内置渠道仍只展示其已支持的档位。

### 删除与失效

移除模型或连接前，先为使用它的默认用途选择替代模型。历史会话不会被悄悄换成其它模型；原连接不可用时，需要在该会话中重新选择可用模型。运行中的任务可能阻止删除，应等待结束后重试。

## 本地图片读取的模型支持

以下适用于已提供“读取图片”能力的版本。

- 内置 DeepSeek Flash 支持让 Echo 在获得文件授权后查看本地图片。
- 提供统一会话文件附件的版本中，自定义 Chat Completions 和 Responses 连接都可按需尝试读取图片，不再要求官方服务地址或手动图片开关。协议兼容不代表远端模型已验证支持视觉；明确拒绝图像时会反馈不可用，不会假装已经看图。
- 同一较新版本也为内置 Kimi 2.5、2.6、2.7 Code 和 2.7 Code Highspeed 提供按需图片读取；K3 等未配置视觉能力的内置模型不开放此工具。较早版本可能仅开放 DeepSeek 和特定官方 Responses 连接，更新指南不会改变旧版限制。
- 不支持时不会自动调用其它视觉模型。具体操作与图片大小限制见[本地图片读取](using-agent-friend.md#让-echo-查看本地图片)。

## OpenRouter 暂不维护

OpenRouter 模型和凭据设置不再向用户开放。隐藏入口不会主动删除以前保存的设置或凭据，也不会自动把旧会话切换到另一模型；这不代表旧渠道仍获得维护或保证可用。需要继续使用时，建议在当前会话和“默认对话模型”中选择已配置的 DeepSeek 或 Kimi，不要为 agent-friend 新购 OpenRouter 额度。

如果已安装版本的模型列表与本文不同，以实际界面为准；旧版本可能没有 K3，或仍显示 OpenRouter 入口。

## 安全建议

- 不要把 Key 发到聊天、截图、Issue 或公开仓库。
- 为 agent-friend 单独创建 Key，便于撤销和查看用量。
- 怀疑泄露时立即到对应平台控制台撤销旧 Key 并创建新 Key。
