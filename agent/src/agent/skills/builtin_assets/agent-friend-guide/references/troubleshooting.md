# 常见排查

## 启动很慢或长时间不能输入

- 先区分桌宠或窗口已经出现、对话窗口正在加载，以及输入框已经可以输入；窗口出现不代表所有加载都结束。
- 提供启动时间记录的版本会自动在本机记录主要加载阶段，无需提前开启调试。应用能够打开后，从“设置 → 帮助与反馈”生成诊断包，并说明大致启动时间、等待时看到的界面，以及是否中途退出或重试；只排查启动时可以不选择聊天会话。
- 如果应用中途退出，随后能够正常打开时，尚未过期的记录仍可能随诊断包取回。旧版本未记录、日志已轮转删除或退出前未保存的部分无法补回；缺少记录不能证明某一阶段没有耗时。
- 时间记录用于区分等待发生的位置，不保证固定秒数内启动。更新指南本身不会为旧安装版本增加记录，也不会改变启动速度。分享前检查诊断包中的私人内容，见[诊断包](data-and-privacy.md#诊断包)。

## 重复启动或提示已有实例

- agent-friend 默认只运行一个正式桌面实例。再次从快捷方式、安装目录或另一份程序副本启动时，通常会唤醒已经运行的窗口，不会再开启一套后台服务。
- 如果提示已有另一类 agent-friend 实例正在运行，本次启动会停止，避免两套程序同时读写数据或争用服务。请回到原实例，从系统托盘正常退出后再重试。
- 不要为了继续启动而结束不认识的进程、删除应用数据或手工修改实例状态文件。无法确认原实例时，先在原窗口的“设置 → 帮助与反馈”生成诊断包；原窗口打不开时，保留提示截图并交给开发者排查。

## 安装程序无法继续

- 如果安装程序提示“安装前检查未通过”，agent-friend 尚未写入或替换程序文件；即使电脑从未安装过 agent-friend，也可能出现这类检查失败。
- 提示框会给出安装器诊断日志的位置，通常是当前 Windows 用户临时目录中的 `agent-friend-installer-<构建编号>.log`。不需要先成功安装或进入设置页，就可以提供这个文件。
- 如果失败前后出现 Windows 安全中心或第三方安全软件提醒，请检查“保护历史记录”或隔离记录。安全软件可能阻止安装器运行临时检查程序，这通常不是网络防火墙连接失败。
- 只有确认安装包来自可信来源，并与提供方公布的文件名及 SHA-256 校验值一致时，才恢复或允许被拦截的项目后重新运行安装器。不要为安装 agent-friend 整体关闭防火墙或杀毒保护。
- 如果仍然失败，请保留完整提示截图和诊断日志并交给开发者；不要自行删除应用数据，也不要查找或结束不认识的系统进程。
- 如果提示明确说无法创建诊断文件，只提供完整截图，并同时说明安装包文件名和选择的安装目录。

## 保存凭据后仍提示缺失

1. 检查字段是否填在正确能力下，例如天气需要 Key 和 Host，语音输入与通话需要不同组合。
2. 查看这一组凭据的保存结果。明确校验失败时，原配置不会被替换；修改凭据后重新保存。
3. 如果提示当前任务占用服务，凭据已经保存但尚未应用；任务结束后点击“重试应用”。
4. 如果设置页显示值来自系统环境或旧配置，那个来源可能覆盖设置页保存的新值；移除旧来源后点击“重试应用”。
5. 不要在聊天中发送 Key 来排查。可在供应商控制台创建一枚新的独立 Key 替换测试。

## 联网搜索失败或一直重复检索

- “网络错误”表示本次没有取得搜索结果，不代表资料不存在。提供详细提示的版本会说明已经尝试的次数；更换关键词不能修复连接故障，可以稍后重试或改用其它可用来源。
- 已有准确公开链接时，可以让 Echo 直接尝试读取，不必等待搜索恢复；搜索与网页读取可能使用不同路径，但都不保证一定能够访问目标。
- “参数无效”时，提供字段提示的版本会指出需要修正的位置，Echo 应先修正参数再试；这类错误不表示你需要更换 Key。持续出现时，从“设置 → 帮助与反馈”生成诊断包。
- 连续步骤遇到相同故障时，较新版本会提示 Echo 调整取证路线；这不代表任务已被自动终止，也不保证外部服务已经恢复。

## 模型请求失败

- 提供连接兼容性改进的版本中，连接仍在发送保活或附加活动时，不会仅因没有新增正文就中断；这些活动不代表任务已完成，也不能证明模型仍在取得进展。长时间没有可见进展时，可以主动停止。更新指南不会修复旧安装版本的连接行为。
- 如果明确提示模型只返回了“尚未接入的输出类型，没有可用回答”，请核对自定义连接能力或切换已配置模型；不能据此认为相关搜索、音频、图片或远端工具能力已经可用。如果提示正文或工具调用不完整、存在冲突，本次损坏响应中的工具不会执行，此前已完成步骤仍会保留；检查连接兼容性后再继续，避免重复执行已完成的操作。
- 显示“模型拒绝了这次请求”时，先阅读拒绝说明并调整请求；它不同于连接中断或服务故障，不要因为这条提示反复充值或更换 Key。回答来源显示“当前无法打开”时，只表示该引用没有可用打开入口，不保证文件已下载或网页仍可访问。

- 长会话发送后、模型开始回复前，应用可能仍在恢复本地会话或查找相关历史。提供历史召回优化的版本会复用本地检索数据，但首次建立、数据失效后重建，以及重新打开已释放的会话时仍可能等待。不能只凭尚未出现正文判断请求已到模型服务，也不能保证固定秒数内开始回复。若同一会话连续多次发送都明显等待较久，可从“设置 → 帮助与反馈”生成诊断包，并说明是首次打开、连续发送还是切换会话后发生；不要自行删除历史文件来排查。更新指南本身不会改变已安装程序的发送行为。
- 在支持分阶段等待的版本中，普通回复默认最多等待 5 分钟取得首响应；开始接收后，连续 5 分钟没有新的有效模型活动才会触发空闲超时。持续收到活动时，不会仅因整次回复超过 15 分钟而停止；自动重试仍有次数限制，也可以主动停止当前任务。自定义时限、通知生成和连接检测可能更短。超时不证明模型没有思考，暂时没有正文也不证明请求已经失败；旧版本可能在更短时间内中断。反复等待后仍失败时，生成诊断包帮助区分请求前准备、连接等待与回复收尾。
- 在支持持续接收模型活动的版本中，整理长会话不要求在固定的短时间内完成；只要仍收到模型活动，就可以继续等待，也可以停止当前任务。整理过程有次数和处理量限制，不会无限重试；只有完整摘要通过检查并被后续请求采用，才会保存为有效上下文。持续活动本身不代表整理已经成功。
- 如果提示会话压缩失败，表示整理已有会话的步骤未完成，本次运行暂停；这不等于刚发送的内容太长，也不代表整个会话无法再使用。提供“压缩后继续”的版本会保留原历史和已完成结果；点击后会先尝试整理，再承接原任务，无需重述已保存目标。仍可在原会话补充新指令或编辑重发。旧版本可能只显示“继续任务”或重试入口；持续失败时，从“设置 → 帮助与反馈”生成诊断包。
- 如果提示缺少可靠的上下文用量证据，可以按界面尝试“压缩后继续”；这不等于服务已确认输入超限。如果明确提示压缩后必须保留的输入仍超过预算，或压缩已达到处理上限，请调整任务范围、输入或模型容量后继续。自定义连接的容量应按服务实际支持值填写，增大配置值不会提高真实容量。旧版本可能统一建议减少本轮输入；不要据此认定短消息本身就是原因。
- 在支持失败重发恢复的版本中，编辑并重发一旦受理，即使尚未出现正文便失败，修改后的请求仍会保留。按错误提示修正输入或配置后再继续；刷新或重新打开会话不会撤销已受理的修改。
- 如果明确提示“当前模型不支持会话压缩参数”，请切换到另一已配置模型，或在“模型与凭据”中核对自定义连接的模型配置，再继续任务；仅等待后原样重试不一定能恢复。
- 回复正文出现前显示“准备回答所需内容花了较长时间”或“暂时没有收到新的模型活动”时，当前请求还没有被判定为失败：模型可能仍在准备、推理或处理，也可能已经停滞。短暂出现可以继续等待；长时间不再更新时可以停止当前回复后重试。同一模型反复出现时，再按本节检查调用渠道，必要时生成诊断包。
- 保存或更换 DeepSeek、Kimi Key 时会先在线校验。显示“已配置 · 已验证”表示校验成功；只显示“已配置”时，可以点击“校验当前凭据”重新取得结论。
- 选择模型时如果提示凭据尚未配置，本次选择不会保存。点击提示中的“配置凭据”或“模型与凭据”，完成对应渠道的 Key 配置后再选择。
- 显示“凭据有误”时，当前 Key 已在保存校验或实际模型请求中被确认无法鉴权；修改后重新保存。保存校验失败不会覆盖原配置。
- 网络或调用渠道服务暂时不可用时，可以稍后重试；只有确认“仍然保存”后，暂时无法校验的候选 Key 才会替换原配置。
- 401 或鉴权失败：Key 错误、已撤销或来自不兼容的平台。
- 如果刚更换 Key 后立即出现“请求格式或参数错误”，也应先回到供应商控制台确认 Key 可用并重新复制，避免错误提示掩盖鉴权失败。
- 余额或额度错误：到对应平台控制台检查账户及当前 Key 的用量、余额和服务状态。权限错误则应检查当前 Key、模型和调用路由是否允许这次请求；仅换一枚同权限的 Key 或反复重试未必有用。
- 旧会话仍使用 OpenRouter 且请求失败时，可切换已配置的 DeepSeek 或 Kimi。OpenRouter 暂不维护，不要为了排查重新购买额度或寻找已隐藏的配置入口。
- 请求过多或服务繁忙：稍后重试；持续出现时查看供应商状态。
- 提供细分错误提示的版本中，“原因尚未确定”表示现有信息不足，不能据此认定是网络、余额或服务过载。请检查连接配置，持续失败时生成诊断包；不要因为这条提示反复充值或更换 Key。
- 明确提示请求未通过本地校验、没有发送请求时，先修改模型配置或请求参数。提示返回内容不符合预期协议时，表示本轮收到的内容无法按当前连接协议继续处理；不能仅凭这条提示判定模型能力不足。先从“设置 → 帮助与反馈”生成诊断包，保留发生时间，再检查自定义连接的协议兼容性或切换已配置模型。提供协议异常诊断的版本会保留必要的失败线索；旧版本可能没有记录具体原因，随后重试成功也不能还原上次失败现场。只有明确的上下文超限才按提示缩短输入或切换更大上下文的模型。
- 会话压缩失败时，较新版本会同时说明可识别的具体原因；先处理对应的额度、权限、配置或连接问题，再继续任务。保留原历史不表示后台压缩已经成功。
- 只有某一调用渠道失败：切换另一已配置模型，区分账号问题与本地通用问题。
- 如果界面显示“正在重试”，先等待自动恢复，也可以停止当前任务。提供五次重试的版本会显示“1/5”至“5/5”；这是首次请求之外的重试次数，旧版本的次数可能不同。凭据、权限或余额问题仍需要先处理原因。
- 支持自动恢复部分输出的桌面对话版本，重试时可能替换尚未完成的文字片段；此前已完成的步骤和工具结果会保留。不要仅因文字变化就重新执行已经完成的操作。语音等入口不一定支持相同恢复方式。
- 失败后若出现“继续任务”，点击可从已有结果继续剩余工作，后续仍可按当前权限使用工具。同一任务的恢复过程会更新当前状态，不需要重复点击。若只看到旧版“继续整理”，其能力可能仅限整理已有结果；需要执行后续操作时，可更新产品或明确发送后续要求。
- 工具是否已执行、外部操作是否完成尚不确定时，先核实执行状态，不要直接重复付款、发布、删除或其它可能产生副作用的动作。没有继续入口时，先处理显示的原因，必要时生成诊断包。
- 主动停止、重新打开会话或重启应用不会自动重新执行任务。检查保留的进度后，再按当前界面提供的方式主动继续。

## 记忆没有更新

- 当前对话理解了某条信息，不等于它已经成为长期记忆。后台处理可能仍在等待模型，或因连接、额度、返回内容不完整等原因没有成功；具体等待与恢复边界见[长期记忆](using-agent-friend.md#长期记忆)。
- 提供记忆正确性修复的版本会保留未成功处理的素材；某条本地素材损坏或与较新的资料冲突时，会暂停处理该条，让后续正常素材仍有机会继续。暂停的素材不会靠重启自动修好，也不会自动补齐所有历史资料。
- 核心身份资料暂时不可用时，普通长期记忆与对话仍可能继续工作；不能仅凭一次回答就断定全部记忆已经丢失。
- 已明确说明稳定信息、后续也正常交流但仍长期未更新时，从“设置 → 帮助与反馈”生成诊断包，并说明大致时间、会话、通过文字还是附件提供了信息。保留原记录，不要自行删除记忆文件；提供诊断包前检查私人内容，分享边界见[诊断包](data-and-privacy.md#诊断包)。

## 会话一直显示等待、继续或取消中

- “任务正在等待处理”表示本轮已经进入队列但尚未开始；不要在同一会话重复发送，等待当前任务开始或使用页面提供的停止入口。
- “任务仍在继续”表示整轮尚未结束。某条消息、工具或本地命令已经完成，不代表 Echo 已经完成最终回复；完成前，当前 Echo 消息底部的完成时间戳和复制操作不会出现。提供用时行的界面可同时显示“已进行 xx”，它表示本轮执行时长，不是完成标记。
- “正在取消当前任务，任务尚未结束…”表示停止请求已经接受，但任务仍在清理。等待状态收口后再发送下一条；如果长时间没有变化，重新打开该会话确认状态，仍不恢复时生成诊断包。
- 较新版本中，若输入尚未被接收就停止或准备失败，内容会回到草稿；若你已补写了新内容，两部分会一起保留。重试前先检查并整理草稿。已经接收的输入仍保留在会话中，不能仅凭“还没看到回复”判断它没有发送成功。
- “这段对话正在其他入口处理中”表示语音、QQ 或其它入口正在占用当前会话。请回到原入口停止或处理，或者等待完成；桌面端不会提供必然失败的停止操作。
- 应用短暂断线或刚启动时可能显示正在恢复运行状态。连接恢复后仍长期停留、侧栏与输入区状态相互矛盾，或任务已经结束但授权卡、命令状态仍未消失时，从“设置 → 帮助与反馈”生成诊断包，并注明大致发生时间和会话。
- 窗口短暂断开后，仍在运行的任务可以重新接回原状态，不会因此重复执行。电脑重启、应用完全退出或后台进程意外结束后，已经完整记录的模型上下文会随历史会话恢复；这只说明本地前缀可以继续，不代表模型供应商一定会给出 Prompt Cache 命中。
- 如果退出发生在回复流式生成中，只会恢复到最近一次完整记录；如果本地命令执行中断，产品会尽量恢复中断前已经保存的部分输出，并明确标记为“不完整、结果未知”，不会自动重放原命令。部分输出不能证明命令成功或失败；若中断前可能已经产生文件修改、消息发送等外部结果，先检查实际结果再决定是否重试，避免重复操作。

## 已连接但会话列表尚未出现

- 初次打开对话窗口时，连接状态变为“已连接”后，会话列表仍可能需要一点时间才能出现。若侧栏显示灰色占位条，表示列表尚未加载完成，不表示历史会话被删除。
- 如果显示“会话列表加载失败”，点击“重试”。如果显示“连接恢复后将加载会话”，等待连接恢复，列表会自动重新加载。
- 已有会话列表在后台刷新或短暂断线时会继续保留。
- 重试后仍然失败，或列表出现后仍找不到原来的会话时，保留当前数据，从“设置 → 帮助与反馈”生成诊断包，并注明大致发生时间和界面提示。

## 历史加载失败但仍显示授权模式

- 历史加载失败时，输入区仍可能显示之前保存的“每次授权”或“本会话无需授权”。显示授权模式不代表历史已经恢复，也不表示当前任务已经获准执行。
- 不要通过切换授权模式来修复会话读写错误。重新打开该会话后仍失败时，保留当前数据，从“设置 → 帮助与反馈”生成诊断包，并注明大致发生时间和会话。
- 如果失败前的任务可能已经修改文件或产生其它外部结果，先检查实际结果，再决定是否重新发送任务，避免重复操作。

## 执行过程没有折叠或用时显示未知

- 若当前版本已提供用时行，没有箭头通常表示这轮不支持折叠或没有可收起的过程；不是只要换成某个模型，旧会话就都会变成可折叠。
- 本轮尚未成功结束、没有可靠最终回答、被停止或失败时，不会自动收起过程。仍有等待或取消提示时，任务尚未结束；不要把正文里某段收尾措辞当作完成信号。
- 刚发送或排队期间，计时行暂不出现是正常表现，实际开始后才计时。旧记录或异常退出缺少可靠时间时显示“用时未知”，不表示所有消息丢失，也不会为补计时自动重跑任务。
- 需要查看已收起的文字时，点击用时旁的箭头。搜索与引用导航也会尝试展开命中的过程并定位；使用边界见[执行过程与用时](using-agent-friend.md#执行过程与用时)。

## 找不到 OpenRouter 或 K3

- OpenRouter 的模型选择和凭据设置入口已隐藏，存量设置不会因此自动删除，维护状态见[模型凭据](model-credentials.md)。
- Kimi K3 在模型列表中显示为 `kimi-k3`。旧安装版本可能尚未提供；以当前界面为准，不要把其它 Kimi 模型的推理档位当作 K3 的档位。

## 文件链接打不开或找不到文件

- 支持文件链接菜单的版本会在点击时说明失败原因。文件已移动或删除时，先复制链接或完整路径，核对原位置；不要把其它目录的同名文件当成原目标。相对路径缺少可靠目录时，可以请 Echo 提供完整路径。
- 文件存在但提示没有访问权限或无法打开文件夹时，可以复制路径，在系统文件管理器中检查访问情况。链接菜单不会自动放宽文件权限，也不代表 Echo 已获得读取权限。
- 附件定位到的是应用保存的副本；跨会话或已失效的附件引用可能不可用。回到附件所属会话核对，必要时重新上传正确文件。
- 看见 Markdown 原文而非可点击链接时，当前渲染器可能没有识别该写法；含空格或特殊字符的目标可以请 Echo 改用正确编码的文件地址。不支持的协议或当前设备无法处理的路径不会自动改开相似目标。
- 旧版本可能没有文件右键菜单，或点击本地链接没有反应。更新到提供该能力的桌面版本后再试；更新使用指南不会替代更新应用。

## 之前上传的文件无法继续读取

- 先回到上传文件的原会话，请 Echo 列出本会话文件并重新读取。上下文整理不等于原件已删除；此恢复方式需要提供会话文件能力的版本。
- 提示原件缺失或完整性校验失败时，重新上传正确文件或恢复本地原件。不要把其它目录中同名或相似的文件当成上传原件，也不要仅凭早先摘要断言已经重读过文件。
- 提示工作目录容量不足时，可在确认文件用途后清理本会话不再需要的处理产物，再重试。容量和读取方式见[会话文件说明](using-agent-friend.md#在后续对话中继续读取上传的文件)。
- 其它会话的附件不能通过当前会话文件列表读取；请回到对应会话，或把需要的文件上传到当前会话。

## 附件不能添加或发送

- 提供统一会话文件附件的版本接收任意类型，不按模型原生格式拒绝。提示文件处理能力不可用时，检查模型工具调用能力及本地命令环境。Windows 提示需要初始化沙箱时，前往“设置 → 系统权限”处理。旧版仍可能有格式限制。
- PDF 扫描页没有可提取文字，或需要观察图表时，确认当前模型支持本地图片读取。没有视觉证据不能把文件名、空文本或局部读取当作全文理解；可切换支持看图的模型或提供所需页的文字。应用不会为此自动发送整份 PDF。
- 检查应用的单文件大小、总大小、单轮数量和工作目录容量限制；具体数值见[模型与附件](using-agent-friend.md#模型与附件)。文件已保存但没有解析工具时，可以提供可读取的导出格式，不要把解析失败当作上传失败。
- 统一会话文件附件不因切换模型而要求移除格式不兼容的文件。模型仍须支持工具调用；看图被明确拒绝时，选择支持视觉的模型或提供文字，不会自动切换模型。旧版可能仍提示原生附件不兼容。
- 文件已上传成功且文件处理能力可用，但不输入文字时发送按钮仍为灰色，可能是旧版纯附件发送问题；更新到提供该修复的版本后再试。正常情况下无需为了发送附件而补写文字。

## Echo 无法读取本地图片

- 先确认当前版本提供“读取图片”，并检查[模型支持条件](model-credentials.md#本地图片读取的模型支持)。附件可添加不代表本地看图工具可用。
- 提示权限不足时，核对授权卡片是否包含目标文件和“读取图片”。只有读取文本权限时，需要重新申请图片权限。
- 提示格式、损坏或超限时，换用有效的静态 PNG、JPEG、WebP，或先缩小图片；具体限制见[本地图片读取](using-agent-friend.md#让-echo-查看本地图片)。反复提交同一个无效文件不会解决问题。
- 旧图片暂时不可见时，可以请 Echo 恢复此前保存的图片；快照缺失或损坏时重新提供有效图片。模型明确表示未收到图片时，不要把已有文字描述当作重新观察原图的结果。

## 搜索、地点或天气不可用

- 联网搜索检查 Tavily Key。
- 附近地点检查高德 Key 是否为 Web 服务类型。
- 天气检查和风 API Key 与账号专属 API Host 是否同时填写，Host 不带协议和路径。
- 保存后等待对话服务自动应用；任务占用服务时，结束任务后点击“重试应用”。

## 语音输入修改后重复或停止续写

- 先检查草稿，删除重复内容；较早版本可先停止语音输入再改字，然后重新开启。
- 提供混合输入修复的版本中，若提示“语音续写无法对齐”，当前修改会保留，此次听写会停止。重新点击麦克风后补说未写入的内容，无需重说整段。
- 正常混合输入与光标续写的操作见[使用方法](using-agent-friend.md#语音)。

## 语音不可用

- 先在“设置 → 系统权限”确认麦克风权限。
- 语音输入可用新版 APP Key，或旧版 APP ID + Access Token。
- 语音通话需要 AK、SK、RTC AppID、RTC AppKey、语音 APP ID、语音 Access Token 全部就绪。
- 火山语音凭据当前只检查字段完整性，不做在线校验。确认相关服务已开通且可用，再保存并等待语音服务自动应用。

## Windows 命令沙箱弹窗或突然不可用

提供沙箱自动恢复的版本中，已获准的命令遇到可恢复环境故障时，会在原操作内等待修复并继续，不需要重复批准命令或另发“继续”；必要的 Windows 管理员确认仍可能出现。修复期间仍可停止任务。多个任务会共享恢复，健康的在途命令不会为此被强制结束。拒绝系统确认、取消任务或恢复超时后，不会反复自动提权。

只有操作已经明确失败，或所用版本尚未提供自动恢复时，再进行下列手动处理。如果 Windows 弹窗指向 `codex-windows-sandbox-setup.exe`，提示“找不到指定的模块”，或沙箱持续不可用，可尝试：

1. 停止当前失败的任务，从系统托盘正常退出 agent-friend，再重新打开；只关闭主窗口不等于完整退出。
2. 打开“设置 → 系统权限”，点击“重新检测”，查看“Windows 命令沙箱”的状态。需要初始化或修复时，点击“开始准备”，按提示完成 Windows 管理员确认。
3. 确认沙箱显示“可用”后，回到会话检查之前的执行结果，再重新发起尚未完成的操作，避免重复已完成的操作。

已有用户通过重启并修复权限恢复使用，但这不是对所有同类弹窗都有效的保证，也不能仅凭弹窗认定缺少某个运行库、用户取消授权或某一方的软件缺陷。无需先重装产品、删除数据或改用不受沙箱限制的执行方式。

如果仍不能恢复，或短时间内再次出现，请保留完整弹窗、发生时间和系统权限页的错误提示，并在“设置 → 帮助与反馈”生成诊断包；说明重启和权限修复各自是否有效，分享前检查私人内容。不要照搬其它产品的代理配置、沙箱状态文件删除或降低隔离的处理办法。

## 本地命令或 Skill 脚本无法运行

- 提供自动恢复的版本中，命令获准后会尝试准备或修复 Windows 沙箱；出现系统管理员窗口时按需确认，等待原操作返回即可。较早版本若授权提示需要准备沙箱，仍需点击“前往系统权限”完成准备。若最终提示启动结果未知，先核对现有进程和结果，不要直接重放可能已经执行的操作。
- 授权按钮位于输入框上方，不在历史工具卡片内。多个请求会在同一位置逐项出现；当前项处理完成后再检查下一项。
- 点击命令卡上的“仅本次允许”后，等待“处理中…”结束，不要连续点击。出现“暂时无法确认授权结果”时，先查看提示和当前任务状态；卡片仍待处理且按钮恢复后，再按需要重试。出现“这项授权已处理或已失效”时，旧卡会撤下，应查看任务结果或新的授权请求，不要继续提交旧请求。较早版本点击后长期没有反馈时，先更新 agent-friend。
- 输入区显示橙色“本会话无需授权”时，后续普通请求不会再逐项弹卡片；需要检查每一步时，直接从同一入口切回“每次授权（推荐）”。
- 如果提示灾难性动作已在本会话免授权模式下被拒绝，先切回“每次授权”，重新检查并发起准确目标，再只批准当前请求。不要通过改写等价命令、变量、通配符或间接脚本绕过拒绝。
- 切换授权模式失败或提示会话状态已经变化时，重新打开当前会话或等待连接恢复后再选择。失败不会把会话留在半切换状态，也不会批准已经等待的其它卡片；切换成功时，普通等待项会按原卡片显示的完整范围自动允许，灾难性请求仍会拒绝。
- 如果输入框上方没有出现授权，确认当前操作来自桌面聊天。不能展示授权的入口不会启动本地命令。
- 模型产生无效工具参数时，对应工具不会执行，也不会发起授权；Echo 会在当前任务内尝试纠正，而不是仅因参数错误重复出现就停止。若本轮最终仍出现明确错误，再按提示重试或切换模型。
- 更新 GitHub Skill 时若提示存在本地修改，或同名目录没有来源记录，覆盖会替换整个旧目录，不会自动合并。使用“每次授权”时，在授权卡核对 Skill 名称、来源、内容摘要与丢失本地修改风险后再决定；使用“本会话无需授权”时，普通替换不会重复弹卡，表示你已经接受本会话内的普通覆盖风险。不想继续时先切回“每次授权”或停止当前任务。下载失败、候选校验失败、来源冲突或替换期间内容发生变化时，原 Skill 会继续保留。
- 如果提示来源冲突，不要改用强制参数、手工删除来源记录或逐文件覆盖。受管理更新只能继续使用记录中的同一 GitHub 仓库和目录；确实需要另一来源时，应保留现有 Skill 并另行确认迁移方案。
- 如果明确提示“命令运行时不可用”，先完整退出并重新启动当前 agent-friend；开发环境需要重启 dev。重启后仍不可用时，更新或修复产品安装。重复申请文件授权或寻找所谓“全局系统权限”不能恢复命令运行时。
- 如果明确提示“受管 Python”或“执行环境”不可用，普通聊天仍可继续，但当前 Python 脚本和依赖操作不会执行。先完整重启 agent-friend；仍不可用时更新或修复产品安装，并从“设置 → 帮助与反馈”生成诊断包。安装系统 Python、启用 Windows 应用执行别名、修改 `PATH` 或切换用户虚拟环境都不能修复产品受管环境。
- Python 依赖安装提示没有兼容分发物、需要源码构建或安装方式不受支持时，改用提供当前平台兼容 wheel 的版本或其它依赖。不要通过 editable、VCS/URL、requirements 文件、自定义包索引或关闭完整性检查绕过限制。
- 从公开包源安装失败时，先确认本次授权允许联网和写入当前会话环境，再检查网络、磁盘空间与包源可用性。本地 `.whl` 仍需先获得对应文件读取授权；失败后不会退回系统 `pip`。
- 如果重启或进入下一轮后提示 Skill 尚未启用、文件授权已失效，请重新发送当前要完成的任务，并处理这一轮新出现的授权。历史中的“已加载”“已允许”不代表当前轮仍可复用。
- 授权前检查命令、目录、文件访问范围和联网权限。拒绝、授权超时或路径在批准后发生变化时，命令会按安全策略停止；不要要求 agent 绕过沙箱重试。
- 可信桌面程序如果确实无法在普通沙箱运行，agent 可能请求“宿主用户（文件和网络不受限）”。该级别不会从普通沙箱静默降级获得；确认程序来源和完整参数可信后再允许。
- Windows PowerShell 5.1 脚本在当前沙箱中可能无法启动。可用同等的 exe、cmd 或 bat 入口；确实需要 PowerShell 时，使用 PowerShell 7（`pwsh.exe`）。带有内置 PDF/截图环境的较新 Windows 版本会优先使用产品自带版本，无需自行安装；旧版本以实际可用环境为准。
- PDF 或截图提示产品自带工具缺失、校验失败或读取权限准备失败时，该命令不会启动。先更新或修复 agent-friend，仍失败则生成诊断包；不要把安装系统 Python、复制 DLL 到系统目录或关闭权限检查当作默认修复方式。
- 出现 Python 启动错误或“找不到 python312.dll”弹窗时，保留完整错误和发生时间。它也可能来自运行环境不可访问，仅凭弹窗不能判断文件真的缺失。截图脚本若提示无法设置默认保存目录，请明确指定本次授权目录中的输出文件，再重新发起任务。
- 没有更优先的授权或平台登录请求时，可在输入框上方查看运行中命令的状态和停止入口；失联、超时或取消后，可展开对话中的对应活动项查看明确终态。若进程长期没有结束，先取消当前任务，再从“设置 → 帮助与反馈”生成诊断包。
- 活动项显示“Agent 已终止”表示 Echo 主动结束的目标命令已经确认停止，不等同于命令自然完成。若 Echo 准备重启或替换命令，但原活动仍显示运行中、终止失败或运行时失联，先停止当前回复并核对详情，不要把替代命令当作已经安全接管；反复出现时生成诊断包。

## 定时任务没有运行或结果异常

- 提供“定时任务”页面的版本中，先打开任务详情和运行历史，确认启用状态、目标会话和下次执行时间；也可以请 Echo 查询。归档目标会话会暂停任务，恢复会话后需要显式恢复任务。旧任务提示缺少目标时，先编辑并选择有效会话。
- “等待”表示尚未开始；同一会话正在处理其它请求时需按顺序等待。已经开始准备或整理上下文不属于等待队列。执行完成后可点“查看消息”跳到目标会话；较早版本的独立运行仍可能只能通过对话查询历史。
- agent-friend 完全退出时不会执行定时任务，也不会留下独立后台服务。重新启动后只会考虑过去 7 天内最近一个错过的计划点；更早或连续错过的计划不会逐次补跑。
- 如果上一次运行仍在进行或等待批准，同一任务的新计划点会被跳过。先处理当前授权或等待运行结束，再根据历史决定是否“立即运行”。
- 文件、命令和 Skill 脚本仍需要正常授权。没有看到授权入口、拒绝、超时或取消时，任务不会绕过权限继续；可以请 Echo 查询该次运行是否正在等待批准。
- 任务绑定的 Skill 已删除、损坏或与其它来源冲突时，本次运行会失败。先在 Skill 管理入口确认精确 Skill 可用，再修改任务或重新运行；不要安装另一个同名 Skill 试图绕过来源检查。
- 一次运行失败、取消或应用关闭后，不会自动重放整个工作流，以免重复外部副作用。提供固定会话请求的版本会把关闭前正在等待或执行的请求标为中断；确认前一次实际结果后，再决定是否立即运行。

## 桌宠通知没有出现或没有声音

- 以下适用于提供“设置 → 通知”的版本。没有该入口时，先更新 agent-friend；较早版本的待办“提醒发送方式”可能仍在“通用”中。
- 没有新回复气泡时，先检查“会话新回复”是否为“不提示”。默认“未查看该会话时”会在你正在前台查看对应会话时省略额外气泡；需要比较时可改为“始终提示”，再观察后续新回复。
- 需要授权或发生异常却没有气泡时，检查“需要你处理”和“异常结束”是否开启；同时回到对应会话查看实际状态。主动停止回复不会额外发出异常通知。
- 待办没有额外提示时，检查同页“待办提醒”的“提醒发送方式”。“智能选择”可能不额外发送，先到对应会话核对提醒历史；设置含义见[通知设置](settings-reference.md#通知)。
- 气泡已经显示但没有声音时，先检查“气泡提示音”是否开启，以及系统音量和输出设备。使用“默认”时还需检查 Windows 消息提示音设置。关闭气泡导致后续消息补位，或同一通知重新显示时，本来就不会再次响铃。
- 提供“选择音频”的版本可以主动试听当前音源。导入失败时，确认文件是可播放的 MP3/WAV，且不超过 10 MiB、30 秒；取消或失败不会替换旧音源。提示正在备份或迁移时，等操作结束后再更换。
- 自定义提示音丢失或损坏时，通知会尝试使用默认提示音，设置页会提示问题；可以重新选择原音频，或点击“恢复默认”。找不到“选择音频”时，当前版本可能尚不支持自定义音源。
- 持续出现气泡缺失、重叠或声音异常时，保留大致发生时间与相关会话，从“设置 → 帮助与反馈”生成诊断包；分享前检查私人内容。

## 桌宠闪烁或卡住时保留运行记录

- 如果“设置 → 帮助与反馈”中有“桌宠显示异常记录”，发生问题后可点击“保留最近异常记录”，看到“异常记录已保存在本机”后再生成诊断包。记录默认在本机持续保留，无需事先开启调试，也无需为保留记录重新制造故障。
- 已经退出或重启也可以生成诊断包，尚未过期的历史和已保存片段仍可能可用。尽量说明发生时间、退出桌宠后是否停止、重启后是否恢复；这些信息帮助关联记录，不要求先截图。
- 提示“暂时无法确认记录已保存”时，不把它视为保存成功；仍可生成诊断包提供已有历史和缺失说明。这些记录帮助缩小排查范围，不保证每次可见闪烁都能被自动识别或还原。保留期限与隐私边界见[数据与隐私](data-and-privacy.md#桌宠显示异常运行记录)。

## Windows 桌宠暂时消失、白屏或桌面变黑

- “设置 → 桌宠 → 显示器恢复保护”默认关闭。只有主动开启后，agent-friend 才会在息屏恢复时暂时隐藏桌宠，等待显示器和缩放状态稳定；通常数秒后会自动恢复。
- 如果恢复画面检查没有通过，agent-friend 会让桌宠保持隐藏，避免遮住整个桌面。确认桌面正常后，可从系统托盘选择“显示桌宠”重新显示；如果反复发生，可关闭“显示器恢复保护”。
- Windows 图形渲染进程异常退出时，即使没有开启“显示器恢复保护”，agent-friend 也会隐藏桌宠。提供新版故障隔离的版本会在有限时间内保留诊断证据，然后尝试一次受保护的应用重启，不再仅凭截图正常就自动重新显示桌宠；旧版本可能仍采用画面检查后恢复的方式。重启可能中断正在进行的回复或通话，请恢复后检查会话进度。
- 自动重启有冷却限制；短时间内再次出现故障时，桌宠可能保持隐藏。确认桌面正常后，可以从系统托盘选择“显示桌宠”；若再次出现异常，请完整退出应用，并按下方步骤提供诊断包。自动重启不代表显卡或系统层面的故障已被修复。
- 如果整个桌面持续黑屏、桌宠区域持续白屏，或自动恢复后仍反复发生，先退出 agent-friend 恢复桌面。恢复后尽快在“设置 → 帮助与反馈”生成诊断包，并注明大致发生时间、显示器数量，以及其他浏览器或应用当时是否也有异常。无需提前开启取证；最近一次息屏恢复或渲染进程事故证据会随你主动生成的诊断包自动包含。
- 不要为了复现而反复强制息屏，也不要把关闭显卡加速、修改驱动或停用安全软件作为首选排查方法。

## 桌宠鼠标命中或点击穿透异常

桌宠点不到、点击位置偏移，或透明区域影响桌面点击时，请记下大致发生时间、显示器数量，以及此前是否调整过显示缩放或移动过桌宠，再从“设置 → 帮助与反馈”生成诊断包。仅排查此类问题无需选择聊天会话，也无需为了取证反复重现问题。

支持输入诊断记录的版本可以导出已经保存在本机的历史。即使桌宠页面无响应，只要设置等现有反馈入口仍可使用，就可以生成诊断包；问题恢复后也应尽快导出。旧包没有输入记录、记录已过期或存在缺口，都不能证明问题没有发生。保留范围与隐私说明见[数据与隐私](data-and-privacy.md)。

## 迁移或恢复失败

- 确认是 Windows 到 Windows。
- 确认迁移包与对应 12 词迁移码匹配，文件没有被修改。
- 确保磁盘空间足够，不要在恢复过程中退出应用。
- 恢复失败后检查“最近回滚备份”，不要先删除它。

## 需要进一步排查

在“设置 → 帮助与反馈”生成诊断包。只选择与问题相关的会话；附件原件和手动渲染截图默认不要包含。息屏恢复或渲染进程事故的最近一次渲染证据可能自动包含；ZIP 不会自动上传，发送前仍要手工检查私人内容。

## 诊断包提示部分内容获取失败

这表示 ZIP 已生成，但某些证据有缺失，不表示整个压缩包损坏。先查看生成结果列出的具体项目；可用内容仍在包中。提供完整导出的版本不会因会话、日志或附件原件达到导出体积上限而截断。旧版可能仍有上限，完整采集方式见[数据与隐私](data-and-privacy.md)。

过去未成功采集的屏幕截图、已删除的文件或已淘汰的记录无法靠重复导出补回。新版会把旧的桌宠输入诊断元数据缺口保留在包内记录，不再仅因该历史标记将本次导出判为失败；实际读取失败仍会提示。

## Windows 沙箱反复初始化失败或提示缺少模块

- 出现“找不到指定的模块”等系统弹窗时，从“设置 → 帮助与反馈”生成诊断包，并提供发生时间和当前应用版本；已有截图可以一并保留。仅凭这句话不能确定缺的是哪个模块，也不能确定是你取消了操作。提供独立沙箱故障记录的版本会自动在本机保留有限证据，已经手动修复或重启也可尽快导出，无需为采集证据反复复现故障或选择聊天会话。
- 回到“设置 → 系统权限”查看 Windows 命令沙箱状态，按页面入口完成初始化或修复。提供修复验证的版本会检查实际执行能力；修复失败时会继续保留需要修复的状态，重启应用不一定能消除该故障。
- 沙箱修复成功不表示原来的业务命令已经重新执行。先核对上一次操作是否产生了实际结果，再决定是否重新发起，避免重复操作。
- 沙箱可用但已授权的联网命令仍被拒绝时，请保留原错误和发生时间。初始化问题、联网策略拒绝和代理连接问题可能分别存在；不要通过关闭沙箱、扩大权限或反复初始化来替代定位。
- 旧版本可能没有新增的故障记录或修复验证。诊断包缺少相关记录不能证明未发生故障；持续出现时，将新诊断包与截图一起交给开发者。

## 联网命令或 Skill 更新失败

- 如果明确提示本地代理不可达、命令尚未执行，先恢复应用使用的代理；代理地址或端口已变化时，修正启动应用时使用的代理配置，并从系统托盘退出后重新启动 agent-friend，再重试原任务。无需为这类故障反复初始化沙箱，也不要通过关闭沙箱或绕开代理强行执行。此提示仅说明本地代理连接失败；代理可以连接也不保证外部网站可用。
- Skill 更新出现“路径过长”时，不等于下载失败或仓库不存在。请保留原错误和应用版本，使用包含路径兼容修复的版本重试；不要先删除已有 Skill。持续失败时生成诊断包交给开发者。
- 如果错误涉及安全连接或证书，不要关闭证书校验，也不必为了更新 Skill 修改整台电脑的 Git 设置。支持兼容重试的版本会针对特定 Windows 安全连接错误自动尝试一次；鉴权、证书和网络故障仍需按实际错误处理。

## QQ 只收到整理提示或部分回答

- 在支持回复续接的版本中，“正在整理较长对话，稍后继续回复。”会作为独立提示保留，正文随后另行发送；看到提示不代表回答已经完成。
- 如果原来的流式消息已经结束或不能再修改，应用会尝试用新消息接上尚未确认送达的正文；已有部分正文时，新消息以“接上条”开头，不会因为整理提示已经送达就放弃回答。网络结果不确定时，少量内容仍可能重复；平台限制也可能使续接失败，不能保证每次完整送达。
- 若长时间仍没有后续内容，回到绑定的原会话查看已保存的回答和运行状态，再决定是否继续或重试；不要反复发送相同任务。保留大致时间，从“设置 → 帮助与反馈”生成诊断包。更新指南本身不会为旧安装版本增加续接能力。
