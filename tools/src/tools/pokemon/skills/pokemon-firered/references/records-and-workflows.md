# 记录、查看和复用

所有命令通过绑定的 scripts/game.py，以 argv 传参并复用主 Skill 的权限。你自己维护记录，工具不读游戏内部状态，不自动辨认事实或判定记录过期。

## 一本玩家笔记

`knowledge` 默认返回当前页 journal、队伍/背包、经验索引和流程目录；`knowledge --section party --entity bud` 只读一个成员，`--section places --entity <地点名>` 查阅索引中的路线。`--all` 才展开全部旧记录。查询不按键、不截图、不传 output_images。返回的是你最后写下的内容，空记录表示没有记录，不等于游戏中不存在。按需要加 `--details` 查看字段来源、更新时间和推断标记，通常无需。

当前目标、位置或战斗、下一步和待确认事项统一写在 journal 当前页；它是可以整页替换的短草稿，不是每轮报告。party/bag 保存队伍、背包；places/notes 保存有复用价值的地标与经验，描述适用起点，不把过去停点称作“当前”。字段自由，文字、数字、列表都可以。使用稳定实体名，如 bud、potion；换位置不换身份。

旧 goals、notes.active_battle 和历史流水仍能按索引读取。首次接续旧笔记时，你根据最新画面与记录归拢当前页；确认无用的重复条目可删除，有价值的经验保留。工具不迁移事实、不判定哪条正确。后续不在多个位置重复维护当前目标或战斗。

`knowledge --data <JSON> --text <完整当前页>` 可在一次写入里更新多个条目并替换当前页；两项也可单独使用。data 未提供的字段保持原值，text 替换整页而非追加。字段 null 表示未知，实体 null 删除该条目。截图来源可选，可重复 `--source <截图编号>` 关联多张实际看过的图；计划和笔记无需截图。工具只检查来源存在，不替你验证文字是否符合图片。

绑定命令示例（值是格式示例，不是当前事实）：

```json
{"argv":["python","scripts/game.py","knowledge","--data","{\"party\":{\"bud\":{\"hp\":\"39/39\"}},\"bag\":{\"potion\":{\"count\":4}}}"],"skill":{"skill_id":"<当前可信 Skill ID>","entry":"scripts/game.py"},"access":{"filesystem":"read_write","network":"disabled","additional_roots":[{"path":"<status 返回的 instance_root>","access":"read_write"}]}}
```

JSON 只做外层工具参数要求的转义；数组里的每个参数不会再次经过 shell。不能把整个命令拼成一个 argv 元素。使用 `--certainty inferred` 可标记自己的推断；也可以直接写“剩余数量不确定”“战斗前的血量”等说明。

看到重要变化后自行更新；操作成功与否以返回画面判断，不因为发出了按键就减库存或记成已完成。明确的领取提示、治疗完成或物品使用结果也是观察证据，足以支持相应更新，不必再打开菜单证明同一件事。没有看到会改变记录的事件时正常使用自己的记录；只有缺失或不确定的信息会影响下一步决定，才额外查看。看到治疗完成可以记录已恢复；若确实需要未知的最大HP等具体数值，再查看队伍。截图只显示选中招式的PP时，不能推写其它招式的PP。

`notes --text <完整当前页>` 是替换同一 journal 的简便入口，省略 text 只读。需要同时更新队伍/背包时优先一次 knowledge 写入。一次决定或一组观察产生的变化整理后一起记，不要求每步落笔，也不必等结束才集中写长报告。未知且不影响决定的数值保留未知；结束前只保存必要的接续信息，不为了汇报遍查菜单或补齐精确数字。当前页最多8000字，不复制整份队伍/背包或每轮流水。

每次写入保留版本；可选 `--revision <查询版本>` 防止覆盖并发更新。stale_revision 表示版本冲突，需要重新查询，不表示游戏信息过期。单次更新最多16000字。删除示例：`{"notes":{"wrong_guess":null}}`。

## 第一次查看与后续一次调用

没有流程时，先用 act 打开队伍/背包，逐页看图、记录必要信息、退出。新的 act/wait 返回的 observation_id 也是成功操作的录制编号。记住每次结束编号，把实际走通且没有漏掉中间操作的一段存为流程。

`workflow-save --data '<JSON>'` 不操作游戏。JSON：

```json
{"id":"inspect-party","kind":"inspect","intent":"查看队伍后返回原界面","stages":[{"to":"<第一步返回的截图编号>"},{"to":"<第二步返回的截图编号>"}]}
```

最多 7 个连续 act/wait、输入最多 400 帧；长流程分段。dialogue/confirm-text 不录成无条件按键。inspect 必须包含返回开始界面。中间截图全部回传，最后一张是当前；读图后记录新信息，不自动从图片写事实。

默认逐步对比全图。inspect 对已识别的主菜单只检查右侧完整菜单及光标，忽略背后的地图；对队伍总览的输出和仅 B 退出检查总览布局及底栏，不要求 HP 等数值仍与旧图相同。若下一步要选队员，仍检查完整队伍图，不能把换了光标的画面当同一目标。未知布局保持全图检查。其它菜单可为**该步**指定 region/end_region（原图 [left,top,right,bottom]，至少 2400 像素），检查足以辨认界面、菜单项目和光标的区域。不能裁掉光标、目标对象或选择内容强行通过。路线不允许缩小全图检查。

后续调用（都加 `--name 流程名 --observation-id 当前编号` 并传 output_images）：

| 命令 | kind | 你已确定的意图 |
| --- | --- | --- |
| inspect | inspect | 查看队伍/背包/详情并返回 |
| use-item | item | 指定物品和成员，如伤药用于 BUD |
| switch | switch | 指定上场成员 |
| move | move | 指定招式，不能泛指自动战斗 |
| route | route | 已验证起点到终点 |

名称来自 knowledge 的 workflows 目录，须与当前意图一致；不能把同一流程用于不同成员/物品/招式。workflow_missing 时先手动完成首次示范。

move 的默认检查对已识别的战斗主菜单/招式菜单保留出战者名字、招式文字、属性、菜单布局和光标，忽略对手画面、HP、PP 数字及 PP 警示色变化；未知界面仍检查全图。流程只执行你这次选定的一招，结算后重新看图决定下一招。重复使用同一招且菜单链已走通时，可以把连续操作录成 move，减少重复开菜单；不需要为了录制而延长战斗。招式变化、光标不符或出战者变化时应重新核对，不能裁掉这些信息强行匹配。

start_or_cursor_mismatch 表示没继续该步；result_mismatch 表示该步已执行但结果不符。都应看返回图手动接管，**不从头重放、不自动退菜单**。completed 只表示检查点通过；用物品、换人或战斗结果仍须看图确认，再更新记录，不能仅凭按键减库存。

路线每步只录一次短方向（最多 32 帧，可带 B 跑步），不含 A、菜单或战斗选择。起点和朝向需正确；遇敌、对白、位置偏差立即停止，不补按键追赶检查点。长路线拆成地标清楚的短段。

## OCR 与保存

看不清字时可 `ocr --source <截图编号>`，传 output_images。只查本地 OCR，不动游戏；返回文字、位置、置信度、原图和同图的3倍像素放大。放大图不是新观察，记录仍用原 source。uncertain=true 不猜数值；高置信度也可能把数字、斜线识别错误。**非紧急用药前，若读到的 HP 与血条长度/颜色明显矛盾，先看放大图核对，仍不清楚就记未知；不要靠用药后的结果来验证先前的血量猜测。** OCR 只作辅助，不能覆盖原图。unavailable/pending 时也有放大图，直接看图，不反复等待。服务由宿主启动，玩家不安装依赖或另起后台任务。

checkpoint/finish 同时快照游戏记录与流程，独立 runner 共用记录源。玩家可以 saves 查询、load 读档重试；party/bag 回到存档的记录（没有则未知），保留自己的目标、地标、备注和已录制流程，由你判断这些经验是否描述当前进度。比如记得怎样捕捉不代表读档后已经抓到，记得物品位置不代表当前已经拿走。**AF 会话与本轮预算不会回退**。宿主的故障恢复仍按原来的配对恢复执行，与玩家主动读档分开。
