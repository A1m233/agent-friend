# 072 · 自然聊天实际发送结果尚未同步回模型历史

- **状态**：open
- **严重度**：medium
- **发现日期**：2026-11-06
- **关联需求**：[171 · 自主陪伴优化](../../requirements/171-autonomous-companionship-optimization/requirement.md)
- **处理决定**：用户明确移出 171，本次只登记，后续再推进。

## 现象

开启 IM 自然聊天后，原答会被改写并拆成气泡发送。后续模型只看到原答时，可能无法准确承接用户针对实际措辞、分段或未来表情包的回复，造成交流割裂。

本项覆盖普通回复和自主分享，不以表情包能力实施为前提。

## 根因初判

自然聊天的实际发送结果尚未作为有来源的记录进入模型历史。改写器计划输出、实际发出的内容以及投递状态需要区分，不能只把原答当作用户在 QQ 收到的内容。

## 影响与判断

用户已决定延期，并明确要求登记 issue。现有桌面原答展示和 QQ 自然聊天保持不变，不属于 171 未完成的实施项。

## 已有讨论与后续方向

完整讨论、候选提示词、代码锚点和风险盘点见[延期方案](../../requirements/171-autonomous-companionship-optimization/deferred-im-natural-history.md)，该记录尚未完成技术方案确认。

- 保留桌面原答，额外提供模型可见、前端不展示的结果块，明确关联原答并按顺序列出实际发送内容与状态；`role=assistant` 是已讨论方向，不是已定协议。
- 在公共系统说明中解释自然聊天及结果块，不仅放在跨会话发送工具中；不额外调用模型总结发送情况。
- 检查历史持久化、重启恢复、压缩、增量计量、引用、记忆抽取及前端投影的影响；不产生额外气泡、未读、通知或二次 IM 发送。
- 覆盖部分成功、超时、回执晚到、中途来信、重复回调和进程中断；未确认发送不等于送达，送达不等于已读，回写不能重复强化用户语义事实。
