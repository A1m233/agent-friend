# 001 · 记忆系统时间感太弱，被追问时间时模型靠编

- **状态**：open
- **严重度**：low
- **发现日期**：2026-06-09
- **关联需求**：008-engine-memory

## 现象

CLI（M2 demo）连续两次独立运行（第二次是重启进程 + 全新会话），两段对话实际只相隔几分钟：

- 会话2 开场："你好" → AI 回 "嗨，Alex！**好久不见**，最近怎么样？"
  - 跨会话记住名字 Alex（pinned）符合预期；但"好久不见"与"实际只隔几分钟"不符。
- 紧接着用户问："你说好久不见，我们上次什么时候见的" → AI 回 "嗯……说实话我有点记不太清了，**可能是前几天？还是上周？** 我就记得一直在跟你聊天。"
  - 被直接追问时间时，模型**编造**了"前几天/上周"，与事实（分钟级）相差很大。

## 根因初判

记忆系统提供给模型的时间信息很弱：

- 记忆库里**没有"会话级的上次见面/上次互动时间"这种信息**。008 抽取的是从对话里提炼的语义/情景事实（如"用户叫 Alex""养了猫"），不抽取"我们几点聊过天"这类会话元信息。
- 唯一的时间维度是 episodic 片段自带的 `ts`，且只被渲染成**相对后缀**（`最近 / 昨天 / N 天前`，见 `memory/src/memory/retrieval/renderer.py` 的 `_time_hint`），给不出"具体哪天/距今多久"的可回答信息。
- 因此当模型被问"上次什么时候见"时，手里没有可靠时间锚点，只能凭话术编一个。

## 影响与判断

- **不违反 008 任何 AC（硬保证未失守）**：
  - 跨会话记名字、连续感（不重新自我介绍）= AC-1 / AC-3，表现正确。
  - "上次见面时间"本就不在 008 抽取/存储范围 → 不属于 R-4.2.2 "确有记录却失忆"。
  - "我有点记不太清了"这类真人化措辞被 AC-4 明确豁免，且全程未暴露 AI 身份。
  - 时间话术归 persona（R-4.4.2），"好久不见"属 persona/模型自由发挥。
- **仍是体感弱点**：模型**编造具体时间**（"前几天/上周"）与 R-4.5.3"不编不藏"的精神有张力；记忆是"第一护城河"，被直接问时间却只能编，长期看伤拟人感。
- **为什么暂不修**：不阻塞任何 AC、不影响核心记忆正确性，优先级低；先记录，待 008 后续增强或相关需求推进时一并处理。

## 可选修复方向

1. **不改**：接受为 008 已知设计边界，仅留此记录。
2. **增强时间感渲染（偏 R-4.4.2）**：在注入的记忆上下文里补一条绝对/语义化的"上次互动时间"（如"上次和这位朋友聊天：约 5 分钟前 / 今天下午 / 3 天前"），让模型被问时间时有据可依。需要一个"会话级最近互动时间"的来源（可从会话流 / 记忆元信息派生）。
3. **persona 兜底话术约束**：在 persona 指引里加"不确定具体时间就别编日期"，把"前几天/上周"这类编造压下去（成本最低，但治标）。
