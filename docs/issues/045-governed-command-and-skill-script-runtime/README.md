# 045 · Agent 缺少统一受治理的命令与 Skill 脚本运行时

- **状态**：open
- **严重度**：medium
- **发现日期**：2026-08-06
- **关联需求**：[065-trustworthy-read-tools-and-tool-runtime](../../requirements/065-trustworthy-read-tools-and-tool-runtime/)、[076-agent-skill-system](../../requirements/076-agent-skill-system/)

## 现象

agent-friend 当前的工具运行时只能调用注册好的固定 Tool，不能像 Codex 一样通过通用命令能力启动本地进程，也不能运行 Skill 自带的 Python、PowerShell 或 shell 脚本。

Skill catalog 即使发现了 `scripts/` 目录，也只能把它作为资源元数据暴露给模型。脚本不会在 Skill 加载时自动执行，这是正确的；但当 `SKILL.md` 在任务运行期明确要求使用脚本时，Agent 仍没有可调用的公共执行能力。Codex 官方 `skill-creator` 随附的初始化、`agents/openai.yaml` 生成和快速校验脚本因此无法在 agent-friend 中运行。

## 根因初判

现有 `Tool` 协议和需求 065 的工具运行时面向受信任的固定实现，需求 065 还明确排除了执行任意 Python、JavaScript、shell 或用户程序。项目尚未定义本地进程执行所需的独立安全边界，包括命令准入、工作目录、参数与环境变量、解释器选择、文件和网络权限、审批、超时与取消、输出上限、退出状态及审计记录。

这不是 `skill-creator` 独有的问题，也不能靠在该 Skill 内封装一个私有 runner 正确解决。

## 影响与判断

- 需求 076 可以正确加载包含 `scripts/` 的 Skill，但本期必须把脚本执行标记为不支持，并在模型尝试使用时返回明确能力缺口。
- 依赖确定性脚本、构建工具、测试命令或外部 CLI 的 Skill 无法完成端到端工作流。
- builtin、个人和项目 Skill 若各自获得不同的执行旁路，会造成权限提升、跨平台行为和诊断语义不一致。

通用命令执行会显著扩大 Agent 的权限与攻击面，涉及桌面端审批、进程生命周期和跨平台兼容，不应塞进需求 076，也不应以“先让 `skill-creator` 能跑”为由做特例，因此按中等严重度的基础能力缺口登记。

## 可选修复方向

- 独立设计通用、受权限治理的命令或本地进程工具，由所有工作流和 Skill 复用；Skill 只声明何时需要运行哪个脚本，不拥有私有执行权限。
- 优先采用结构化可执行文件与参数列表、规范化工作目录和受控环境变量，避免让模型通过不透明字符串绕过准入判断。
- 明确 builtin、个人和项目 Skill 的信任来源，但不因来源是 builtin 就自动获得无限文件、网络或进程权限；最终授权仍由统一策略和必要审批决定。
- 提供超时、协作式取消、进程树清理、输出与日志上限、退出码和结构化失败结果，并覆盖 Windows、macOS 与 Linux 的解释器差异。
- 执行时绑定本轮已加载的 Skill 快照或内容版本，防止目录热更新后实际运行了未经本轮审阅的另一份脚本。
- 以官方 `skill-creator` 的初始化和快速校验脚本作为兼容性用例，同时补充恶意参数、越界路径、环境泄露、网络访问和取消残留进程等安全用例。
