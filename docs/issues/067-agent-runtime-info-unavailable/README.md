# 067 · Agent 缺少模型与上下文预算的运行信息查询入口

- **状态**：open
- **严重度**：low
- **优先级**：low（用户确认延后处理）
- **发现日期**：2026-10-05
- **关联需求**：[004-engine-system-prompt-composer](../../requirements/004-engine-system-prompt-composer/)、[005-engine-tool-calling-and-web-search](../../requirements/005-engine-tool-calling-and-web-search/)、[009-engine-context-management](../../requirements/009-engine-context-management/)

## 现象

用户希望 AF 能可靠回答当前使用的模型、上下文窗口和上下文占用，当前缺少面向 Agent 的统一查询入口。本次按主干 `607c50b6` 静态核对代码，未执行真实 LLM 对话复现，不将具体回答错误视为已验证现象。

- `agent/src/agent/conversation.py` 已持有当前模型配置，并通过 `_active_llm_client()`、预算快照和上下文观测记录窗口、token 估算、压缩触发阈值及最近一次输入 token 用量。
- 当前模型上下文装配已经提供日期、时区、交互端、通道、审批状态及工具能力等信息，但尚未提供模型与上下文预算的统一状态查询。
- `agent/src/agent/tools/factory.py` 已装配多类工具，但没有用于读取当前模型、有效窗口及上下文预算的专用工具。

## 根因初判

引擎已有部分运行数据，但尚未将模型身份和上下文预算组织为 Agent 可读取的当前运行快照。不能仅凭模型自身推理确认宿主实际选用的模型配置和窗口数值。

当前自我呈现已区分 `self_presentation_immersive.md` 与 `self_presentation_transparent.md`：沉浸模式倾向避免技术标签，透明模式允许说明 AI 身份和有证据的上下文来源。后续需要明确运行信息查询在这两种模式下的表达边界；不应再按旧版身份提示词推断当前一律禁止技术事实回答。

## 影响与判断

影响用户询问模型、窗口和上下文使用情况时的透明度，也限制 Agent 对自身运行约束的了解。现有引擎内部预算和压缩机制已经读取相关数据；本次没有发现该信息暴露缺口导致这些机制失效的证据，也未核定为既有需求 AC 违例。

用户认为优先级不高，明确要求先登记、以后再补。本 issue 记录当前设计弱点，不启动实现；后续若作为新增能力交付，再进入对应需求流程。

## 可选修复方向

- 可考虑只读的 `get_runtime_info` 工具，复用当前运行实际生效的模型配置、上下文预算及压缩观测数据；具体接口待后续设计。
- 数值应区分配置值、元数据、兜底值、估算和实际 usage，并注明快照时点。有效输入窗口不能直接表述为厂商保证的总窗口，最近一次输入 token 也不等于此刻精确占用。
- 与现有每轮模型配置快照、模型切换及上下文管理保持一致，仅返回必要字段，不暴露包含凭据的完整 provider 配置。
- 结合现有沉浸 / 透明模式，明确用户直接询问时如何准确表达已取得的运行事实；未取得的信息不猜测。
