# 046 · Agent 在原文读取失败后仍将二手消息归因于官方

- **状态**：open
- **严重度**：medium
- **发现日期**：2026-08-07
- **关联需求**：[073-agentic-research-navigation](../../requirements/073-agentic-research-navigation/)

## 现象

生产 bad case 的冷启动回放 `C19-05` 直接询问“明日方舟p3r联动什么时候上线”。搜索结果中，9 月或 9 月初来自 TapTap 社区帖和新浪转述；可见的一手账号内容只说明联动 SideStory 筹备中。

- 在 [首次冷启动报告](../../../agent_eval/reports/2026-08-06T17-32-01-cb5195d-C19-05.json) 中，Agent 成功读取了明确标注为非官方的 TapTap 页面，最终仍写成“官方说法还只到预计 9 月初上线”。
- 在 [ref-only 契约报告](../../../agent_eval/reports/2026-08-06T18-04-38-cb5195d-C19-05.json) 中，Agent 直接用 URL 调用 `web_fetch`，两次均被 fixture 拒绝；随后仍回答“消息来自鹰角在夏日嘉年华特别通讯中的官宣”。

另一个任务已决定把 `web_fetch` 收紧为只接受 `evidence_ref`。本 issue 不为 URL 调用增加兼容，也不重复实现该工具变更；待其合入后，以 ref-only 生产契约重新回放。

## 根因初判

模型把“官方宣布存在联动”和“社区或媒体转述预计 9 月上线”合并成了“官方预计 9 月上线”。当前 Prompt 已要求标题、摘要、正文和转述只证明对应来源表达了什么，但单次回放显示模型仍可能越过来源层级；在工具读取失败时也没有收缩结论。

同时，`C19-05` 当前自动 judge 只检查“社区 / 二手 / TapTap / 非官方”等字面锚点，首次报告曾出现自动通过、人工复核失败，不能单独用 pass rate 代表产品行为正确。

## 影响与判断

用户会把社区预测误认成官方时间窗口，影响时效性信息的准确性和对 Agent 取证能力的信任。该问题明显但可通过检查实际来源规避，暂定 `medium`。

当前先等待另一个任务的 ref-only 工具契约合入，避免在过渡接口上继续修 replay 或重复实现；本分支只固化行为契约和现有证据。

## 可选修复方向

- ref-only 工具改动合入后，保持原始 query 与同一证据快照重跑 `C19-05`，人工核对工具调用和最终归因。
- 在不引入工具侧可信度评分的前提下，继续收紧 Agent 的证据合成：没有一手原文时只能局部归因给实际来源，读取失败后必须降低结论强度。
- 为 `C19-05` 增加能区分“官方尚未公布日期”和“官方预计 9 月”的稳定判分能力，并将 runtime / fixture 错误与模型行为失败分开报告。
