# 066 · Windows 用户现场沙箱加载失败与联网恢复待验证

- **状态**：open
- **严重度**：high
- **发现日期**：2026-09-11
- **关联需求**：[124-windows-command-reliability](../../requirements/124-windows-command-reliability/requirement.md)

## 现象

用户电脑多次命令沙箱初始化失败，历史截图显示 `codex-windows-sandbox-setup.exe` 弹出“找不到指定的模块”。截图来自较早安装版本，用户确认近期弹窗应为同款；近期弹窗尚无精确时间和完整路径绑定，不能将旧截图直接当作新构建复现。

已有诊断记录四次独立失败（北京时间）：9 月 8 日 00:53、9 月 10 日 00:56、9 月 11 日 01:43 和 02:10。出现 `orchestrator_helper_launch_canceled` / ShellExecuteExW 1223 或 `orchestrator_helper_incomplete`；后续 sandbox unavailable 是下游表现，不另计一次根因。

另有显式请求联网的 HTTPS 命令得到代理 CONNECT 403；用户关闭自己的代理后仍出现。关闭个人代理不能排除产品受管代理或继承配置。

## 根因初判

用户弹窗的具体缺失或加载失败模块仍待定位。原生码 1223 不能证明用户点击了取消；静态 PE 直接导入未列出 VC runtime，也不能排除传递依赖或动态加载问题。没有证据将问题归因到某个 DLL、杀毒软件或用户操作。

已经确认并实施修正的产品机制缺口：受管网络未接入授权决策回调导致默认拒绝；就绪判断接受不完整或不兼容的状态；旧 vendor 校验未覆盖 Windows 配套助手。它们不等价于已经证实用户弹窗根因。

## 影响与判断

影响用户核心命令执行能力。需求 AC-1、AC-3、AC-7、AC-8 的现场或完整验收证据仍有缺口。用户明确决定先合入实现并推送，再将剩余工作登记为 issue，由用户随后打包给受影响用户；本 issue 保持 open，需求不标记整体完成。

## 继续处理步骤

1. 从包含上述合并提交的最新主干使用标准 package 入口生成候选安装包，记录源码 commit、build ID、安装包哈希和 Guide 基线，完成所要求的安装验证等级。此前 runtime-only 成功不替代 full-matrix。
2. 现场先保留当前失败截图、精确时间、应用版本与诊断包，再经用户授权安装候选包；不要先清理状态文件、账户或代理现场。
3. 在设置的系统权限页显式初始化或修复，观察有无系统弹窗、最终状态与实际命令探针；失败后重新导出诊断，核对构建身份、阶段、原生码、助手完整性及证据缺口。
4. 分别验证已授权联网和未授权联网；区分受管代理、继承代理、策略拒绝与上游连接失败，不通过关闭沙箱或扩大权限消除症状。
5. 修复成功后先核对原业务是否已有副作用，再单独重试原操作。沙箱 ready 不代表业务已恢复或完成。
6. 若仍弹缺模块错误，基于新事件的精确路径和原生码补充只读加载证据；新增现场采集或系统修改先取得相应授权，不预先指定修复 DLL。

## 关闭条件

取得 Windows 10 与用户电脑上“失败 → 候选版本修复 → 探针成功 → 原操作独立恢复”的证据；所需安装、网络和回归验证完成，并获得用户验收确认。只有本机通过、暂时未复现或新诊断采集成功，都不足以关闭本 issue。
