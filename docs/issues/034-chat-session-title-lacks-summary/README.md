# 034 · 历史会话标题缺少语义摘要,侧栏难以扫描

- **状态**：open
- **严重度**：low
- **发现日期**：2026-07-01
- **关联需求**：002-engine-session-management

## 现象

聊天窗口左侧历史会话列表里，多数条目显示为类似 `会话 2026-06-18 02:34` 的默认标题。列表条目连续出现时，侧栏更像时间戳日志，而不是可辨认的对话历史。

用户需要靠日期或逐个打开会话来判断内容，无法从列表第一眼看出每段会话讨论过什么。

## 根因初判

agent 侧当前已有 `TitleGenerator` 扩展点，但默认标题仍由 `agent/src/agent/sessions/manager.py` 的 `_default_title()` 生成，格式为 `会话 YYYY-MM-DD HH:MM`。

前端 `HistorySidebar` 只展示 session summary 里的 `title`，没有足够上下文自行生成语义标题。因此根因更偏 agent/session 层：会话创建或首轮用户输入后，没有把用户 query、会话摘要或标题生成结果写回可供列表展示的标题字段。

## 影响与判断

影响范围主要是桌面聊天窗口的历史会话可读性和侧栏观感。它不影响会话创建、切换、恢复或消息收发功能，但会让历史列表难扫描，尤其是会话数量变多后。

本次只做记录，暂不修复：标题生成涉及 agent 侧 session 元数据、首轮用户 query 捕获、可能的摘要生成时机，以及历史 session 兼容策略，不适合混入当前前端窗口/ActionBar 优化。

## 可选修复方向

1. 创建会话后，使用首条用户 query 作为初始标题，并做长度截断与空白兜底。
2. 在首轮或若干轮对话后，由 agent 侧生成短标题/摘要并写入 session summary 可读取的标题字段。
3. 若继续保持 `initial_title` 不可变，可新增 display title / derived title 字段，避免破坏现有 session 事件语义。
4. 前端只负责展示 agent 提供的语义标题；当标题仍是默认时间戳时，再降级显示为 `新对话` + 弱化日期信息。
