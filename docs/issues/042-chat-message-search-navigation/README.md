# 042 · 长会话缺少完整的对话内搜索与消息定位

- **状态**：open
- **严重度**：medium
- **发现日期**：2026-08-05
- **关联需求**：002-engine-session-management、010-desktop-shell-and-chat-ui

## 现象

在消息较多的长会话中，用户使用系统原生 `Ctrl+F`（macOS 为 `Cmd+F`）搜索历史消息里的关键词时，无法命中已经滚出当前可视区域的内容。例如，历史消息中实际存在“邦”或“only”，但停留在会话底部搜索时会显示找不到；只有把对应消息滚动到附近、使其重新渲染后，浏览器原生查找才可能命中。

期望对话页提供产品内搜索能力：能够检索当前会话的完整可见消息集合，展示匹配数量，在上一条 / 下一条结果间切换，并直接滚动定位和高亮目标消息，形成接近全局搜索的使用体验。

## 根因初判

代码层面已确认，对话消息列表使用 `@tanstack/react-virtual` 虚拟化渲染，默认只挂载当前可视区域及少量 overscan 消息。离屏历史消息不在 WebView DOM 中，而原生页面查找只能检索当前已挂载文本，因此 `Ctrl+F` 无法覆盖完整会话。

当前前端也没有接管 `Ctrl+F` / `Cmd+F` 的对话搜索逻辑，无法基于完整消息数据执行检索并驱动虚拟列表定位。

## 影响与判断

长会话中无法可靠查找已经出现过的人名、术语、代码片段或调查结论，用户容易误判内容不存在，也难以回到目标上下文。会话越长，问题越明显。

该问题不造成消息丢失，且可以通过反复滚动或让 Agent 回查历史间接绕过，但它破坏了原生查找带来的预期，因此按中等严重度的核心可用性缺口登记。需求 002 曾明确将“会话搜索（按内容检索）”留待后续迭代，本 issue 作为后续能力入口。

## 可选修复方向

- 在对话页提供搜索框，并接管 `Ctrl+F` / `Cmd+F`，搜索数据源使用当前会话完整的可见消息模型，而不是 DOM 文本。
- 提供匹配总数、当前序号、上一条 / 下一条、关闭搜索等基础交互，并在消息内容中高亮当前结果与其他结果。
- 命中离屏消息时，先通过虚拟列表的 `scrollToIndex` 定位，待目标行挂载后再完成精确滚动、聚焦和高亮。
- 明确富文本、代码块、工具调用结果及折叠内容的检索口径，并保证搜索结果与用户实际可见内容一致。
- 实施前确认首期范围是“当前会话全文搜索”，还是同时提供跨会话结果列表与会话跳转；后者可复用相似入口，但不应与本次虚拟列表定位问题隐式绑定。
