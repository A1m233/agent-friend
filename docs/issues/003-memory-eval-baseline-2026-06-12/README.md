PerLTQA 全量首跑：**macro 平均 0.219**。分数分布严重偏左：

| 分段 | 题数 | 占比 |

## 根因初判

按"修了能涨多少分"排优先级：

### 主因 1 · 抽取阶段把对话压成话题摘要，把判分需要的具体词洗掉了

最尖锐的反例。张小红样本的 dialogue block `4_0_1#1`，**单段对话用户原话**：

> 张小红：他喜欢通过**手环触摸屏幕**翻阅**英语启蒙故事**和**绘本**，并尝试进行**听读**和**配音**的活动。
> 张小红：每天**放学回家后**，张小明会和我**一起分享**他在系统中的**学习成果**，并与我**讨论**一些**学习上的问题**。
> 张小红：试用期间他的**学习兴趣**明显增加，他愿意**主动参与**各种**学习活动**，并在系统的帮助下取得了一定的**学习进步**。

PerLTQA 在这段挂了 14 个 anchor，**全部在用户原话里逐字出现**。但我们落到 memory 的抽取产物只剩：

- episodic：「用户分享了弟弟张小明使用智能学习手环的经历，以及用户作为农业工程师对这一教育创新项目的兴趣」
- semantic：「用户愿意花时间与弟弟张小明一起探索智能互动学习系统的功能」

→ 这一段对话产生的连续 3 道题（涉及上述 14 个 anchor）**全部 0 分**，一个 anchor 都没召回。LLM 把"手环触摸屏幕、英语启蒙故事、绘本、听读、配音、放学、分享、讨论..."的具体词揉成了"使用智能学习手环的经历"这种**话题级摘要**。

这个机制能解释**有 episodic/semantic 召回但仍 0 分的 665 道题**：找到了正确话题、但抽取阶段已经把判分词洗掉了，下游怎么召都召不回。

### 主因 2 · pinned 通道挤占了召回额度

1613 道零分题里 **863 道（53.5%）召回里只有 pinned**——清一色"用户的名字是张小红"、"用户有一个弟弟叫张小明"这种**无论问什么都会出现**的身份事实。一旦 retrieve 在 episodic/semantic 找不到匹配，pinned 就成了"占位安慰品"。

背后是两件事叠加：
- 上游：抽取产物太稀（见主因 1），retrieve 没素材
- 下游：retrieve 没有"宁可空也别返回不相关 pinned"的策略

### 主因 3 · 召回数量与得分强相关，retrieve 严重偏稀

| recalled_count | 题数 | 0 分率 | 均分 |
|---|---|---|---|
| 1 | 499 | 86% | 0.05 |
| 2 | 733 | 77% | 0.10 |
| 3 | 505 | 55% | 0.23 |
| 4 | 336 | 42% | 0.32 |
| 5 | 204 | 35% | 0.40 |
| ≥8 | 218 | 24–33% | ~0.46 |

**45.5% 的题只拿到 ≤2 条召回**，而 ≤2 条几乎只可能是那两条 pinned。`recalled_count == 11` 的样本（仅 3 道）均分 0.82——说明召回再宽一点，分就能上来。FTS5 中文分词 + 抽取产物稀薄共同导致绝大多数 query 命中不到 episodic/semantic。

### 次因 4 · judge 的 substring 偏差（已知，但不是本期主因）

`012 design §8` 已承认：substring 匹配会漏掉同义改写（anchor "手环触摸屏幕" 不会被召回里的 "智能学习手环" 命中）。但这不能用来掩盖主因 1——上面那段对话里有逐字出现的 "听读"、"配音"、"绘本"，抽取产物里**连这些字都没有**，不是判错。

## 影响与判断

- **不违反 008 任何 AC**（008 是工程能力 AC，不打分）：跨会话记得名字、不重新自我介绍等核心保证未失守，零分题不等于"对话不可用"——pinned + 在场上下文还能撑住基础体验。
- **但是 memory 价值主张的明显弱点**：长对话里"具体细节回看"几乎做不到——一段对话用户讲过的具体词（人名、动作、物件、时间副词、数量），抽取阶段已经丢失，下游再怎么改 retrieve / judge 都救不回来。这与 008 的核心承诺"长期记得用户讲过什么"有张力。
- **为什么登记为 issue 而非立即修**：
  - 改抽取 prompt / 抽取颗粒度是**结构性变动**，会影响 008 既有上线行为，需要单独跑评估、对比、回归
  - 当前 baseline 已入仓（commit `ef59c8e`），后续任何抽取/召回改动都有对比锚点
  - 优先级取决于下一阶段是先推产品还是先推记忆质量

## 可选修复方向

按优先级（高 → 低）：

1. **抽取产物保留具体词**（最大杠杆，对应主因 1）：改抽取 prompt / 调整抽取颗粒度。两条路子：
   - **逐 turn 抽**而非整段 block 抽，避免一段被压成一个话题摘要
   - 在 prompt 里强约束"保留专有名词、时间、动作动词、数量词、物件名"，禁止用"该应用 / 一些 / 各种"这类指代词替换原词
2. **召回不返回无关 pinned**（对应主因 2）：pinned 命中也走相关性阈值，或把 pinned 从 episodic/semantic 召回额度里**剥离**——pinned 永远附带、不挤占 top-K
3. **加宽检索召回**（对应主因 3）：FTS5 中文分词改进 + 叠加向量召回，把 recalled_count 从平均 2.6 拉到 ≥4
4. **judge 升级到 LLM-as-judge**（对应次因 4）：解决 substring 偏差——但**当前阶段还轮不到它**，主因 1 没解决时升级 judge 只是把"召不到"变成"召不到但分数好看一点"
