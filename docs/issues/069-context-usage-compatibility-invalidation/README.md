# 069 · 上下文计量兼容性判断过宽，轻易丢弃已有用量并触发压缩

- **状态**：open
- **严重度**：medium
- **发现日期**：2026-10-07
- **关联需求**：[154-session-scheduled-requests](../../requirements/154-session-scheduled-requests/)（发现入口；问题属于公共上下文计量链路）

## 现象

已有会话由定时任务追加一条短消息时，开头先压缩约 68 秒。用户希望后续处理计量兼容性：不要因无关变化轻易丢弃已经取得的上下文长度依据，尽量复用可信用量，只对实际变化的部分重新评估。

本次确认的实例：

- 上一轮实际输入为 121,937 token，原压缩摘要仍在使用。
- 本轮压缩前候选上下文没有附件或工具图片，但估算达到 643,590，超过 320,000 触发阈值；模型有效窗口为 400,000。
- 2026-10-07 14:00:26（UTC+8）开始压缩，14:01:34 完成上下文构建；随后正常调用模型。
- 用户反馈“总是很轻易地丢弃已经算好的上下文长度”。目前只证明本例的具体机制，尚未统计其它会话中的发生频率或全部失效原因。

## 根因初判

**confirmed：运行记录、源码与无模型调用的离线对照一致。** 普通发送和定时触发复用同一请求／上下文链路，并非定时任务单独实施估算。

1. 历史用量记录使用 `attachment_input_projection=session-pdf-v1`、`attachment_profile=openai-attachments-v1`；当前 dev 使用 `session-files-v2`、`tool-images-v1`。变更来自既有附件改造 commit `536735a8`。
2. `Conversation._usage_scope()` 无条件把这两项纳入整个请求的计量兼容性身份。即使本轮没有附件，版本变化也使旧 usage anchor 失配；`estimate_input()` 进入 `request_scope_changed` 全量估算。
3. 历史中 13 段加密推理信息原本都能匹配旧用量组件。整体失配后被视为未知成本，预算为整个请求额外预留一个完整窗口，即 400,000 token。
4. 本例结果为 **243,590 可计量部分估算 + 400,000 未知容量预留 = 643,590**。因此不能把该数值直接解释成实际输入占用。

源码入口：

- `agent/src/agent/conversation.py`：`_usage_scope()`、`_estimate_rendered_input()`、`_restore_context_usage()`。
- `agent/src/agent/context/usage_anchor.py`：`estimate_input()`、`_estimate_components()`、`estimate_full_input()`。
- `agent/src/agent/context/input_identity.py`：`input_compatibility_scope()`。

## 验证证据与边界

- 来源：本次 feature worktree 的真实 dev，Bridge PID 47360；现场 `tauri.log.dev` 的 `context_compaction_started`／`context_build` 与同一会话 JSONL 的 `context_usage`、rollout 和 compaction 记录。日志会轮转，本文保留必要数值，不复制用户正文、加密推理载荷或凭据。
- 离线按持久化模型历史及本轮新增上下文重建候选，精确复现 **643,590**；分别采用旧、新附件身份，重算的兼容性哈希与前后持久化记录完全一致。
- 仅在离线对照中允许复用原计量依据，结果为 **139,469**：原实际用量 121,937 加增量估算 17,532；未知成本组件为 0，低于压缩阈值。该结果为保守的部分复用上界，**不是重新请求模型得到的实际用量，也不构成无条件复用旧 anchor 的修复方案**。
- 本轮没有修改生产代码、迁移用户记录或发起真实模型调用。

## 影响与判断

无关的输入处理版本或能力声明变化可能使整份可信用量依据失效，引发不必要的摘要调用、等待和上下文重写。由于归属公共续聊链路，影响不限定于定时任务；其它变化类型仍需逐项核实。

本 issue 与摘要生成上限、冷恢复耗时不同，也不包含等待队列展示或停止按钮问题。用户明确要求以后处理，本次只登记，不关闭估算或压缩保护。

## 可选修复方向

- 收紧兼容性失效范围：区分实际输入变化、仅影响附件的变化及无关配置变化；无附件请求不应仅因附件处理版本变化丢弃全部计量依据。
- 尽量保留可证明兼容的历史组件和可信 usage；重新计量新增／改变部分，避免一处失配导致全部重估。不能把整体真实用量随意拆分，或用旧片段的估算值相减来伪造精确计量。
- 对真正未知成本保留保护，同时明确区分真实用量、字符估算、保守上界和未知容量预留，并记录旧依据无法复用的具体字段与原因。
- 后续覆盖冷恢复、版本升级、工具／配置变化、真实附件投影变化和加密推理重放；重点验证“无关变化不触发压缩”与“真正不兼容仍安全降级”。本例可作为离线回归线索，不需要先调用真实模型。
