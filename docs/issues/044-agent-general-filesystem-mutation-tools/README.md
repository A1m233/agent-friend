# 044 · Agent 缺少通用且受治理的本地文件读写能力

- **状态**：open
- **严重度**：medium
- **发现日期**：2026-08-06
- **关联需求**：[076-agent-skill-system](../../requirements/076-agent-skill-system/)

## 现象

agent-friend 当前没有面向 Agent 的通用本地文件工具。Agent 既无法枚举目录或读取任意本地文件，也无法按工作流创建目录和文件、编辑既有文件、应用补丁，或在受控范围内移动和删除文件。

这会直接限制需要读取或产出本地资产的 Skill。以首个计划内置、并与 Codex 官方版本对齐的 `skill-creator` 为例：它可以被发现并加载，也可以基于已注入的 `SKILL.md` 向模型说明目录结构和编写规范，但 Agent 不能继续读取 `references/`，也不能真正初始化 Skill 目录或修改 `SKILL.md`、`agents/openai.yaml` 等文件。若只为 Skill 系统或 `skill-creator` 增加一组私有读写接口，会让同一种文件操作绕开 Agent 的统一权限与审计边界。

## 根因初判

现有工具注册表主要承载固定业务工具，尚未建立通用本地文件工具的公共契约。读取侧缺少目录和文件作用域、敏感路径、符号链接与目录穿越、体积上限和内容类型等约束；变更侧还缺少写入授权、变更预览、并发修改冲突、原子落盘和可审计结果等共同约束。

需求 065 已补充可信只读工具和工具循环治理，但没有提供通用本地文件变更能力；需求 076 的职责则是 Skill 的发现、加载和上下文装配，不适合顺带扩张为完整的本地文件操作权限面。

## 影响与判断

- 需求 076 可以交付 Skill catalog、完整 `SKILL.md` 加载和 builtin Skill，但本地附加资源不能继续按需读取；`skill-creator` 在当前能力下也只能诚实报告无法执行文件读写，不能宣称已读取参考文件、创建或更新 Skill。
- 所有未来需要创建或维护本地资产的 Skill 都会遇到相同限制，不只影响 `skill-creator`。
- 为单个 Skill 增加特权工具会形成旁路，使权限、审批、诊断和测试语义逐步分叉。

该缺口不阻塞把全部必要说明写在 `SKILL.md` 内的纯指导型 Skill；依赖独立 `references/`、`assets/`、现有文件检查或任何文件变更的 Skill 会受限。它不应扩大需求 076 的本期范围，因此按中等严重度的通用 Agent 能力缺口登记，留待独立需求补齐。

## 可选修复方向

- 对齐 Codex 的通用 Agent 工具思路，提供可复用的目录查看、文件读取、创建、编辑或补丁、移动和删除能力，不给 Skill 系统或某个 Skill 建立私有读写 API。
- 读取与变更可以分里程碑交付，但应共享路径规范化、允许范围、符号链接和审计模型；先补读取时也不能默认获得全盘无边界访问。
- 统一做路径规范化和允许范围校验，明确 workspace、用户显式授权目录及产品数据目录的边界；把符号链接、目录穿越和目标在操作间变化纳入威胁模型。
- 对变更型操作提供一致的权限判断、必要审批、diff 或操作摘要、原子写入和冲突检测，使 Skill 只负责描述工作流，不负责另造安全模型。
- 让工具结果明确区分成功、未授权、目标已变化、部分失败和不支持，避免模型把计划或尝试表述成已经落盘。
- 后续以独立需求定义最小首期能力和桌面端审批体验，并用 `skill-creator` 作为端到端验收样例之一，而不是能力的唯一调用方。
