# 073 · QQ 自然聊天尚缺少表情包寻找、管理与使用能力

- **状态**：open
- **严重度**：low
- **发现日期**：2026-11-06
- **关联需求**：[171 · 自主陪伴优化](../../requirements/171-autonomous-companionship-optimization/requirement.md)（已明确排除，后续单独立项）
- **类型**：用户指定登记的后续功能待办，不是既有能力回归。
- **处理决定**：本次只留档，之后独立走需求澄清与设计。

## 现状与目标

用户希望 AF 可以自己寻找有意思的 meme、梗图和表情包，管理可复用的素材，并在开启 QQ 自然聊天时选择合适的表情包参与交流。自主寻找可以不立即分享，之后在适合的聊天中使用。

这是自然聊天的通用能力，不仅用于自主陪伴；现有图片发送不等于已经实现了这一完整能力。

## 当前缺口

尚未完成表情包发现、管理、选择与自然聊天发送的完整设计和实现，也未确认工具接口、素材存储及发送契约。

## 影响与判断

用户已将其移出 171，并明确要求作为 issue 留档。后续应单独开需求，不借本次文档登记恢复实施。

## 已表达的方向

- 提供让 AF 自己寻找、保存、查看、复用和管理表情包的工具能力；具体边界后续讨论。
- 让 AF 知道“自然聊天”是什么、这些素材可以用于自然聊天，避免只有偶然读取某个 Skill 才知道能力存在；说明放在哪里尚未确定。
- 用户倾向通过能力和工具支持自主选择，不在自主陪伴提示词中强制要求找图、发图或设置场景配额，保留 AF 的创意与不使用的选择。
- 开启自然聊天时如何选择素材、组合文字与图片、处理发送失败，以及原样发送模式的边界，需要在后续需求中明确。
- 配合 [072 · 实际发送结果同步回模型历史](../072-im-natural-result-model-history/README.md)，使 AF 能承接用户对已发表情包的回应。如何表达图片内容及发送状态仍需设计，不能把收藏、计划发送或未知结果当成已送达。
