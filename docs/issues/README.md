# 问题登记（Issues）

本目录存放 `agent-friend` 里**已经发现、但当下不打算立刻修复**的问题：bug、体感瑕疵、技术债、设计弱点等。目的是"先记下来不丢"，等有空档或相关需求推进时再回头处理。

> 这里只登记"暂不修"的问题。**马上就修的不必进这里**——直接改代码 + commit 即可。

## 适用范围

- 已确认的 bug / 缺陷，但优先级不高、暂缓修复。
- 体感瑕疵、设计弱点、已知技术债。
- 需求落地时发现、但超出当期范围、决定延后的问题。

不属于这里：

- **新功能 / 新能力** → 走 `docs/requirements/<NNN>-xxx/`。
- **长期话题的探索笔记** → 走 `docs/explorations/`。
- **项目级方向决策** → 走 `docs/decisions/`。
- **立即修复的问题** → 直接改，不登记。

---

## 目录约定

每个 issue 是一个**独立文件夹**，命名格式 `<3 位数字编号>-<kebab-case 英文短语>`，主文档统一叫 `README.md`：

```
docs/issues/
├── README.md                          ← 本文件，仅维护管理规则
├── 001-memory-weak-time-sense/
│   ├── README.md                      ← issue 主文档
│   └── （可选：assets/、日志片段、复现脚本等附带资料）
└── 002-xxx-yyy/
    └── README.md
```

约定要点：

- **主文档统一叫 `README.md`**：GitHub 进文件夹时自动渲染，体验最好（与 `decisions/` 一致）。
- **编号 3 位、连续递增**：仅在本目录内编号，与 `requirements/` 的编号空间互不相干（路径本身已区隔，引用时写"issue 001"即可）。
- **kebab-case 英文短语**：跨平台路径友好、一眼看出问题主题。
- **一个 issue 一个文件夹**：方便在同一 issue 下放复现日志、截图、最小复现脚本、相关参考等附带资料。

---

## 文件格式

issue 主文档（`README.md`）以一段元信息头起手，后接正文。元信息用简单的 `键: 值` 列表（不强制 YAML frontmatter，保持轻量）：

```markdown
# <编号> · <一句话标题>

- **状态**：open
- **严重度**：low | medium | high
- **发现日期**：YYYY-MM-DD
- **关联需求**：008-engine-memory（无则填"无"）

## 现象
（用户/系统实际看到了什么，能复现最好附复现步骤或日志）

## 根因初判
（目前判断的成因；尚未定位则写"待定位"并列出怀疑点）

## 影响与判断
（影响范围、是否违反某需求的验收标准、为什么暂不修）

## 可选修复方向
（已经想到的几条路子，不强求落地，给未来的自己留线索）
```

### 字段说明

- **状态**：`open`（待处理）/ `resolved`（已修复）。修复后**不删目录**——把状态改成 `resolved` 并在文末补一句"修复指向"（commit / 需求 / PR），保留可追溯。
- **严重度**：粗分三档即可。`high`=影响核心体验或数据正确性；`medium`=明显但有规避；`low`=体感瑕疵 / 技术债。
- **关联需求**：指向相关的 `docs/requirements/<NNN>-xxx/`，方便那个需求推进时一并处理。

---

## 关闭一个 issue

修复完成后：

1. 把对应 issue 主文档（`README.md`）的 **状态** 改为 `resolved`。
2. 在文末加一行修复指向（如"已在 commit `abc1234` / 需求 011 修复"）。
3. 暂不搬移到归档子目录——数量积累到难以浏览时再考虑 `resolved/`。

---

## 与其他 docs 子目录的边界

| 目录 | 职责 |
| ----- | ----- |
| `docs/decisions/` | 项目级重大决策 |
| `docs/requirements/` | 具体需求 + 技术方案 |
| `docs/explorations/` | 长期话题的探索笔记 |
| `docs/issues/`（本目录） | 已知但暂不修复的问题 / 技术债 backlog |

简单原则：

> **"要做的新事" → requirements；"要想清楚的事" → explorations；"坏了但先不修的事" → issues。**
