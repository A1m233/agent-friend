# 001 · Agent 会话历史工具的证据边界

- **状态**：active
- **来源日期**：2026-06-25
- **来源**：issue 025 / C4 contract eval
- **适用范围**：agent 会话历史工具（`recall_past_chats`）、工具结果渲染、历史归因类回答
- **最近更新**：2026-06-25
- **替代条目**：无

## 经验

当 agent 通过会话历史工具查看自己过去的对话时，工具结果本身必须携带明确的**证据边界**：哪些内容是历史片段直接支持的，哪些内容没有找到，哪些内容不能用通识、训练数据、用户暗示或外部搜索补齐。

这类问题不能只靠 system prompt 约束。模型在看到空召回、弱召回或用户给出的诱导性对象时，仍可能把“我找不到历史证据”滑向“但我知道这个对象的一般信息”。真正有效的边界应同时出现在全局 prompt 和 tool output 中，让 agent 在最靠近证据的位置看到限制。

## 背景

issue 025 中，用户问的是“你之前提过 / 推荐过 / 说过什么”这类历史归因问题。`recall_past_chats` 没有找到对应历史证据后，agent 虽然承认自己不记得，但仍会用常识补出电影、方法、工作流等具体内容，造成“空召回后继续编造”的体验。

修复过程中，单独加强 system prompt 后，C4 评测仍有失败；继续把证据边界写进会话历史工具的空结果和非空结果提醒后，C4 复测通过。这说明工具结果渲染不是纯展示层，它也是 agent 推理边界的一部分。

## 反模式

- 只在 system prompt 里写“不要编造历史”，但 tool result 只返回“没有找到”。
- 命中少量历史片段时，把片段时间、相似主题或用户当前问题里的对象当成历史证据。
- 空召回后，顺手切换成通用知识回答，比如列出作品、步骤、工具、参数或候选项。
- 为了补齐历史归因问题，同轮调用外部搜索；搜索能验证外部事实，但不能证明“我之前说过”。
- 把用户问题里暗示的对象当成已确认事实，例如用户问“你之前推荐的 X 是不是……”，就默认 X 曾经被推荐过。

## 推荐做法

- 会话历史工具的空结果提醒应明确说明：没有历史证据时，只能说没找到，不能用通识、训练数据、印象或用户暗示补细节。
- 非空结果提醒也要声明证据边界：只有片段字面支持的内容才能被归因为“之前聊过 / 推荐过 / 说过”。
- 如果用户可能想要通用知识，应先确认是否切换问题类型，例如“我没找到我们之前聊过这个；如果你愿意，我可以按一般资料讲”。
- 对历史归因问题，外部搜索最多用于后续外部事实核验，不能在同轮替代会话历史证据。
- 测试应覆盖空召回和弱召回两类场景：空结果不能补常识，弱结果不能用相似主题补缺失细节。

## 适用与不适用

适用：

- 用户问 agent 过去是否说过、推荐过、答应过、讨论过某件事。
- `recall_past_chats` 返回空结果，或返回片段但缺少用户询问的关键实体、方法、步骤、数字、工具、日期。
- 评测目标是历史归因、会话证据、反编造或 recall tool 行为。

不适用：

- 用户明确要求通用知识、外部事实或实时资料，且没有把问题表述成“我们之前聊过什么”。
- 长期记忆抽取、摘要质量、记忆存储策略等问题；这些属于 memory 系统，不等同于 agent 会话历史工具。
- 已经有明确历史片段支持的事实；这时应基于片段回答，而不是机械拒答。
