# 桌面应用正常启动与生命周期

## 状态

CONFIRMED

确认日期：2026-09-17。

## 背景

用户让 Agent 执行 MAA 日常后，希望继续使用 MuMu 模拟器。一次运行中，Agent 在收尾时确认模拟器进程仍存在并报告保持运行，但用户随后发现模拟器已关闭。已有诊断高度支持任务结束时的受管进程清理造成关闭，尚缺少该进程的最终终止回执，不能把这一归因写成完全确认。

现有 MAA skill 已要求用户未指定时默认保持模拟器可见运行。产品需要提供能够兑现这一预期的桌面应用启动能力，并让 Agent 区分启动动作、应用就绪和任务进程清理。

## 目标

- Agent 按用户意图正常打开桌面应用，用户能继续操作该应用。
- 已打开的应用不因当前任务完成、取消或 agent-friend 退出而被连带关闭。
- 启动仍受既有授权与审计约束，应用持续运行不等于获得持续自动操作权限。
- Agent 能准确说明启动结果和生命周期，不把临时进程的存活检查当作任务结束后的持续运行保证。

## 范围

### 包含

- Windows 桌面应用启动，以 MuMu 和现有 MAA skill 的完整链路为主要验收场景。
- 将桌面应用与随任务清理的普通命令区分，保留后者既有的取消、超时和清理能力。
- 打开应用前识别明确目标；已有目标实例可以复用时避免不必要的重复启动。
- 区分启动请求已接受、窗口可用和业务运行环境就绪；失败或未知状态不得报告为已就绪。
- 任务完成、任务取消、agent-friend 正常退出及受管服务停止时的应用存活边界。
- 记录启动方式、生命周期归属、失败原因及本产品实际发起的关闭动作，便于事后解释。
- 核对并适配独立维护的 MAA skill 启动指引，保留其目标实例发现、ADB、业务执行与结果核验流程。
- 明确其他平台和无可用交互桌面环境的支持边界；能力不可用时给出真实限制，不静默采用会随任务被终止的方式。

### 不包含

- 通用后台任务平台、定时执行、守护进程和长期无人值守编排。
- 对所有桌面应用提供统一业务控制、自动恢复或常驻监控。
- 保证应用不会自行崩溃、被用户关闭，或在注销、关机后继续运行。
- 扩大 MAA 的账号、设备、资源消耗或后续自动执行授权。
- 将历史事故的概率性归因改写为已完全复现的结论。

## 行为要求

1. 用户要求打开桌面应用且未要求任务后关闭时，默认交给用户桌面继续使用。取消 Agent 任务表示停止后续 Agent 工作，不自动转化为关闭已打开应用。
2. 用户已经打开的应用不因本次复用而被纳入任务结束清理范围。
3. 用户明确要求关闭时，按目标应用现有的安全操作边界执行，不能仅凭过期 PID 或进程名称关闭不确定实例。
4. 启动请求返回成功不代表窗口或业务已经就绪。对 MuMu，后续仍需核对可见窗口、目标实例、Android 状态和实际 ADB 地址。
5. 启动请求可能已生效但结果不明确时，先核对现有状态，不能无条件重复启动。
6. MAA 的有限执行进程与 MuMu 应用分别管理；日常执行、取消和证据收集不能依赖持续持有 MuMu 启动句柄。
7. 生命周期应同时在模型可见结果和可追溯证据中体现；能力不可用、启动失败和就绪未知必须能够区分。

## 验收条件

- [x] AC-1：从未运行的目标 MuMu 实例开始，Agent 正常打开可恢复、可操作的窗口，并完成目标实例与 Android/ADB 就绪核验。
- [x] AC-2：通过现有 MAA skill 完成一次用户授权的日常；本轮最终回复和运行清理完成后，窗口、实例及 ADB 仍可用。
- [x] AC-3：目标应用已打开后，分别取消当前任务、正常退出 agent-friend、停止受管服务，均不会因本产品的进程清理关闭目标应用；在确认来源的真实 Windows 产品运行态验证。
- [x] AC-4：复用预先由用户打开的 MuMu 后，任务结束不会关闭它；不因复用而改变其生命周期归属。
- [x] AC-5：普通临时命令仍按既有契约在取消、超时和任务结束时清理；持续应用启动能力不能使普通命令意外常驻。
- [x] AC-6：覆盖目标不存在、授权拒绝、能力不可用、启动结果不明确、窗口出现但 Android 未就绪等情况；不误报成功，不无条件重复启动。
- [x] AC-7：用户明确要求关闭已确认目标时可按适用流程正常关闭；没有关闭请求时不自动发起关闭。
- [x] AC-8：模型可见工具契约、结果及诊断证据能区分启动接受、应用就绪、生命周期归属和终止原因；包括历史“未发关闭工具即否认自身影响”的回归场景。
- [x] AC-9：MAA skill 的正式指引与实际产品能力一致，用户下次执行同一日常无需临时 shell 绕行或额外手工启动。
- [x] AC-10：其他平台和缺少交互桌面的入口明确报告支持边界；未实现或未验证的行为不宣称支持。

## 依赖与验证边界

- MAA skill 由独立仓库维护，联动修改与验证需记录双方准确版本。
- 真实日常会操作游戏，实际执行时需要明确账号、设备、资源范围；需求确认不替代真实游戏操作或外部 LLM 调用所需授权。
- 自动化测试与真实桌面验收分别记录；仅凭源码、mock、开发模式或一次进程列表不能证明安装版生命周期隔离通过。
- 具体启动机制、工具接口和跨进程通信在技术方案阶段确定。
