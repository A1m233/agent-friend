# 119 · 桌宠图形异常可观测与故障留存

## 状态

COMPLETED（用户接受已记录的验证范围与限制；详见 progress.md）

## 背景

2026-09-07 的 Windows 闪烁反馈中，手机视频显示前景窗口基本保持，后方窗口区域反复消失、恢复。用户确认退出 agent-friend 后闪烁立即停止，重启后未再出现。这支持故障与当次桌宠运行中的图形呈现状态有关，但不足以确定 WebView2、宿主窗口、Windows 合成或驱动的具体责任。

已有诊断包保留了窗口、输入和进程事件。视频对应的 02:09 时段未观察到 GPU 进程崩溃、桌宠窗口反复显隐、调整尺寸或鼠标穿透持续切换；包中的自动渲染截图来自更早的事件。现有证据不能解释“进程仍在运行，但桌面持续闪烁”的异常，也不能以缺少崩溃事件证明显示正常。

本需求补齐持续、可关联且重启后仍可读取的运行时证据。截图仅作为既有辅助证据，不作为本需求的核心产物或必要前提。原始视频、诊断包及私密内容不纳入 Git 仓库。

## 目标

- 用户无需预先开启调试，在故障发生并退出、重启后，仍能通过诊断包提供故障前后的有界证据。
- 能分别判断页面是否继续执行、渲染是否推进、宿主窗口做过什么操作，以及可获取的系统图形事件；不能用任一层正常替代整条显示链路正常。
- 让后续排查可以收窄假设，并清楚指出缺失的观测，而非只增加无法解释的日志数量。
- 观测对正常动画、输入、功耗、磁盘和启动退出的影响有明确预算与验证。

## 范围

### 包含

#### R-1 · 默认轻量观测

- 首期以 Windows 桌宠图形链路为重点，覆盖页面生命周期与运行进展、实际渲染进展、图形上下文丢失与恢复，以及可取得的 WebView2 和系统显示事件。
- 对宿主窗口的显隐、尺寸、位置、DPI、透明与穿透样式、置顶等相关操作，记录触发原因、操作前后状态与实际执行结果。
- 尽可能复用现有输入证据、Windows Shell、WebView2 及显示恢复采集；明确每类事实的权威来源，避免相互矛盾的重复记录。
- 区分主动暂停、窗口隐藏、显示器关闭、正常低帧率与异常停滞；未观测到实际呈现时明确标记未知。

#### R-2 · 跨层关联

- 能关联构建身份、应用进程、页面实例、窗口、渲染实例与同一异常事件；重启与页面重建必须可区分。
- 保留用于关联与排序的时间依据，明确跨进程时间偏差、聚合及异步处理的限制。
- 原始观察、异常信号与诊断结论分开表达；出现低帧率、超时或上下文事件不直接等同于本次闪烁根因。

#### R-3 · 故障留存

- 默认采用容量、时间和写入频率受限的持久记录，关键历史在正常退出、应用重启后仍可读取。
- 自动异常信号及用户反馈可保留对应事件片段；不要求异常必须触发进程崩溃，也不依赖出问题的桌宠页面持续响应才能导出已有证据。
- 正常滚动历史与已保留故障片段的淘汰规则可解释，健康记录不能立即挤掉故障片段。
- 对异常退出、队列拥塞、写入失败、限流、截断、淘汰和未知尾部损失如实报告，不承诺无法保证的完整性。

#### R-4 · 系统图形证据与按需深入采集

- 区分默认可用的轻量证据与需要额外权限、工具或明显开销的深入跟踪。
- 方案阶段核实系统图形跟踪能捕获哪些边界、权限与开销；较重采集按需启用，具有明确持续时间、容量、停止和失败处理。
- 平台或权限不足时提供明确的能力与缺口说明，不能把前端心跳或渲染提交充当系统实际呈现证据。

#### R-5 · 诊断导出与隐私

- 接入既有诊断包、机器契约及解析消费者，提供证据覆盖、身份、事件摘要和缺口信息。
- 新旧诊断包兼容；旧包没有新增证据时标为未采集，不误报损坏。
- 默认记录结构化状态和统计，不采集画面内容、聊天正文、键盘输入、连续鼠标轨迹或无关应用私密内容。
- 深入采集的实际内容与权限边界必须说明，遵守既有诊断导出授权与隐私约定。

### 不包含

- 在根因尚未确认时直接修复此次闪烁，或承诺消除所有图形异常。
- 改变桌宠承载形态、强制禁用 GPU、修改用户显卡设置，或新增自动重启恢复策略。
- 默认持续截图、录屏或高开销系统跟踪。
- 为其他平台承诺与 Windows 完全相同的底层图形能力；其他平台须明确支持范围且不发生行为回归。

## 验收条件

- [ ] AC-1：无需预先开启调试，运行期间即可形成默认观测记录；模拟进程不崩溃但页面或渲染停止推进时，记录能够区分已观察阶段与未知呈现状态。
- [ ] AC-2：受控窗口显隐、尺寸、DPI、穿透与相关样式变更能够关联到触发原因、实际结果与所属实例；重复请求和无变化操作不会造成无界日志。
- [ ] AC-3：受控故障信号或用户反馈能保留关联片段；正常退出和重启后可导出旧实例证据，并与新实例区分。
- [ ] AC-4：故障留存及导出不依赖桌宠页面响应；故障记录不会被后续健康流量立即覆盖，保留与淘汰行为有确定性验证。
- [ ] AC-5：截断、丢弃、写入失败、异常退出尾部、平台不支持与权限不足均可识别，不以“导出完成”表示事件证据完整。
- [ ] AC-6：明确默认与深入图形采集的能力边界；深入采集按需启停且有界，不可用时正确降级，不将页面帧率或提交计数误标为桌面呈现正常。
- [ ] AC-7：新增证据可由正式诊断导出入口及真实解析器消费；覆盖旧包兼容、结构契约、隐私约束和未知能力处理。
- [ ] AC-8：按方案明确的预算验证稳定运行与事件突发时的 CPU、内存、磁盘和写入开销；观测失败不阻断桌宠渲染、输入及应用退出。
- [ ] AC-9：至少完成一次 Windows 真实运行态的“采集—故障标记—退出重启—诊断导出—解析”验证。受控故障仅证明采集机制，不宣称复现本次用户闪烁；项目检查通过，用户确认验收。
