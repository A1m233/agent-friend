# 050 · 单一人格自定义

## 状态

CONFIRMED

## 背景

agent-friend 已经在引擎层具备 persona 的持久化、读取、更新和 system prompt 分层装配能力，但桌面产品尚未向用户提供人格调整入口。当用户希望自己的朋友少一点说教、更直接、回复更短或更会接住情绪时，只能由开发者修改人格 Markdown，普通用户无法自主调整。

项目底层虽然曾为多 persona 和会话内切换留下能力，但当前产品并没有完整考虑多人格的管理、会话归属、记忆边界与跨通道一致性。本需求不扩展为人格管理系统，而是聚焦用户唯一的“我的朋友”：用户可以在设置中调整这一个人格，所有正式通道在后续回合中使用同一份有效人格。

人格调整同时需要服务两类用户：入门用户不应先学会编写 prompt；高级用户则不应被困在功能有限的内置 Markdown 编辑器中。因此本需求提供“自然语言调整”和“直接编辑本地人格文件”两条交互路径，两者最终修改同一份用户人格真相源。

## 目标

- 用户能从“设置 → 人格”调整唯一朋友的性格、相处方式和表达风格。
- 入门用户可以像聊天一样连续描述期望变化，在明确确认前获得可继续调整的候选人格。
- 用户可以连续多次修改同一份未应用草稿，后一次修改不会丢失前一次已经达成的效果。
- 高级用户可以用自己电脑上的默认工具打开 `persona.md` 或其所在文件夹，不需要在应用内使用另一套 Markdown 编辑器。
- 人格修改不改写已有聊天记录，不迁移会话和记忆归属，从下一个新用户回合开始生效。
- 用户能撤销本次应用或恢复出厂默认人格，外部文件错误不能让正式对话不可用。
- 人格编辑对话复用现有对话页的消息展示、流式状态、输入交互和错误反馈，不在设置页重建另一套聊天 UI。

## 范围

### 包含

**设置入口与单一人格语义**

- 设置中心新增“人格”分类，作为本期唯一正式入口。
- 桌宠 ActionBar 不新增独立人格编辑按钮；用户继续通过现有设置入口进入。
- 产品中始终只呈现一个可编辑的当前人格，不向用户暴露底层 persona 列表和切换概念；人格展示名从 `persona.md` 第一处一级标题派生，可随正文一起修改。
- 人格只能影响朋友的性格、关系、回应方式和表达风格；不能覆盖项目身份、工具使用、记忆一致性、不可信内容、输出协议与安全边界等公共 system prompt 职责。
- 人格变化对文字聊天、桌宠、语音和 IM 等正式入口共享，不按通道维护彼此独立的人格文件。

**入门用户的自然语言调整**

- 页面主体提供自然语言输入，询问用户“希望我有什么变化”。
- 用户提交后进入独立的人格编辑 Agent 对话；Agent 可以澄清、连续讨论，并在信息充分时生成一份未应用的完整候选人格。
- 页面始终渲染当前人格约束；产生候选后提供当前版本、候选版本和逐行变化三个视图，并同时呈现简短变化摘要。
- 要求明确时直接生成候选方案；要求过于模糊或内部冲突时，先提出一个简短的澄清问题，不擅自补全重要人格方向。
- 用户可以基于当前候选人格继续表达“再短一点”“但不要显得冷淡”等增量要求。
- 每次继续调整都基于同一编辑 Agent 的历史和最近一次完整候选，不重新回到已保存版本。
- 编辑对话与候选由后端独立 session 持久化；切换设置分类、隐藏窗口、重新打开窗口或重启应用后仍可继续。
- 用户可以放弃整段编辑对话和候选，回到当前正式人格；本期不提供“撤销上一条未应用要求”的独立操作。
- 生成、继续调整和失败重试都应明确呈现进行中、成功和可行动的失败状态，不让用户误以为未确认的内容已生效。

**编辑对话与候选审阅**

- 人格编辑 Agent 使用专用 system prompt 和唯一的 `propose_persona` 工具；不开放搜索、历史召回、长期记忆或其他外部动作。
- 编辑对话保存到独立内部 session，不进入正式会话列表，不抽取或修改长期记忆，也不改变当前正式人格。
- 设置页复用正式对话页抽出的受控消息时间线、Markdown 消息渲染、流式 AG-UI 投影和输入组件。
- 编辑 Agent 的普通回复用于澄清和解释；候选正文只在人格约束区域展示，不在聊天里重复显示工具卡或整份 Markdown。
- 本期不再提供一块独立的“候选人格试聊”区域；用户通过完整候选正文、变化摘要与 diff 审阅修改结果。

**高级用户的本地文件编辑**

- 人格页面提供“打开 `persona.md`”和“打开所在文件夹”操作。
- 应用不内置 Markdown 编辑器；用户使用操作系统默认应用或自己熟悉的编辑器。
- Bridge 启动时即以出厂人格准备唯一可编辑文件，不向用户展示“默认/已自定义”状态，也不要求用户先点击打开操作。
- 外部编辑器保存后自动应用，不要求用户返回设置页再点击一次“应用”。
- 设置页能反映外部文件已生效、存在格式问题或已被删除等状态。
- 外部文件无法被解析或读取时，正式对话继续使用最后一个有效人格，并向用户呈现可行动的错误信息。
- 已有未应用自然语言草稿时进入高级编辑，必须先说明该草稿的去向，不得在用户无感知时用旧草稿覆盖新的外部修改。

**应用、冲突与恢复**

- 自然语言候选人格只在用户明确点击“应用修改”后成为正式人格。
- 应用前后页面均应明确区分“当前正式人格”与“未应用候选人格”。
- 自然语言草稿基于的正式人格在编辑期间被外部改动时，最终应用必须阻止旧草稿静默覆盖新版本，并提示用户基于最新内容重新调整。
- 正式人格更新后不改写已有消息；已经进行中的用户回合使用开始时的人格快照，新版本从下一个用户回合开始生效。
- 自然语言应用成功后提供“撤销本次修改”；还应提供“恢复默认人格”，回到随应用发布的出厂基线。
- 恢复默认前必须说明影响并获得用户确认；恢复后仍不改写历史消息。

### 不包含

- 不提供多人格列表、创建、复制、删除、重命名或切换交互。
- 不允许每个会话、每个通道分别选择或维护人格。
- 不建设人格模板库、人格市场、导入导出、分享或发布流程。
- 不从普通日常聊天中自动、静默地改写正式人格。
- 不提供性格滑杆、数值比例或固定特质 schema。
- 不在应用内建设 Markdown 代码编辑器。
- 不建设候选人格试聊沙盒。
- 不为人格编辑 Agent 开放搜索、历史召回、外部动作或除候选提案外的其他工具调用。
- 不让用户编辑 persona 以外的公共 system prompt section。
- 不提供未应用候选的逐步撤销、分支或合并历史。
- 不新增独立的“人格编辑模型”用户配置；本期复用已配置的对话模型。

## 验收标准

- AC-1：设置中心存在“人格”分类，作为本期唯一正式入口；ActionBar 不新增人格编辑按钮。
- AC-2：用户可以通过复用正式聊天体验的多轮编辑 Agent 提交人格要求，得到行为变化摘要和未应用候选人格；信息不足时系统返回简短澄清问题。
- AC-3：用户连续进行至少三次增量调整时，每次都基于编辑历史和最新候选人格，前序未被新要求否定的改动保留；用户可放弃整个编辑工作区。
- AC-4：候选人格在明确应用前不影响正式聊天、语音或 IM；页面始终能区分正式版本和候选版本。
- AC-5：人格编辑对话与候选提案不进入正式 session 列表、长期记忆或通用工具调用链路。
- AC-6：人格编辑复用现有对话页的受控消息时间线、Markdown 渲染、AG-UI 流式投影、输入与错误反馈能力；设置页没有复制独立聊天实现。
- AC-7：设置页提供“打开 `persona.md`”和“打开所在文件夹”；首次使用时能自动准备用户可编辑文件。
- AC-8：用户从外部编辑器保存有效的 `persona.md` 后，无需回到应用内二次确认，新人格从下一个用户回合开始生效。
- AC-9：外部人格文件无效或暂时无法读取时，正式对话仍使用最后有效版本，设置页展示明确错误；修复文件后能恢复正常。
- AC-10：自然语言草稿基于旧正式版本、期间 `persona.md` 被外部修改时，应用草稿被阻止并提示冲突，不会静默覆盖新内容。
- AC-11：人格在一个正在进行的用户回合中保持一致；修改从下一个新回合生效，不改写已有聊天记录。
- AC-12：修改一级标题可以改变朋友的展示名，但不会创建新的 persona ID，也不要求迁移旧 session、记忆归属或为各通道创建不同人格。
- AC-13：用户可以撤销刚应用的自然语言修改，也可在确认后恢复出厂默认人格；两种操作均不改写历史消息。
- AC-14：人格页和正式对话页均不向用户暴露多 persona 列表、切换入口或每会话人格选择。
- AC-15：用户只能修改 persona 层，候选或外部文件不会覆盖其他公共 system prompt section。
- AC-16：相关确定性自动化测试和 `./scripts/check` 全量门禁通过；任何真实 LLM 编辑验收均在运行前单独获得授权并记录调用量级。
