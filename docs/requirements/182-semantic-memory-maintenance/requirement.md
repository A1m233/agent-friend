# 182 · 普通长期记忆检查与维护接入

## 状态

CONFIRMED

- 确认日期：2026-11-22。
- 分支：feature/182-semantic-memory-maintenance。
- 本文确认产品目标、范围与验收要求；用户于 2026-11-22 确认技术方案并授权开始实现，见 design.md 与 progress.md。

## 背景

AF 已提供 maintain-af-memory Skill，但正式会话没有配套的普通 Semantic 全量查询和定向维护工具。用户要求检查全部普通长期记忆时，AF 可能只能看到召回片段，无法确定库存、逐条核实来源或完成指定修改。

此前在隔离环境中进行的 AF 记忆检查，依赖临时注入的库存、分页、来源和维护工具。其成功不能证明正式产品具备相同能力。面向源码用户提供的独立检查包可以辅助调查，但不能替代产品接入。

170 需求已处理部分记忆抽取质量问题。本需求承接普通 Semantic 的用户主动检查与维护闭环，沿用现有质量标准和来源纪律。

## 目标

用户直接在正常 AF 会话中提出检查或维护要求，即可完成明确范围内的普通长期记忆检查、查证、建议、授权后的修改和实际结果核验，不需要 Inspector、源码、数据库导出或额外测试工具。

检查与维护都应能够解释实际覆盖和结果，并在中断后继续。只有逐条留有判断才算完成相应检查；只有修改成功并读回核验才算完成相应维护。

## 范围

### 包含

1. 检查一条、一个主题或全部当前有效的普通 Semantic；全量范围以指定实例和所属用户的普通事实清单为准。
2. 查询普通事实正文、当前状态、来源、关联变更与必要的普通事实历史，寻找重复或冲突候选。
3. 根据直接来源读取必要原话，区分用户发言、助手判断、引用内容和宿主定时任务输入。
4. 为每条记录留下保留、改写、合并、退役、撤销或待核的建议及理由。
5. 用户明确授权后的定向、批量修改；包括将有据但无长期价值的流水账退出普通层。
6. 可恢复的检查进度、建议、执行回执和读回核验结果。
7. 与后台抽取、其他会话修改以及检索索引的协同；维护期间数据变化不能造成覆盖、漏记状态或重复应用。
8. 正式工具装配、现有维护 Skill 接线以及实际产品入口的验证。

### 不包含

- Core 或 Episodic 的维护；清理工具不展开读取这两层，也不把退出普通 Semantic 的内容搬入 Episodic。
- 自动 dreaming、定时巡检或自主扩大维护范围。
- 重做基础记忆抽取策略、通用记忆质量评测系统或新的管理面板。
- 删除原始会话，或为维护普通事实而改写原始证据。
- 将开发者工具、外部脚本或 Inspector 作为正常用户必须使用的前置条件。

## 用户体验与行为要求

### 正常会话即可使用

用户可以自然表达“检查全部普通长期记忆，只列建议”“看看这条是不是记错了”“按刚才的建议清理这些记录”等需求。AF 应识别本次对象和范围；宿主已有实例、用户或会话信息时，不要求用户提供内部编号、数据库路径或技术配置。

记忆不可用、范围不清或能力不可用时，应说明具体限制；不能将搜索未命中说成库存为空，也不能把部分可见记忆说成全量清单。

### 查证和质量判断

每条拟保留或替换的事实都应说明跨会话的长期用途。一次操作的进度、读数或完成回执不能仅因事实正确、补充日期或调整主语而获得长期价值。

文字相似只用于发现候选。合并前核对主体、时间、适用范围和独有信息。临时要求不能被扩大为长期偏好，助手推断不能变成用户确认。

来源缺失、截断、已不可访问或仅有经历引用时，保留待核状态，继续检查其他条目。来源存在与原话支持该命题需要分别判断。

### 检查和修改边界

“只检查”“先给建议”等请求不得改变用户记忆的正文、有效状态和来源。持久化本次检查进度及建议不等于应用建议。

明确授权后，按授权范围处理相应记录和操作。已经明确授权的同一批处理不逐条重复询问；授权不覆盖后来新增的目标或实质变化的替代内容。Skill、记忆正文和模型自报不能成为授权来源。

区分以下处置：

- 曾经正确、现在过时：结束当前有效状态，保留有意义的历史。
- 原本就错、来源或归属错误：撤销错误派生事实，历史展示能识别其错误状态。
- 真实但只服务一次执行：退出普通长期层，原始会话仍可追溯。
- 重复：保留有依据的独有内容和来源，再处理重复部分。
- 改写：替代正文重新接受来源、范围和长期价值判断。

### 覆盖和续接

全量检查应明确本次清单、实际读取数、已判断数、已核验修改数，以及待核和未处理项目。读过正文不自动算作完成判断，执行请求已提交不自动算作修改成功。

中断、上下文压缩或重新打开后，能够找回已完成判断、待处理条目、证据缺口和执行回执，避免遗漏或重复操作。检查期间新出现的记忆须说明是否纳入本轮，不能悄悄改变完成比例。

### 修改一致性和可追溯性

修改前核对目标最新状态和相关普通事实。目标被后台抽取或其他会话改变时，重新判断受影响内容，不覆盖新状态。

修改后读回实际正文、有效状态、来源和变更关系。重复提交、超时重试或结果反馈丢失不能造成重复新增、重复退役或无法判断是否已生效。

已退出当前有效集合的旧事实，不得继续作为当前事实从普通记忆检索路径返回。替代事实与索引更新状态应可核验；暂未完成的更新不能报告为已完成。

原始证据、相关历史和操作原因保持可追溯。不得通过跨层批量删除来实现普通 Semantic 的撤销。

## 验收条件

- [ ] AC-01：正式产品工具装配支持用户在正常会话中查询全部当前有效的普通 Semantic；不依赖 Inspector、开发环境权限或临时工具注入。
- [ ] AC-02：支持单条、主题和全量检查；能完整遍历超过单页容量的清单，并准确报告实际范围。
- [ ] AC-03：维护查询和写入均限定所属用户及普通 Semantic；Core、Episodic 与原始会话不被维护操作读取扩展或修改。
- [ ] AC-04：来源查询保留发言者和宿主触发来源；缺失、截断、只有经历引用等情况正确标为待核，不伪造依据。
- [ ] AC-05：每个已检查 ID 有建议及理由；覆盖长期用途、错记、重复、过时、临时约束和执行流水，保留项也有长期用途说明。
- [ ] AC-06：只检查场景不改变用户记忆；明确授权后按范围执行批量修改，未经授权或超出范围的操作不生效。
- [ ] AC-07：改写、合并、退役和撤销的结果符合各自含义，保留必要独有信息及来源，并有可读回的实际回执。
- [ ] AC-08：压缩、中断和重新打开后可从剩余项目继续；未检查、待核、待执行和已核验修改不会混淆。
- [ ] AC-09：后台抽取或其他会话造成目标变化时，不覆盖新状态；重试和反馈丢失不产生重复应用。
- [ ] AC-10：修改后的普通事实状态、历史查询和普通记忆检索一致；退出当前集合的旧事实不会被当作当前事实返回。
- [ ] AC-11：真实模型验收经过正式注册的工具与维护 Skill，覆盖只检查及授权修改；确定性测试覆盖边界和失败路径，不以假模型代替行为质量结论。
- [ ] AC-12：源码运行及受影响的冻结运行时路径有匹配证据；独立检查包的运行结果不能充当正式产品验收。
- [ ] AC-13：项目规定检查通过，未验证平台和真实行为缺口明确记录，并取得用户验收确认。

真实模型调用、平台验证和冻结运行时验证继续服从各自既有治理流程。
