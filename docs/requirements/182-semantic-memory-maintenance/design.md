## 现状分析

现有 Memory 门面拥有抽取、检索、索引回填和运行生命周期；SqliteMemoryStore 拥有事实、变更组与抽取提交事务。普通事实具备有效期、软删除标记、来源和所属用户。检查工具没有正式注册；Inspector 的存在不等于会话能力。

通用结构化检索会同时查询 Episodic 并展开经历引用，invalidate_sources 也会跨层失效。本需求不以这些入口执行普通记忆维护。原始会话读取复用会话存储的读取协议，保留触发来源。

## 方案设计

### 模块与职责

- memory/maintenance：普通事实查询、检查清单、建议、冻结修改批次及提交核验的领域能力。
- memory/store/maintenance：使用现有 memory.db 连接和锁的持久化实现；不另建真实记忆副本或旁路写入器。
- agent/memory_maintenance：将来源指针解析为限定的原始事件证据，并适配已有审批 broker。
- agent/tools/builtin/semantic_memory：正式工具，区分普通事实查询、来源读取、检查进度和修改请求。所属用户、会话、真实发言及运行信息由宿主注入。
- agent_bridge/assembly 与工具 factory：在正常运行时注入服务；memory disabled 时返回明确不可用，不依赖 Inspector。
- 现有审批 REST、桌面审批卡片和 IM 审批路由：增加记忆修改批次类型，沿用现有审批模式和生命周期。
- maintain-af-memory：接入真实工具；质量标准继续由既有 reference 负责，不在工具里复制整套准入规则。

### 清单和恢复

在同一记忆库新增检查、条目和修改批次记录。检查保存 owner、发起会话、创建时间和选择范围；条目保存固定顺序、事实 ID、版本摘要、检查时正文/来源、建议和证据状态。

开始全量检查时固定当时的有效普通事实集合。后续新记忆不改变本轮分母。读取、判断、执行和核验分别计数；待核属于有判断但证据未齐，不等于检查全部通过。

分页使用固定清单位置或受绑定游标，不能对不断缩短的 pending 列表使用旧 offset。恢复查询可从原会话列出未完成检查；历史工具输出不是唯一进度来源。长正文和长来源均提供明确的续读位置。

### 原话和来源

只解析当前普通事实及其变更组中的直接事件引用。范围绑定所属用户和可访问会话，读取限定事件、发言者、时间、截断状态和 request_source。只有经历 ID 时不展开 Episodic，返回来源待核。

来源数据与当前用户指令分开；记录中的“用户希望”等文字不能充当本次授权。返回正文不包含工具执行输出、隐藏推理或不相关历史。查证缺口不阻断其它条目的检查。

### 建议、批次与授权

记录建议只修改检查元数据，不改用户记忆。保留、待核和拟修改均须有理由；改写保存候选正文，合并保存目标集合及独有来源。

修改先把已选择建议规范化为不可变批次，记录目标 ID、预期版本、处置、替代正文和证据引用，生成内容摘要。审批展示这一批的实际变化，沿用 per_request、auto_review、full_access 等现有模式。用户对一次明确批次的授权不拆成逐条确认。

模型不得传入“已授权”布尔值、数据库路径或任意 owner。检查/建议工具不包含事实写入能力；执行工具必须经过宿主审批并绑定该批摘要。拒绝、取消、超时、审批模式变化或目标变化时不能写入。新的目标或替代内容必须形成新批次，不能复用旧授权。

### 事务、处置和幂等

修改在 memory.db 的单一事务中完成：先核对全部目标的所属用户、普通层属性、有效状态和版本，再执行整批。任何目标失配时整批不写，返回需重新检查的条目。

- retire：结束有效期，保留历史上曾有效的事实。
- revoke：设置普通事实的撤销/软删除状态；保留事实行及维护回执，普通历史检索不再把它当成曾经正确。
- rewrite：退役或撤销目标，生成有来源的替代普通事实。
- merge：处理重复项并保留或生成承接独有信息的普通事实；保留参与项来源。
- 不物理删除原始会话、Episodic 或 Core，不通过来源批量失效代替按 ID 维护。

复用现有 Semantic 引入/退役、FTS 写入和变更组机制；维护回执补充处置语义、实际新旧 ID、原因、授权事实及提交时间。相同批次重试返回同一回执；相同请求标识对应不同正文时拒绝。

### 后台抽取与检索一致性

维护提交更新普通事实维护版本。抽取构建上下文时携带该版本；提交 Semantic 变化前核对它，拒绝依据维护前状态计算的过期结果，保留明确的重试/待处理状态，不覆盖维护后的事实。

维护完成后请求现有索引回填。检索候选仍按数据库当前有效/撤销状态回查，向量索引滞后不能使旧事实重新作为当前事实返回。写入回执与索引状态分开报告。

维护报告及引用是处理材料，不构成用户新确认。接线时核对 memory_feed，避免把助手的处置说明或引用旧错记重新认作用户事实；如需改变模型输入，纳入同一候选渲染确认。

### 验证与交付

先在隔离库测试分页、来源、清单恢复、事务回滚、跨 owner/层拒绝、版本冲突、重试回执和检索过滤。工具契约及正常 factory/Bridge 装配另行验证，避免只覆盖手工注入 registry 的测试。

固定合成场景，捕获正式 Conversation 的 baseline 与独立候选完整 ModelRequest（含工具）。具体原文确认后接入正式资源，再以相同样例重渲染核对。真实模型使用经确认的产品模型与有界清单，单独取得运行授权。

新能力须在安装版工作且现有 frozen smoke 未覆盖，按 package-sensitive 处理：增加离线 capability smoke，并按 frozen-runtime-packaging 运行要求验证。全量 check 和平台影响计划按项目规范执行。审批卡片复用现有领域组件；正式桌面视觉验证依用户授权执行。

## 影响分析

数据库采用加表和元数据迁移，不重写旧事实正文；旧无直接来源的记录继续可查但可能待核。新增写入入口与后台抽取共享一致性规则，不扩张跨层维护权限。

主要风险是长清单上下文压力、来源不完整、并发修改、权限投影差异及安装版缺失接线。分别通过持久化进度、显式缺口、版本校验、实际审批链和冻结运行时测试覆盖。
