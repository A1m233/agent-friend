# 072 · 中文内容平台搜索增强

> Chinese Social Platform Search

## 状态

CONFIRMED

## 1. 背景

agent-friend 已具备通用 `web_search` 与 `web_fetch`，但这条链路主要依赖普通互联网搜索索引和网页正文提取。当用户明确要求在小红书或 Bilibili 上寻找某篇笔记、视频、专栏或相关内容时，现有能力存在三个连续缺口：

- Agent 只能把平台名称混入普通查询词，不能稳定表达站点范围、内容类型、排序或时间等平台检索条件；
- 普通搜索索引对中文内容平台的覆盖不完整，容易漏掉用户已经确认存在的内容；
- 即使搜索结果出现目标 URL，登录态、动态渲染或平台特有资源标识也可能使通用网页读取无法取得足够正文。

现有搜索提示还会把当前年份加入所有查询。该约束适合明确要求最新信息的场景，但会污染不限定年份的帖子检索，进一步降低召回。

用户已经在真实对话中遇到“让 Echo 搜一个帖子却搜不到”的体验问题。因此，本需求要先改善通用搜索对中文内容平台的定向召回，再为小红书和 Bilibili 增加只读的平台搜索与内容读取能力，使 Echo 能完成“理解平台意图 → 找到候选内容 → 读取必要信息 → 基于来源回答”的完整链路。

## 2. 目标

1. 提高现有通用互联网搜索在小红书和 Bilibili 内容检索场景中的召回质量，避免无关时间约束和缺少站点定向造成的漏检。
2. 为小红书和 Bilibili 提供面向用户意图的只读搜索与内容读取能力，不再完全依赖普通网页索引和静态页面提取。
3. 让 Agent 能根据用户表达选择合适的通用或平台能力，并在需要时从搜索结果继续读取内容后再回答。
4. 让不同平台的底层接入方式统一进入 agent-friend 既有 Tool、会话事件、运行预算、错误处理和可信证据体系。
5. 用可复查的基线、候选验证和必要的运行 spike 支撑接入选择，不因开源项目声称支持某功能就直接视为可用。
6. 保持平台访问只读、低频、用户可控；遇到未登录、访问受限、内容不存在或平台能力不可用时如实反馈。
7. 当平台能力因缺少登录而中断时，让 Agent 判断缺失证据是否影响当前用户目标，并在合适的交互端请求授权；授权完成后无需用户重复说“继续”，由同一会话中的 Agent 重新规划并完成原目标。

## 3. 范围

### 3.1 包含

- 修正通用搜索对查询时间的处理：只有用户意图或事实时效性确实需要时才加入年份、日期或时间范围；寻找不限定时间的既有内容时不得强行附加当前年份。
- 让通用搜索能够表达小红书或 Bilibili 等明确站点范围，并在底层搜索服务支持时使用结构化的域名、地区、搜索深度或等价能力，而不是只依赖模型手写查询运算符。
- 允许 Agent 针对同一内容检索意图生成少量互补查询、合并并去重结果，在运行预算内提高召回；结果不足时仍需明确停止，不能无限改写重试。
- 支持识别用户明确指定小红书或 Bilibili 的搜索意图；未指定平台时，普通互联网搜索仍是默认入口，Agent 可根据结果和用户目标决定是否需要平台能力。
- 支持小红书笔记的关键词搜索、足以区分候选的基础信息，以及搜索候选或用户本轮明确提供的受支持笔记链接的正文和可用公开详情读取。
- 支持 Bilibili 视频、专栏与图文动态（`opus`）的关键词搜索或直链读取、足以区分候选的基础信息，以及选定内容的简介、正文或平台已提供字幕等可用文本读取。
- 搜索结果至少保留平台、标题、作者或发布者、内容类型、来源链接、平台资源引用，以及来源提供时的发布时间和互动信息。
- 内容读取结果必须能和搜索候选或本轮受信平台 URL 稳定关联；平台特有的临时标识、令牌或资源参数由工具链管理，不要求模型从 URL 或文本中自行拼装。
- 平台能力需要登录或本地连接器时，能够区分未配置、未登录、登录失效、访问受限和普通无结果，并引导用户完成必要的本地授权步骤。
- 平台工具应向 Agent 明确表达已经取得的证据、缺失的能力及其原因；是否必须登录才能完成当前目标由 Agent 结合用户请求判断，不由连接器直接替用户目标下结论。
- 桌面聊天中，Agent 能说明登录对当前目标的必要性并发起可确认、可取消的本地授权请求；用户明确同意后才启动对应平台的本地登录流程。
- IM 中，Agent 能识别当前请求来自 IM，并在登录只能由电脑端完成时明确告知用户、将待处理授权交给桌面端；不得声称用户可以在当前 IM 对话内完成本地浏览器或二维码授权。
- 本地授权完成后，原会话能够自动恢复 Agent 执行；Agent 根据最新上下文决定再次搜索、读取或采用其它路径，代码层不得不经 Agent 判断就直接重放此前失败的业务工具调用。
- 从 IM 发起的原任务在桌面端完成授权后，仍应回到原 IM 会话继续并把最终结果送回原交互端，不要求用户在任一端再次发送“继续”。
- 所有平台凭据、Cookie 或登录状态只在实现所需的受控本地边界内使用，不进入模型可见结果、会话正文、普通日志或仓库文件。
- 平台搜索和读取继续进入既有 tool call/result 事件，保留来源 URL、失败类别、耗时和结果数量等必要诊断信息。
- 在确定生产接入前建立当前 `web_search` 基线，选择覆盖不同难度的固定公开案例；对候选开源方案进行静态核对，并在静态证据不足时运行受控 spike 验证实际能力。
- spike 至少核对目标功能、运行环境、依赖、许可证、登录要求、结果字段、失败行为、Windows 可运行性、维护活跃度和与 agent-friend 只读边界的适配成本。
- 将 spike 的直接观察、解释、局限和最终决定分开记录，并为采用或放弃的候选保留可追溯依据。

### 3.2 不包含

- 小红书或 Bilibili 的发布、删除、点赞、投币、收藏、关注、评论、回复、私信或其他写操作。
- 自动处理验证码、规避平台风控、绕过访问控制、模拟高频人类行为或建立批量爬取能力。
- 首页推荐流运营、热点监控、竞品批量分析、账号自动化运营或长期数据仓库。
- 小红书评论的完整采集与分析。
- Bilibili 评论、弹幕的完整采集与分析，以及无平台字幕视频的音频下载和语音转写。
- 抖音、快手、微博、知乎等其他平台；后续应能沿既有边界增加，但不作为本需求验收范围。
- 通用 MCP client/runtime、第三方动态工具市场、用户自定义 MCP 配置 UI 或完整 Skill runtime。
- 为平台登录单独建设完整的账号设置中心；首版只要求存在安全、可理解、可恢复的本地授权路径。
- 在 IM 消息中传递二维码、Cookie、令牌或其它可复用登录材料，或仅凭 IM 中的自由文本确认就在可能无人值守的电脑上启动浏览器、图片查看器等本地授权界面。
- agent-friend 托管的平台访问服务、账号体系、云端代理、凭据代管、平台流量中转或集中采集服务；本需求的连接器、登录态和平台请求全部在用户本机运行。
- 改变 Conversation 的工具循环、并发、取消、运行预算或上下文投影语义。
- 允许模型读取任意构造的平台 URL、跨轮复用未再次授权的直链，或把通用 `web_fetch` 冒充为小红书/Bilibili 平台工具。
- 以任何方式承诺绕过平台协议、开放能力或访问限制；若候选路径缺乏可接受的授权与稳定性，本需求应记录阻塞或收窄能力，而不是隐藏风险继续接入。

## 4. 核心需求

### 4.1 平台意图与工具路由

- **R-1.1 明确平台优先**：用户明确说“在小红书搜”“去 B 站找”或提供对应平台内容线索时，Agent 应优先使用能表达该平台语义的搜索能力，不得把普通互联网搜索的空结果直接等同于平台上不存在。
- **R-1.2 未指定平台保持通用**：用户没有指定平台、问题也不依赖平台内部字段时，Agent 继续使用普通互联网搜索，不为所有搜索增加平台工具成本。
- **R-1.3 可解释降级**：平台能力未配置、未登录、受限或失败时，Agent 可以尝试站点定向的通用搜索作为补充，但必须保留证据边界，不得把降级结果描述成已经完成站内搜索。
- **R-1.4 多步读取**：搜索摘要不足以回答用户问题时，Agent 应读取最相关的少量候选内容再回答；没有读取正文时不得声称已经看过完整帖子、视频内容或专栏正文。
- **R-1.5 平台直链优先**：用户本轮明确提供受支持的小红书或 Bilibili 内容 URL 时，Agent 应优先通过平台读取能力解析同一资源，不先把精确资源退化成宽泛关键词搜索，也不得把 `web_fetch` 描述成平台工具。直链不受支持或未获本轮授权时返回明确状态。

### 4.2 通用搜索召回增强

- **R-2.1 时间约束按需**：年份、日期和时间范围只在用户明确要求或问题具有真实时效性时加入查询；寻找已有内容时保持用户给出的时间线索，不添加无依据的当前年份。
- **R-2.2 结构化站点定向**：底层服务支持时，平台范围应通过结构化域名或等价过滤表达；不支持时才退化为查询文本中的站点限制，并在结果中核对实际来源域名。
- **R-2.3 有界查询扩展**：允许围绕标题片段、作者、主题、时间线索和平台名称生成少量互补查询；扩展必须有上限、结果去重，并在无新增证据时停止。
- **R-2.4 结果证据**：通用搜索结果继续保留标题、URL 和摘要，并在 provider 提供时保留相关度、发布时间或其它有助于筛选的可信字段。
- **R-2.5 既有场景兼容**：实时新闻、产品信息和其它普通网页搜索行为不得因平台优化而退化；未涉及平台内容时不强制启用平台过滤。

### 4.3 小红书只读搜索与读取

- **R-3.1 笔记搜索**：能够按关键词搜索小红书笔记，并在来源支持时使用内容类型、发布时间或排序等筛选条件。
- **R-3.2 候选可区分**：搜索结果应提供标题、作者、内容类型、来源链接和可用的发布时间或互动信息，让 Agent 与用户能够区分相似候选。
- **R-3.3 笔记读取**：能够读取选定笔记的正文和回答当前问题所需的公开详情；正文不存在、不可见或读取受限时返回明确状态。
- **R-3.4 登录边界**：需要登录时由用户主动完成本地登录；系统不得要求用户把 Cookie、密码或令牌粘贴到普通对话中。
- **R-3.5 平台引用连续性**：搜索结果产生的资源引用能够直接用于后续读取，不依赖模型猜测或重建平台内部参数。
- **R-3.6 受信直链读取**：用户本轮提供可解析且包含上游读取所需参数的小红书笔记链接时，工具可在隐藏授权与固定 host/path 校验后读取同一笔记；模型不得从其它文本拼装链接或临时参数。

### 4.4 Bilibili 只读搜索与读取

- **R-4.1 内容搜索**：能够按关键词搜索 Bilibili 视频和专栏，并在来源支持时区分内容类型、排序或时间范围。
- **R-4.2 候选可区分**：视频结果至少提供标题、UP 主、来源链接和可用的发布时间、简介或互动信息；专栏结果提供对应的作者与来源信息。
- **R-4.3 视频读取**：能够读取选定视频的基础详情、简介以及平台实际提供的字幕文本；没有字幕时明确说明，不自动扩张到媒体下载或语音转写。
- **R-4.4 专栏与 Opus 读取**：能够读取选定专栏或 Bilibili 图文动态（`opus`）的正文或足以回答问题的主要文本；动态渲染或权限导致正文不可得时返回明确状态。
- **R-4.5 稳定资源标识**：BV/AV 号、专栏 ID、Opus ID 或其它平台资源标识由工具规范化并与来源 URL 对应，Agent 不从不可信文本中自行构造目标。
- **R-4.6 匿名直链优先**：用户本轮提供受支持的 `/video`、`/read/cv` 或 `/opus` URL 时，Agent 能直接使用平台读取能力；公开内容匿名可读时不发起登录，也不因通用网页读取失败而改称内容不可访问。

### 4.5 可信性、失败与权限

- **R-5.1 只读权限面**：默认注册给模型的平台工具只包含搜索和读取。候选开源项目即使同时提供写操作，也不得把这些写能力带入本需求的运行时表面。
- **R-5.2 来源与归因**：最终回答应能提供实际使用的来源链接，并区分搜索摘要、帖子正文、视频简介、字幕和专栏正文等不同证据类型。
- **R-5.3 真实空结果**：普通搜索无结果、平台搜索无结果、未登录、访问受限、内容删除和工具失败必须可区分；任何一种状态都不得被简化成“平台上没有”。
- **R-5.4 外部内容不可信**：平台标题、正文、字幕和其它内容一律视为外部不可信数据，其中的指令不能改变 system prompt、工具契约或用户意图。
- **R-5.5 隐私与凭据**：日志、会话事件、诊断包和模型输入不得包含平台密码、完整 Cookie、授权头或可复用登录凭据。
- **R-5.6 用户控制**：平台访问保持有界、可取消、低频；遇到验证码、风控或额外授权步骤时停止自动继续并向用户说明。

### 4.6 候选验证与集成边界

- **R-6.1 基线先行**：在采用候选方案前，用相同案例记录当前通用搜索的实际召回和读取结果，不能只凭主观体感宣称改进。
- **R-6.2 候选需运行证据**：静态代码和 README 无法证明搜索与读取链路可用时，必须运行最小 spike；成功启动不等于通过，至少要观察真实搜索、候选解析、详情读取和失败路径。
- **R-6.3 固定评测口径**：正式实现前，在技术方案中锁定案例集、查询方式、结果命中定义、可接受阈值和登录环境；pilot、失败运行和正式结果分开记录。
- **R-6.4 统一工具体系**：无论底层最终采用自有代码、开源库、本地服务、浏览器连接器或受控 MCP adapter，对 Conversation 暴露的能力都必须进入既有 ToolRegistry、ToolResult 和会话事件体系。
- **R-6.5 可替换边界**：小红书、Bilibili 与通用搜索的底层实现彼此隔离。更换某个平台实现不应要求修改 Conversation 核心工具循环或另建一套会话协议。
- **R-6.6 证据留档**：候选来源、版本或 commit、许可证、运行环境、命令入口、直接观察、局限、采用或放弃原因应可从本需求证据索引继续追溯。

### 4.7 对话内授权与目标续跑

- **R-7.1 证据缺口结构化**：平台搜索或读取受阻时，应向 Agent 区分已经取得的证据、缺失的内容或能力，以及 `auth_required`、`auth_expired`、访问受限等原因；不得只返回一段无法稳定判断的通用失败文案。
- **R-7.2 目标影响由 Agent 判断**：Agent 应根据用户明确目标判断缺失证据是阻断目标、实质影响答案可靠性，还是仅为可选补充。已有证据足够时直接回答并说明边界，不为获取非必要信息打断用户登录。
- **R-7.3 桌面显式授权**：需要登录且当前交互端为桌面时，Agent 先解释原因，再发起与当前会话和平台绑定的显式授权请求；只有用户确认后才启动本地登录，拒绝、取消、超时或失败均不得被视为已授权。
- **R-7.4 IM 端能力边界**：当前交互端为 IM 时，Agent 必须知道本地平台登录不能在该 IM 对话内完成，并将授权请求交给运行 agent-friend 的电脑端处理；不得要求用户在 IM 中发送敏感凭据，也不得承诺当前端无法提供的授权操作。
- **R-7.5 Agent 续跑而非工具重放**：登录成功后，系统应自动唤起原会话中的 Agent continuation，并提供可信的授权完成状态。由 Agent 基于最新上下文决定下一步，不在代码层直接重放原失败调用，也不要求用户再次发送“继续”。
- **R-7.6 原交互端连续性**：授权是电脑端的本地交互，不改变原用户任务的回复目的地。从 IM 发起的任务完成授权并续跑后，最终回复仍返回原 IM 会话；桌面发起的任务继续留在原桌面会话。
- **R-7.7 有界恢复**：同一授权请求应可取消、过期并避免并发重复；授权失败、用户拒绝或续跑后仍受限时，Agent 如实说明并停止循环请求，不得自动反复拉起登录。

## 5. 用户体验与信任边界

- Echo 可以自然地说“我去小红书找找”或“我看看这个 B 站视频”，但只有实际完成对应平台调用后才能声称做过这些动作。
- 用户指定平台时，Echo 不应因为普通网页搜索没有结果就断言内容不存在；应使用平台能力、说明当前访问限制，或请求更有区分力的线索。
- 搜索结果较多或存在相似候选时，Echo 可以列出少量候选请用户确认，不应为追求一次回答而静默选择证据不足的对象。
- 最终回答以用户问题为中心，不机械倾倒平台内部 ID、临时令牌、原始 JSON、Cookie 状态或 provider 技术细节。
- 平台内容具有删除、权限、个性化排序和动态变化。回答只能陈述本次实际取得的证据，不把某个账号或某次搜索排序外推为平台全局结论。
- 需要用户登录时，说明“需要在本机完成平台登录”以及下一步；不要求用户在对话里发送敏感凭据。
- 在桌面端，登录说明和真正的执行授权应清晰区分；自然语言用于解释原因，结构化确认动作代表用户允许启动本地登录流程。
- 在 IM 端，Echo 应明确说明授权需要回到运行 agent-friend 的电脑完成。授权完成后原任务自动继续，最终结果回到用户最初发起任务的 IM 会话。
- 登录成功不等于必须机械重试原操作。Echo 应重新检查当前目标与已有证据，选择合适的搜索、读取或回答路径。
- 平台能力不可用时允许坦诚留白，不以绕过风控、扩大采集或伪造已读内容换取表面完成。

## 6. 验收标准

### 6.1 通用搜索召回

- [x] 不限定时间的帖子检索不会被自动附加当前年份；明确要求最新、某年或某时间段时仍会使用正确时间约束。
- [x] 用户明确指定小红书或 Bilibili 时，通用搜索能够使用结构化站点定向或经过结果域名核验的等价路径。
- [x] 有界的互补查询能够合并、去重结果，并在重复无新增或达到运行预算时停止。
- [x] 普通实时信息与非平台网页搜索的既有行为、失败语义和来源字段不退化。

### 6.2 小红书

- [x] 用户提供明确关键词后，Agent 能通过小红书只读能力返回可区分的笔记候选，而不是只报告普通互联网搜索结果。
- [x] Agent 能从选定候选继续读取笔记正文和可用公开详情，并基于实际取得的内容回答、附来源链接。
- [x] 搜索结果到详情读取的资源引用可直接延续，不要求模型自行拼接平台临时参数。
- [x] 未登录、登录失效、无结果、内容不可见和访问受限具有可区分行为；任何状态都不会被误报为“平台上不存在”。
- [x] 登录步骤由用户在本机主动完成，密码、Cookie 或令牌不会进入普通对话、模型输入、仓库或诊断包。

### 6.3 Bilibili

- [x] 用户提供明确关键词后，Agent 能通过 Bilibili 只读能力搜索视频与专栏，并返回标题、作者或 UP 主、内容类型和来源链接等可区分字段。
- [x] Agent 能读取选定视频的详情、简介和平台已有字幕，或在没有字幕时明确说明当前文本边界。
- [x] Agent 能读取选定专栏的主要正文，或在访问受限时返回明确状态。
- [x] Agent 能读取用户本轮提供的受支持 Bilibili `opus` 直链；匿名可读时不要求登录，并将图文正文标为实际取得的证据。
- [x] BV/AV 号、专栏 ID、Opus ID 和 URL 被稳定规范化并对应到同一资源，不从不可信正文中构造未授权目标。

### 6.4 基线、spike 与质量门槛

- [x] 固定案例集对每个平台至少覆盖精确标题、标题片段、作者加主题、主题加时间线索四类查询，并记录当前 `web_search` 基线。
- [x] 技术方案锁定案例数量、命中定义、结果位次和通过阈值；Bilibili 达到门槛，小红书未达项按原口径完整保留，并由用户接受为首版已知质量边界，不通过删除案例、扩大窗口或降低阈值改写结果。
- [x] 每个进入最终方案的外部候选都有精确版本锚点、许可证核对、Windows 运行结果、搜索与详情读取观察、失败路径和局限记录。
- [x] 未采用候选的放弃原因仍可追溯，不把 README 声明或单次成功启动当成生产可用证据。

### 6.5 权限、可信性与回归

- [x] 模型可见的平台工具表面只有搜索与读取，不包含发布、互动或其它写操作。
- [x] 平台内容进入模型前保持不可信数据边界，页面或帖子中的指令不能改变工具和系统行为。
- [x] 搜索摘要、正文、简介、字幕和专栏等证据类型在结果中可区分，最终回复不会声称读取了实际未取得的内容。
- [x] 工具调用和结果继续进入现有会话事件；失败不破坏对话继续进行，且不泄漏 provider、Cookie、授权头、调用栈等内部信息。
- [x] 默认自动化测试使用 fake provider、fixture 或本地受控服务，不请求真实小红书、Bilibili、Tavily、LLM 或其它外部付费服务。
- [x] 项目统一检查脚本全部通过，现有 `web_search`、`web_fetch`、工具运行预算、取消、并行与上下文投影行为不退化。

### 6.6 对话内授权端到端门槛

- [x] 可重复的端到端测试从真实 Conversation、Bridge 和交互端上下文进入，而不是直接调用认证 manager 或 connector；受控 fixture 覆盖桌面与 `im:qq` 的可信 surface，并证明两种端行为不同。
- [x] 桌面未登录场景在受控 E2E 中从平台受阻进入显式授权；批准后同一会话自动 continuation，Agent 重新搜索、读取并完成原目标，无需用户补发“继续”。
- [x] `im:qq` 受控 E2E 明确要求回运行 agent-friend 的电脑授权；桌面批准后 continuation 保留原 destination，最终结果只返回原 IM，不在 IM 内启动登录或索要凭据。
- [x] 用户拒绝、取消、授权超时、授权失败和请求终态均有确定性状态机回归，不会直接提交 continuation 或形成重复登录循环。
- [x] 小红书 Chromium、Bilibili 二维码、匿名读取、平台搜索/读取和授权卡片均取得选择性的真实桌面观测；二维码、凭据、正文和其它敏感材料未进入仓库证据。
- [x] 用户在平台 URL 后紧接中文标点与自然语言、且 URL 含跟踪参数时，真实 Agent 仍能识别同一受信资源并优先调用 `social_read`；不会误走 `web_fetch`、宽泛搜索或声称执行了实际未发生的平台调用。
- [x] 用户基于当前自动化门禁、真实 smoke 和已知残余风险，明确同意不再追加真实平台/LLM smoke，并按“没有已知阻塞首版的明显 bug”完成本需求验收。

### 6.7 非阻塞后续验证

以下原定扩展验收矩阵在 2026-08-02 收口时转为后续观察项，不作为本需求完成门槛，也不视为已经验证：

- 从真实 QQ inbound 发起受限目标、电脑批准后最终回复返回同一 QQ 会话。
- DeepSeek 与 Kimi 分别从证据缺口走完整授权请求和 continuation，而不只是平台搜索/读取。
- 小红书与 Bilibili 分别从隔离未登录状态走到真实登录完成、Agent continuation 和原目标完成。
- 对“已有匿名证据足够、登录后字段只是可选补充”的真实模型判断增加独立重复样本。

## 7. 依赖与约束

- 现有 Tool Protocol、ToolRegistry、ToolResult、会话事件和运行预算由既有需求提供，本需求只在其边界内增加或扩展只读能力。
- 小红书和 Bilibili 的公开页面、登录要求、访问限制和接口行为可能随平台变化；具体接入方式必须由技术方案结合最新静态与运行证据选择。
- 开源代码许可证只约束代码使用，不等同于平台授予内容访问、自动化或商业使用权限。候选技术可运行仍不能替代平台规则与产品风险评估。
- 真实平台 spike 可能需要公网访问和用户本机登录。运行前应说明目标、请求规模、账号影响和数据边界；需要登录时由用户主动操作。
- agent-friend 当前不承担面向用户的平台访问服务端角色。除用户自己配置的搜索 provider 外，平台请求应由桌面应用在本机直接发出；不得以“以后放到我们的云端代理”作为首版安全、兼容或凭据治理的兜底。
- 本需求不引入通用 MCP 或 Skill runtime。若候选以 MCP 暴露能力，只允许在本需求内通过最小、只读、受控适配接入现有工具体系。
