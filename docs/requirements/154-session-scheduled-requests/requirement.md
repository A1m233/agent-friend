# 154 · 会话定时请求与任务管理

## 状态

CONFIRMED

## 背景

099 已提供持久化定时任务、调度、运行记录及自然对话管理能力，但尚无前端管理页面。其每次执行创建独立会话的方式，与本需求确认的“在固定会话中定时发送一次用户请求”不同。

本需求建立用户可直接操作的定时任务模块，并将任务执行统一为普通会话中的请求。它承接 099 延期的界面范围，调整后续执行的会话归属；099 的历史文档和运行事实继续保留。

## 目标

- 用户可以在前端创建、查看、编辑和管理定时任务。
- 一个任务绑定一个固定会话，定时发送保存好的请求；会话承载上下文、执行过程、结果和后续交流。
- 模型与访问权限可跟随会话，也可由任务单独指定，不改变会话自身配置。
- 同一会话通过通用等待队列串行处理请求，定时任务只作为请求来源。
- 用户可在任务详情、运行历史与会话消息之间相互定位，并正确理解任务状态。

## 核心定义

- **定时任务**：保存目标会话、请求内容、执行配置和时间安排的持久安排。
- **一次执行**：到时或手动立即运行后，向目标会话提交一次用户请求并跟踪其结果。对应完整用户请求轮次，可包含多次模型调用和工具操作。
- **会话**：提供执行时的已有上下文，保存真正开始执行的请求及回复，并允许用户继续手动交流。
- **会话等待队列**：会话通用请求执行能力，不由定时任务模块拥有；其请求可来自手动发送、定时触发或其它接入方。

## 范围与需求

### R-1 固定会话与创建方式

- 创建任务时，用户选择一个已有普通会话，或新建一个普通会话并绑定任务。
- 新建会话只发生一次，之后每次执行复用该会话，不为每次触发创建新会话。
- 新建会话时单独显示名称输入框，供用户确认或修改，不强制与任务名称相同。
- 一个会话可以关联多个独立管理的定时任务，各任务保留自己的时间、配置和运行历史。
- 任务创建所在的聊天只代表来源；目标会话必须明确，不把来源关系自动解释为执行绑定。
- 定时请求使用目标会话执行时的上下文；用户手动交流也会成为后续执行可用的会话上下文。

### R-2 请求内容与配置

- 正文和附件保存在任务中，之后按时间安排重复提交；附件遵循现有统一会话文件语义和应用级限制。
- 保存后的附件在首次触发前、重复执行及应用重启后仍可读取，不依赖短期上传草稿；缺失或损坏时如实反馈。
- 模型、访问权限默认跟随目标会话在实际执行时的当前配置；任务可分别单独指定，界面明确显示跟随或覆盖状态。
- 单独指定的配置只影响该任务发起的请求，不改写目标会话的默认配置，也不影响之后手动发送的请求。
- 访问权限沿用产品已有的权限能力与审批边界，不把过去的一次性审批变为可重复使用的批准。
- 会话中的普通追问不会隐式改写任务正文、附件或时间安排；用户明确修改任务时，前端和已有自然对话管理入口使用同一任务状态。
- 099 已有的可选 Skill 能力需要兼容，不因增加界面或固定会话而丢失。

### R-3 通用会话队列

- 同一会话已有请求执行时，定时请求进入该会话等待队列，不打断当前轮；不同会话保留现有有界并发能力。
- 定时任务不拥有另一套执行队列，不要求通用队列理解任务时间规则或任务管理状态。
- 排队、开始、取消与终态由公共请求执行能力提供；任务运行历史关联这些状态，不维护独立的执行事实。
- 等待期间任务详情显示“等待会话空闲”；真正开始执行时才将定时请求写入会话消息历史。
- 请求来源用于展示和关联，不应仅因来源是定时任务就在普通手动请求到来时被隐式丢弃。
- 明确的容量限制、拒绝、取消、失败和重启中断应可查询，不能让请求无记录消失或把未执行标成完成。
- 本期不以通用队列为由重做与此需求无关的所有后台主动事件策略。
- 根据 2026-10-07 用户确认，本期暂不开放聊天输入框的手动发送入队交互：执行中可准备草稿，保留原停止入口，待当前执行结束后再发送；底层通用队列继续供定时请求使用。

### R-4 前端任务管理

- 主窗口侧边栏提供“定时任务”入口，包含任务列表、创建／编辑和任务详情。
- 列表可辨认任务名称、目标会话、启用状态和下一次执行时间，并可进入详情。
- 列表采用向下滚动加载，保留已加载内容，不展示上一页／下一页按钮。
- 创建／编辑可配置请求正文、附件、目标会话、时间安排及模型／访问权限的跟随或覆盖。
- 表单优先展示正文、时间和目标会话，附件按需添加；模型／思考强度、Skill、权限收进更多设置。模型和强度直接选中实际配置，不额外添加默认／跟随占位项；保留未修改时跟随会话以及恢复会话配置的能力。
- 新建计划自动使用本地时区，编辑已有任务保留原计划时区，只展示提示，不要求填写时区。表单同排控件对齐，操作按钮使用有背景的样式；“更多设置”使用内容宽度的普通白底按钮（outline，背景随主题适配）。底部不添加独立色块。
- 详情展示上述配置和运行历史，支持暂停、恢复、立即运行和删除，并可打开目标会话。
- 运行历史区分等待、执行中、等待审批及最终结果，保留计划时间与实际执行时间；失败或跳过展示原因。
- 已产生会话消息的运行可跳转至对应消息；尚未开始或提交失败时不伪造消息定位。
- 本期频率入口开放一次、每天、工作日、每周，暂不开放每月与固定小时间隔；首次执行时间的设置体验完善前不扩大入口。时区自动处理，不要求用户理解底层调度表达式。已有其它频率任务仍可保留原安排。

### R-5 消息来源与双向导航

- 由定时任务发起的用户消息气泡上方显示“由 xxx 定时任务发起”。辅助文字为灰色，任务名称 xxx 为蓝色链接。
- 点击任务名称进入对应任务详情；正文和附件继续按普通用户消息呈现。
- 来源随具体消息持久保存，刷新或重开会话后仍可识别；手动消息不显示该来源标识。
- 同一会话存在多个任务时，每条消息能准确定位其来源任务。
- 任务删除后，历史消息保留来源，点击时明确展示任务已删除，不能形成无反馈的失效链接。

### R-6 既有任务与生命周期

- 旧任务需要由用户确认固定目标会话后再进入新的执行方式；不得猜测来源会话或某次历史会话就是目标。
- 旧配置和历史执行记录保留，旧运行仍关联原来的实际会话，不能迁移成从未发生过的历史。
- 删除目标会话后，关联任务停止后续发送并显示原因，不悄悄新建替代会话。
- 归档目标会话后，关联任务停止执行，尚未开始的请求不再启动；取消归档不自动恢复任务，用户可以显式恢复。
- 暂停和删除任务沿用已有生命周期语义，不撤销已经完成的工作或抹除历史。
- 除固定会话及其请求接入所必需的调整外，沿用现有时间规则、离线补跑、同任务非重叠执行和失败不自动重放整个工作流的原则。
- 本地应用退出或设备休眠期间不声称已经执行；应用重启后，已经提交但尚未完成的请求标记为中断，不自动重放。已经持久化完成事实的运行保留其真实终态。

## 不包含

- 不绑定会话的独立任务、每次触发新建会话、一次触发向多个会话同时执行。
- 额外的任务专属 Agent 执行器、对话系统或等待队列。
- 新增复杂工作流编排、外部事件触发、任意 cron／RRULE、云端调度或应用退出后的后台服务。
- 新增权限等级、自动继承一次性审批或自动重放已执行的外部副作用。
- 通用会话队列的拖拽排序、批量编排等未讨论的高级管理功能。

## 验收条件

- [ ] **AC-1**：可以选择已有会话或新建一次会话创建任务；连续两次触发进入同一目标会话，目标会话可继续普通交流。
- [ ] **AC-2**：同一会话关联多个任务，任务独立管理，来源与运行记录不混淆。
- [ ] **AC-3**：正文和附件可保存、修改、重启恢复和重复使用；首次执行前的附件不会被草稿过期或无引用清理误删，缺失／损坏有明确错误。
- [ ] **AC-4**：跟随模式使用实际执行时的会话模型和权限；覆盖模式使用任务配置且不改变会话默认值，异常和取消后同样不泄漏覆盖配置。
- [ ] **AC-5**：会话忙时请求等待，不打断当前轮；同会话串行、跨会话有界并发，通用队列不依赖定时任务领域。
- [ ] **AC-6**：等待请求不会因随后手动发送而被隐式丢弃；等待、开始、取消、拒绝、失败和中断可准确查询。
- [ ] **AC-7**：定时请求只在真正开始执行时进入消息历史；灰色来源提示和蓝色任务链接在实时与历史展示中一致，手动消息不误标。
- [ ] **AC-8**：侧边栏入口、列表、创建／编辑和详情可用，暂停、恢复、立即运行、删除与自然对话管理共享同一状态。
- [ ] **AC-9**：从消息打开任务详情，从已执行的运行记录定位对应会话消息；等待或失败但无消息的运行有正确反馈。
- [ ] **AC-10**：旧任务在用户确认目标前不会自动采用新绑定执行，旧配置与历史保持可查，确认后可按新方式运行。
- [ ] **AC-11**：目标会话归档或删除后停止后续发送并说明原因，未开始请求不继续启动，取消归档不自动恢复任务；任务删除后历史消息保留来源，链接提供已删除状态。
- [ ] **AC-12**：原有时间／时区、离线补跑、同任务非重叠、Skill 和审批能力不回归；重启后未完成请求标记中断且不自动重放，已持久化终态不被改写。
- [ ] **AC-13**：核心逻辑、跨层来源投影、附件寿命、配置隔离、排队与迁移有确定性自动化测试，项目统一检查通过；真实 LLM 和桌面视觉验证按单独授权如实记录，用户确认最终验收。

## 方案阶段待展开

- 队列接入、请求优先级与已有主动事件的兼容；手动发送入队交互延后细化。
- 保存任务附件与排队请求附件的持久引用及清理所有权。
- 请求级模型／权限配置的执行边界，避免通过修改会话默认值实现临时覆盖。
- 任务编辑、暂停／删除、会话归档和应用重启与已排队请求之间的实现时序，见技术方案。
- 旧任务的目标确认、迁移幂等与升级期间的调度门禁。
- 页面布局、运行记录分页／刷新、消息定位和已删除任务状态。

上述问题不改变已确认的产品定义；若方案需要扩大行为范围，应重新讨论。
