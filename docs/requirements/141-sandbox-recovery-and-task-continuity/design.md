# 沙箱故障静默恢复与任务续接 — 技术方案

## 状态

CONFIRMED（2026-09-24 用户确认统一恢复、原调用等待、安全续接及保护健康在途任务）

## 需求

[requirement.md](./requirement.md)

## 现状

命令工具在授权后校验环境、准备只读工作目录，再通过 `process/start` 启动。Windows 修复已有 helper 探针、初始化和读写两种实际执行验证，但仅从显式入口调用。工具运行器独立计算超时，进程启动 RPC 失败当前移除本地跟踪记录；超时和断线不证明进程未启动。

## 方案

### 恢复所有者与范围

在 `agent.command_runtime` 增加小型恢复协调器，由共享 CommandRuntime 持有。普通宿主命令不进入它。Windows 沙箱准备和启动经过该协调器；显式修复与自动恢复使用同一互斥范围。协调器只接受已完成权限审批的调用；不赋予新文件或网络权限。

同一恢复期间阻止新的沙箱准备/启动，等待已进入启动边界的操作退出，以及健康在途命令结束；不为了修复关闭健康 exec-server 或杀业务进程。并发等待者加入同一恢复，单个取消只退出自己的等待，所有等待者退出后不继续发起新的修复阶段。

### 故障分类与续接

- 初始化未完成或已记录的沙箱故障：原命令未发出，可自动修复后启动。
- 文件系统 helper 明确失败：仅对准备产品自有目录的确定性操作恢复并重试。
- `process/start` 收到明确的、结构化 RPC 拒绝，且属于已知沙箱启动失败：保留失败证据，恢复后可重试启动；如已收到输出/终态事件则不再认定未执行。
- RPC 超时、断线或缺少沙箱确认：保留进程标识和未知结果，不自动重放。未知在途操作阻止可能影响其身份的自动初始化，直到能够获得确定终态；固定后端不支持重新附着时如实报告限制。
- 已启动进程继续沿现有事件和本地 snapshot 观察；已完成结果直接复用。普通业务非零退出、ACL 拒绝、代理故障及输入错误不触发沙箱修复。

恢复复用现有 setup/probe，读写执行与文件系统准备验证均成功才放行。探针走内部不递归恢复路径。每次续接前重新检查取消、路径身份和原授权风险指纹；输入不变才允许续接。

### 预算与取消

一个工具调用在准备和启动之间共享最多一轮外层恢复预算。一个 runtime 的自动恢复结束后 60 秒内不启动另一轮恢复（已恢复健康时正常命令不受影响）；手动修复保持可用。底层固定版本已有一次凭据重试，外层只包装一次，不声称可限制其内部系统调用次数。

自动恢复等待总预算 480 秒，覆盖等待安全时机、复用现有最长 300 秒初始化及后续探针；无操作进展不续期。工具控制器为该等待提供至多 480 秒的受控额外预算，业务命令自己的执行时限不因此增长。恢复期间仍检查 run 取消，不通过延长所有工具的默认超时实现。

UAC 允许出现。取消后立即停止该等待者并禁止其业务续接；已经提交给 Windows 的初始化不能宣称可撤回，协调器在该修复实际结束前保持互斥，避免第二次提权并发。无人确认时按时限失败。显式修复与自动修复不相互套娃。

### 工具、授权与呈现

Bridge 和审批组件允许先批准规范化命令，再由工具内部处理沙箱就绪；不再要求用户先去设置修复。既有授权内容与每次授权/会话自动模式保留。运行中的工具卡维持普通等待，不显示恢复专用入口或消息；最终恢复失败后才允许既有错误呈现与手动修复入口。

现有命令工具只在具备授权 surface 的桌面聊天中开放；IM/定时任务的既有不支持边界保持，不借本需求开放宿主命令权限。直接受信任的 runtime 调用使用同一协调器；没有授权的入口继续拒绝。

### 诊断与持久化

优先复用现有脱敏 diagnostics 和独立 sandbox incidents，记录恢复事件、阶段与同一 operation 的关联，不保留原始命令或凭据。新增诊断语义须同步 producer capability、consumer handler、reference 与测试。自动恢复的运行中协调状态不跨 Bridge 重启恢复；历史调用仍按原 resident-only/持久化证据契约处理，重启不自动重放业务。

## 涉及模块

| 模块 | 改动 |
| --- | --- |
| command_runtime | 恢复协调、明确启动拒绝与结果未知区分、修复/探针取消检查 |
| tool_runtime | 有界恢复等待预算，不改变普通工具超时 |
| command tools / approvals | 原调用内集成、续接前重新校验、解除授权前就绪限制 |
| chat approval/result presentation | 保留普通批准与等待，成功恢复不显示中间错误 |
| diagnostics producer/consumer | 按实际新增字段或事件语义同步 |
| tests | 故障注入、并发、取消、预算、无重复执行及入口边界 |

## 验证与限制

用 fake exec-server 和受控同步事件验证完整调用链，禁止以 sleep 凑并发顺序。运行 backend、frontend、Rust 项目检查。真实 Windows UAC 与现场恢复单列验收缺口，不自动操作用户 production。新增运行时能力按 frozen-runtime-packaging 评估，命中 package-sensitive 时补 frozen smoke，安装包交付另走标准入口。

不承诺未知结果的任意命令可重放，也不承诺通过重连恢复固定后端不支持的进程附着；最终报告保留这一边界。
