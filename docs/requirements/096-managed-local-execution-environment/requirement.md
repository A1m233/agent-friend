# 受管本地执行环境

## 状态

CONFIRMED

## 背景

需求 085 已经让 agent-friend 能在授权、安全、进程生命周期和结果真实性约束下运行通用本地命令，但命令能够启动不代表最终用户具备可用的通用计算环境。当前命令运行时仍从受控宿主 `PATH` 解析 Python 等程序；正式 Windows 产品中虽然存在用于启动 agent-friend 固定服务的冻结运行时，它并不是可供 Agent 执行任意脚本的 Python 环境。

这会让“整理本地数据、转换文件、生成临时脚本、调用库完成一次性自动化”之类普通电脑任务依赖用户是否预装 Python、安装了哪个版本、如何配置 `PATH`，以及当前沙箱能否启动该宿主程序。真实诊断中，Agent 已经正确取得通用命令能力，却因 `python` 与 `python3` 解析到不可用的 Windows 应用执行别名而无法运行安装脚本；后续模型重复猜测解释器路径也没有改变底层能力缺口。

agent-friend 不应要求普通用户为了让 Agent 完成电脑任务而自行安装 Python、配置包管理器或维护虚拟环境。它需要像管理自身固定命令运行时一样，提供由产品负责版本、完整性、隔离和生命周期的通用脚本执行环境，让 Agent 可以按任务组织确定性脚本并通过现有命令能力运行，而不是为每种自动化目标增加专用 Tool、专用 Skill 旁路或错误码特判。

## 目标

- 让 Windows 正式产品在用户没有安装 Python、没有配置 Python `PATH`、也没有准备开发环境时，仍能完成需要 Python 脚本的通用本地任务。
- 让 Agent 可以在产品管理的临时工作区中组织、运行和迭代确定性脚本，并准确取得标准输出、错误、退出状态和生成物。
- 为任务需要的第三方 Python 依赖提供隔离、可治理的安装与复用能力，不修改系统 Python、用户 Python 或产品不可变基础运行时。
- 让解释器、标准库、依赖环境和任务工作区具有明确的产品身份、健康状态、资源边界、清理语义与诊断证据。
- 在 Agent 开始当前会话的首次推理前完成共享执行基底检查和会话环境准备，不把环境初始化成本与失败推迟到第一次命令调用。
- 跨会话共享有明确内容身份的只读解释器、工具和依赖制品，同时保持每个会话的可写环境彼此隔离。
- 继续复用需求 085 的命令授权、沙箱、文件与网络范围、进程治理和结果契约，不建立 Python 专属的平行审批或执行通道。
- 与需求 095 的运行恢复职责保持正交：本需求提供稳定执行能力和真实错误结果，不接管模型如何重试、换路线、等待用户或终止 run。

## 范围

### 包含

#### 产品管理的 Python 能力

- 正式 Windows 产品携带可供通用任务执行的固定 Python 能力；用户无需另行下载 Python、启用 Windows 应用执行别名、配置 `PATH`、安装包管理器或登录外部开发工具。
- 产品始终选择自身受治理的解释器，不因用户机器上是否存在 `python`、`python3`、`py`，或其版本、别名、注册表和用户配置不同而改变行为。
- 解释器版本、来源、许可证、平台架构、内容身份及其与 agent-friend 产品版本的关系可追溯。缺失、损坏、身份不匹配或健康检查失败时，通用 Python 能力失败关闭并返回可诊断结果，不能静默改用宿主 Python。
- 产品更新负责更新基础解释器和随产品交付的基础能力；运行期不得静默替换产品基础解释器或下载未经产品版本治理的解释器。
- 第一阶段正式安装包与干净机器验收只覆盖 Windows x64；源码运行形态在 Windows、macOS 和 Linux 上保持一致的 Agent 调用与结果语义，但不因此承诺首期交付其它平台安装包。

#### 准备时机与共享层次

- 应用运行时启动时检查并预热应用级共享执行基底；创建或恢复会话时开始准备该会话的可写环境，当前会话第一次 Agent run 进入模型采样前得到确定的 ready、degraded 或 unavailable 状态。
- 环境准备可以与用户进入会话、输入消息等非执行交互并行，但第一次命令调用不能再承担解释器下载、完整性扫描、依赖管理器启动或会话环境首次创建等未声明冷启动步骤。
- 基础解释器、受治理包管理器、产品预装能力和内容寻址的依赖制品由符合身份条件的会话共享。产品版本、解释器、平台、架构或缓存格式变化时自动使用新的共享身份，不能读取不兼容旧层。
- 每个会话的虚拟环境、安装集合、脚本和中间结果保持独立可写；一个会话安装、升级、删除或修改包不能改变其它会话的导入结果。
- 共享缓存必须并发安全、可失效、可清理且可重建。可写会话不能把任意内容直接发布成其它会话会信任的共享制品，也不能因清理共享缓存而破坏已经声明可继续使用的会话环境。
- 共享基底或缓存准备失败只影响对应执行能力，不阻止不依赖该能力的普通聊天；失败状态在 Agent run 前可查询，并由实际命令使用普通工具结果准确返回。

#### 通用脚本工作区

- Agent 可以为当前用户目标创建产品管理的任务工作区，在其中写入一个或多个 Python 脚本、模块、配置片段和中间结果，并通过现有通用命令能力运行。
- 工作区属于 agent-friend 的执行基础设施，不冒充用户选择的项目或文件夹，也不因为能够写入内部临时文件而自动获得对用户目录的读写权限。
- 脚本读取用户文件、修改用户文件或把结果交付到用户指定位置时，继续使用现有文件与命令授权边界；内部工作区不能成为复制用户数据后绕过授权的中转旁路。
- 同一任务中的脚本可以合理迭代和复用必要的中间结果，不要求把每段逻辑压进一条不可审查的命令字符串，也不因内部实现分成多个文件而额外扩大权限。
- run 取消、会话失活、应用异常退出、超时和正常完成后，工作区具有确定的保留或清理状态；不留下无限增长、无法归属或后续会话可误用的脚本与进程。

#### 隔离的第三方依赖

- 当用户目标确实需要 Python 标准库之外的能力时，Agent 可以把兼容的第三方依赖安装到产品管理的隔离环境；不得写入系统级、用户级或 agent-friend 基础 Python 环境。
- 依赖下载继续受需求 085 的网络声明和逐次授权约束；没有网络授权时不能暗中联网，没有文件写入范围时不能把依赖落到宿主任意目录。
- 可写依赖环境绑定当前会话。一个会话安装的包、入口脚本和配置不能未经治理地污染其它会话，也不能通过用户现有 `pip` 配置、环境变量或 site-packages 获得不可审计的隐式依赖。
- 产品能够报告实际解析和使用的依赖版本、来源与安装结果，并对不兼容平台、缺少可用分发物、完整性失败或需要未交付编译工具链的依赖给出准确失败；首期不承诺任意 Python 包都必然可安装。
- 产品必须通过共享、内容寻址且并发安全的缓存复用经过身份校验的下载制品，避免每个新会话重复下载同一 wheel；会话安装结果仍写入独立环境。复用不得跨越依赖身份、平台架构、产品 Python 版本、缓存格式、权限或隐私边界。

#### 公共命令与 Agent 使用方式

- 通用 Python 通过需求 085 已有的 `exec_command`/进程契约运行并产生普通工具结果；本需求不增加只服务 Python 的私有 runner、隐式宿主执行或绕过审批的新 Tool。
- builtin Skill、个人 Skill、普通聊天任务和未来其它通用工作流使用同一受管 Python 能力；是否由 Skill 发起不改变解释器身份、依赖隔离、授权和审计边界。
- Agent 可以选择短表达式、临时脚本或多个小模块来完成任务，但实际命令、工作目录、文件与网络能力仍需被现有控制面准确表达和执行。
- Python 的缺失、损坏、依赖安装失败、脚本异常、超时和取消返回稳定、真实且模型可见的执行结果，不把失败包装成成功，也不依赖 prompt 文案猜测宿主安装路径。
- 对执行结果的后续修正、重试、替代路线、用户等待和 run 终态统一由需求 095 的通用运行恢复语义负责；本需求不增加 Python 专属重试次数、停止条件或强制收尾逻辑。

#### 安全、资源与诊断

- 受管 Python 继承现有命令沙箱、逐次授权、网络控制、环境过滤、输出上限、超时、取消和进程树清理约束；提供解释器不等于获得不受限制的本机代码执行。
- 基础解释器、任务脚本、依赖环境、下载缓存和用户输出具有可区分的所有权与生命周期，不能用一个宽泛可写目录混合承载。
- 运行时不默认继承用户 Python 的 `PYTHONPATH`、启动脚本、site customization、包索引凭据、虚拟环境、代理凭据或其它无关宿主配置。
- 依赖安装和脚本执行必须服从磁盘、文件数量、输出、执行时间和进程数量等有界资源政策；达到边界时停止新增消耗并返回准确原因。
- doctor、安装完整性检查和诊断包能够说明受管 Python 是否存在、身份是否匹配、基础健康检查是否通过、最近失败属于解释器/依赖/权限/沙箱还是脚本本身，但不收集用户脚本正文、用户文件内容、凭据或完整命令输出。
- 正式 Windows 冻结产品必须通过实际安装后的 capability smoke 证明通用脚本和隔离依赖可用；源码测试、构建目录文件存在或固定服务能够启动均不能代替这项证据。

### 不包含

- 不重新实现需求 085 已有的命令执行、授权、沙箱、网络、进程会话、输出和取消协议。
- 不重新设计需求 095 所负责的 malformed 调用、重复失败、`no_progress`、空响应、流恢复、等待用户和 run 终态。
- 不调整 system prompt、persona 或 Skill 指令来要求模型猜测更多 Python 路径，也不为本次 Windows 1920 错误增加专属恢复分支。
- 不为 Skill 安装、表格处理、压缩包、文件转换或其它单一业务建立 Python 专属 Tool；这些只是通用能力的使用场景。
- 不让用户直接管理产品 Python、把它注册到系统 `PATH`、设为文件关联、当作通用终端环境，或用它替代用户自己的开发环境。
- 不承诺安装需要任意系统编译器、管理员权限、内核驱动、桌面交互或不受支持原生 ABI 的第三方包。
- 不在运行期自动安装或修改系统级解释器、编译器、Git、Node.js、PowerShell 或其它任意宿主工具链。
- 不把用户的 Python 配置、凭据、全局包、虚拟环境和缓存导入产品环境，也不向其中写入。
- 不提供后台常驻 notebook、IDE、通用终端 UI、远程代码执行服务或应用退出后继续运行的 detached Python 任务。
- 不在首期交付 macOS/Linux 正式安装包中的受管 Python payload、签名、公证和完整发布矩阵。

## 关键约束

- [085 · 受治理的通用本地命令运行时](../085-governed-local-command-runtime/requirement.md) 继续拥有命令 Tool、授权、沙箱、工作目录、文件/网络范围、进程生命周期和结果真实性；096 只补齐该运行时中可依赖的产品管理计算环境。
- 并行需求 095“Agent 运行恢复与终止语义”拥有工具失败后的继续、暂停和停止决策。096 只要求错误可稳定表达并兼容该通用机制；在 095 合入或方案变化后，096 进入实现前必须重新对账，不能复制其未合入实现。
- [078 · 受治理的本地文件系统工具](../078-governed-local-filesystem-tools/) 继续拥有用户文件的读取、写入和变更语义；内部脚本工作区不能扩大用户文件权限。
- [082 · 工具执行治理](../082-tool-execution-governance/requirement.md) 继续拥有工具编排和结果保留的一般原则；组织 Python 脚本不应制造模型级忙轮询或无意义的逐行工具调用。
- 受管 Python 是通用执行基底，不是隐藏的业务自动化框架。新增能力应优先通过普通脚本、现有 Tool 和真实依赖表达，不为未知未来需求预建插件系统。
- 任何真实第三方下载都继续受现有网络授权、供应链和隐私边界约束；自动化验证应优先使用确定性本地 fixture，公开网络 smoke 只补充验证真实链路。

## 验收条件

- [ ] **AC-1 干净 Windows 开箱可用**：在 Windows x64 正式安装后的隔离测试机上移除用户 Python、禁用相关 `PATH`/应用执行别名依赖后，Agent 仍能通过公共命令能力创建并运行 Python 脚本，取得真实输出和退出状态；不读取或安装用户级 Python。应用启动完成后共享基底健康可查，新会话第一次模型采样前已形成会话环境状态，第一次 `exec_command` 不再执行基础环境冷启动。
- [ ] **AC-2 通用电脑任务**：确定性端到端场景证明 Agent 能在受管工作区中组织多个脚本或模块，读取已授权的 JSON/CSV 文件、完成转换与汇总、生成归档，并把结果写到已授权位置；验收不依赖为这些场景新增专用 Tool 或 Skill 私有 runner。
- [ ] **AC-3 宿主环境隔离**：有无用户 `python`/`python3`/`py`、不同宿主 Python 版本、恶意或损坏的 `PYTHONPATH`/site customization、用户虚拟环境及全局包都不会改变产品实际选择的解释器和基础导入结果。
- [ ] **AC-4 工作区与用户文件边界**：Agent 可以在产品工作区写脚本和中间文件，但未授权用户路径仍不可读写；只读授权不能因脚本运行升级为写入，链接、相对路径、归档路径和中间复制不能绕过现有文件边界。
- [ ] **AC-5 隔离依赖安装**：使用确定性受控包 fixture 证明兼容依赖可安装、导入和执行，实际版本与来源可查询；环境不写系统/用户 site-packages 或产品基础运行时。另有受批准网络的公开源 smoke 证明真实下载链路可用，失败不会退回用户 `pip`。
- [ ] **AC-6 依赖失败与共享复用**：无兼容分发物、完整性不匹配、网络未授权、源不可达、磁盘超限及需要未交付编译工具链时返回可区分失败；两个独立会话安装相同 wheel 时第二次命中共享内容缓存而不重复下载，但各自环境仍可独立升级、删除和修改。不同 Python 版本、平台、依赖身份、缓存格式或权限上下文不会错误复用。
- [ ] **AC-7 现有命令治理复用**：Python 执行继续经过需求 085 的同一 `exec_command` 授权、沙箱、网络、输出、超时、取消和进程树清理链路；代码与产品界面中不存在 Python 专属平行审批或隐式 `host_user` 旁路。
- [ ] **AC-8 会话生命周期**：正常完成、脚本失败、依赖安装失败、超时、用户取消、run 取消、会话失活、恢复和应用异常退出都有自动化覆盖；无残留子进程，run 临时目录及时清理，会话环境跨 turn 保留并在会话删除或受治理 GC 时释放，重复任务、staging 和缓存不会导致无界增长。
- [ ] **AC-9 完整性失败关闭**：基础解释器或标准库缺失、篡改、版本/架构/产品身份不匹配时，在运行用户脚本前失败关闭并给出稳定能力状态；不得静默解析宿主 Python，也不得把固定服务启动成功当作通用 Python 健康。
- [ ] **AC-10 诊断与隐私**：doctor、安装清单和诊断包可核对受管 Python 的版本、内容身份、健康、工作区/依赖环境状态及失败类别；自动化检查证明其中不包含用户脚本正文、用户文件正文、包索引凭据、环境凭据或无界命令输出。
- [ ] **AC-11 与 095 的边界**：096 产生的成功与失败均使用普通命令结果进入 Agent 循环，没有 Python 专属失败次数、强制收尾或 prompt 特判；在 095 当前契约下，确定性集成测试证明结果可以被通用恢复机制消费，且取消、安全和显式预算仍能终止执行。
- [ ] **AC-12 Skill 与非 Skill 一致**：同一受管 Python 能力可由普通聊天任务、builtin Skill 和个人 Skill 使用；解释器身份、依赖隔离、授权、工作区和结果语义不因来源不同而变化，Skill 内容身份保护继续成立。
- [ ] **AC-13 冻结产品验证**：Windows frozen candidate 和实际安装后分别完成解释器健康、标准库脚本、多文件脚本、隔离依赖、用户文件边界、取消清理、完整性篡改和宿主 Python 干扰 smoke；所有报告绑定精确产品 build 与 payload 身份。
- [ ] **AC-14 跨平台与回归**：源码环境在 Windows、macOS、Linux 使用一致工具和结果契约；首期未交付的正式安装平台被准确标注。需求 078、082、085、095 相关回归及项目 lint、typecheck、单元/集成测试和 `scripts/check` 全量门禁通过。
- [ ] **AC-15 提前准备与能力降级**：应用启动、会话创建、会话恢复和首轮并发场景证明共享基底只准备一次、会话环境按身份幂等准备，首个 Agent run 不与首次命令争抢初始化；准备失败时普通聊天仍可继续，命令能力返回稳定 unavailable/degraded 事实，恢复后新 run 使用新的环境快照。

## 开放问题

- Windows 正式产品采用独立可调用解释器、可重定位 Python 分发物，还是与现有冻结服务运行时共享部分制品，需要在技术方案阶段结合隔离、完整性、体积和更新边界确定；现有 `agent-friend-runtime.exe` 不能被直接当作任意脚本解释器。
- 依赖安装入口、锁定与来源策略、允许的 wheel/原生扩展范围和离线行为需要在技术方案中明确；首期不应隐式引入完整本地编译工具链。
- 共享依赖缓存如何确保只有受治理的包管理器能够写入、会话安装文件不会反向污染缓存，以及清理缓存不会破坏会话，需要在技术方案中确定。
- 产品内部脚本写入与现有文件 Tool/命令审批如何组合，才能既避免为每个临时文件重复打扰用户，又不把内部工作区变成用户文件权限旁路，需要对照 078/085 的现有契约设计。
- 诊断包新增哪些受管环境字段，以及如何升级 producer contract、fixture 和检查 Skill，需要在实现前按诊断包治理规则确定。
- 095 当前处于并行需求阶段；096 设计和实现开始前必须以其最新已确认文档与代码为准重新核对共享运行时边界。
