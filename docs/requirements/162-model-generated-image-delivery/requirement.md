# 162 · 模型生成图片的接收与交付

## 状态

CONFIRMED

确认日期：2026-10-15。用户确认 162 编号及本需求范围，随后确认技术方案并授权开始实现。

## 背景

2026-10-11 的一次 QQ 私聊回合中，上游返回图片生成的开始、生成中和完成事件，
应用接入层将其作为未支持能力跳过，同时跳过非文字输出项。最终会话只保存和展示了文字，
其中却提到已经生成的图片。用户在桌面端查看同一会话时看不到图片。

已有运行证据证明上游报告了生成完成、应用跳过了相关输出；未保留可检验的原始图片，
因此不能把上游完成事件等同于图片内容已完整、有效或已送达。

150 明确未包含图像生成能力；151 已建立统一会话附件和按需读取能力。
本需求补齐模型图片输出的接收与交付，不以修改回答文案代替实际交付。

## 目标

- 当前连接返回受支持的原生图片结果时，用户能够在原会话看到图片，并定位应用保存的原件。
- 图片与对应文字保持关联和顺序，支持纯图片、单图、多图和图文混合回复。
- QQ 私聊能够交付图片，并区分生成、保存和投递结果。
- 无法完整交付时明确说明失败或能力边界，不静默丢图，也不误报完整成功。

## 范围

### 包含

- 首期接收当前 Responses 连接已经返回的原生图片结果及必要的生成状态。
- 图片原件校验、会话归属、持久保存、桌面展示与通过右键菜单定位原件所在文件夹。
- 重新打开会话或重启后恢复图文结果；图片缺失或损坏时保留消息关系并明确反馈。
- QQ 私聊的图片投递、图文衔接、部分失败与发送结果未知的反馈。
- 相关会话历史、后续模型上下文、附件发现和读取、实时事件及历史展示的一致性。
- 重复终态、异常数据、生成失败、中断、取消、保存失败和渠道限制的有界处理。
- 确定性协议回放、持久化与恢复、展示和投递回归，以及必要的脱敏诊断。

### 不包含

- 独立生图服务、额外生图凭据或模型选择配置、专用图片编辑器和生成参数面板。
- 主动为所有连接启用上游生图工具、自动切换模型或新增 Images API 路由。
- 承诺支持所有 provider 的私有图片协议，或顺带支持音视频输出。
- 恢复此前已经丢弃且未保存的图片、历史失败批量补发、通用媒体发件箱。
- 默认执行真实 LLM 调用、真实 QQ 对外投递、桌面视觉验收或构建安装包。

## 需求行为

- **R-1 接收与关联**：完成的有效图片作为本轮助手输出保留，与文字保持可理解的顺序和归属。
  仅有进度或完成信号而没有有效图片，不算图片交付成功；纯图片不能被判为空回复。
- **R-2 持久与访问**：图片由应用托管，与原会话关联；正常重启、历史加载和上下文整理
  不导致图片丢失或要求重新生成。沿用既有会话文件的隔离和访问约束。
- **R-3 桌面交付**：在原回复中看到图片，左键查看大图，右键打开原件所在文件夹；不额外显示文件名或保存按钮。加载失败和原件失效有明确状态。
  多图不得串线、重复或挤占正常文字阅读。
- **R-4 QQ 交付**：QQ 私聊发送图片及相关文字；生成完成、原件保存和平台接受分别有依据。
  平台接受不等同于客户端已显示；失败或结果未知不能记为完整送达。
- **R-5 部分成功与恢复**：生成、保存、展示或投递发生失败时，保留已取得的有效内容，
  明确指出未完成部分。取消后不继续发送新的正常内容；为恢复投递不得自动重跑生图。
- **R-6 后续对话**：后续能够发现和按需读取已保存图片，保持助手生成这一来源；
  不将图片误标为用户上传，也不因历史重放自动重复生成或发送。
- **R-7 诊断与兼容**：诊断能够区分上游没有有效图片、接收失败、保存失败和投递失败，
  不把图片正文或完整 Base64 写入普通日志。现有文本、函数调用和用户附件链路不回归。

## 验收条件

- [x] **AC-1**：受控 Responses 响应中的纯图片、单图、多图和图文混合输出能完成接收，
  图片与文字关联及顺序正确；重复完成事件不导致重复图片。
- [x] **AC-2**：图片原件可持久保存，在桌面原会话中左键查看大图、右键定位原件；不显示额外文件名或保存按钮。重开会话和重启后仍可访问；2026-10-16 用户决定将真实桌面重启验收延后到实际使用，不将未执行记为通过。
- [x] **AC-3**：后续对话可发现并按需读取已生成图片；压缩与历史恢复保留其来源和访问关系，
  不自动重发图片正文给模型、不重新生成、不重复投递。
- [x] **AC-4**：QQ 私聊图文和纯图片回复能够投递，内容顺序可理解；图片或文字部分失败时，
  记录和提示与实际结果一致，原会话保留已保存图片。
- [x] **AC-5**：仅有生成完成信号、无图片、图片损坏、超出接收限制、磁盘失败和原件缺失
  均有明确结果，不静默丢失、不以文字成功掩盖图片失败。
- [x] **AC-6**：覆盖流中断、取消、重复事件、明确投递拒绝及发送结果未知；恢复有界，
  不为补发重新生图，不把未完成或未知记录为完整成功。
- [x] **AC-7**：脱敏诊断可关联生成、保存与投递阶段；现有文本、工具、用户附件及非 QQ
  入口的兼容性经受影响回归和项目 scripts/check 验证。
- [x] **AC-8**：真实模型、真实 QQ 与桌面视觉验证按授权分别记录；未执行不记为通过，
  用户确认验收完成后才收口。
