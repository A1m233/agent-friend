# 162 · 模型生成图片的接收与交付 — 技术方案

## 状态

CONFIRMED

2026-10-15 用户确认方案并授权实现。需求见 [requirement.md](./requirement.md)，
现状依据见 [evidence-index.md](./evidence-index.md)。

## 现状分析

Responses 解析器跳过 image_generation_call；内部流事件和助手历史主要围绕文字。
附件存储已支持内容寻址和租约，ImageReadingService 已有受限 PNG/JPEG/WebP 校验。
SessionFileService 仅发现用户附件，桌面助手块没有图片，QQ OutboundContent 仅包含文本。

## 方案设计

### 接收与状态

- 增加 provider-neutral 图片开始、完成事件，携带 item identity/output index；完成结果包含
  有界图片字节或稳定失败码，原始字节不进入 repr、普通日志、会话 JSONL 或模型历史。
- image_generation_call.result 是最终图片输入。开始/生成中只更新活动，partial_image 不作为
  最终交付；仅完成信号不足以成功。重复完成以身份、内容摘要和状态校验，不重复交付。
- 图片为独立有序助手项，不塞进正文 Markdown 或工具调用。文字保持现有流式路径。
- 完整图片项可保存；整轮未完整结束仍标中断，已保存图片不删除。纯图是有效输出，
  不触发空文本重试，不伪造模型提供的 final_answer phase。
- 复用现有静态图片校验边界：PNG/JPEG/WebP、8 MiB、1600 万像素、最长边 8192；
  单次模型响应最多接收 4 张有效图片，超限明确失败，不悄悄缩放原件。

### 保存、事件与模型历史

- Agent 层校验并通过 AttachmentStore 导入图片，发布前建立持久事件引用，遵守现有租约/GC 保护。
  会话保存助手图片项、来源、顺序、附件引用或失败状态，先持久化再推送。
- 实时 AG-UI、后台 push 与历史恢复使用同一图片消息语义；前端按 item 顺序投影。
- 图片生成失败、校验失败、存储失败分别记录可理解的状态，不删除已取得的文字或其它图片。
- SessionFileService 扩展到助手图片，来源明确为 assistant_generated；复用发现、准备和看图工具。
- 同轮续接及跨轮历史投影只带文件引用和结果事实，不自动重投图片正文；压缩、rollout 恢复、
  usage anchor 和来源字段一起核对。图片失败反馈由宿主提供，不靠篡改模型正文掩盖失败。

### 桌面交付

- 新增有序图片块，保留预览和加载失败提示；生成图片不显示额外文件名和保存按钮，左键复用已有 AttachmentImageViewer。
- 图片缩略图接入现有 LinkInteractionBoundary，复用“打开所在文件夹”和“复制完整路径”菜单；键盘菜单、关闭、失效反馈沿用公共边界，不另建图片菜单。
- 文件定位接口同时识别当前会话的用户附件和生成图片引用；仍校验会话归属、原件可用性。复用既有 reveal_link_target，不新增图片保存命令或用户数据路径拼接。
- 图片出现、加载完成与失败须纳入现有虚拟列表尺寸和滚动更新；纯图也有正确的回复终态与动作栏。

### QQ 交付

- 复用 qqbot-agent-sdk 1.2.2 的媒体上传和富媒体消息发送，不建立公网图片托管。
- 图片前的文字仍按既有流式机制交付；首个图片边界后暂缓后续文字，按内容顺序逐段发送。
  回复收集携带图片项及其顺序，不再以空字符串判断整轮没有输出。
- 图片发送只接受宿主已校验、归属当前会话的附件；平台需要的本地路径由宿主解析，
  不从模型文案提取路径。图片上传结果不等同于消息发送成功。
- 每段保留 delivered/failed/unknown 回执，全部成功才认为完整投递；平台接受不等于客户端已显示。
  明确不可恢复拒绝不重复发送；结果未知不盲目重发。取消后停止新投递；恢复不重跑生图。
- 非图片通道明确给出能力限制和桌面查看提示。已有纯文本恢复及菜单行为保持兼容。

### 涉及模块

| 模块 | 改动 |
|---|---|
| llm_providers/responses、stream_events | 图片输出装配、身份与重复校验、纯图有效性 |
| agent 图片输出、conversation、assistant_phase | 保存、持久事件、有序输出、失败与取消 |
| agent sessions、session_files、attachments/input_projection | 来源、文件发现、同轮/跨轮历史、恢复 |
| agent_bridge 事件编码、附件访问与 IM | 实时/历史一致、图片访问、QQ 交付与回执 |
| frontend 聊天类型、reducer、projection、消息组件与共享链接菜单；Bridge 文件定位接口 | 图片块、预览、右键定位原件、失效状态 |
| 相关 tests 和 frozen capability smoke | 协议回放、存储与恢复、投递、纯图、失败及打包能力 |

## 影响分析与验证

- 对真实 transport/provider 边界回放合法合成图片；覆盖纯图、多图、图文交错、重复与冲突、
  完成快照、无有效 result、损坏、超限、流中断和取消。
- 以隔离数据目录覆盖持久引用与 GC、重启/压缩恢复、助手来源、模型请求无自动图片正文。
- 受控 QQ 响应覆盖上传失败、发送拒绝、未知结果、部分成功、顺序和取消；不访问真实账号。
- 前端验证实时、push、历史投影一致及图片失败/共享右键菜单交互；完成项目 scripts/check 门禁。
- 复用 Pillow 与 SDK，但新增可分发能力，须评估并覆盖 frozen doctor 的图片处理高风险路径；
  按 frozen-runtime-packaging 执行必要的 runtime-only 验证，不自动构建安装器。
- 真实 LLM、真实 QQ 和桌面视觉验收按已有授权门禁单独执行并记录缺口；未执行不能写通过。
