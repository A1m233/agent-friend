# 首方 Guide / Skill 独立自动更新

## 状态

CONFIRMED

## 背景

`agent-friend-guide` 当前既在独立公开仓库中维护，也会作为 builtin Skill 的固定快照随
agent-friend 桌面安装包交付。该模式保证了离线可用和内容可追溯，但最终用户要取得任何知识、
指令或配套资源更新，仍必须等待新的桌面版本和安装包。

项目已有 `maintain-agent-friend-guide` 负责在常规产品变更合入时检查、发布和同步 Guide，也已有
GitHub Skill 的来源记录、内容摘要、staging、失败回退、catalog watcher 与用户轮 snapshot 等
基础能力。本需求需要在这些既有边界上增加首方 Skill 自动更新，而不是把知识维护、桌面发版和
运行时 Skill 更新继续绑在同一条发布链路中。

首方 Guide / Skill 也可能直接在其受信仓库中独立发布，而不经过某次 agent-friend 产品变更合入。
这种发布与经 `maintain-agent-friend-guide` 完成的发布具有同等的首方信任身份；运行时安全不能以
“是否由维护 Skill 发起”作为判断依据，而应验证发布来源、内容完整性和兼容性。

## 目标

- 让 `agent-friend-guide` 的完整 Skill 包能够独立于桌面版本发布，并由已安装客户端自动取得更新。
- 允许首方 Skill 包中的任意正常组成部分独立更新，包括 `SKILL.md`、references、scripts、assets、
  展示元数据和其它包内资源，不按内容类型设置额外白名单。
- 保留随桌面安装包交付的离线基线，并在本地保留最近一次有效内容，使首次启动、断网和更新服务
  不可用时仍可使用 Guide。
- 只激活来源、完整性、格式和宿主兼容性均已验证的首方版本；未经验证或被篡改的远程内容不得
  成为模型指令或 Skill 资源。
- 让更新在用户轮之间一致切换：正在执行的轮次继续使用其冻结版本，后续轮才使用新版本，既有
  会话历史不被改写。
- 在下载、校验、切换或新版本加载失败时继续使用上一份有效版本，并支持首方发布方安全撤回或
  回退到先前有效内容，而不要求重新发布桌面安装包。
- 首期只完成固定首方 `agent-friend-guide` 的最小自动更新闭环，同时让包与版本契约能够在未来
  复用于少量其它首方 Skill，不建设通用 marketplace。

## 范围

### 包含

#### 完整首方 Skill 包独立发布

- `agent-friend-guide` 继续以独立公开仓库为人工维护来源，可以在没有 agent-friend 产品代码变更
  和桌面发版的情况下发布新版本。
- 自动更新以完整 Skill package 为单位，不把 `SKILL.md`、references、scripts、assets 或其它
  合法资源拆成不同信任等级，也不要求内容更新必须限制为纯文本。
- 每个可分发版本都具有稳定、不可混淆的版本身份和完整内容身份；已经发布的具体版本不能被
  静默改写成另一份内容。
- 首方发布既可以来自常规 `maintain-agent-friend-guide` 工作流，也可以由受信仓库独立完成。
  两条路径生成的合规发布对客户端具有相同语义。

#### 自动检查与更新

- 客户端对固定首方更新源进行低频自动检查，不要求用户逐次运行 Skill 安装或更新命令。
- 自动检查、下载和验证不得阻塞正常对话启动；没有新版本或网络不可用时继续使用当前有效内容。
- 相同版本的重复检查保持幂等，不重写包内容、不制造无意义的 catalog 变化。
- 更新状态至少能够在诊断或日志中区分：未检查、无更新、已更新、来源或完整性校验失败、无兼容
  版本、下载失败、切换失败和使用回退版本。

#### 首方信任与供应链验证

- 首期更新源和 Skill 身份由产品固定，不允许远程索引把任意第三方仓库或另一个 Skill 包提升为
  受信首方内容。
- 客户端在激活候选版本前验证发布者身份或等价的首方授权证明、完整包内容身份、版本元数据、
  包结构和宿主兼容性。
- 校验所依赖的信任锚不能只来自与候选包相同、可被一并篡改的远程内容；具体签名、证明或可信
  发布机制在技术方案中确定。
- 下载和校验 Skill 包不会自动执行其中的 scripts、hooks 或其它可执行资源；更新后这些资源仍只
  能通过 agent-friend 已有的 Skill 激活、命令运行时、权限和审批机制使用。
- Skill 更新不能改变 Agent 的宿主权限、绕过现有工具治理，或因其首方身份获得隐式执行特权。

#### 版本兼容、离线与回退

- 发布信息能够表达 Skill 包版本与 agent-friend 产品版本或更新协议之间的兼容边界。
- 客户端只选择与当前运行版本兼容的候选；远端存在更新但没有兼容版本时继续使用当前有效内容，
  不把“不兼容”误报为更新成功。
- 桌面安装包继续携带与该桌面版本匹配的 builtin Guide 作为最终离线基线。一次更新机制版本随
  桌面版交付后，后续纯 Skill 内容更新不再要求重新打包。
- 已验证的本地更新版本在断网后继续可用；缓存损坏、状态损坏或更新失败时至少能够回到仍与当前
  宿主兼容的最近有效版本或随包基线。
- 首方发布方能够通过后续受信发布撤回问题版本或重新指向先前有效内容；客户端不得把网络重放的
  旧发布状态误当成新的合法回退。

#### 用户轮与会话一致性

- 更新候选只有在完整验证和安全切换成功后才进入有效 Skill catalog。
- 已经开始的用户轮继续使用轮次开始时冻结的 catalog、Skill 正文和包内资源，不因后台更新切换
  到另一版本。
- 更新完成后，现有会话无需重启应用、Bridge 或新建会话；catalog 刷新后的后续用户轮使用新版本。
- 旧 Skill 正文已经进入会话历史时保持原样；再次激活才读取当前有效版本。
- 旧版本资源不能在仍被当前轮或并行运行实例引用时被提前删除。

#### 与现有维护流程和能力的关系

- `maintain-agent-friend-guide` 继续负责常规产品变更合入时的知识检查和首方发布闭环，但不成为
  运行时判断发布是否可信的唯一入口。
- 现有 builtin installer、Skill catalog、watcher、轮次 snapshot、GitHub Skill 更新中的 digest、
  staging 和失败回退能力应作为可复用基础进行评估；是否直接复用由技术方案根据职责边界决定。
- 技术方案需要比较独立知识包、受管首方 Skill 和轻量 marketplace 三种形态，并说明采用、改良或
  放弃的原因；最终选择以简单、可靠和最小改动为优先。

### 不包含

- 第三方 Skill marketplace、公开目录、搜索、推荐、评分、投稿或审核平台。
- 任意用户仓库、个人 Skill、共享 Skill 或现有 GitHub Skill 的后台批量自动更新。
- 把远程索引中的新来源、新公钥或新 Skill 身份未经桌面信任锚授权直接提升为首方内容。
- 自动执行新版本携带的脚本，或为脚本增加现有命令运行时之外的权限、审批或执行旁路。
- Skill 编辑、版本浏览、手工选版、冲突合并或 marketplace 管理的专用桌面 UI。
- 重构与首方 Skill 更新无关的 Agent catalog、工具系统、会话存储、桌面更新器或安装包能力。
- 修改本需求之外的 `agent-friend-guide` 知识正文；支付宝相关 Guide 补充由其它会话负责，不进入
  本需求分支。
- 要求所有首方 Skill 立即接入自动更新；首期交付对象仅为 `agent-friend-guide`。

## 关键信息

- 现有 Skill catalog、builtin 物化、watcher 和用户轮 snapshot 见
  [需求 076](../076-agent-skill-system/requirement.md)。
- `agent-friend-guide` 的公开源、builtin 快照和维护工作流见
  [需求 079](../079-agent-friend-guide-skill/requirement.md)。
- GitHub Skill 的来源记录、完整包 digest、staging、原位替换和失败回退见
  [需求 088](../088-github-skill-update-lifecycle/requirement.md)；该需求明确不包含 builtin 或自动更新，
  本需求不得把用户管理状态与首方发布状态混为一体。
- “可信首方发布”由固定产品信任边界和可验证发布证明决定，不由内容是否为文本、是否包含脚本，
  或是否经 `maintain-agent-friend-guide` 发起决定。
- “自动更新”只负责取得、验证、缓存和切换 Skill package；Skill 激活和包内资源的实际使用继续
  服从现有 runtime capability、权限与审批契约。

## 验收条件

- [ ] **AC-1 独立发布生效**：在不修改 agent-friend 产品仓库、不提升桌面版本且不重新构建安装包
  的情况下，发布一个新的合规 `agent-friend-guide` 版本；已安装客户端自动取得并在后续用户轮
  使用该版本。
- [ ] **AC-2 完整包更新**：候选版本同时修改 `SKILL.md`、reference、script 和其它合法包内资源时，
  客户端对完整 package 进行验证和切换，不因资源类型拒绝合规首方更新；更新过程不自动执行脚本。
- [ ] **AC-3 两种发布路径等价**：经 `maintain-agent-friend-guide` 发布和在受信首方仓库中独立发布
  的两个合规版本都能进入同一自动更新流程，不要求客户端识别发布由哪个维护工作流发起。
- [ ] **AC-4 供应链拒绝**：来源身份不符、授权证明无效、内容摘要不匹配、包结构无效或下载内容被
  篡改时，候选不会进入有效 catalog，也不会成为模型指令；当前有效版本保持可用并留下诊断。
- [ ] **AC-5 兼容版本选择**：更新源同时存在兼容和不兼容版本时，客户端只选择当前宿主允许的
  合规版本；没有兼容候选时继续使用当前有效版本并如实记录原因。
- [ ] **AC-6 离线与首次启动**：新安装客户端在完全离线环境中可以使用随包 Guide；成功更新后再次
  离线启动时可以使用本地最近有效版本，不依赖重新下载。
- [ ] **AC-7 失败保护与回退**：下载、校验、缓存、状态提交、catalog 加载或切换失败时，上一份
  有效版本仍可发现和激活；首方发布方通过新的受信发布撤回问题版本后，客户端可安全回到指定的
  先前有效内容，且拒绝把重放的旧发布状态当成新回退。
- [ ] **AC-8 轮次一致性**：后台更新发生在用户轮执行期间时，该轮正文和包内资源保持旧版本；更新
  成功且 catalog 刷新后的下一用户轮使用新版本，历史中的旧正文不被改写。
- [ ] **AC-9 幂等与可诊断**：对相同发布状态重复检查不会重写内容或产生无意义 catalog 版本；更新
  版本、来源、最近检查结果、当前有效版本和回退原因可通过日志或诊断证据复核。
- [ ] **AC-10 范围隔离**：第三方 marketplace、个人或共享 Skill 自动更新、自动脚本执行、专用管理
  UI 和无关 Agent 重构不会因本需求获得隐式实现。
- [ ] **AC-11 项目门禁**：更新协议、信任验证、版本选择、缓存切换、失败恢复、catalog 刷新和轮次
  snapshot 具备与风险相称的确定性自动化测试，项目规定的完整检查通过；无需真实 LLM 调用即可
  完成机制验收。
