# 173 · 将 Codex 的 imagegen 工具适配到 AF

## 状态

CONFIRMED。2026-11-07 确认范围。

## 背景

需求 162 让 AF 能接收、保存和展示模型返回的图片。用户现在希望模型在普通对话中主动生成图片，下一轮还能编辑刚生成的图片或用户上传的参考图。已有实测中，使用 CPA v8.0.59 的 GPT-6.1 Sol 对话能识别参考图，但上游没有为聊天请求提供生图工具，回复中只有文字。

## 目标

在支持工具调用的 AF 会话中，提供与 Codex imagegen 相符的静态图片生成和编辑体验。用户继续用自己选择的聊天模型，以自然语言描述意图，结果回到原会话。图片请求跟随当前连接，支持多种上游，不要求用户持有 OpenAI 账号。

## 范围

- **调用和输入。** 用户可从描述生成一张新图，也可指定有权读取的图片文件，或使用当前对话中的上传图片、先前生成的图片做编辑。对齐 Codex 的两种参考方式：指定目标，或取最近若干张图，单次最多五张；两种方式不混用。找不到所指图片或无法确定对象时，说明缺口或请用户补图。支持透明背景请求；保留与修改目标无关的画面内容。
- **连接和模型。** 聊天模型负责理解意图并调用工具，图片服务使用当前连接的地址和凭据。服务提供默认图片模型时，无需额外选择；必须指定时，允许用户在该连接上填写图片模型 ID。切换聊天连接后按新的连接重新判断。提示词和参考图只发往用户选择的上游。
- **能力边界。** 分别处理可生成、可编辑、只读图以及能力尚未知的情况。既有聊天或读图成功不能作为图片服务可用的证据，也不能凭模型名称断言支持。只支持生成的连接仍可生图；编辑不可用时给出对应反馈。
- **结果和历史。** 在原会话呈现执行状态、有效图片或失败原因；原图与编辑结果作为不同的会话资产保留，支持重新打开后继续引用。已有原生图片交付行为继续可用；一次用户操作应避免重复生成、重复展示或重复消耗。
- **本期边界。** 聚焦 Codex 的基础静态生图和编辑工具及其在 AF 中的适配。动画 GIF、跨连接选择另一图片服务、图片参数控制面板和专用画布编辑器均不属于本期。新版 CPA 是一个验收连接，不限定产品只能接 CPA。

## 验收条件

- [ ] **AC-1 对话生图。** 对支持生成且有默认值的连接，用户无需再配置图片模型；在 AF 中请求“画一张白底红圆”，本轮出现一张可打开的真实图片。
- [ ] **AC-2 连续改图。** 下一轮要求“把刚才的红圆改成橙色”时，实际使用上一轮交付的图片，结果符合改色要求；两张图均可访问，重开会话后可再次引用，恢复历史不重跑生成。
- [ ] **AC-3 参考输入。** 上传图、可访问的指定文件和多张会话参考图均有对应验证。错误引用、越权、超过五张和混用两种方式时有清楚结果，不静默换图；覆盖静态透明背景。
- [ ] **AC-4 多上游。** 覆盖有服务默认值、要求图片模型 ID、只支持生成、能力未知及不支持图片的连接。验证使用当前连接及其模型设置；切换连接不会沿用另一连接的图片模型或凭据。
- [ ] **AC-5 交付和异常。** 覆盖有效结果、响应不含图片、上游拒绝、取消、保存失败、重复事件及已有原生图片结果。仅有文字或 HTTP 成功状态不算出图成功。
- [ ] **AC-6 真实验证。** 以独立 CPA v8.0.59 验证默认模型的实际生成和编辑，再通过 AF 正常聊天入口走两轮。记录独立接口结果和 AF 端到端结果；每个场景均以 AF 最终可读取的图片或准确的失败反馈为依据。现用 CPA 服务保持独立。

## 外部依赖验证

2026-11-07，在独立 CPA v8.0.59 实例上使用当前账号，两次请求均省略图片模型 ID。生成接口返回 1254×1254 的白底红圆 PNG，编辑接口以这张输出为输入，返回同尺寸的橙圆 PNG。两次 HTTP 200，图片均可完整解码。此记录只覆盖该连接的默认模型路径，AC-6 的 AF 两轮聊天验收仍待实现后执行。
