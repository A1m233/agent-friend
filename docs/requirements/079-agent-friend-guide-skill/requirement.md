# agent-friend 专有知识 Skill 与维护工作流

## 状态

CONFIRMED

## 背景

agent-friend 已经具备桌面聊天、长期记忆、人格、桌宠、工具调用、语音和多种第三方服务配置等产品能力，但相关知识分散在代码、需求文档、设置界面和开发者说明中。陌生用户或协助用户的 Coding Agent 很难快速判断产品能做什么、应该如何使用、某项能力需要哪些配置，以及遇到问题时应如何排查。

项目需要一个公开、可复用的专有知识 Skill，让兼容 Agent Skills 的 Coding Agent 和 agent-friend 自身都能按需获取同一套产品知识。该知识还会随着产品能力、配置字段和用户流程变化而演进，因此不能只交付一次性文档；项目还需要一套面向维护者的 Skill 工作流，在合适的交付节点提醒用户是否检查知识更新，并在获得授权后闭环完成跨仓库维护。

[新用户可用性与公开引导 exploration](../../explorations/user-readiness-and-public-guidance/README.md) 已记录首启引导、API Key、配置验证、数据隐私和公开 Skill 等前期问题。本需求将其中与公开知识 Skill 及其持续维护直接相关的部分转化为正式交付范围；产品内首启 UI、设置帮助入口和完整文档站仍留给后续需求。

## 目标

- 建立公开的 `agent-friend-guide` Skill，为最终用户及协助他们的 Coding Agent 提供准确、易理解、按需加载的 agent-friend 产品知识。
- 让 agent-friend 随产品交付同一知识 Skill 的内置版本，用户无需额外安装即可在 agent-friend 中使用。
- 让公开知识拥有唯一、明确的维护来源，并让 agent-friend 内置版本能够追溯到对应的公开版本。
- 建立项目内显式维护 Skill `maintain-agent-friend-guide`，支持判断产品变更是否需要更新知识、执行已授权的跨仓库更新以及处理部分完成后的续跑。
- 在所有安装包构建前，以及用户要求把变更合入 `main` 并推送远端前，提醒用户是否进行知识维护检查；提醒本身不自动执行检查，也不阻止用户继续原操作。
- 避免内部重构、测试整理或其它没有用户可见影响的改动产生无意义的知识更新。

## 目标用户与使用场景

### agent-friend 最终用户

- 了解 agent-friend 当前具备哪些能力、如何开始使用及有哪些限制。
- 了解某项能力依赖哪些第三方服务，未配置时会产生什么影响。
- 查询 API Key、App ID、Access Token、Host 等设置字段的用途、申请入口和配置方式。
- 查询设置保存后的生效方式、常见错误、数据存储和隐私边界。

### 协助用户的 Coding Agent

- 在用户安装、配置、使用或排查 agent-friend 时，按需读取权威产品知识并给出可行动的指导。
- 区分当前已支持能力、实验性能力、可选增强能力和尚未交付能力，不把项目愿景误述为当前产品事实。

### agent-friend 项目维护者

- 在产品功能、配置、数据行为或用户流程变化后，判断公开知识是否需要同步更新。
- 在用户授权后完成公开知识更新、验证、提交推送以及 agent-friend 内置版本同步。
- 在跨仓库流程只完成一部分时，根据已完成状态继续执行，而不是重复发布或自动回滚已有公开提交。

## 范围

### 包含

#### 公开产品知识 Skill

- 在独立的公开开源仓库中维护符合 Agent Skills 目录规范的 `agent-friend-guide` Skill。
- Skill 面向最终用户及协助用户的 Coding Agent，不以项目维护者内部架构文档为主要内容。
- Skill 采用渐进式披露：入口只保留用途、回答边界和知识导航，详细内容按主题拆分并仅在相关问题出现时加载。
- Skill 能够被兼容的 Coding Agent 从公开仓库安装或引用。
- 公开仓库为知识内容的唯一人工维护来源；agent-friend 内置内容不得形成另一套需要独立手写维护的事实源。
- 每个可交付知识版本都能说明其适用的 agent-friend 产品范围或版本边界，并能追溯到公开来源。

#### 产品功能与使用知识

- 说明 agent-friend 的产品定位、当前用户可见功能、基本使用方式和当前限制。
- 覆盖首次使用时的建议配置顺序，并区分基础能力所需配置与可选增强能力所需配置。
- 说明对话、记忆、人格、桌宠、搜索、地点、天气、语音等能力的用户视角用途，以及缺少可选配置时的降级行为。
- 对仍处于实验、待验证或尚未交付状态的能力进行明确标注，不把路线图或历史需求描述当作当前可用事实。

#### API Key 与运行配置知识

- 完整覆盖 DeepSeek、Kimi、Tavily、高德地图和和风天气当前所需凭据的用途、官方申请入口、产品内配置位置、是否必需、影响能力和保存后的生效方式。
- 火山引擎首期覆盖：
  - agent-friend 当前展示的火山相关字段及其用途；
  - 语音输入与语音通话分别依赖哪些凭据组合；
  - 缺少不同字段时受影响的能力；
  - 可用于定位对应控制台页面的官方入口与检索关键词；
  - 在 agent-friend 中的配置位置和生效方式。
- API Key 指引不得要求、收集或展示用户的真实凭据，也不以执行真实第三方 API 调用作为本需求的默认验收方式。

#### 配置验证、排障、数据与隐私知识

- 解释配置保存后是否立即生效、是否需要重启相关能力，以及用户可以如何判断配置是否已生效。
- 覆盖常见的凭据缺失、权限不足、额度不足、网络失败、配置未生效和能力降级问题，并给出可行动的排查顺序。
- 说明 API Key 的保存与展示边界，以及会话、记忆、人格、Skill、日志和其它主要用户数据的用途与存储类别。
- 说明用户可用的数据清理、重置、诊断或求助路径；不存在的产品入口不得被虚构。

#### agent-friend 内置 Skill

- agent-friend 默认提供 `agent-friend-guide` 作为 builtin Skill，用户不需要把公开仓库手动安装到 agent-friend 才能使用。
- builtin Skill 与现有 Skill catalog、选择、激活、渐进式加载和权限边界保持一致，不获得额外的隐式权限。
- 内置版本在离线环境中仍能提供随当前产品交付的知识，不依赖运行时从公开仓库在线拉取内容。
- 内置内容与公开来源之间的版本和一致性可验证；更新内置内容时保留明确的来源记录。

#### 项目维护 Skill

- 在 agent-friend 项目内提供显式维护 Skill `maintain-agent-friend-guide`，不作为面向最终用户的 builtin Skill 交付。
- 维护 Skill 至少支持两个彼此分离的阶段：
  - **检查**：只读分析尚未完成知识审阅的产品变更，判断是否需要更新，并列出依据、受影响知识主题和建议更新内容；
  - **更新**：仅在用户另行授权后，更新公开知识仓库、完成必要验证与提交推送，再把精确的公开版本同步回当前 agent-friend 分支并验证一致性。
- 判断必须结合实际变更、相关代码、测试和用户可见行为，不得仅按文件路径、提交标题或关键词机械判定。
- 判断范围不得只局限于当前未提交 diff；需要能够覆盖自上次已完成知识审阅以来尚未处理的变更，避免历史遗漏。
- 无用户可见影响的内部重构、测试整理、格式调整或等价变更可以判定为无需更新，但需要给出简洁理由。
- 执行提交或推送前遵守各仓库的 Git 范围确认、提交信息和外部写入授权约束，不因运行维护 Skill 而获得无限制写权限。
- 跨仓库流程部分成功时记录公开仓库提交、agent-friend 同步状态和剩余步骤；重新执行时从已完成状态继续，不重复发布，也不自动回滚已经推送成功的公开提交。

#### 知识维护提醒

- 在构建以下任一安装包前提醒用户是否进行知识维护检查：
  - stable release；
  - trusted-beta；
  - local-test。
- 在用户明确要求将当前变更合入 `main` 并推送远端前，提醒用户是否进行知识维护检查。
- 提醒只询问是否检查，不自动运行检查、不自动修改知识、不自动提交或推送。
- 用户拒绝或跳过检查时，提醒本身不阻止打包、合入或推送；后续操作仍服从其原有门禁。
- 普通 feature/fix 分支 push 不触发该提醒。
- 对同一代码状态或同一交付动作已经询问过、已经检查过或已经完成维护时，不重复提醒；代码状态发生实质变化后可以再次提醒。
- 用户直接要求执行知识维护检查或更新时，直接进入对应工作流，不先重复询问是否检查。

### 不包含

- 产品内首次启动向导、readiness checklist UI、设置字段 tooltip、帮助按钮或诊断面板改造。
- 独立公开文档站、GitHub Pages 或完整用户手册站点。
- 火山引擎从开户、实名认证、服务开通到所有控制台操作的完整截图式教程。
- 在应用运行时从公开仓库自动更新 builtin Skill。
- 自动运行知识维护检查、自动修改公开知识或未经用户授权自动提交和推送。
- 因用户跳过知识检查而阻止 local-test、trusted-beta、stable release、合入或推送。
- Codex plugin、公共 plugin marketplace 或其它插件分发渠道的打包与发布；首期只交付标准 Agent Skill 仓库和安装说明，并为未来扩展保留兼容空间。
- 为完成知识说明而新增第三方服务连接测试 UI，或使用用户真实 API Key 执行外部服务验收。
- 与本需求无关的现有项目文档全面重写。

## 关键信息

- 现有 Agent Skill 系统及 builtin Skill 能力见 [需求 076](../076-agent-skill-system/requirement.md)。
- 新用户引导和公开知识的前期问题见 [新用户可用性与公开引导 exploration](../../explorations/user-readiness-and-public-guidance/README.md)。
- agent-friend 当前的公开知识必须以实际代码、当前设置字段、已确认需求和真实产品行为交叉核对，不能直接复制可能过时的顶层 README 或历史路线图表述。
- 本需求涉及两个不同职责的 Skill：`agent-friend-guide` 负责提供产品知识；`maintain-agent-friend-guide` 负责维护工作流。二者不得因共享主题而合并成一个同时面向最终用户和项目维护者的宽泛 Skill。

## 验收条件

### 公开知识与 Coding Agent 使用

- [ ] 独立公开仓库中存在符合 Agent Skills 规范的 `agent-friend-guide`，并提供清晰的安装或引用方式。
- [ ] 兼容 Coding Agent 能针对产品功能、首次配置、API Key、数据隐私和常见排障请求选择该 Skill，并只加载完成问题所需的知识主题。
- [ ] Skill 能正确区分当前可用、可选增强、实验性和未交付能力，不把产品愿景或历史状态误述为当前事实。
- [ ] DeepSeek、Kimi、Tavily、高德地图和和风天气的凭据指引覆盖官方入口、用途、配置位置、影响能力和生效方式。
- [ ] 火山引擎指引覆盖当前字段、功能依赖组合、缺失影响、官方定位入口和配置生效方式，并明确首期不提供完整截图式开户教程。
- [ ] 数据、隐私、配置生效和常见故障知识与当前产品行为一致，不虚构尚不存在的入口或能力。

### agent-friend 内置使用

- [ ] 新安装或升级到包含本需求的 agent-friend 后，`agent-friend-guide` 默认出现在 builtin Skill catalog 中，无需用户手动安装。
- [ ] builtin Skill 能通过现有统一 Skill 激活路径使用，不绕开 catalog、权限或渐进式加载机制。
- [ ] 在无法访问公开仓库的环境中，builtin Skill 仍能回答随该产品版本交付的知识。
- [ ] agent-friend 内置内容能够验证其与某个精确公开来源版本一致，并保留可追溯来源。

### 维护检查与更新闭环

- [ ] `maintain-agent-friend-guide` 能在只读检查中基于尚未审阅的实际产品变更，输出“需要更新”或“无需更新”的结论、证据和受影响知识主题。
- [ ] 纯内部、测试或格式变更能够被合理判定为无需知识更新；用户可见功能、配置、数据或限制变化不会仅因路径映射缺失而被漏判。
- [ ] 用户授权执行更新后，维护工作流能够完成公开知识修改、验证、提交推送、agent-friend 内置版本同步和一致性验证。
- [ ] 公开仓库已经推送但 agent-friend 尚未同步等部分完成状态可被识别并安全续跑，不重复发布、不自动回滚公开提交。
- [ ] 未获得更新授权时，检查过程不会修改任一仓库，也不会执行提交或推送。

### 提醒行为

- [ ] stable release、trusted-beta 和 local-test 三种安装包在构建前都会提醒用户是否进行知识维护检查，但不会自动检查。
- [ ] 用户要求将变更合入 `main` 并推送远端前会收到同类提醒；普通 feature/fix 分支 push 不触发提醒。
- [ ] 用户拒绝检查后可以继续原有打包、合入或推送流程，知识提醒不会变成额外阻塞门禁。
- [ ] 同一代码状态或同一交付动作不会重复提醒；相关代码发生实质变化后能够再次提醒。
- [ ] 用户直接要求检查或更新时不会先收到多余的“是否检查”询问。

### 项目门禁

- [ ] 新增或调整的 Skill、同步和提醒机制有与其回归风险相称的自动化验证。
- [ ] 项目规定的完整检查通过。
- [ ] 不执行真实第三方 LLM、搜索、地图、天气或语音 API 调用也能完成本需求的确定性验收；若另行安排真实调用，必须单独取得授权。
