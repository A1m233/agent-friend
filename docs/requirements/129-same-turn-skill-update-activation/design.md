# 已有 Skill 更新后同轮使用 - 技术方案

## 状态

CONFIRMED

## 需求文档

[requirement.md](./requirement.md)

## 现状分析

轮初 catalog 的正文版本参与后续激活校验，阻止轮内新版加载。激活只保存正文，文件授权指向活目录，命令首次执行才按 Skill ID 缓存包快照。installer 的事务成功仅通过标准输出呈现，Conversation 没有可信更新通知。

## 方案设计

### 版本绑定

轮初 catalog 固定候选身份，激活时重新校验当前有效定义和调用权限。每次激活取得完整包快照；正文、文件 scope 和新命令共用此版本。再次激活可替换当前绑定，同版本去重。历史消息不回写，旧命令持有旧快照，轮结束统一清理。

### 更新结果

复用现有 installer 和命令授权，给受支持更新增加结构化结果通道。宿主只接受经过验证的首方 installer、精确执行入口和当前运行所属的结果，校验目标身份、事务结果与实际包内容；任意 stdout、模型声明和 shell 拼接不得冒充可信更新。

命令完成后在继续模型或后续工具前消费一次结果：目标已在本轮激活则自动重新加载，未激活则只刷新候选版本。buffered 与 streaming 完成路径统一处理。普通 watcher 与首方后台更新不自动切换当前轮绑定。

### 激活结果与权限

正文、资源 scope 和当前 binding 一起发布。宿主显式选择的来源由宿主保留，模型不能自报调用类型。新版的调用限制与命令、文件、网络授权仍独立校验。更新成功但加载失败时分别报告状态，暂停该 Skill 的后续绑定操作，允许同轮修正并重试；不静默回退旧版。

### 上下文与生命周期

新版本正文和切换说明作为新结果进入历史；同版本不重复注入，脚本单独变化仍更新资源版本。压缩及恢复使用最新成功状态，不把旧正文、旧 scope 或失败版本重新投影为当前能力。取消或异常仍结束命令并清理快照，不启动新轮外工作。

## 影响分析

不新增模型可见更新工具或绕开命令审批。不改变首次安装、更新同源与覆盖规则。重点验证脚本单独更新、旧流式命令继续运行、伪造回执、失败与取消、显式调用权限和上下文恢复。新资源通道及安装包内执行路径按 frozen-runtime-packaging 分类验证；真实 LLM 运行遵守单独授权。
