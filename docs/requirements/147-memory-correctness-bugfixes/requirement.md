# 147 · 记忆正确性修复

## 状态

COMPLETED

2026-10-01：用户确认五项修复与 10 分钟等待增补；全部验收条件完成，已合入主干并推送，local-test 安装包已构建与核验。详见 progress.md。

## 背景

本次由“长期使用后核心身份资料仍为空”的诊断开始。指定附件案例确认：主对话能够理解 PDF，但现有记忆素材投影仅传递用户文字、文字引用与助手回复，没有把附件内容交给抽取器。该案例同时经历了后台抽取延迟。用户明确要求先不增加机制，先盘点并修复现有记忆链路的 bug。

进一步核对输入投影、抽取协议、延后处理、持久化、来源失效、时间检索及 Core 装配后，得到五项独立问题。它们的证据等级不同：时间偏移同时有本地持久化与离线证据，其余主要由确定性构造复现支持；不能把所有复现都说成已经发生在用户数据中。详细锚点与限制见 [证据索引](evidence-index.md)。

## 目标

- 不把抽取协议错误误记为成功，避免有价值素材被静默标记为已处理。
- 编辑撤销来源后，相应错误记忆不能经历史版本搜索重新进入模型上下文。
- 区分来源观察时间、事实有效时间与写入时间，使延迟处理不把历史事实移动到补处理当天。
- 单条不可处理的待处理记录不能永久阻断其他正常素材，同时保留失败证据及可恢复性。
- Core 数据异常时统一进入已有的不可用状态，保留普通记忆与正常对话的可用性，不返回半份核心资料。

## 范围

### 包含

1. 基础抽取结果的结构校验、合法空结果判定、失败状态、幂等提交和待处理清理。
2. 已失效来源对应的普通 Semantic 历史版本及 Core 历史记录的有效性；覆盖跨会话替换后编辑原会话最后一条消息的场景。
3. 延后抽取中新事实与被替换事实的时间边界、历史查询以及 Episodic 与 Core 的一致性。
4. 延后记录解码或确定性本地数据异常对队列后续工作的影响、失败归属及恢复边界。
5. Core 存量数据解码、字段与完整投影校验的异常分类，以及自动对话中的降级呈现。
6. 与上述修复直接相关的最小诊断信息和确定性回归验证。
7. 2026-10-01 用户增补确认：基础记忆抽取与 Semantic 协调的完整响应等待调整为 10 分钟；不调整其他模型调用、连接超时、重试次数、冷却或调度。

### 不包含

- 新增附件正文或任意工具结果进入长期记忆的通路。
- 历史 Core 自动补建、批量重抽历史、自动修复或回写个人记忆。
- 新增后台定时补跑、全局调度系统、无界恢复或通用队列平台。
- 改变 Core 字段范围、保守迁移策略、记忆模型选择或按语义猜测事实替换目标。
- 把合同法定姓名直接等同于期望称呼，或把文件地址直接等同于当前住处。
- 重做召回排序、上下文压缩或重复实施 145、146 的资源与发送延迟治理。
- 以安装包构建、用户实例重启或真实 LLM 调用作为未经授权的默认验证步骤。

## 需求

### R-1 抽取失败与成功严格区分

缺少受支持协议必需结构、字段类型错误或条目结构错误的输出必须标记为失败，不得作为成功空结果提交，不得因此删除待处理素材。合法空结果仍应幂等提交。

兼容协议只能接受明确受支持的旧格式，不得用兼容名义接受任意 JSON 对象。既有受控旧格式消费者的兼容边界在方案中明确，不以破坏回放或评测为代价收紧生产校验。

### R-2 来源失效覆盖历史版本

来源被编辑撤销时，由该来源直接产生的当前事实和历史事实均不得继续作为有效查询证据；保留记录用于追溯，不把审计历史伪装成可召回事实。

跨会话更新后，编辑原会话最后一条消息不应使无关会话的有效新事实失效。失效操作幂等，不能通过重新抽取、恢复队列或索引回填复活已撤销内容。

本期不新增自动恢复先前事实版本的语义；“使错误来源失效”与“判断应该恢复哪项旧事实”分开处理。

### R-3 延后处理保持正确时间语义

来源观察时间与实际入库时间分别可追溯；不得仅因延迟执行就把事实有效起点和替换边界移动到入库当天。无法可靠得出更精确事实发生时间时，沿用既有观察时间语义，不让确定性代码猜自然语言日期。

方案必须明确多发言片段的观察边界、Core 与 Semantic 的有效期、普通替换和撤回、跨会话乱序及既有数据的兼容方式。不能产生结束早于开始的有效期，也不能让迟到的旧观察无条件覆盖较新的当前事实。

既有个人数据不自动批量重写；历史偏移的修复须作为另行授权的数据操作。

### R-4 单条失败不永久阻断正常素材

可确定为单条记录问题的解码、结构或本地数据错误，不得让所有会话反复停在同一个队首。失败项应保留原始材料及可解释状态，不得静默删除或谎报成功。

连接、认证、限流、临时服务故障继续遵守既有失败归属和有界恢复策略，不能为了绕过单条错误而对故障连接逐条发请求。保持 FIFO 的正常处理顺序、单次最多两段的恢复边界，以及重启、flush、close 不主动补发积压的语义。需要调整的例外及恢复条件在方案中明确。

### R-5 Core 异常统一降级

无法解码的 Core 字段、未知字段、非法类型、时间或投影约束应进入统一的不可用状态；该状态与正常空资料可区分。普通记忆可用时仍应返回，不让单项 Core 损坏直接破坏整轮对话。

保持完整 Core 装配语义；不得通过静默跳过坏条目、截断或返回半份 Profile 来掩盖错误。保留定位问题所需的信息，不将个人资料正文扩散到常规诊断日志。
