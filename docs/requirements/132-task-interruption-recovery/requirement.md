# 132 · 任务中断恢复与状态呈现一致性

## 状态

CONFIRMED

确认日期：2026-09-16。

## 背景

真实任务在已完成若干工具步骤后，因为后续模型请求的临时连接故障停止。用户尝试从工具结果继续时，又产生一次内部失败，界面保留两条错误及空回复。进一步检查发现，现有继续入口仅允许整理文字，即使恢复入口可用，也无法执行尚未完成的后续步骤。

本需求统一盘点任务中断、恢复执行及用户可见状态，消除局部恢复机制之间的语义冲突。原始证据、构建限制和对照资料见 [evidence-index.md](./evidence-index.md)。

## 目标

- 短暂模型故障优先在当前运行内恢复，用户能看懂当前是在等待、重试还是已经停止。
- 恢复继续完成原任务，保留后续工具能力，同时复用已完成步骤，避免重放副作用。
- 同一任务恢复过程具有一致的错误、进度和耗时呈现，实时更新与重新打开历史一致。
- 默认可恢复模型请求失败的自动重试上限增加到 5 次，首次请求不计入重试次数。

## 范围

### 包含

1. 盘点模型连接失败、流式输出中断、工具失败、用户停止以及运行时重启的现有处理；区分可自动恢复、需用户继续和不可恢复的边界。
2. 对可恢复的模型请求失败，首次请求后最多自动重试 5 次，即该次请求最多 6 次尝试。首次请求、重试和手动继续使用明确的计数口径；不能由内部多层重试暗中放大该预算。
3. 重试采用有界等待，等待期间可停止；不可恢复的凭据、权限、内容策略等错误不因增加次数被无意义重试。
4. 自动恢复保留当前任务与已完成结果；手动继续恢复剩余工作，允许合法的新工具调用，而非仅生成总结。恢复不自动切换模型、Provider、账号或提升权限。
5. 工具已确认完成时复用结果；执行状态未知时明确保留未知语义，先核实状态或请求必要决策，不把网络重试等同于再次执行动作。
6. 用户主动停止后不自动恢复。应用或 Bridge 重启后默认由用户主动继续；只重开页面或重连客户端不重复启动仍在运行的任务。
7. 同一任务恢复过程统一显示一个当前状态区域：重试中、最终失败、正在继续、恢复完成；恢复失败更新原状态，不新增只有错误的空助手回复。独立任务与独立错误不得错误合并。
8. 统一后台终态、实时事件、历史投影、重连校准和耗时口径；保留每次运行尝试的诊断记录，不以隐藏日志换取界面简洁。
9. 检查共享引擎变更对桌面对话、IM、语音及其它运行入口的影响；已有渠道能力边界不被恢复绕过。

### 不包含

- 整个 Agent 架构重构、改写工具系统或新增通用工作流引擎。
- 无界自动重试、用户停止或重启后的无人值守自动续跑。
- 对任意外部系统提供无法证明的副作用 exactly-once 保证。
- 修复外部模型服务自身的网络或服务端故障。
- 为此次需求直接修改 MAA skill 或其它业务任务规则。

## 验收条件

- [x] **AC-01 中断边界**：各类中断的恢复动作、终态和用户可见状态均有明确归属；实现与盘点结论一致。
- [x] **AC-02 重试预算**：可恢复请求可执行第 1 至第 5 次自动重试；第 5 次成功可继续任务，全部失败最多发生 6 次请求尝试；计数与展示一致，没有嵌套放大。
- [x] **AC-03 停止与不可恢复错误**：退避等待中停止能及时生效，停止后不再发出请求；不可恢复错误不进入通用重试。
- [x] **AC-04 后续工具能力**：工具 A 成功、后续模型请求失败，恢复后可执行尚未完成的工具 B 并最终回答；A 不因恢复被宿主重放。以“预检查完成、实际动作尚未执行”为代表案例。
- [x] **AC-05 部分输出**：已有文字、完整工具调用和未完整工具参数分别覆盖流中断，恢复后不重复已提交内容、不执行残缺调用，无法安全自动恢复时明确转入可解释的停止状态。
- [x] **AC-06 恢复请求一致性**：有生命周期事件的真实 Runtime 路径能恢复合法失败；重复点击、过期目标、并发继续和新用户消息竞争不产生重复执行或额外错误空回复。
- [x] **AC-07 工具副作用边界**：已完成、未开始、仍在运行及结果未知的工具分别验证；未知状态不被谎报为未执行或成功，不盲目重放。
- [x] **AC-08 展示一致性**：自动重试及多次手动恢复只更新关联任务当前状态；事件重复到达、先后顺序变化、刷新和重连不制造重复错误、空助手消息或伪造耗时。
- [x] **AC-09 重启与主动停止**：重启后保留已提交结果并等待用户主动继续；用户主动停止后不自动恢复；客户端重连不新建重复运行。
- [x] **AC-10 渠道边界**：共享 Provider/Runtime 的受影响入口通过回归检查，恢复保持原有审批、取消和权限边界。
- [x] **AC-11 验证与验收**：核心机制有确定性测试，项目 `scripts/check` 全绿；用户确认验收。真实 LLM 与桌面视觉验证的范围及授权另行记录，未执行不得报告为通过。
