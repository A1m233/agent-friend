# 066 · 附近地点搜索

> Nearby Place Search

## 状态

<!-- DRAFT | CONFIRMED -->

CONFIRMED

## 1. 背景

agent-friend 当前只有 `web_search` 等少量读取工具。当用户询问“帮我找福民银行附近最近的照相点”时，模型会尝试使用普通网页搜索，但网页结果无法稳定完成地标解析、附近 POI 查询和距离排序，容易给出不完整、不可验证或似是而非的建议。

因此，本需求要为 Agent 增加专用的附近地点搜索能力：用户给出地点、地标或地址作为锚点，Agent 能找到附近的目标地点，并基于可靠地理数据回答。该能力与 `web_search` 互补：地点工具负责地理位置与距离事实，网页搜索可在需要时进一步补充官网、预约、近期信息等网页内容。

## 2. 目标

1. 让用户能以地点、地标或地址为锚点，查询附近的某类地点。
2. 在锚点可靠确定后，返回有地理数据支撑的名称、距离和地址，并根据用户意图合理排序。
3. 在锚点存在多城市同名、同城多分店或其他合理歧义时，让 Agent 先向用户澄清，而不是静默猜测。
4. 在地点服务无结果或不可用时如实反馈，不使用普通网页搜索伪装已完成附近地点查询。
5. 允许附近地点搜索与其他工具分步配合，让 Agent 在坚守各自事实边界的前提下完成更完整的任务。

## 3. 范围

### 3.1 包含

- 支持以用户给出的地点、地标或地址作为附近查询锚点。
- 支持以自然语言描述目标类型，例如“照相馆”“药店”。
- 支持用户提供可选城市来缩小锚点范围。
- 在锚点能够唯一、可靠地确定时，以该锚点查询附近地点。
- 在锚点存在多城市同名、同城多分店或其他合理歧义时，向用户展示足以区分的候选信息并请求澄清。
- 至少返回结果的名称、与锚点的距离和地址。
- 向用户明确说明本次查询以哪个锚点为中心、覆盖多大范围，不用含糊的“附近”代替实际范围。
- 当用户明确说“最近”时优先按距离排序；对普通“附近”查询，允许综合距离与相关性合理排序。
- 电话、营业信息等附加字段只在地点服务提供可靠数据时返回，不得推测或编造。
- 当查询无结果、凭据缺失、额度耗尽或地点服务失败时，给出自然、可理解的反馈。
- 允许 Agent 先用地点搜索建立可靠的位置与距离事实，再用 `web_search` 或未来的其他合适工具补充网页信息或继续完成后续任务。
- 工具调用与结果继续遵守现有会话事件、隐私、错误处理和工具描述约定。
- 地点服务所需凭据继续通过项目现有的运行时凭据与配置入口管理。
- 用户保存或删除运行时凭据后，系统按凭据声明的生效范围自动刷新对应运行服务；不要求用户手动重启应用或 Bridge。
- 对话模型和记忆模型等会被运行服务启动时读取的普通设置，也应由系统自动完成必要的运行服务刷新，让用户无需理解底层生效时机。

### 3.2 不包含

- 获取设备“当前位置”。
- 新增系统定位权限。
- 交互式地图 UI、地图窗口或地图标记渲染。
- 导航、路线规划或出行时间估算。
- 天气查询。
- 地点收藏、位置历史或长期位置记忆。
- 修改工具循环轮次、并发策略、总调用预算、超时预算或重复调用检测。
- 实现或接管 `calculate`、`datetime_calculate`、`web_fetch`、memory 或 reminder 工具。
- 把地理编码、候选解析和附近 POI 查询等底层步骤暴露成需要模型自行串联的多个用户意图工具。

## 4. 核心需求

### 4.1 工具意图与查询入口

- **R-1.1 用户意图入口**：Agent 应能通过一个贴近“查找某地附近的某类地点”用户意图的工具完成常见查询，而不是自行编排多个 provider 底层接口。
- **R-1.2 查询要素**：查询至少能表达目标地点类型和锚点，并允许在用户已给出时携带城市范围。
- **R-1.3 不依赖当前位置**：本期查询的锚点必须来自用户提供的地点、地标或地址，不请求或暗中使用设备位置。

### 4.2 锚点解析与歧义

- **R-2.1 可靠锚点**：只有在系统能够可靠确定锚点时，才能以该位置进行附近查询。
- **R-2.2 歧义澄清**：锚点存在多城市同名、同城多分店或其他合理多候选时，Agent 必须请求用户澄清，不得按市中心距离、热度或候选顺序静默选择。
- **R-2.3 候选可区分**：请求澄清时应提供候选的名称和地址等足以让用户区分的信息；不展示没有可靠来源的推测。
- **R-2.4 城市仅缩小范围**：用户提供城市可用于缩小锚点范围，但不能被视为已经解决城市内的多候选歧义。

### 4.3 附近结果与可信字段

- **R-3.1 最小结果集**：每个返回的附近地点至少包含名称、与锚点的距离和地址。
- **R-3.2 距离事实**：距离必须基于地点服务返回或可靠地理数据得出，不得根据网页文本、常识或模型猜测。
- **R-3.3 排序语义**：用户明确要求“最近”时必须优先按距离排序；对普通“附近”请求，可综合相关性与距离给出合理结果。
- **R-3.4 可选字段诚信**：电话、营业时间或其他附加信息只能在服务有可靠数据时返回；缺失时省略或明确表示未提供，不得编造。
- **R-3.5 查询范围透明**：成功执行附近查询时，Agent 必须向用户说明本次采用的锚点和搜索半径；不得只用“附近”描述一个未交代的地理范围。

### 4.4 失败、无结果与工具协作

- **R-4.1 真实失败反馈**：查询无结果、凭据缺失、额度耗尽或 provider 失败时，Agent 应告知用户当前未能完成附近地点查询，并在可能时提供可执行的下一步。
- **R-4.2 不伪降级**：地点查询失败后，不得仅凭 `web_search` 结果宣称已找到“附近”或“最近”的地点。
- **R-4.3 允许分步协作**：附近地点搜索与 `web_search` 等工具不互斥。Agent 可先以地点工具确立锚点、候选、距离和地址，再用其他工具补充官网、预约方式、近期评价或其他网页信息。
- **R-4.4 事实边界**：多工具协作时，附近性、距离和地理排序必须依据地点数据；网页搜索只能补充其擅长的网页信息，不得覆盖或伪造地理事实。

### 4.5 约束与兼容

- **R-5.1 现有会话语义**：工具调用、结果和失败必须沿用现有会话事件、隐私与错误处理语义。
- **R-5.2 既有凭据入口**：地点服务凭据必须与现有运行时凭据和配置管理方式保持一致，不为本工具新建另一套用户配置入口。
- **R-5.3 并行需求边界**：本需求不修改 `Conversation` 工具循环，不实现或接管 065 需求负责的读取工具、循环深度、调用预算、超时和重复调用检测。
- **R-5.4 配置自动生效**：保存或删除运行时凭据，以及修改对话模型或记忆模型后，系统必须按配置影响范围自动刷新 Bridge 或 Voice Bridge；用户不需要手动重启。
- **R-5.5 安全刷新**：配置先可靠持久化，再执行刷新。若刷新因活动任务、通话或运行时错误未完成，系统必须保留已保存配置并明确提示“已保存但尚未应用”，不得误报为保存失败，也不得强行中断正在进行的交互。
- **R-5.6 统一编排**：运行服务刷新由集中机制依据既有配置 effect 执行，不在每个 provider 或凭据控件中复制重启逻辑；同一时刻只执行一次配置变更与对应刷新。

## 5. 验收标准

- **AC-1**：用户说“帮我找深圳福民银行附近最近的照相馆”，且锚点可唯一确定时，Agent 使用专用地点能力返回至少包含名称、距离和地址的候选，并优先按距离排序。
- **AC-2**：用户说“某商场附近的药店”且未强调“最近”时，结果可同时考虑距离与相关性，但每个结果仍有可靠的距离和地址。
- **AC-2a**：完成附近查询后，最终回答明确说明用于查询的锚点和搜索半径，例如“以某商场为中心 5 公里内”，而不是只说“商场附近”。
- **AC-3**：锚点在多城市或同一城市内存在多个无法可靠排除的候选时，Agent 先展示可区分的候选并要求澄清，不执行基于静默猜测的附近查询。
- **AC-4**：用户已提供城市但城市内仍有多个合理锚点候选时，Agent 仍请求澄清，不以城市参数代替唯一性判断。
- **AC-5**：地点服务未返回电话或营业信息时，Agent 不补写、猜测或把缺失数据表述为已确认事实。
- **AC-6**：查询无结果、凭据缺失、额度耗尽或 provider 失败时，Agent 如实说明未能完成附近地点查询，不用 `web_search` 结果假装已按位置或距离完成查询。
- **AC-7**：一个需要地理事实与网页信息的复合请求可分步调用附近地点搜索和 `web_search`；最终回答不将网页搜索推测冒充为距离事实。
- **AC-8**：不获取设备当前位置、不请求系统定位权限，且未提供可用锚点时不暗中推断用户位置。
- **AC-9**：地点服务凭据通过现有运行时凭据与配置入口管理，未新增与项目其他凭据脱节的第二套入口。
- **AC-9a**：保存或删除任一已登记运行时凭据后，系统按其 effect 自动重启 Bridge 或 Voice Bridge；重试地点查询时无需用户手动重启应用。
- **AC-9b**：修改对话模型或记忆模型后，系统自动刷新 Bridge，使 Bridge 启动时读取的默认对话模型和记忆客户端配置一致生效。
- **AC-9c**：凭据或模型设置已持久化、但对应运行服务无法安全重启时，界面明确区分“保存成功”和“尚未应用”，且不打断活动通话或生成任务。
- **AC-10**：工具调用及结果在现有会话事件中可正常记录，失败不破坏对话继续进行，且不改变现有工具循环语义。
- **AC-11**：项目规定的自动化门禁全部通过，既有工具工厂、凭据管理、会话事件和 `web_search` 行为不退化。

## 6. 依赖与约束

- 附近地点查询依赖能够提供锚点候选、POI、距离和地址数据的地点服务；具体 provider 与底层 API 编排属于技术方案。
- 用户给出的锚点、城市和查询词可能被发送给外部地点服务，其处理必须继续遵守项目现有隐私约定。
- 本需求与 `feature/065-trustworthy-read-tools-and-tool-runtime` 并行开发。两者共享的工厂、依赖、凭据和测试接入点应在 065 合入后基于最新 `main` 集成，不为规避冲突建立并行的 registry 或配置架构。
