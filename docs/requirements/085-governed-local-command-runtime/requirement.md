# 受治理的通用本地命令运行时

## 状态

CONFIRMED

## 背景

agent-friend 当前只能调用已经注册的固定 Tool，不能像通用 Coding Agent 一样在用户授权和安全边界内启动本地进程，也不能执行 Skill 明确引用的 Python、PowerShell、shell 或其它命令行脚本。这个缺口已经由 [issue 045](../../issues/045-governed-command-and-skill-script-runtime/README.md) 登记，并限制了依赖确定性脚本、构建工具、测试命令和外部 CLI 的 Agent 工作流。

这个能力不应被实现成某个 Skill、某种业务或某个程序的专用 Tool。Skill 负责提供任务知识、脚本入口和操作步骤；公共命令运行时负责执行、授权、安全、进程生命周期和结果真实性。这样，未来的日常自动化或其它个性化 Skill 可以继续把 Agent 作为决策主体，而不需要为每个目标程序重新开发一套工具接口。

命令运行还包含普通 Tool 没有的长生命周期问题。构建、打包和测试可能持续数分钟；如果 Agent 每隔一秒查询一次状态并由模型重新推理，不仅浪费模型调用，还会迅速污染上下文。系统需要在模型之外持续观察进程和向用户展示进度，只在出现真正需要 Agent 决策的事件时恢复模型。

通用命令也显著扩大了本地权限与供应链风险。最终用户不应为了获得该能力自行安装或配置 Codex，也不应因为机器上恰好存在用户自己的 Codex 配置、登录态或 PATH 而得到不一致行为。产品需要携带并治理自身依赖的官方 Codex 命令执行能力，同时复用 agent-friend 已有的授权控制面。

真实 Skill 安装验证进一步暴露出，命令运行时“能够启动沙箱进程”不等于用户旅程已经可用。Windows 沙箱的一次性系统初始化、沙箱内网络栈与托管代理、Skill 包工作目录和安装后的 catalog 刷新必须作为同一条能力链路验证；否则这些缺口只会在 Agent 真正执行联网 Skill 脚本时逐层暴露。

## 目标

- 为 Agent 和 Skill 提供可复用的通用本地命令执行与交互式进程能力，不为具体业务程序建立专用 Tool。
- 复用现有授权请求、批准、拒绝、超时、取消、会话归属和前端展示链路，并为未来不同授权等级保留统一扩展边界。
- 让长时间运行的命令由本地运行时事件驱动地观察和展示，不以固定周期的 LLM 调用维持进程等待。
- 让命令、工作目录、环境、文件与网络能力、输出、退出状态、取消和进程树清理形成一致、可测试的安全契约。
- 让没有项目或用户所选工作区的普通会话也能自然使用命令能力，并把命令启动目录、文件访问范围和授权决定作为彼此独立的概念治理。
- 让 Skill 脚本执行绑定本轮实际加载的 Skill 内容身份，防止运行期间资源变化导致执行对象被静默替换。
- 由产品在 Windows 安装包中携带并治理固定版本的官方 Codex 命令执行依赖，不要求或复用用户自行安装的 Codex；源码运行形态保持 Windows、macOS 与 Linux 的一致能力接口。
- 把 Windows 沙箱初始化作为跨会话共享的系统能力准备统一管理，并与每条命令的授权决定明确分离。
- 让声明需要网络的命令在批准范围内获得真实可用、可诊断的网络能力，而不把“沙箱进程已启动”误报为网络可用。

## 范围

### 包含

#### 通用命令与进程交互

- Agent 可以提交结构化的命令执行请求，至少表达可执行程序、参数和执行所需的受控环境信息；只有任务确实依赖特定目录时才需要显式指定工作目录，否则由产品提供安全、稳定且可审核的默认执行目录。
- 默认命令继续在受限沙箱中执行。可信桌面程序或其它确实依赖当前桌面用户会话、无法在受限沙箱运行的宿主能力，可以显式申请 `host_user` 执行级别；该级别必须使用结构化参数并在审批中清楚展示不受文件系统和网络沙箱限制，不能从普通命令静默降级获得。
- 命令能力可以运行 Skill 明确引用的确定性脚本、项目已有构建与测试入口以及用户任务所需的其它本地 CLI，不限定为托管脚本清单。
- 普通会话不以创建项目、打开文件夹或选择用户工作区作为命令执行前置条件；在受控环境和授权边界内，命令可以发现并运行产品允许从 `PATH` 解析的本地 CLI。
- 命令启动后返回可识别的工具调用与进程会话状态；完成时准确返回退出码、标准输出、标准错误、持续时间、是否被截断以及终止原因。
- 对确实需要交互的前台进程，Agent 可以向仍然活跃且归属匹配的进程会话写入输入，并取得后续输出或终态。
- 进程会话不能跨会话、跨 run 或跨工具调用错误复用；进程已经结束、失效或归属不匹配时返回结构化失败，不能把输入写入其它进程。
- 第一版不提供 detach。Agent 启动的命令始终由当前运行时治理，用户取消任务、应用结束相关执行或命令超时后，不留下脱离管理的子进程树。

#### 长任务与模型调用边界

- 命令仍在正常运行本身不构成一次新的模型推理事件。系统不能通过每秒或其它固定短周期的 LLM 调用轮询进程状态。
- 本地运行时在模型之外持续接收命令输出、进程退出和异常事件，并可以独立向当前会话界面推送进度。
- Agent 发起命令后，其工具调用可以保持逻辑上的进行中；普通等待期间不要求模型反复调用状态查询工具。
- 只有命令完成、失败、被取消、需要新的授权、需要真实交互输入、出现必须由 Agent 判断的异常，或用户主动要求 Agent 介入时，才恢复模型处理。
- 输出更新用于用户可见进度和运行时记录，不因每个输出片段自动触发 LLM 调用；恢复模型时提供有界、合并后的必要结果。
- 进程交互能力用于真实输入、用户或 Agent 的显式状态查询和有界异常恢复，不得被实现为固定频率的模型级轮询循环。
- 底层事件通知暂时不可用时，系统可以采用有界长等待进行恢复，但不能退化为秒级忙轮询；等待期间仍须支持取消并在终态后及时恢复。

#### 授权复用与等级扩展

- 命令执行复用现有统一授权控制面，包括请求创建、会话与 run 绑定、批准、拒绝、超时、取消、失活恢复、前端推送和历史终态；不另建一套平行审批系统。
- 授权请求向用户展示将要执行的命令与参数、运行时最终解析的规范化工作目录、目的、关键能力范围和可识别的风险，使用户能够拒绝或仅本次允许。
- 第一版只开放仅本次授权。批准只覆盖界面中展示的原始操作、必要的受治理进程生命周期及其原始会话和 run，不跨任务永久保留，也不能静默扩大命令、目录或能力范围。
- 授权模型为未来的当前 turn、当前 session、持久规则或其它授权等级保留明确的作用域与生命周期维度；第一版未开放的等级必须不可选且 fail-closed，不能用占位值获得更宽权限。
- 文件授权与命令授权可以表达不同资源和风险，但共享相同的审批生命周期、归属校验和用户交互语义；现有文件工具行为保持兼容。
- 已批准命令在原始范围内进入长时间运行状态时，不因运行时内部等待或进度观察反复要求用户批准；命令发生实质变化或需要新增能力时重新申请。
- 无法承载本地审批交互的入口遇到待授权命令时，不默认批准，并明确提示用户转到能够完成审批的桌面端。

#### 全局沙箱能力准备

- Windows 命令沙箱初始化属于当前产品安装与用户环境共享的系统能力准备，不属于某个会话、run 或某条命令的授权。初始化成功后，所有沙箱命令复用同一份受治理状态，不重复要求管理员授权；显式 `host_user` 请求不依赖沙箱 readiness，但仍必须逐次审批。
- 产品在全局设置中统一展示命令运行能力与 Windows 沙箱的状态，并提供用户主动触发的初始化、重新检测和必要修复入口；普通命令不能在后台静默弹出 UAC 或修改机器级沙箱状态。
- 会话遇到未初始化状态时应明确引导用户完成全局准备。初始化成功只解除能力前置条件，不代表批准原命令，也不能扩大该命令请求的文件、网络、模式或生命周期范围。
- 初始化状态失效、产品依赖变化或网络代理要求变化时应回到“需要修复”的可诊断状态，不能在每个新会话中重新表现为一次普通命令审批。

#### 安全、环境与结果边界

- 每次执行都在明确的安全边界内运行。命令不能仅凭模型生成的字符串自动获得不受限制的文件、网络、环境变量或系统资源访问；`host_user` 只能由结构化直接进程请求和明确的一次性审批获得，审批必须把不受沙箱限制作为能力事实展示。
- 工作目录必须由运行时确定并规范化；它只表达进程从哪里启动，不自动成为用户工作区。工作目录默认只获得启动命令所必需、并在审批中明确展示的最小只读权限；写入该目录以及访问其父目录、相邻目录或其它宿主路径必须另行申请。相对路径、父目录跳转、符号链接、Windows junction 或进程启动后的路径变化不能绕过已经展示并批准的边界。
- 传给命令的环境以产品定义的受控基线和本次明确允许的增量为准，不默认继承凭据、令牌、代理、调试开关或其它不必要的宿主敏感环境。
- 文件系统、网络和其它高风险能力遵循最小必要与 fail-closed 原则。运行环境无法可靠落实某项声明的隔离时，不能把它描述为已隔离或静默放宽。
- 宿主路径确实不存在、路径存在但未获授权、路径因沙箱策略不可见、以及可执行程序无法从受控 `PATH` 解析必须形成可区分诊断；Agent 不能把权限或沙箱限制误报为软件未安装、文件不存在或环境损坏。
- 命令输出、单次读取量、累计保留量和注入模型上下文的内容均有明确上限；超限时保留终态和可诊断信息，并说明截断，而不是造成无限内存或上下文增长。
- 日志和诊断记录命令生命周期、授权决定、退出状态和安全拒绝所需的元数据，但不无界记录输出，也不主动记录凭据和其它敏感内容。
- 超时、用户取消、Agent 取消、运行时关闭和异常中断均产生可区分的终态，并在可治理范围内清理命令启动的整个进程树。

#### Skill 内容身份与公共能力

- builtin、agent-friend 专属个人 Skill 和共享个人 Skill 使用同一套公共命令运行时；Skill 来源本身不自动获得无限本地权限。
- Skill 请求执行包内脚本时，执行目标绑定到当前 Agent run 已加载的 Skill 快照或等价的不可混淆内容身份。
- 对已经结构化绑定到已激活 Skill 的包内命令，系统从该 Skill 身份和包内相对入口确定实际工作目录与不可变快照映射；Agent 不需要复制产品生成的内部绝对安装路径或快照路径。普通非 Skill 命令可以省略工作目录，由运行时提供并在审批与结果中展示实际目录。
- Skill 文件在加载后被修改、替换或通过链接指向其它内容时，系统不能静默执行与本轮已加载内容身份不一致的脚本；应拒绝、重新加载或重新申请必要授权。
- Skill 可以提供脚本、引用和工作流知识，但不能通过私有 runner、隐藏子进程或其它旁路绕开公共授权、安全和审计语义。
- 本需求以项目已有的确定性本地脚本和测试命令验证通用能力，不依赖特定业务 Skill 或 MAA 才能证明命令运行时可用。

#### Codex 依赖交付与跨平台

- 正式 Windows 产品随安装包携带经过固定版本和完整性治理的官方 Codex 命令执行依赖；用户无需另行下载 Codex、登录 Codex、配置用户级 Codex 目录或调整 PATH。
- 产品使用隔离的运行配置与数据位置，不读取或污染用户已有 Codex 的配置、凭据、会话和缓存；用户自行安装的不同版本也不能改变产品行为。
- 被携带依赖具有明确的版本、来源、许可证、哈希和与产品版本的对应关系；缺失、损坏、版本不匹配或完整性校验失败时拒绝启动命令能力并给出可诊断错误。
- 依赖更新必须作为受治理的产品更新进入构建、验证和发布流程，不能在运行期静默下载或自动切换到未验证版本。
- 源码运行形态在 Windows、macOS 与 Linux 上暴露一致的 Agent 工具和结果语义，并允许开发者通过项目标准入口提供匹配依赖；平台无法提供等价安全保证时明确报告能力不可用或差异，不静默降级。
- 第一阶段正式冻结运行时和安装包交付只覆盖 Windows；macOS 与 Linux 安装包内携带及发布验证不属于本需求。
- Windows 冻结运行时中的能力必须通过实际打包后的确定性 capability smoke 验证，不能只用源码环境测试或检查文件存在来代替。

### 不包含

- MAA、明日方舟日常流程、MAA 专用 Tool、MAA Skill 或 MAA runtime smoke。真实人工旅程可以贡献脱敏的通用 Agent 行为回归，但不把 MAA 运行环境作为本需求的机制验收前提。
- 任何具体业务 Skill 的设计与交付；本需求只提供它们可复用的命令能力基底。
- 定时任务、无人值守自动化、后台常驻工作流和应用退出后继续运行的 detached daemon。
- 当前 turn、当前 session、持久规则、命令白名单或其它非“仅本次”的授权等级实现及其管理界面。
- 把全局沙箱初始化视为对未来命令的全局批准，或因沙箱已经初始化而跳过任一命令的具体授权。
- 完整终端模拟器、终端标签页、面向用户的通用 shell UI 或远程命令执行服务。
- 让 Codex Agent、Codex app-server 或其它完整 Agent runtime 代替 agent-friend 自身的模型编排、会话和 Tool Runtime。
- 为 agent-friend 重新实现一套 Codex 命令执行服务器，或把官方命令执行组件复制、分叉成项目自维护实现。
- 用命令执行替代现有结构化文件工具；可以执行命令不意味着文件读写默认绕开文件授权和既有安全语义。
- 运行期自动安装系统级解释器、包管理器、编译器或其它任意第三方 CLI。
- macOS 与 Linux 正式安装包、签名、公证和发布矩阵。
- 以真实 LLM 调用、外部付费 API 或特定第三方服务作为确定性验收前提。

## 关键信息

### “仅本次”命令授权的口径

- 一次批准绑定用户实际看到的命令操作、能力范围、会话和 run，并覆盖该命令受治理的完整生命周期。
- 运行时内部等待、输出收集、终态获取和同一交互进程的必要输入不因技术上的多次通信被拆成新的宽泛授权；新增命令、改变工作目录、扩大文件或网络范围等实质变化需要重新审批。
- 用户拒绝、请求超时、run 取消、命令结束或运行时失活后，历史授权不可再次使用。

### 运行时观察与模型恢复

- 运行时观察是本地进程管理行为，不是 Agent 推理。它可以持续接收输出、更新界面和等待退出，而不产生 LLM 调用。
- 模型恢复只发生在有新的决策信息或用户主动介入时。单纯经过一段时间、命令仍在运行或收到普通进度输出，不属于新的决策信息。
- 用户可以在模型未运行期间看到命令仍在执行并主动取消；取消结果最终作为一次明确终态提供给 Agent。

### 与现有能力的关系

- 本需求闭环 [issue 045](../../issues/045-governed-command-and-skill-script-runtime/README.md) 所描述的公共命令与 Skill 脚本运行时缺口。
- 需求 [078](../078-governed-local-filesystem-tools/) 继续拥有结构化文件访问与变更语义；命令运行时复用其既有审批基础设施，但不取代文件工具。
- 需求 [082](../082-tool-execution-governance/) 的工具执行治理原则继续适用：可由运行时完成的等待、输出聚合和进程观察不应展开为重复的模型工具调用。

## 验收条件

- [ ] **AC-1 通用命令执行**：Agent 能通过公共能力运行项目已有的确定性本地脚本或测试命令，并取得包含退出码、输出、持续时间、截断状态和终止原因的真实结构化结果；能力不依赖为被测程序开发专用 Tool。
- [ ] **AC-2 结构化执行边界**：命令、参数、运行时解析后的规范化工作目录和受控环境被明确表达并校验；工作目录无论由 Agent 指定还是由产品默认提供，都在审批与结果中保持一致。无效程序、无效目录、启动失败和不支持的平台能力均返回稳定错误，不冒充命令成功。
- [ ] **AC-3 现有授权链路复用**：命令审批复用现有会话与 run 绑定、批准、拒绝、超时、取消、失活恢复、前端推送和历史终态；代码和产品交互中不存在独立于公共授权控制面的平行审批系统。
- [ ] **AC-4 仅本次授权**：用户可以查看命令、参数、实际工作目录、目的和关键风险后拒绝或仅本次允许；批准不能跨原始会话、run 或实质变化后的命令复用，拒绝和失效后不会启动进程。
- [ ] **AC-5 授权等级扩展边界**：授权契约能够明确区分资源、动作、作用域和生命周期；第一版只开放仅本次，未实现的 turn、session 和持久等级不可选且 fail-closed，现有文件审批行为保持兼容。
- [ ] **AC-6 长任务无模型忙轮询**：一个持续至少 10 分钟的确定性本地测试命令可以在 Agent 不进行固定周期状态查询、也不因普通进度输出反复调用 LLM 的情况下运行至终态；模型调用 trace 或等价证据能证明等待期间不存在秒级模型轮询。
- [ ] **AC-7 独立进度与及时终态**：长命令运行期间，当前会话可以在不恢复模型的情况下收到有界进度；命令完成、失败或取消后，运行时及时形成终态并只用必要的合并结果恢复 Agent。
- [ ] **AC-8 交互式进程**：对仍活跃且归属匹配的前台进程会话可以写入真实交互输入并取得后续结果；结束、失活或归属不匹配的会话拒绝输入，且交互接口不会被固定周期模型轮询使用。
- [ ] **AC-9 取消、超时与进程树清理**：用户取消、Agent 取消、超时和运行时关闭产生可区分结果，并通过确定性测试证明受治理的子进程树不会在执行结束后残留；第一版不存在 detach 旁路。
- [ ] **AC-10 环境与能力隔离**：未经允许的宿主敏感环境不会传入命令；文件、网络和其它高风险能力不能超出声明并批准的范围，无法落实隔离时命令 fail-closed 且诊断准确。
- [ ] **AC-11 输出与上下文上限**：持续输出、大输出和二进制或不可解码输出不会导致无界内存、日志或模型上下文增长；结果准确标记截断并保留退出状态和必要诊断。
- [ ] **AC-12 Skill 内容身份**：Skill 脚本执行绑定当前 run 已加载的 Skill 内容身份；加载后替换文件、链接逃逸或内容变化不会静默执行另一份脚本，builtin、个人和共享个人 Skill 均不能获得私有执行旁路。
- [ ] **AC-13 产品自带 Codex 依赖**：正式 Windows 安装后的命令能力在机器没有用户级 Codex、用户未登录 Codex、PATH 不含 Codex 的情况下可用；存在用户自己的其它 Codex 版本与配置时，产品仍使用隔离且固定的受治理版本。
- [ ] **AC-14 供应链失败关闭**：被携带依赖的版本、来源、许可证和完整性可追溯；缺失、篡改或版本不匹配会在启动命令前被拒绝，且运行期不会静默下载或切换版本。
- [ ] **AC-15 跨平台边界**：Windows、macOS 与 Linux 源码运行入口共享相同工具和结果契约；正式安装包 AC 首期只要求 Windows，未交付的平台安装包不会被描述为已支持。
- [ ] **AC-16 冻结运行时验证**：Windows 冻结 runtime 中使用无网络、无真实 LLM、无 MAA 的确定性 fixture 实际完成命令启动、输出、退出、长等待、取消和 Skill 脚本身份高风险路径；源码环境测试不能替代该证据。
- [ ] **AC-17 回归与项目门禁**：批准、拒绝、超时、失活、命令注入边界、目录与链接逃逸、环境泄露、网络与文件能力、输出上限、交互输入、取消清理、依赖完整性及多会话归属均有针对性自动化测试，且项目完整检查门禁通过。
- [ ] **AC-18 全局沙箱能力状态**：Windows 沙箱未初始化、可用和需要修复的状态由全局设置统一展示和操作；一次成功初始化可被其它会话复用，普通命令不会隐式触发 UAC，初始化成功也不会自动批准任何待执行命令。
- [ ] **AC-19 沙箱内真实网络能力**：在宿主网络与受治理代理可用时，经过公共命令 Tool、产品 Codex exec-server 和 Windows 沙箱的 network-enabled 命令能够完成实际 DNS、连接和 HTTPS 数据交换；network-disabled 仍然拒绝访问。Winsock、代理、证书或外部服务失败必须形成可区分诊断，不能仅以 `process/start` 成功判定网络通过。
- [ ] **AC-20 Skill 安装完整旅程**：builtin Skill 安装器可以从公开 GitHub 仓库安装一个标准测试 Skill 到隔离的个人 Skill 根，并在不重启应用的情况下由 catalog 发现；执行使用当前 run 的不可变 Skill 快照和包内工作目录，不要求 Agent 猜测产品内部绝对路径。自动化回归使用受控 fixture 固定机制，最终公开仓库 smoke 不绑定 MAA 业务逻辑。
- [ ] **AC-21 无工作区命令旅程**：在会话没有项目、没有用户所选文件夹且 Agent 未提供工作目录时，公共命令 Tool 仍能在产品提供的安全默认目录中运行允许从受控 `PATH` 解析的确定性 CLI。默认 `cwd` 只获得审批中明确展示的最小只读权限，写入及其它宿主路径必须另行申请；宿主路径不存在、未授权、沙箱不可见和程序解析失败具有可区分的模型结果、历史终态和用户可见诊断。
- [ ] **AC-22 宿主用户执行级别**：可信桌面程序可以通过公共命令 Tool 的 `host_user` 级别以当前桌面用户身份启动；请求必须使用结构化 `argv`，复用一次性审批并展示文件系统、网络和环境均不受沙箱限制。未批准、使用 shell 字符串、伪造受限 `access`、绑定 Skill 或从普通沙箱静默降级均失败关闭；该请求不被 Windows 沙箱 readiness 错误拦截。
