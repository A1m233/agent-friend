# 受治理的通用本地文件工具

## 状态

CONFIRMED

## 背景

agent-friend 当前没有面向 Agent 的通用本地文件能力。Agent 无法在任务需要时自行查找本地文件，也无法读取任意用户文件或 Skill 包内按需引用的 `references/`、`assets/` 等资源；创建、编辑、移动和删除本地文件同样不可用。

这个缺口已经由 [issue 044](../../issues/044-agent-general-filesystem-mutation-tools/README.md) 登记，并直接限制 [需求 076](../076-agent-skill-system/) 中 builtin `skill-creator` 及其它依赖本地资产的 Skill。只给 Skill 系统增加私有文件接口会形成绕开统一权限与审计边界的特权旁路，因此需要补齐一套所有 Agent 工作流都能复用的公共文件能力。

agent-friend 的普通会话不要求用户预先选择 workspace。文件能力需要保持这种低门槛体验：会话在没有任何用户文件权限时也能正常工作；当任务确实需要本地文件时，由 Agent 自行判断目标和最小必要范围，向用户发起可理解的临时授权请求，而不是把查找路径和管理 workspace 的工作提前交给用户。

Agent 有时只知道文件名、用途或大致位置，并不知道准确绝对路径。此时系统还需要提供受治理的文件发现能力，使 Agent 能先在合理范围内自行查找目标，再对准确目标申请内容访问或变更权限。查找能力本身不能暗中退化为无边界的全盘内容读取。

## 目标

- 让普通会话在默认无用户文件权限的前提下正常工作，并在任务需要时由 Agent 主动申请最小必要的临时文件权限。
- 让 Agent 在不知道准确路径时能够自行申请并执行有边界的文件查找，不要求用户先选择 workspace 或手动浏览文件夹。
- 提供所有 Agent 工作流和 Skill 可复用的目录查看、文件读取、文本编辑与常用文件变更能力，不为单个 Skill 建立特权旁路。
- 让授权请求清楚展示访问位置、权限类型、操作原因及破坏性动作，使用户能够明确允许或拒绝。
- 让授权请求始终归属于发起它的会话：当前会话可以在任务上下文中处理，后台会话能够被发现并导航返回，不用全窗口模态交互打断其它会话。
- 让临时授权、路径边界、链接与目录穿越、并发修改、原子落盘、内容体积和结果真实性形成统一、可测试的安全契约。
- 使 `skill-creator` 能够通过公共文件工具按需读取 Skill 包资源，并在用户授权后创建或维护个人 Skill 文件；仍需命令执行的步骤继续如实报告现有能力缺口。
- 能力随产品运行时交付，不要求用户另行安装 Python、Node.js 或其它命令行工具。

## 范围

### 包含

#### 无 workspace 会话与按需授权

- 普通会话可以在没有用户 workspace、项目或文件夹授权的情况下创建并正常对话。
- 默认状态下，Agent 不能枚举、搜索、读取或修改任意用户文件。
- 当 Agent 已知目标位置时，可以对指定文件或最小必要目录主动申请只读或读写权限，并说明当前任务为什么需要该权限。
- 桌面端以审批交互展示规范化后的实际位置、请求权限和原因；用户可以选择拒绝或仅本次允许。
- 第一版只支持仅本次授权。授权在当前用户轮的完整操作链中可以复用，使读取、修改和结果验证能够连续完成；当前用户轮结束后自动失效，不能跨轮、跨会话或永久保留。
- 用户拒绝、授权范围小于请求范围或授权在使用前失效时，Agent 得到明确的结构化结果，并据此停止、缩小请求或采用其它合理方案，不能把请求过权限表述成已经完成文件操作。
- 用户不需要通过文件夹选择器建立 workspace。只有 Agent 无法形成任何合理搜索范围、用户主动选择文件，或用户希望用拖放、选择器提供目标时，才把这些交互作为补充入口。

#### 会话内审批与后台关注状态

- 文件授权请求在发起它的会话中、对应工具调用的运行位置展示为授权卡片，不使用覆盖整个聊天窗口的全局 Dialog。
- 授权卡片展示规范化后的实际位置、权限、原因和破坏性动作；删除、覆盖、移动等危险操作在卡片内使用更醒目的风险表达，但第一版不再叠加第二层全窗口确认。
- 当前正在查看其它会话时，后台会话的新授权请求不能抢占或遮挡当前界面；对应会话在侧边栏持续显示可点击的“等待授权”状态。本期不额外产生应用内弹出提醒。
- 点击侧边栏状态后回到原会话，并在原工具调用位置处理请求。多个会话可以各自存在未决授权，任何批准或拒绝都只能作用于其原始会话和 run。
- 切换会话、刷新页面或短暂断连时，只要原 run 和授权请求仍然活跃，返回原会话后就恢复同一授权卡片。请求超时、run 取消、用户拒绝或批准后，卡片准确进入对应终态。
- 桌面运行时或 Bridge 重启、原 run 已结束或原请求已不在等待时，旧卡片只能显示“已中断”或“已失效”，不能继续批准；用户重新发起任务后，由 Agent 根据当时状态产生新的必要审批。
- 已处理的授权卡片在会话中保留精简结果，帮助用户理解后续 Agent 行为；历史卡片不可再次操作，也不能恢复或延长已经失效的权限。

#### Agent 主动文件发现

- Agent 不知道准确路径时，可以根据任务线索选择合理的搜索区域并主动申请仅本次搜索权限。
- 系统可以向 Agent 提供不泄露用户路径实现细节的标准位置，例如当前用户目录、桌面、文档、下载目录和当前已激活 Skill 的资源范围；审批界面向用户展示解析后的真实位置。
- 搜索请求至少支持按文件名和相对路径查找文件或目录，并返回有界、可继续获取的匹配结果。
- 仅获得搜索权限时，Agent 只能取得定位所需的名称、路径、文件类型和必要元数据，不能读取匹配文件的正文。
- 需要按正文查找时，Agent 必须先获得对应搜索区域的读取权限；找到目标后，修改仍只对准确文件或最小必要目录另行申请读写权限。
- 搜索范围不能因为没有结果而自动扩大到用户主目录之外、其它磁盘或系统目录；扩大范围需要新的、清楚展示的授权请求。
- 当前已激活 Skill 的只读资源范围可以直接用于查找和读取该 Skill 明确引用的包内资源，不借此获得包外用户文件权限。

#### 通用文件读取

- 提供目录列举、路径状态查询和文本文件读取能力。
- 文本读取支持按范围获取和继续读取，使大文件不会无界进入模型上下文；结果明确说明是否截断及如何继续。
- 文件类型、编码或体积不受支持时返回明确诊断，不能用乱码、空结果或不完整内容冒充完整读取。
- 二进制文件首期只提供类型、大小等必要元数据，不把任意二进制内容直接注入模型上下文。
- Skill 附加资源通过同一公共读取能力按需访问，不因 Skill 已激活而预加载整个目录。

#### 通用文件变更

- 提供创建目录、创建文本文件、对既有文本应用补丁、复制、移动、重命名和删除文件或目录的公共能力。
- 文本编辑以可检查的变更表达为主，成功结果能够说明实际修改的目标和摘要；匹配失败、内容已变化或目标冲突时不静默覆盖。
- 创建或替换文本文件时采用安全落盘语义，失败不能留下被截断的目标文件或伪装成完整成功的半成品。
- 复制、移动和删除支持文本及二进制文件；对二进制文件执行这些操作时保持字节内容不变。
- 删除、覆盖、跨目标替换等破坏性动作必须在授权请求中明确展示实际动作和目标，不能把宽泛的“允许修改”静默扩大成用户未看到的删除或覆盖。
- 批量操作能够区分全部成功、部分成功和失败项，并提供可审计的结构化结果。

#### 文件作用域与安全边界

- 每个文件工具调用都必须绑定当前仍有效的授权或产品授予的只读能力范围；不能仅凭模型提供的任意绝对路径访问磁盘。
- 授权只能覆盖请求中展示并由用户允许的范围。用户批准子集时，未批准路径保持不可访问。
- 路径规范化、相对路径解析、父目录跳转、符号链接、Windows junction 或其它目录链接都不能使操作逃逸已授权范围。
- 系统自有会话、记忆、凭据、设置、日志和其它受保护产品数据不因其位于某个已授权父目录内而自动变得可读写。
- 项目或 Skill 中承载 Agent 指令、权限和工具配置的受保护元数据不因父目录可写而自动可变更；确有当前任务需要时，必须对准确目标和实际动作显式授权，builtin 资源始终不可写。
- 权限检查覆盖操作开始与实际落盘时的目标，防止目标在授权后通过链接替换、重命名或其它竞态逃逸边界。
- 工具结果区分成功、拒绝、越界、不支持、目标已变化、部分失败和内部错误，使 Agent 能基于真实状态继续工作。

#### Skill 与多入口一致性

- builtin、agent-friend 专属个人和共享个人 Skill 都使用同一套公共文件工具和权限模型；来源是 builtin 不代表自动获得用户文件写权限。
- 已激活 Skill 的包内资源以只读能力范围提供；Agent 仅在 Skill 指引或当前任务需要时按需查找和读取。
- 创建或维护个人 Skill 时，Agent 对准确的新 Skill 目录或待修改目标申请权限，不要求用户先把整个个人 Skill 根设置为 workspace。
- 桌面端与普通 OpenAI-compatible 对话入口使用同一文件工具执行和结果语义。无法承载本地审批交互的入口遇到新权限请求时，明确提示需要在桌面端继续，不默认批准或扩大权限。
- 以 builtin `skill-creator` 作为端到端兼容样例之一：Agent 能读取其必要包内资源，并在仅本次授权下创建或修改个人 Skill 的文本资源；需要执行脚本时仍明确报告 [issue 045](../../issues/045-governed-command-and-skill-script-runtime/README.md) 所跟踪的命令能力缺口。

#### 跨平台、运行时与诊断

- 文件作用域、标准位置、路径展示、链接处理和文件操作在 Windows、macOS 与 Linux 上遵循一致的产品语义，并正确处理平台路径差异。
- 文件工具依赖由 agent-friend 的开发和冻结运行时统一提供，用户使用能力时不需要自行安装 Python、Node.js、ripgrep 或其它系统工具。
- 开发环境和冻结 Windows runtime 均能执行本需求的核心文件能力；打包缺失依赖、资源或动态导入时必须在交付验证中暴露。
- 诊断信息能够区分权限请求、用户决定、实际授权范围、文件操作结果和安全拒绝，但不在普通日志中记录用户文件正文、凭据或不必要的敏感内容。
- 核心路径规范化、临时授权、文件发现、读写、链接逃逸、并发变化、原子落盘、破坏性动作和错误结果均具有确定性自动化测试。

### 不包含

- 创建会话前强制用户选择 workspace、项目或文件夹。
- 跨用户轮、跨会话或永久保存文件权限，以及权限管理中心、常用 workspace 和项目级持久目录管理。
- 默认读取用户主目录、全盘搜索、自动遍历所有磁盘或在搜索失败后静默扩大授权范围。
- 通用 shell、CMD、PowerShell、终端、本地进程或任意 Skill 脚本执行；这些能力继续由 [issue 045](../../issues/045-governed-command-and-skill-script-runtime/README.md) 跟踪。
- 依赖用户自行安装 Python、Node.js、ripgrep 或其它命令行运行时才能使用的实现。
- 解析、编辑或生成图片、音频、视频、压缩包、Office、PDF、数据库等二进制格式的内容；首期只保证其复制、移动、重命名和删除不改变字节内容。
- 文件版本历史、云盘同步、协同编辑、回收站恢复、备份或通用文件管理器 UI。
- 绕开公共权限模型的 Skill 私有读取、写入或 authoring service。
- 因 Skill 是 builtin、官方提供或已激活，就自动执行其脚本或扩大其用户文件权限。
- 自动批准权限、长期记住用户决定或以模型判断替代用户的本次审批。
- 应用内弹出提醒、系统级通知、通知中心或操作系统后台提醒；第一版只提供侧边栏待处理状态。后续提醒渠道不得改变审批的会话与 run 绑定语义。

## 关键信息

### “仅本次”的口径

- “当前用户轮”包含一次用户输入，以及生成该次最终回答前发生的模型续轮、文件查找、读取、变更和结果验证。
- 同一授权只在该轮内、原始批准范围内复用；不会因为后续工具调用属于同一轮就扩大路径、权限类型或破坏性动作。
- 用户发起下一条消息、当前轮取消或会话结束后，授权自动失效。

### 搜索与内容访问的口径

- “搜索权限”只允许取得定位目标所需的文件名、相对路径、类型和必要元数据；文件名和路径本身也属于用户数据，必须经过本次审批后才能返回给 Agent。
- “读取权限”允许在批准范围内读取受支持的文本内容，并可用于正文搜索。
- 搜索结果不是后续修改授权。Agent 找到目标后，仍需对准确目标申请并获得所需读写权限。

### 公共文件能力与 Skill 的关系

- Skill 负责说明任务工作流和何时需要文件；公共文件工具负责统一执行、权限、安全和审计。
- 激活 Skill 只自动提供该 Skill 包自身的只读能力范围，不提供用户目录权限，也不提供命令执行能力。
- 本需求闭环 issue 044 所描述的公共文件能力缺口，但不宣称完整闭环 `skill-creator`；其确定性脚本仍依赖 issue 045 的后续命令运行时。

## 验收条件

- [ ] **AC-1 无 workspace 会话**：未选择项目、workspace 或用户文件夹时，普通会话能够正常创建和对话；Agent 尝试搜索、读取或修改用户文件时不会获得默认磁盘访问。
- [ ] **AC-2 已知目标的仅本次审批**：Agent 对准确文件或最小必要目录发起包含规范化位置、权限类型和原因的请求；桌面端允许用户拒绝或仅本次允许，拒绝后不执行文件操作。
- [ ] **AC-3 临时授权生命周期**：批准的权限可供当前用户轮内的读取、修改和验证链路复用，但不能扩大到未批准路径或动作；下一用户轮开始后同一访问需要重新审批。
- [ ] **AC-4 Agent 主动发现**：Agent 不知道准确路径时，能够自行选择标准位置或其它合理范围并请求搜索权限；批准后可按名称或路径取得有界匹配结果，不要求用户手动选择文件夹。
- [ ] **AC-5 搜索与内容隔离**：仅批准搜索时，结果只包含定位元数据而不包含文件正文；正文搜索或文件读取需要相应读取权限，修改搜索结果需要对准确目标取得读写授权。
- [ ] **AC-6 通用读取**：在有效只读或读写范围内，Agent 能列举目录、查询路径状态并分段读取受支持的文本文件；截断、编码不支持、二进制和体积边界均有明确结果。
- [ ] **AC-7 文本创建与编辑**：在有效授权内，Agent 能创建目录和文本文件、对既有文本应用可检查的补丁，并在内容已变化、匹配失败或目标冲突时拒绝静默覆盖；失败不破坏原文件。
- [ ] **AC-8 复制、移动与删除**：在明确展示实际动作和目标并获得授权后，Agent 能复制、移动、重命名和删除文件或目录；二进制文件经复制或移动后字节一致，批量操作准确报告部分失败。
- [ ] **AC-9 路径逃逸防护**：绝对路径注入、`..`、符号链接、Windows junction、链接替换和重命名竞态均不能使搜索、读取或变更逃逸批准范围；安全拒绝具有稳定诊断。
- [ ] **AC-10 受保护路径**：产品会话、记忆、凭据、设置、日志、builtin 资源及受保护 Agent 元数据不会仅因父目录获批而自动可读写；允许的精确例外仍受本次审批和实际动作约束。
- [ ] **AC-11 Skill 公共能力闭环**：已激活 Skill 可以按需查找和读取自身包内资源；builtin `skill-creator` 能使用同一公共文件工具，在仅本次授权后创建或修改个人 Skill 文本资源，没有私有文件旁路，且需要脚本时如实报告命令能力缺口。
- [ ] **AC-12 多入口失败语义**：桌面端和普通 OpenAI-compatible 对话入口共享文件工具执行结果；不能展示本地审批的入口遇到新权限请求时不会默认批准，并明确提示转到桌面端继续。
- [ ] **AC-13 无用户依赖安装**：开发态和冻结 Windows runtime 均能完成核心搜索、读取和文件变更流程，最终用户无需另行安装 Python、Node.js、ripgrep 或其它系统工具。
- [ ] **AC-14 回归与门禁**：无文件授权、拒绝授权、权限失效、查找、读取、编辑、二进制搬运、路径与链接攻击、并发变化、原子失败、受保护路径和 Skill 集成均有确定性测试，且项目完整检查门禁通过。
- [ ] **AC-15 会话内审批与后台恢复**：当前会话的授权请求在对应工具调用位置以内联卡片展示，不以全窗口 Dialog 打断操作；切到其它会话后，原会话在侧边栏持续显示可点击的待授权状态，返回后仅在原 run 与请求仍活跃时恢复处理；多个会话的请求互不串联，批准、拒绝、超时、取消和运行时失活均形成不可复用的准确历史终态，失活请求必须通过新任务重新申请。
