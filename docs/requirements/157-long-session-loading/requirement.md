# 157 · 长会话加载与执行冷恢复治理

## 状态

CONFIRMED — 2026-10-08 用户确认编号与需求范围，并明确本期不新增“取消加载”入口。

同日用户确认扩大范围：在历史展示治理之外，纳入发送前的执行冷恢复及可复用状态的持久化缓存。

2026-10-09 用户指出已合入实现破坏原有展示，确认按普通 fix 完整撤回事件碎片和逐条正文加载交互，
恢复原消息/工具样式；打开会话只取最新一页，向上滚动加载旧页。执行恢复缓存保持独立。

用户已确认技术方案并授权开始实现；方案见 [design.md](./design.md)，实施状态见 [progress.md](./progress.md)。

## 背景

Windows 安装版打开已有长会话时，用户长时间看到加载状态。本次只读诊断定位到一个约
1.22 GB 的历史文件，内部运行记录占主要体积。一次会话详情请求耗时约 37.5 秒；读取期间
恢复程序追加状态，使正在构建的查询结果无法进入缓存，随后发生再次读取。接口成功返回后，
目标会话实际何时完成界面呈现仍缺少证据，用户已切换到其他会话。

此前 122 已实现分页与运行态复用，但保留了首次查询未命中时全量扫描历史的边界；145 改善
了内存与新增存储增长，仍保留冷恢复和旧大文件治理的缺口；146 的召回与发送优化不等于
聊天历史展示已解决。本需求承接这些剩余问题，不把此前阶段交付改写为全部验收通过。

用户进一步指出重启后的首次准备仍慢，热运行后明显缩短。源码确认执行态驻留时复用内存状态，
冷路径仍从持久日志重建模型历史和上下文。现有 rollout 已保存模型状态，但读取与校验仍依赖
历史提交链。该机制支持优化方向，不等于已测得本次实际发送前等待的全部原因。

诊断事实、源码身份、既有需求及局限统一见 [evidence-index.md](./evidence-index.md)。

## 目标

1. 用户打开已有长会话时，能够及时看到当前需要的历史内容，较早或较大的内容仍可完整查看。
2. 让历史展示承担与当前浏览需要相称的工作，减少重复全量处理，避免浏览必须等待无关的执行准备。
3. 在多会话切换、历史增长和后台恢复并发时，合理复用仍有效的读取结果，保持内存与派生数据有界。
4. 加载中切换会话、失败后重试均有明确结果，不让旧响应覆盖当前会话或遗留无终点的加载状态。
5. 用可复查的分阶段证据说明改善、成本及剩余问题，并以真实桌面体验完成验收。
6. 重启后能够复用与当前历史一致、已经验证的执行恢复结果，减少首次发送前重复解析和重建；
   保持发送时所需动态事实和运行时校验的新鲜度。

## 范围

### 包含

- 手动打开历史会话及启动后恢复上次会话，从发起读取到历史首屏呈现的完整链路。
- 原始历史读取、内部记录处理、恢复依赖、查询构建与缓存、接口传输、前端投影与呈现的工作量盘点。
- 首次打开、重复打开、多条长会话交替访问、原始历史追加或改写后的正确失效与恢复。
- 加载较早历史、搜索和引用定位等共享历史展示能力的入口，防止优化被全量读取旁路绕过。
- 单个用户回合包含大量工具调用或输出的场景；分页轮数较少不自动等于工作量较小。
- 后台恢复、追加和其他读取与会话打开并发时的正确性及重复工作治理。
- 现有切换、加载提示和失败重试行为；不新增独立取消加载按钮。
- 已有大历史与新增历史的兼容验证、资源成本及可重复性能观察。
- 发送前执行态冷恢复、可复用恢复结果的持久化及其来源证明、失效回退和资源成本。
- 无派生缓存首次准备、进程重建后命中持久缓存、同进程驻留热复用三类状态的独立验证。

### 不包含

- 安装文件完整性校验、窗口创建顺序、启动进度界面以及后端启动任务的编排优化。
- 重做模型推理、记忆质量、人格、工具能力或全产品性能治理。
- 供应商服务端 prompt cache、推理或网络提速；直接缓存整份最终发送请求并跳过当次动态准备。
- 将删除历史、截断可见内容、取消已有执行任务或放宽恢复校验作为提速手段。
- 自动改写、压缩或清理真实用户原始会话；旧文件物理维护不作为打开会话的前置要求。
- 默认构建或覆盖安装包、替换正在使用的安装版、发布版本或调用外部计费模型。

## 需求

### R-1 可归因的加载盘点

明确历史读取、执行恢复、查询构建、传输与界面呈现的边界，关联同一次打开操作和实际运行身份。
区分应用启动、首次会话读取、暖访问、切换及后台并发；不将长连接存活时间或全局启动里程碑
直接当作指定会话的加载时间。缺少客户端证据时保留未知。

### R-2 旧大历史的有效展示

无需用户清理旧历史，即可获得当前需要的内容。历史展示不应为未使用的内部运行记录承担
不必要的完整处理；仅浏览历史不必等待无关的执行准备。继续发送或执行时仍须完成必要校验。

首次准备派生状态与后续复用分别计量，不能用预热后的单次结果代替首次打开，也不能以隐藏
后台全量工作代替真正消除重复工作。

### R-3 正确且有界的复用

未变化的历史和仍有效的结果应合理复用。交替访问多条大历史，不应反复承担等价的完整处理。
历史追加、编辑重发、恢复补写、外部文件变化和损坏必须得到正确处理；必要重建可观测、可解释。

保持已有活跃与闲置资源边界，不能通过无限增大缓存换取表面提速，也不能因浏览切换中止后台任务。

### R-4 大回合与历史导航

打开会话只请求最新一页，向上滚动沿用既有交互逐页补充较早内容并保持阅读位置。
有效持久索引直接读取所需页，不先读取全部正文再截取。无索引或索引失效的重建成本单独记录。

恢复原有整轮消息、工具分组、执行过程折叠、正文、操作栏和间距；不增加逐条正文加载按钮、
占位卡片或额外的“加载较新消息”入口。分页不把同一回合拆成独立消息。大回合保留完整内容，
轮数限制不承诺固定字节上限。搜索和引用缺页时逐页定位，复制使用已完整加载的原消息语义。

### R-5 切换与失败的收口

加载中能够切换到其他会话；旧读取结果不能覆盖当前选择或留下永久加载状态。失败应明确展示，
用户能通过现有交互重试。浏览行为与 Agent 执行取消分离，本期不新增取消加载入口。

### R-6 正确性与兼容

新版本可读取已有数据。展示及执行恢复优化不改变权威执行状态、审批、模型配置、工具副作用事实、
当前有效上下文或既有损坏恢复边界。派生状态丢失、陈旧、损坏或维护中断时，原始历史仍安全，
系统能够重建或明确失败，不伪装成空历史。

执行恢复缓存还须保留原始历史完整性验证的效果；不能只依据时间戳、文件长度或最后一条提交
就跳过旧前缀的损坏检测。进程内对象、持有中的锁、客户端连接和正在执行的任务不能被当作
跨进程可直接复活的缓存事实。

### R-7 分层验证与体验验收

使用短、普通、固定 GB 级旧历史、多个长会话及长工具回合样本，覆盖冷暖访问和并发状态变化。
记录精确版本、样本身份、缓存条件、重复次数、阶段耗时、读取与重建工作量、传输规模、内存及
派生磁盘成本。固定样本采用隔离副本；真实用户原始数据不作为可修改的测试夹具。

本期不预设固定秒数门槛。以消除重复工作、正确复用、失败可恢复和同条件下实际体验改善作为
判定依据；收益与回退均报告，不凭单次最快结果宣称通过。自动化正确性、源码运行态、安装态
接口和真实桌面呈现各自保留证据边界，由用户确认体验验收完成。

历史首屏与发送前执行准备分别测量。执行准备覆盖无缓存、重启后持久缓存命中、进程内热复用，
将来源验证、执行恢复、动态上下文装配、持久化维护以及本地发起 provider 请求的边界分开。
缓存建立和更新成本也进入对账，不能把冷恢复等待全部转移到每次发送或结束后再宣称整体改善。
fake provider 可验证机制及本地准备，不等于真实供应商收到请求或给出首个输出。

### R-8 可复用的执行恢复状态

将可复用且已经验证的模型历史、有效事件身份、摘要与上下文恢复状态作为独立于展示索引的
派生能力。进程重启后，在能证明与原始历史、提交及恢复语义版本一致时复用，减少重复解析、
校验计算及重建；不能以复用名义绕过原始历史损坏检测。

原始持久化仍是权威事实。缓存不存在、来源不一致、内容损坏、格式或恢复语义不兼容时，安全
回退到现有可信恢复或明确失败；不把恢复失败变成空会话，不错误提升为可精确续接。
缓存创建、更新失败或中断不能改变原始保存结果，也不能造成重复业务追加或工具副作用。

### R-9 发送时动态事实与执行边界

恢复快照不等于当前完整发送上下文。发送时仍核对并更新时间、入口与工作区状态、权限、Skill
与工具能力、模型和连接配置、新输入相关的记忆召回、附件有效性、预算及未决工具状态。
展示索引和执行快照可以复用来源验证设施，但不能互作权限、模型上下文或恢复资格的真相。

保持单写者约束和执行前源版本核对；获取执行所有权后仍须处理必要的工具事务恢复。只恢复
可验证的纯状态，不恢复旧进程的资源所有权，不自动重放已执行副作用。

## 与启动优化工作的边界

本需求拥有历史展示读取、发送前执行冷恢复及其缓存机制，以及启动后恢复上次会话所复用的加载能力。启动优化工作
拥有安装校验、窗口出现与进度、后端启动编排和附件引用扫描时机。共享读取模块只能形成一套
一致方案；本需求测量后台竞争对加载的影响，不据此自动接管启动编排。完成后复测完整启动，
将随共享能力改善的部分与独立启动耗时分开报告。
