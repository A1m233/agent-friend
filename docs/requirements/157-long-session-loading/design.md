# 157 · 长会话加载与执行冷恢复治理 — 技术方案

## 状态

CONFIRMED — 用户确认展示索引、执行恢复快照、动态事实刷新、维护成本及分别验收的方案，并授权开始实现。

## 需求文档

[requirement.md](./requirement.md)；事实及观测局限见 [evidence-index.md](./evidence-index.md)。

## 现状分析

历史详情先通过 SessionStore 构造业务快照，再按用户回合分页。读取仍解码整个 JSONL，
内部 rollout 记录在业务过滤之前完成恢复工作。运行态查询缓存无法跨进程复用，读取期间
源文件追加可能使结果失效。单回合可以包含大量工具调用，因此轮数限制不构成字节或呈现上界。

SessionManager 的执行热路径复用驻留状态，冷路径通过 load_execution 扫描并验证完整提交链。
已有 rollout commit 可以引用更早的 transcript item，不能把最后一条 commit 当作独立检查点。
模型历史恢复后仍需重新装配当次动态上下文，并持有当前进程的执行所有权。

正常 runtime 完成先保存 terminal rollout commit，之后还会持久化 run_terminal。
缓存发布时机必须覆盖最终持久状态，不能在 rollout commit 后马上发布已过期快照。

## 方案设计

### 所有权与模块

| 区域 | 职责 |
| --- | --- |
| agent/sessions/business_index | 可丢弃的持久业务索引、增量更新、有界查询与内容定位 |
| agent/sessions/store.py 及读取辅助模块 | 原始 JSONL 权威读写、来源版本、校验及派生状态失效 |
| agent/sessions/execution_cache | 精确来源执行恢复快照、格式版本与完整性检查、原子发布 |
| agent/sessions/manager.py、runtime 与 Conversation 完成入口 | 纯状态恢复、执行所有权和动态恢复、回合最终落盘后的缓存维护 |
| agent_bridge 会话路由 | 有界历史页、正文详情及定位协议；继续保留兼容消费者 |
| frontend 会话 API、history store 与消息呈现 | 增量页适配、延迟正文、稳定消息片段和请求生命周期 |
| scripts 及相邻 tests | 隔离夹具、分层计时、确定性回归与项目门禁 |

不新增第三方依赖。派生数据放在现有 sessions 数据根下的独立隐藏子目录，由 SessionStore
统一管理；用户配置及日志继续使用既有 owner。禁止把新缓存放入仓库或复用桌面设置文件。

### 业务索引

原始 JSONL 始终是权威。每个会话维护可独立删除和重建的 SQLite 业务索引，包含格式版本、
来源身份及版本、有效业务事件、事件稳定身份与顺序、分支失效信息、页面边界及正文定位。
持久索引使用既有 SQLite 能力，不复用只存召回文本的 RecallIndex 充当展示真相。

首次缺失索引需要一次可信扫描。只为展示读取时避免构造随后被丢弃的内部 rollout 大对象，
但不放宽原有损坏检测、事件验证和有效分支语义。旧的完整执行及诊断读取保持各自契约。

本进程已知追加在原始数据 fsync 成功后按实际追加内容更新索引；内部记录追加也需推进源版本。
rewrite、截断、来源身份不匹配或索引损坏时作废重建。索引维护失败不能改变原始保存结果。
跨线程与多进程依托已有写者边界和索引事务；不将多个查询启动成并行全量重建。
读取竞争时返回可证明一致的页或明确重试，不循环重新扫描 GB 文件直到追上写者。

query/load_business 复用同一业务索引；有界历史路由直接查询所需行，不能先把整个业务快照
装进内存再切页。其他消费者需要完整业务快照时保留兼容路径，但不承担内部运行记录重建。

### 历史页与延迟正文

历史入口支持 latest、before 和 around(event UUID)，带来源 epoch/content version、游标、
前后是否有内容等信息，同时限制条目数与序列化字节。改写导致 epoch 变化时旧游标明确失效。

页面保持稳定 message/run/block 身份及顺序。长 run 可以拆为连续消息片段，工具请求与结果
保持关联。正文显式区分 inline 与 deferred，不用空 payload 冒充完整事件。延期正文通过
版本绑定的内容引用分段取得；状态、错误、审批及交互必需的摘要事实随首屏提供。

前端保留既有消息、执行过程折叠与 live reducer。新适配器只处理新增历史页，未变化消息保留
对象身份；避免每次旧页追加重新投影全部历史。长执行片段进入虚拟列表时保持关联，操作栏
和状态头按逻辑消息展示。搜索和引用直接取目标窗口，避免全量 GET 或逐页回溯。

复制逻辑消息时先取齐既有复制语义要求的文本，然后一次写入剪贴板；失败不写半截文本。
详情读取失败保留现有内容并可重试。切换、关闭视图和 runtime 代际变化释放历史请求订阅，
最后订阅者退出时中止网络读取；仍核对请求身份，覆盖 A→B→A。此行为不取消后台执行，
不新增取消加载按钮。有效首响应可先呈现，后台刷新不能把它扣留到第二次查询完成。

### 执行快照及来源证明

第一版只接受与原始文件完全一致的独立纯状态快照，不实现跨版本尾部增量恢复。快照绑定
session、文件身份、原始长度、完整原始字节 SHA-256、快照格式和恢复语义版本，并验证
快照自身内容摘要。使用明确 JSON 序列化，不序列化锁、客户端、任务、进程或 pickle 对象。

首次完整可信恢复后可以产生候选；重启后命中时顺序读取全部原始字节计算摘要、核对来源，
省去 JSON 解码、提交链重放和模型状态重建。摘要不一致、文件变化、格式不兼容、快照损坏
或不能精确恢复时回退原有路径。不能只靠大小、mtime 或最后 commit 接受缓存，也不能将
恢复错误伪装为空会话或升级续接资格。缓存错误与原始损坏错误分别处理。

恢复后的模型历史、上下文与有效事件身份必须与可信完整恢复等价。获得当前执行 writer lease
后再核对源版本并按原有顺序进行未决工具事务恢复；快照不能自动重放副作用。权限、Skill、
工具、模型和连接配置、时间、入口和工作区、新输入的记忆召回、附件及预算继续当次刷新。
展示索引不能充当执行恢复资格、权限或模型输入的真相。

### 维护成本与最终落盘

原始数据完成最终持久写入后再捕获纯状态候选。runtime 路径在 run_terminal 成功追加后处理，
直接 Conversation/CLI 入口也需覆盖生成器完整结束后的状态。快照失败单独捕获，不能进入
run_terminal 保存失败分支或把成功执行变成失败。

快照临时写入后原子替换，只保留最新一份；发布前再次核对来源。下一任务已改变来源时
弃用旧候选，不反复全量重建。合并同一会话待发布工作，避免无界后台任务和磁盘增长。

为避免每轮重新读取 GB 文件，可信扫描或冷摘要验证可保留进程内 hash 状态，原始追加成功后
仅在前缀版本连续且尾部干净时对真实编码字节增量更新。外部变化、部分写入、rewrite 或其他
不确定情况使该状态作废；不把 Python hash 对象持久化。写入和冻结候选的耗时纳入验证。

### 观测与验证路径

历史操作关联导航、请求、服务端读取/索引、响应规模、客户端解码/投影及首屏提交；执行准备
分别计量来源校验、完整恢复或快照命中、动态上下文、维护及本地 provider 调用边界。
日志只记录身份、计数、版本和耗时，不输出消息内容或敏感上下文。

通过 fake provider 与隔离临时 sessions 根验证正确性；三种执行冷热条件和展示冷热条件
分别建样本。针对 rewrite、旧前缀损坏、时间戳/大小伪装、维护中断、并发追加、pending tools、
取消和归档删除补确定性断言。性能对照计入原始读取字节、解析事件数、索引/快照成本、
传输与内存；不得用单次最快值代替可比结论。

固定 GB 样本需从用户历史只读复制到隔离目录并绑定指纹，不修改原始历史。真实桌面验收
使用当前 worktree 对应的新鲜 runtime；源码、安装态服务端与桌面 UI 证据不能互相冒充。
真实 LLM 调用及现有用户 runtime 的生命周期不在本次实现授权中。

## 影响分析

冷命中仍有完整文件 I/O，因此收益需实际测量，不能承诺与进程内热复用同速。首建和重建仍
可能慢，必须可观测且不重复；若成本未达预期，应报告事实后讨论下一步，不放松完整性。

持久派生数据增加磁盘占用，须随会话删除/改写正确清理、按版本淘汰，保留原始数据可恢复。
新分页与延迟正文涉及全套历史消费者，必须同步搜索、引用、复制及 live/history 拼接。
UI 自动取消只影响浏览请求，不能传播到 Agent 执行取消。

实现不得修改 prompt 正文、身份公共契约或恢复语义；模型输入来源等价是回归约束。
冻结 runtime 影响在完成 diff 后按项目规则分类；本方案不引入动态导入、资源类型和原生依赖，
但若新增持久能力的高风险路径需要 frozen smoke，应补覆盖并运行相应门禁，不默认构建安装包。
