# 消息文本引用与跨通道统一引用

## 状态

CONFIRMED

## 背景

随着会话变长，用户只说“这句”“上面那个方案”或“你刚才提到的限制”时，Agent 很难稳定判断具体指向哪段内容。复制粘贴原文虽然能补足字面信息，却丢失来源角色、原消息和会话位置，也无法在历史中回到原文。

桌面文字对话需要提供类似 Codex 的精确文本引用：用户可以引用自己或 Agent 消息中的某段文字，并在同一条新消息中携带多个引用。QQ 用户也已经能在客户端使用平台原生引用；如果 QQ 通道不把引用信息交给 Agent，同一句“这个呢”仍会在跨通道时失去上下文。

本需求把“引用”定义为跨入口一致的会话语义，而不是某个界面的 Markdown 样式。桌面端和 QQ 只负责按各自能力产生引用，引用进入会话后使用同一套持久化、历史展示和 Agent 上下文语义。

## 目标

- 让用户能精确指出当前会话中某条用户或 Agent 消息的特定文本片段。
- 允许一条新消息携带多个引用，并允许不补充正文、只发送引用。
- 让引用在输入、发送后历史、会话重开和 Agent 上下文中保持一致、可追溯。
- 让桌面端文本选择和 QQ 客户端原生引用收束到同一引用能力，不形成通道专属提示词或第二套引用语义。
- 在来源或原文无法恢复时明确降级，不静默丢失引用，也不要求 Agent 猜测原文。

## 范围

### 包含

#### 桌面文字对话

- 用户可以在当前会话中选中一条已完成的用户或 Agent 消息里的连续可见文本，并执行“引用”。
- 引用范围只包含用户实际选中的消息正文；工具卡片、不可见思考、状态卡片和附件本体不混入文本选区。
- 一条草稿可以按添加顺序携带多个引用。新增引用不覆盖已有草稿或已有引用，每个引用都可以独立移除。
- 输入区把全部引用收束为一个紧凑的聚合入口；悬停、键盘聚焦或点击后展开浮层展示多条引用，至少能辨认来源角色和引用原文，并能独立移除其中任一条。
- 引用本身算作可发送内容；正文为空时仍允许发送。
- 发送后的用户消息继续展示其引用。长引用允许视觉折叠，但不得在 Agent 上下文或持久化事实中静默截断。
- 点击已发送的引用可以定位到原消息，并突出显示被引用的准确片段；原消息当前不可定位时给出明确的不可用状态。

#### QQ 原生引用

- QQ 本期按平台当前能力只接收单条完整消息引用，不把它伪装成桌面端多引用或精确文字片段引用。
- 在 QQ 平台向 Bot 推送了原生引用信息的私聊和群聊消息中，系统识别用户引用的原消息及可获得的原文。
- QQ 引用与用户本轮附加文字一起进入当前绑定会话；QQ 只发送引用、不附加新文字时也能形成有效用户输入。
- QQ 平台直接提供原文时使用该原文；只提供引用索引时允许通过可恢复的消息索引解析来源。
- 原文始终无法取得时保留“存在一条引用但原文不可用”的事实，并让用户和 Agent 都能区分该降级状态。
- QQ 引用进入会话后与桌面引用使用相同的历史展示和 Agent 上下文语义；之后从桌面端打开该会话时仍能看出引用关系。
- QQ 引用中附带的媒体类型和现有可用附件信息不被无声丢弃；本需求的核心引用验收仍以文本为主。

#### 统一引用语义

- 每个引用都能表达：引用原文快照、来源角色、来源消息以及在来源消息中的位置；具体数据结构由技术方案确定。
- 多个引用保持用户添加或平台提供的顺序。
- Agent 能明确区分引用内容和用户本轮正文，也能区分引用来自用户还是 Agent，不能把 Agent 原话误认成用户的新陈述。
- 引用关系随会话保存和恢复，不依赖当前前端内存或某次请求中的临时文本拼接。
- 通道 adapter 只负责提取平台引用并转成统一语义；会话持久化和 Agent 上下文投影不得为 QQ 另建平行实现。

### 不包含

- 在飞书、Telegram、微信等其它 IM 通道实现引用接入。
- 在语音通话中通过口语自动识别“引用哪一句”。
- 跨会话、跨联系人或跨 QQ 群引用消息。
- 引用工具卡片、不可见思考、提醒卡片或任意非消息正文 UI。
- 把普通 Markdown blockquote 或用户手写的 `>` 自动升级为带来源关系的引用。
- 改造 QQ 客户端自身的引用交互；QQ 是否支持多引用或精确片段选择服从平台能力。
- 改变 QQ Bot 出站回复是否自动引用用户消息的现有策略。
- 为引用媒体新增独立的图片理解、语音识别或文件解析能力。

## 关键信息

- 既有会话模型已经为消息提供稳定标识，早期 Session 需求也把“引用 / fork”列为消息标识的未来扩展方向。
- 当前桌面消息支持复制和最新用户消息编辑，但没有文本选区引用或结构化引用预览。
- 当前 QQ SDK 和入站事件已经保留引用消息所需的类型、消息元素和原始事件；现有 agent-friend 路径尚未把引用原文转成 Agent 可见上下文。
- 同类产品中，Telegram 已验证“选中精确片段 → 引用预览 → 点击回到原文并高亮”的交互；GitHub 和 Slack 的左侧竖线 blockquote 可作为视觉语法，但不能替代来源关系。

## 验收条件

- [ ] **AC-1 用户文本片段引用**：用户选中一条已完成用户消息中的连续文本并引用，输入区显示来源和准确原文。
- [ ] **AC-2 Agent 文本片段引用**：用户选中一条已完成 Agent 消息中的连续文本并引用，输入区显示来源和准确原文。
- [ ] **AC-3 多引用**：同一草稿可以加入来自不同用户 / Agent 消息的多个引用，顺序稳定；输入区以一个聚合入口承载全部引用，展开后可以独立删除任一引用而不改变正文和其它引用。
- [ ] **AC-4 纯引用发送**：正文为空、仅有一个或多个引用时可以发送并形成有效用户轮次。
- [ ] **AC-5 发送后展示**：已发送消息在正文上方或等价明确位置展示全部引用；长引用可折叠展开，视觉折叠不改变完整引用语义。
- [ ] **AC-6 回到原文**：点击已发送引用后定位到来源消息并突出准确片段；虚拟列表或长会话不导致定位到错误消息。
- [ ] **AC-7 会话恢复**：关闭并重新打开会话后，引用原文、来源角色、顺序和来源关系仍能恢复，已发送引用仍可展示和定位。
- [ ] **AC-8 Agent 指代理解**：当会话中存在相同或近似文本时，Agent 能基于结构化引用识别用户指向的具体来源和片段；多个引用不会被合并成无来源的一段普通用户文本。
- [ ] **AC-9 跨入口统一**：桌面端引用和 QQ 原生引用进入会话后使用相同的持久化事实与 Agent 上下文投影；QQ 路径没有独立拼接的通道专属引用提示词。
- [ ] **AC-10 QQ 文本引用**：在平台提供引用信息的 QQ 私聊和群聊场景中，用户引用自己或 Bot 的文本消息后发送，Agent 能获得引用原文和用户本轮文字，并能据此回答。
- [ ] **AC-11 QQ 纯引用与降级**：QQ 只发送引用时可以进入 Agent；当平台事件只含可解析索引时能恢复引用，当原文确实不可恢复时明确标记不可用且不让 Agent 猜测。
- [ ] **AC-12 历史互通**：从桌面端打开包含 QQ 原生引用的绑定会话时，能看出该用户消息引用了什么；平台限制不会被伪装成桌面端多引用或精确选区能力。
- [ ] **AC-13 既有行为不回归**：不带引用的桌面和 QQ 消息、消息复制、最新用户消息编辑重发、附件输入和普通会话恢复继续保持原有行为。
