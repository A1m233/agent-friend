# 118 · 长会话读取与可取消执行

## 状态

CONFIRMED

## 背景

长会话的打开、刷新、自动召回与任务准备目前会多次处理同一份完整会话记录。用户在取消回答时经历长时间等待，还出现准备阶段取消返回任务不存在、随后原任务仍继续启动的情况。

既有诊断确认了几类成本与控制缺口：不具备召回资格的当前会话在读取和排序之后才被排除；扩大候选范围会重新搜索；历史搜索使用的会话列表同时计算无关的模型配置；多个详情刷新入口重复加载；任务登记之前已有耗时准备，登记之后的部分准备步骤没有及时响应取消。116 已改善授权查询、单次详情内复用和读锁范围，本需求承接其尚未覆盖的读取与执行控制边界。

现场一次完整召回耗时 136.628 秒。恢复事故时会话文件前缀的离线实验耗时约 11.55 秒；提前排除不合格当前会话的对照约 0.94 秒，返回证据 ID 集合相同。这些结果证明了可消除的工作，但没有解释现场额外约 125 秒，也没有证明返回正文及顺序完全等价。证据来源、条件、修订与局限由 [证据索引](./evidence-index.md) 维护。

## 目标

- 会话增长后，浏览列表、进入会话、详情刷新和继续发送仍具有及时且可理解的反馈。
- 自动召回与显式历史查询减少与本次请求无关的读取及重复处理，保持有效证据与已有业务边界。
- 桌面文字任务从用户发起发送后即可表达并落实取消意图，准备、排队与运行各阶段的状态准确收口。
- 并发读取、追加写入、多窗口、切会话和重连不会造成重复工作失控、旧状态覆盖或跨会话污染。
- 以分阶段测量和前后对照支持方案取舍，区分已确认改善、未覆盖场景与尚未解释的现场耗时。

## 范围

### 包含

- 会话列表元数据、聊天详情、历史检索及任务准备中与完整历史读取相关的成本。
- 当前会话自动召回范围、显式查询范围与读取工作的对应关系，以及一次请求内的重复搜索。
- 同会话重复详情请求及其与运行终态、内容变更、切换和重连的协调。
- 桌面文字发送接纳前后的取消窗口，及共享引擎内历史恢复、记忆检索、上下文准备阶段的取消传播。
- 对共享读取能力的 CLI、语音、IM、后台任务等调用方进行兼容性检查；各入口的控制权限沿用既有约定。
- 长会话首次访问、读取辅助数据首次建立或失效恢复的反馈、可取消性和后续访问成本。
- 对聊天历史分页或逐步加载进行收益、实现复杂度、正确性和维护风险评估，在方案中明确采用或暂不采用的理由。
- 必要的分阶段观测、确定性行为验证和隔离性能对照。
- 用户验收调查确认的 K3 摘要参数兼容、摘要边界创建与恢复不一致，以及确定性参数失败重复触发问题；与取消链路一起在 118 验证。
- 原生阶段与无阶段模型的执行过程展示分别处理：保留原生语义，允许在可信成功结束后按消息顺序推断最终展示，并明确区分来源。

### 不包含

- 以更换模型、修改记忆抽取质量、重做相关性排序、改变压缩策略或关闭记忆来规避读取成本。
- 自动截断或删除用户历史、放宽损坏记录检查、授权检查或副作用恢复约束。
- 将整个任务中心、所有工具执行器或全部持久化系统一并重写。
- 将聊天分页预先确定为本期必须交付的功能，或预先承诺某种索引、缓存、存储技术。
- 不经单独授权重启用户运行实例、重跑用户任务、调用真实外部 LLM，或把真实会话正文放入仓库。

## 行为要求

### R-1 日常读取与任务反馈

不同用途的读取应承担与其结果相称的工作。仅获取列表或会话元信息，不应反复处理与这些结果无关的完整执行内容；同一状态的重复查询不应持续累积等价的完整处理。

发送后的接纳、准备、拒绝和失败应有明确反馈。轻量查询成功不代表历史能够完整恢复，也不能替代任务执行前必要的完整性与权限检查。

### R-2 召回与历史查询正确性

沿用 048、069、098 的相关性、有效分支、时间、owner、persona、当前会话截止边界和 Core 例外语义。明确不具备本次召回资格的数据不应产生可避免的大量读取；允许参与召回的旧证据不能因优化而永久失去检索机会。

显式历史查询按自身的目标会话、时间和查询范围工作，不误用自动召回的排除规则。性能对照同时检查证据身份、正文、排序、范围和截断状态；仅数量或 ID 集合相同不能单独作为完整正确性证明。

### R-3 取消覆盖完整准备生命周期

用户发起桌面文字发送后，取消意图不能因为后台尚未登记任务而丢失，也不能出现界面已接受取消、原发送随后又开始执行的情况。排队、历史恢复、记忆检索及上下文准备均须参与取消处理。

取消请求已被接纳与执行真正终止应能够区分。取消生效后不得再启动新的模型调用或工具操作；已经开始的外部操作按既有生命周期处理，已发生的副作用不得被伪装成未发生。

取消不能被当作普通检索失败吞掉后继续执行。重复取消、完成与取消竞态、重连和停止后续聊保持唯一终态及既有恢复语义。桌面不会因此获得对不可由桌面控制的外部运行的越权取消能力。

### R-4 并发与状态一致性

同会话重复读取、多窗口和重连应减少等价工作，并最终取得必要的新状态；读取期间的新版本不能被永久遗漏。旧结果不能覆盖新版本或切换后的会话，运行尾部、授权状态与历史内容不能因刷新合并发生错误拼接。

读取与追加写入并发时，正常批量追加的一致性、写入进度及损坏尾部处理继续符合既有契约。不同会话不能因单个大会话的重复处理受到不必要的串行阻塞。

### R-5 首次处理与分页评估

区分正常重复访问、进程首次访问、旧会话首次处理和辅助读取数据失效后的恢复。首次处理可以有独立成本，但应有准确反馈、支持取消，并避免后续访问反复支付相同成本。

分页只作为候选方案评估。比较内容须包括后端实际读取量、传输量、前端投影与持有成本，以及滚动定位、引用回跳、跨边界消息和工具分组、编辑重发、活动运行和版本一致性的影响。当前已有虚拟滚动不能被当作已有数据分页；只减少页面返回量也不能被当作已经减少后端完整读取。

若收益不足或复杂度、风险不合适，本期允许不实现分页。若选择分页或逐步加载，其具体交互和完整历史访问方式必须在技术方案中明确并确认。

### R-6 测量与归因

性能使用固定条件下的实测和前后对比，不设预定的 1 秒、2 秒或 p95 数值硬门槛。记录数据规模、参考环境、冷热状态、并发条件、端到端与分阶段耗时、读取量和重复次数；有足够重复样本时再报告分位数。

行为正确性、取消可靠性与数据完整性仍是验收要求。测量结果必须说明改善、退化和剩余成本，不以取消数值门槛为由省略性能验证。

保留现场额外约 125 秒的归因缺口，补充能够区分读取、解析、投影、查询、等待及取消收口的观测。若仍不能复现原事故，明确已取得的证据与下一项区分性检查，不宣称根因已经全部解释或所有慢取消已经消失。观测不得包含用户正文、工具参数与输出或凭据。

### R-7 摘要可靠性

当前支持的 K3 推理档位在摘要调用中保持原值，不因 SDK 参数兼容而被静默丢弃。区分本地 SDK 拒绝和厂商请求失败；同一运行与模型配置下已确认无法重试的参数错误，不反复启动相同摘要操作。

摘要创建、当前模型历史与重启恢复使用一致且可验证的边界。已保存的摘要可以在对应历史中复用；编辑后的不匹配记录和无法安全验证的旧记录不得强行使用。记忆召回与记忆观察使用可验证的业务事件截止，不把模型内部消息 ID 当成用户消息来源。

摘要请求等待及重试过程参与 R-3 的取消；完成与取消竞态不得继续主对话或发布虚假的成功压缩。此修复不改变压缩阈值、分页取舍或记忆质量策略。

### R-8 原生阶段与推断展示

有原生阶段能力的运行继续按其真实阶段展示；没有阶段信息的运行，在整轮明确成功结束、正文分段和顺序完整时，可以把最后一条非空助手消息留作最终展示，将此前正文和普通工具过程收纳。用户仍能展开查看完整过程。

推断仅用于展示，必须能与原生来源区分，不能把推断阶段写回用户历史或向模型冒充原生阶段。运行中、取消、失败、没有可信终态的历史、原生阶段异常或存在相互矛盾的阶段事实时，不自动推断和收起。最后正文之后仍有工具工作的情况不冒充已有最终答复。

折叠保持消息原顺序，错误、提醒与需要用户操作的内容保持可见。手动展开优先，搜索和引用可以展开并定位原文，复制继续包含完整内容。历史恢复使用同一展示规则，不回填或改写旧阶段数据。

## 验收条件

- [x] **AC-1 日常读取**：在短会话、长会话及不同会话数量的隔离数据上验证列表、详情和发送准备，记录并减少已确认的无关或重复完整处理，保持缺失、不可读取和损坏记录的错误边界。
- [x] **AC-2 召回范围与结果**：覆盖当前会话无截止边界、有截止边界、已失活内容、Core、其他会话和显式查询；比较证据身份、正文、顺序、范围和截断结果，确保可检索内容不因优化丢失。
- [x] **AC-3 接纳前取消**：受控阻塞发送准备，确认用户取消不会因任务尚未登记而丢失，后续准备解除后不再启动已取消任务。
- [x] **AC-4 执行中取消**：分别在排队、历史读取、记忆检索、上下文准备和执行边界取消；验证取消传播、正常终态、停止后续聊及已发生副作用的处理，不被普通失败降级吞掉。
- [x] **AC-5 并发一致性**：覆盖重复详情、多窗口、读取期间追加写入、切会话、重连和完成/取消竞态；必要新状态不丢失，旧结果不覆盖，写入可以推进，重复工作不会无界累积。
- [x] **AC-6 首次处理与兼容性**：分别验证首次与重复访问、旧数据及辅助读取数据失效；保持历史恢复、有效分支、模型配置、权限和各入口控制语义，并验证首次处理的反馈与取消。
- [x] **AC-7 性能对照**：在明确的环境与数据条件下报告端到端/阶段耗时、读取量和重复次数，保留未改善或退化项的解释；不使用预设时延数值判定通过与否。
- [x] **AC-8 分页取舍**：方案记录分页的预期收益、联动范围、风险和最终选择。若采用，补齐滚动、引用、分组、编辑重发、运行尾部和版本一致性验证；若不采用，记录理由与重新评估条件。
- [x] **AC-9 可观测性与证据**：观测可关联请求、会话摘要、运行及阶段，区分取消接纳和完成；记录不含敏感正文，明确受控结果与现场归因的区别。
- [x] **AC-10 项目门禁与用户验收**：受影响测试和项目 `scripts/check` 通过；按最终方案执行适用验收并记录局限，用户确认验收完成后收口。
- [x] **AC-11 摘要可靠性**：K3 三档参数原样进入摘要请求；本地参数错误不误报为厂商拒绝且同 run 不重复；模型专用边界、已物化摘要、真实 rollout 重启恢复、编辑失效与旧记录保守兼容均有回归；记忆来源仍是有效业务事件；摘要 HTTP 等待取消后资源释放且不继续主对话。
- [x] **AC-12 阶段展示来源**：原生与推断来源可区分；无阶段成功运行仅在完整终态后推断，保留最后逻辑消息的所有正文片段；原生异常、运行/取消/失败、旧终态缺失和工具仍在末尾等情形不误折叠。实时与历史结果一致，搜索/引用、复制、手动开关及异常可见性通过自动化和已授权的真实桌面验证。
