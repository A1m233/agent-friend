# 118 · 长会话读取与可取消执行 — 技术方案

## 状态

CONFIRMED

## 需求文档

[requirement.md](./requirement.md)

## 现状分析

会话 JSONL 同时承载用户可见事件和较大的执行恢复记录。`SessionStore.load()` 为完整恢复构造所有事件，列表摘要还会反扫最新模型配置；聊天详情和历史查询借用这些路径，承担了与输出不相称的读取及对象构造成本。`SessionSearchService` 另有进程内索引，但刷新时持全局锁，不能解决共享读取成本。

历史召回先枚举和加载会话，再过滤当前会话与截止边界。候选不足时重新扩大搜索窗口，重复读取同一输入。前端多个详情入口只有响应序号保护，没有合并正在进行的请求。

AG-UI 在 runtime 登记前打开历史、解析模型与附件；此时取消可能得到 404。登记后的恢复、记忆和部分上下文处理也没有完整贯通取消。运行登记不等于用户输入已持久接收，若改变准备阶段，必须同时处理草稿和乐观消息的收口。

已确认机制与未定位现场时间见 [证据索引](./evidence-index.md)。方案不承诺解释现场全部 136.628 秒。

## 方案设计

### 1. 存储拥有可复用的查询投影

完整 `load/open` 继续服务可执行 Session 和 rollout 恢复；新增查询读取能力用于列表、详情和历史搜索。查询结果是只读快照，不能成为 writer、续跑或恢复成功的凭据。

快照保留业务事件、有效分支判断所需标记、原始事件位置、元信息及损坏诊断，解析后不保留庞大 rollout 正文。首建仍校验全部记录并沿用损坏尾部政策；只有完整成功的结果可以发布。事件位置不能因排除内部事件而改变当前回合截止语义。

复用层归属 store，按会话合并构建，不在重读和解析期间持全局缓存锁。进程内缓存限制条目数量和估算容量；文件身份、长度与高精度修改信息决定新鲜度，不能只依赖追加之后才通知的 broker revision。已知追加可增量推进；外部变化、替换、截断或不安全的增量边界必须重建。缓存不是第二份持久化真相源。

取消等待者不能发布半成品，也不能让其他会话阻塞。构建遇到取消可由其他仍在等待的请求重新承担；共享有效结果不随单个调用者取消而失效。读取使用快照与短文件锁，追加批次的原子边界保持不变。

历史查询枚举只需会话 ID 和活动时间，不计算无关模型配置；真正的列表摘要仍保留最新 raw model 语义。详情使用 active model 语义。元数据批量读取一次。已有全文搜索缓存改为复用共同版本与读取能力，避免增加平行失效规则。

首期不做持久化索引。进程首次访问旧大会话仍有扫描成本，需支持取消和阶段反馈；若该成本在本轮测量后仍占主导，再独立评估持久化索引的同步、崩溃恢复与迁移成本。

### 2. 召回先约束范围，单请求复用工作

自动召回在枚举前排除没有截止边界且不具备资格的当前会话；显式查询沿用自身范围。带截止边界的当前会话仍保留完整回合的 provenance 判断，不能先裁去后半回合而错误接纳前半回合。

一次请求内复用历史候选准备与扩量结果，避免每次 limit 扩大重新加载。结构化检索各来源的限额、排序、合并与 RRF 语义保持；不能把一个最大合并列表切片冒充原来的各来源限额。可复用查询向量等确定性中间结果。

memory 接收可选的取消检查回调，不反向依赖 agent runtime。取消贯穿枚举、读取、候选处理和检索降级边界；捕获普通异常前必须让取消继续传播。

### 3. 先登记运行，再做可取消准备

发送入口登记前只做低成本输入结构和标识校验。历史恢复、有效模型及附件验证放入已登记的 worker，在 preparing 阶段执行；每个耗时阶段和模型、工具启动边界检查同一个取消信号。

因此部分原本 HTTP 拒绝的错误会变成已登记运行的准备失败。保留明确错误码和终态；模型或附件验证失败时不得伪造已持久接收的输入。准备验证先于可能产生外部效果的 hook，取消或失败释放本次拥有的资源，不释放其他运行已持有的合法资源。

协议分别表达运行登记与输入接收事实。只有实际持久接收用户输入之后才标记 input accepted；此前取消或失败可恢复草稿并移除相应乐观消息。此后失败必须保留已落盘输入，不能再恢复成一个待重发副本。新增字段兼容旧入口和缺失字段，AG-UI、运行快照及前端共享一致语义。

附件先验证再一次性消费；不在原子消费或持久化批次中途抛取消。上下文压缩不改变策略，只把取消传递到现有 ModelCallControl，并防止异常降级将取消当成压缩失败后继续执行。

前端从发送开始持有按 runtime/session/run 标识的取消意图。404 或网络失败不清除意图，后续登记、push、响应或重连校准触发补发。服务器确认前显示请求中，确认后仍等待真实终态；不能把 abort HTTP 当作后台已停止。完成与取消竞态沿用唯一终态，已经发生的副作用仍然保留。

取消意图只保存最小身份与阶段，若为窗口重载恢复需暂存，仅使用窗口级会话存储，不持久化用户正文、附件或凭据。运行消失不自动等于拒绝；确认拒绝、终态或 runtime 身份失效后才清理。控制能力继续服从既有来源与权限。

OS 单次调用和本地推理不能保证强制抢占；在调用前后检查，真实结束后才能发布终态，不虚报即时停止。

### 4. 合并详情请求，暂不分页

所有同会话详情 GET 通过一个专用在途协调器。一个请求执行期间，后续读取共享结果；如内容事件或本地变更产生了更新需求，完成后补一次读取。不同会话独立，运行身份与页面生命周期变化隔离旧请求。保留切会话、revision、审批状态及投影应用的现有保护，不让同一快照重复覆盖或漏掉新的终态。

首期保留完整聊天数据与现有虚拟滚动。分页只减少返回量并不一定减少后端扫描，而且当前消息与工具分组、引用搜索跳转、编辑重发和运行尾部依赖完整事件集合。当前先减少后端读取与重复 GET，风险与已知收益更匹配。

后续若传输量、浏览器投影或内存成为实测主成本，再评估页面游标、跨页分组和引用定位；本需求不加入临时分页协议。

### 5. 观测与验证

观测关联请求、匿名会话标识、run 和阶段；区分登记等待、读取、解析、投影、检索、上下文以及取消接纳/收口，记录字节数、命中与重复次数，不记录正文、工具参数或凭据。

确定性验证使用隔离合成数据、fake LLM 与受控并发屏障，覆盖短/长会话、首次/重复访问、追加/替换/截断、损坏尾部、当前回合截止、旧结果保护、准备失败草稿、重复取消和恢复续聊。性能对照使用相同数据和环境，报告读取量与阶段时间，重复样本足够时才报告分位数，不设硬时延门槛。

真实用户数据、LLM 调用与桌面运行态仍服从单独授权。未执行的真实体验验收明确标为未验证，不用 mock 冒充。最终执行项目 scripts/check。

### 6. 验收追加的摘要修复

K3 的 Chat 请求准备显式允许 `reasoning_effort`，复用已有窄范围兼容逻辑并保留调用者选定值。内部白名单只进入 LiteLLM，不放入模型 defaults 或 Responses 请求。通过真实 SDK 与模拟 HTTP 检查参数，避免只模拟高层生成函数而漏过 SDK 校验。

新摘要 checkpoint 使用 `checkpoint_version=3`、`scope=model`，covered/source/retained 明确对应同一份冻结模型历史。`summary_message_uuid` 和摘要消息的 `compaction_id` 随实际模型历史保存；`model_prefix_sha256` 绑定压缩前的有序消息身份。恢复区分完整原历史待折叠与摘要已经物化两种状态，均验证对应身份和边界，不因为查不到已被折叠的消息就重建摘要，也不凭相似正文猜测关系。

`business_covered_through_uuid` 与 `business_prefix_sha256` 单独承载可证明的业务截止。记忆召回和观察只使用通过业务活动前缀校验的截止点；无法证明时保守保留更多原始上下文。查询路径仍排除 rollout，不为摘要兼容引入完整恢复读取。旧 v1/v2 继续严格验证原边界；无稳定标记且不能验证的模型专用 checkpoint 不宣称恢复成功，其已在可信 rollout 中保存的正文仍保留在模型历史中。

本地 SDK 参数拒绝统一为 `LLMUnsupportedParameterError`，日志只记录类型、来源和稳定原因码，不记录异常中的正文或凭据。同 session/run/model 的确定性参数失败在后续构建中直接降级；新的运行或模型可再次尝试。已有网络、超窗重建与一般失败熔断边界保留。

带取消控制的非流式生成使用可取消的异步 HTTP 调用并保持 Chat 语义，调用前后、等待和重试均检查同一信号。取消请求任务后关闭本次客户端；资源清理开始后不再被重复取消打断。provider 接受前的摘要仍是候选，失败、拒绝或取消不得保存成功 checkpoint。

### 7. 原生阶段与推断展示分离

在前端执行区策略中派生 `source=native|inferred|none`，不新增 Session、Bridge 或 ChatMessage 持久字段。原生路径继续消费该run保存的能力与validation；native的pending/missing_final/conflict不转成推断。legacy或缺阶段能力记录的正文必须全部为unknown/缺失，才可进入顺序推断；混入合法原生阶段时保持原展示。

推断要求明确run ID、`status=complete`和`runOutcome=completed`，不存在仍运行的工具或可见运行错误；任何模式已记录的validation=conflict均禁止推断，以保留消息边界异常。按既有正文item顺序去重mid，选择最后一个有非空文本的逻辑item；其所有片段均留在执行区外，不能把迟到的旧item片段当作新的最终消息。若最后逻辑正文开始后还有工具工作，不推断最终展示。空正文或不可信旧终态不触发推断。

`MessageList`使用同一个派生结果计算连续执行分段和默认收起。native按可信commentary收纳；inferred仅收纳最终mid以外的正文和普通工具。仍复用现有分段，不搬动或重排blocks。错误/警告、request类工具、提醒和活动边界沿用区外保护。source通过展示策略结果和DOM诊断属性区分；默认不增加用户界面的协议标签。

成功终态之前没有推断式自动收起；原有手动开关和搜索/引用强制展开继续优先。实时、重连、编辑重发与历史恢复均重新派生，不保存永久推断、不修改raw phase，不影响模型历史、记忆、IM或语音。自动化覆盖来源、终态、逻辑mid、保护项和源数据不变；真实Tauri验收已经由用户单独授权，须核对运行源码身份。

## 影响与风险

- 新读取路径仍保持持久化格式、模型工具 schema、权限和原有分支语义；查询成功不得替代执行恢复。
- bounded cache 必须防止引用暴露后修改污染、并发 stale publish 和大会话内存放大。缓存淘汰允许重建，不允许遗漏历史。
- CLI、语音、IM 等共享调用方继续可调用原有接口；取消能力通过可选参数或清晰的能力适配接入。
- preparing 错误时序变更同时更新错误展示与 input acceptance；旧客户端字段缺失不能被当作肯定拒绝。
- 纯业务实现按 frozen-runtime 规则分类，若引入打包敏感因素再按该规则补验证，本需求不默认生成安装包。
