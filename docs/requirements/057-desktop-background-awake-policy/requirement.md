# 057 · 桌面后台在线与防休眠策略

## 状态

CONFIRMED

## 背景

agent-friend 的桌面端已经能够在启动后托管 `agent_bridge`，由 bridge 加载已绑定的 IM 通道并维持长连接；设置窗口或聊天窗口关闭后，应用也可以继续留在系统托盘运行。但这些能力只覆盖了应用自身的进程生命周期，没有处理操作系统的电源生命周期。

当电脑因长时间无人操作而自动休眠时，桌面端、Agent Runtime 和 IM 长连接都会随系统暂停。用户看到的桌宠可能仍是“已启动”状态，但远端发送的 IM 消息无法在休眠期间被本机处理。Agent 执行耗时任务时也可能因为系统空闲计时器到期而被中断。

防休眠不应由 IM、Agent、语音或某个 React 窗口分别维护。它是桌面壳需要统一管理的基础能力：产品要有一致的用户策略、当前状态和安全边界，各业务能力只表达“当前是否需要保持后台在线”，不能各自改变系统电源行为。

本需求建立统一的桌面后台在线策略。用户可以选择跟随系统、仅在接通电源时保持在线，或始终保持在线；桌面端根据用户策略和当前业务需要统一阻止系统因空闲自动休眠，并提供前往系统电源设置的入口与合盖边界说明。

## 目标

- 在 Agent 执行本地任务或存在需要持续在线的 IM 绑定时，按用户选择阻止电脑因空闲自动休眠。
- 允许显示器按系统设置关闭，不通过保持屏幕常亮来换取后台在线。
- 只向用户提供一项互斥的后台在线策略，避免多个开关组合出冲突或含义不清的状态。
- 由桌面端统一维护防休眠状态、触发原因和生命周期，业务模块不各自持有系统防休眠能力。
- 在设置中心展示当前电源条件、后台在线状态和触发原因，让用户知道策略是否正在生效。
- 提供前往系统电源设置的入口和平台对应指引，帮助用户理解并自行配置合盖行为。
- 如实表达平台能力和限制，不把合盖、手动休眠、低电量保护或未知状态误报为“保证在线”。

## 范围

### 包含

#### 单一后台在线策略

- 设置中心提供一项“后台在线策略”，包含三个互斥选项：
  - **跟随系统**：应用不主动阻止系统休眠。
  - **仅接通电源时保持在线**：存在后台在线原因且设备接通电源时阻止空闲休眠；作为推荐选项展示。
  - **始终保持在线**：存在后台在线原因时阻止空闲休眠，包括电池供电期间。
- 新用户和已有用户升级后的默认值均为“跟随系统”，未经用户主动选择不改变电脑的既有电源行为。
- “始终保持在线”需要明确提示电池消耗、发热以及合盖放入包内可能带来的风险。
- 三个选项是同一策略的不同取值，不提供“仅接电保持”和“电池也保持”两个可同时开启的独立开关。
- 策略只控制是否阻止系统休眠，不提供“保持屏幕常亮”选项。

#### 统一后台在线原因

- 桌面端维护统一的后台在线状态，同一应用运行态内只有一个权威来源。
- 首期接入以下后台在线原因：
  - 至少存在一个已启用、按产品语义应持续维持连接的 IM 绑定。
  - 至少有一个本地 Agent 任务仍在执行。
- IM 原因以“用户仍要求该绑定持续在线”为准，不以某一瞬间的连接健康状态为准；断线重连期间不能因为连接暂时异常而释放防休眠状态。
- 多个原因可以同时存在；任一原因仍然有效时，不得因为另一原因结束而提前允许系统休眠。
- 原因消失、用户切换策略、电源状态变化或应用退出后，防休眠状态应及时重新计算，不遗留失去业务依据的持续唤醒。
- 后续语音通话、设备迁移、备份等长任务可以接入同一产品语义，但本期不把它们列为正式触发原因或验收对象。

#### 电源状态变化

- “仅接通电源时保持在线”需要跟随设备电源状态实时变化：
  - 接通电源且存在后台在线原因时进入保持在线状态。
  - 切换为电池供电后退出保持在线状态，重新服从系统电源策略。
  - 再次接通电源时，如果后台在线原因仍然存在，自动恢复保持在线。
- “始终保持在线”不因接电或电池供电切换而退出，但仍受操作系统最终电源决策约束。
- 无法可靠读取电源状态时，不得把“仅接通电源时”误报为正在生效；设置页应展示无法确认或未生效状态。

#### 防休眠生命周期与安全边界

- 保持在线只阻止操作系统因空闲计时器进入自动休眠；显示器可以按系统设置关闭。
- 防休眠状态必须跟随桌面应用生命周期，不依赖设置窗口、聊天窗口或某个 WebView 是否打开。
- 隐藏桌宠、关闭受管理窗口或保留在系统托盘时，只要策略条件仍满足，后台在线状态继续有效。
- 用户退出应用后，应用必须释放自身持有的防休眠状态；不得在桌面端退出后遗留独立常驻的唤醒进程。
- 应用不得模拟鼠标或键盘输入，不得通过周期性制造虚假用户活动维持在线。
- 应用不得静默修改系统电源计划、休眠超时、合盖动作或其他操作系统级持久配置。
- 防休眠状态不能被描述为唤醒已经睡眠的电脑，也不能被描述为能够阻止用户手动睡眠、休眠、关机，或系统因低电量、温度、更新和硬件策略采取的强制动作。

#### 设置中心与当前状态

- 在现有“通用”设置中增加清晰的后台运行区域，不新增独立设置窗口。
- 设置页至少展示：
  - 当前选择的后台在线策略。
  - 当前是接通电源、电池供电，还是无法确认。
  - 当前是否正在保持系统唤醒。
  - 当前触发保持在线的用户可理解原因，例如“QQ 保持在线”或“Agent 正在执行任务”。
- 没有后台在线原因、策略条件不满足、平台不支持或状态无法确认时，界面需要解释为什么当前没有保持唤醒，不能只展示一个含义不明的关闭状态。
- 后台在线状态发生变化后，已打开的相关窗口应看到一致结果，不因跨窗口缓存出现互相矛盾的展示。
- 用户从系统设置返回、应用重新获得焦点或从系统恢复后，应刷新可能变化的电源能力和当前状态。

#### 系统电源设置入口与合盖引导

- 设置页提供“打开系统电源设置”入口；平台支持时直接打开对应系统页面。
- Windows 入口至少能够打开“电源与电池/电源和睡眠”相关设置，并同时展示进入“选择关闭盖子的功能”的简短人工路径。
- macOS 入口至少能够打开或引导用户进入“电池/能源与睡眠”相关设置。
- Linux 桌面环境存在可靠入口时可以打开对应设置；无法可靠定位时提供人工路径或明确的不支持说明。
- 系统入口不可用或打开失败时，应用继续可用，并向用户提供可执行的人工操作说明。
- 对笔记本用户明确说明：合盖行为由系统控制；如果系统配置为合盖时睡眠，Agent 和 IM 会随系统暂停。
- 应用只负责跳转和引导，不自动替用户把合盖动作改成“不执行任何操作”。

#### 平台保证范围

- Windows 是本需求当前正式开发、使用与验收平台，覆盖后台在线策略、业务原因聚合、电源状态变化、系统防空闲休眠和设置入口/指引。macOS 保留已有兼容实现，但不设置构建或真机验收门槛。
- Linux 保持相同设置语义和统一能力边界；如果运行环境缺少可靠的系统防休眠或设置入口，应明确报告不支持或无法确认，不伪造生效状态。
- 不在未完成对应真机验证前承诺“锁屏后仍持续在线”。锁屏行为应作为平台验证记录保留，验证稳定后才能升级为正式产品承诺。
- 不承诺应用能够突破平台对合盖、低电量、热保护、休眠或关机的限制。

### 不包含

- 不提供保持显示器常亮、演示模式或屏幕防熄灭能力。
- 不自动修改 Windows 电源计划、合盖动作、注册表或 macOS/Linux 的持久电源配置。
- 不保证用户手动睡眠、休眠、关机或笔记本按系统策略合盖后 Agent 与 IM 仍然运行。
- 不提供从睡眠状态远程唤醒电脑的 Wake-on-LAN、定时唤醒或云端唤醒能力。
- 不建设应用退出后独立运行的系统服务、守护进程或云端 Agent 托管能力。
- 不在本期把语音通话、设备迁移、备份或其他未来任务接入后台在线原因。
- 不把 IM 断线重连、网络切换、凭据失效或 provider 自身稳定性问题等同于防休眠问题；这些能力继续由对应 IM 模块负责。
- 不在需求阶段锁定平台 API、内部数据结构、事件协议或具体组件形态；这些由 `design.md` 基于平台调研确定。
- 不调用真实 LLM、IM 厂商或其他外部 provider API完成自动化验收。

## 验收标准

- [x] 设置中心“通用”分类只提供一项后台在线策略，并能在“跟随系统”“仅接通电源时保持在线”“始终保持在线”之间互斥选择。
- [x] 新用户和已有用户升级后默认“跟随系统”；界面将“仅接通电源时保持在线”标为推荐，但不会未经用户选择自动启用。
- [x] 选择“始终保持在线”前或选择时，用户能看到电池消耗、发热和合盖收纳风险提示。
- [x] 策略为“跟随系统”时，应用不持有系统防休眠状态。
- [x] 策略为“仅接通电源时保持在线”时，只有在接通电源且至少存在一个后台在线原因时持有防休眠状态；切到电池后及时释放，再次接电后按现有原因恢复。
- [x] 策略为“始终保持在线”时，只要至少存在一个后台在线原因，接电和电池供电期间都保持防休眠状态。
- [x] 存在已启用且应持续连接的 IM 绑定时形成 IM 后台在线原因；连接暂时异常或正在重连不会错误移除该原因。
- [x] 本地 Agent 任务开始和结束能够形成并释放对应后台在线原因；多个任务或多个原因并存时不会提前释放防休眠状态。
- [x] 防休眠状态不依赖设置、聊天或其他受管理窗口保持打开；桌宠隐藏到托盘后仍按策略生效。
- [x] 应用退出、最后一个原因消失、策略改为“跟随系统”或策略条件不再满足后，不遗留应用创建的防休眠状态。
- [x] 保持在线期间显示器仍可遵循系统设置关闭，应用不模拟用户输入或强制屏幕常亮。
- [x] 设置页正确展示当前策略、电源状态、是否正在保持唤醒及全部用户可理解的触发原因；无法确认或不支持时不会显示虚假的生效状态。
- [x] Windows 和 macOS 均能从设置页打开相应的系统电源设置或得到明确人工路径；入口失败不会影响应用其他功能。
- [x] 笔记本用户能够看到合盖边界说明，应用不会自动修改系统合盖动作或宣称能够阻止所有合盖睡眠。
- [x] Linux 缺少可靠防休眠能力或系统设置入口时显示明确降级状态，不把无效操作报告为成功。
- [x] 用户从系统设置返回、应用重新聚焦或从系统恢复后，后台在线状态能够重新校准。
- [x] 后台在线策略归一化、多个原因聚合、电源状态切换、生命周期释放、平台不支持和设置入口失败均有自动化测试覆盖。
- [x] Windows 完成真实桌面端电源 smoke，验证系统可观察到防休眠状态按条件建立和释放；锁屏与合盖结果只记录事实，不超出本需求承诺。
- [x] `./scripts/check` 全量门禁通过。

## 开放问题

- Windows 与 macOS 的系统防休眠能力分别采用何种原生 API 或依赖，以及 Linux 如何按桌面环境降级，由技术方案阶段调研确定。
- 本地 Agent 活跃任务的权威状态从现有哪个运行时边界提供，需要在技术方案阶段沿 045/047 的现有 owner 核对，不能由 React 页面根据 loading UI 推断。
- “存在应持续在线的 IM 绑定”的权威判定和变化通知，需要在技术方案阶段基于当前 IM Runtime、凭据持久化和桌面 bridge 状态确定。
- Windows 是否提供稳定的合盖行为深链、macOS/Linux 系统设置入口的兼容范围，需要在技术方案阶段验证；不稳定时以通用电源设置入口加人工路径为准。
- 锁屏期间系统防休眠请求是否持续生效，需要按平台和电源模型记录真机结果；在形成稳定证据前不进入产品保证范围。
