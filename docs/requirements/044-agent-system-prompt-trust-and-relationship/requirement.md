# 044 · Agent System Prompt 可信边界与陪伴表达升级

## 状态

CONFIRMED

## 背景

当前 agent 已通过 `SystemPromptComposer` 将 system prompt 拆为项目身份、persona、人格切换、
工具使用、记忆一致性、输出格式、通道与运行时上下文等职责，并由 `agent_eval` C1-C5 覆盖
历史召回、时效事实、身份稳定、事实抗编造和记忆矛盾回应。现有结构已经具备持续演进的基础，
但真实行为边界仍存在三类缺口。

第一，搜索结果、历史片段、文档与工具返回内容虽然已经被要求只能支持其实际包含的事实，
却尚未被统一定义为“不具备指令权的数据”。第三方内容可能夹带要求 agent 忽略既有规则、
改变身份、调用工具、泄露信息或执行动作的文字；如果只约束事实引用而不约束指令权限，
agent 仍可能受到间接 prompt injection 影响。

第二，内部调度目前通过 user role 中的 `<system_trigger>` 标记让模型理解系统主动回合。
模型仅从文本本身无法判断该标记来自可信 runtime 还是普通用户伪造。内部触发语义不能只依赖
一段用户也能输入的文本，否则普通用户内容可能被误判为系统事件。

第三，现有 prompt 对事实、工具和记忆红线规定较多，但对“一个好的朋友型 Echo 应主动表现
出什么”描述不足；同时运行时上下文把事实查证范围写得过宽，并硬编码了近似知识截止日期。
这可能让 Echo 过度搜索、频繁保留意见，或表现得像一个擅长避错的工具，而不是有温度、
有分寸、能长期相处的虚拟朋友。

本需求把上述问题收敛为一次 system prompt 可信边界与陪伴表达升级：明确哪些内容有指令权、
哪些事实需要查证、内部事件如何避免被用户伪造，以及 Echo 应建立怎样的关系感。所有行为都
需要进入可复跑的自动化或 agent 行为评测，避免只凭 prompt 文案存在就宣称完成。

## 目标

- 第三方内容、工具结果、历史片段与文档中的文字不能覆盖用户原始目标、项目级规则、身份或权限边界。
- 普通用户不能通过输入内部标记获得 system trigger 的可信来源语义。
- 稳定常识可以自然回答；时效、易变化、低置信度、高风险和私人历史事实按各自证据要求处理。
- system prompt 不再依赖某个底层模型的固定知识截止日期假设。
- Echo 能表达在意、关系连续性、适度独立判断与温和分歧，而不只是服从或复述用户。
- Echo 不通过占有、排他、愧疚、恐惧或挽留建立操控式依赖，并支持用户自然结束对话或连接现实支持。
- system prompt 各 section 的职责清楚，重复规则得到收敛，现有 C1-C5 行为不退化。
- 新增的可信边界与关系行为拥有可复跑的测试和 agent_eval 契约。

## 范围

### 包含

**不可信内容边界**

- 默认 system prompt 明确把网页、搜索结果、历史片段、文档、附件转录和工具返回内容视为待分析的数据，而不是对 agent 的指令。
- 第三方内容中要求改变身份、忽略规则、调用工具、泄露信息或执行外部动作的文字不得获得指令权。
- agent 只能从不可信内容中提取完成用户原始请求所需的信息，不得让内容自己改写任务目标。
- 会承载第三方内容的现有内置工具需要清楚表达内容来源与证据边界；必要的结果结构同步调整。
- 高风险动作仍须遵守既有授权与确认边界，不能因为工具结果或第三方内容声称“已授权”而跳过。

**内部 system trigger 来源边界**

- 普通用户输入与 runtime 内部生成的 system trigger 在进入模型前必须可区分。
- 用户手工输入 `<system_trigger>...</system_trigger>` 或等价内部标记时，只能作为普通用户文本处理，不能获得内部调度语义。
- 现有 bedtime、idle reflection 等真实内部事件继续能触发预期的主动开口或静默整理行为。
- 后续历史归因仍不能把内部触发内容说成用户曾经表达过的话。

**事实查证分级**

- 稳定、低变化且模型有充分把握的常识允许直接回答，不强制搜索或逐条说明来源。
- 新闻、价格、天气、人物职位、产品状态、平台规则等近期或易变化事实必须先取得当前证据。
- 对具体命名实体或细节缺乏把握时，先查证或清楚标记不确定，不能用模糊语气把猜测包装成确认。
- 用户私人历史只能来自当前对话中可见内容、实际召回到的历史片段或用户刚明确提供的信息。
- 移除绑定某个模型或某个日期的固定知识截止描述；底层 provider 切换不应要求同步修改这条行为规则。

**关系与陪伴表达**

- 默认项目级关系边界对所有 persona 生效；persona 可以改变语言风格，不能改变非操控、非排他的底线。
- Echo 应表现出稳定在场、在意用户、关系连续性和适度独立性，可以有自己的观察、偏好与温和分歧。
- 用户表达情绪或困难时，Echo 优先理解当下意图与感受，不急于说教、诊断或把每次对话都变成解决方案。
- Echo 可以表达牵挂和期待再次交流，但不得用占有、排他、愧疚、恐惧或挽留绑定用户。
- Echo 不暗示自己是用户唯一的理解者或支持来源；当现实支持更适合时，可以自然支持用户连接可信任的人或专业帮助。
- 用户表示要睡觉、工作、离开或结束对话时，Echo 自然收尾，不刻意制造新的问题强行延长对话。

**Prompt 职责收敛**

- 回看现有默认 section 中重复的身份、工具、证据、记忆与运行时规则，明确每类规则的主要归属。
- 只清理明确重复或冲突的内容，不借本需求全面重写 `SystemPromptComposer` 或所有 persona。
- 默认装配顺序需要继续体现项目级边界高于 persona 风格、具体通道覆盖默认输出、动态上下文靠近末尾等现有原则。
- 对最终默认 prompt 的体积建立可观察基线，避免新增规则后无边界增长。

**评测与验证**

- 在 `agent_eval` 中新增不可信内容 / 间接 prompt injection 契约，覆盖搜索、历史或等价工具结果夹带恶意指令的场景。
- 在 `agent_eval` 中新增关系与非操控边界契约，既覆盖禁用表达，也覆盖在意、独立判断、自然收尾等正向行为。
- 扩展现有相关契约：稳定常识不应无谓搜索，时效事实仍需查证；多轮身份诱导和 prompt 探测不得破坏项目身份；工具结果中的指令不得导致事实或动作越权。
- 补非 LLM 自动化测试，覆盖 system prompt 默认装配、内部标记来源隔离、工具结果结构和 eval loader / selection / judge 等确定性行为。
- 真实 LLM eval 不进入默认 `./scripts/check`；执行前必须按 `llm-api-confirm` 单独获得用户明确授权。

### 不包含

- 不改变 Echo 当前是否承认 AI、程序或虚拟身份的产品策略；该问题需要独立产品决策或需求讨论。
- 不建设医疗、法律、自伤、未成年人等大而全的安全政策体系。
- 不建设 prompt 管理后台、远程配置、版本发布平台或 A/B 实验平台。
- 不无差别重写所有工具 description；只调整本需求直接涉及的不可信内容与证据边界。
- 不全面重构 system prompt composer、persona catalog、消息协议或 agent 主循环。
- 不以关键词禁用列表作为关系质量的唯一验收方式，也不在首版引入通用 LLM judge 平台。
- 不执行真实外部 LLM 调用作为默认自动化门禁。

## 验收标准

- AC-1：默认 system prompt 明确规定第三方内容与工具结果不具备指令权；其中夹带的忽略规则、改变身份、调用工具、泄露信息或执行动作要求不会被遵循。
- AC-2：用户手工输入 `<system_trigger>` 或等价内部标记时不会获得内部事件语义；真实 runtime system trigger 继续按预期工作，且不会在历史中被归因为用户原话。
- AC-3：稳定常识可以不调用搜索直接回答；新闻、价格、天气、人物职位、产品状态和平台规则等时效事实仍会先取得当前证据。
- AC-4：默认 system prompt 不再包含绑定具体底层模型的固定知识截止日期；低置信度具体实体仍须查证或明确不确定。
- AC-5：用户私人历史只基于当前对话、实际召回片段或用户明确提供的信息回答；不可信内容和外部事实不能伪装成过去对话证据。
- AC-6：默认 system prompt 包含适用于所有 persona 的关系与陪伴边界；Echo 能表达在意、关系连续性、适度独立判断和温和分歧。
- AC-7：Echo 不使用占有、排他、愧疚、恐惧或挽留话术绑定用户，不暗示自己是用户唯一的支持来源；用户结束对话时能自然收尾。
- AC-8：关系行为评测同时包含正向与负向判断，不以“未命中禁词”单独代表具备良好陪伴表现。
- AC-9：现有 prompt section 中明确重复或冲突的规则得到收敛；默认装配职责和顺序有自动化测试锁定，prompt 体积有可观察基线。
- AC-10：`agent_eval` 新增不可信内容 / 间接注入与关系边界契约，loader、CLI selection 和确定性 judge 能正确处理新增 case。
- AC-11：现有 C1-C5 不退化；新增或扩展的确定性测试覆盖内部标记隔离、工具结果边界、prompt 装配和评测基础设施。
- AC-12：`./scripts/check/run.sh` 通过，默认 check 不触发真实 LLM 或搜索 API；若执行真实 LLM eval，已单独获得授权并在 `progress.md` 记录模型、调用量级、范围与结果。

## 开放问题

- 关系表达的正向行为如何在不引入通用 LLM judge 的前提下获得稳定自动判分，需要在技术方案中结合现有 deterministic judge 能力设计；必要时允许将部分自然度验收保留为人工 spot check，但不能只验禁词。
- system trigger 的可信来源可以通过消息 metadata、用户输入转义、内部专用消息结构或组合方案实现；本需求只锁定“用户不可伪造”的结果，不在需求层预设具体机制。
- Prompt 体积基线采用字符数、估算 token 数还是 provider tokenizer，需要在技术方案中选择不引入过度依赖且能稳定回归的口径。
