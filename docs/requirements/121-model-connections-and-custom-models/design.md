## 方案
- RuntimeConfigPanel 复用现有 Tabs，按模型和服务凭据分组。模型选择继续使用现有持久化入口。
- 凭据列表使用现有 Collapsible，摘要显示服务名、供应商与当前凭据状态，编辑区复用 RuntimeCredentialGroupEditor。
- 页签和折叠内容保留挂载、隐藏非活动内容，保留编辑草稿。凭据操作进行中禁止收起和切换页签。
- 外部 focusGroup 和错误提示跳转统一执行切换页签、展开、滚动。已有 OpenRouter 隐藏策略保持。
- 不调整后端协议、凭据存储或模型目录，不引入依赖。

## 第二步现状与模块边界
- agent_bridge/runtime_config.py 通过模型名推断供应商，失败时回退默认供应商；自定义模型不能沿用该回退。
- SessionModelService、SessionManager 及历史 store 校验依赖静态模型目录；需要分开历史结构校验与执行可用性校验。
- DeferredLanguageModel 缓存首次创建的客户端，记忆配置闭包绑定启动时选择；只刷新 UI 不能完成后台配置更新。
- Tauri runtime_credentials 保存后重启服务的既有行为不适合自定义连接的执行边界更新。
- Responses 当前只有流式适配，generate 仍走 Chat；记忆、压缩、通知对结果有不同消费契约。

## 第二步方案

### 配置与模型身份
连接承载稳定身份、显示名称、Base URL、协议和凭据引用；模型承载稳定身份、远端 Model Name、上下文长度与能力信息。显示名称、远端模型名和内部模型引用不能互相替代。

内置模型保留现有稳定标识，自定义模型使用独立标识。内置目录和用户配置合成只读目录快照，通过注入供选择、校验和装配使用，不新增全局可变注册中心。模型名不再决定自定义连接的地址或凭据。

runtime_config 负责读取配置和凭据；llm_providers 负责模型定义、能力及请求协议；agent_bridge 负责目录装配、执行绑定和连接操作协调；agent/memory 消费中立模型接口。业务模块不读取 keyring 或桌面设置文件。

### 历史与执行
历史读取只验证结构并保留模型引用，不要求模型仍在当前目录中。执行入口单独检查引用、凭据和能力；未知或已删除引用返回可恢复错误，不回退供应商。

一次对话及其工具循环持有同一配置快照；压缩若属于该轮，沿用相同绑定。一次记忆抽取及协调共用一个绑定；独立通知任务在启动时绑定。客户端缓存必须受配置版本约束，不能跨任务永久保留过期配置。

执行登记和连接删除检查经过同一协调入口。存在相关执行时拒绝删除并返回占用信息，由用户等待或停止；删除期间不允许新执行穿过检查。取消和异常退出必须释放执行登记。

### 保存、应用和恢复
Tauri 继续拥有设置与 keyring 写入，Python 拥有运行快照与活动执行。前端继续通过统一设置/业务客户端访问，不直接操作存储。

保存带配置版本检查，防止旧表单覆盖新配置。先准备新配置与凭据，再发布完整可用版本；设置和 keyring 无跨存储事务，操作需要记录可恢复的进度和清理责任，不声称它们天然原子。保存与运行应用状态分别反馈，失败可重试，已有执行保留旧快照，新执行不得使用不完整配置。

删除必须一并处理默认对话与记忆选择，并协调活动执行；不能先删密钥再验证默认用途。重启恢复以完整已提交配置为准，残留准备状态需恢复或清理。现有内置凭据与工具服务操作保持原边界。

### 协议与结果
维持 LanguageModel.generate/stream 接口；Responses 补充真正的非流式请求和响应适配，与流式共享输出项解释、终态和错误分类。complete 委托同一 generate 路径。

最终结果消费与过程事件展示分开：明确 final 时只消费最终结果；普通无 phase 响应保留兼容路径；无法唯一确定结果、拒答、不完整响应或非预期工具项不能被当作成功正文。不能任意取最后一段或聚合所有 commentary 来凑 JSON。交互流继续保留工具 ID、原生 item 和 phase 回放信息。

参数按协议及供应商已有 profile 显式转换，核对输出预算、reasoning、工具 optional/strict 语义、存储参数和不支持字段。通用 Responses 不默认请求服务端保存；供应商不支持该参数时遵循明确的兼容映射，不以失败后切换 Chat 隐藏问题。严格 JSON Schema 不随本次传输迁移自动启用。

### 前端交互
沿用已验收模型页结构，增加自定义连接编辑与模型列表。保存、模型发现和生成测试分别触发；显示保存/应用/测试状态。删除界面列出默认用途替换入口与执行占用，失效模型在历史中可见并能跳转重新选择。

## 第二步影响与验证策略
涉及 runtime_config、llm_providers、agent_bridge、agent 会话与历史、memory 执行绑定、桌面设置与前端模型选择，以及 agent_eval/memory_eval 的构造入口。语音入站 Chat Completions 接口保持兼容，验证其向模型端的路由不受影响。

先用确定性测试固定 HTTP 路由、参数、结果提取、迁移和并发行为，再用真实供应商 smoke 验证协议及多阶段业务链路。覆盖矩阵和实际执行证据维护在 progress.md，验收标准归 requirement.md；不得以旧版本或单纯 HTTP 成功替代本次产品行为证据。

新增能力需要复核 frozen capability smoke 覆盖范围；命中 package-sensitive 时执行项目要求的 runtime-only 验证。完整安装包构建不是本方案默认动作。

## 草稿发现与测试交互修订（2026-09-09，用户已授权）
以地址/密钥 → 获取并选择模型 → 测试模型 → 保存为主路径，手动添加作为后备。模型列表可搜索勾选，已添加模型独立展示。移除与删除采用常驻 destructive 按钮；外层滚动布局保持。

新增中立元数据解析位于 llm_providers/connections，发现和探测编排位于 agent_bridge/model_connections/inspection；前端表单与模型选择区分离，Tauri 只转发 owner 授权的 loopback 检查请求。检查使用当前草稿及临时密钥，不写设置或 keyring；空密钥仅允许通过现存连接 ID 读取该连接凭据。保存继续走原协调事务。

上下文元数据按服务显式输入窗口 → 精确内置目录 → SDK 目录参考 → 未知处理；不把输出 max_tokens 当作上下文。来源显示给用户，允许覆盖；未知时展开输入，但仍可先测试。修改地址、密钥或协议时清除发现/测试结果及本次自动填值，保留明确手动值。元数据及探测结果不作为持久化能力声明。

主动测试最多 3 次生成请求：普通生成、流式工具调用、工具结果回传后的最终生成。使用无副作用合成工具，分别反馈生成及工具闭环结果；第一步失败后跳过工具测试。关闭模型网络/过载自动重试，设置超时及总期限，错误仅返回分类，不返回响应正文或密钥。探测不测量最大窗口、不触发记忆或实际业务工具。保存不隐式发起探测。

## 启动装配与异步布局修复（2026-09-10）
用户确认修复后，统一构造一次基础 BridgeRuntime，再按 IM 开关追加相关能力；提醒、调度与社交鉴权的最终装配共用一条路径。连接管理不再依赖 IM 分支是否重复传入字段。

外层滚动使用 stable both-edges 预留对称滚动空间；操作反馈常驻，失败重试时原位显示处理中；共享 Button 加载态隐藏但保留原子内容占位，spinner 绝对定位覆盖，保留可访问名称和禁用语义。已有 asChild 行为保持。

## 推理强度与附件方案修订（2026-09-10，已确认）

### 配置与执行
默认对话、记忆模型和会话内选择共用推理配置语义。服务默认独立表示为不发送参数，不复用现有 none 标识表达“不支持”；显式字符串 none 仍是一个应传给服务端的值。自定义档位只做基础字符串校验，不经内置模型枚举限制；协议层将同一档位映射为 Chat reasoning_effort 或 Responses reasoning.effort。既有内置模型继续使用各自已定义的推理策略。

默认设置补充推理选择的持久化与旧格式兼容，缺省时保持既有行为。后续新对话、通知和记忆按各自配置入口获得强度；会话覆盖只影响该会话的后续执行。已经绑定的执行与工具循环不因设置变化重新装配。请求拒绝不静默删参数、降档或换服务。SDK 不得在透传前按内置模型名过滤自定义字符串；通过请求捕获测试核对实际 wire。

前端共用“服务默认、常见建议、自定义输入”的语义；建议不是服务能力清单。标准模型发现不虚构推理档位列表。能力提示使用可读连接名与模型名，区分配置未知、应用未接入和服务拒绝。

### 附件能力及转换边界
模型定义与运行快照携带图片、文档能力及相应处理方式，用户可声明或覆盖自定义能力。MultimodalInputAdapter 消费显式能力和处理方式，不再通过模型名前缀选择自定义供应商；内置 Kimi/DeepSeek 原有专用路径保持。

复用现有附件上传、资产存储、类型与数量/大小校验。JPEG/PNG/WebP 读取本地资产后转换为 data URL 图片块；TXT 按文件内容和可读文件标识进入文本消息。PDF 优先读取原文件并使用 OpenAI 原生 file/input_file 内容块；不依赖兼容服务另外实现 Files 上传 API。Chat/Responses 在协议边界转换各自结构，不能把原生 PDF 当作 DeepSeek 专用图片 file_id。

历史只保存附件资产引用，发送时按当前执行快照重新转换；不把 Base64 写入会话正文。需覆盖同一附件跨会话轮次、重启恢复和模型切换；缓存若涉及服务端产物，必须保留原有连接/凭据隔离。旧附件在不支持的目标路径上须明确标识，不把无法读取的内容声称为已读取。

PDF 原生输入是否被 CPA 接受仍属待验证事实；拒绝时保留错误，不自动退化成丢失图表/扫描信息的纯文本。若需本地渲染兼容路径，先明确新增依赖、页数/像素预算与部署影响，再回到设计确认，不能用“已支持 PDF”掩盖降级。

### 本轮真实验证契约
使用隔离合成附件和测试会话，不发送用户已有截图、PDF 或历史内容作为测试材料。先完成确定性参数、配置继承、装配及内容转换测试，再运行有界真实请求；执行前说明模型、路径、用量，沿用用户对本需求 smoke 的授权，不重复申请。

- 推理：CPA/Luna 的服务默认、明确档位分别捕获真实请求；自定义陌生字符串用本地捕获固定透传机制，实际不接受的值验证明确失败且无隐式改写。服务成功返回仅表示请求接受，不能证明内部采用该档位。
- 图片：合成图片包含不能从文件名或问题文字推知的颜色/图形/短码，覆盖 JPEG/PNG/WebP。分别检查目标模型读到的实际内容，以及图片后的追问与历史恢复。
- 文档：TXT、文字 PDF、扫描 PDF 分开；PDF 用正文/页面内容中的合成短码、图表或位置关系检验读取，不仅判断 200 或非空答案。原生 PDF 拒绝单独记录，不算通过。
- 链路：所选强度随工具首调用、回传后的回答及后续会话正确生效；默认对话、记忆及通知各自入口核对；记忆检查 JSON、领域结果与隔离落库，不以普通聊天代替。
- 兼容：DeepSeek/Kimi 按受影响参数和附件路径复验；两种传输的确定性 wire 测试全覆盖，真实端点不支持某种组合时如实报告。
- 桌面：从设置/会话界面实际选择强度、添加附件、发送与恢复错误，并与原生/Bridge 请求和结果关联。不能仅手动装配路由，绕过默认 IM 启动入口。

每批记录源码版本/哈希、目标协议和 endpoint、脱敏请求证据、实际调用数、预期与实际断言。失败和复验产物分别保留；guide 在最终用户验收和合入前按最终行为更新。
