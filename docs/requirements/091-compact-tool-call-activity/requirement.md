# 紧凑工具调用活动流

## 状态

CONFIRMED

## 背景

agent-friend 会在桌面对话流中展示工具调用的进行中、完成和失败状态，并保留参数、结果、命令输出、授权信息等诊断细节。随着 Agent 能力扩展，一轮回复可能连续执行搜索、读取、Skill 加载、本地命令和文件访问等多个工具。

当前界面把每次工具调用都渲染成一张独立卡片。即使普通工具已经收起参数与结果，卡片边框、内边距、状态和卡片间距仍会随调用次数线性累积；本地命令、文件访问等专用卡片还会默认展示更多运行信息。连续工具较多时，执行过程会挤占对话正文，用户需要滚动较长距离才能看到 Agent 的说明和最终回答。

Codex 当前产品采用更紧凑的渐进披露方式：单次工具调用默认以短描述呈现，连续工具调用可聚合为一个折叠活动段，用户需要时再查看逐项细节。agent-friend 应借鉴这种信息层级，但继续保留自身的审批、登录、命令停止和失败恢复等交互能力。

## 目标

- 让工具执行过程退居为紧凑、可检查的活动记录，不再与助手正文争夺主要视觉空间。
- 单次普通工具调用默认用一行用户可理解的动作摘要呈现。
- 连续普通工具调用聚合为一个可折叠活动段，并概括调用数量和主要动作。
- 通过分层展开完整保留每次调用的参数、结果、输出和诊断信息。
- 需要用户关注或操作的授权和运行中进程统一由输入框上方的稳定 Dock 承载；对话流继续保持紧凑，登录等没有 Dock 承接的独立交互仍保留专用表面。
- 实时会话与历史会话使用一致的展示规则，不改变工具执行、事件持久化和恢复语义。

## 范围

### 包含

#### 单次工具调用的紧凑呈现

- 单个普通工具调用默认只占一行，只展示展开箭头和语义化动作摘要，不附加状态圆点或右侧状态文案。
- 组摘要和单项摘要统一使用项目公共 `TextEllipsis`，按活动行的实际可用宽度判断溢出；活动行应占满对话内容区，摘要生成层不得预先按字符数截断，避免右侧仍有空白却提前出现省略号。
- 默认摘要描述“做了什么”，不以原始工具名、完整参数 JSON 或完整结果作为主要标题。
- 搜索、读取、Skill 加载、查看图片和已经结束的普通命令等非交互态工具应能生成稳定、克制的摘要。
- 用户可以展开单次调用，查看当前已有的参数、结果、命令输出、执行位置和其它诊断信息。

#### 连续工具活动分组

- 同一轮助手回复中连续出现的两个及以上普通工具调用合并成一个工具活动段。
- 对无需用户继续操作的工具，是否进入同一活动组只由原始相邻关系决定，不读取成功、失败、警告或取消状态作为分组边界。
- 活动段默认展示一行综合摘要，至少说明调用数量和主要动作类别；运行中可以描述“正在执行”，结束后统一使用中性的“执行了”，不透露或统计失败数量。
- 助手可见正文、提醒事实、上下文压缩反馈以及需要用户处理的独立交互会结束当前连续分组；后续工具形成新的活动段。
- 不同普通工具类型可以进入同一连续活动段，不要求为了视觉整齐而改变原始调用顺序。
- 展开活动段后按原始顺序展示每次调用的紧凑行；用户可继续展开其中某一项查看完整详情。

#### 流式状态与展开控制

- 工具仍在运行时，紧凑行或活动段摘要应持续反映当前动作和总体进度，不需要等待整轮完成才出现。
- 活动段摘要随进行中和完成事实更新，但紧凑层不额外堆叠状态装饰；需要用户处理的事实继续由独立交互卡片承载。
- 用户主动展开或收起后，流式状态更新不得擅自覆盖用户选择，也不得因每次事件更新反复开合。
- 新增调用、调用完成和助手继续输出正文时，应尽量保持阅读位置稳定，避免不必要的高度跳变或强制滚动。

#### 需要突出处理的工具状态

- 等待文件、命令、网络或其它权限决定时，输入框上方的授权 Dock 是唯一自动出现的完整授权表面；它必须提供执行目的、命令或目标、工作目录、超时、执行级别、文件与网络权限、Skill 来源和附加范围等足够判断的信息。
- 授权通过后若命令仍在运行，同一 Dock 原地切换为运行状态条，保留动作摘要、命令、运行状态和停止入口；执行终止后自动消失。
- 对话流中的命令和文件工具在等待授权、启动、运行和终态全过程都保持紧凑行，不自动插入完整卡片；完整命令、输出和诊断只在用户主动展开单项时显示。
- 等待用户登录、确认或补充信息的工具不得只显示在收起的活动段内部。
- 失败、超时、拒绝、取消或运行时失联可以与相邻普通工具进入同一活动组；活动摘要保持中性，不提示是否失败或失败数量，原始状态和具体原因只在展开详情中保留。
- 上述调用进入不再需要用户操作的终态后，可以回落为紧凑历史记录，但原有结果和状态不得丢失。

#### 一致性与可访问性

- 实时流式消息、切换后恢复的历史消息以及刷新后的同一会话使用相同的分组、摘要和展开规则。
- 展开与收起支持键盘操作、明确的焦点状态和可识别的展开状态；不能只依赖鼠标点击或颜色表达状态。
- 明暗主题下保持可读性，并沿用现有对话页的信息层级与设计语言。
- 工具活动摘要不得为了生成自然语言而新增真实 LLM 调用。

### 不包含

- 不改变工具注册、参数 schema、执行顺序、并行策略、预算、取消或错误模型。
- 不改变工具调用与结果事件的协议、持久化格式、关联标识或历史恢复语义。
- 不重新设计文件、命令、网络、社交登录等授权策略及其权限边界。
- 不删除、截断或降低现有参数、结果、命令输出和诊断信息的可访问性。
- 不重做整个聊天气泡、输入框、会话侧栏或桌宠气泡视觉。
- 不实现 reasoning 展示、执行计划视图或通用 Agent trace 调试器。
- 不改变 IM 渠道中的工具执行反馈和交互入口。
- 不要求精确复刻 Codex 的图标、文案、像素尺寸或未公开的内部实现。

## 验收条件

- [ ] AC-1：一轮中只有一个普通工具调用时，默认只显示一行语义化动作摘要；摘要使用公共 `TextEllipsis` 并按真实可用宽度省略，完整参数与结果在展开后可见。
- [ ] AC-2：同一助手轮中两个及以上连续普通工具调用默认合并为一个工具活动段，收起时只显示综合摘要和数量，不重复展示状态圆点或右侧状态文案。
- [ ] AC-3：助手正文、提醒事实、上下文压缩反馈或需要用户处理的独立交互会正确结束连续分组，展开后的工具顺序与原始事件顺序一致。
- [ ] AC-4：活动段展开后显示每次调用的紧凑行，单项继续展开后能查看改动前已有的参数、结果、命令输出、执行位置和诊断信息。
- [ ] AC-5：实时执行时摘要能随调用开始和结束更新；结束后的摘要保持中性，不根据失败数量改变文案，用户主动选择的展开状态不会被后续流式事件重置。
- [ ] AC-6：命令和文件授权只在底部 Dock 自动展示完整判断信息，对话流始终保持紧凑；命令运行期间 Dock 保留停止入口，终止后消失；登录等未被 Dock 承接的交互仍可发现。
- [ ] AC-7：连续的失败、超时、拒绝、取消、成功和其它普通终态不会因状态不同被拆成多个活动组；摘要不提示或统计失败，展开后能查看每项原始状态和原因。
- [ ] AC-8：进入无需用户操作的终态后，文件、命令、Skill 和其它专用工具可以回落为紧凑记录，同时保留原有终态和详情。
- [ ] AC-9：实时会话、历史切换恢复和刷新后的同一事件序列产生一致的分组、摘要、顺序和终态展示。
- [ ] AC-10：连续工具调用在收起状态下不会随调用数量线性增加完整卡片高度；活动行使用完整可用宽度，展开、收起和流式更新期间没有明显的阅读位置跳变、提前省略或横向溢出。
- [ ] AC-11：活动段和单项详情可以通过键盘展开、收起，并具有可识别的焦点和 `aria-expanded` 展开状态；明暗主题均可读。
- [ ] AC-12：自动化测试覆盖单次调用、连续分组、文本边界、混合工具、流式增量、失败状态、交互型工具例外、历史恢复和展开状态保持。
- [ ] AC-13：工具执行协议、调用结果关联、授权与停止操作、会话持久化、历史恢复、普通助手文本和现有错误处理没有回归。
- [ ] AC-14：项目规定的 lint、typecheck、单元测试与集成测试全部通过；桌面端视觉验收按项目授权规范单独确认并记录结果。
