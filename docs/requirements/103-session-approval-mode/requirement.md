# 会话级免授权模式与高危兜底

## 状态

CONFIRMED

## 背景

agent-friend 现有本地文件与命令能力默认要求用户逐项授权，并且只开放“仅本次允许”。这一默认值适合大多数使用场景，但在用户明确理解风险、希望 Agent 在同一会话内连续完成大量本地操作时，反复审批会打断任务，也会使需要多步文件、命令和联网能力的工作流难以持续推进。

完全取消逐项审批会显著扩大风险。当前命令能力既包含受 Codex exec-server 沙箱约束的普通命令，也允许 Agent 显式申请不受文件系统与网络沙箱限制的 `host_user` 执行；文件能力还包含覆盖、移动和删除等破坏性动作。因此，会话级免授权必须是用户主动、可见且经过重复风险确认的选择，不能成为新会话默认值或全局偏好。

同时，“本会话无需授权”只表示普通授权请求不再逐项弹窗，不应承诺任何命令都必然执行。对于磁盘清除、范围不明的广泛强制删除等可机械识别的灾难性动作，系统仍需要保留一道不可由会话免授权自动绕过的高危门禁。

## 目标

- 让用户可以在单个持久会话中选择继续逐项授权，或在充分知情后让后续普通授权请求自动允许。
- 在输入区和具体授权卡片上提供一致的模式入口、二次确认和状态反馈。
- 让高风险模式始终可见、可随时退出，并且不传播为全局默认或新会话默认。
- 在减少重复审批的同时，保留现有沙箱、受保护路径、结构化请求、作用域校验和可观测性边界。
- 对可机械识别的灾难性本地动作提供简单、确定性且不依赖额外 LLM 调用的最后一道门禁。

## 范围

### 包含

#### 两种会话授权模式

- 每个桌面聊天会话仅提供两个授权模式：
  - `每次授权（推荐）`：保持现有逐项展示、批准或拒绝的行为。
  - `本会话无需授权`：自动允许该会话后续新产生、且未命中高危门禁的本地文件与命令授权请求。
- 新建会话始终以“每次授权（推荐）”开始；创建新会话、切换会话、复制内容或其它会话管理动作不能继承另一会话的免授权状态。
- 授权模式随原会话持久化。应用重启、重新打开历史会话或会话归档后恢复时继续使用原模式，但界面必须持续显示当前高风险状态。
- 用户可以随时切回“每次授权（推荐）”。退出高风险模式不需要二次确认，并立即影响之后新产生的授权请求；已经启动的文件或命令操作不被追溯撤销。
- 会话免授权不创建全局默认、持久命令规则、白名单或跨会话授权。

#### 输入区模式入口与风险状态

- 授权模式控件跟随输入区已有的会话级控件放置，使用户在发送任务前能够查看和调整当前模式。
- 安全模式显示为推荐选项。高风险模式使用醒目的风险图标、颜色和文案，不能只依赖下拉菜单内的勾选状态表达。
- 会话正处于高风险模式时，重新进入会话无需再次弹窗，但当前状态必须在输入区持续可见，避免用户遗忘该会话仍会自动允许普通请求。

#### 每次进入高风险模式都二次确认

- 每次从“每次授权”进入“本会话无需授权”都必须出现二次确认；此前曾确认过、同一应用进程内再次切换或同一会话再次进入都不豁免。
- 弹窗至少明确说明：Agent 后续可以在不逐项询问的情况下读取、创建、修改、覆盖、移动或删除本地文件，运行本地命令，使用申请到的网络能力，以及执行显式申请的 `host_user` 不受限命令。
- 弹窗明确推荐继续使用“每次授权”，并说明即使选择免授权，系统仍可能拒绝灾难性高危动作。
- 弹窗提供清楚区分的取消与确认动作，不提供“以后不再提醒”或把高风险模式设为默认的选项。
- 用户取消、关闭弹窗或确认请求失败时保持原模式，不产生隐式授权。

#### 授权卡片入口

- 本地文件和本地命令授权卡片在现有“拒绝”“仅本次允许”之外，增加“本会话无需授权”动作。
- 从授权卡片选择“本会话无需授权”时，使用与输入区完全相同的二次确认内容和风险语义。
- 用户在某张卡片上完成确认后，只批准该卡片所展示的精确请求，同时把所属会话切换为“本会话无需授权”；其它已经挂起的授权请求保持待处理，之后新产生的普通请求才自动允许。
- 卡片触发的批准与会话模式切换必须形成一致结果。失败时不能留下“模式已切换但当前请求未批准”或“当前请求已批准但模式未切换”的半完成状态。
- 从输入区切换模式不追溯批准任何已经挂起的请求；这些请求仍需用户逐项处理。

#### 自动允许的覆盖范围与边界

- 会话免授权覆盖现有统一授权控制面中的本地文件请求和本地命令请求，包括 Agent 显式申请的 `host_user` 命令。
- 自动允许只消费请求已经明确表达的动作、路径、权限、命令、工作目录、网络能力、执行级别、会话和 run 归属，不能主动扩大任一范围。
- 普通 `sandboxed` 命令不会因为会话免授权而自动升级为 `host_user`；是否申请 `host_user` 仍由原工具契约显式表达。
- 现有 Windows 沙箱准备、exec-server sandbox enforcement、受保护产品路径、Skill 内容身份、路径规范化、命令结构化参数、进程归属、超时和取消边界继续生效。会话免授权不能把能力前置条件或运行时安全拒绝解释成已经通过。
- 当前不能展示桌面授权交互的入口不会因为某个桌面会话曾开启免授权而自动获得新的本地能力；非桌面入口继续遵循其原有可用性和 fail-closed 边界。

#### 灾难性高危门禁

- 系统在授权模式之外保留一个确定性高危门禁。第一版只处理能够由结构化请求、规范化路径和明确命令形态可靠识别的灾难性本地动作，不引入额外 LLM 风险评审。
- 至少覆盖以下类别：
  - 磁盘、卷或分区的格式化、清除或同等破坏性操作；
  - 对文件系统根、Windows 盘符根、当前用户目录、当前工作区根或 agent-friend 产品数据根发起的强制递归删除；
  - 使用未解析变量、通配符、命令替换、间接脚本或其它无法在执行前确定真实目标与范围的强制递归删除。
- 在“每次授权”模式下，命中高危分类的请求继续通过授权卡片展示完整目标、范围和风险，用户可以对该精确请求作出单次决定。
- 在“本会话无需授权”模式下，命中高危分类的新请求不得自动执行，也不得静默退回普通自动允许；系统直接拒绝并提示用户切回“每次授权”后重新发起和检查该动作。
- 用户从一张已经展示精确高危请求的授权卡片主动选择“本会话无需授权”时，该卡片仍属于用户对当前精确请求的显式决定；确认后可以批准当前请求，但之后新产生的高危请求仍按免授权模式的高危拒绝规则处理。
- 高危门禁应返回稳定、可解释的拒绝原因和命中的风险类别，避免 Agent 通过改写等价命令盲目重试。
- 普通的、目标明确且范围窄的文件清理不能仅因使用删除动作就被一律归为灾难性高危；门禁需要区分可审计的局部删除与广泛、不可逆或目标不明的破坏。

#### 可见记录与并发一致性

- 自动允许的请求仍保留原始请求详情、作用域、终态和历史记录，并标明“依据本会话设置自动允许”。
- 高危拒绝保留请求摘要、风险类别和拒绝原因，并标明它没有执行。
- 会话模式变化需要同步到同一会话的所有桌面窗口和相关状态投影；旧窗口或断线重连不能用过期模式错误批准请求。
- 切换模式与新授权请求并发发生时，后端以明确的模式版本或等价一致性边界决定请求走人工、自动允许还是高危拒绝，不能依赖前端到达顺序猜测。
- 用户取消 run、删除会话或运行时失活时，原有 pending approval 和进程清理语义继续生效；会话免授权不能恢复已经取消或失效的请求。

### 不包含

- Codex 的第三种自动评审模式、基于 LLM 的风险 reviewer 或为风险判断额外调用真实模型。
- `acceptEdits`、只读、按工具分类自动批准等更多权限档位；本需求只保留“每次授权”和“本会话无需授权”。
- 全局免授权默认值、跨会话授权、永久命令规则、路径白名单、组织级策略管理或用户自定义 denylist。
- 让会话免授权绕过操作系统 UAC、Windows 沙箱准备、exec-server sandbox、产品受保护路径或现有 Tool Runtime 校验。
- 把 Codex app-server、完整 Codex Agent runtime 或 Claude Code 权限系统接入 agent-friend。
- 让 IM、定时任务或其它不能承载桌面授权交互的入口因复用同一 session id 而自动获得本地文件或命令执行能力。
- 第一版对数据外泄、凭据探测、生产环境变更和持续安全弱化进行通用语义识别；这些风险不能在缺少可靠证据时由简单字符串规则声称已经覆盖。

## 关键信息

### “本会话无需授权”的产品口径

- 它表示该会话后续普通授权请求无需逐项弹窗，不表示 Agent 获得未申请的能力，也不表示任何命令都必然执行。
- `host_user` 请求仍必须由 Agent 显式提出并保留不受沙箱限制的风险事实；高风险模式只改变用户逐项决策方式，不改变请求本身的执行级别。
- 灾难性高危动作仍可能被拒绝。用户需要执行此类动作时，应切回“每次授权”，重新检查并只批准当前精确请求。

### 已挂起请求的口径

- 从输入区切换模式只影响切换完成后新创建的请求，不自动处理队列中已有请求。
- 从某张授权卡片切换模式同时构成对该卡片的显式批准；其它已有请求不随之批准。
- 这一区分需要在前端文案、后端行为和测试中保持一致，避免用户误以为一次切换已经批准整个等待队列。

## 验收条件

- [ ] **AC-1 两种模式与安全默认值**：桌面会话只提供“每次授权（推荐）”和“本会话无需授权”；所有新会话默认前者，且不存在全局免授权默认或跨会话继承。
- [ ] **AC-2 输入区入口与持续状态**：用户可以在输入区查看和切换模式；高风险模式在菜单关闭、应用重启、历史会话重开和归档恢复后仍持续醒目可见。
- [ ] **AC-3 每次进入都二次确认**：每次进入高风险模式都展示风险、推荐单次授权并要求明确确认；取消、关闭或失败保持原模式，不能跳过或永久关闭提醒。
- [ ] **AC-4 普通请求自动允许**：高风险模式下，新产生且未命中高危门禁的文件、sandboxed 命令和显式 `host_user` 请求自动允许；执行范围与原请求一致，sandboxed 请求不会被自动升级。
- [ ] **AC-5 授权卡片切换**：文件与命令授权卡片都提供“本会话无需授权”；确认后批准当前精确请求并切换所属会话模式，任一步失败都不会留下半完成状态。
- [ ] **AC-6 已挂起请求不被批量批准**：从输入区切换不处理已有 pending 请求；从卡片切换只处理当前卡片，其它 pending 请求继续等待用户决定。
- [ ] **AC-7 高危模式退出**：切回“每次授权”无需确认并立即影响后续请求；已开始的操作不被撤销，之后的请求重新逐项展示。
- [ ] **AC-8 灾难性动作兜底**：磁盘或分区清除、对关键广泛根路径的强制递归删除、以及目标范围无法确定的强制递归删除均被稳定识别；默认模式可逐项决定，免授权模式直接拒绝并提示切回安全模式。
- [ ] **AC-9 局部删除不过度拦截**：目标明确、范围窄且不触及关键根路径的普通文件清理不会仅因使用删除动作就被高危门禁一律拒绝。
- [ ] **AC-10 既有安全边界保持**：Windows 沙箱准备、exec-server sandbox enforcement、受保护路径、Skill 身份、路径规范化、进程归属、超时、取消和非桌面入口 fail-closed 行为均不因会话免授权而放宽。
- [ ] **AC-11 可见审计**：自动允许与高危拒绝均在活动状态和历史记录中显示原请求、决策来源、风险分类和终态；不能静默执行或静默失败。
- [ ] **AC-12 多窗口与竞态一致性**：同一会话在多窗口、重连和模式切换并发请求下得到一致结果；过期客户端不能错误批准请求，取消或失效请求不能因模式变化复活。
