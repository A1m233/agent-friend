# 上下文用量连续性与局部变化复用

## 状态

CONFIRMED

## 背景

123 已建立真实输入用量锚点与增量估算，但工具定义、请求设置或旧消息前缀变化时，整份上下文回退到全量粗估。2026-09-13 的一次续聊在首次回复前触发压缩：上轮实际输入 118652 token，本轮压缩前估算 254111，超过 217600 的阈值。日志记录请求作用域变化，前后工具定义指纹不同。该事件证明局部变化后的计量连续性缺口；未压缩新请求的实际用量未知，不能把全部差额视为高估。

本需求是 123 的后续独立交付，保留旧文档作为历史。已确认方向是尽量复用已有实测依据，而不是将任意变化都视为全量失效。

## 目标

局部上下文变化时尽量保留未变历史的可信实测依据，只对未被覆盖或发生变化的成本估算，减少全量粗估造成的过早压缩，同时保持超窗保护。

## 范围

### 包含

- 连续工具循环、新用户轮次、工具定义和动态系统上下文变化的用量连续性。
- 新增、替换、删除内容的成本处理，以及下一次真实 usage 对计量依据的更新。
- 重启恢复、历史编辑与重发、压缩、模型与连接切换时的复用或安全重建边界。
- 附件与不透明推理等特殊成本的隔离处理，尽量避免局部未知导致整段已知历史失去依据。
- 候选上下文预算、最终请求复核及诊断信息的同源计量。
- 确定性回归、兼容旧会话与异常 usage 的验证。

### 不包含

- 改变现有摘要策略、历史保留政策、输出预留或安全缓冲比例。
- 改变用户界面、记忆召回、模型窗口目录或工具公开契约。
- 承诺任意模型切换或不可观测成本都能继续复用；不把估算描述为精确 tokenizer 结果。

## 需求

- **R-1 尽量复用**：有兼容的实测依据时，局部变化不得仅因整份请求指纹变化就默认将全部历史退回粗估。复用边界应由计量兼容性和变化范围决定。
- **R-2 成本完整**：正确处理追加、替换和删除，避免漏算、重复计入或用粗估差额过度扣减实测总量。缓存命中不减少上下文占用；输入、输出和 reasoning 遵循 provider 语义。
- **R-3 安全与隔离**：跨会话或不兼容计量身份不得混用；不可证明的部分须明确处理，必要时重建或降级，保留最终预算复核和超窗恢复。
- **R-4 持续更新与恢复**：新可信 usage 更新计量依据；重启后尽量恢复可用依据，旧会话和未知元数据仍可安全使用。
- **R-5 可解释**：诊断可区分精确前缀复用、局部变化复用和全量回退，并对账实测基数、变化成本、未知成本处理及压缩原因。不得持久化另一份私有请求正文或凭据。

## 验收条件

- [ ] **AC-1**：合成高估历史已有可信 usage 时，工具定义或系统上下文的小幅变化能保留历史计量依据；不会单因旧历史重新全量粗估而触发压缩。
- [ ] **AC-2**：新轮次、连续工具调用、模型输出及变化内容无遗漏或重复计入；真正的新增成本达到阈值时仍触发保护。
- [ ] **AC-3**：替换、删除、重排和同一标识内容变化分别有断言；不能用过大的粗估扣减导致低估。无法安全复用时，降级原因可解释。
- [ ] **AC-4**：重启恢复、旧格式、压缩、历史编辑与重发、跨会话以及模型/连接切换分别验证复用或失效边界；新真实 usage 能刷新依据。
- [ ] **AC-5**：附件、图片及不透明 reasoning 有明确且可验证的成本处理；候选计量不触发上传等副作用，不把密文长度直接等同于真实 token。
- [ ] **AC-6**：候选预算、最终发送复核和日志口径一致；缺失、异常或不兼容 usage 不破坏既有安全恢复，诊断字段可对账且不泄露正文。
- [ ] **AC-7**：项目 scripts/check 全绿，用户确认验收；真实 LLM 验证另行授权，离线机制回归不冒充原会话精确重放或真实运行。
