## 现状与方案

123 的锚点只有整份请求作用域和完整消息前缀摘要，工具或前缀变化会失去全部计量依据。现有 request capture、usage 配对、assistant 元信息持久化和 ContextManager 估算入口继续作为责任源。

- 将计量兼容身份与可变内容分开：会话、模型/路由、provider 计量与 reasoning 配置保持兼容门禁；工具定义作为独立内容参与匹配，不再让整段历史失效。未知请求设置保持隔离，不假设其不会改变模型输入。
- 新版本锚点保存带语义域的内容摘要和出现次数，分别识别消息内容、工具调用、reasoning 和工具定义，不复制请求正文。相同内容最多复用原有次数，新增重复项仍收费。
- 新格式对连续追加与局部变化共用片段匹配，采用原始真实 input usage 加当前请求中未匹配部分的估算；匹配成立时不计算全量 fallback。删除或替换的旧内容暂留在实测基数作为无法精确分配的安全余量，不用旧粗估扣减。每次均与原始实测锚点比较，不把上次估算当新实测；新的可信 usage 替换整个锚点。
- 压缩和裁剪候选需要能够实际降低预算：局部复用保留的余量过大时，可采用独立的完整候选估算；这不是从实测总量中减去局部粗估。只有需要降低预算的删除候选才比较两条路径，普通追加/局部替换不重复全量估算。
- 已实测的相同 reasoning 可按摘要复用；新增 reasoning 使用对应输出实测上界，不能把密文长度视为 token。无可用上界时明确计入未知成本保护。附件候选使用无上传副作用的来源预算，与已知历史成本隔离；最终渲染后重新匹配和核对，未知文件使用来源预算或现有文档上限。
- 旧版本保留原有严格校验行为，新 usage 才生成新版本。恢复校验版本、摘要与数量。不同计量身份不复用，新摘要调用不覆盖主对话锚点。
- 候选与最终发送使用同一计量函数；记录模式、实测基数、匹配/新增/保留余量片段数、增量成本和降级原因。未知成本与正常文本估算分别报告。

## 涉及文件与影响

| 范围 | 责任 |
|---|---|
| agent/context/usage_anchor.py 与就近辅助模块 | 版本化内容计量、匹配、验证与估算 |
| agent/conversation.py | 兼容身份、候选与最终计量、请求 capture、日志 |
| agent/tests | 高估反例、重复/修改/删除、恢复、附件/reasoning、最终保护 |

保持 provider capability 边界，不新增厂商分支、不改工具公开契约或模型 prompt。纯 Python 业务逻辑，预期 frozen runtime 分类为 standard，不引入依赖或构建安装包。锚点元信息增长随活跃上下文片段数线性变化，需校验其恢复成本。

## 验证

确定性单测覆盖计量公式、重复计数、局部替换、不可扣减反例、未知推理、旧格式；Conversation 测试覆盖工具变化、新轮次、rollout 恢复、压缩和最终发送保护。项目 backend/frontend/rust 三段门禁全部执行；本阶段不调用真实 LLM、不启动桌面运行态。
