# 125 · 跨会话与跨入口的统一身份

## 状态

CONFIRMED

## 背景

桌宠气泡曾把原会话中自己的回复转述为“它说需要你补张图”，以及“看它这次复述得对不对”。本机通知事实及实际展示回执已确认这两类表达出现，造成通知者与会话回答者是两个主体的体验。现有证据确认症状，不据此断定当时运行版本中的完整成因。

[050 单一人格自定义](../050-single-persona-customization/requirement.md) 已规定唯一朋友与正式通道共用有效人格。本需求补齐跨会话、跨入口的身份承接，以及相关提示词的维护治理。

用户期望所有入口中的她成为一个整体，明确包括人格编辑对话。仅统一名字、语气或替换代词不足以满足该目标。

## 目标

- 用户始终在与同一个朋友交流；会话、渠道、模型和后台任务的变化不产生另一个回答主体。
- 她正确承接自己过去的发言、操作、承诺、提醒、错误及未完成事项。
- 统一身份与事实、来源、权限及信息可见性边界同时成立。
- 公共提示词契约集中维护，各入口按职责复用，避免复制后逐渐分叉。
- 为 Coding Agent 新增或修改相关入口提供明确的项目级维护约束。

## 范围

### 包含

1. 盘点所有代表她对用户发言的入口，包括桌面聊天、气泡通知、语音、IM、定时任务结果、提醒以及人格编辑；明确各入口的职责、提示词来源和公共契约覆盖情况。
2. 盘点历史检索、长期记忆、压缩摘要、通知历史等上下文链路，核对发言人与行为归属在生产、传递和消费过程中的保真性。
3. 对她自己的回复和行动保持连续的主体表达，不把另一个会话中的自己称为第三方。可以自然省略主语，不要求每条输出机械添加“我”。
4. 正确区分用户、自身、外部人物或 Agent、工具及引用内容；不把真实第三方的发言或行为认领为自身。
5. 信息不足时如实表达尚不清楚、未取得细节或无法确认；不虚构查阅、回忆或跨会话全知，不把统一身份解释为权限扩大或自动同步全部上下文。
6. 人格编辑同样由她自然表达，保留编辑功能既有数据、权限和候选应用边界。沉浸式与透明交流均满足身份连续性及真实性要求。
7. 明确公共身份契约、用户人格、任务专用规则、内部处理组件的责任边界；公共规则拥有单一维护来源，消费者按职责复用。
8. 新增项目 Rule，约束 Coding Agent 编辑提示词或新增 Agent／模型调用入口时识别职责、复用应有契约、维护入口清单并验证实际装配及行为。Rule 管开发过程，不复制产品提示词正文。
9. 建立确定性装配验证及行为回归场景，覆盖正常承接、错误修正、信息不足与真实第三方引用。

### 不包含

- 合并会话存储、共享所有上下文，或新增跨用户的数据访问权限。
- 重写已保存的对话、通知原文或历史证据。
- 新增多人格系统，或改变人格候选的确认与应用机制。
- 要求摘要器、记忆抽取器等内部组件扮演她与用户交流；这些组件负责来源与事实保真。
- 通过全局代词替换、固定第一人称模板满足验收。

## 关键信息

- 延续 [050 单一人格自定义](../050-single-persona-customization/requirement.md) 的产品范围。
- 与 [083 透明交流设置](../083-agent-transparency-setting/requirement.md) 的真实性及来源说明边界兼容。
- 通知沿用 [117 统一通知](../117-unified-notifications/requirement.md) 的状态、展示和留痕职责。
- 技术方案需记录入口及上下文消费者清单，分别标注已接入、需调整和不适用及理由；不能仅凭共用模型或人格推断已满足契约。
- 真实模型验证遵守既有 LLM 调用授权和 agent_eval 治理；确定性验证不替代自然语言行为验收。

## 验收条件

- [ ] AC-1：完成发言入口及上下文链路盘点，所有发现的生产入口都有归属和处理结论。
- [ ] AC-2：聊天、通知、语音、IM、定时任务及人格编辑正确承接自身言行，不把其他会话中的自己表述为独立第三方。
- [ ] AC-3：新建会话、跨渠道续聊及切换模型不改变身份归属；自然表达不强制重复身份声明。
- [ ] AC-4：对已取得的历史证据能承接过去的回答、承诺与错误；缺少证据时不虚构细节、读取动作或完成状态。
- [ ] AC-5：真实第三方、工具结果、用户发言及嵌套引用的归属仍然准确，不因统一身份而错误认领。
- [ ] AC-6：人格编辑维持同一主体表达，候选内容不被误认作已生效人格或已经执行的行为；现有权限和数据隔离保持有效。
- [ ] AC-7：公共提示词契约具有单一来源，各消费者按职责复用；验证覆盖实际装配及局部规则冲突，内部处理组件保留来源边界。
- [ ] AC-8：项目 Rule 对相关提示词编辑和新增入口具有明确触发范围、维护责任及验证要求，并与现有 Rule 和 Codex adapter 一致。
- [ ] AC-9：两类已确认气泡症状及跨入口、信息不足、第三方引用等行为完成回归验证；执行范围、模型配置、结果和局限可追溯，用户确认验收完成。
