# 053 · 桌面端统一系统权限管理与申请交互

## 状态

CONFIRMED

## 背景

agent-friend 已经具备语音通话和语音输入能力，两者都需要访问系统麦克风。当前权限申请仍跟随具体功能发生：语音输入直接请求麦克风，语音通话则在 RTC 链路中启用设备。随着未来继续增加相机、屏幕录制、通知、辅助功能等能力，如果每个业务模块继续自行检查和申请权限，用户会在使用过程中突然面对来源、说明和恢复方式各不相同的系统弹窗，代码中也会出现多套状态判断与错误处理。

权限不是某个业务功能内部的一次性前置步骤，而是桌面壳需要长期管理的基础能力。应用需要知道当前版本涉及哪些系统权限、用户已经处理过哪些权限、系统当前是否仍然授权，并在首次启动、版本升级、权限被撤销和用户实际调用功能等场景中保持一致行为。

本需求建立统一的系统权限管理与申请体验。用户从统一入口主动开始授权后，应用集中计算当前需要处理的全部权限，并按统一流程向操作系统逐项申请；业务模块不再各自触发系统授权。同时，统一权限模块维护并分发权限状态，成为所有窗口和业务功能获取系统权限状态的唯一来源。

## 目标

- 提供统一、可预期的系统权限说明和集中申请流程，避免业务功能在使用过程中各自突然申请权限。
- 用户点击统一入口的“开始授权”后，一次性处理当前版本需要且当前尚未完成处理的全部系统权限。
- 已授权权限不重复申请；版本升级只补充新增权限；权限失效或被撤销后能重新进入恢复流程。
- 由统一权限模块闭环权限注册、状态检测、申请、刷新、恢复指引和状态分发。
- 所有窗口和业务模块读取同一份权限状态，不各自探测、缓存或推断系统权限。
- 用户拒绝或暂不处理可选权限后记住选择，不在每次启动反复打扰；用户真正使用相关功能时仍可重新进入统一权限流程。
- 权限补齐后，在原动作仍然有效的前提下，尽量恢复用户原本要执行的操作。
- 保持清晰的麦克风使用边界：只有用户明确开始语音功能时才采集，结束或失败后立即释放，不在后台持续占用。

## 范围

### 包含

#### 统一权限入口与集中申请

- 提供由桌面壳统一承载的系统权限准备入口，而不是由语音通话、语音输入等业务功能分别展示申请交互。
- 当存在一项或多项待处理权限时，集中说明这些权限的用途、涉及的功能以及不授权的影响。
- 用户明确点击“开始授权”后，应用计算当前版本已登记、当前需要处理的全部系统权限，并统一编排后续系统授权。
- 一次集中申请中，已授权权限直接跳过，不重复触发系统弹窗。
- 多项权限需要申请时，系统弹窗按可理解、不会互相叠加的顺序逐项出现。
- 申请完成后集中展示结果，包括已授权项、未授权项、暂不可用项以及可以前往系统设置恢复的项目。
- 用户关闭说明、拒绝可选权限或选择暂不处理时，应用不在后台继续触发系统申请。

#### 权限生命周期触发

统一权限流程至少覆盖以下场景：

1. 首次启动时，当前版本登记的系统权限尚未处理。
2. 应用升级后，新版本引入了新的系统权限。
3. 用户此前已经授权，但后来从系统设置中关闭或撤销权限。
4. 用户调用功能时发现所需权限缺失。
5. 应用启动、恢复、重新显示或重新聚焦后，检测到系统权限状态变化。

首次启动和版本升级是集中准备权限的主要入口；功能调用时发现权限缺失是兜底入口。业务功能不得因为进入兜底场景而自行申请权限，而应把用户带回同一套统一权限流程。

#### 统一权限状态

- 统一权限模块是系统权限状态的唯一权威来源。
- 权限状态同时反映系统当前状态和应用已知的处理历史，使产品至少能够表达：
  - 从未申请或尚未处理；
  - 已授权；
  - 用户已拒绝；
  - 曾经授权、之后被撤销；
  - 受到系统或设备策略限制；
  - 当前平台、系统版本或设备不支持；
  - 无法再次直接申请，但可以前往系统设置恢复；
  - 暂时无法可靠判断，需要重新刷新或验证。
- “曾授权后被撤销”允许由应用历史与当前系统状态共同判断，不要求所有平台都提供同名原生状态。
- 不得把未知、无法读取或平台不支持误报为“已授权”。
- 应用启动、恢复、重新显示或重新聚焦后，统一权限模块应刷新可能已经变化的状态。
- 统一权限模块应向所有已打开窗口和业务使用方分发状态变化，避免不同窗口看到互相矛盾的结果。

#### 业务模块接入边界

- 业务模块只声明当前功能或动作依赖哪些系统权限，并从统一权限模块读取或订阅状态。
- 业务模块不得直接调用操作系统权限 API、WebView 权限 API，或通过打开设备来自行申请、判断权限。
- 业务模块不得维护与统一权限模块并行的权限真相源。
- 权限缺失时，业务模块请求统一权限流程介入；权限满足后，由原业务模块决定是否继续仍然有效的待执行动作。
- 用户已经取消、窗口已经关闭、请求已经过期或状态已经变化时，不得因为稍后获得授权而误执行旧动作。
- 多个窗口或功能同时请求权限时，只允许存在一个统一申请流程；不得叠加系统弹窗或重复申请同一权限。

#### 权限状态变化后的业务反应

- 权限被系统撤销后，统一权限模块刷新并通知所有使用方。
- 尚未开始的受影响功能应停止进入设备使用阶段，并提供统一恢复入口。
- 正在使用权限的功能发现权限失效时，应安全停止相关能力并释放设备或系统资源。
- 权限重新满足后，使用方能够基于统一状态恢复可用性，不要求应用整体重启。

#### 设置与恢复入口

- 设置中心提供长期可见的系统权限管理入口，展示当前版本登记的权限、用途和当前状态。
- 对已拒绝、已撤销或无法再次直接申请的权限，提供清晰、可执行的恢复说明。
- 平台支持时，可以从统一入口前往对应的系统设置页面。
- 用户从系统设置返回、应用重新获得焦点或恢复后，状态自动刷新，无需用户手动猜测是否已经生效。

#### 首期麦克风接入

- 首期建立完整的统一权限基础设施和产品交互，并首先登记麦克风权限。
- 现有语音通话和语音输入迁移到统一权限入口和统一状态源。
- 排查并收拢仓库内现有直接申请或隐式触发麦克风权限的路径。
- 语音通话和语音输入不得再各自维护麦克风权限判断或申请流程。
- 麦克风属于可选能力：用户拒绝或暂不处理时，文字聊天及其他不依赖麦克风的功能继续可用。
- 用户明确开始语音通话或语音输入前，不得因为权限检测、状态刷新或预热而持续打开麦克风。
- 如果申请或验证过程不得不临时打开麦克风，完成、取消、超时或失败后必须立即停止所有轨道并释放相关资源。
- 语音通话结束、语音输入停止、窗口关闭或流程异常时，继续保持现有的设备释放要求。

#### 未来权限扩展边界

- 未来新增相机、屏幕录制、通知、辅助功能等系统权限时，应能接入同一套统一入口、生命周期和状态分发语义。
- 新权限可以拥有平台差异、用途说明、申请方式、恢复方式和支持状态，但不应要求业务功能重写统一申请流程。
- 本需求只为未来权限类型保留清晰扩展边界，不提前实现尚不存在的权限功能。

#### 首期平台保证范围

- Windows WebView2 的网页来源权限与 Windows 系统隐私设置可能同时影响最终可用性，统一状态需要避免只依据其中一层得出错误结论。
- 首期正式实现和验收只保证 Windows 桌面端；Windows 的权限查询、集中申请、恢复和生命周期刷新属于本需求交付范围。
- macOS 不属于本期实现、编译验证、实机 smoke 或可用性保证范围；统一权限模块仍保留平台 adapter 边界，但 macOS 在本期应明确返回 `unsupported`，不得保留业务模块直接申请系统权限的旁路。
- 对平台无法可靠区分的状态，应如实降级为未知、受限或需要验证，不伪造精确结论。

### Cloudflare Quick Tunnel 边界

Cloudflare Quick Tunnel 是语音通话依赖的产品隐私确认，不是操作系统权限，不进入系统权限注册表，也不成为系统权限状态的一部分。

语音通话可以在更上层的“能力准备”体验中同时检查麦克风权限和 Quick Tunnel 隐私确认，但必须明确区分：

- 麦克风是由操作系统控制的系统权限；
- Quick Tunnel 是用户是否同意建立外部临时公网通道的产品隐私选择。

两者不得共用状态枚举、申请 API、历史字段或误导性文案。本期可以保持现有 Quick Tunnel 确认流程，只要求它与统一系统权限流程组合时不互相冒充。

### 不包含

- 不在首期实现相机、屏幕录制、通知、辅助功能或其他尚未被产品使用的系统权限。
- 不把 Cloudflare Quick Tunnel 隐私确认建模为系统权限。
- 不把 API 凭证、模型配置、开机自启、主题或其他普通设置纳入系统权限管理。
- 不改变语音交互“用户显式触发、不做后台持续监听”的项目级姿态。
- 不建设与当前需求无关的通用插件系统或跨产品权限框架。
- 不实现或验收 macOS 麦克风权限 adapter；该平台后续作为独立需求接入统一权限边界。
- 不在需求阶段锁定平台 API、具体数据结构、跨窗口协议、组件形态或持久化实现；这些由 `design.md` 基于平台调研确定。

## 验收标准

- [x] 首次启动且当前版本存在尚未处理的系统权限时，出现统一权限说明入口；用户未点击“开始授权”前不触发系统权限弹窗。
- [x] 用户点击“开始授权”后，应用集中处理当前版本需要且当前尚未完成处理的全部系统权限，已授权权限不会重复申请。
- [x] 多项待处理权限按统一顺序逐项申请，不出现叠加或互相竞争的系统弹窗。
- [x] 应用升级并新增权限后，只提示和处理新增或重新失效的权限，不重复申请仍然有效的既有权限。
- [x] 用户跳过或拒绝可选权限后，应用记住本次处理结果，不在每次启动重复打扰；设置中心和相关功能仍可重新进入统一流程。
- [x] 统一权限模块能够表达未处理、已授权、已拒绝、曾授权后撤销、系统限制、不支持、可前往设置恢复和未知等产品状态。
- [x] 所有窗口和业务模块从统一权限模块读取或订阅权限状态；不存在第二套业务侧权限真相源。
- [x] 应用启动、恢复、重新显示或重新聚焦后能够刷新权限状态，并向已打开窗口和使用方分发变化。
- [x] 用户从系统设置撤销麦克风权限后，应用刷新为非授权状态，语音通话和语音输入均不再把麦克风视为可用。
- [x] 用户从系统设置恢复麦克风权限并返回应用后，统一状态能够更新，相关功能无需整体重启即可恢复可用。
- [x] 语音通话和语音输入不再各自直接发起系统权限申请，而是声明麦克风依赖并使用统一状态与统一入口。
- [x] 功能触发时发现权限缺失，只会进入统一权限流程；权限满足且原请求仍有效时，可以继续原动作，不会重复执行或执行已取消动作。
- [x] 多窗口或多个功能同时请求麦克风权限时只有一个申请流程，不重复触发系统弹窗。
- [x] 权限检测和刷新不会在后台持续占用麦克风；任何临时打开的媒体流在完成、取消、超时或失败后立即释放。
- [x] 语音通话结束、语音输入停止及相关错误路径均会释放麦克风，不遗留后台采集。
- [x] 设置中心提供系统权限状态与恢复入口；平台支持时可前往相应系统设置页面。
- [x] Quick Tunnel 在交互和状态中被明确标识为产品隐私确认，不被展示或分发为操作系统权限。
- [x] Windows WebView2 profile 与 Windows 系统隐私状态的双层差异有真实验证记录；无法可靠区分的状态不会被误报为已授权。
- [x] 核心状态归一化、集中申请编排、并发单飞、状态刷新与分发、动作恢复和资源释放具有自动化测试覆盖。
- [x] 项目全量门禁通过。
