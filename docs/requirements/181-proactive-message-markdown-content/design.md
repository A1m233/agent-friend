# 181 · 主动消息正文与 Markdown 图片说明 - 技术方案

## 状态

CONFIRMED

## 需求文档

[requirement.md](./requirement.md)

## 现状分析

`SendConversationMessageTool` 是普通会话和自主活动共用的工具定义。`ToolRegistry` 使用同一 Draft 7 schema 生成模型工具参数并在执行前校验；未知字段会返回现有 `invalid_arguments`，不会进入投递服务。

`SessionDeliveryService` 把已接受的投递存入持久队列，消费者分别完成助手消息写入及 IM 通知。旧请求中的附件已经解析为受管资产引用，消费时无需再次经过公开工具参数校验。

本次采用用户于 2026-11-22 确认的 v1 工具定义候选。实现仅收窄模型公开输入，沿用既有参数拒绝及持久队列机制。

## 方案设计

### 涉及文件

| 文件路径 | 改动类型 | 说明 |
|---|---|---|
| `agent/src/agent/tools/builtin/conversation_access/delivery.py` | 修改 | 应用已确认的工具说明、正文说明及 schema 删除 |
| `agent/tests/test_conversation_delivery_tool.py` | 新增测试 | provider 工具定义、旧参数拒绝及修正调用 |
| `agent_bridge/tests/test_session_delivery_service.py` | 补充测试 | 真实投递服务中的正文、角色、重启及旧附件队列 |

### 公开工具定义

删除 `properties.attachment_asset_ids` 和对应 `dependencies`。保留根对象 `additionalProperties: false`；旧字段即使为 `[]` 或 `null` 也属于未知字段，不能被静默忽略。

工具说明中原来的附件引用和 IM 单张图片支持说明替换为：

> 仅发送正文，不支持附带图片或文件。

`content.description` 使用用户确认的完整文本（实际为连续字符串，以下换行仅用于阅读）：

```text
已经完成的最终消息正文；不能填要求目标Agent继续执行的指令。
需要展示图片时，在正文中使用 Markdown 图片语法 ![图片说明](图片地址)。
图片地址须可被接收端直接访问；本地路径、asset_id 和 file_ref 不会自动转换为可见图片。
QQ 等 IM 端不保证显示 Markdown 图片，不要把消息发送成功当作图片已展示。
```

其余工具定义与公共提示词维持原文。工具执行仍通过既有注册表；不引入第二套参数校验或新的模型可见错误文案。

### 投递与兼容

正文沿既有调用链写为 `assistant_message`，并按现有通知策略交给 IM。此处不解析 Markdown，不从正文提取图片或发起上传。

保留宿主内部附件处理、持久队列的附件数据、历史投影和 QQ 原生图片发送能力，以处理升级前已接受的请求及其他既有消费者。公开工具的字段移除不要求迁移或清理历史数据。内部服务不是模型可绕过注册表直接调用的新工具。

### 验证

- 核对共享 Chat 工具定义及实际 Responses 请求投影均不含旧字段，保持其余参数分支。
- 使用旧字段的调用须在触达 submit 前失败；删除旧字段后，同一正文可正常提交。
- 经注册表到真实投递服务验证 Markdown 图片、代码示例和转义文本原样保留，助手身份和防重投保持不变，IM 不自动携带图片对象。
- 直接构造升级前已持久化的附件请求，重建服务后完成一次投递；再次读取历史及再次消费不得丢图或重复发送。
- 用已确认的固定样例重新捕获普通会话和自主活动的完整模型输入，与 v1 候选逐字比较；真实模型和客户端行为不由离线结果代替。
- 按项目 `scripts/check` 执行 backend、frontend、rust 门禁。

## 影响分析

此次纯工具契约与业务测试变更归类为 `standard`，无依赖、资源装载、冻结运行时或平台原生行为变化；不需要构建安装包或启动桌面端。

主要限制已在需求中确认：取消附件参数会收起对应的主动原生图片发送能力，Markdown 不提供跨渠道可见性保证。该限制由 issue 075 跟踪，本次不扩展到正文图片转换。
