# 181 · 主动消息正文与 Markdown 图片说明

## 状态

CONFIRMED

## 背景

主动发送工具当前允许把已有图片或文件作为附件投递到另一用户会话。桌面将附件作为助手正文前的独立卡片展示，QQ 则依赖独立的原生图片上传路径。用户希望 AF 把图片表达放在自己发送的消息正文中，同时暂缓解决桌面与 QQ 的统一图片交付问题。

本次收窄主动发送的能力面，移除附件参数，并准确说明 Markdown 图片的用法和可见性边界。跨渠道兼容问题已登记为 [issue 075](../../issues/075-cross-channel-proactive-image-delivery/README.md)。

## 目标

- AF 使用主动发送工具时只提交消息正文及必要的目标、通知和来源信息，不再通过附件参数发送图片或文件。
- AF 知道可以在正文中使用 `![图片说明](图片地址)` 表达图片，并理解图片地址须可被接收端访问。
- 能力调整不破坏历史消息、升级前已入队的投递以及其他既有发送能力。

## 范围

### 包含

- 从 `send_conversation_message` 的公开能力中移除 `attachment_asset_ids`，并对继续使用该参数的新调用给出明确拒绝。
- 调整模型可见的工具说明和正文参数说明，解释 Markdown 图片用法及渠道限制。
- 保留消息的助手身份、文字投递、排队和通知语义。
- 保持历史附件可读取，以及升级前已接受投递的处理能力。

### 不包含

- 将本地路径、附件 ID 或受管文件引用自动转换为桌面可见图片或 QQ 原生图片。
- 解析正文图片并自动执行上传、图片传输或跨渠道格式替换。
- 修改用户输入附件、正常生图回复或现有图片查看能力。
- 解决 TIM 对既有 Markdown 通知消息的兼容问题，见 [issue 074](../../issues/074-tim-markdown-notification-unreadable/README.md)。

## 关键信息

移除附件参数意味着本期收起原先通过该参数主动向 QQ 发送原生图片的能力。Markdown 图片是否可见取决于图片地址可访问性及接收端支持，本需求不承诺仅添加 Markdown 语法即可在所有渠道显示图片。

模型可见内容的具体措辞须在方案阶段提供现行输入、候选输入及逐字差异，经用户确认后实施。

## 验收条件

- [x] AC-1：模型收到的主动发送工具定义不含 `attachment_asset_ids`，新调用携带旧参数时被明确拒绝，不能静默忽略并返回成功。
- [x] AC-2：工具说明包含 Markdown 图片写法、可访问地址要求和渠道限制，不承诺上传或传输本地图片。
- [x] AC-3：正文中的 Markdown 保持原文和顺序；投递结果仍为助手消息，现有文字通知、排队和防重复行为不回归。
- [x] AC-4：历史附件消息与升级前已入队的带附件消息仍能按原有契约读取或处理，正常生图回复与用户输入附件不受影响。
- [x] AC-5：模型可见输入与用户确认的候选版本一致，相关确定性测试及项目检查通过；没有执行的真实客户端或模型验证明确标记为未验证。
