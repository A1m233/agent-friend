# 058 · Spine 桌宠拖拽朝向与转身过渡

## 状态

CONFIRMED

## 背景

当前明日方舟 Spine 桌宠已经支持拖拽跟手，并在拖拽开始时播放 `Move` 动画、松手后回到常态动画。但无论用户向左还是向右拖，模型始终保持资源默认的朝右姿态，拖拽方向与角色朝向不一致。

现有 Spine 资源也不包含独立的 `Turn`、`FaceLeft` 或 `FaceRight` 动画。项目内首批 14 个明日方舟模型只有 `Default`、`Interact`、`Move`、`Relax`、`Sit`、`Sleep` 等基础动画，因此不能依赖资源中现成的转身动作解决问题。

本需求让 Spine 桌宠根据用户的水平拖拽方向自然改变朝向，并记住最后朝向。转身的视觉表现作为独立、可迭代的能力边界；首版采用平滑水平翻转，后续可以单独调整或替换效果，而不改变拖拽方向判定和持久化语义。

## 目标

- 用户向左拖动 Spine 桌宠时，桌宠朝左；向右拖动时，桌宠朝右。
- 同一次拖拽中改变水平方向时，桌宠能够跟随新的稳定方向再次转身。
- 避免轻微手抖、输入噪声和近乎垂直的拖拽造成频繁翻面。
- 松手后保持最后朝向，并在应用重启、模型切换后恢复。
- 首版以平滑水平翻转表现转身，且转身效果可以独立迭代。
- 保持既有拖拽动画、位置持久化、点击命中、透明穿透、ActionBar 与气泡锚点行为稳定。

## 范围

### 包含

#### 拖拽方向决定朝向

- Spine 桌宠具有“朝左”和“朝右”两种稳定朝向。
- 当前朝右时，用户产生明确的向左水平拖拽后，桌宠切换为朝左；当前朝左时向右拖拽同理。
- 朝向依据拖拽过程中的有效水平移动决定，而不是只在拖拽结束后根据最终位置决定。
- 同一次拖拽中，如果用户明显反向移动，桌宠应切换到新的方向。
- 近乎垂直的拖拽、未超过拖拽阈值的移动和小幅水平抖动不改变朝向。
- 朝向改变不能中断桌宠位置跟手；转身期间桌宠仍应继续随指针移动。

#### 松手后保持朝向

- 拖拽结束后，桌宠保持最后一个稳定朝向，不自动恢复到默认朝右。
- 点击、普通状态动画以及 `Move` 结束后的常态动画继续使用当前朝向。
- 没有发生有效水平拖拽时，桌宠保持原朝向。

#### 朝向持久化

- 朝向作为桌宠全局偏好持久化，不按模型分别保存。
- 切换不同明日方舟 Spine 模型后，新模型继续使用当前全局朝向。
- 切换到不消费该朝向的 avatar backend 后，已保存朝向仍被保留；再次切回 Spine 时恢复。
- 应用重启后恢复最后保存的朝向。
- 已有用户的持久化数据没有朝向字段时，默认朝右，且已有桌宠位置数据继续生效。
- 持久化数据缺失或朝向值无效时安全回退到朝右，不导致桌宠窗口不可用。
- 持久化失败不能阻断当前拖拽和本次运行中的朝向切换。

#### 独立的转身过渡

- 转身视觉效果与方向判定、持久化语义解耦，后续可以独立调整或替换。
- 首版转身效果采用平滑水平翻转，不依赖 Spine 资源中不存在的独立转身动画。
- 只有稳定朝向发生改变时才触发转身；同一方向上的连续拖拽事件不重复启动过渡。
- 转身过渡需要足够短，不让用户感到桌宠拖拽滞后；具体时长与缓动在技术方案和真实桌面端验收中确定。
- 从持久化状态恢复、切换模型或首次加载时直接以已保存朝向显示，不播放一次无用户意图的转身过渡。
- 转身过程中不得出现长期压扁、消失、错误偏移或持续闪烁；快速反向拖拽时应稳定收敛到最后方向。

#### Spine 模型与既有能力兼容

- 首批 14 个内置明日方舟 Spine 模型均采用同一朝向语义，不能为单个模型散落专用判断。
- 现有拖拽开始 `Move`、拖拽结束返回常态的动作语义保持不变；朝向切换不要求新增资源动画。
- 水平翻转不能破坏：
  - 桌宠拖拽位置与跨屏行为。
  - sprite 可见边界与屏幕区域上报。
  - alpha hit-test 与透明区域鼠标穿透。
  - ActionBar 相对桌宠的定位与交互。
  - bubble anchor 与对话气泡跟随。
  - normal / mini 尺寸及贴边、恢复行为。
- Live2D 的 gaze、拖拽参数反馈和现有渲染行为不在本需求中改变。

#### 真实桌面端验收

- 本需求需要在真实 Tauri 桌面端完成拖拽与视觉验收，不能只用 Vite Web 页面证明效果正确。
- 验收至少覆盖左右拖拽、同次拖拽反向、垂直拖拽、快速反向、松手保持、模型切换和应用重启恢复。
- 验收时同时观察透明命中区域、ActionBar 与气泡锚点，确认水平翻转没有造成可见偏移或交互错位。

### 不包含

- 不制作或修改 `.skel`、`.atlas`、贴图等明日方舟模型资源。
- 不新增 `Turn`、`FaceLeft`、`FaceRight` 等资源动画。
- 不在本期复刻明日方舟原作的具体转身曲线或特效；首版只要求平滑水平翻转。
- 不为朝向增加设置项、手动翻转按钮或模型级独立配置。
- 不让 gaze、角色自动移动、窗口位置或其他非拖拽事件自动改变朝向。
- 不改变 Live2D 桌宠的朝向与拖拽反馈行为。
- 不重做 Spine avatar runtime、模型 catalog、模型导入或模型缩放能力。

## 关键约束

- 朝向的用户语义是桌宠全局状态，具体数据结构与存储接口由技术方案确定。
- 转身效果必须具备独立边界，但不为未来效果预建通用动画插件系统。
- 方向判定应对拖拽输入噪声稳定，具体阈值与判定策略由技术方案和真实交互验证确定。
- 当前 Spine 外层的 bounds、命中测试、锚点和尺寸计算已有稳定行为；实现朝向时不能把负尺寸或镜像后的临时坐标泄漏给这些调用方。
- 旧版持久化数据必须向后兼容，不能要求用户重置桌宠位置或设置文件。

## 验收标准

- [ ] 桌宠当前朝右时，明确向左拖拽会触发一次平滑转身并稳定朝左；当前朝左时向右拖拽同理。
- [ ] 同一次拖拽中明显反向移动时，桌宠能够再次转身并最终朝向最后一个稳定水平方向。
- [ ] 近乎垂直的拖拽、小于有效阈值的移动和水平抖动不会让桌宠频繁翻面。
- [ ] 转身期间桌宠持续跟手，没有可感知的拖拽冻结或位置跳变。
- [ ] 松手后保持最后朝向；后续 `Move`、常态和交互动画均沿用该朝向。
- [ ] 朝向作为桌宠全局状态持久化；切换不同内置明日方舟模型以及应用重启后均能恢复。
- [ ] 旧版只含位置锚点的持久化数据继续可读，缺失或非法朝向安全回退到朝右。
- [ ] 首次加载和从持久化状态恢复时直接以目标朝向显示，不额外播放转身过渡。
- [ ] 转身过渡具有独立边界，首版平滑水平翻转不依赖资源中的独立转身动画。
- [ ] 首批 14 个内置明日方舟 Spine 模型的朝向、拖拽和转身行为一致。
- [ ] Live2D 桌宠的现有拖拽反馈和渲染行为不发生变化。
- [ ] 朝向切换后，sprite bounds、alpha hit-test、鼠标穿透、ActionBar、bubble anchor、normal / mini 与贴边恢复没有回归。
- [ ] 方向判定、抖动抑制、快速反向、持久化兼容和转身状态收敛有自动化测试覆盖。
- [ ] 完成真实 Tauri 桌面端 smoke，覆盖左右拖拽、同次反向、垂直拖拽、快速反向、松手保持、模型切换、重启恢复及锚点/命中检查。
- [ ] `./scripts/check` 全量门禁通过。

## 开放问题

- 有效水平移动的阈值、垂直拖拽判定与快速反向时的稳定策略，需要在技术方案阶段结合现有拖拽事件频率确定。
- 平滑水平翻转的具体时长、缓动和被反向输入打断时的收敛方式，需要在技术方案与真实桌面验收中确定。
- 朝向变换应位于 Spine display tree 的哪一层，才能在保持外层正向 bounds 语义的同时避免视觉中心偏移，需要在技术方案阶段结合现有 fit、anchor 与 alpha hit-test 链路确认。
- 桌宠朝向写入现有 UI 状态存储时的更新粒度和失败恢复方式，需要在技术方案阶段沿当前位置持久化边界确定。
