## 用完 skill 后发现的缺口

1. **查看发言还要查看触发来源。** 当前 AF 的 `read_conversation` 会过滤有 `payload.request_source.kind` 的合成用户输入。核查定时任务时，能访问原始事件的一端可查触发元数据；只有聊天检索时应标注无法确认当轮为人工发言。39 条定时来源的经历以“用户”开头，本次仅就其中 4 条明确声称当日发消息的经历核实了错误，不能把 39 条全部判错。[业务消息过滤](../../../../agent/src/agent/sessions/message_access.py#L27)
2. **给出旧来源的解析路径。** 1,111 条有效普通事实中，758 条有直接事件引用，305 条只有经历 ID，均能先找到对应经历，再沿 `source_ref` 定位会话。另 48 条自身来源列表为空，其中 7 条所在变更组仍有非空来源。找到引用、找到原话和原话支持命题，应该分别记录。空列表本身不能证明原命题错误。
3. **合并前检查依赖，核对跨层的部分重复。** Episodic 的 ID 可能被 Semantic 引用；Core 与一个包含多个命题的 Semantic 也可能只重复一个字段。建议先列出独有信息与反向引用，再决定改哪些成员。复查历史报告时，先读当前状态以免重复处置已退役条目。

本机私有证据目录保留快照指纹、完整目标 ID、事件锚点、可复算统计和各条建议。此报告省略账号、实际值、会话 ID 和完整原话。
