# PDF 会话文件输入与上下文预算

## 状态

CONFIRMED

## 背景

需求 142 已提供本会话上传文件的发现、原件校验和工作目录接入，支持跨轮、压缩与重启后重取。但现有 PDF 默认投递仍会把完整文件或厂商抽取的全文加入模型请求；未退出模型历史的附件还会被再次投递。文件可在工作目录中处理，并未改变默认模型输入方式。

现有文档预算以源文件字节数估算并设置单份 64,000 token 封顶，渲染后的原生文件也存在同值兜底。这既不能反映 PDF 实际解析成本，也会把未送入模型的文件误计为上下文。仅删除封顶、继续按 PDF 字节数估算，仍可能造成过早压缩或错误拒绝。

本需求在 142 的文件能力和 123 的真实用量锚点基础上，统一 PDF 默认处理方式及相关预算语义。059、123、142 保留为历史交付记录。

## 目标

- 用户上传 PDF 后，Agent 默认通过会话文件能力按任务需要读取，避免完整原件自动占用模型窗口。
- 上下文预算反映真正进入模型的文件提示、读取结果及其他输入，不受单份文档 64k 人为封顶影响。
- 新上传、历史重放、编辑重发、压缩及重启后的文件处理保持一致，用户无需重新上传有效原件。
- 文件可接收、文本可读取和视觉内容可理解的能力边界清晰，失败时提供可行动的反馈。

## 范围

### 包含

- PDF 默认采用会话文件方式；首轮及后续请求提供可操作的文件提示，按任务需要读取正文或页面。
- 桌面对话、AG-UI 和既有 IM 附件入口，以及仅附件消息、混合附件、编辑重发和旧会话兼容。
- 上传准入区分应用可处理的会话文件与模型可直接消费的原生附件，避免文本模型仅因缺少原生 PDF 能力而无法使用可提取文本的 PDF。
- 所有文档估算路径移除单份 64k 封顶或同义固定上界；PDF 文件方式、实际投递的文本、原生文件及真实 usage 分别按其实际含义处理。
- 投递方式变化时，旧原生文件的预算与用量校准不得错误继承到新的文件方式。
- 文本 PDF、扫描件与包含图表的 PDF 的读取边界、失败反馈及相关验证。
- 保持 142 已有的原件保护、来源身份、会话隔离、文件大小与工作目录容量约束。

### 不包含

- 400k 变成 250k 的模型配置问题。
- 修改 PDF skill、扩展可上传格式、增加项目概念或重建会话工作目录能力。
- 改变图片附件的默认投递方式；PDF 以外文档的默认投递方式也不在本期切换范围。
- 重做全局 tokenizer、承诺所有 provider 的原生文件都能精确预估，或调整模型窗口、输出预留和误差缓冲政策。
- 新的通用 OCR 服务、跨 provider 自动转交文件、文件管理或复杂 PDF 预览界面。

## 需求

- **R-1 默认按需读取**：添加 PDF 不自动将完整文件、Base64 或抽取全文送入模型。模型收到足以识别本轮附件并使用已有文件能力的提示；用户要求处理整份文档时，应支持分段处理，不能把局部读取冒充全文完成。
- **R-2 持久可恢复**：新旧会话都保留有效原件与来源关系；上下文压缩不影响后续可信重取，文件处理失败不能破坏会话继续使用。
- **R-3 准入一致**：各入口采用一致的实际处理能力与限制。可读取文本的 PDF 不必依赖模型的原生 PDF 输入能力；本地处理不可用时明确说明，不能接收后静默丢弃。
- **R-4 真实输入预算**：文件方式只计算实际投递的文件提示与读取结果。实际进入模型的文档文本不得按单份 64k 封顶，也不能以 PDF 源文件大小、Base64 长度或文件标识长度替代其解析后成本。未知原生成本不得伪装成已知安全上界。
- **R-5 用量隔离与恢复**：兼容的真实 usage 继续用于校准；投递方式、模型或请求内容变化后，不复用不兼容的旧计量依据。取消、重试、压缩和超窗恢复仍保持有界且可诊断。
- **R-6 视觉边界明确**：需要理解扫描内容、布局或图表时，应使用当前模型实际支持的视觉读取能力。无法完成时说明限制及可行下一步，不从空文本或文件名编造内容，也不自动退回整份 PDF 原生投递。是否保留显式原生入口在方案阶段评估。
- **R-7 来源与可观测性**：文件提示、工具结果及文档正文保持数据来源边界；文档中的指令不能覆盖用户请求。诊断信息能够解释实际投递方式、估算依据与触发压缩原因，不增加附件正文的默认记录。

## 验收条件

- [ ] **AC-1**：有效大 PDF 在首轮模型请求中仅产生文件提示，不包含完整 PDF 或全文；文件字节增大本身不会导致错误超窗拒绝或压缩。
- [ ] **AC-2**：模型能够发现并准备本轮 PDF，通过既有读取能力取得指定页或内容；整份文档任务有分段处理与完成范围的验证。
- [ ] **AC-3**：续轮、历史重放、编辑重发、压缩及重启后继续采用同一默认方式，旧会话无需重传有效原件。
- [ ] **AC-4**：桌面、AG-UI 和 IM 的准入及失败语义一致；覆盖仅附件、混合图片与 PDF、模型切换、本地处理不可用和文件超限。
- [ ] **AC-5**：具有文件工具能力但不支持原生文档输入的模型可处理文本层 PDF；不会因此放开其不支持的图片等原生输入。
- [ ] **AC-6**：全部文档预算入口不再使用单份 64k 封顶；实际大于 64k 的可见文档文本或读取结果不会被压到 64k，文件提示与工具输出不漏算、不重复计入。
- [ ] **AC-7**：首轮、无 usage、新增附件、兼容锚点及旧原生锚点迁移均有确定性回归；未知原生成本不按虚构上界作安全判断，真正超窗时仍可恢复或明确失败。
- [ ] **AC-8**：扫描件及图表分别覆盖可用视觉路由和不可用路由；未获得视觉证据时不宣称理解，不自动发送整份原件作为回退。
- [ ] **AC-9**：原件缺失或损坏、同名文件、会话隔离、工作目录容量与只读副本行为保持 142 的约束。
- [ ] **AC-10**：诊断记录可以对账投递方式、估算依据、usage 与压缩触发；不包含新增的私有正文或凭据。
- [ ] **AC-11**：受影响自动化测试和项目检查通过。真实模型、桌面交互及跨平台观察分别记录证据与未验证边界，并由用户确认验收完成。
