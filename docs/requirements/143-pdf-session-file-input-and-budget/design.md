# PDF 会话文件输入与上下文预算 - 技术方案

## 状态
CONFIRMED

## 需求文档
[requirement.md](./requirement.md)

## 现状与职责

AttachmentStore 与持久用户事件拥有原件和引用；142 的 session_files 拥有发现、会话授权、完整性校验及工作副本准备。Conversation 负责上下文选择和预算；MultimodalInputAdapter 负责厂商投递。当前 PDF 在 adapter 中被完整发送或抽取，候选预算却按源文件字节数并封顶 64k。

## 方案

### 统一模型输入投影

在 agent/attachments 内实现小型投影组件，由 Bridge 注入 SessionManager 和 Conversation。投影只生成模型视图副本，不修改业务事件、附件资产、消息 UUID 或引用顺序。预算估算与最终 renderer 调用相同投影；首轮、工具续轮、编辑重发及旧会话统一覆盖。

PDF 只生成有界元数据和使用 session_files 的提示，不打开 PDF 正文、不上传、不自动准备副本。名称等用户字段通过结构化编码保持数据边界。Agent 使用现有 list/prepare、命令和按需激活的 Skill；不修改 PDF skill。缺少实际文件工具时明确说明不可读取，不回退到整份文件。

TXT 保持全文文本输入语义，在本地按已支持的 UTF-8 解码后进入同一投影，使估算与最终正文一致。候选计算不调用厂商上传或抽取接口。单次装配复用已验证的文本读取结果，避免每个裁剪候选重复读取大文本；缓存必须有界且绑定资产身份。图片保留既有厂商投递与预算规则。

摘要与模型历史仍保留可追溯身份；不把 PDF 正文或 Base64 写入会话。模型投影幂等，避免重放时反复追加提示；压缩 checkpoint 继续使用既有消息身份。

### 应用上传能力与模型原生能力

新增共享附件输入策略：由原生模型能力、资产库限制及本地文件工具可用性派生应用可接收类型和逐类型限制。原生模型能力字段不被伪装成支持 PDF；模型目录另提供应用附件输入信息。

PDF 使用会话文件路径，要求持久会话、资产服务、session_files、命令能力及模型工具调用能力。可修复的沙箱未初始化状态沿用现有初始化流程，不误判成永久不支持。图片和 TXT 继续服从原生模型能力。单轮产品限制沿用最多 10 个、总量 100 MiB；各原生输入子集继续受厂商限制，PDF 单文件复用 142 的 100 MiB 边界。

桌面 Composer、草稿兼容性、AG-UI、编辑重发和 IM 共用该策略。模型切换保留草稿，重新计算可发送性。工具在接收后失效时返回可行动错误，保留资产；不默默转换为原生 PDF。

### 文档成本与用量迁移

移除 budget、usage_anchor、Conversation 中全部文档 64k 常量及兜底。PDF 只计算提示；TXT 按实际投递正文计算；工具读取结果沿用既有文本和图像预算。新附件单独预检与最终请求预检必须使用相同投影，不能保留字节数下限再次推高文件方式预算。

仍遇到无可验证成本的原生文档块时，接入既有 unknown component 语义：兼容实测 usage 可覆盖同一输入；未测量的成本标为未知，使用明确的准入保护而非伪造 64k 或按 Base64/file_id 长度计数。图片 file_id 必须按实际路由区分，避免误判成文档。正常 PDF 流程不再产生原生文档块，也不新增原生 PDF 切换入口。

投影版本进入输入计量兼容身份；旧原生附件锚点不得自动升级为新投影的有效测量。校准因子的持久化与恢复也核对投影/输入类型身份，避免旧多模态因子污染新的文件提示请求。继续以真实 usage 为优先依据，保留现有输出预留、缓冲及有界超窗恢复。

### 视觉内容与错误

文字层按任务范围提取；扫描页和图表通过现有 PDF 运行依赖渲染为图片，再用当前模型支持的 view_image 查看。模型不支持图像工具结果时明确告知视觉限制，不猜测图像内容，不自动发送整份 PDF，不新增 OCR 或跨模型调用。

原件损坏、缺失、目录容量、会话隔离继续由 142 的工具契约负责；新增准入错误区分模型原生类型不支持和本地文件处理不可用。文件提示不授予命令或文件权限。

### 诊断与验证

预算 notes 记录投影版本、投递类型、估算/实测/未知来源及回退原因，不记录新增正文。最终 provider 请求断言不存在 PDF 文件块、PDF Base64 或隐式厂商抽取调用；同时断言实际工具读取结果正常进入模型。

测试覆盖首轮、仅附件、混合附件、历史、压缩、重启、编辑重发、模型切换、文本模型、工具不可用、大小与配额、扫描页视觉可用/不可用、超过 64k 的真实文本、旧锚点与校准恢复、未知原生文件以及图片 file_id。行为验证与确定性机制分别记录；真实 LLM 运行遵守逐次授权。前端先完成自动化检查，真实桌面验收单独依授权执行。

运行 scripts/check 的 backend/frontend/rust 门禁。实现后按实际 diff 核对冻结影响；本能力组合的高风险投影与准入路径须由现有 smoke 覆盖或补齐，再按 frozen-runtime-packaging 规则决定 runtime-only 验证，不构建完整安装包。
