# 模型请求等待与恢复治理

## 状态

CONFIRMED（2026-09-23 用户确认编号与范围）

## 背景

真实长会话中，模型请求在尚未收到响应头时触发统一的 45 秒静默超时，随后自动重试，放大等待时间。现有记录能确认请求阶段超时，却不能充分区分上传、首响应等待和流内静默。另有请求前准备与回答后收尾耗时，需要与网络等待分开归因。

## 目标

建立按请求阶段和业务用途区分的等待、恢复及取消规则，减少正常慢请求被提前中断，又保证无进展任务能够有界结束。所有支持的模型调用入口应具有一致、可解释、可验证的行为。

## 范围

### 包含

- 盘点对话、工具续接、会话压缩、记忆处理、通知、连接检测的实际调用链、默认值、覆盖来源、超时及重试所有者。
- 区分连接建立、上传与首响应等待、流式空闲、业务总时限；明确活动信号与计时重置边界。
- 统一错误归类、重试预算、退避、取消及输出提交后的恢复边界，避免层层重试相乘。
- 保留通知、连接检测等业务入口所需的短时限；不将交互对话的等待策略无差别外推。
- 交互对话及其工具续接不新增整次调用的累计时长硬上限；持续有进展时不因累计时间被中断。有限重试按次数治理。
- 补充实际生效阈值、超时阶段、最后进展、尝试次数与分段耗时的安全诊断证据。
- 盘点请求前准备、回答后收尾、大会话和大请求体对本次体验的影响，独立性能根因需要独立改造时提出平级需求。

### 不包含

- 本期不承诺解决供应商内部排队或推理性能，也不将网络等待自动归责于模型能力。
- 不默认改造会话存储、记忆检索或上下文压缩架构。
- 不新增无实际入口需求的协议，不要求为所有阈值新增用户设置界面。
- 不通过放宽鉴权、权限和业务错误分类实现重试。
- 不自动调用真实付费模型，也不自动安装到 production。

## 验收条件

- [ ] AC-1：形成完整入口与各层时限、覆盖优先级、重试预算的盘点表，无未解释的旧常量或隐含 SDK 限制。
- [ ] AC-2：受控首响应延迟超过旧 45 秒、但仍在新策略允许范围内的请求，不被旧门槛中断；超过有效阶段时限的请求有界失败并准确归类。
- [ ] AC-3：正文、推理与状态等活动的计时语义明确且有测试；模型内部不可见计算、网络字节和有效事件不能混称进展。流内持续活动不因整请求固定计时被误杀。
- [ ] AC-4：连接等待、流式等待、退避和后台调用均可取消；取消后不再启动重试，不遗留本地请求或后台生产任务。
- [ ] AC-5：首输出前、已有正文、部分工具参数、工具执行后等边界的重试有明确策略；不重复提交正文或工具副作用，预算不因跨层恢复重置。
- [ ] AC-6：通知、连接检测、记忆等入口维持各自明确的时限和恢复规则；已有业务总时限能约束多次尝试与退避。交互对话不新增整次调用硬上限，持续活动累计超过 15 分钟的模拟调用仍可完成。
- [ ] AC-7：日志和诊断证据可解释实际阈值、超时阶段、活动与重试；未知阶段如实标记，不新增凭据、完整请求或推理内容泄漏。
- [ ] AC-8：可重复的本地模拟覆盖慢首响应、流内静默、持续推理、断流、取消、重试耗尽及跨入口场景；项目检查通过。真实模型观察如需执行，另按调用授权约定进行。
- [ ] AC-9：对本地准备、收尾和请求体积给出有证据的归因或明确缺口；需另行改造的性能问题列出边界，不以调大超时代替解决。
