## 实现边界

- 默认冷却 60 秒；服务端 Retry-After 更长时遵守更长等待。无空闲计时器，重启/关闭不补发积压。
- 每次后续活动最多处理两段；恢复调用禁用内部重试。协调阶段仍最多一个附加模型调用，因此“两段”不等于“两次物理请求”。
- SQLite 保存私有素材与来源，日志仅记动作和数量。健康活动的序号不能提前释放随后失败轮的素材。
- 原始诊断包未改动；没有迁移或修复用户既有错误 extraction commit，历史素材是否漏记仍需个案证据。
- 修正过载分类后，旧版漏识别而不重试的错误会进入既有预算：前台可能由一次尝试变为最多六次（首次 + 五次退避重试，仍受取消、输出安全和调用方更小预算约束）。本期减少失败通知及记忆附加流量，不承诺每种故障的总请求数都比旧版更少。
- 语义为业务逻辑与文档变更；打包 runner 因 prompt_sections README 路径判定 `package-sensitive`，按机器门禁补充冻结运行时验证，不手工降级。
