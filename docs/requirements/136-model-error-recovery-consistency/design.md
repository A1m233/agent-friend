## 现状分析

- `llm_providers/error_normalization.py` 对 HTTP、Responses 独立 error 和失败终态取证不一致；事件 type 与错误 type 混用，未知错误被 Bridge 统一映射为连接不稳定。
- `LLMClient` 已有有界重试与输出安全边界，SDK 重试关闭；本期复用这些边界，不再增加重试层。
- `notifications/service.py` 当前在模型润色失败后才使用本地文案，失败通知因此增加非必要调用。
- `runtime` 的 post-turn observation 未区分失败轮；memory worker 串行但没有持久化延后机制。抽取失败返回空 output，与合法空结果混淆并产生 extraction commit，阻碍重新处理。

## 方案设计

### 涉及模块

| 模块 | 改动 |
|---|---|
| `llm_providers` | 统一错误证据与分类、Responses 载体修正、安全诊断、重试计量 |
| `agent_bridge/errors.py` | 稳定用户提示，区分未知、临时、配置及请求原因 |
| `agent_bridge/notifications` | 失败通知本地生成；旧 pending 失败通知同样走本地分支 |
| `agent/runtime`、`agent/memory_feed.py`、直接 observation 调用方 | 传递失败状态，复用现有素材投影，不用模型判定价值 |
| `memory/extraction`、`memory/store`、`memory/facade.py` | 显式抽取结果、持久化延后、有界恢复、来源失效与幂等 |

### 错误与恢复

载体解析只提取事实：HTTP status（未知保留空）、错误 code/type、错误来源、Retry-After 和请求关联；不把 SSE code 伪造为 HTTP 503。归一化先处理明确的额度、凭据、权限、上下文等语义，再处理通用 HTTP 状态；未知原因保留未知。原有异常继承保留，以兼容调用方。

错误正文是不可信私有数据。对外异常字符串使用固定分类摘要；诊断保留已知错误代码、未知值摘要及长度、安全请求关联，不持久化原始错误正文或把 SDK 原始异常链写入日志。协议解析错误与本地参数校验单独标记。

临时连接/服务故障进入现有重试策略；默认首次请求之外最多五次，调用方更小的预算优先。额度、认证、权限、请求及未知错误不自动空转。已输出内容、工具副作用、用户取消、deadline 的边界继续优先于错误可重试性。

逻辑调用、传输入口尝试与重试计划分别计量，关联 operation；传输入口计数不声称服务端已接收，更不等同 CPA 内部上游请求数。诊断输出停止原因和累计尝试。沿用现有日志导出，不新增诊断包证据家族。

### 失败通知

`run_failed` 在接收阶段直接使用 `fallback_text`；worker 对历史 pending/generating 的失败通知同样兜底，不调用 generator。正常完成和其他通知保留原策略。通知持久化、唯一 event key、claim 和投递语义不变。

### 记忆素材及抽取结果

仅跳过空素材或已处理的相同来源；不能按用户说“继续”等文本猜测素材无价值。失败轮中的非空素材保存为延后项，保留现有 user/assistant 投影和来源。工具原始结果继续保留在会话中，不新增把任意工具正文送入记忆的通路。

抽取结果显式区分调用失败、解析/校验失败、成功空结果及成功结果。失败不写 extraction commit；合法空结果照常幂等提交。基础抽取成功、后续协调失败时保留已有合法基础结果，并记录协调降级，避免重新抽取已提交的基础结果。

### 延后存储与恢复

在现有 SQLite 记忆库内增加内部待处理记录，保存带版本的 fragment、来源、入队顺序、状态和失败信息；不新增依赖或独立数据库。记录是私有用户数据，不写入日志。与 extraction commit 使用相同 observation 身份，提交后清除 pending；崩溃后根据 commit 对账，避免重复写入。

保留单 worker。失败轮只保存素材；后续正常活动提供一次有界恢复机会，单次最多两段，按入队顺序处理。已有故障或积压时使用冷却，恢复阶段禁用每次模型调用内部重试；基础抽取和协调分别计数。失败停止当前批次，不启动空闲定时探测，重启/flush/close 不主动补发积压。

恢复沿用独立记忆模型配置。前台模型成功仅是后续活动，不作为记忆连接健康证据；记忆调用的实际成功/失败决定自己的冷却状态。不同调用方不能各自创建无限恢复循环。

来源撤回/重写时先与正在处理的 worker 同步，再使对应待处理素材失效；失效之后不能重新落库。退出仅等待正在进行的工作，延后项保留。延期造成记忆更新变慢，诊断记录数量与原因。
