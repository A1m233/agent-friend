# 136 · 模型服务错误归因与恢复一致性

## 状态

CONFIRMED

确认日期：2026-09-19。

## 背景

近期用户通过自定义 Responses 连接使用产品时，多次遭遇模型调用失败。诊断证据包含真实的上游连接与过载错误，也包含产品自身的恢复失败、错误分类遗漏和错误原因丢失。已有 132、135 及相关修复处理了任务继续、重试预算和压缩失败后的历史保护，本需求补齐错误进入这些恢复机制前后的语义与证据链。

当前实现对相同错误在 HTTP、独立流式错误事件和失败终态中的处理不完全一致；部分明确过载没有进入瞬时重试，未知或请求错误被笼统呈现为连接不稳定。原始错误语义丢失，又妨碍事后区分服务故障、请求兼容问题与产品缺陷。

原始事故、脱敏模拟、源码基线及局限统一记录在 [evidence-index.md](./evidence-index.md)。

## 目标

- 错误分类、自动恢复、用户提示和诊断证据相互一致。
- 有证据的瞬时故障进入有界恢复，需要修改配置或请求的问题给出对应指引。
- 发生失败后能够查明错误来源、业务阶段、尝试过程及停止原因；证据不足时保留未知。
- 共享模型调用链路覆盖前台对话与后台生成，保留既有任务、历史和副作用保护。
- 故障期减少非必要后台请求，避免失败通知与低价值记忆抽取继续消耗同一故障连接。

## 范围

### 包含

1. 盘点 HTTP 失败、流式错误、失败终态、断流、协议解析和本地请求校验的错误处理；相同语义不因载体差异被误分。
2. 区分临时连接或服务故障、限流、凭据、权限、额度、请求参数、上下文窗口及未知错误。分类证据与错误发生位置保留，不把未知原因断言为上游不稳定。
3. 分类接入现有恢复机制，保持首次请求之外最多五次自动重试的既有默认上限、取消感知等待和副作用边界；明确不可自动重试与停止重试的原因。
4. 用户提示与实际恢复能力一致，明确等待重试、需要调整配置、暂停任务或原因待查；沿用同一恢复链的错误去重。
5. 保留经过脱敏的错误原因摘要、稳定代码、请求关联、业务操作、尝试次数与最终结果，支持在诊断包中复核。不得泄露凭据、完整请求或私有会话正文。
6. 区分对话、会话压缩、记忆抽取与通知等调用；错误经过包装、降级或兜底后仍能追踪，不把后台失败改写成已完成前台任务失败。
7. 核对桌面、IM、语音及共享调用方的影响，保留各入口既有取消、截止时间、权限及恢复能力边界。
8. 以脱敏合成错误验证分类与恢复，并以 132、135 的行为为回归基线。真实故障缺少原始错误载荷时，不用模拟结果反推历史原因。
9. 失败通知直接使用本地事实文案，不为了描述模型调用失败而再次调用模型润色。通知接收、去重、查看与记录等既有能力保持有效。
10. 故障期低价值记忆抽取允许延后或跳过，区分纯恢复尝试与包含新事实的用户输入、有效回答及业务结果；不得笼统丢弃所有失败轮次的有价值信息。延后处理有界，不在服务恢复时无界补发，也不因前台切换模型就偷偷变更记忆模型。

### 不包含

- 修复 CPA 或模型服务自身的网络、认证池及服务端容量问题。
- 自动切换模型、账号或 Provider，放宽权限，增加默认重试次数或无人值守无限恢复。
- 重做任务运行状态系统、上下文历史保护、诊断包完整导出或业务 Skill。
- 通用连接级全局熔断、跨账号限流调度或全量请求队列重构。本期负载治理限于上述已确认的失败通知和低价值记忆调用。

## 验收条件

- [ ] **AC-01 载体一致性**：语义等价的 HTTP、独立错误事件和失败终态得到一致分类与恢复建议；载体、协议及本地错误来源仍可区分。
- [ ] **AC-02 分类边界**：连接故障、过载、限流、额度、凭据、权限、请求、上下文与未知错误均有确定性覆盖；未知错误不被伪装成确定的网络故障。
- [ ] **AC-03 恢复预算**：可重试故障使用已有预算和等待约束，不叠加隐藏重试；不可自动恢复错误不空转；停止与截止时间及时生效。
- [ ] **AC-04 部分输出及工具安全**：恢复不重复已提交内容或已完成工具，不执行残缺参数；执行状态未知时保留未知，不因分类修正绕过保护。
- [ ] **AC-05 用户可理解性**：提示、可用操作及最终状态与实际原因一致；同一恢复链不制造重复错误，重新加载和历史查看不改变其含义。
- [ ] **AC-06 证据完整性**：诊断能够关联业务操作、错误来源、请求尝试及最终恢复决定；重试耗尽、不可重试、用户取消和截止分别可辨，缺失信息明确标记。
- [ ] **AC-07 隐私边界**：错误含凭据、URL 参数、私有文本或异常大载荷时，用户界面及持久化诊断不泄露敏感内容，仍保留必要分类证据。
- [ ] **AC-08 多入口与后台调用**：流式对话和非流式生成及受影响业务入口通过验证；摘要、记忆和通知失败保留业务归属，不撤销已确认的任务结果。
- [ ] **AC-09 既有能力回归**：132 的继续任务、去重与预算，以及 135 的历史保全和任务连续性保护保持有效。
- [ ] **AC-10 项目门禁**：相关确定性测试和 `scripts/check` 全绿，用户确认验收；真实模型、CPA 实测与桌面视觉验证按实际授权记录，未执行不报告为通过。
- [ ] **AC-11 失败通知零模型调用**：模型故障触发失败通知时，使用本地文案，新增模型调用数为零；多次终态通知与重新启动不重复生成通知或触发补偿性模型调用。
- [ ] **AC-12 记忆负载治理**：连续故障与用户重复恢复场景中，低价值素材不会逐轮立即触发同一故障连接的记忆调用；包含新事实的输入与有效结果保持可恢复。延后、跳过及恢复后的处理数量与原因可观测，处理有界。
- [ ] **AC-13 放大量可核算**：分别核算前台、压缩、记忆、通知和各自重试；逻辑调用、实际传输尝试与重试计划不混算。模拟持续故障时，失败通知不增加流量，记忆治理确实减少相应调用，且既有前台重试预算不被后台预算暗中放大。
