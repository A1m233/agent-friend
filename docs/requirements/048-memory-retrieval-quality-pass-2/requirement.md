# 048 · 记忆召回质量第二轮升级

> Memory Retrieval Quality Pass 2 — 统一检索语义、稳定核心身份、补强改写与时间召回

## 状态

CONFIRMED

## 背景

[`008`](../008-engine-memory/requirement.md) 已建立 semantic / episodic / pinned 三层记忆、异步抽取、SQLite 持久化、关键词召回与上下文注入；[`013`](../013-memory-quality-pass-1/requirement.md) 又通过保留具体词、中文分词和 pinned relevance gate 完成第一轮质量提升。全量 PerLTQA 评测中，macro 从 `0.2189` 提升到 `0.3783`，零分率从 59.5% 降到 41.7%，说明现有方向有效，但仍存在以下用户可感知缺口：

- 查询与历史原话语义相同、字面词不同的时候，关键词检索容易漏掉相关记忆。
- “你还记得我吗”“你能想起我吗”这类只表达记忆意图、不包含姓名关键词的问法，可能被 pinned gate 误判，导致已有核心身份未被召回；bridge 已通过关闭 gate 临时规避，但 CLI 等入口仍可能使用不同配置。
- 时间信息主要作为粗粒度相对后缀注入，无法稳定支持“上次什么时候”“以前是什么、现在是什么”等问题。
- 自动记忆召回与 `recall_past_chats` 分别使用结构化 memory 和原始 SessionStore，各自拥有查询、时间、排序和结果表达逻辑，难以保证多个入口对同一证据作出一致判断。
- 当前评测主要关注抽取后的字面 anchor 是否被召回，尚不足以覆盖身份询问、同义改写、时间推理、知识更新和无答案拒答。

本需求承接上述缺口，完成第二轮以“召回正确性”为核心的质量升级。重点不是简单增加召回数量，而是让 agent 在不同问法、不同入口和带时间约束的场景中，稳定找到有证据的记忆，同时控制无关记忆干扰。

## 目标

- 用户换一种说法询问过去聊过的内容时，agent 仍能召回相关记忆。
- 用户直接询问“你还记得我吗”时，agent 能稳定获得已确认的核心身份信息。
- 用户询问时间、当前状态或历史状态时，agent 能基于实际记录回答；证据不足时不猜测。
- 自动召回与显性历史回忆共享检索语义和证据判断，不再因入口不同而对同一记忆产生矛盾结果。
- 召回结果保持相关、去重、可控，不以无限扩大 top-K 换取表面召回率。
- 新能力有独立评测集、可对照 baseline 和足以定位问题的召回 trace。

## 范围

### 包含

#### 核心身份记忆稳定召回

- 姓名、核心关系等身份级事实具备稳定的“始终记得”语义，不依赖用户必须说出对应关键词。
- 核心身份记忆与普通高重要性记忆在召回和上下文预算上可区分，避免为修复身份漏召回而把全部 pinned 无条件注入。
- 桌面端、CLI、IM 等运行入口使用一致的核心身份召回语义，不再依赖入口侧临时关闭 gate 获得正确行为。
- 核心身份内容有明确容量或上下文预算，不能随记忆增长无限占用 prompt。

#### 统一检索编排与证据语义

- 自动 `Memory.retrieve` 与显性 `recall_past_chats` 通过同一检索编排能力处理查询语义、时间边界、候选格式、有效性过滤、排序去重和 trace。
- 结构化记忆与原始会话历史可以继续保留各自的数据所有权和存储形态，通过统一检索能力下的不同数据源接入。
- 自动召回采用较小预算，优先提供当前回复所需的核心与相关记忆；显性回忆允许扩大检索范围、补查原始历史证据。
- 在相同查询与相同检索范围下，多个入口对共有证据的时间解释、有效性和相对顺序应一致；显性入口可以返回自动入口未纳入预算的合理补充，但不能给出相互矛盾的证据判断。
- 不向用户暴露数据库、索引、召回通道、内部 id 等实现机制；统一的是证据行为，不改变朋友式表达边界。

#### 语义改写召回

- 在查询与记忆没有明显共同关键词、但表达同一人物、偏好、事件或关系时，系统仍能召回相关候选。
- 精确人名、物件名、数量、原话片段等关键词召回优势必须保留，不能用语义召回替代现有精确检索能力。
- 多种召回信号产生的重复候选需要合并，最终排序同时兼顾相关性、重要性、时间与记忆层级。
- 加宽候选范围后，无关候选不得因数量增加而大量进入最终上下文。

#### 记忆意图与时间范围

- 能区分核心身份询问、显性回忆、普通隐性关联、时间限定查询和当前/历史状态查询。
- 支持用户明确给出的日期或自然时间范围，如“昨天”“上周”“三个月前”“上次”。
- 对“最近”“以前”等模糊时间表达保持合理边界，不把不确定范围伪装成精确日期。
- 对发生更新的事实，能够区分“现在是什么”和“以前是什么”；历史版本不因失效而从历史查询中彻底消失。
- 缺少可靠时间或历史证据时，召回结果必须如实为空或标记证据不足，不为生成层提供虚构时间锚点。

#### 上下文质量控制

- 同一事实在 core、semantic、episodic 或原始历史中重复出现时，避免重复注入。
- 单一主题或单一记忆层不得无控制地占满本轮上下文。
- 最终上下文区分核心身份、长期事实、相关经历和原始证据的作用，且各部分有可观测的预算或数量限制。
- 无关、已失效或低可信候选不能仅因重要性、时间接近或 pinned 标记进入最终上下文。
- 召回为空时维持现有证据优先边界：不编造、不用用户暗示补成历史事实。

#### 评测与可观测性

- 保留现有 PerLTQA 全量 baseline 作为观察性回归证据；只有在抽取语料冻结时，才把检索模式间差异用于硬门禁。
- 新增覆盖核心身份询问、同义改写、时间查询、知识更新、跨会话证据和无答案拒答的评测样本。
- 将“候选是否被正确召回”和“最终回答是否正确使用证据”分开观测，避免只看最终回复而无法定位是检索失败还是生成失败。
- 召回 trace 至少能说明：查询意图与时间范围、各数据源候选、候选被合并或过滤的原因、最终注入项及其排序依据。
- 能以相同数据集对照改动前后的关键词-only 与本期终态，证明新增召回能力的独立贡献。
- 在正式实现前测量现有 warm retrieve 性能基线，并在 `design.md` 锁定本期可接受的延迟与资源预算。

### 不包含

- **不做持久化抽取队列**：进程强退后的待抽取任务恢复、写入幂等、fragment 级事务另立可靠写入需求。
- **不做 Reflection / consolidation**：不在本期从多次经历归纳人格、长期模式或抽象关系。
- **不引入完整知识图谱**：不以 Neo4j、图遍历或通用 ontology 作为本期前提；是否需要轻量关系结构由后续实际评测决定。
- **不做记忆管理 UI**：Memory Inspector 的编辑、删除、恢复、pin/unpin 不属于本期。
- **不做 temporary chat / memory 总开关**：用户侧暂停记忆、临时会话与隐私控制另立需求。
- **不改变 persona 或主对话模型**：本期只提供更可靠的证据上下文，不用 persona prompt 掩盖召回缺口。
- **不要求物理合并数据存储**：结构化 memory 与 SessionStore 是否迁移到同一数据库属于技术方案选择，本需求只要求统一检索行为。
- **不承诺完整多跳关系推理**：本期覆盖跨会话证据检索与当前/历史状态，不扩展为任意关系链推理系统。

## 核心需求

### R-1 核心身份不因问法变化而丢失

- 已存在有效核心身份记忆时，系统必须在身份或记忆意图询问中稳定提供该证据。
- 普通无关问题不应触发全部普通 pinned 注入。
- 各运行入口对核心身份的默认行为一致。

### R-2 多入口共享一致的检索语义

- 自动召回和显性回忆必须共享查询解释、时间边界和证据有效性判断。
- 两个入口使用不同预算时，显性结果可以是自动结果的合理扩展，但共有候选不得出现相互冲突的状态或时间解释。
- 多数据源结果必须经过统一去重与排序后再提供给调用方。

### R-3 改写问法能够命中相关记忆

- 对测试集中预先确认的同义改写，终态召回必须严格优于关键词-only 对照。
- 精确关键词用例不因新增语义通道而退化。
- 改写召回的提升不能以显著增加无关上下文为代价。

### R-4 时间与知识更新可基于证据回答

- 时间限定查询只使用范围内的有效证据。
- 当前状态查询优先使用当前有效版本；历史状态查询可以找到对应历史版本。
- 无时间证据或无相关历史时，系统必须返回证据不足，而不是推测日期、时间段或旧状态。

### R-5 最终上下文可控、可解释

- 最终注入项经过有效性过滤、去重、排序和预算控制。
- trace 能把一次失败定位到查询解释、数据源召回、融合排序、过滤或上下文截断中的具体阶段。
- 开发者能够区分自然自动召回、显性历史回忆和调试 probe，不混淆生产行为与试探行为。

## 验收标准

- [ ] 已有姓名等核心身份记忆时，“你还记得我吗”“你能想起我吗”“我们之前认识吗”等身份/记忆意图样本全部获得核心身份证据。
- [ ] 与身份无关的负向样本不会因此注入全部普通 pinned；最终回复不被无关身份事实主导。
- [ ] 桌面端、CLI、IM 的默认装配不再使用互相冲突的 pinned/core 行为开关。
- [ ] 自动召回与显性回忆共用检索编排；在相同查询、时间范围和数据源范围下，共有候选的有效性与时间解释一致。
- [ ] 显性回忆扩大范围时，只增加有来源的补充证据，不与自动召回中的有效事实冲突。
- [ ] 同义改写评测集的 Recall@K 相对关键词-only 对照严格提升；每个核心改写场景至少召回一条支持答案的证据。
- [ ] 现有精确人名、物件、数量和原话关键词用例不因新增召回能力退化。
- [ ] “上次什么时候”“上周聊过什么”等时间样本只返回正确范围内证据；无可靠时间时不产生虚构时间答案。
- [ ] 知识更新样本能够区分当前值与历史值，旧值不会作为当前事实注入。
- [ ] 无答案样本不召回无关记忆充当答案，最终回答遵守证据不足边界。
- [ ] 最终上下文不存在可识别的重复事实，并满足 `design.md` 锁定的层级预算和相关性口径。
- [ ] 召回 trace 可见查询意图、时间范围、数据源候选、融合/过滤原因和最终注入结果。
- [ ] 检索硬门禁使用确定性 fixture，或在同一份冻结抽取 DB、相同问题集上比较 keyword-only 与 hybrid；同义改写 Recall@K 严格提升，精确关键词集合不退化。
- [ ] PerLTQA 终局验收使用同一问题集、同一模型参数、AB/BA 交错调度和版本锁定的 pass-1 / 048 抽取契约建立并发基线；不得拿历史单次结果与另一轮随机抽取直接宣称提升。
- [ ] 终局 2×2 对照同时报告 E0+R0（pass-1 并发基线）、E0+R1（检索独立贡献）、E1+R0（抽取独立贡献）、E1+R1（048 完整终态）。E1+R0 不低于 E0+R0，且 E0+R1、E1+R1 均严格高于 E0+R0；否则 048 不得标记为质量优化完成。
- [ ] E1+R1 的 PerLTQA macro 严格高于历史 pass-1 `0.3783`，零分率低于并发 E0+R0；总提升的 paired bootstrap 95% CI 下界大于 0，核心身份、精确词、时间和知识更新关键切片均不得退化。
- [ ] 固定 fragment 重复抽取实验分别报告 success / empty / error、输出不稳定 probe 数、empty/success 翻转数，以及每轮 semantic / episodic 数量；抽取波动不得归因成检索回归。
- [ ] 新增评测分别报告候选召回结果与最终回答结果，能够区分 retrieval failure 与 generation failure。
- [ ] warm retrieve 性能满足 `design.md` 在实现前锁定的延迟与资源预算。
- [ ] 核心召回、改写召回、时间过滤、版本查询、去重和多入口一致性均有非真实 LLM 自动化测试覆盖。
- [ ] `./scripts/check/run.sh` 全绿；默认检查不触发真实 LLM API。
- [ ] 如执行真实 LLM 抽取或回答评测，已按 `llm-api-confirm` 单次获得用户明确授权，并记录调用范围与结果。

## 开放问题 / 待技术方案决策

- 核心身份记忆使用现有 semantic 子类型、独立结构还是其他兼容形态。
- 查询意图和时间范围由确定性规则、模型改写或混合方式生成。
- 关键词与语义候选如何融合、是否需要额外 rerank，以及各阶段候选数量。
- 语义表示使用何种本地模型、索引与迁移方式，如何控制桌面端启动和运行开销。
- 原始 SessionStore 是即时扫描、建立独立索引，还是迁移到可统一查询的存储；无论选择哪种，SessionStore 仍保持会话事实来源职责。
- 自动召回与显性回忆分别使用哪些数据源和预算，如何保证显性结果是合理扩展而非另一套语义。
- 当前/历史事实需要补哪些时间与版本字段，如何兼容现有 `valid_from` / `valid_until` 数据。
- 去重、层级配额、相关性阈值与证据不足的具体判定口径。
- 新增综合评测集的样本来源、规模、Recall@K、回答正确性和负向误召回指标。
- 当前 warm retrieve 的实际性能基线，以及本期允许的延迟、内存、磁盘和启动预算。
