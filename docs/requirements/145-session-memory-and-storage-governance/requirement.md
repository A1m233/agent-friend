# 145 · 会话内存与持久化增长治理

## 状态

CONFIRMED

## 背景

2026-09-29 的本机诊断发现，AF Bridge 单进程工作集约 6.83 GiB，私有提交内存约 9.36 GiB。两个近期使用的会话文件分别约 1.06 GB 和 0.93 GB，内部恢复记录占其序列化体积约 96%～98%。启动恢复任务结果持有完整会话的机制已通过隔离复现确认；运行态再次加载并长期持有会话，是另一条已核对的引用路径。现有证据尚未对运行进程全部内存逐项归账，不能将总占用全部归给单一原因。

需求 113 保证模型流水持久化与恢复，120、122 改善会话响应及驻留复用，144 处理上下文压缩与任务恢复。本需求补齐这些能力在内存生命周期、内部记录增长和大历史读取方面的整体资源约束，避免局部优化把成本转移到另一条路径。

## 目标

- 让内存占用能够按组件、持有者和生命周期解释，区分必要状态、可回收状态、重复数据与未归因部分。
- 消除启动扫描和结束任务对完整历史的不必要长期持有；多会话连续使用后，闲置资源能够安全回收。
- 控制新增内部恢复记录的冗余增长，并使已有 GB 级会话也能受益。
- 保持连续发送的响应速度，以及历史、权限、执行事实和重启恢复的正确性。
- 用固定样本、阶段测量和回归契约验证改善，而非依赖重启、单次低读数或主观判断。

## 范围

### 包含

- Bridge 启动恢复、附件核对、会话列表与详情、查询与搜索、执行准备和模型流水恢复。
- 活跃与闲置会话运行态、通知与提醒、记忆相关会话消费者、任务结果与异常引用、事件订阅与队列、工具输出及查询缓存。
- 创建、打开、发送、切换、并发、任务结束、取消、归档、删除和应用重启的资源生命周期。
- 业务历史、当前有效模型上下文、内部恢复与诊断记录的体积构成、重复保存、解析与复制成本。
- 新记录增长和已有大历史的兼容处理；执行前确定旧数据处理的安全边界。
- 前端、语音及工具子进程的占用对账；是否深入整改以实测归因决定。

### 不包含

- 默认更换持久化技术栈、重做通用工作流框架或把本需求扩成所有产品性能问题的改造。
- 将操作系统工作集下降等同于对象释放，或将模型 token 上下文缩短等同于进程内存回收。
- 通过丢弃用户历史、跳过恢复校验、隐藏等待、减少必要执行证据或自动重放工具来获得性能数字。
- 未经另行授权修改当前用户数据、清理历史、重启用户正在使用的实例或发起真实 LLM 调用。

## 需求

### R-1 可归因的资源盘点

对范围内入口建立调用与数据持有关系，说明持有对象、重复副本、释放条件、容量约束及异常路径。区分对象存活、分配器保留、峰值临时分配、缓存、工作集和私有提交；不能把未知部分直接标为泄漏。

盘点应覆盖启动后未打开会话、首次冷恢复、重复发送、多会话切换、任务结束与闲置阶段，并明确证据能解释和不能解释的范围。

### R-2 有界且安全的运行态生命周期

完成的后台任务、恢复报告和异常结果不应无必要地永久保留完整会话。闲置会话和可重建派生数据必须具有明确资源边界，持续访问更多历史会话不能使无用状态无限积累。

活跃执行、审批等待、仍运行的工具、未决事务和取消收尾不能因资源回收失去其权威状态或互斥保护。回收后的再次使用能够安全恢复，且不引入频繁重建造成的明显延迟退化。

当前打开、正在加载或对话中的会话属于活跃使用，不计入闲置会话缓存的容量、数量和过期预算。已经加载过但不再被使用的会话才可能进入闲置池；切换页面不应使仍有任务的会话失去保护。活跃会话仍需计量和优化重复占用，但不能因闲置预算不足而中止对话、截断上下文或被迫卸载。

闲置运行态的初始预算为合计 256 MiB、最多 8 个会话、闲置保留不超过 10 分钟；资源安全释放完成后的稳定状态应满足上述约束。保护中的活跃资源单独列账，不以整个进程或全部已加载会话套用这一预算。

### R-3 历史增长与读取放大治理

分别量化业务事件和内部记录的增长。重复上下文、标识符、快照及诊断信息应具有与其用途相称的保存成本；小幅新增业务内容不应无必要地反复复制累计历史。

仅需摘要、投影、附件引用或当前恢复状态的消费者，不应无必要地把全部原始历史长期装入内存。既有大文件也需纳入方案与验证，不能仅通过新格式限制未来增长。

### R-4 保持恢复与数据兼容

保持用户历史可查、有效分支正确、当前模型上下文连续，以及中断与损坏边界下的安全恢复。兼容已有格式和旧数据，明确处理失败、取消与中断后的行为。

兼容方向限定为高版本读取、恢复并继续使用低版本数据。不要求低版本读取或写入高版本产生的新格式，也不要求为降级运行提供旧格式导出或兼容写入。迁移操作自身失败或中断时的数据完整性与恢复保护仍然必须满足。

保持单写者、权限、Skill 状态、模型配置、工具执行事实和恢复校验；不能复活撤销分支或自动重放已执行副作用。旧数据治理需具备可验证的完整性与失败恢复措施，具体机制由方案阶段确认。

### R-5 可重复的性能与正确性验收

建立短、普通、真实长会话和可控增长样本的基线。分别记录启动峰值、恢复峰值、稳定内存、任务结束后的回收、多会话累积、磁盘增长和关键操作耗时。

在方案确认前明确样本、重复次数、统计口径、内存与增长预算、响应速度保护线及判定阈值。绝对占用、增量与增长趋势共同判断；不能只报告相对下降百分比。

对已冻结的 A/B 大历史样本，单会话完整恢复的进程私有提交峰值减去模块导入基线不超过 512 MiB。该门槛是固定样本的性能目标，不是活跃会话的产品内存配额。连续发送的热路径不得反复完整读取历史；冷恢复耗时按同环境、同输入、各 3 次独立进程测量的中位数对比基线，退化须解释并在验收时明确确认，不能仅凭内存下降判定通过。

## 验收条件

- [ ] AC-01 / R-1：完成范围内入口与持有关系盘点；每项注明证据、容量与释放边界，明确总内存对账残差及未验证路径。
- [ ] AC-02 / R-2：启动恢复完成后完整会话不再因任务结果无必要地存活；包含弱引用或等价对象生命周期断言与隔离内存测量。
- [ ] AC-03 / R-2：反复访问和执行多个会话后，闲置资源符合 R-2 预算；验证当前打开、加载和对话中的会话不占用闲置预算，活动结束后的转入、闲置回收及回收后恢复均正确。
- [ ] AC-04 / R-3：给出内部记录构成、每轮增量和长历史增长对比；相关只读消费者不再无必要地完整加载并长期持有恢复历史。
- [ ] AC-05 / R-3、R-4：已有大历史和新增数据都通过治理验证；历史查询、有效上下文、精确或明确降级恢复、新版使用旧数据和迁移中断处理保持正确；不以旧版读取新格式作为验收要求。
- [ ] AC-06 / R-4：覆盖并发、审批、运行中工具、取消、编辑重发、归档、删除、源文件变化、损坏和重启；不新增陈旧状态、重复副作用或锁一致性问题。
- [ ] AC-07 / R-5：在同口径固定样本下比较基线与候选，达到已确认资源门槛及响应速度保护线；分别标注真实安装包、隔离进程和合成验证的结论边界。
- [ ] AC-08：核心机制有自动化回归覆盖，项目 scripts/check 通过；回报实际改善、未验证项与残余风险，由用户确认验收完成。

## 调研与交付约定

- 用户在 2026-09-30 确认编号和整体范围，并明确要求充分参考他人实践。形成方案前必须查阅成熟产品的官方文档、可访问源码和相关测试，不能先自行定案再补参考链接。
- 对关键选择记录来源版本、实际机制、适用约束、采用或不采用的理由及 AF 的验证方式；调研材料进入证据索引，需求和方案正文不复制参考分析。
- 不从闭源产品界面推断其内部结构，也不把第三方源码还原、社区问题或 token 压缩说明当成已证明的进程内存策略。
- 先确认需求，再完成方案调查与评审；需求确认不代表实现、数据迁移或真实模型验证已获授权。
- 证据中的用户会话、prompt、工具正文与私有数据不进入仓库；只保存脱敏统计、代码锚点和可复查的方法。
