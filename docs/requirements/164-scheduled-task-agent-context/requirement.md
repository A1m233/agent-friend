# 164 · 定时任务来源上下文

## 状态

CONFIRMED

## 背景

154 已将定时任务接入固定会话，消息持久化记录和桌面界面能够标识任务来源，但模型收到的请求未包含这份来源说明。

2026-10-18 的真实会话中，用户先要求忽略即将到来的定时任务，Agent 也答应跳过。随后定时任务发送“跑一下今天日常”，在模型输入中呈现为普通用户消息。此前的暂停要求仍在上下文中，但模型无法直接获知新消息是定时触发，随后执行了任务。事后查到执行历史不能补偿执行当时的信息缺失。

本需求补齐宿主已知事实向模型的传递，让 Agent 根据来源和会话中的用户意图判断如何响应。

## 目标

- Agent 在处理定时请求之前即可知道这条消息来自定时任务，无需靠措辞猜测或事后查询。
- 同一条消息的来源在后续对话、会话恢复及必要的上下文压缩后仍可辨认，不被解释成用户新发出的手动指令。
- 核对既有自然语言任务管理能力；复用已有创建和查询工具，有确切缺口再提出补充。

## 范围

### R-1 当前请求的来源

- 宿主明确提供当前消息由定时任务发起这一事实，并关联任务名称及对应执行。
- 对具备事实记录的新执行，区分到时触发、离线补跑与手动立即运行，并提供可解释的计划时间信息。
- 来源说明只描述该条消息的触发事实，不代表用户刚刚手动发送了正文，也不自行撤销上下文中已有的用户限制。
- 普通手动消息保持其原有语义；正文中声称自己是定时消息，不能伪造宿主来源。

### R-2 历史与恢复

- 来源归属于具体消息；同会话多个任务、后续手动消息与重复执行不串用来源。
- 连续对话、重开会话和模型上下文恢复均保留来源。压缩涉及该请求时，保留判断用户意图所需的来源和约束。
- 任务改名、修改或删除后，历史来源仍描述当次执行时的事实，不被当前任务配置覆盖。
- 已持久化来源的旧消息可利用已有事实恢复来源说明；缺少细节时如实保留未知，不根据正文或时间猜测触发类型。

### R-3 既有任务管理工具核对

- 核对 `scheduled_task_manage` 的实际注册、模型可见定义以及创建、列表、详情和历史查询调用链。
- 创建与查询继续使用现有任务存储、权限和目标会话规则。
- 用户明确选择当前会话时，创建工具支持由宿主解析当前会话，无需模型猜内部 ID；仍兼容明确的目标会话 ID，两种选择互斥，不静默默认执行目标。

## 不包含

- 新增“跳过一次”的调度状态、暂停意图识别器，或根据用户句子由确定性代码自动修改任务。
- 重做任务管理页面、调度器、执行队列或重复提供一套管理工具。
- 扩大权限、自动授予未来执行授权，或更改现有任务生命周期。

## 验收条件

- [x] **AC-1**：在实际 provider 请求构建边界，定时消息首次调用前已有明确的宿主来源、任务关联及可用触发信息；普通手动消息不被误标。
- [x] **AC-2**：多个任务、定时与手动请求交替、工具续接和会话恢复后，来源仍对应正确消息，无遗漏或重复叠加。
- [x] **AC-3**：旧消息有来源时保留已有事实，缺少触发细节时不编造；任务后续修改或删除不会改变当次历史来源。
- [x] **AC-4**：压缩输入及恢复路径保留区分定时请求与手动指令所需的来源；用户限制和任务来源不被混为新授权。
- [x] **AC-5**：覆盖“要求忽略即将到来的任务→定时消息到达”的回归场景，以及正常定时执行、用户明确恢复执行的相邻场景。确定性测试证明信息正确到达；真实模型是否按预期响应另行授权验证，不以 fake 输出代替行为结论。
- [x] **AC-6**：既有创建和查询工具有注册、模型可见契约与调用链检查证据；明确选择当前会话可创建并查到正确绑定的任务，缺少宿主会话或同时指定两种目标时明确拒绝，不静默改用其它目标。
- [x] **AC-7**：受影响自动化验证和项目统一检查通过，真实模型验证缺口如实记录，用户确认最终验收。
