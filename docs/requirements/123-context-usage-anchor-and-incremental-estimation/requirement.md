# 上下文真实用量锚点与增量估算

## 状态

CONFIRMED

## 背景

长会话中，用户可见轮数较少仍可能伴随大量工具调用。2026-09-09 的一次本地运行中，同一请求的本地估算为 204,845 token，而 provider 返回输入用量为 111,680；随后本地估算达到 211,310，超过 209,716 的阈值而触发压缩。该观测确认估算显著偏高，但尚未完成历史安装包到源码的身份绑定。

009 的设计曾提出真实 usage 锚点加新增消息估算，初始实现却使用全量字符估算。063 增加了 usage 校准与恢复，但只允许向上校准，无法纠正持续高估。本需求独立完善计量机制，保留旧需求作为历史记录。

## 目标

让压缩判断尽量反映实际上下文占用，减少全量粗估偏差造成的过早压缩，同时保留防止超窗的安全边界。减少重复估算已被真实 usage 覆盖的历史内容。

## 范围

### 包含

- 有可信真实用量时，以对应上下文为锚点，只估算尚未计入的内容。
- 正确计入模型输出、工具调用与结果、用户输入、系统上下文、工具定义及附件等请求成本。
- 覆盖连续工具循环、重启续聊、模型或连接切换、历史编辑与重发、压缩及动态上下文变化。
- 锚点无法证明有效时安全回退；没有 usage、usage 异常或协议语义不兼容时仍有可用估算。
- 所有已有上下文预算入口采用一致的计量语义，避免展示值与实际压缩判断各自计算。
- 记录锚点来源、增量估算、回退原因、最终预算与触发依据，并用确定性回归验证。

### 不包含

- 改变现有输出预留、误差缓冲比例、摘要生成策略或历史保留政策。
- 本期必须接入精确 tokenizer 的承诺；必要性在方案阶段评估。
- 重新设计工具结果裁剪、模型窗口目录、记忆召回或用户界面。

## 需求

- **R-1 真实用量优先**：已获得与当前上下文兼容的真实 usage 时，已覆盖历史的字符估算误差不得反复累积到后续预算。
- **R-2 成本完整**：增量包括自锚点以来真正进入下一次请求的内容；同一成本不得遗漏或重复计算。输入用量、输出用量、缓存用量和 reasoning 用量按 provider 的实际语义处理，不能直接混加。
- **R-3 有效性与隔离**：锚点应绑定其计量对象与模型调用身份；跨会话、跨模型、历史重写或恢复时不得复用不兼容锚点。允许安全重建或回退。
- **R-4 安全降级**：无可信锚点时保留完整估算及现有超窗恢复能力，不因追求更晚压缩而取消安全余量。
- **R-5 可观测与可回归**：诊断信息能够说明本轮为何采用锚点或回退、哪些内容被估算、为何触发压缩；测试应固定真实高估形态及主要失效路径。

## 验收条件

- [ ] **AC-1**：对接近本次观测比例的确定性输入，建立真实用量锚点后，仅追加少量内容不会因旧历史全量高估再次触发压缩；新增成本达到阈值时仍正确触发。
- [ ] **AC-2**：连续工具调用、新用户输入及模型输出的预算计算可断言，无漏算或重复计入；下一次可信 usage 能更新锚点。
- [ ] **AC-3**：重启续聊、模型/连接切换、历史编辑与重发、压缩、系统上下文和工具定义变化分别有锚点恢复、失效或安全回退测试。
- [ ] **AC-4**：无 usage、异常 usage、首轮及旧会话数据继续可用；缓存 token 不被错误从上下文成本中扣除，不混用不同 provider 的用量语义。
- [ ] **AC-5**：文本和附件成本以及已有不同上下文调用入口有针对性覆盖；不削弱现有预算安全、摘要与超窗恢复测试。
- [ ] **AC-6**：可从诊断字段对账锚点、增量和最终预算，并区分回退与正常增量路径；证据不包含完整私有会话或凭据。
- [ ] **AC-7**：项目 scripts/check 全绿，并由用户确认验收。真实 LLM 验证如有必要，按单独授权执行；离线回归不得冒充真实运行验证。
