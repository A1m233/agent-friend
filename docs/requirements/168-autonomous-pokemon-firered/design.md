## 现状与边界

AF 个人 Skill 由 `agent.paths.skills_dir()` 定位，catalog、包快照和授权由现有 Skill 系统负责。Skill 不能自行注册模型工具。首版命令工具返回文本，`view_image` 独立提供图片；本次优化通过显式 `output_images` 复用 `ToolResult.images` 返回图片，权限与资源预算见后文。工具 registry 可以由源码实验入口组合，产品默认 registry 无动态插件入口。

首版保持游戏包在 `tools/src/tools/pokemon/skills/pokemon-firered/`，通过 `scripts/pokemon/run.*` 安装到 AF 个人目录。该包不是 Cursor/Codex 个人指引，不放入 `.cursor/skills`，不改 builtin manifest、冻结资源或安装器。实验入口属于 tools，沿用 AF 的 Conversation、SessionManager、人格、会话存储与模型契约，不复制第三方模型循环。

## 组件与数据流

1. 个人 Skill：玩法边界、当前运行状态、工具使用与恢复说明。脚本随 Skill 复制，使用 Python 标准库和 AF 受管 Python 基线已有的 Pillow；不包含 ROM、模拟器二进制或攻略。
2. mGBA 适配：独立 Lua 脚本通过帧回调执行有界按键序列，截图和存档；不读写游戏内存。宿主与模拟器用本机专用工作目录中的原子请求/回执交换，避免暴露网络控制服务。
3. 游戏客户端：校验参数、串行锁、持久动作日志、观察编号、结果不确定处理、版本绑定、暂停和恢复。游戏资产从 `agent.paths.user_data_dir()` 下的专用目录派生；安装脚本将实际路径写入个人包配置，不让模型猜路径。
4. AF 实验入口：组合游戏专用工具并直接返回图片；由现有 AF 运行调度驱动有来源的系统续玩，受轮次、时限和停止条件限制。桌面个人 Skill 首版使用命令 + view_image，两轮旧试玩均属于两次工具调用路径；本次优化改为命令带图，不能把旧试玩当作新路径的性能证据。

## 协议与执行

- 每个实例一个独占控制锁。操作使用宿主生成的唯一 ID；模型只传上一次结果的 observation ID 和按键序列。
- 每批最多 32 段、总计 600 帧，每段明确按键和帧数。方向互斥，拒绝未知键、额外字段、布尔冒充整数和超限输入。等待用空按键段表示。
- 模拟器校验请求边界后逐帧执行；请求只消费一次。动作后释放按键并生成新截图；取消和截止时间同样释放按键。模拟器被暂停时只能在恢复回调后处理，不能宣称立即中断暂停中的模拟器线程。
- 发布请求前持久化 pending；回执验证后才落 completed/failed/cancelled。超时标记 unknown，不自动重放。重连先对账或取消旧动作并重新观察，禁止把“没有回复”当作“没有执行”。
- 截图文件不可覆盖，以操作 ID 命名；模型只看到截图、动作摘要、观察编号和明确状态，不提供 RAM、地图坐标或剧情标志。
- Lua 不执行来自请求的代码，协议仅接受固定格式的数据；所有文件名由宿主生成并限制在实例目录。实例元数据绑定 ROM SHA-256 与 mGBA 版本。

## 存档、上下文与长跑

恢复点由模拟器存档、截图、AF 会话事件游标、游戏笔记及版本身份组成；最后原子发布 manifest。只有完整文件及校验匹配才是可恢复点。禁止把旧存档与新的完整会话直接拼接继续操作；回滚应建立清楚标记恢复边界的 AF 会话分支，保留原历史。

暂停停止先关闭自动续玩，再取消当前运行并释放按键。重启默认保持暂停，必须显式恢复；程序重启不能获得新的调用预算。正常游戏失败由 AF 观察后继续，不自动回滚以改变战斗结果。

续玩始终保留原用户目标、游戏身份、模型身份、Skill 版本、预算和任务 ID，使用可信 system trigger，不伪造用户每一步发送“继续”。每轮重新验证 Skill；版本变化或身份不匹配即停。模型声明通关只进入待核验状态，保留画面和存档，由真实证据和用户验收决定完成。

## 视觉往返与有界对话优化（2026-10-31 确认）

用户在两轮试玩后确认先处理动作带图、减少无效尝试与稳定截图，并授权加入有界对话推进；暂不做模拟器倍速、进程常驻或推理档位调整。

- **图片回传**：通用 exec_command 新增可选 output_images，引用当前轮已获 read_image 的 filesystem_scope_id；仅支持 buffered。脚本 stdout 为单个 JSON，image_paths 是该 scope 下的相对图片路径。宿主沿用 FilesystemService 和 ImageReadingService 校验、快照并返回 ToolResult.images；脚本不能自行授予权限。不支持图像/无有效 scope 时在命令前拒绝；命令完成后收图失败明确标识已执行，不重新运行副作用。
- **独立预算**：单次工具结果最多 8 图、每图 8 MiB、合计 32 MiB；provider 仍核对其能力限制。工具历史投影最多 10 图/32 MiB，在上限内追加，超过后一次淘汰旧前缀至 4 图/16 MiB 附近，保留最近一组完整结果。清理图片保留原文字与恢复引用；不生成新的摘要、不删除磁盘图片。数字分别约束单次输出与活跃历史，不能共用一个常量。
- **稳定观察与无进展提示**：普通 act 结束后在总 600 帧预算内按 12 帧采样，文字区连续稳定或非对白画面基本稳定后返回；最多额外 180 帧、单次视觉操作 20 秒。转场、空白或持续动画导致等待耗尽时如实返回未稳定。保存最近三次操作/预期及画面指纹，提醒 AF 比较可见变化；相同图不等于未执行，不自动重放、不自动规划路线。
- **dialogue**：AF 看图确认普通对白后调用，携带当前观察编号。harness 再观察，等文字稳定、保存当前页、按 B 8 帧并释放 24 帧，逐次检查。出现额外窗口/可能选项、对白消失或未知布局、重复页、图片/帧/时间预算耗尽即停止；最多 7 次推进，最多 8 张图（含最终画面），仍受 600 帧及试玩总时限约束。返回按时间排序的画面与停止原因，选择、战斗、命名等由 AF 理解并决定。
- **识别边界**：只读 240×160 PNG 像素，首版适配当前候选的默认白色对白框；额外白色窗口保守视为不确定，不自动取消或确认菜单。OCR 已作为辅助候选评估，但本机没有已配置 OCR 引擎，本轮不引入额外依赖，也不将 OCR 缺失当作继续按键的许可。原始页面始终交给 AF；蓝色教学页或其它皮肤回退到普通视觉操作。
- **互斥与验证**：整个视觉操作持有现有 supervisor 锁，每个底层动作继续记录唯一操作与回执；未知动作不重放。verify-visual 只接受暂停且无 pending 的实例，先存快照，完成或异常均暂停并恢复测试前状态，证据与真实 AF 游玩分开。核心采用确定性协议/权限/图片与停止条件测试，真实模型效果留给独立授权的后续试玩。

上述是已确认方向的实现细化；没有新增外部模型玩家、攻略或内置宝可梦包。

### 第三轮观察后的修订（用户已授权）

- 就绪判断按区域分开：白色对白与蓝底战斗文字比较文字区域，底部战斗菜单比较菜单区域；普通画面用 30×20 色块比较，容忍少量局部动画而保留滚屏变化。连续两次 12 帧采样满足条件即返回，空白/转场不视为就绪。act 仍最多额外 180 帧，总 600 帧/20 秒保护不变；显式 WAIT 不被悄悄缩短。
- 个人脚本增加 `wait --observation-id`，只释放按钮并等待就绪；普通画面最多 600 帧，蓝底战斗文字最多 1200 帧（循环首轮后修订），单次 20 秒不变；Skill 优先短按 + 自动等待，未就绪再 wait，减少模型长 WAIT 与自动等待叠加。
- 对白识别剔除书架尺寸的小白块，允许普通战斗教学/结果文字批处理；战斗菜单和选择窗口停止。新技能、进化及其它需要选择的场景仍由 AF 决策，未知皮肤不自动猜测。
- 含方向键的操作返回已有操作前截图和最终截图，末图始终为当前状态。motion 仅提供粗色块变化及高匹配、低歧义的背景滚动估计，不声明玩家坐标、碰撞或可通行；重复提示容忍少量局部动画。内部色块保存在实例探索记录，模型只接收紧凑提示与最近三次尝试。AF 在未知路口先单方向短步验证，避免多方向盲组合。
- OCR 先用既有截图试验：独立 uv 环境、固定 RapidOCR ONNX 1.4.4、CPU、原尺寸/3 倍放大。样本显示可读出不少中文但名称/字形误识别且每页有额外延迟，本轮不安装进个人包、不参与按键决策；保留 ocr-check 可复查入口。没有新增产品或冻结 runtime 依赖。

### 第四轮观察后的修订（用户已授权）

- 把像素稳定与决策边界分开。蓝底战斗文字稳定后继续无按键采样，保存不同文字页，直到战斗菜单、确认箭头、选择窗口或场景边界；确认与行动都交还 AF。普通画面及输入按键保留 600 帧上限；循环首轮后把蓝底战斗的无按键等待独立为总 1200 帧，20 秒/8 图及本轮截止保护不变，耗尽时明确未到决策点。
- 每次采样优先检查选择窗口；除已有白色区域保护外，小型白框需同时满足四边深色框证据。书架小白块不触发。普通对白仍逐次 B 推进，战斗蓝底对白只等待，不自动确认。
- 正常方向操作只回当前图，画面变化很小或近期重复时附前图；AF 可通过 `--compare` 显式请求对照。原图文件名始终可恢复，返回图按时间排列，末图对应当前观察编号；不改写已发历史做去重。
- 第四项只诊断：图片未渲染候选的固定预算与已计量 usage anchor 存在重复预留机制，详见 E-015。本次不改全局压缩阈值或估算代码。
- 用户明确把下一轮改为 Astra high，当前目录窗口 800000；这是对先前保留模型档位的覆盖。继续原存档、个人 Skill，真实试玩最多 30 分钟；模型、窗口、harness 同变，不作为受控性能 A/B。

第五轮后按真实帧收口识别细节：确认箭头按9/7/5/3/1三角形及本皮肤颜色匹配，归一其阴影，支持两行而不掩去其它红字；蓝底战斗中的额外白区要求四边框证据，避免捕捉闪光触发选项停止。该局部修正只有离线回归，不改写第五轮已冻结的运行版本。

### 第五轮后的上下文与观测修订（用户已授权）

- 桌面观察器只读日志时使用短生命周期句柄；Windows允许共享删除，按文件身份和偏移追踪当前文件及最多5份轮转文件，完整换行后才消费记录。日志读取失败独立留痕，不能取消截止检查；终态对齐去重后的逻辑模型调用数与API计数，HTTP重试不混为新模型轮次。
- 输入预算增加显式本地渲染契约，生产多模态适配器只读取已落盘工具图像、核验hash并生成与实际发送相同的内容块；用户文档继续先投影为文件引用。不执行上传或模型调用。未知自定义renderer未声明本地契约时保留原保守路径。图片复用、增量、丢失和模型路由变化统一进入既有usage anchor，不改窗口、阈值或全局图片常量。
- 成功buffered命令在模型视图中精简审批/环境/时延诊断字段，原始事件和UI结果不改；只有恢复工具可用时启用，并携带原result_ref。stdout、stderr、进程/终态、语义未评估标记、截断和恢复字段保留，错误、流式和截断输出不精简。历史删图提示仍保留，不剥掉图片不可见的事实。
- 命令启动先记录读取权限准备与process/start两个阶段；不凭总耗时猜测Python加载，不跳过权限准备、关沙箱或先做常驻进程。本次真实试玩据此定位剩余开销。
- 核心桥接代码变更后重启当前分支Tauri dev，核对新进程与源码。继续Astra high、800000窗口、原会话/原存档，个人Skill每轮最多30分钟；观察器先布防，保存预留时间不变。

## 五轮循环中的专用工具修订

- 第4轮真实样本修正第3轮的单帧确认：固定奖金页出现输入后未推进，经验页还出现文字稳定但经验条变化。confirm-text现在仅在识别为确认箭头且归一化全图连续60帧稳定后，用既有tap时序8帧A/24帧释放；原上限和停止边界不变。第3轮单帧方案保留为历史，不再是现行行为。finish后直接报告已核实内容，避免保存后恢复大结果挤占收尾预算。AF摘要/取消统计仅作观测，未修改。

- 第3轮后新增显式confirm-text：AF决定推进已见蓝底确认文字后调用；重新观察，只对稳定确认箭头短按A一帧并释放，逐页留图，遇菜单/选择/普通对白/未知/重复/无箭头停滞即停止。沿用600帧输入、1200帧被动战斗等待、20秒、8图和整轮截止，最多7次确认，绝不自动选招式或回答选择。普通dialogue仍使用B；白色对话识别增加当前灰框路牌配色，保留双边框和白底面积门槛。单帧按键实际效果由下一轮验证，未证明战后NPC文字属于A重触发。

- 第1轮多次战斗结算在592–600帧退出，随后需要新的模型请求和短wait。此前输入动作与无按键结算共用600帧预算，造成尚有单次时间余量时提前返回。现将只有蓝底战斗文字触发的无按键采样放宽到总1200帧，并保留20秒、8图及桌面总预算三重边界；输入按键与普通对白/世界画面仍不超过600帧。不自动确认、攻击、选择或重放。
- 后续短wait的36帧不能视为缺失结算的真实长度，因为模型思考期间模拟器仍在运行。改动收益由下一轮真实观察验证，不把阈值修改本身当成提速证据。所有改动只在Pokemon工具、配套测试与个人Skill，不改AF通用harness。

- 第2轮后：当前皮肤的浅色标题卡/右上黑条入场插画视为transition，不因静止而宣称就绪；选择窗口出现后仅等待底部说明文字稳定，记住本批已见选择，窗口消失也不自动续按B。
- 无箭头蓝底文字有可见字形且约8秒持续相同时，以text_unchanged交还AF，decision_ready=false，不自动确认。依据本轮采样，普通自动结算相同文字最长约5.8秒，而战后台词约17.9秒；该分界只是保守的提前交还策略，不保证所有长动画都已识别，也不授权按A。20秒/帧/图片/本轮预算仍保留。

- 第5轮后：当前队伍页青色背景排除于battle_menu的紫白底部匹配，回复通知交还AF作other处理，不增加自动按键。Skill补充移动/转向和交互之间释放等待，避免尚未转向就按A；不提供地图坐标或攻略。最后修订只做离线与无模型检查，不新增第六轮试玩。
