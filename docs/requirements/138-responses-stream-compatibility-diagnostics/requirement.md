# 138 · Responses 流式协议兼容性与异常可诊断性

## 状态

CONFIRMED

确认日期：2026-09-20。

## 背景

一次翻译 PDF 的任务在工具结果续接后的第 3 次模型请求中，因
`responses_protocol_error: unsupported stream event` 中断。诊断包和用户侧日志
确认了解析失败位置，但未保留触发事件的类型。用户随后在本地重跑成功，不能据此
还原原事故的事件序列，也不能判定原问题已修复。

本需求以该事故暴露的协议覆盖与取证缺口为入口，不预设模型、第三方连接或产品
解析器中哪一方产生了不合规事件。原事故的具体事件类型仍为未知。

## 目标

- 系统盘点 Responses 流式协议与现有产品能力的覆盖关系，补齐适用的兼容缺口。
- 协议失败后，支持通过本地诊断证据识别异常事件及失败阶段，无需依赖再次复现。
- 保持响应、工具调用和终态的一致性，中断与恢复不引发错误执行或虚假成功。

## 范围

### 包含

- 对照官方协议，盘点事件类型、输出项、终态及现有处理行为，区分必须处理、
  可安全忽略、当前能力不支持和协议异常。
- 覆盖现有 Responses 连接中的文本、推理相关元事件、函数调用和工具结果续接。
- 对第三方兼容连接明确支持边界，不根据模型名称或一次成功假定完全兼容。
- 失败证据能够关联响应与本地调用，辨认事件类型、必要结构、解析阶段和失败原因；
  缺失、截断或未采集的证据必须可辨认。
- 诊断信息从 provider 边界传递到本地日志及诊断包，并保持上下游错误语义一致。
- 为新增证据限定内容、大小与保留范围，不额外记录正文、工具参数或结果正文、
  凭据、原始 reasoning 或 provider 私有续接数据。
- 核对异常后的重试和停止边界，以确定性回放覆盖成功、失败及工具执行安全。

### 不包含

- 接入全部音频、图像、服务端工具或后台任务能力。
- 自动切换模型或协议以掩盖解析失败。
- 默认记录完整请求、原始 SSE 或用户附件；建立完整会话重放平台。
- PDF 生成库与本地文档环境的配置、安装或修复。
- 将原事故直接判定为某种具体事件、模型能力问题或已解决问题。

## 关键信息

- 延续 [114](../114-llm-provider-responses-api/requirement.md) 建立的 provider 边界，
  并结合 [121](../121-model-connections-and-custom-models/requirement.md) 的现行连接能力。
- 官方参考：<https://developers.openai.com/api/docs/guides/streaming-responses>。
- 技术方案须固定协议盘点所用的来源与版本/访问时间，区分官方定义和第三方观测。
- 用户已确认需求范围与编号；技术方案待确认。真实 LLM 验证另按调用授权规则执行。

## 验收条件

- [x] AC-01：形成可复查的协议覆盖清单，每类事件说明适用能力、现有行为、目标处理及验证依据。
- [x] AC-02：现有支持能力的合法事件序列正确完成，文本、函数参数、phase、usage 与终态不丢失、不重复或被错误解释。
- [x] AC-03：可安全忽略的事件有明确依据；未支持能力及未知或畸形事件按明确边界处理，不一概吞掉。
- [x] AC-04：构造协议失败后，仅凭导出的诊断证据即可确定事件类型（或明确缺失）、必要结构、失败阶段与关联调用；正常业务错误不被误标成未知协议事件。
- [x] AC-05：异常证据经过敏感内容与大小边界测试，不泄露正文、凭据、工具内容及 reasoning；诊断缺口可辨认。
- [x] AC-06：异常顺序、截断、不完整终态、重复事件及工具续接均有确定性测试；残缺工具调用不执行，恢复不重复执行已有工具，不误报成功。
- [x] AC-07：既有 Responses 与 Chat Completions 行为通过适用回归验证，项目 scripts/check 全绿。
- [x] AC-08：用户确认验收完成；原 PDF 重跑成功不单独作为本需求通过依据。
