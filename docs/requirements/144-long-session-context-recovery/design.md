# 长会话上下文管理与原会话恢复 - 技术方案

## 状态

CONFIRMED

## 需求文档

[requirement.md](requirement.md)

## 现状分析

基线为 `2ededbf8246027c6679979e8d140a29bd2d963d5`。`usage_anchor.py` 将旧请求总量作为保留 opaque 状态的整体上界，但数值接口无法区分上界和候选估算。`summarizing.py` 仅按完整用户轮选择保留尾部，当前长任务不能继续缩小；“继续任务”重用原用户事件，因此不能自动解除这个限制。

有效模型历史与业务事件已经分离。`Conversation` 在 provider 接受请求后提交模型历史、cache epoch 与 compaction；rollout 支持恢复实际 replacement。这条主链继续复用。

## 方案设计

### 模块职责

| 模块 | 调整 |
| --- | --- |
| `context/usage_anchor.py`、`budget.py` | 区分独立估算、整体保守上界及未知，提供结构化候选判断。 |
| `llm_providers/protocol.py`、`client.py` | 声明适配器是否支持在完整事务边界重建客户端上下文。 |
| `context/protocol.py`、`turns.py` | 压缩控制、共享尝试预算、真实目标来源与安全事务切点。 |
| `context/summarizing.py` 及就近辅助模块 | 普通压缩与强制恢复共用规划；任务内覆盖、分段归纳与结果准入。 |
| `context/summary_prompt.py` | 保留任务来源、工具参数及结果引用，内部摘要不加载对外人格。 |
| `context/checkpoints.py` | v4 摘要和目标锚点身份校验，兼容 v1–v3。 |
| `conversation.py` | 注入目标与预算依赖，继续模式、候选校验、原子提交及恢复。 |
| Bridge 继续接口、错误投影与桌面消息卡 | 显式“压缩后继续”，统一恢复原因与操作。 |
| 相关 engine、Bridge、前端测试 | 合成 opaque 回归、事务、重启、失败、取消与入口联动。 |

### 预算判断

保留现有兼容性身份和 v4 usage anchor，不新增多响应 reasoning 成本账本。扩展 `InputEstimate` 的证据属性，明确整体上界与可信独立估算的区别。原请求的实测总量只在兼容请求中作为实测锚点；缩短候选保留少量 opaque 时，旧总量仍可作为保守上界，但其超限只说明需要恢复，不能声称必要内容已实际超限。

`RuntimeContext` 提供结构化候选评估回调；数值估算接口保留给目标水位等数值消费者。压缩规划和最终准入使用同一输入投影与证据属性。未知成本不置零，不按密文长度计费，不从实测总量直接减去旧文本估算。候选完全替换旧 opaque 后使用独立估算；新请求成功后沿既有 usage 路径建立新锚点。保留需求 143 的模型、连接、投影版本及校准身份。

### 安全事务与目标锚点

优先使用原有完整用户轮切点；不足时允许在当前用户轮已闭合的 provider 响应及工具事务后切分。同一响应的文本、reasoning、并行调用与结果作为完整组处理；未闭合调用不能被截断或伪造结果。原始事件保留，checkpoint 只替换有效模型视图。

`Conversation` 传入已接纳的真实用户消息来源，不能用最后一个 `role=user` 猜当前目标。覆盖前缀包含当前目标时，生成独立 `synthetic=task_anchor` 模型项，使用新 UUID，绑定原 user event UUID 和内容身份；保留原话、引用及附件来源标记。它不新增业务用户事件，也不形成新的真实用户轮。

有效候选为“摘要、目标锚点、合法原始尾部”，加上既有 system、工具目录及当前动态上下文。当前权限和 Skill 仍从宿主事实装配，摘要不恢复旧授权。协议工具结果已返回但外部工作仍运行或结果未知时，摘要保留该状态和可核实引用。

适配器能力增加窄声明 `context_checkpoint_mode=replace_complete_groups|unavailable`。现有发送完整客户端历史且不依赖服务端 continuation 的适配器明确声明前者；未知第三方实现默认后者。该能力只允许替换完整已完成组，不授权剥离保留组中的必要 reasoning。原有普通历史压缩兼容路径保留，新任务内重建必须核对能力。

### 摘要来源与调用边界

摘要只接收纯文本、无工具请求，复用现有摘要入口。转录补足 source UUID、调用和结果引用及实际 `arguments_json`，让压缩后的信息仍可重取。

来源超过单次预算时按安全事务单元顺序归纳。每段包含前一段临时摘要、当前目标和下一段原文；全部覆盖完成才产出最终候选。当前任务不能静默省略早期事务后宣称已覆盖。中间摘要仅在内存中，不写成成功 checkpoint。

每个压缩周期最多 3 个成功分段、4 次摘要请求，容量与暂时故障重试计入同一预算；关闭摘要调用内层额外重试，避免层层相乘。容量拒绝时可缩小剩余分段预算并重划未覆盖部分；余额不足、单个必要输入无法容纳或无法取得有效摘要时暂停。保留现有 512–4096 输出预算和压缩后 0.7 倍触发阈值的目标水位。

共享预算贯穿同一轮的 provider 容量拒绝恢复；恢复 builder 不重新领取额度。同一输入和候选没有变化时不重复自动恢复。出现新的真实模型/工具进展后可进入新压缩周期。用户显式重试临时失败可以建立新周期，但仍受同样上限及候选必须改变的约束。

### 检查点与提交

checkpoint v4 增加目标锚点身份和来源校验。摘要及锚点使用各自新的模型 UUID，原用户业务 UUID 不被重用为改写内容。覆盖边界和模型前缀摘要仍绑定原冻结输入；业务前缀由既有边界映射证明。

候选准备时冻结来源身份，发送和提交前确认来源、有效分支及取消状态。沿用 session mutation/turn 锁，不引入新锁系统或平行任务状态。仅 provider 接受后，在现有 rollout 边界原子提交 replacement、compaction 与相关 cache 状态；失败、取消和来源变化丢弃候选，不撤销已接纳的新用户输入。

冷恢复优先读取 rollout 中的完整 replacement。校验摘要和锚点身份、原目标仍在有效分支、保留尾部及来源摘要；materialized 后不重复折叠。旧 v1–v3 可继续读取；v4 缺失或失配不能靠文本相似或新建 UUID 猜测恢复。

### 显式恢复与错误语义

继续接口增加向后兼容的恢复模式，默认保留普通继续。错误卡对上下文问题显示“压缩后继续”，经现有 run admission、source run 校验和会话互斥进入强制压缩路径。后端根据当前事实复核，不能由客户端标记绕过事务或权限检查。

该操作明确包含压缩与任务续跑，仍使用 provider 接受提交边界；本期不新增独立的“只压缩、不续跑”提交语义。普通发送、编辑重发和工具续轮统一进入同一候选构建路径。

区分必要输入超限、计量证据不足、事务待确认、摘要失败和模型配置问题。稳定原因贯穿异常、run_error、实时事件及历史投影，不能只靠中文文案判断。保留现有错误码和旧客户端行为，新增可选详情时默认安全。操作进行中复用压缩活动和运行状态，重复操作在前后端均被互斥挡住。

## 影响分析

### 上下游

- 原始事件、文件、工具执行与权限系统不因压缩而重新执行或改写；只调整有效模型视图。
- 预算和候选共用需求 143 的投影；原生未知文档不会借恢复绕过容量准入。
- 所有共享引擎入口受益于自动压缩；桌面显式操作复用已有继续接口和封装按钮。
- 摘要 prompt 契约升级，旧摘要不被伪装成含有新字段；消费者清单同步说明新承接来源。
- 不引入运行时依赖、动态导入或新资源加载方式。按实际 diff 复核 frozen runtime 风险；当前设计属于既有机制内的业务逻辑与协议调整。

### 验证与风险

确定性验证覆盖：真实故障的合成输入形态、opaque 与重复组件、候选和 wire 投影一致、单用户长循环与并行工具、摘要分段和总次数、目标身份、旧 checkpoint 兼容、失败与取消、provider 接受前后、重复恢复、编辑分支、冷启动及 PDF 回归。执行项目完整检查。

真实模型观察仍需单独授权，用于验证摘要保真和承接质量；fake 只证明机制。桌面视觉验收按项目规则询问，未获授权不启动用户运行态。证据与验收缺口记录在 progress 和 evidence-index，不把代码完成写成用户验收完成。
