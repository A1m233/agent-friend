# 长会话上下文管理与原会话恢复

## 状态

CONFIRMED

## 背景

长会话在接近上下文预算时会进入压缩。已有真实故障表明，压缩候选即使移除了大量旧历史，仍可能因为保留少量不透明推理状态而沿用整个旧请求的输入预算，提前判定“必须保留的内容已超预算”。与此同时，当前用户轮被整体保护，单个任务的长工具循环缺少释放空间的途径。用户点击“继续任务”可能再次进入相同阻塞。

现有失败保护避免了未经有效摘要就丢弃历史，但“保住历史”仍不足以保证会话可继续使用。本需求补齐正确计量、当前任务中途压缩和原会话恢复，保持已有的任务连续性、权限与持久化约束。脱敏事实、来源和局限见 [证据索引](evidence-index.md)。

## 目标

- 压缩实际减少输入后，预算能够合理释放；不把计量不确定性误报为已证实的不可恢复超限。
- 同一个长任务可以在安全边界压缩并继续，无须用户人为制造新轮次或迁移会话。
- 上下文问题中止当前运行后，用户仍能在原会话恢复、补充指令或调整任务。
- 压缩和恢复保留当前目标、执行事实及可重取的原始记录，不造成宿主自动重放已完成动作。

## 范围

### 包含

- 通用上下文预算、实测用量复用、不透明状态及候选请求的计量一致性。
- 自动压缩、当前任务的中途压缩，以及压缩失败后的显式恢复操作。
- 桌面端的恢复交互与状态展示；共享引擎调用方采用一致的失败和恢复语义。
- 发送、继续任务、编辑重发、配置变化、取消与冷启动后的恢复。
- 脱敏确定性回归、完整入口验证及另行授权的真实模型承接质量验收。

### 不包含

- 重做需求 143 的 PDF 输入路由、会话文件管理和文档预算投影。
- 自动切换模型或连接、自动扩大上下文配置、跨会话搬迁作为常规恢复办法。
- 外部动作的通用 exactly-once 保证、持久工作流引擎或针对单个业务任务的特例。
- 所有 provider 故障或确实超出容量的必要输入都能自动恢复的保证。

## 需求

### R-1 候选计量与有效输入一致

压缩、删除或替换历史后，已移除输入的整段预算不能仅因少量保留内容而永久残留。计量仍须保持可信：不能把未知成本当零，也不能从实测总量中粗暴减去未经验证的估算，或把密文长度当作真实 token 数。

候选判断、最终请求准入、持久化用量和用户可见原因采用兼容的输入口径。更换模型、连接、输入投影或上下文内容后，应正确复用或失效已有证据。区分实测值、估算值、保守上界和未知部分。

### R-2 当前任务可中途压缩

当前用户轮不再必须全文保留到任务结束。长工具循环达到预算压力时，允许在不会截断未完成工具事务的边界压缩，并承接同一任务。

承接内容至少保留最新目标、用户修正、有效约束、关键结果、已完成与待处理工作，以及结果未知或仍在运行的动作。不能把计划写成事实、把尝试写成成功、把未知写成未执行。需要详情时可按有效会话分支重取原始记录。

### R-3 有界自动恢复与原会话显式恢复

自动压缩成功后继续当前任务；失败后进行有边界的恢复，不能无休止重复同一请求。最终暂停时，原会话提供明确的压缩恢复操作，恢复应能够改变导致阻塞的有效输入，而不是仅换运行标识重新发送。

用户恢复时不必重复描述已保存目标。用户发送新指令、修正任务或编辑重发，也应进入相应的恢复判断；仍不可恢复时保留输入并解释阻塞。历史压缩失败不得永久禁止会话接收后续输入。

### R-4 失败原因与操作相匹配

区分计量证据不足、摘要生成失败、实际容量拒绝、必要内容确实无法容纳，以及工具事务尚未结束等原因。可恢复时给出有效操作；需要用户调整时说明需要调整什么。不能把“减少本轮输入”作为所有问题的统一建议。

显示恢复进行中、成功、失败和取消状态；重复操作不能并发创建互相覆盖的压缩或续跑。模型或网络暂时不可用时保留会话，后续可重试。

### R-5 历史、分支与执行事实保持一致

失败、取消、无效摘要或超预算候选不得覆盖最后有效上下文及原始记录。成功压缩后的有效上下文能够持久化和恢复；刷新或重启不应重新加载已被有效压缩覆盖的全部旧历史，也不应重复提交同一压缩结果。

编辑撤销后的旧分支不能复活。保留最新用户输入、错误归属与已完成结果；任务完成后的整理失败不能把完成结果改成任务失败。

### R-6 延续权限和工具执行边界

压缩摘要不构成新的执行授权。历史审批、工具 scope 和 Skill 状态不能因摘要或恢复自动重新生效。用户已停止的任务不能被自动恢复。

宿主不得为了恢复而自动重放已完成工具调用。仍运行和结果未知的动作必须保留其状态并先核实；恢复不保证外部系统具备 exactly-once 语义。

### R-7 可诊断与可验证

记录压缩触发、候选输入变化、预算证据类型、恢复尝试及停止原因，支持串联一次运行的完整恢复过程。日志与诊断材料不新增完整敏感内容或不透明推理载荷泄露。

确定性验证固定计量、状态、事务与持久化契约；真实模型验证用于观察摘要保真和任务承接，不能用离线估算通过替代。

## 验收条件

- [x] **AC-01 / R-1**：用合成不透明状态复现“大量历史被移除但旧整段预算仍残留”的输入形态；候选能合理释放预算，并覆盖重复组件、未知成本和证据不兼容，不能通过将未知成本置零而通过测试。
- [x] **AC-02 / R-1**：候选与最终请求使用同一输入投影；模型、连接或投影变化后证据正确复用或失效，需求 143 的文档路径回归通过。
- [x] **AC-03 / R-2、R-3**：一个用户输入内的长工具循环可以压缩并继续，不要求增加用户消息；未完成调用与结果不能被拆断或伪造。
- [x] **AC-04 / R-2、R-6**：承接内容区分当前目标与旧话题、最新修正与旧指令、计划与执行结果；已完成、运行中、未知和剩余工作正确，旧权限不复活。
- [x] **AC-05 / R-3、R-4**：自动恢复有界；暂停后显式恢复能改变阻塞条件，在可恢复案例中于原会话继续，无须重述任务。无法恢复时准确说明原因与可执行操作。
- [x] **AC-06 / R-3、R-5**：压缩失败后的新消息、编辑重发和“继续任务”经过完整入口验证；输入不丢失，编辑撤销分支不复活，旧失败不永久锁死会话。
- [x] **AC-07 / R-4、R-5**：摘要异常、空摘要、无效候选、容量拒绝和中途取消均保留最后有效上下文及原始记录；失败或取消不提交成功结果。
- [x] **AC-08 / R-4、R-6**：重复恢复、并发操作、用户停止、工具执行前后和未知结果场景下，宿主不重复执行已完成动作，不自动续跑已停止任务，不并发覆盖压缩结果。
- [x] **AC-09 / R-5**：成功压缩后销毁运行态并冷恢复，仍使用正确有效上下文、输入、分支和错误归属；不会重新灌入全部已覆盖历史或重复摘要。任务完成后的整理失败不改变完成事实。
- [x] **AC-10 / R-7**：恢复过程可以从脱敏日志关联触发、候选、尝试、结果和停止原因；保守估算不被表述成真实 token 用量。
- [x] **AC-11 / R-2、R-7**：经另行授权的真实模型观察覆盖长任务中途压缩及失败后恢复，核对目标、约束、结果和剩余工作；记录模型、输入形态、次数和局限，不外推普遍成功率。
- [x] **AC-12 / R-4、R-7**：桌面恢复交互及共享引擎的调用方验证通过；正式桌面交互验收是否由 Agent 执行按项目视觉验收规则确认，未执行时如实标注。
