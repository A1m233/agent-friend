# OpenRouter 模型渠道接入与调用层解耦

## 状态

CONFIRMED

## 背景

agent-friend 当前只提供 DeepSeek 与 Kimi 两个直接模型渠道。用户希望通过 OpenRouter 使用部分境外模型，首批目标是 Gemini 3.7 Flash 与 GPT-5.6 Luna，并继续复用现有的主对话模型、记忆模型和单会话模型切换体验。

需求 089 已经补齐按 provider group 管理凭据、候选凭据校验、保存与应用反馈、服务安全重启和运行时鉴权失效处理。OpenRouter 应复用这套能力，而不是再建设一条独立的凭据路径。

与此同时，当前 Agent、Bridge 装配和测试仍直接依赖具体模型客户端。继续用“每新增一个渠道就在上层增加分支”的方式接入，会让模型传输实现逐渐侵入会话、工具调用、上下文和测试。本需求需要在接入 OpenRouter 的同时建立稳定的项目自有模型调用边界，使后续增加或替换模型传输实现时不必改写 Agent 核心语义。

## 目标

- 用户只需配置一个 OpenRouter API Key，即可在 agent-friend 中使用经过产品确认的 OpenRouter 模型。
- 模型设置准确区分“调用渠道”和模型作者，不把 OpenRouter 误呈现为模型厂商。
- Gemini 3.7 Flash 与 GPT-5.6 Luna 均可用于主对话、记忆模型和单会话模型切换。
- OpenRouter 凭据完整复用既有的安全校验、保存、应用、服务重启和运行时失效反馈。
- Agent 核心只依赖项目自有的模型调用契约，不依赖具体 provider、聚合平台或第三方模型 SDK。
- 保持现有工具循环、审批、会话持久化、上下文压缩、记忆和中断恢复语义不变。

## 范围

### 包含

#### OpenRouter 调用渠道与模型目录

- 新增 OpenRouter 调用渠道，并在产品自有模型目录中固定开放：
  - `openrouter/google/gemini-3.7-flash`；
  - `openrouter/openai/gpt-5.6-luna`。
- 两个产品模型标识必须包含 OpenRouter 渠道前缀，与未来可能出现的 Google 或 OpenAI 直连渠道保持全局唯一。
- 两款模型均可配置为主对话模型或记忆模型，也可在会话允许切换时作为下一条回复使用的模型。
- 本地产品目录继续决定展示名称、上下文窗口、输入能力、工具能力与默认模型；OpenRouter 的在线模型目录不直接成为用户可选模型列表。
- 请求必须指向用户选择的明确模型，不得静默改用自动路由、其它模型或跨模型 fallback。
- 模型调用不得静默忽略工具调用等 agent-friend 已声明为必要的请求能力；当前路由无法满足时应明确失败。
- OpenRouter 路由默认不得选择会对用户数据进行非瞬时留存的上游端点，也不得在失败后静默放宽该约束。

#### 模型选择交互

- 主对话模型和记忆模型选择区域统一使用“调用渠道”表述；工具、地图、天气、语音等非模型设置继续使用符合各自领域的“供应商”表述。
- OpenRouter 模型在尚未配置凭据时仍然可见，便于用户发现能力。
- 用户选择尚未具备可用凭据的 OpenRouter 模型时，系统不得保存或切换到不可用状态；应明确说明缺少 OpenRouter 凭据，并提供直达对应设置组的操作。
- 凭据已经配置但正在应用、应用受阻或已失效时，模型选择和调用反馈应与真实状态一致。
- 直接使用 DeepSeek、Kimi 的现有选择体验保持不变。

#### OpenRouter 凭据与应用

- 设置中心新增 OpenRouter 凭据 group，仅管理 OpenRouter API Key，并复用需求 089 的统一 group 编辑与状态表达。
- 保存新 Key 时使用安全、低成本、不会生成模型回答的 OpenRouter 官方鉴权入口进行校验。
- 校验必须区分有效、明确无效和暂时无法验证；新 Key 无效时继续保护已有可用凭据。
- 一次 OpenRouter 凭据提交最多触发一次 Bridge 应用流程，并连续展示保存、校验、应用、重启、完成或失败阶段。
- 环境变量、系统 keyring 和兼容来源的优先级、来源说明及凭据版本绑定规则沿用既有契约。
- 自动化测试和普通凭据校验不得生成真实模型回答或消耗真实模型额度。

#### 模型调用边界

- Agent、Conversation 与 Bridge 的会话装配只依赖项目自有的模型调用契约和模型工厂。
- 项目自有契约覆盖现有上层真正需要的模型能力，包括模型身份与上下文限制、完整回复、流式事件、工具调用增量、完成与用量信息、错误以及取消。
- 具体模型客户端、provider 配置、第三方 SDK 对象和传输细节不得泄漏到 Agent 核心；上层不得通过具体类型判断决定模型调用行为。
- OpenRouter 的接入应落在模型目录、凭据解析和模型基础设施适配层，不得在 Conversation 的工具循环、审批、持久化或上下文逻辑中新增 OpenRouter 专用分支。
- 项目自有模型目录继续拥有产品模型 ID、能力声明、默认选择和路由策略；底层传输库或聚合平台不得反向接管这些产品语义。
- 独立 fake model 应能直接实现项目契约并覆盖 Agent 测试，不需要伪装或强制转换成某个具体模型客户端类型。

#### 调用能力与错误反馈

- 两款 OpenRouter 模型首期支持文本输入、流式文本输出和 agent-friend 现有工具调用流程。
- 首期不得因为上游模型声明支持图片或文件，就向用户开放尚未经过 agent-friend 适配和验证的多模态能力。
- OpenRouter 鉴权失败应使当前凭据的有效状态失效，并引导用户重新配置。
- 余额或 Key 限额不足、权限或策略拒绝、内容安全拒绝、限流、网络错误和上游暂时不可用必须保持各自分类，不能全部归类为凭据无效。
- 能可靠取得的 token 用量、上游请求标识和诊断信息应进入现有用量与诊断通道，不得包含 secret 或敏感请求内容。
- 取消、超时、有限重试和流结束行为应与既有模型渠道保持一致，不能因 OpenRouter 接入造成无法停止的后台请求或重复工具执行。

### 不包含

- 不开放 OpenRouter 全量模型市场，不动态同步或自动展示新增模型。
- 不支持 `openrouter/auto`、多模型候选数组、跨模型自动降级或按成本自动选模。
- 不支持任意自定义 API 地址、用户自定义 provider 或通用 provider 插件市场。
- 不接入 OpenRouter OAuth，不查询余额、账单、套餐或历史用量。
- 不建设 Google Gemini API 或 OpenAI API 的直接调用渠道。
- 不在本期开放 Gemini 3.7 Flash 或 GPT-5.6 Luna 的图片、文件、音频或视频输入。
- 不以本需求为由重写 Agent 的工具循环、审批、权限、会话事件、持久化、记忆或上下文压缩语义。
- 不把底层模型传输库拥有的路由、fallback、代理、预算或完整 Agent loop 能力引入产品核心。
- 自动化测试不调用真实 OpenRouter 或其它真实 LLM API。

## 验收条件

- [ ] AC-1：设置中心、主对话模型、记忆模型和会话模型选择器均出现 OpenRouter 调用渠道，并且模型选择区域使用“调用渠道”而不是“供应商”。
- [ ] AC-2：OpenRouter 只展示 Gemini 3.7 Flash 与 GPT-5.6 Luna；两款模型都可用于主对话、记忆模型和单会话模型切换，产品 ID 全局唯一。
- [ ] AC-3：OpenRouter 凭据未配置时模型仍可见，但任何选择动作都会在持久化前被阻止，并明确引导到 OpenRouter 凭据设置组。
- [ ] AC-4：保存 OpenRouter Key 时执行不生成模型回答的安全校验，能区分有效、无效和暂时无法验证；无效新 Key 不覆盖旧凭据。
- [ ] AC-5：OpenRouter 凭据的保存、应用、Bridge 重启、阻塞、失败和运行时失效反馈完整复用需求 089 的状态与安全契约，一次提交最多触发一次应用流程。
- [ ] AC-6：Gemini 3.7 Flash 与 GPT-5.6 Luna 均能通过 OpenRouter 完成普通流式文本对话和至少一次完整工具调用循环，且不会静默切换到其它模型。
- [ ] AC-7：OpenRouter 请求无法满足必要工具参数或隐私路由约束时明确失败，不静默忽略参数、降低能力或放宽数据留存要求。
- [ ] AC-8：鉴权失败、额度不足、权限或策略拒绝、内容安全拒绝、限流、网络错误和上游暂时不可用具有可行动且互不混淆的用户反馈。
- [ ] AC-9：两款 OpenRouter 模型首期只声明并开放文本与工具能力；图片、文件、音频和视频输入不会被错误展示为可用。
- [ ] AC-10：Agent、Conversation 与 Bridge 会话装配面向项目自有模型调用契约；其中不存在 OpenRouter 专用行为分支，也不依赖具体第三方模型 SDK 类型决定核心流程。
- [ ] AC-11：独立 fake model 无需继承、伪装或强制转换为具体模型客户端，即可覆盖完整回复、流事件、工具调用、模型切换、错误和取消测试。
- [ ] AC-12：替换模型调用契约的具体实现不会改变工具审批、调用预算、会话事件、持久化、中断恢复、上下文压缩和记忆语义；相关既有回归测试保持通过。
- [ ] AC-13：DeepSeek 与 Kimi 的模型选择、普通对话、工具调用、多模态附件、凭据管理和错误处理没有回归。
- [ ] AC-14：自动化测试使用 mock/fake 覆盖 OpenRouter 目录、凭据校验、选择前置检查、请求路由、流式事件、工具调用、错误分类、取消和调用契约，不调用真实第三方 API。
- [ ] AC-15：项目规定的 lint、typecheck、单元测试与集成测试全部通过；真实 OpenRouter 模型验证如需执行，按真实 LLM 调用授权单独进行并记录模型、范围和结果。
