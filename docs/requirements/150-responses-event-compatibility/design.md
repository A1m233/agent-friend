## 现状与模块边界

实现基线 `49c20d17`。Responses 状态机位于 llm_providers/responses；未知事件会直接失败，
refusal 在首个片段即抛错，annotation 校验后未进入公共最终消息。PhaseRun 会重新构造
ProviderAssistantItem，因此只改解析器无法实现信息保真。SessionModelHistory、业务事件、
Bridge 编码和前端实时/历史 reducer 都要同步传递新增的可选消息元数据。

## 事件接收与完成

- 在 Responses 子目录维护统一事件分类清单；官方事件、已观测扩展与未知事件分开统计。
  机器测试对照固定来源清单及锁定 SDK；能力分类不等于授权执行。
- `keepalive` 和其它未知事件记录有界、脱敏的结构证据后跳过，不依据字段白名单阻断。
  不按陌生事件名前缀猜测正文、工具参数、错误或完成。附加字段不影响已知业务字段的解析。
- 未实现能力的进度事件同样不直接终止；输出项不属于 message/function_call/reasoning 时
  记录为不参与执行的 Other 项，不向本地工具执行器分派、不伪造结果或持久化原始私有 payload。
  已知正文与调用仍须正确匹配身份、内容索引、完整参数及终态；只有 Other、没有可用结果时
  报告明确的能力/空结果边界，不制造空白成功。
- 非对象或无法解码的未知输入保留受限证据并跳过；已识别业务事件的身份冲突、文本冲突、
  不完整 JSON 等继续明确失败。额外原始字段不作为完成快照冲突依据。
- completed 才结束成功消费，停止等待后续 EOF；failed/incomplete/cancelled 保持各自非成功语义。
  流提前 EOF 是未完成，不能用正文、保活或工具片段代替终态。
- 工具必须在有效完成响应后执行；不因兼容放宽提前执行、不重放已完成副作用。

## 等待与取消

保留当前 300 秒默认事件空闲计时和显式覆盖。每个可消费的流事件，包括未知事件和保活，
均属于连接活动；不新增正文推进计时、纯保活次数限制或交互累计硬时限。
已有业务 deadline、用户取消、有限重试预算继续有效。SDK 未暴露的 SSE 注释心跳不能冒充
已观测活动，实际传输边界以本地 HTTP/SDK 测试为准；不新增另一套请求或重试器。

## 拒绝与引用信息

- 在 provider-neutral assistant item 增加默认空的可选内容元数据：按 content_index 保存
  text/refusal 内容类型和引用集合。引用保留类型、文本位置、显示名和 URL/远端文件标识等
  白名单字段，不允许混入任意 provider payload；旧消息缺字段时仍按普通文本处理。
- refusal delta/done 和完成快照一致装配，正文供用户阅读，最终响应标记拒绝语义；拒绝与
  工具调用混合时不能执行工具。拒绝完成不等于用户任务完成，不自动重试拒绝。
- `final_response_text` 等内部结果消费者识别拒绝并返回明确拒绝错误，避免把拒绝文字当成
  摘要、JSON 或有效任务结果。HTTP/业务 content_filter 错误继续保留既有安全失败语义。
- 引擎 PhaseRun 与最终 item 对账时保留元数据；业务 assistant_message payload、模型历史
  Message.meta 和 rollout 均保留必要字段，不另建存储。展示元数据不随意注入模型请求；
  拒绝正文仍以 assistant 发言保留，跨 route 投影不泄漏私有 provider 字段。
- 使用统一 assistant 消息元数据更新事件连接引擎与 Bridge；AG-UI、push 和历史查询采用
  相同可选字段，旧调用方继续消费正文。已完成快照为最终元数据依据，重试 reset 同步撤回。
- 桌面在消息处显示拒绝状态及来源列表；URL 引用复用安全打开入口，只允许可打开的网络地址。
  远端文件 ID 不转成本机路径或伪造下载链接；不可访问引用显示文件名及不可打开说明。
  IM 等纯文本入口投影拒绝正文和可用来源说明；语音只朗读正文，引用信息留在持久记录。

## 验证和诊断

- 固定官方事件清单、版本/日期和 fixture 分类；SDK 升级出现未归类项时测试失败，但运行时
  不把清单穷举当作协议版本协商。每类事件至少有相称的合法/失败用例，避免分类测试自证。
- 合成 SSE 经真实 SDK/transport 和 LLMClient 验证 keepalive、未知事件、有效完成、提前 EOF、
  Other 输出项、拒绝、引用、交错工具调用与元数据扩展；本地时钟/HTTP 验证持续保活和取消。
- 覆盖 PhaseRun、业务落盘、rollout 恢复、模型切换、实时推送与历史 reducer 一致性；
  内部摘要拒绝不落有效 checkpoint，工具调用计数证明不执行残缺参数、不重复副作用。
- 兼容跳过证据按每次响应限量记录并汇总计数；不把原始事件、正文、拒绝文本、工具参数或
  私有推理写日志。现有诊断包通过应用日志获得证据，不新增 ZIP 协议。
- 未知事件跳过不显示成用户错误；真正失败按能力不支持、结果损坏、提前结束或连接中断
  给出准确提示。重试语义复用当前分类，不能为消除提示引入无界重试。
- 执行 backend/frontend/rust 三段 scripts/check。真实 LLM 和桌面视觉验收分别取得适用授权，
  未执行明确记录。纯 Python/TS 逻辑与静态导入初判 standard，无新增依赖或打包资源；
  若实施触及 package-sensitive 条件重新评估。

## 影响与局限

生产改动集中在 llm_providers/responses、stream_events/final_result、agent/assistant_phase、
conversation、sessions、Bridge 事件投影及前端消息 reducer/呈现。只新增可选字段，旧存档
不迁移、不重写，不改变工具 schema、授权和业务执行入口。

未知事件不会自动获得产品能力；不支持的远端工具不会在本地执行。持续保活可能让请求继续
等待，用户可取消或由调用者 deadline 终止；这属于确认后的等待语义，不声称可推断远端进度。
