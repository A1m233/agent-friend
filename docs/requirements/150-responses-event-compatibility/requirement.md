# 150 · Responses 事件完整支持与运行兼容性

## 状态

CONFIRMED

确认日期：2026-10-05。用户确认编号和范围，并已授权在方案确认后实施本范围内的代码修改。

## 背景

现有 Responses 对话在压缩成功、工具读取与备份完成后，因兼容连接返回
`keepalive` 事件而中断。该事件被解析器归为未知协议错误，导致原本可以继续的任务失败。
本次诊断已绑定实际安装版本并通过事件类型摘要核对触发类型；不将故障归因于上下文压缩。

[138](../138-responses-stream-compatibility-diagnostics/requirement.md) 已建立事件分类、
结构校验和受限错误证据，但未知事件停止、拒绝正文及引用信息未完整传递、事件清单仅对照
锁定 SDK 等边界，尚不足以满足日常使用的兼容性与信息完整性要求。

## 目标

- 当前产品已提供能力所需的合法事件能够正确完成，不因无害保活或附加事件中断任务。
- 文本、函数调用、拒绝说明、引用、usage、phase 和终态在适用链路中完整且一致。
- 真正的协议故障能够说明发生了什么、已完成到哪里，以及是否可以安全继续。
- 事件覆盖可持续检查，避免协议或 SDK 演进后只能靠用户再次撞到错误发现缺口。

## 范围

### 包含

- 对官方协议、锁定 SDK 和已观测兼容连接逐项盘点事件、输出项、字段与合法顺序，
  标明来源、版本或访问日期、当前处理、目标行为、支持边界与验证依据。
- 覆盖当前 Responses 路径的文本、推理元事件、函数调用、工具结果续接、拒绝说明、
  引用信息、usage、响应身份、phase、成功及非成功终态。
- 对 `keepalive` 等具有明确证据的非业务事件提供兼容处理；未知附加事件的处理必须有
  可验证边界，不能一律放行，也不能仅凭陌生事件名直接认定完整业务结果不可用。
- 核对上述信息从 provider 接收、引擎消费、持久化、历史恢复到适用展示入口的链路；
  有限展示能力须明确说明，不静默丢失可支持的信息。
- 区分模型拒绝、连接能力不支持、响应损坏、网络中断和内容不完整，保留已完成事实，
  按现有恢复契约给出准确的用户提示，不把拒绝回答当作模型服务故障。
- 保活不表示任务完成，不产生正文或工具调用，不妨碍取消；等待按相邻流事件的空闲时间约束，
  持续有事件时不另设正文推进计时或整轮累计时限，显式业务 deadline 仍然有效。
- 通过脱敏诊断证据辨认事件类别、处理决定、失败阶段与关联调用；保持正文、工具参数、
  凭据和私有推理内容的既有隐私边界。
- 补齐确定性协议回放、跨层回归与事件清单检查，覆盖协议演进和已观测兼容扩展。

### 不包含

- 新增音频生成、图像生成、托管搜索、服务端 Shell、MCP 或服务端压缩等独立产品能力；
  这些能力仍须盘点事件、输出项与接入前提，不能仅凭接收事件宣称完整支持。
- 承诺兼容所有未来未知协议、无条件忽略未知事件，或将残缺响应当作成功。
- 自动切换模型或 API、无界重试、重跑已完成工具以掩盖协议问题。
- 默认采集完整请求、原始 SSE、用户会话或私有推理；引入另一套会话存储或通用协议插件框架。
- 默认调用真实 LLM、构建安装包、自动验收或合入主干。

  并核对 [136](../136-model-error-recovery-consistency/requirement.md) 的恢复语义和
  [140](../140-model-request-timeout-recovery/requirement.md) 的超时约定。

- 官方定义与第三方运行观测分别记录；SDK 中存在类型不等于产品已完整支持该能力。
- 当前安装版事故来源与本需求实现基线分别记录，不用最新代码替代历史运行身份。

## 验收条件

- [x] AC-01：形成完整、可复查的覆盖清单，每项事件/输出项有明确处理类别、来源、边界与验证依据；新增协议项能暴露分类缺口。
- [x] AC-02：已观测 `keepalive` 与支持的非业务事件出现在合法位置时，文本/工具续接正常完成；不伪造输出或完成、不丢 usage、不破坏取消、事件空闲超时和显式业务 deadline；持续保活不触发另设的正文推进超时。
- [x] AC-03：现有能力的合法事件序列正确装配；多 item、交错函数调用、推理元事件、phase、usage、完成快照均不丢失、串线或重复。
- [x] AC-04：拒绝说明能够被保留并以可理解的拒绝结果呈现；恢复历史仍能识别拒绝，不误报普通服务故障，不执行残缺工具调用。
- [x] AC-05：支持的引用信息在接收、持久化、恢复及适用展示链路保留正确关联；无法展示或访问的引用有明确边界，不伪造链接或静默遗漏。
- [x] AC-06：未知附加事件、未支持能力、畸形事件、冲突或缺少终态分别按明确边界处理；可继续的情况不中断，不能证明完整的情况不误报成功。
- [x] AC-07：协议异常前已完成的工具事实保持可恢复；中断、有限重试或用户继续不会执行残缺调用、重复已完成副作用或宣称未完成配置已生效。
- [x] AC-08：诊断记录能说明处理决定及原因，且通过隐私、字段长度和日志/诊断包保留验证；仅具部分证据时明确说明缺口。
- [x] AC-09：确定性回放经过实际 SDK/transport 及公共模型边界，跨层覆盖持久化与恢复；Chat Completions 和现有 Responses route 无回归，项目 scripts/check 全绿。
- [x] AC-10：用户确认验收完成；真实模型与桌面视觉验收如需执行，按各自授权边界记录，不以未执行替代通过。
