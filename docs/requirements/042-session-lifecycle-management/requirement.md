# 042 · 会话生命周期管理

> Session Lifecycle Management
>
> 为桌面端会话补齐第一阶段管理能力：聊天侧栏支持单个会话重命名与归档；设置中心可查看已归档会话，并支持搜索、取消归档、单个永久删除和全部删除已归档会话。确认类交互统一收敛到一个纯 UI 确认弹窗组件，语音通话确认迁移到该组件且保持现有视觉不变。

## 1. 背景

### 1.1 现状

- 聊天页已有历史会话侧栏，支持新建会话、打开历史会话和恢复上次打开会话。
- 当前会话标题来自后端 session summary，用户不能手动重命名。
- 历史会话没有归档能力，所有会话都会出现在普通历史列表中。
- 后端已有删除 session 的接口，但当前语义主要服务内部清理，不是面向用户的会话管理入口。
- 设置中心已有两栏 shell 和基础分类，但还没有会话管理入口。
- 语音通话已有业务确认弹窗，样式独立写在 `VoiceTunnelConsentDialog` 中；后续删除、归档等高风险操作也需要一致的 double check 体验。

### 1.2 这次要做什么

本需求新增“会话生命周期管理”的第一批用户可见能力：

- 用户可以在聊天侧栏重命名单个会话。
- 用户可以在聊天侧栏归档单个会话；归档后，该会话从普通历史列表中隐藏。
- 用户可以在设置中心进入已归档会话视图，搜索归档会话，并对单个归档会话执行取消归档或永久删除。
- 用户可以一键永久删除全部已归档会话。
- 归档、删除、全部删除、语音通话确认均使用统一确认弹窗组件；只有语音通话确认需要 3 秒等待，其它确认不倒计时。

### 1.3 设计共识

- **确认弹窗先统一 UI，再复用业务**：新增纯 UI `ConfirmDialog` 类组件，不绑定会话、语音或设置业务；语音通话弹窗迁移后视觉必须保持不变。
- **归档不是删除**：归档只改变会话在列表中的可见性；取消归档后，会话重新回到普通历史列表。
- **删除是永久动作**：单个删除与全部删除已归档会话都必须 double check；删除后会话文件与会话管理元数据不再保留。
- **删除不联动 memory**：本期永久删除会话不软删或清理由该会话抽取出的 memory，避免把会话生命周期与记忆生命周期耦合。
- **普通历史列表默认排除归档会话**：已归档会话仅在设置中心归档视图中管理。
- **当前会话被归档或删除时前端要自洽**：如果操作目标是聊天页当前打开的会话，聊天页应回到安全空态 / 新会话态，清理上次打开会话记录，并刷新跨窗口会话列表。
- **已归档会话本期不直接打开**：用户需要先取消归档，再回到普通聊天历史列表打开。
- **归档列表时间优先展示最后聊天时间**：已归档列表中的时间信息以会话最近活跃时间为主；归档时间可作为内部字段或排序辅助，UI 不强制展示。

## 3. 非目标（Out of Scope）

- 不做 project 概念、project filter 或按 project 分组。
- 不做归档会话直接打开查看。
- 不做批量选择、多选删除或多选取消归档。
- 不做会话导出、恢复站、最近删除、撤销删除。
- 不做自动会话标题总结或 LLM 标题生成。
- 不改 memory 生命周期：删除会话不联动 memory source refs。
- 不调整 IM 会话、语音通话业务流程或 voice_bridge 控制协议。
- 不重做设置中心整体信息架构；只新增会话归档管理入口。

## 4. 核心需求详述

### 4.1 通用确认弹窗

- **R-4.1.1 纯 UI 边界**：确认弹窗组件只接收 props 渲染，不依赖会话 store、语音 store、settings 或后端接口。
- **R-4.1.2 操作语义**：组件支持默认确认与 destructive 确认；destructive 确认按钮使用项目现有危险操作视觉。
- **R-4.1.3 布局变体**：组件支持至少两种按钮布局：普通横向布局，以及语音通话现有的纵向 / stacked 布局。
- **R-4.1.4 可选等待时间**：组件默认不倒计时；当业务传入等待秒数时，确认按钮在等待结束前不可点击，并清晰展示剩余等待状态。
- **R-4.1.5 loading 状态**：确认动作进行中时，确认按钮可展示 loading 并阻止重复提交。
- **R-4.1.6 关闭行为**：用户点击取消、关闭弹窗或按 Escape 时，业务应收到取消语义；不能误触确认。

### 4.2 语音通话确认迁移

- **R-4.2.1 样式无变化**：语音通话确认迁移到通用确认弹窗后，标题、正文、辅助说明、弹窗尺寸、背景、阴影、按钮排布与当前视觉保持一致。
- **R-4.2.2 3 秒等待**：语音通话确认按钮需要等待 3 秒后才可点击。
- **R-4.2.3 既有业务不变**：确认后继续走原有拨号流程；取消后继续走原有取消流程。
- **R-4.2.4 设置项不变**：本次不改变 `voiceTunnelConsentAccepted` 的保存语义。

### 4.3 聊天侧栏会话操作

- **R-4.3.1 hover 操作入口**：普通历史会话 item 在 hover / focus 时展示操作入口；常态下不挤占标题与时间信息。
- **R-4.3.2 重命名入口**：用户可对单个普通会话执行重命名。
- **R-4.3.3 归档入口**：用户可对单个普通会话执行归档；归档前必须弹出确认。
- **R-4.3.4 当前会话归档**：如果归档目标是当前打开会话，归档成功后聊天页清空当前会话上下文，进入安全空态 / 新会话态，并清理 last chat session id。
- **R-4.3.5 列表刷新**：归档或重命名成功后，普通历史列表应刷新并展示最新状态。

### 4.4 会话重命名

- **R-4.4.1 标题输入**：用户可输入新的会话展示标题。
- **R-4.4.2 空标题处理**：空白标题不得提交；应保留原标题或提示用户补齐。
- **R-4.4.3 标题展示**：重命名成功后，普通历史列表和归档列表均展示新标题。
- **R-4.4.4 标题持久化**：应用重启后，重命名标题仍然可见。
- **R-4.4.5 不改事件内容**：重命名只影响会话展示标题，不修改历史消息内容。

### 4.5 会话归档

- **R-4.5.1 归档确认**：归档前弹出确认弹窗；归档确认不倒计时。
- **R-4.5.2 普通列表隐藏**：归档成功后，该会话从普通历史列表中消失。
- **R-4.5.3 归档列表可见**：归档成功后，该会话可在设置中心已归档会话列表中找到。
- **R-4.5.4 归档不破坏历史**：归档不删除会话文件，不改变消息事件流。

### 4.6 设置中心已归档会话视图

- **R-4.6.1 设置入口**：设置中心新增已归档会话管理入口。
- **R-4.6.2 搜索**：用户可按标题搜索已归档会话；搜索仅作用于归档列表。
- **R-4.6.3 列表内容**：列表展示会话标题和最近活跃时间；无归档会话或搜索无结果时展示空态。
- **R-4.6.4 全部删除**：归档列表存在会话时，提供“全部删除”入口；点击后必须确认。
- **R-4.6.5 操作 hover 显示**：单个归档 item 的取消归档与删除入口在 hover / focus 时出现。
- **R-4.6.6 destructive 删除视觉**：单个删除与全部删除均使用危险操作视觉。

### 4.7 取消归档

- **R-4.7.1 单项恢复**：用户可对单个已归档会话执行取消归档。
- **R-4.7.2 恢复后列表更新**：取消归档成功后，该会话从归档列表消失，并重新出现在普通历史列表。
- **R-4.7.3 不需要确认**：取消归档是可逆的低风险操作，本期不要求 double check。

### 4.8 永久删除

- **R-4.8.1 单个删除确认**：删除单个已归档会话前必须弹出确认弹窗；不倒计时。
- **R-4.8.2 全部删除确认**：删除全部已归档会话前必须弹出确认弹窗；不倒计时。
- **R-4.8.3 删除结果**：删除成功后，会话不再出现在普通历史列表或归档列表中，重新打开应用也不应恢复。
- **R-4.8.4 当前会话删除**：如果删除目标是当前打开会话，删除成功后聊天页清空当前会话上下文，进入安全空态 / 新会话态，并清理 last chat session id。
- **R-4.8.5 不联动 memory**：删除会话不触发 memory 软删、重建或清理。

### 4.9 后端会话管理契约

- **R-4.9.1 列表区分归档状态**：后端支持获取未归档会话列表和已归档会话列表。
- **R-4.9.2 元数据持久化**：重命名标题和归档状态需要稳定持久化，应用重启后仍然可读。
- **R-4.9.3 删除一致性**：删除会话时，对应会话管理元数据也应同步清理，避免孤儿记录污染列表。
- **R-4.9.4 兼容旧会话**：历史已有 session 文件在没有管理元数据时，默认视为未归档，并使用既有初始标题。
- **R-4.9.5 错误语义**：目标会话不存在、标题非法、删除失败等情况应返回可被前端转成友好提示的错误。

### 4.10 跨窗口同步

- **R-4.10.1 会话变更事件**：重命名、归档、取消归档、删除、全部删除成功后，应触发跨窗口会话变更通知。
- **R-4.10.2 聊天页刷新**：聊天页收到会话变更后刷新普通历史列表。
- **R-4.10.3 设置页刷新**：设置页归档视图收到会话变更后刷新归档列表。
- **R-4.10.4 last session 清理**：当前或上次打开会话被归档 / 删除后，持久化的 last chat session id 不应继续指向不可恢复打开的会话。

## 5. 使用约束

- **前端 UI 约束**：`frontend-ui-conventions` 生效。页面 / 业务代码不得散写原生交互件；新增通用纯 UI 件放在 `frontend/src/components/ui/`，并沿用项目 token。
- **shadcn 约束**：若实现中需要新增 dropdown-menu 等 shadcn 通用件，必须通过项目 `add-shadcn-component` skill 与 shadcn CLI 引入，不手写冒充 shadcn 源码。
- **视觉验收约束**：本需求影响聊天页、设置页和语音通话窗口 UI，验收时需要按 `frontend-visual-verification` / `desktop-visual-inspection` 观察真实 Tauri 桌面端；Vite web 预览只能作为草稿。
- **后端存储约束**：用户数据仍走 `agent.paths` 相关目录，不能把会话管理数据落到仓库根 `data/` 或前端 `localStorage`。
- **确认弹窗约束**：语音通话迁移后必须确认视觉无变化；删除和全部删除必须使用 destructive 视觉。
- **测试约束**：后端会话管理契约、旧会话兼容、重命名 / 归档 / 删除状态转换应有自动化测试；前端 store/API 与关键纯逻辑应补测试。
- **真实 LLM 调用授权**：本需求不需要真实 LLM 调用；如验收过程中触发真实对话，需另行确认。

## 6. 验收标准

- **AC-1 语音确认视觉不变**：语音通话确认弹窗迁移到统一确认弹窗后，真实桌面端视觉与当前版本一致，且确认按钮需要等待 3 秒后可点击。
- **AC-2 普通确认无倒计时**：归档、单个删除、全部删除确认弹窗均不倒计时。
- **AC-3 会话重命名**：用户可从聊天侧栏重命名单个会话；刷新列表、重启应用后新标题仍展示。
- **AC-4 会话归档**：用户归档单个会话后，该会话从普通历史列表消失，并出现在设置中心已归档会话列表。
- **AC-5 当前会话归档安全态**：归档当前打开会话后，聊天页不再停留在已归档会话上下文中，last chat session id 被清理。
- **AC-6 归档搜索**：设置中心已归档会话列表可按标题搜索；空列表和无搜索结果都有清晰空态。
- **AC-7 取消归档**：用户可取消归档单个会话；取消后普通历史列表恢复展示该会话，归档列表移除该会话。
- **AC-8 单个永久删除**：用户可永久删除单个已归档会话；删除前有 destructive 确认，删除后重启应用也不恢复。
- **AC-9 全部删除**：用户可永久删除全部已归档会话；删除前有 destructive 确认，成功后归档列表为空。
- **AC-10 删除不联动 memory**：删除会话不会触发 memory 软删或清理逻辑。
- **AC-11 跨窗口刷新**：聊天页和设置页同时打开时，在任一窗口修改会话状态，另一窗口能刷新到最新列表。
- **AC-12 旧会话兼容**：没有会话管理元数据的历史 session 默认显示在普通历史列表，标题仍使用既有 session summary。
- **AC-13 自动化门禁**：相关单测通过，`./scripts/check` 全绿。
- **AC-14 真实桌面验收**：在当前开发平台完成真实 Tauri 桌面端观察，覆盖聊天侧栏 hover 操作、确认弹窗、设置中心归档列表、语音通话确认样式。

## 7. 已知风险与监测项

| # | 风险 / 监测项 | 处理 |
| --- | --- | --- |
| 1 | 会话 JSONL 是 append-only 事件流，重命名 / 归档若直接写入事件流可能拖慢列表查询或污染对话语义 | design 阶段明确会话管理元数据与事件流边界，并保持旧 session 兼容 |
| 2 | 统一确认弹窗如果抽象过宽，可能变成难维护的万能弹窗 | 只覆盖当前已确认场景：语音确认、归档、删除、全部删除；其它高级能力后续再扩展 |
| 3 | 语音通话弹窗迁移后视觉细节可能漂移 | 迁移前后用真实桌面端截图 / DOM 检查比对，必要时保留业务 wrapper 控制样式 |
| 4 | 当前会话被归档 / 删除时，conversation store、sessions store、last chat persistence 可能出现不一致 | design 阶段明确成功回调顺序和跨窗口事件语义，并补 store 测试 |
| 5 | 全部删除已归档会话涉及批量文件操作，部分失败时用户提示与状态回滚复杂 | design 阶段定义批量删除返回语义和前端刷新策略 |
| 6 | 设置中心新增会话入口可能与后续 project / 多工作区概念重叠 | 本期只做已归档会话，不引入 project 过滤；后续 project 作为独立需求 |
