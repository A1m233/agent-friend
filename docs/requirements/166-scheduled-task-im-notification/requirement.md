# 166 · 定时任务 IM 结果通知

## 状态

CONFIRMED

## 背景

现有定时任务会向固定会话提交请求，执行 Skill 或项目工作，并将结果保存在该会话。会话绑定 IM 并不意味着定时运行的结果会自动发送到 IM，用户离开桌面后可能不知道工作已经完成或失败。

产品已有 IM 会话绑定、消息投递和 Todo 提醒通知能力。本需求在单个定时任务上提供可选的结果通知，复用并按需要扩展现有逻辑。

## 目标

- 用户可以逐个定时任务决定是否把执行结果发送到执行会话绑定的 IM。
- 结果沿用本次任务的真实输出，不为通知重新执行业务或生成另一轮模型回复。
- 用户能够分别判断任务执行结果与 IM 投递结果。

## 范围与需求

### R-1 任务级设置

- 创建、编辑定时任务时提供“将结果发送到会话绑定的 IM”开关，默认关闭；旧任务缺少该设置时保持关闭。
- 开关随任务持久保存，重启后保留；同一会话中的不同任务可独立设置。
- 前端与已有自然语言任务管理入口共用这一配置，查询和详情能够辨认是否开启。
- 开启通知只授权该任务的结果投递，不改变任务执行权限，也不自动开启其它任务或普通手动对话的转发。

### R-2 发送时机与内容

- 开启后，定时触发、离线补跑和任务“立即运行”均按同一规则处理，在本次执行结束后投递结果。
- 通知来自本次运行的最终回复，不转发中间说明、思考、工具调用或工具原始输出，也不取同会话其它运行的回复。
- 本次运行失败且没有最终回复时，发送简短、可理解的失败状态，不能宣称工作已完成。
- 通知提供必要的任务名称和执行状态以便辨认；完整执行记录继续保存在原会话与任务历史。
- 等待审批期间的远程审批通知不属于本次范围，不因开启结果通知而获得 QQ 审批能力。
- 失败、中断或提交拒绝有结果或简短状态通知；用户主动取消、同任务忙导致跳过以及计划过期只记录历史，不额外通知。

### R-3 跟随会话绑定

- 通知目标来自本次实际执行会话在发送时仍有效的 IM 绑定，不使用任务创建来源会话，也不猜测收件人。
- 同一执行会话绑定多个 IM 聊天时，向这些绑定分别投递；界面说明会发送到所有当前绑定。
- 已解绑或已切换到其它会话的目标不再接收本次通知。
- 没有绑定时跳过 IM 投递，任务照常执行，结果仍保存在原会话。
- 绑定存在但通道离线、平台拒绝或发送结果不确定时如实记录，不静默换发到其它会话或收件人。

### R-4 投递反馈与防重复

- 任务执行结果与通知投递结果分别记录和展示，支持“任务已完成，但通知失败”。
- 多个目标各自记录投递结果，单个目标失败不掩盖其它目标的结果。
- 记录成功、明确失败、结果不确定及跳过原因，不把调用返回或超时直接解释为用户已经收到。
- 同一次运行不得因重复完成事件或进程重启而重复发送；发送结果不确定时不自动重发。
- 重启后明确尚未尝试的通知可继续首次投递；已经尝试且结果不确定的通知保留未知，旧任务历史不追溯发送。
- 投递失败不能导致任务重新执行、覆盖任务终态或影响其它任务的调度。

### R-5 复用与兼容约束

- 复用既有会话绑定和 IM 消息投递能力；必要公共能力在现有逻辑上提取或扩展，供原调用方和定时任务共用。
- 不复制一套仅供定时任务使用的 IM 发送、错误分类或重试逻辑，不要求各 Skill 或项目保存 QQ 凭据并自行发送。
- 保持原 Todo 提醒的通知策略与用户可见行为；不把其活跃位置选择策略直接套用到已明确开启的任务结果通知。
- 保持现有调度、会话队列、Skill 加载、执行权限、会话持久化和任务生命周期行为。
- IM 平台的权限、频控及发送限制继续生效；设置开启不等于平台保证送达。

## 不包含

- 独立收件人选择器、全局结果广播、任意会话自动转发或新的 IM 平台接入。
- 新的调度器、任务执行器、通用通知框架、投递重试队列或手动补发功能。
- 中间进度推送、远程审批通知、额外模型摘要调用、独立附件或图片投递能力扩展。
- 修改 Skill 或项目业务逻辑，以及应用退出后仍独立运行的后台服务。

## 验收条件

- [x] **AC-1**：创建、编辑、查询和重启恢复均保留任务开关；旧任务默认关闭；同会话多个任务互不影响，界面和自然语言管理状态一致。
- [x] **AC-2**：开启的任务在定时触发、离线补跑和立即运行结束后发送本次最终回复；关闭时不发送，不混入其它运行、中间说明或工具输出。
- [x] **AC-3**：失败且没有最终回复时发送准确的简短失败状态；通知不产生额外模型调用或业务重跑，审批等待不触发本期通知。
- [x] **AC-4**：发送到执行会话当前所有有效绑定；覆盖无绑定、多个绑定、发送前解绑和切换会话，不发送到来源会话或其它收件人。
- [x] **AC-5**：通道离线、平台拒绝和超时分别如实反馈；多个目标结果可区分，投递失败不改变执行结果或阻塞其它任务调度。
- [x] **AC-6**：重复终态处理、并发处理和重启不重复发送；结果不确定时不自动重发；旧历史不会因升级被追溯发送。
- [x] **AC-7**：有明确的现有能力复用路径和原提醒回归证据，受影响自动化测试及项目统一检查通过。
- [x] **AC-8**：真实 IM 接收与界面验收结果如实记录，并由用户确认最终验收；真实对外发送、桌面启动和视觉观察按适用授权流程执行，不用 mock 结果冒充真实送达。
