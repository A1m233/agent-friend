# 176 · AF 桌面前端视觉整理

## 状态

CONFIRMED · 2026-11-08 确认首批范围，具体视觉方案待定。

## 背景与目标

打开聊天窗口时，用户应能认出 AF 并自然找到输入框。会话增多后，用户应能快速认出当前会话及需要处理的状态。从聊天切到待办、设置或 IM 接入时，同级标题、辅助说明和滚动区域应有一致的视觉层级。

## 已确认的改动与验收条件

| 区域 | 改动 | 验收时看什么 |
| --- | --- | --- |
| 聊天首页与顶栏 | 保留居中问候和输入框的留白，强化 AF 的身份感。连接正常时右上角只显示反馈入口。 | 新开聊天，问候与输入框是第一眼的重点。反馈仍可找到，断线时能直接看出异常。 |
| 聊天侧栏 | 收敛重复的“新对话”入口，让常用操作、当前会话和需要处理的会话容易区分。 | 展开侧栏后只有一个常驻的新对话主入口。历史较长时仍能启动新对话，当前会话和等待处理状态都可辨认。 |
| 同级页面 | 统一设置、待办、IM 接入的页头层级，包括标题字级、辅助文字、标题与说明的间距，以及同排操作的对齐。各页按内容保留窄栏、双栏或表单布局。 | 在同一窗口尺寸和主题下依次切换三页，同级标题和说明呈现一致，操作与所属标题的关系清楚。 |
| 滚动区域 | 页面自有的滚动区统一采用 AF 已有的细滚动条样式。优先看聊天历史、设置主体和待办双栏，再盘点定时任务、记忆和长工具输出等区域。 | 长内容出现时，滑块清楚、可拖动，左右栏仍可独立滚动。涉及历史位置、触底加载和键盘操作的区域保留原有行为。 |

## 待定细节

- 首页是否放角色头像、反馈入口的最终位置、选中行和滑块的具体颜色与尺寸，留到视觉方案阶段比较。
- 表单输入框、菜单、桌宠气泡等有独立滚动行为的表面逐项判断。浅色和深色都要能辨认状态。
- 方案稳定后评估将哪些可复用约定写进现有前端 rule 或 skill。本阶段只记录需求和视觉参考。
