# Varin 桌面界面观察

2026-11-08。参考作者在 Linux DO 发布的三张桌面产品截图，均为浅色主题。以下是供 AF 试稿时比较的候选做法。原图没有演示滑块拖动、展开动画或深色主题，这些效果仍待实物验证。[作者原帖](https://linux.do/t/topic/3110574)

| 画面 | 在图里能看到什么 | 值得在 AF 试什么 |
| --- | --- | --- |
| [助手与角色面板](https://cdn3.ldstatic.com/original/4X/1/5/9/1590282dc6215c6d12a09edbd4f3582b6eea9bca.png) | 灰白画布上，角色的头和双手跨过侧栏的一道横线，下方接名字和状态。右边的角色容易记住，左边的回复仍有整列留白。工具经过缩成一行浅色文字。 | 首页可以试一个小尺寸的 AF 角色标记，靠近问候语。用同一尺寸的窗口比较有无标记的两版，看视线能否自然移到输入框。 |
| [工作台与侧栏](https://cdn3.ldstatic.com/original/4X/4/6/8/468dd891791b34cae0bf47b8cf6324b70a0a1450.png) | 新建和搜索各有一个图文入口；历史行没有逐条画框。当前会话用一整条淡蓝灰底标出，普通行靠对齐和行距分组。 | AF 的历史项可试整行浅底表示“当前”，把小图标留给未读或等待处理。用一列同时含当前、未读和等待状态的会话检查三者能否区分。 |
| [聊天正文与输入框](https://cdn3.ldstatic.com/original/4X/5/0/a/50af52deda17588cbcd3e7cbd9369620beca7c56.png) | 回复、选项和输入框共用左边线。用户消息用轻微底色区分，助手正文直接铺在画布上。输入框的细边和浅阴影勾出轮廓，蓝色集中在选中项和操作。 | AF 的正文和输入框已经共用列宽。优先比较正文、辅助信息和输入区各自的对比度，并检查长标题、工具行是否仍沿同一条边线阅读。 |

试稿时先比较两个场景：空白首页，以及有长历史和待处理状态的会话。前者看问候、角色与输入框的关系，后者看会话列表和工具摘要是否让正文容易扫读。页头与滚动条仍按 AF 自身场景验收。
