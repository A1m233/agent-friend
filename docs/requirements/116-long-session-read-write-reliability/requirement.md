# 116 · 长会话查询与读写可靠性

## 状态

CONFIRMED

## 背景

长会话的一次真实运行在工具执行前提交会话记录时，因等待 JSONL 写锁超过 10 秒而失败。已落盘的用户消息、部分助手消息和失败终态仍然存在；不能把这次故障描述为整段会话丢失。

调查已确认当前查询路径存在额外的完整历史读取：普通内容变更会触发当前会话的授权状态刷新；授权查询为确认会话存在而加载完整历史；详情查询会重复加载同一历史。会话加载的共享锁同时覆盖原始读取与逐行解析。

上述调用关系由代码支持，但事故时的锁持有者未知，尚未稳定复现同一次超时。长会话体积及离线读取耗时只能说明压力条件，不能单独证明事故根因。本需求以消除已确认的冗余、增强并发读写验证和可观测性为目标，不承诺仅凭这些改动就解释或杜绝所有存储故障。

115 已完成助手阶段协议与执行过程展示。本需求基于其合入后的主干独立交付，不改变助手阶段、工具执行或模型行为语义。

## 目标

- 查询授权状态或判断会话存在时，不因历史持续增长而反复加载完整会话。
- 合并重复查询，同时保证运行中的授权变化、切会话和重连后的状态仍及时、准确。
- 详情查询减少无用读取，保持已有版本校准和历史恢复行为。
- 用确定性并发验证及不包含用户内容的锁观测，判断读写竞争是否得到改善。
- 开发和验证使用隔离数据，用户可以继续使用原有运行实例和真实会话。

## 范围

### 包含

- 收敛只读授权状态和存在性查询对完整历史加载的依赖，明确不存在、不可读取及历史损坏等情况的查询边界；授权修改与任务执行中的历史校验不属于本项减负范围。
- 合并当前会话的重复授权刷新，保留真正授权变更、切会话、重连及修改失败后的必要校准。
- 复用详情请求中已经读取的会话信息，保留版本变化时的必要重新读取。
- 覆盖长会话、多读者与追加写入并发时的正确性、读取次数及写入进度。
- 增加能够区分读写操作、锁等待与持有耗时的本地观测，关联会话而不记录其内容。
- 评估缩小读取锁范围的正确性与收益；是否采用锁外解析，在技术方案中明确，并以一致性及恢复验证为前提。

### 不包含

- 将会话存储整体迁移到数据库，或实现通用摘要索引、分页、日志压缩及历史清理。
- 通过增大锁超时、移除文件锁或忽略持久化错误掩盖问题。
- 自动重放失败请求、自动重跑工具或改变外部副作用恢复策略。
- 跨语言事件字段补齐、服务退出后的就绪状态修复及记忆抽取持久化。
- 修改用户真实会话、复制真实内容到仓库、重跑用户的 MAA 任务或调用真实 LLM。
- 重启用户正在使用的运行实例，或把开发版本直接应用到该实例。

## 行为要求

### 轻量查询与错误边界

授权状态查询与完整历史读取承担不同职责。轻量查询必须保留会话标识和路径校验，不存在的会话不得返回虚构的默认授权状态。

会话文件存在但历史损坏或正文不可读时，仍允许查询独立授权元数据；文件属性检查失败必须报告错误。轻量查询成功不能被解释为历史可恢复，也不能放宽授权修改或新任务执行的前置条件。

### 授权刷新与会话隔离

运行中的授权变化仍需及时可见，不得仅为了减少查询而统一推迟到运行结束。普通内容追加不应制造持续堆积的授权查询；旧响应不能覆盖较新状态，也不能污染切换后的其他会话。

### 详情与持久化一致性

详情请求应减少已经取得信息的重复读取，同时保留现有 revision 校准。正常完成的批量追加不得被并发读者读取为中间态；I/O 中断留下的部分尾部继续按既有恢复规则判断，不新增物理写入的事务保证。

### 验证与诊断

自动化验证使用合成短会话、长会话及受控并发条件。报告应分别说明受控场景的改善、仍有的竞争边界，以及是否真正复现历史事故。

锁观测只记录定位竞争所需的操作、身份、耗时与规模信息，不包含用户文本、工具参数或输出、授权凭据及原始 JSONL。

## 验收条件

- [x] **AC-1 轻量查询**：只读授权状态与存在性查询不加载完整历史；合成短、长会话的检查能证明这一点，不存在的会话保持明确错误。
- [x] **AC-2 错误与权限边界**：非法标识、旧路径兼容及不存在场景有回归覆盖；历史损坏时的轻量查询行为按确认方案验证，完整历史及执行路径的保护不被放宽。
- [x] **AC-3 刷新合并**：连续普通内容变更不会产生无用的授权请求堆积；必要刷新能够合并且最终收敛，不遗漏刷新期间发生的新授权变更。
- [x] **AC-4 运行中与跨会话一致性**：活跃 run 中授权变化仍能更新；切会话、重连及修改失败后的校准有效，旧响应不会覆盖较新状态或其他会话。
- [x] **AC-5 详情读取**：一次详情查询消除仅用于重复确认存在或取得授权状态的完整历史加载；revision 变化后的必要校准保持有效。
- [x] **AC-6 并发与恢复**：合成长会话、多读者和批量追加场景验证读取快照、写入进度及错误处理；保留损坏尾部、工具中断和 rollout 恢复的相关回归覆盖。
- [x] **AC-7 锁观测**：可以区分锁等待、锁持有、读取及写入，并关联会话；成功、失败及超时场景有确定性覆盖，日志中不包含会话内容或凭据。
- [x] **AC-8 锁范围决策**：技术方案明确是否采用锁外解析及理由；若采用，证明解析旧快照期间追加写入可继续，读取不会拼接前后两个不同快照。
- [x] **AC-9 开发隔离**：测试只使用临时目录和合成数据，不修改真实会话，不重跑 MAA 或真实模型，不影响用户正在使用的运行实例。
- [x] **AC-10 项目门禁与验收**：受影响测试及项目 `scripts/check` 门禁通过，记录证据和局限，并取得用户验收确认后收口。
