## 背景

[114](../114-llm-provider-responses-api/requirement.md) 已合入 main，提供原生 Responses 流式调用、assistant item phase 映射和与 Provider 无关的能力查询。其合入提交为 `c863ac793717f3b2335993a17471b5531d1326e4`。

当前 Agent 尚未保留消息 phase 和完整 assistant item 边界，桌面端仍将工具前后的 assistant 文本按普通文本块展示。需求 115 接续这一基础，完成阶段语义、持久化与回放、上层协议和桌面对话执行过程折叠。

现有模型历史、记忆、搜索、IM、语音和宠物等业务已经消费工具前后的 assistant 文本；部分内部模型调用还有独立的 JSON 或结构化摘要输出契约。因此 phase 应增加信息，而不能把所有业务改成只消费最终回答。用户也可以在同一会话中切换支持和不支持 phase 的模型，历史轮的展示必须保持独立、稳定。

## 目标

- 支持原生阶段语义的 Agent run 能清楚区分执行过程与最终回答，桌面用户可以展开或收起执行过程。
- 每轮桌面对话都有独立的用时/轮级状态/折叠入口，运行时实时更新、结束后固定；模型和工具的当前活动文案仍在内容尾部显示。是否支持折叠只影响入口的点击能力，不影响用时与活动信息。
- 刷新、重开、切换模型、恢复和编辑重发后，展示仍由相应 run 自己的有效会话事实决定。
- 既有业务继续获得其原来可见的完整 assistant 文本，严格输出工作负载保持原契约。
- 所有上层只消费统一阶段和能力，不感知底层厂商或调用 API。

- 逐项保护模型历史、Memory、上下文压缩、搜索、IM、语音、宠物、提醒、主动轮和现有文本聚合入口。
- DeepSeek 三个现有 Responses 模型启用 native phase 能力；Kimi K3 保留其 Responses route，但暂不启用阶段交互。

- IM、语音、宠物的新 phase 视觉、宠物气泡折叠、推理正文展示；本次新增计时仅用于桌面对话的逐 run 状态行，不扩展到其它通道。
- 用户手动展开/收起状态跨进程持久化；它是当前界面的 view state。
- Agent 执行进程异常退出后的自动续跑、自动重发模型请求或重新执行工具；文中恢复只指历史回放、模型上下文重建或仍存活后台的运行态重连。

- 修复会话已读蓝点重新出现；用户决定仅登记 [issue 060](../../issues/060-session-read-state-reappears/README.md)，文档随本需求后续合入，生产修复另行处理。

## 功能要求

### 1. 阶段语义与模块责任

- 面向业务的 assistant 文本阶段统一为 `commentary | final_answer | unknown`。
- `commentary` 是用户可见的工具前说明、执行更新或阶段性进度；它不是私有 reasoning。
- `final_answer` 表达本轮面向用户的收尾回答。文字阶段与 run 的完成、失败、取消状态分别表达，不能用 phase 替代运行终态。
- `unknown` 表示无法可靠确定。缺失、非法或旧数据不得按文本位置、最后一轮、是否有工具、结束原因或当前模型静默猜成其它阶段。
- `llm_providers` 负责厂商解析、API/transport 选择、能力声明和原生字段转换；`agent.system_prompt` 负责何时说明进度、何时收尾；Agent 负责语义校验、业务事件和持久化；Bridge 负责协议投影与透传；前端负责展示。
- 新增的厂商名称、模型名称、endpoint、SDK 或 transport 判断只能存在于 `llm_providers`；已有纯通道适配不因此迁移。测试与独立 smoke 可以指定待测模型。

### 2. 能力范围与行为 Prompt

| 模型 | 115 的阶段交互范围 |
| --- | --- |
| `deepseek/deepseek-v4-flash` | 启用 native phase |
| `deepseek/deepseek-v4-pro` | 启用 native phase |
| `deepseek/deepseek-v4-flash-vision-exp` | 启用 native phase，作为本期真实 smoke 的主模型 |
| `kimi/kimi-k3` | 保留 Responses，phase capability 继续 `unavailable`，使用 legacy 展示 |
| 其余既有 Chat Completions route | 保留 legacy 交互与 `unknown` 兼容 |

能力开启是用户确认的产品范围；不能将其描述为每个模型已经完成真实 phase 验证。单个 item 缺失 phase 时仍然未知。

每个 run 开始时冻结自身能力。native run 的 Prompt 规定有信息增量的简短 commentary 和真实收尾时的 final；普通直接回答不强制补一段进度，也不要求每次工具调用都重复说明。现有自然表达、通道约束和严格输出要求继续有效。

`unavailable` run 保持 legacy 展示，即使某次偶然收到 phase 也不临时切换整轮交互。上游真实 metadata 应保留以供回放和审计；能力快照不是删除原生事实的理由。

### 3. 逐 run 事实源、持久化与模型切换

沿用 [113](../113-session-rollout-persistence-and-recovery/design.md) 的权威边界：会话 JSONL 中的产品事件经 `Session.active_events` 投影 UI 和业务历史；同文件中的 rollout 内部事件恢复模型 transcript、上下文和缓存状态。

- 该轮能力、assistant 分段阶段和完成事实必须能从有效产品事件恢复。刷新后不向模型 catalog 查询“历史轮当时是否支持”。
- 折叠语义只属于对应 run，不读取会话当前模型来重新解释全部历史。以后修改模型 capability 配置也不能追溯改变已保存轮次。
- 持久化与实时分段保持稳定关联；同 response 的多个 item、同 phase 的不同 item、跨工具和多个 run 均不能误合并或串线。
- 模型历史保留 commentary 与 final 的正文、顺序和原始可回放 phase。切换到不支持该字段的 API 时，由 `llm_providers` 完成兼容转换，保留产品历史事实。
- `unknown` 正文照常回放；不能给原生 API 虚构支持值。展示侧的降级不得篡改已经收到的合法原生 phase。
- 旧 session 缺少 phase、能力或 run 信息时安全保留原展示，不追溯填值。编辑重发使旧分支失活后，折叠、搜索、引用和记忆继续服从相同 active projection。
- rollout 继续承担模型恢复，不增设 UI 从 rollout 猜展示的旁路；两种投影的文本、身份与 phase 关联需要有一致性验证。

### 4. 桌面对话展示

- 每个桌面对话 run 顶部显示独立的用时/轮级状态行：实际运行中为“已进行 xx”，被停止的轮次结束后为“xx 后被停止”，成功完成仍为“用时 xx”。停止文案不声明停止者或原因，不为此新增归因逻辑；其它失败/过期等实际结果不因本次文案改动被改写成停止。
- 刚发送及尚未开始的排队阶段暂不显示计时行和下方分隔线，只保留尾部加载/等待提示；实际开始后再出现“已进行 xx”，不闪现“用时未知”，也不用零秒充当等待占位。历史或异常确实缺少可信用时时仍明确未知：已停止显示“已停止，用时未知”，其余保持对应未知文案。发出取消请求但尚未实际结束时仍属于运行中、继续计时，不提前显示“被停止”。
- 顶部不承载等待模型、重试、整理工具结果等当前活动文案；这些继续在内容尾部显示。顶部字号/行高与正文一致、文字起点对齐，下方使用更细的分隔线，hover不改变背景和文字颜色。计时与活动信息均不依赖模型是否支持 phase。
- 用时行是唯一轮级展开/收起入口，统一控制该轮所有可折叠过程分段；有折叠资格且实际有可折叠内容时显示箭头并可点击。不支持折叠或没有过程内容时遵循相同的计时显示时机，但无箭头、点击行为或按钮悬停效果，不因折叠能力灰化或隐藏信息行。工具卡自身已有操作不因此禁用。
- 当前活动状态随内容进展显示在尾部：开始时可以只有等待文案；产出文字和工具结果后，后续等待出现在它们下面，不固定在头部。仅保留当前活动提示，不把旧加载文案作为历史正文残留；实际结束后移除活动提示，最终回答及失败等结果独立保留。停止结果由顶部摘要表达，不再在正文下单独显示“已停止回答”行。
- 手动收起执行过程时，当前等待/取消等活动状态仍在折叠区域外的尾部可见，不能让用户误以为本轮已结束。工具运行、审批与授权沿用各自已有卡片或入口，不另造重复的模型加载提示，也不隐藏必要交互。
- 用时口径为实际开始执行到实际结束的总经过时间，包含模型、工具、重试及等待授权的时间，不包含开始前排队。排队时显示排队状态，不伪装成正在执行。点击取消后到实际结束之前仍计时，不能在发出取消请求时提前停表。
- 用时依据该 run 的真实运行事实，刷新、切换会话/模型和重开不得重新从零累计；已结束轮次不再增长。缺少可信计时数据的旧记录显示“用时未知”，不猜值、不显示虚构的零秒；恢复时无法确认原结束时刻也不得把停机时间计入执行用时。
- 对符合阶段交互条件的 run，commentary 与适合收纳的工具活动组成可展开的执行区域，保留内部时序；有效 final 在区域外正常展示。
- 运行中执行区域默认展开。成功终态且存在有效 final 后，执行区域默认收起；当前界面中用户主动选择的开关状态应得到保留。
- 只有直接 final 且没有过程内容时不创建空折叠容器。
- unknown 文本始终在执行折叠区域外保持可见，legacy run 保持既有呈现。
- 失败、取消、不完整、只有 commentary 或没有可信 final 时，不自动收起过程，不伪装成已有完整回答。
- 需要用户处理的审批、授权或交互卡片保持可达；固定提醒事实、错误和现有主活动状态不因过程收起而消失。
- 搜索或引用导航命中折叠内文本时先展开再定位、高亮；展开后的 commentary 可选择引用。整条消息复制仍包含原来可复制的全部文本与固定事实内容。
- 复用现有主活动状态，避免同时出现多套矛盾的运行指示；折叠变化与虚拟列表、滚动跟随、用户离开底部阅读协作。
- 手动开关只保存在当前界面状态，刷新后由该轮持久事实重新计算默认状态，不把 UI 偏好写入模型 transcript。

### 5. 安全降级与执行连续性

- phase 缺失或非法：业务阶段为 unknown，正文保留。
- 同一原生 item 的 phase 可以随消息生命周期更新，不得仅因开始值与完成值不同就判定协议失败或中断执行。正文继续实时显示；阶段校正不得重复消息、改变正文与工具的原有顺序，或提前宣告 run 完成。
- 消息阶段应依据其原生生命周期事实更新；完成后的产品历史、最终展示与模型回放保持一致，不用开始时的旧值覆盖完成结果。允许同一段文字在回答区与执行过程区之间调整分类；自动收起仍须满足该 run 的成功终态及有效 final 条件。
- 阶段更新不等于放行真正的协议损坏；消息身份或正文发生不可接受的矛盾时，仍按明确错误/中断处理，已产出正文保持可见。缺失、非法 phase 与旧数据继续 unknown 降级，不从位置、工具或当前模型猜值。
- 标记 final 的文本后又出现工具调用或 commentary：不得据此提前完成 run 或隐藏后续内容；相应 final 的展示语义安全降级，保留原始来源事实。phase 不能替代工具授权或执行规则。
- 用户取消、超时、EOF、不完整终态以及有限重试都遵守既有运行契约。已输出文本不能因新增阶段事件重复发送或重放。
- 不为了补一个 final 自动增发模型请求；没有有效 final 的已结束 run 使用可见降级。
- 静态 Prompt、模型能力快照、模型历史分段和回放不能破坏既有 prompt-cache epoch、witness、usage 和 reasoning state 的观测或恢复边界。

### 6. 现有业务消费契约

下表的“完整文本”包含 commentary、final 和 unknown，仍服从各业务已有的 partial、角色、来源、surface 和 presentation 规则；不扩大原先不可见内容的访问范围。

| 业务 | 本期必须保留的行为 |
| --- | --- |
| Memory feed / 长期记忆 | 继续接收完整 assistant 文本；完整与 partial 的既有边界不变，按原顺序观察，不额外注入 phase 标签或重复 observe |
| 记忆抽取与语义 reconciliation | 继续一次性 `generate()`、JSON 解析及既有失败处理；不混入对话阶段 Prompt，不以 final 选择输出 |
| 上下文压缩 | 继续一次性 `generate()`、现有 `<analysis>/<summary>` 文本契约和解析；待压缩历史包含原有 commentary |
| 模型历史与对话回忆工具 | 完整保留可用文本及工具关联，支持阶段保真回放；不能用最后一个 assistant item 代替整个回应 |
| 全局搜索与 memory search 的 session source | commentary 可被命中，保留原有来源/时间/可见性过滤，结果锚点可定位 |
| IM 静态和流式回复 | 全部可见文本按原顺序投递，保留既有段落边界；流式回复不等待 final |
| IM 整条消息引用 | 聚合发送的消息可引用到其完整正文及稳定会话来源；分段后 fallback 不得缩成最后一段 |
| 语音与 OpenAI-compatible 出口 | 全部可见增量继续输出，不因 phase 缓冲到 final，不改变客户端正文契约 |
| 普通桌面对话 | 只改变执行过程展示；搜索、引用、复制、错误、审批和主活动状态继续可用 |
| Bedtime ambient 气泡 | 继续使用全部可见增量，包括 commentary；保留 source/presentation 路由 |
| Idle reflection | `memory_only/none` 继续静默，其内部观察文本保持原聚合行为 |
| Todo 固定提醒 | 确定性事实卡、IM 固定文案和宠物气泡独立投递，不要求模型 phase，不因缺少 final 丢弃 |
| Todo Agent 增强回应 | 桌面 conversation 回应适用本 run 的折叠；IM 保留完整文本；保持原先不进入宠物气泡的路由 |
| Social auth 续接 | 桌面和 IM 分别沿用其通道语义，commentary 不丢失，授权交互不被隐藏 |
| Scheduled task | 保持普通 UserEvent/专属会话路径，不因阶段元数据新增宠物气泡 |
| 宠物状态与口型 | 可见 text delta 继续触发既有状态和 lipsync，不过滤 commentary |
| send / send_async、CLI、eval | 原完整文本聚合契约不静默改成 final-only |

- 本次已确认的首次 smoke 预算为至多 2 次模型生成请求、每次最多 1024 输出 token、不自动重试。图像上传等前置网络操作需在设计中如实说明；若路由或场景无法在该边界验证，先报告并调整授权，不能省掉图像后声称 Vision 图像路径已验证。
- 首次 smoke 只能证明该模型该样本观察到的行为，不代表 Pro 等其它模型均已真实验证，也不证明阶段质量稳定。取消、重试和各类故障主要由确定性验证覆盖，不能把它们写成两次真实请求已全部验证。
- 真实调用前按 `llm-api-confirm` 告知目的、配置与调用量；额外调用、扩大模型或复验不自动继承无限授权。桌面端视觉验收方式在进入对应验证前按项目规则确认。

## 验收条件

- [ ] **AC-01 原生分段保真**：单次 response 的多个 assistant item（含相同 phase 的不同 item、交错 delta）能独立归位，实时/完成文本、工具关联、顺序和阶段不串线；同一 item 的阶段更新保持原消息身份，不能被开始值锁死。
- [ ] **AC-02 三态兼容**：原生 commentary/final 可用，缺失/非法/旧字段为 unknown；没有位置、工具存在性或当前模型补值。
- [ ] **AC-03 逐 run 能力**：新 run 使用冻结能力；同会话 native→legacy→native、反向切换、刷新、重开与 capability 配置变化均不改变旧 run 的展示资格。
- [ ] **AC-04 模型范围**：DeepSeek 三个现有模型声明 native；K3 Responses 保留但阶段交互 unavailable；其它 Chat 路径与存量配置保持兼容。
- [ ] **AC-05 产品事实与恢复**：有效会话事件可恢复每轮分段、阶段与终态；UI 不读取 rollout 或 currentModel 重新猜测历史。
- [ ] **AC-06 模型回放**：同 run 工具续接、下一用户轮、rollout 重启恢复和跨 API 模型切换保留正文及原生 phase；成功完成后产品历史、最终展示与模型回放中的阶段一致，不被流式开始值覆盖。unknown 不伪造 API phase，reasoning/tool call/result 关联正确。
- [ ] **AC-07 阶段更新与异常**：同一 item 开始/完成时的合法 phase 变化不单独触发失败；真正的身份/正文矛盾，以及 final 后续工具/commentary、取消、失败、超时、EOF 和 partial 场景保持文本可见且不提前完成或自动折叠；原始 phase 与展示降级不互相覆盖。
- [ ] **AC-08 重试与幂等回放**：新增 item 事件不扩大安全重试范围；重复输入回放和订阅恢复保留分段/阶段且不重复正文或工具动作。仅阶段元数据更新不能造成 IM/语音重复投递、Memory 重复观察或前端正文重播。
- [ ] **AC-09 Prompt 隔离**：native run 的进度/收尾指令来自 Agent Prompt；legacy、内部 JSON 与结构化摘要调用保留契约，正文不出现 marker。
- [ ] **AC-10 Memory 不回归**：commentary 继续进入完整消息观察，partial 过滤、顺序、来源及 observe 次数正确；两类记忆 JSON 调用的请求、解析与失败处理覆盖回归。
- [ ] **AC-11 摘要不回归**：摘要输入保留完整可用历史，`generate()` 与现有结构化文本解析不受 phase Prompt 或 final-only 聚合影响。
- [ ] **AC-12 搜索与引用**：两类 session 搜索可命中 commentary；桌面命中折叠文本自动展开定位；引用、复制及 IM 整条消息 fallback 保留正确完整内容和锚点。
- [ ] **AC-13 IM 与语音**：普通/流式 IM、语音和兼容 API 按原序输出全部可见阶段，保留段落及终态，不等待 final；CLI/send/eval 原聚合契约受保护。
- [ ] **AC-14 宠物与主动入口**：Bedtime、idle reflection、Todo 固定气泡/事实卡/增强回应、social auth、scheduled task、pet speaking/lipsync 按各自既有路由与可见性通过回归。
- [ ] **AC-15 桌面折叠**：阶段 run 的过程默认运行中展开、成功且有有效 final 后收起；final/unknown 可见，无空容器；失败/取消/无 final 不自动收起，用户当前手动选择不被反复覆盖。
- [ ] **AC-16 交互连续性**：审批/授权、固定提醒、错误与主活动状态可达；折叠与搜索定位、虚拟列表、滚动跟随协作；编辑重发的失活事件不泄漏到当前投影。
- [ ] **AC-17 上层边界**：Agent/Bridge/Frontend 没有新增 Provider/API 选择分支；能力和 phase 通过统一类型传递，不解析正文推断。
- [ ] **AC-18 Cache 与用量**：同一稳定 run/上下文的 continuation、Prompt cache epoch/witness、usage 及 reasoning 恢复具有覆盖；新增边界不静默破坏历史身份或报告精度。
- [ ] **AC-19 Vision 观察验证**：在已授权预算内保存可复查的公共链路 smoke 证据，明确实际图片输入、工具续接、所见 phase、endpoint 与 usage；缺失目标行为如实记为缺口，不靠猜 phase 或自动加请求通过。
- [ ] **AC-20 交付门禁**：项目要求的确定性检查与打包影响验证通过，真实 LLM 与视觉验证状态如实记录，用户明确验收后才合入 main。
- [ ] **AC-21 逐轮用时与终态摘要**：native与legacy均在顶部按运行/停止/成功完成分别显示“已进行xx / xx后被停止 / 用时xx”，停止不归因于任何人。刚发送/排队时计时行和分隔线均不出现，尾部等待仍可见；实际开始后直接显示真实用时，不闪现未知或用零秒占位。实际执行期间实时增长，模型/工具/重试/授权等待连续计时，排队不计入，取消请求不提前停表或显示停止终态。实际结束后固定，切会话/切模型/刷新/重开保持一致；历史/异常缺可信时间的停止记录为“已停止，用时未知”，其余明确未知，不虚构零秒或停机用时，也不把失败/过期等结果改写成停止。
- [ ] **AC-22 独立用时入口与尾部活动**：每run只有一个用时/折叠入口，不混入当前加载文案；支持且有过程内容时统一切换该轮全部可折叠部分，不支持或无过程时无箭头/点击。入口与正文同字号/行高且对齐，下方细线分隔，两种入口均无hover变色。开始等待、文字输出、工具执行/结果、后续等待及终态切换时，当前活动跟随内容尾部且不留下旧提示；手动收起后仍可见，真实结束后移除，不与工具/审批重复，也不留下独立停止行。final/unknown/必要交互卡、搜索引用、手动展开、滚动与复制继续正确。
