CONFIRMED

## 现状与边界

AttachmentStore 持久化内容寻址原件；Session.active_events 保留有效消息及附件引用，不随摘要折叠丢失。附件回收仍由 attachment_reconciliation 按持久事件判断，不改变原件存储布局。

现有命令工作目录按会话 ID 的 SHA-256 分隔；默认命令可以读写当前目录。会话删除已有工作目录清理入口。现有模型工具不能发现和准备历史文档，摘要中的附件标记也缺少资产身份。

## 方案

### 会话文件服务与工具

新增 `agent/session_files/`，负责当前有效用户消息附件的发现、授权和工作副本准备。工厂仅在 SessionStore 与 AttachmentStore 均可用时注册 `session_files` 工具。

工具使用 Draft 7 schema，提供两个互斥操作：

- `list`：按 offset/limit 分页，返回稳定 file_ref、来源消息、原始名称、媒体类型、大小和哈希。不复制文件，不将文件内容送入模型。列表不声称原件已通过完整性验证。
- `prepare`：接受 list 返回的 file_ref；只在当前会话有效用户消息中查找，验证资产原件并准备副本，返回同一身份信息、工作目录及相对路径。PDF 后续经已有命令与 Skill 按需处理；图片沿用既有能力。

session_id 由 Conversation 注入，不在 public schema 中暴露。file_ref 由消息 UUID 和附件序号确定，不接受任意路径或全局 asset_id 作为授权凭据。历史消息编辑失活后，该引用不能再通过工具准备。

### 工作目录与原件保护

副本位于 `inputs/<file_ref>/<safe-name>`。文件名规范化、保留有效扩展名并限制长度，规避 Windows 保留名、分隔符与大小写冲突。不同来源的同名文件各有独立目录。

使用独立字节副本，禁止硬链接到原件。准备时流式核对持久引用的大小和 SHA-256，临时文件完成后原子替换。原件缺失、损坏或身份不一致时失败，不信任已有副本，也不搜索用户目录。

工具创建的输入副本标记只读；这是避免误改的便利措施，原件隔离由独立副本和资产库访问边界保证。修改文件应另存到工作目录其他位置。拒绝输入目录链上的 symlink/reparse point；只处理服务确定的目标文件。并发准备通过服务锁串行化。

### 容量

- 上传继续使用既有资产库 100 MiB 上限及当前模型能力限制。
- 会话工作目录单文件 100 MiB，总量 1 GiB，最多 2,000 个文件；由共享容量规则供准备工具与命令入口复用。
- 原子替换前计入新副本的增量容量；流式复制有单文件上限，不把整个文件加载到内存。
- 超限拒绝新增物化，不删除原件；列表和已有文件读取不依赖写入容量检查。
- 文件大小与模型输出量分别控制，沿用已有命令输出预算，不修改 token 估算。

### 压缩与模型可见性

每次请求的工具定义明确说明上传文件可从 session_files 列举并准备到会话工作目录，压缩后仍可调用。摘要转录保留来源消息和资产引用，作为辅助证据而非访问唯一依据。文件名及内容视为用户数据，不能作为宿主指令。

不为每轮注入全量文件目录或原件；重新 list 可从持久历史恢复引用。无需修改上下文折叠算法、事件 schema、PDF Skill 或 provider 文件上传行为。

### 生命周期

重启后从持久有效事件恢复目录；工作副本丢失可按需重建。缺失原件不能用旧副本冒充恢复成功。会话删除清理整个对应工作目录，补齐 Windows 只读副本清理；清理不跟随链接。共享原件继续服从既有附件回收机制。

## 验证与影响

覆盖工具 wire schema、宿主会话注入、持久历史压缩与重启、同名文件、同大小篡改、缺失原件、目录逃逸、容量、删除和共享原件。大 PDF 验证发现/准备不向模型返回原始字节。

运行项目 backend/frontend/rust 检查。新增本地文件能力评估为 package-sensitive，按 runtime-only 流程验证冻结资源与调用链；不构建或安装完整安装包。真实模型行为与 deterministic 机制分开记录，未授权时不调用外部 LLM。
