# 会话文件发现与附件重取

## 状态
CONFIRMED

## 背景与归属

需求 059 建立了附件资产与消息引用，其 requirement 要求明确再次引用旧附件时能够重取，design §9.4 将 Agent 重取工具延后。本需求作为独立交付补齐该能力，保留 059 的历史交付记录。

已提供的诊断证据表明，附件退出模型上下文后，仅有名称不足以支持可信重取。诊断包的运行构建为 `2070fe95c06ccc9f086ba2d7b4898334ca1a6979`，`dirty=true`，不能与该提交源码作精确等同。包内原件被排除，完整性检查未报告失败；本需求不把包内检查记录表述为独立复核了原件字节。

## 目标

- Agent 能发现本会话已经上传的文件，确认来源消息、文件身份与可用状态。
- 上传附件能够在已有会话工作目录中供 Agent 读取和处理，Agent 明确知道该入口及其与上传原件的关系。
- 跨轮、上下文压缩和应用重启不使该能力消失；不依赖摘要完整保留文件引用。
- 附件资产库继续作为原件来源，处理过程不得损坏或替换原件。

## 范围

### 包含

- 当前上传类型的通用会话文件发现、可信读取与工作目录接入。
- 历史已上传附件的兼容，无需用户为了获得能力重新上传仍然有效的原件。
- 同名和不安全文件名、身份与完整性校验、容量限制、会话隔离。
- 缺失或损坏原件的明确失败，以及工作目录呈现的恢复与清理。
- 删除会话后清理对应工作目录文件；共享原件仍按有效引用生命周期治理。
- 模型可见的能力说明与稳定入口在上下文压缩后仍然可用。

### 不包含

- 修改 PDF skill、扩展上传格式、通用文件管理界面或新的产物管理产品。
- token 估算、模型窗口配置等独立交付。
- 每轮自动把所有历史文件原始载荷重新送入模型。
- 搜索 Downloads/Documents 或以同名、相似本地文件替代上传原件。

## 验收条件

- [ ] AC-1：上传后跨轮可发现并读取该文件，返回来源及可验证身份。
- [ ] AC-2：发生上下文压缩、原始消息退出模型窗口后，仍能重取原附件。
- [ ] AC-3：重启后已有会话文件仍可用，既有会话无需重新上传。
- [ ] AC-4：发现和读取仅限当前会话有效引用，伪造其他会话文件引用不能越权。
- [ ] AC-5：原件缺失或损坏时明确报错，不默默使用未验证的副本或外部同名文件。
- [ ] AC-6：同名不同内容可区分；Agent 获得来源与身份，不能把相似文件当作原附件。
- [ ] AC-7：工作目录中的输入文件可供现有命令运行能力处理，修改处理文件不影响原件。
- [ ] AC-8：文件名不能逃逸目录；复制与读取受大小和工作目录容量限制保护。
- [ ] AC-9：删除会话清理对应工作目录文件，不破坏其他会话仍引用的原件。
- [ ] AC-10：大 PDF 按需读取或处理，文件发现不自动发送完整原件给模型。
- [ ] AC-11：有意义的自动化测试与项目检查通过；真实 LLM 验证按授权规则执行，未覆盖边界如实记录。
