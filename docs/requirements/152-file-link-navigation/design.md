## 方案设计

### 1. 公共链接交互模块

在 `frontend/src/lib/links/` 放置链接目标分类、上下文类型与操作服务；在 `frontend/src/components/app/link-interactions/` 放置公共链接交互边界及菜单项。前者不承担渲染，后者不各自拼接文件路径。

各入口只交付两类信息：原始链接目标或可信附件引用，以及所属内容上下文。上下文区分会话消息、人格文件和应用内部导航；会话上下文携带所属 session ID，不在执行动作时读取“此刻选中的会话”替换来源。

统一目标结果包括外部地址、本地候选路径、附件引用、内容内部锚点、应用导航和不可用目标。可定位结果携带绝对路径及文件／目录类型；失败结果携带稳定原因与可复制的原始目标。菜单、左键和键盘入口共用同一动作服务。

不另建通用菜单注册框架，不把当前业务能力变成所有产品操作的全局事件总线。

### 2. 全局右键体系与事件归属

继续使用 `installProductContextMenuPolicy` 作为窗口右键策略唯一入口，复用现有 `components/ui/context-menu` 和 `PortalHost` 的样式、键盘、定位、关闭及生命周期能力。

公共链接菜单只有一份目标到菜单项的映射、一份动作执行与反馈逻辑。聊天正文、来源引用、人格预览、具有可信本地身份的附件入口都使用同一公共实现；入口适配器不得单独新增菜单项集合、原生 Menu、绝对定位浮层或文件打开逻辑。

事件通过 `composedPath()` 找到原始命中对象和最近的内容上下文，避免 TDesign Shadow DOM 重定向后只看到宿主。仅当事件命中受管链接时取得链接菜单所有权，不在整个正文或应用根一概标记 custom 从而压掉原生文本菜单。

- 命中文件／目录链接：打开公共链接菜单；即使有选中文本，也保留文件定位操作，并在需要时提供复制选中文本项。
- 命中普通选中文本或输入区：沿用现有编辑／复制策略。
- 命中会话列表或其它已有专用操作：沿用其菜单，不被链接监听器截获。
- 命中空白或非链接内容：沿用现有 suppress/native 策略。

公共菜单在活跃内容边界中复用；多窗口各有本地实例，但没有多份业务实现。同一次事件只能打开一个菜单。应用 Activity 隐藏、会话切换、内容卸载或命中节点失效时关闭菜单并清理关联，避免 Portal 残留。

菜单打开时保存目标与来源上下文快照；异步解析使用请求代次校验，旧请求不得覆盖新菜单。执行前再次检查目标状态，已经关闭或切换来源的菜单不继续执行。

### 3. 渲染器适配与目标保真

TDesign 继续承载聊天 Markdown，不更换消息组件。通过锁定版本支持的 Markdown 渲染扩展保留完整 href 与链接身份，由公共交互边界处理点击和右键。优先使用公开配置；实施时必须用实际锁定版本验证链接产生与清洗顺序，不能仅凭文档摘要假定本地协议已经进入 DOM。

人格预览通过 react-markdown 的链接组件与 URL 转换入口接入同一目标分类；只扩展受管链接的处理，不关闭图片和其它属性的安全转换。被渲染器过滤的目标应保留为不可用链接描述以说明原因，不能通过显示文字反猜地址。

不以正则替换整段 Markdown。内联、引用式、表格、强调等先由现有解析器处理，再在链接节点边界统一适配。纯代码和普通路径保持文本；聊天现有关闭裸 URL 自动链接的设置保持不变，其它入口已经生成的自动链接同样受管。

以原始目标为准，移除旧打开逻辑的显示文字优先及无条件剥离尾部下划线／星号策略。普通有效文件名和 URL 不因“修复 Markdown”被改写。媒体预览仍由原组件负责，不能因为外层捕获点击而破坏图片查看。

### 4. 路径解析与宿主操作

前端负责链接语法分类，宿主负责本地文件存在性、类型和实际系统定位。新增窄的 Tauri 本地定位模块，承接检查和定位；文件调用已有 opener reveal，目录调用目录打开。两种操作均不把文件交给默认程序运行。

相对路径的基准由拥有该上下文的后端提供：会话使用现有 `session_workspace_path`；人格文档使用现有受管理人格文件父目录。bridge 提供只读的上下文解析能力，先验证会话或附件身份，再返回可信路径。前端及 Rust 不复制 Python 的会话目录哈希算法或用户数据路径常量。

路径规则：

- 先区分 Windows 盘符／UNC、POSIX 绝对路径、file URI、明确协议和相对路径，避免将盘符当成外部协议。
- 普通路径与 URI 分别解析；URI 按协议解码一次，普通路径不无条件执行 URL 解码。空格、括号、百分号、井号及 Unicode 字符保持原意。
- 支持 `:行`、`:行:列`、`#L行` 形式的文件引用；对裸路径中合法的同名字符与引用后缀有歧义时，先检查原始文件候选，不能直接删尾后打开另一文件。
- 相对目标只基于其来源上下文解析，不使用 WebView 的绝对化 anchor.href、进程 cwd 或最近命令目录；无上下文返回可见的基准缺失错误。
- Windows 共享路径按平台语义处理；异平台路径不映射到当前机器的同名位置。`//...` 等可能是协议相对网址也可能是共享路径的目标，在无明确来源语义时说明歧义，不猜测。
- 纯锚点在对应内容根中查找实际目标；缺少目标时反馈，不跳转应用页面。内部应用导航必须明确标识，避免与绝对文件路径混淆。

已知不可用目标使用不可用语义和原因提示，保留复制原始目标能力；不要求在每次流式渲染时对全部文件做磁盘查询。用户交互时解析并反馈，稳定结果可按目标与来源上下文缓存；执行时重新核对存在性。

### 5. 附件与来源引用边界

附件适配器传递 asset/draft 身份和来源会话／消息，不将 bridge content URL 送到普通外链打开器，也不按显示名称找磁盘文件。后端复用附件存储及会话文件服务校验有效引用；定位产品实际持有的文件副本，并让用户能区分副本与上传前的原位置。

需求 151 负责统一会话文件附件能力，本需求负责链接交互。实施前读取其已公开的实际接口与进度；已有可复用身份接口时直接适配，尚未提供时仅在现有服务边界补足本需求必需的身份解析，不另造附件目录或生命周期。接口出现实质冲突时回到方案同步，不能自行删减附件入口验收。

Provider 的 file_id/container_id/filename 不等于本地文件身份。无法解析的引用继续明确标记不可用，能够解析的链接接入公共服务；不自动下载远端产物，也不按名字寻找替代文件。

### 6. 动作与反馈

| 目标 | 左键／默认动作 | 公共右键菜单 |
| --- | --- | --- |
| 本地文件 | 打开所在文件夹并尽量选中 | 打开所在文件夹、复制完整路径 |
| 本地目录 | 打开目录自身 | 打开文件夹、复制完整路径 |
| 可信附件本地目标 | 经身份解析后定位；既有图片预览入口保留 | 定位实际文件副本、复制完整路径 |
| http/https/mailto/tel | 使用受支持的系统打开能力 | 打开链接、复制链接 |
| 内容锚点／应用导航 | 对应内容跳转或原应用操作 | 不添加虚假的文件定位项 |
| 不可用或不支持 | 显示原因，不静默吞掉 | 原因提示、可用时复制原始目标 |

公共动作服务统一输出用户可理解的反馈，沿用现有 toast；日志记录分类与失败边界，不以 console warning 代替用户反馈。缺失、访问受限、无基准、格式歧义、不支持平台及系统定位失败分别表达。复制失败也有反馈。

## 影响分析与验证安排

- 不改变消息正文、附件标识或历史存储格式；运行时解析上下文，历史重载同样适用。前后端接口新增采用兼容方式，缺少服务时明确失败。
- 新入口不成为模型工具，不新增 LLM 调用或修改公共 prompt；实现若发现确需改变这些边界，先重新评估。
- 对路径分类、编码与后缀歧义、会话身份、文件类型、错误映射做确定性测试。渲染测试必须覆盖真实解析器产出的链接，不能全部以手写 a 元素代替。
- 公共菜单测试覆盖正文／人格／来源共用实现、Shadow DOM、选中文本、已有会话菜单、键盘操作、异步过期结果及 Activity/Portal 隐藏恢复。
- 维护入口 × 目标类型 × 左键／右键 × 结果的证据表；当前纯文本入口的排除结论也留痕，防止把未检验写成不适用。
- 实现授权后按项目脚本运行受影响检查及完整 `scripts/check/run.*`。真实桌面端验收已由需求授权，使用 `desktop-visual-inspection` 与标准脚本，核对 runtime 身份和源码新鲜度。
- Windows 真实文件夹定位与 WebView 行为在本机验收；其它平台无法实际执行时如实记录缺口，不宣称跨平台实测通过。
- 当前 worktree 没有 frontend/node_modules；渲染器锁定版本的实际行为、桌面菜单和系统定位尚未验证。实施时先完成渲染与公共菜单的最小验证，再接入其余入口，不通过放宽过滤或多写一套菜单绕过。
- 涉及 bridge 的新增本地文件解析能力按实际 diff 评估 frozen runtime 影响；遵守已有打包敏感规则，不因文档阶段研究自动构建安装包。
