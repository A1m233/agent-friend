# 界面链接行为与本地文件定位

## 状态

CONFIRMED

## 背景

界面已经把部分文件目标呈现为可点击的蓝色超链接，但现有聊天打开逻辑只接受部分外部协议，本地文件目标点击后没有用户可见反馈，也没有右键打开所在文件夹的入口。链接外观与实际能力不一致，影响用户找到和使用 Agent 提及或生成的文件。

本需求以用户看到的可交互链接为范围，不以某一种 Markdown 写法划界。显式 Markdown 链接是核心入口，但不能以“不是内联 Markdown 链接”为由遗漏其它已经呈现为链接的内容。“蓝链”指具有链接语义和可交互外观的内容，不依赖某个主题下的具体颜色值。

## 目标

- 产品内所有已呈现的链接都具有与目标类型匹配的行为，消除点击无反馈的假交互。
- 本地文件链接支持右键打开所在文件夹，并在平台支持时选中文件，支持复制完整路径。
- 覆盖不同内容入口、消息生命周期、路径写法和失败状态，提供可复查的完整盘点与验收证据。

## 范围

### 包含

| 内容入口 | 覆盖要求 |
| --- | --- |
| 用户消息、助手回答、执行过程正文及错误正文 | 所有实际渲染出的链接，包含流式与历史消息 |
| 回答来源引用 | 已有网页链接及能够确定身份的文件目标；不能凭文件名猜本地位置 |
| 消息附件、输入区附件 | 纳入交互盘点；存在链接式文件交互且具有可信本地身份时接入定位 |
| 设置中的人格正文与候选预览 | 使用其它渲染入口产生的链接也适用相同目标语义 |
| 引用预览、工具参数和结果等展开内容 | 核对是否产生链接；实际产生的链接必须覆盖，纯文本保持文本 |
| 应用内导航和链接样式操作按钮 | 核对并保留原有操作语义，不误判为本地文件 |

链接形式包括内联与引用式 Markdown 链接、渲染器自动生成的链接，以及列表、表格、强调、引用块或其它内容结构中的链接。判定目标以真实链接地址或可信文件身份为准，不由显示名称猜测；显示文字与目标不一致时不得静默改开显示文字所指向的位置。

### 不包含

- 主动将尚未呈现为链接的普通路径、行内代码或代码块文字全部自动链接化。
- 新建通用文件管理器、内置文件预览器、编辑器或文件下载管理产品。
- 为没有本地身份的远端文件引用伪造本地路径，或按同名文件搜索并替代原目标。
- 以本需求改造附件上传、资产存储或会话文件管理的整体生命周期。

## 行为要求

### 目标与交互

- 本地文件链接的右键菜单提供“打开所在文件夹”和“复制完整路径”。定位使用文件本身的目录，不将行号等引用后缀当成文件名；平台允许时选中文件。
- 本地目录链接能够打开该目录，菜单语义明确区分目录自身与文件所在目录。
- 左键必须具有明确行为，不能静默吞掉点击。本地文件链接左键默认定位文件，目录链接打开目录自身；不以引入内置预览器作为前置条件。
- 文件链接右键菜单统一接入产品已有的全局右键体系；各内容入口使用相同菜单与操作语义，不分别维护多套实现。
- 网页、邮件、电话及应用内部链接按各自受支持的语义工作，不统一转成本地文件操作。
- 无效地址、不支持的目标、路径基准缺失、文件被移动或删除、访问受限、系统操作失败时，提供用户可理解的原因与可行的复制操作。已知不可用目标不继续伪装成正常可打开的链接。
- 不因消息渲染、悬停或菜单展开自动打开文件、程序或外部地址。

### 路径与内容兼容

- 覆盖 Windows 盘符路径与分隔符、macOS/Linux 绝对路径、本地 `file://` URI。
- 相对路径仅在存在可信且与内容对应的基准目录时解析；不得使用前端页面 URL、偶然的进程工作目录或最新一次无关命令目录猜测。
- 核对含中文、空格、括号、百分号、井号和 URL 编码的文件名，避免截断、重复解码或错误地移除文件名字符。
- 覆盖常见行号、列号和行锚点后缀；定位文件不承诺编辑器跳到具体行。
- 共享路径、异平台路径、远端引用、纯页内锚点及特殊协议必须得到明确分类和行为；无法在当前设备处理时明确说明，不误开其它目标。
- 链接位于复杂 Markdown 结构、组件内部或浮层中时，仍遵守相同语义。

### 生命周期与既有交互

- 流式内容生成、完成、历史分页加载、切换会话、重启恢复、展开执行详情后的链接行为保持一致。
- 流式生成期间尚未完整形成的链接不触发错误目标；菜单打开后内容更新或切换会话不得操作另一个文件。
- 保持文本选择、复制、引用、消息编辑、滚动、网页打开与现有图片预览行为。
- 鼠标右键之外保留可用的键盘访问方式；菜单关闭后焦点行为合理。

## 验收条件

- [ ] AC-1：形成覆盖所有产品链接入口的清单，并记录入口、目标类型、左键行为、右键行为、失败反馈和验证结果；纯文本与应用操作的排除有代码或运行态依据。
- [ ] AC-2：正文中的本地文件蓝链能够右键打开所在文件夹，支持复制完整路径；目录链接打开目录自身。各入口复用全局统一的右键菜单实现，不重复维护菜单、动作或错误反馈。
- [ ] AC-3：内联、引用式、自动生成及列表、表格、强调、引用块中的实际链接都覆盖，不因 Markdown 写法不同遗漏。
- [ ] AC-4：Windows、本地 file URI、macOS/Linux 路径、相对路径、特殊字符和行号引用均有确定性案例；目标与显示文字不一致时仍处理正确目标。
- [ ] AC-5：回答来源、附件链接式交互和人格正文等独立入口均有处理结论；不按名字伪造附件或远端引用的本地身份。
- [ ] AC-6：所有蓝链左键都有明确行为；支持的外部链接继续可用，内部导航与链接样式按钮不受影响。
- [ ] AC-7：不存在、无权限、无可信基准、不支持或系统操作失败时有可见反馈；不出现静默无响应，不打开替代目标。
- [ ] AC-8：流式、完成、历史重载、切换会话、重启恢复、展开详情及菜单期间内容变化均正确；文本选择、复制、引用和既有预览不回归。
- [ ] AC-9：自动化测试覆盖路径分类、内容入口、行为分发及关键错误边界，项目 `scripts/check/run.*` 检查通过。
- [ ] AC-10：在身份与源码版本明确的真实 Tauri 桌面端核验渲染后的链接、右键菜单、文件夹定位和失败反馈；覆盖组件内部生成的链接。未执行平台与场景明确记录为未验证，不用源码扫描替代运行态结论。
- [ ] AC-11：用户明确确认验收完成。

## 关键信息与边界

- 本需求承接现有文件定位能力和会话文件身份机制，具体复用与模块边界由技术方案定义。
- 需求 151 已被 `unified-session-file-attachments` 占用；本需求使用 152。设计阶段核对相邻需求边界，避免各自新增不一致的附件身份或生命周期。
- 用户于 2026-10-05 确认“所有蓝链”的整体范围及真实桌面端验收，随后确认左键默认定位和统一技术方向，并明确要求右键菜单使用全局统一实现。代码实现按后续阶段授权推进。
