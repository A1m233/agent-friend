## 背景与目标

真实诊断包压缩后约 71 MB，压缩前约 1.25 GB；其中一份后台输出日志约 1.02 GB、1115 万行，所选会话导出约 100 MB。后台日志长期积累与导出处理开销叠加，用户只能等待“生成中”，难以判断进度或主动结束。

已有实现提供日志脱敏、所选会话范围、附件与安装完整性检查、部分失败报告和最终文件发布保护。这些能力需要保留，同时统一治理采集范围、处理成本、任务生命周期和长期日志增长。需求 183 已治理普通会话查询中的不必要全量读取，诊断导出仍有其独立的完整性和性能要求。

本需求使用户通过一个标准入口快速获得足以支持日常排查的诊断包；深入调查时可以独立扩大日志时间、所选会话历史或检查项目。用户无需判断应该使用哪一种打包模式。每次导出均提供真实的范围说明、进度、取消、失败信息和资源边界。

## 范围

### 包含

- 桌面诊断入口、会话诊断导出、运行日志与结构化证据收集、脱敏、完整性检查及归档全过程。
- 后台输出与现有业务日志的保留、轮转、重复记录治理，以及已积累巨大日志的处理。
- 进度、取消、超时、部分失败、重复导出、页面离开和返回、临时文件及进程中断恢复。
- 诊断包生产契约、解析消费者、兼容性、性能测量和受影响平台验证。

### 不包含

- 安装包构建、发布渠道和开发构建缓存治理。
- 改变 Agent 对话行为、删除用户会话或附件资产、自动上传诊断包。
- 扩大截图、附件原件、原生内存转储等敏感材料的采集授权。
- 以新增完整读取替代需求 183 的按需会话查询能力。

## 需求

### 1. 一个标准导出入口，按需扩大范围

| 采集内容 | 标准行为 | 按需补充 |
| --- | --- | --- |
| 基础状态和故障证据 | 收集运行身份、必要状态及已保留的相关故障证据。 | 对需要额外授权的材料继续逐项说明和选择。 |
| 普通运行日志 | 收集近期相关记录，实际读取与处理受明确预算约束。 | 独立扩大到更早或全部已保留的日志，不联动增加其它材料。 |
| 用户所选会话 | 收集其近期内容，明确实际范围和覆盖。 | 独立扩大到更多轮次或所选会话完整历史，不联动扩大运行日志或执行安装校验。 |
| 附件及专项检查 | 保留低成本的状态与元信息，检查是否执行须真实报告。 | 按目的选择附件原件、安装文件完整性校验等额外工作；原始转储、截图的既有授权不扩大。 |

- 界面始终只有一个“生成诊断包”入口，不提供一个把更多历史、全部原件和所有昂贵检查绑定在一起的“完整模式”。
- 默认页面围绕选择会话、选择轮数和生成诊断包组织；问题说明输入框直接可见、按需填写，额外材料、专项检查和显示异常工具收拢到高级选项。折叠后仍能看见已启用的额外范围及必要隐私提示。
- 标准采集应足以服务大多数日常排查；不能为了显得快而省略关键故障证据，导致用户普遍需要再次导出。
- 用户在开始前能理解将收集的内容；扩大某一项时说明该项的预计数据量与成本，无法准确估计的部分明确标注。
- 每次导出说明实际时间窗口、会话范围、预算和遗漏；完成声明范围不等于包含全部历史。
- 对主动选择的完整会话或全部保留日志，不以默认近期预算静默截断；也不能承诺恢复已按保留规则删除的历史。
- 包内与界面分别表达“声明范围内收集完成”“有意未纳入的范围”“真实采集失败”，避免把遗漏混成失败，或把失败伪装为完整。
- 默认覆盖范围、会话范围、各类预算及故障证据优先级在方案阶段确定，作为采集策略，不作为两种产品模式；不能可靠确定时间窗口时如实说明。

### 2. 导出效率与资源可控

- 消除大量小写入、重复扫描、无必要的数据复制与等待；独立采集工作合理安排，不让一个缓慢来源阻塞所有可用证据。
- 默认采集的实际读取和处理量应受其声明范围约束，不能先读取全部历史，再丢弃绝大部分以生成小包。
- 大日志、多会话、长记录与大附件均纳入内存、CPU 和临时空间评估；扩大采集范围后也不能依赖把全部输入同时放入内存。
- 附件校验、安装完整性检查等成本单独可观察；减少重复工作时仍保证检查结果的来源和有效性，未验证不能报告为验证成功。
- 导出期间保持桌面主要操作及正常聊天可用，不为加速打包停止业务服务或改变会话状态。

### 3. 日志生命周期与故障证据

- 对后台标准输出、标准错误和业务日志统一核对保留责任，避免任何通道无限积累。
- 高频正常轮询与重复日志采用明确的保留策略；异常、慢请求和关键状态变化仍应可关联、可解释。
- 普通日志容量压力不能无声挤掉已保留的故障证据；故障证据自己的保留范围和淘汰规则也要明确。
- 已有巨大旧日志需要兼容处理，避免首次升级或启动因一次性全量处理而长时间阻塞；处理范围和不可恢复的历史淘汰须可解释。
- 导出与日志追加、轮转、重启并发时，保持来源身份及采集窗口准确；缺失、截断或保留期不足必须反映在覆盖信息中。
- 日志保留与本次导出范围是不同边界：缩小本次收集范围不能触发历史材料删除；日常淘汰仍由明确的日志保留规则管理。

### 4. 可观察、可取消的导出任务

- 用户能看到当前阶段、处理量及已用时间；无法估算的工作量明确表示，不能用虚假百分比制造完成预期。
- 取消贯穿采集、会话读取、校验、脱敏和压缩，不能只关闭界面提示而让后台继续大量工作。
- 页面离开后返回仍能获取同一任务的实际状态；重复点击、多个入口或重复请求不得意外启动竞争的大任务。
- 每个采集来源有适合其工作的等待与取消语义。缓慢但有进展的大导出与无响应来源要能区分。
- 部分来源失败时，尽可能保存其余有效证据并说明失败项；无法生成可信归档时明确失败，不发布损坏包。
- 完成、部分完成、取消和失败均有明确终态；重试不会覆盖已有成功包或干扰其它任务。

### 5. 临时文件、异常恢复与隐私

- 识别输出位置不可写及临时空间不足；预估不能替代对执行期间磁盘耗尽等错误的处理。
- 正常完成、取消、失败后清理本次临时材料；进程意外退出后的残留可在后续安全识别和处理。
- 清理只作用于确认归属本功能且已不在使用的临时文件，不误删其它任务、用户文件或最终诊断包。
- 最终产物发布不得覆盖既有文件；中间产物不能被显示为已成功生成的诊断包。
- 保留凭据脱敏、provider 私有状态排除、路径安全和原件授权边界；分块、并发或缓存优化不能造成泄露或跨任务混入。
- 包内、界面及解析工具对范围、失败、检查状态和历史覆盖缺口的解释一致；旧版本诊断包继续可读。

## 验收条件

2026-11-28 用户确认本轮交付并要求合入主干、推送远端；勾选范围依据 [progress.md](./progress.md) 的逐项证据。文件安全采用已有确定性检查和 Windows 专项，实际磁盘耗尽、ACL 拒绝及断电未实测；macOS 按用户明确指示本轮不执行，不把未执行项表述为已验证。

- [x] **AC-01 · 单一入口与独立扩展。** 界面使用一个标准导出入口；扩大日志范围、会话范围或开启专项检查互不隐式联动，同一输入下的组合输出与声明一致。
- [x] **AC-02 · 默认范围。** 增长范围外历史时，实际读取与处理量不出现无说明的全量放大；相关故障证据和必要基础状态仍可获得，默认包在代表性日常故障样例上具有实际排查用途。
- [x] **AC-03 · 完整性。** 主动扩大范围后保留所选已保存证据的完整采集能力；会话改写、追加、日志轮转、损坏或来源缺失得到正确处理和报告。
- [x] **AC-04 · 日志保留。** 运行日志具有明确且有效的保留预算；高频正常访问不无限积累，关键错误和故障证据覆盖可验证；已有巨大日志有兼容处理证据。
- [x] **AC-05 · 生命周期。** 在主要阶段取消、重复请求、离开并返回页面、来源超时及部分失败场景中，状态准确、工作终止或降级符合声明，正常业务不被停止。
- [x] **AC-06 · 文件安全。** 覆盖临时和输出空间不足、权限错误、进程中断及文件名竞争；无错误成功状态、无已有包覆盖、无越界清理，残留按归属处理。
- [x] **AC-07 · 隐私与校验。** 凭据及私有状态过滤不回退；原件授权不扩大；附件和安装完整性验证的实际执行状态与报告一致。
- [x] **AC-08 · 契约与兼容。** 生产契约、生产者和解析消费者一致；旧包继续可读；新包的范围、遗漏、部分失败与阶段信息可被正确解释。
- [x] **AC-09 · 性能。** 固定大日志、长会话、多会话和附件样例，绑定源码、平台和配置，记录阶段耗时、实际读写量、峰值内存及临时空间；达到方案阶段事先确认的数值预算。同范围性能比较与缩小采集范围的收益分别报告。
- [x] **AC-10 · 平台与体验。** 受影响平台的文件占用、轮转、取消和异常退出行为取得对应证据；用户完成范围选择、进度和终态体验验收。Agent 代做真实桌面视觉验收仍需按项目规则取得授权。

## 方案阶段需要收敛的事项

- 标准导出的默认覆盖范围、会话范围、各类材料预算，以及相关故障证据如何优先纳入；扩大范围的选项如何按目的呈现。
- 日志保留与降噪的具体规则、历史巨大文件的兼容处理和证据淘汰说明。
- 取消响应、普通场景耗时、大样例吞吐、内存及临时空间的数值门槛；先测基线，再确认预算，未冻结门槛不得开始实现或宣称验收通过。
- 各来源必须做的完整性检查、可复用结果的有效性，以及无法验证时的降级表达。
- 任务离开页面、应用退出及异常中断后的状态和清理责任。
