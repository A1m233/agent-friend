## 1. 一个入口与独立选项

继续使用设置页反馈面板的“生成诊断包”。不引入 quick/full 模式字段或绑定多个维度的预设。扩展材料折叠呈现，所有选项在任务开始时冻结。

按用户 2026-11-28 的界面反馈，将会话列表、最近轮数／全部轮次和生成按钮放在同一主区域；列表限定最大高度，问题说明保持直接可见的选填输入框，不提供折叠开关。高级选项置于主区域之后，默认收起，容纳全部日志、安装校验、附件原件、原始转储及两类显示异常工具。折叠不重置已选项，主区域简要列出额外范围；会话私人内容、已包含的完整桌面截图和原始转储提醒不随高级区域隐藏。沿用既有 Collapsible 组件的键盘和无障碍语义，不新增导出模式或改变采集协议。

会话列表复用共享 store 的 `loaded/loading` 状态：只在无可用条目、且某一来源尚未完成首次加载时显示加载占位。焦点触发的后台刷新保留已有条目、已知空态及选择，避免内容自适应高度的列表被短暂替换而造成页面跳动；共享刷新机制照常执行。

| 维度 | 默认 | 主动扩展 |

| 普通日志 | 每个日志族末尾最多 5 MiB，全部普通日志最多 32 MiB | 全部已保留日志，解除默认日志预算 |

日志族把当前文件和轮转备份视为一个来源，按新到旧分配预算。尾部起点对齐完整记录；不能可靠识别时间时不承诺固定小时窗口。记录原始大小、实际读取、起止偏移、纳入字节和有意省略原因。已保留的原生崩溃、显示故障等专项证据不挤占普通日志预算。

近期会话沿用现有有效轮次、改写审计和私有内容过滤语义，不因为增加扫描预算而漏掉一个已选轮次。逐记录投影与传输，内存随最大单记录而非全部历史增长；超长单记录专项单独测量，不把文件流式处理宣传成恒定内存。

开始前显示已选范围与可由元信息获得的数据量；会话投影和压缩后的大小标为估计或未知，不为了估算额外扫描全部正文。

## 2. 后台任务与状态

Rust diagnostics 模块持有唯一活动任务，前端调用开始、查询、取消命令。状态包括任务 ID、递增版本、开始时间、阶段、处理量、取消请求和终态。查询快照是状态权威；事件用于及时更新，前端拒收旧版本，重新进入页面可以恢复观察。

阶段覆盖准备、基础状态、会话、附件、日志、归档与清理。终态为完成、部分完成、已取消、失败。重复开始在原任务活动期间返回忙碌，不并发抢占磁盘；任务实际结束前不释放活动所有权。开始、取消和最终发布的竞态由同一任务状态协调，已经发布的成功包不能被后来的取消改写成失败。

任务运行在后台，不把同步文件处理放在 WebView 或异步执行器线程。读取、扫描、哈希与 ZIP 复制的块边界检查取消；HTTP 请求可中断，会话断连传递到 Python 取消检查。取消请求先显示“正在取消”，工作停止与清理完成后进入终态。应用重启不自动续采新数据；中断残留按所属任务清理。

基础 HTTP 查询保持短超时并并发执行；大会话采用流式响应，不套用健康检查的 5 秒总超时。单个来源失败记录为 partial，其它可用证据继续收集；归档、契约或安全保护失败不发布包。

## 3. 采集与归档数据流

### 日志

保持已打开文件的固定前缀身份，先定位选中范围，再分块读写；暂存输出使用 256 KiB 缓冲，显式检查 flush 错误。保留凭据、路径、敏感行和多行凭据过滤。追加不进入当前快照；源文件缩短、消失或轮转造成缺口时如实报告。

### 会话

复用 SessionStore 的固定文件前缀和取消机制。诊断范围扫描与记录投影保留在 sessions 模块，HTTP 适配只负责传输。保留现有 JSON 导出消费者，新桌面采集使用逐记录流，避免 Python 整体列表、HTTP 整体 JSON 与 Rust Value 多份同时存在。

大范围记录按原顺序写入受拥有的暂存文件，形成原有 sessions/session-NNN.json 形状。内部 rollout/provider 私有内容继续只保留允许的摘要；附件候选在逐记录处理时提取。一个会话完成后释放解析内存，再处理下一个会话。

### 检查与附件

默认安装采集读取身份和已有观察，不调用会遍历所有 payload 文件的发现校验入口；明确区分历史校验与本次校验。用户选择本次完整校验时才执行，并支持取消。启动与安装安全调用方保持原有强校验。

未选附件原件时不读取正文计算哈希。选入的附件从同一打开文件读取、校验和暂存，归档使用已校验字节，避免校验后文件变化导致报告与 ZIP 内容不一致。未知、未检查、不匹配和读取失败分别表达。

### 临时文件与发布

使用诊断专属工作目录、任务身份和活动锁。正常路径 RAII 清理；后续运行只清理确认归属、未被活动任务持有的残留，不跟随符号链接越界。最终 ZIP 临时文件与目标位于同一文件系统，完成 ZIP 尾部、flush/sync 后使用不覆盖已有目标的发布操作；不依赖 exists 后 rename 的竞争窗口。

开始前检查临时及输出目录可写性与空间，执行期间继续处理 ENOSPC 等实际错误。估算不足不能成为成功声明；清理失败单独报告。最终包不属于临时文件回收范围。

## 4. 运行日志保留

后台 stdout/stderr 由父进程持续读取并写入受管理的轮转文件，子进程不长期持有被重命名日志的句柄。每个服务当前文件最多 10 MiB，保留 5 份备份；超长输出按字节边界处理，不能等待换行后才轮转。

沿用现有 ServiceProcess、Windows Job Object 和进程组的所有权、退出和回收语义。日志读取随进程生命周期回收，磁盘错误必须可观察；不能因写日志失败阻塞子进程的 stdout/stderr 管道或静默假装保留成功。

业务日志沿用已有轮转。成功的高频轮询减少重复访问日志，保留异常、错误 HTTP 状态、慢请求与关键生命周期信息，不只以是否抛出异常判定错误。

已有巨大 runtime 日志在确认写入者已关闭后转入历史保留区，记录转存时间，不扫描正文、不直接删除。保留 7 天，其间标准采集仍按尾部预算、全部日志选项可采集历史文件。期满只清理该受管理区域中的已过期历史日志；导出范围选择本身不触发删除。

## 5. 契约与模块责任

- diagnostics 模块内拆分任务状态、选取策略、暂存/归档等职责；不建立通用后台作业框架。
- runtime_services 内维护服务输出的轮转与生命周期；Python request observation 维护请求日志等级。
- sessions 维护范围读取、投影与取消；bridge routes 维护传输及断连。
- frontend services/store 维护命令与状态订阅，反馈面板复用现有输入、勾选和折叠组件。
- producer machine contract 新增范围、覆盖与任务度量语义，升级相关 capability；旧 full-retained 声明不能用于默认范围。
- 同时更新真实 inspector handler、格式 reference、Rust producer 与 Python consumer 测试；历史 v1 包仍可读。

## 6. 实施与验证安排

按任务状态和范围 → 流式采集/归档 → 日志生命周期 → UI/消费者契约 → 综合验证推进；每步补可断言的回归测试。

固定样例分别测近期与完整范围，不把少采集的收益混入同范围实现比较。已有日志暂存隔离基线约 128 MiB/6.38 秒；缓冲候选约 0.72 秒，只证明这一阶段。实施后用正式采集路径重测，并记录字节数、分阶段时间、峰值内存与临时空间；不得把隔离结果外推为端到端承诺。

确定性门槛包括默认日志读取上界、扩大范围保真、历史增长不触发近期会话全量读取、脱敏不回退、可取消、不覆盖发布和越界清理保护。速度与取消延迟保留精确平台/夹具结果，不引入未经测量确认的整包固定秒数承诺。

本轮按用户 2026-11-28 的最新指示执行 Windows 本机验证，先不进行 macOS 专项，不以寻找 Mac 作为本轮收尾条件；这不表示 macOS 已通过验证。项目 backend/frontend/rust 检查按影响计划执行；安装器等级由标准分类器与实际语义判定。用户已明确授权 Agent 启动 Tauri 做真实桌面交互与视觉验收；不能把静态验证当作桌面验收。
