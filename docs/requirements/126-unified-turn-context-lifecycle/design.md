## 现状与责任边界

Conversation 的发送与编辑重发分别准备 Skills、历史、记忆和工具循环状态。重发从业务事件投影模型历史，并禁止压缩检查点提交。SessionModelContext 的已初始化状态独立于真实模型历史，重建或截断后可能继续跳过已丢失的消息。能力说明两处传入空 surface，与 Skill 读取路径不一致。

业务事件仍为用户历史的权威；SessionModelHistory/rollout 负责模型历史；context 策略负责选择内容；Conversation 负责本轮接纳、请求及提交。保留现有边界，不新增通用工作流框架。

## 方案

### 入口与共同生命周期

普通 stream 与 edit_resend_latest 作为薄入口，统一委托用户轮执行方法。编辑入口仅校验目标、确定替换附件/引用和有效历史；记忆来源失效与 rewrite marker 属于历史变更，后续 Skills、输入落盘、模型快照、工具循环、取消和收尾采用同一实现。

重发优先使用已验证模型历史中目标用户消息之前的前缀。移除该轮前置的临时上下文，避免旧召回或附件边界进入新轮。无法证明前缀有效时回退到业务事件投影；不按摘要文本猜测身份。已有摘要必须经当前有效事件及模型身份校验，覆盖被替换轮的摘要不能复用。

### 环境上下文与历史协调

根据本轮真实日期、surface、通道、权限及公开工具生成当前环境事实，再与模型历史中实际保留的最后一条同类消息比较。相同事实保持原身份与位置；缺失或变化才追加，不能只依赖进程中的 initialized 状态。

同一协调逻辑用于策略输入和最终输出，并进入预算估算边界，使 FIFO/压缩移除消息后的补齐不会绕过预算。候选消息身份在一次构建内固定；仅请求接受后更新已提交状态。

会话与 Skill 能力说明共用真实 surface，不扩大工具或审批权限。能力目录漏列工具由独立任务负责。

### 检查点与提交

移除编辑入口的特殊禁用行为。继续沿用候选准备、provider 接受后提交、失败丢弃的生命周期；审核 rollout 与 compaction/tool_context_edit 的写入顺序和恢复边界，保证恢复能够检测并修复中途状态，不宣称多次文件追加天然原子。

### 调用路径覆盖

| 路径 | 处理 |
|---|---|
| 普通发送、编辑重发 | 共用用户轮生命周期 |
| 工具续轮、失败工具结果续跑、预算收尾、系统触发 | 继续复用公共模型组装与请求提交 |
| 正常重启恢复 | 保留已验证 rollout；依据实际历史协调环境状态 |
| 历史重新对齐 | 允许安全重建；统一补齐环境状态并校验检查点 |
| 摘要压缩、FIFO 截断 | 最终模型输入再次协调环境信息，纳入预算 |
