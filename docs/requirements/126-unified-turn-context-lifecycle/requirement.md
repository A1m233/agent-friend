# 126 · 对话入口统一与上下文状态一致性

## 状态

CONFIRMED

## 背景

普通发送和编辑重发虽共享部分上下文组装与工具循环，但入口仍分别维护历史选择、上下文准备和检查点行为。公共能力演进时，需要逐个入口补齐，容易出现遗漏。

2026-09-12 的长会话诊断确认：编辑重发从业务事件重新投影历史，无法复用仍存在于模型历史中的摘要；再次生成摘要时又没有提交新检查点，也没有报告压缩进度。该轮上下文准备约 82 秒，其中摘要调用约 69 秒。

确定性复现进一步确认：编辑重发、历史重新对齐及 FIFO 截断可能移除日期、交互界面、通道和可用能力等上下文消息，而对应状态仍记录为已注入，导致后续不补发。现有相关测试 109 项通过，未覆盖这些跨入口与历史变化组合。

## 目标

让普通发送与编辑重发共享公共处理契约；历史发生变化时，模型可见内容、摘要与工具裁剪检查点、环境上下文状态保持一致，避免依赖开发者逐入口记忆补齐。

## 范围

### 包含

- 普通发送、编辑重发的有效历史选择、公共准备与执行生命周期。
- 失败续跑、重启恢复、历史重新对齐、摘要压缩与 FIFO 截断对关联上下文状态的影响。
- 摘要及工具裁剪记录的复用、失效、提交和后续恢复。
- Skills、附件、引用、环境信息、记忆召回等已有公共能力在相关入口的完整接入。
- 压缩进度、完成、丢弃与取消的可观察行为。
- 跨入口共同契约测试及历史变化组合回归。

### 不包含

- 重写全部 Agent 引擎、引入通用工作流平台或改变产品交互入口。
- 改变上下文预算估算算法、模型窗口配置或摘要质量策略。
- 新增任意历史分叉、回滚外部工具副作用或扩大工具权限。
- 改变人格身份语义、跨会话数据共享或记忆存储体系。

## 需求

### R-1 公共能力一致

普通发送与编辑重发在确定有效起点后，遵循相同的公共准备、执行和收尾契约。新增公共上下文能力时，不要求分别复制两套实现。失败续跑和其他已有调用入口需有明确归属及差异说明。

### R-2 有效历史与编辑语义

编辑重发不得混入被替换轮的回答、工具结果或失效记忆；仍有效的摘要和历史应可复用。覆盖了被编辑内容的摘要必须失效或安全重建。保持原始业务事件可追溯，不把历史失活解释为撤销已发生的外部副作用。

### R-3 历史与派生状态一致

历史重建、恢复、压缩或截断后，检查点和上下文注入状态必须对应当前模型可见历史。必要的当前环境信息被移除后需恢复；已存在且有效的信息不得无故重复注入。无法验证身份或边界时采用明确的安全回退，不冒称精确恢复。

### R-4 检查点生命周期一致

新摘要和工具裁剪记录在请求接受、失败、取消和恢复边界采用统一规则。不得因入口不同而无条件禁止提交；未被接受的候选不得被当作已生效状态。检查点与模型历史应可共同恢复，旧会话保持可读取和可继续使用。

### R-5 进度真实可见

相关入口触发压缩时均提供真实进度；完成、取消或丢弃能正确结束活动状态。避免实际正在压缩而只长期显示笼统准备状态。不以固定响应秒数作为外部模型延迟承诺。

### R-6 回归覆盖公共契约

测试需观察最终模型请求、持久化状态和恢复结果，而不只检查是否调用公共函数。覆盖正常发送与重发的共同能力，以及历史变化、失败、取消、重复恢复等组合。

## 验收条件

- [ ] AC-1：形成既有对话入口与历史变化路径清单，每条都有公共流程归属、必要差异和验证结论。
- [ ] AC-2：有效旧摘要在编辑重发中可复用；覆盖被编辑轮的摘要不能污染新请求；原始业务历史仍可追溯。
- [ ] AC-3：普通发送与重发对 Skills、附件、引用、环境上下文及记忆边界采用共同契约测试，不遗漏、不错误继承被替换轮内容。
- [ ] AC-4：编辑重发、历史重新对齐、压缩和 FIFO 截断后，当前环境上下文与已注入状态一致；无变化时不会重复追加。
- [ ] AC-5：新摘要及工具裁剪检查点在请求接受后正确提交；失败、取消、重启与重复恢复不会产生假生效或历史失配。
- [ ] AC-6：压缩活动在普通发送、重发和相关续跑入口可观察，完成、取消和丢弃均正确收口。
- [ ] AC-7：跨入口回归覆盖本次已确认问题及短会话无压缩场景，并验证已有工具配对、幂等、记忆失效和旧会话兼容行为。
- [ ] AC-8：项目规定检查通过，完成用户验收；真实 LLM 验证如需执行另按授权规则处理。
