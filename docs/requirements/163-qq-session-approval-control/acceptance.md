# QQ 联合验收操作单

当前状态：真实 iOS QQ 隔离探针已完成档位、单次批准/拒绝、免授权继续、过期与旧按钮验证；卡片预览已获得截图。真实 Tauri/bridge 联验已补充 QQ 入站模型任务、桌面先拒绝后 QQ 旧按钮、桌面同步和 bridge 重启持久化。2026-10-18 用户已确认整体体验并授权合入推送；下方为原始操作计划，不能将每一行视为已逐项手验，未实测变体与自动化覆盖边界见 evidence-index.md。

## 开始前

- 用户已指定手机 QQ（iOS）；具体系统和 QQ 版本仅作为出现兼容性差异时的可选诊断信息，不是开始验收的前置条件。
- 本轮已按实例身份完成隔离探针及本分支 Tauri 联验。收尾已恢复原 QQ 会话绑定、停止测试 dev 实例，并启动原安装版，确认 QQ 在线；若再补验，必须重新核对运行实例与源码新鲜度，不能用原安装版作为候选证据。
- 建立专用测试会话并绑定 QQ，使用临时测试目录和无害命令。真实模型由用户在 QQ 发消息触发；coding agent 若要代发测试调用，须另告知调用量并取得本次授权。
- 每个步骤由 coding agent 先给出准确对象与预期，用户反馈客户端所见后，coding agent 核对对应服务端记录。不要一口气做完再凭记忆回报。

## 顺序

| 步骤 | 用户操作 | 客户端检查 | 服务端检查 |
|---|---|---|---|
| 1 | QQ 菜单 → 授权设置 | 会话标题和当前档位可见 | session 与绑定一致 |
| 2 | 选择本会话免授权 → 取消 | 完整风险说明、取消结果 | 模式未变；旧确认按钮失效 |
| 3 | 重新进入并确认免授权，再切回每次授权 | 成功反馈准确，退出无额外确认 | 模式版本变化；桌面读取一致 |
| 4 | 请求创建一个指定临时文件，点仅本次允许 | 路径与 create 权限完整可读 | request/run/callback 对应，文件内容匹配 |
| 5 | 请求创建另一个临时文件，点拒绝 | 拒绝提示与最后回复一致 | 文件不存在，没有额外执行 |
| 6 | 请求无害命令，如输出固定测试文字，分别允许和拒绝 | 完整命令、目录、文件与网络权限 | 允许时一次启动/退出；拒绝时零启动 |
| 7 | 让普通请求进入等待，在卡片打开授权设置并开启免授权 | 等待期间按钮能用，随后继续任务 | pending 收敛，无死锁；普通后续请求自动允许 |
| 8 | 切回每次授权，桌面先处理，再点击 QQ 原卡片；重复点击已处理按钮 | 显示已处理/失效 | 决定不翻转、操作不重复 |
| 9 | 打开确认页，切换绑定会话后再点旧确认；再切回 | 旧操作不影响任何会话 | 绑定与版本检查拒绝旧 token |
| 10 | 展示含中文、反斜线、引号、尖括号等的无害授权对象，以及超预算长详情 | 预算内完整可读；超预算只提示转桌面 | 不对摘要/截断内容签发可批准 token |
| 11 | 安排一次重启后点击旧按钮，再重新打开菜单 | 旧按钮失效，档位持久化正确 | 原 pending 不复活，新 run 身份正确 |

第 10 步只检查安全对象的展示，不执行具有破坏性的命令。灾难性动作拦截由确定性测试覆盖。

## 结果记录

每次记录：候选来源、QQ 平台/版本、步骤编号、时间、客户端反馈、session/run/request、平台消息与 interaction 标识、审批状态、实际文件或命令结果。截图只在用户愿意提供时采用，并先脱敏。

服务端的 `IM approval controls` 关联请求与消息回执；`IM approval interaction` 关联点击和请求；`IM approval state` 记录状态变化。最终执行证据从原工具结果与进程状态核对，不能从“已批准”推断成功。

消息发送失败、按钮缺失、文字被隐藏/截断或回调无法对应时，记录该步未通过并停止相关批准。所有客户端项完成且用户明确确认后，才能结束需求验收。
