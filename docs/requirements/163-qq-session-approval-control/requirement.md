# QQ 会话授权控制

## 状态

CONFIRMED

## 背景

QQ 已支持绑定桌面持久会话，并通过菜单切换会话、模型和推理强度，但没有授权档位入口。现有本地文件授权和命令执行只接受桌面聊天入口；即使同一会话已在桌面开启免授权，QQ 发起的操作也无法通过该入口限制。

用户希望直接在 QQ 管理授权并完成任务。本需求同时交付档位设置与实际单次审批链路，避免出现能切换模式却不能使用对应能力的半完成体验。

QQ 客户端由第三方提供，coding agent 当前无法直接观察用户所用客户端。平台发送回执、服务端回调与自动化测试分别只能证明链路的一部分，不能替代客户端展示和真实操作验收。

## 目标

- 在已绑定的 QQ 私聊中查看、设置当前会话授权档位。
- 在 QQ 内完成本地文件和命令请求的单次批准、拒绝，以及免授权模式下的任务执行。
- 保持 QQ 与桌面针对同一会话的状态一致，防止过期或跨会话交互造成错误授权。
- 用真实 QQ 客户端操作与对应服务端证据完成跨端验收。

## 范围

### 包含

#### 会话授权档位

- QQ 菜单展示当前会话及其授权档位，提供“每次授权（推荐）”和“本会话无需授权”两种选择。
- 档位属于已绑定的持久会话，与桌面共享同一状态；重启后保留。新会话仍默认每次授权，切换会话不复制原会话档位。
- 每次从每次授权进入免授权，都在 QQ 展示风险并要求用户再次明确确认；取消、过期或操作失败不变更模式。
- 风险说明涵盖本地文件读写和删除、命令执行、申请到的网络能力及显式申请的非沙箱命令，并提示高危动作仍可能被拦截。
- 切回每次授权无需额外确认，立即影响后续授权请求，不追溯终止已开始的操作。
- 模式变更结果明确回复；QQ 菜单与等待授权的消息必须展示对应会话，避免把历史消息误认为当前状态。

#### QQ 单次审批与实际执行

- QQ 发起的本地文件和命令授权请求可以在当前绑定的私聊中展示并操作，不必回到电脑逐项审批。
- 审批前展示实际动作及其完整授权范围，包括相关文件目标与权限，或命令、工作目录、网络能力及执行级别；不得只展示模型概括而隐藏实际对象。
- 用户可以仅本次允许或拒绝；批准只对当前仍有效的精确请求生效，不产生额外路径权限、永久规则或跨会话授权。
- 免授权沿用现有会话语义：普通请求按其精确范围自动允许，灾难性高危请求仍拒绝；沙箱命令不因免授权而自动提升执行级别。
- 等待单次审批时可以操作授权控件；不得要求先等待当前回复结束才能批准当前回复所需的请求。
- 切换到免授权时，已有普通待审批请求自动收敛，高危请求按现有规则拒绝；QQ 和桌面不得继续表现为有效待审批。
- 批准、拒绝、失效、执行失败与执行完成分别表达；平台收到按钮点击不等于操作已经批准或执行成功。

#### 一致性与异常边界

- 仅接受当前已绑定 QQ 私聊用户的有效操作；旧菜单、重复点击、绑定变化、会话删除、运行取消、审批过期均不能错误授权。
- QQ 与桌面同时操作时，只接受符合当前会话和请求状态的决定；另一端提示请求已处理或状态已变化。
- QQ 无法展示完整授权对象、按钮被平台拒绝或消息发送失败时，不自动批准，不把移除按钮后的文本发送成功当成可用审批界面。
- 失败或超时应明确反馈并结束等待，或指向仍有效的桌面审批入口；不能无限等待不可操作的消息。
- 断线、重连和服务重启不能恢复已失效的批准，也不能使重复回调重复执行。
- 系统保留请求、决策来源、状态变化和执行结果之间的关联，以便核对真实客户端操作。

### 不包含

- 群聊、频道、其他 IM 平台的授权接入。
- 新增第三种授权档位、全局免授权默认、永久白名单或跨会话授权。
- 绕过现有高危门禁、操作系统权限、沙箱、受保护路径或工具范围校验。
- 本期不另行扩展桌面应用启动、第三方网站登录等其他专用授权能力。
- 定时任务、语音等入口因共享会话而自动获得 QQ 授权能力。
- 以修改旧需求 103 历史正文的方式覆盖其非桌面入口边界；本需求明确新增已绑定 QQ 私聊的受治理入口，其余边界保持。

## 验收条件

- [x] **AC-1 档位入口**：真实 QQ 客户端能查看当前会话档位并完成双向切换，切换后 QQ 与桌面读取结果一致。
- [x] **AC-2 风险确认**：每次进入免授权均展示完整风险并二次确认；取消、旧按钮或失败不变更模式；退出无需二次确认。
- [x] **AC-3 文件单次审批**：真实 QQ 展示精确文件目标与权限；批准后只执行该操作，拒绝后没有该操作副作用。
- [x] **AC-4 命令单次审批**：真实 QQ 展示完整命令、目录和权限信息；允许后执行一次，拒绝后不执行，执行状态和回复相符。
- [x] **AC-5 免授权与高危边界**：QQ 免授权任务可以完成受治理的普通文件与命令操作；高危动作被拒绝，其他入口及现有沙箱边界不被放宽。
- [x] **AC-6 待审批可操作**：运行等待审批期间 QQ 的批准、拒绝和档位控制仍可用；切换免授权后 pending 正确收敛，不出现等待回复结束才能批准的死锁。
- [x] **AC-7 跨端竞争与旧交互**：桌面先处理、QQ 后点击，重复回调、会话切换或删除、运行取消和超时均不重复执行、不串会话；状态提示与服务端一致。
- [x] **AC-8 持久化和恢复**：会话模式重启后保持，其他新会话保持默认；断线或重启后的旧审批按钮不能恢复失效请求。
- [x] **AC-9 投递失败**：按钮不可用、授权详情无法完整展示、消息失败或结果不明时不误授权；用户得到明确反馈，服务端等待有界。
- [x] **AC-10 确定性回归**：核心状态、调用链、身份与范围校验、失败和竞态均有自动化覆盖，项目 `scripts/check` 全绿。
- [x] **AC-11 真实跨端验收**：在明确的候选版本上，由用户操作实际 QQ 客户端，coding agent 核对对应服务端证据；至少覆盖档位双向切换及取消、文件和命令允许/拒绝、免授权任务、已有 pending 切换、跨端先后处理及旧按钮。记录 QQ 客户端平台/版本、服务端来源与新鲜度、操作时间、客户端所见、回调、审批终态和实际副作用。人工结果缺失或链路无法关联时保持待验收。
- [x] **AC-12 用户验收确认**：用户确认真实 QQ 使用体验满足需求，才能把需求标记完成并进入合入。

## 验收执行约束

- 自动化覆盖机制；真实客户端验证展示、可点击性、返回反馈和真实投递链路。二者分开记录，不相互替代。
- 发送接口成功仅证明平台接收；回调 ACK 仅证明点击事件被接收；批准终态也不等于执行成功。以实际执行证据判定最终效果。
- 验收使用专用会话和可清理的临时测试文件、无害命令。高危拦截用不会执行破坏性动作的受控测试证明，不在用户机器上试执行危险命令。
- coding agent 不默认拥有 QQ 客户端观察能力。客户端结论由用户实测反馈或用户提供的脱敏截图等证据支撑，并注明观察来源。
- 真实环境验收前核对运行实例、源码新鲜度和 QQ 绑定，避免多个 bridge 同时消费同一机器人连接；已有用户运行实例的接管或重启另按生命周期规则执行。
- 本次确认不代表已经执行真实 LLM 测试。需要由 coding agent 发起真实模型调用时，另说明目的、配置和粗略调用量，并遵守逐次授权规则。
