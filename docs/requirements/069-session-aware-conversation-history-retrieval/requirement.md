# 069 · 会话感知的历史查询与可靠召回

> Session-aware Conversation History Retrieval

## 状态

CONFIRMED

## 1. 背景

[`020`](../020-engine-tool-conversation-history/requirement.md) 已让 Agent 能通过
`recall_past_chats` 主动检索本地历史对话，[`048`](../048-memory-retrieval-quality-pass-2/requirement.md)
又统一了显式历史查询与自动记忆召回的检索编排。现有能力在底层会扫描多个持久化会话，
因此“跨会话正文检索”本身已经存在。

真实使用仍暴露出一个更完整的产品缺口：用户按产品中可见的会话名称询问
“帮我看看诗欣IM这个会话今天聊了什么”时，Agent 把会话名称当作消息正文关键词搜索，
没有定位到同名会话，也漏掉了“今天”的时间条件。工具返回无关候选后，Agent 又把
“没有按这个词搜到消息”错误解释成“工具只能查当前会话”，并在后续追问中持续强化
这条错误能力描述。

进一步排查确认，当前能力还存在以下相互关联的问题：

- 会话展示标题、用户重命名标题与归档状态属于会话管理信息，历史查询看不到这些信息，
  因此不能按用户实际看到的名称选择目标会话。
- 查询以消息级候选为中心，不能稳定表达“指定会话 + 指定时间范围 + 整体总结”的意图。
- 普通跨会话查询容易被最近且较长的当前会话占满，其他同样相关的会话在最终截断前被挤出。
- 编辑并重发后已经失效的旧对话分支仍可能被历史查询召回，与用户当前看到的有效历史不一致。
- 无可靠命中时，结构化记忆或弱相关候选仍可能把结果填成成功，生成层难以区分“确实找到”
  和“只有一些模糊相关内容”。
- 显性历史意图需要由 Agent 统一理解并生成结构化工具参数；宿主层若再用词法规则解析同一句
  用户输入，会形成两套语义来源并造成会话名、时间或查询目标分歧；已有
  [`issue 019`](../../issues/019-im-recall-tool-not-triggered/README.md) 记录了调用稳定性风险。

本需求在 020 与 048 的底座上，把“能扫历史文件”提升为“用户可以按自己理解的会话和时间
可靠地回看过去”，并让工具结果、模型回答与产品会话视图使用一致的事实边界。

## 2. 目标

- 用户能按产品中可见的会话名称或足够明确的名称片段定位目标会话，并查询或总结其中的历史。
- 用户同时表达的会话、主题、时间范围和说话方约束不会在工具调用或检索过程中静默丢失。
- 历史查询只使用当前有效、可归属的对话证据；无证据时如实为空，不用无关记忆填充答案。
- 普通跨会话查询兼顾相关性、时间与会话覆盖，不让当前会话仅因更长或更新而垄断结果。
- Agent 稳定理解并如实表达本工具的能力边界；遇到未定位、未命中或用户补充条件时重试或澄清，
  不自行编造“不能跨会话”等限制。
- 桌面、IM、CLI 与 bridge 持久化入口共享一致语义，并具备可定位失败阶段的测试和观测证据。

## 3. 范围

### 3.1 包含

#### 面向用户的会话定位

- 支持使用产品当前展示的会话标题定位目标会话，包括初始标题和用户重命名后的展示标题。
- 支持使用足够明确的标题前缀或片段定位，例如完整展示标题为“诗欣IM（……）”时，
  用户说“诗欣IM”能够匹配该会话。
- 多个会话同时匹配、名称过于宽泛或没有足够证据判断目标时，Agent 应自然列出少量可理解的
  候选并请求用户确认，不得自行猜选。
- 用户使用“当前这个会话”“QQ/IM 那个会话”等产品已知范围描述时，可以结合已存在的会话
  和通道信息缩小候选；不得把任意未保存昵称猜成某个会话。
- 定位过程和最终表达使用用户可理解的标题、时间和通道概念，不向用户或模型暴露底层
  session id、文件名、schema 或存储路径。

#### 复合查询意图保真

- 同一请求中的目标会话、主题关键词、明确时间范围、说话方与查询目标应同时生效。
- “今天 / 昨天 / 上周 / 某个日期”等明确时间表达必须由 Agent 完整映射为结构化参数；工具只
  校验和执行参数，不从原始用户 query 二次推断。
- 支持以下用户目标：
  - 确认某个会话中是否聊过某件事；
  - 找回某句话或相邻对话；
  - 总结某个会话在一段时间内聊过的主要内容；
  - 在未指定会话时跨所有可回忆会话搜索或总结。
- 目标或边界仍然含糊且会实质改变结果时先澄清；能够从当前请求可靠确定时不增加多余确认。

#### 有效历史与生命周期语义

- 历史查询与产品当前会话视图使用一致的有效分支；编辑并重发后被替换的旧消息、旧工具结果
  和旧回复不得再次作为可回忆证据。
- 当前正在执行的本轮问句、调用工具前的过渡话、未完成的 partial 回复不得污染“过去聊过什么”
  的结果；当前会话中本轮之前的有效历史仍可查询。
- 已硬删除的会话或内容不可召回。
- 已归档会话仍可召回：归档表示从普通列表收起，不等于遗忘或删除。定向查询命中归档会话时，
  无需向用户暴露内部归档实现，但不得因归档而假装不存在。
- 现有人格与单设备 owner 边界继续生效，不因扩大查询能力而跨越既有数据所有权范围。

#### 结果相关性与证据边界

- 指定会话后的结果必须可归属到该目标会话；无法归属到目标会话的结构化记忆不能用于回答
  “这个会话里聊过什么”。
- 没有满足用户约束的可靠证据时，结果必须保持无命中语义；不能为了填满 top-K 而把弱相关或
  无关候选包装成成功。
- 精确标题、精确关键词、原话片段等强信号优先保留；语义相关候选可以补充，但不得压过
  可验证的精确证据。
- 普通跨会话查询以相关性为首要依据，并兼顾时间与会话覆盖。同样相关时，单个当前会话不能
  仅因消息更多或时间更近而无上限占满最终结果。
- 消息片段必须包含实际命中位置，并在需要时携带相邻问答；长消息不能因固定从开头截断而让
  模型看不到触发命中的内容。
- 面向“聊了什么”的总结按有效对话轮次和主题组织，避免把重复、相邻重叠或同一轮的多个候选
  当作多个独立事实。

#### Agent 行为可靠性

- 用户明确询问过去会话、此前说法、指定会话内容或一段时间内聊过什么时，Agent 应稳定选择
  历史工具并生成语义正确的参数；可靠性通过工具描述、schema、回归 fixture 与 agent eval
  保障，不在宿主层复制一套自然语言意图路由器。
- 首次查询未定位或未命中，但用户补充“是另一个会话”、具体标题、时间或主题后，应使用新增
  条件重试；仍无法确定时澄清，不能直接宣称能力不存在。
- Agent 对本工具的自我描述必须与真实能力一致：可以自然说明能回看过去聊过的内容，也应如实
  说明只能依据本机保留且当前有权访问的会话证据；不得声称“只能查当前会话”。
- 工具调用失败、目标不存在、条件无结果和能力不支持是不同结果，生成层必须能够区分并作出
  相应表达。
- 延续既有朋友式表达，不向用户暴露工具名、参数、数据库、索引、内部 id 或调试 trace。

#### 兼容、评测与可观测

- 保持 020 已有无指定会话的正文搜索、时间、说话方和数量限制能力不退化；正文搜索参数从含义
  模糊的 `query` 更名为 `search_text`，明确它只承载历史正文检索内容，而不是用户整句请求。
- 桌面、IM、CLI 和 bridge 持久化入口使用同一套会话定位、有效历史和检索语义；无状态 API
  不得因此获得并不属于其请求的数据访问能力。
- 开发观测能够区分失败发生在会话定位、查询解释、数据源召回、候选融合、预算截断还是生成层，
  并能看到候选所属会话的内部统计；这些调试信息不得进入面向用户的工具结果。
- 自动化测试覆盖会话标题定位、标题片段匹配、歧义澄清、时间约束、有效分支、空结果、跨会话
  排序与归档/删除边界。
- Agent 行为评测覆盖真实失败链：按会话名查询 → 首次未命中或需澄清 → 用户补充目标 → 重试并
  正确回答，以及用户追问工具能力时不再给出错误限制。
- 机制性行为优先使用 fake / mock 和确定性 fixture 固定；真实 LLM 只作为经单次授权的观察性
  验证，不作为默认测试命令的隐式外部调用。

### 3.2 不包含

- 不建设通用的“产品自我认知 / 能力目录”系统；本期只保证会话历史查询相关能力陈述真实。
- 不新增或重做会话列表、重命名、归档等桌面 UI；复用产品已经存在的可见标题与生命周期信息。
- 不支持把任意未保存的私人昵称自动绑定为会话别名，也不新增联系人目录或外部平台通讯录同步。
- 不做跨设备、跨安装或云端会话同步；查询范围仍是本机已有且当前有权访问的数据。
- 不扩展为通用记忆抽取质量需求、任意知识图谱或多跳关系推理；只处理会话历史查询需要的证据。
- 不恢复或查询已硬删除内容，不新增回收站能力。
- 不预先指定必须引入持久化全文索引、向量库或新第三方依赖；若现有规模无法满足性能目标，
  在技术方案中基于实测决定最小必要优化。

## 4. 核心需求

### R-1 会话名称能够成为查询范围

- 产品展示给用户的最终会话标题是可查询标识，用户无需知道底层 id。
- 完整标题与足够明确的标题片段都能定位；多义匹配必须澄清。
- 选定目标后，后续检索和总结不得混入其他会话的不可归属证据。

### R-2 用户约束不得静默丢失

- 会话、主题、时间、说话方和查询目标可以组合。
- 明确约束必须生效或触发澄清，不能因工具调用参数不完整而退化为无范围搜索。
- 对时间范围总结，结果只覆盖范围内的有效对话。

### R-3 查询视图与用户可见历史一致

- 编辑重发后的失效分支、partial 输出和当前未完成轮不进入历史结果。
- 归档仍可回忆，硬删除不可回忆。
- 各持久化入口对同一会话给出一致的有效历史判断。

### R-4 无证据时可靠为空

- 无目标会话、目标歧义、目标存在但无相关内容、数据源失败必须可区分。
- 结构化记忆或语义相似内容只有在满足当前会话范围和相关性要求时才能作为证据。
- 生成层不得把无关候选、用户暗示或自身猜测补成过去发生过的对话。

### R-5 跨会话结果相关且有覆盖

- 排序优先反映相关性，再结合时间、重要性和会话覆盖。
- 单会话候选不能无条件垄断跨会话结果；同样相关的其他会话应获得合理展示机会。
- 返回片段包含命中位置并减少同一轮重复，能够支持自然总结而非机械罗列消息。

### R-6 历史意图与能力陈述可靠

- Agent 决定是否调用历史工具，并把会话标题、正文检索内容、时间、说话方和模式分别写入
  结构化参数；宿主与工具不得接收原始 query 后再次判断用户意图。
- 工具 schema 使用 `search_text` 表达正文搜索语义；`session_title` 只接收展示标题或明确片段，
  不得混入“去看看”“这个会话”等动作词。
- 明确历史查询稳定执行；补充条件后由 Agent 结合对话上下文重试或澄清。
- Agent 不把一次没命中解释为能力不存在，不把参数或数据边界误述为“不能跨会话”。
- 查询动作、结果来源和失败表达继续遵守 [`039`](../039-memory-inconsistency-response/requirement.md)
  建立的工具使用与证据真实性边界。

### R-7 可验证、可定位且不破坏既有入口

- 机制正确性由确定性测试锁定，生成行为由 agent eval fixture 覆盖。
- 调试 trace 能区分定位、检索、融合、截断和生成阶段，不靠查看用户正文猜测失败位置。
- 已有无目标会话的历史查询和自动记忆召回不因本需求退化。

## 5. 验收标准

- **AC-1 按展示标题查询**：存在展示标题为“诗欣IM（……）”的会话时，用户说“去看看诗欣im
  这个会话里今天有没发什么”，Agent 生成 `session_title=诗欣im`、今天的时间范围与 summary
  模式，不传正文 `search_text`；工具定位该会话，结果只使用该会话今天的有效对话。
- **AC-2 标题歧义澄清**：两个会话都匹配同一名称片段时，系统不猜选，向用户展示少量自然候选；
  用户确认后继续原查询，不丢失时间和主题条件。
- **AC-3 目标不存在**：没有匹配会话时明确表达未定位到目标，并允许用户补充；不得改称工具不能
  跨会话，也不得用其他会话内容作答。
- **AC-4 复合约束保真**：指定会话、时间范围、主题和说话方的组合查询只返回同时满足全部约束
  的内容；用户明确说“今天”时该条件不会静默消失。
- **AC-5 编辑重发一致性**：被编辑重发标记为失效的旧用户消息、旧回复和旧工具结果均不能被
  历史查询召回；新分支可以正常命中。
- **AC-6 当前轮隔离**：本轮用户问句、工具前过渡话和 partial 回复不进入本轮历史结果；当前轮
  之前的有效消息仍可查询。
- **AC-7 可靠空结果**：目标会话存在但没有相关内容时返回无结果；无关结构化记忆不能把状态
  变成成功，Agent 不编造相关历史。
- **AC-8 跨会话排序与覆盖**：多个会话各有相关证据且当前会话候选显著更多时，最终结果仍包含
  其他同样相关会话；更弱的不相关候选不会只因会话多样性被强行加入。
- **AC-9 命中片段可用**：关键词位于长消息中后部时，返回片段仍包含关键词及必要邻近上下文；
  同一轮的重叠候选不会在总结中被重复计算。
- **AC-10 生命周期边界**：归档会话仍能被标题定向或普通历史查询命中；硬删除会话不能命中。
- **AC-11 补充条件后重试**：首次查询未定位后，用户补充“是另一个会话”或具体标题，系统会
  使用补充条件继续查询或澄清，不直接结束为“查不到其他会话”。
- **AC-12 能力陈述真实**：用户询问该能力时，Agent 不再声称“只能查当前会话”；回答同时保持
  本机数据、权限和无证据不猜测的真实边界。
- **AC-13 多入口一致**：桌面、IM、CLI 和 bridge 持久化路径共享上述定位与有效历史语义；无状态
  API 仍保持无状态隔离。
- **AC-14 既有行为不退化**：020、039、048 已有历史工具参数、证据边界、自动召回和工具调用
  相关自动化测试继续通过。
- **AC-15 自动化与观测**：确定性测试覆盖 AC-1 至 AC-10 的机制行为；agent eval 覆盖 AC-11、
  AC-12 的生成行为；trace 能把失败定位到明确阶段，默认验证不调用真实外部 LLM。
- **AC-16 项目门禁**：项目规定的完整检查通过；若另行授权真实 LLM 观察验证，模型、范围和结果
  记录在本需求进度文档中。

## 7. 开放问题 / 技术方案阶段确认

- 会话定位应扩展现有历史工具、增加独立的会话解析能力，还是在统一检索请求中增加受控范围，
  由 `design.md` 根据现有模块边界决定。
- 标题片段的归一化、匹配优先级、歧义阈值和候选数量需要在方案中锁定，并覆盖中英文与长标题。
- 指定会话时如何约束结构化 memory、如何保留可溯源的原始历史，以及跨源结果如何表达置信度，
  由方案阶段结合现有 provenance 能力确定。
- Agent 工具选择与参数生成的稳定性由 tool description、结构化 schema、模型回归 fixture 和
  观察性 eval 共同保障；不新增宿主层自然语言路由。
