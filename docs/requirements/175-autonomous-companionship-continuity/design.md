# 175 · 自主陪伴优化技术方案

CONFIRMED。对应[需求与验收条件](./requirement.md)的 R1–R3。

## 内心活动读取

在会话工具组注册 `read_inner_activity`。默认读最近一次唤醒，继续读取使用工具返回的游标，按主题检索得到的 `inner_activity_ref` 可直接用作 `source_ref` 定位命中的唤醒。工具从本地会话存储定位已有内心会话并校验来源，沿用会话历史的有效事件与唤醒边界。只投影活动时间、AF 正文和有关的投递回执；宿主简报、模型内部事件及工具原始结果不作为活动正文。长文本须有界且可续读。过期游标和丢失的引用返回可恢复的错误。

## 本轮文件审批

工具及提示装配共同使用审批服务对当前 session、run、surface 的判定。普通上下文、Skill 激活及刷新沿用同一份能力说明。实际执行仍逐次校验路径与权限。测试用不同的普通会话与内心会话，先取历史中的文件引用，再对同一文件申请权限、读旧版本、追加并重新读取。拒绝和版本冲突以工具结果为准。

## 首次联系

沿用持久化的首次概览标记，仅在首次活动构造本轮专用的介绍块。该块加入本轮 system prompt，避免宿主唤醒简报作为历史回放时再次出现介绍。联系暂停时跳过，恢复后按正常节奏运行。普通发送保留精确目标契约；首次活动缺目标时允许宿主选择可用普通会话。存在普通会话但均归档则跳过。零会话时随投递建立可回复的普通会话，目标使用可恢复的标识。发送与暂停协调，重试复用同一次招呼的投递记录。桌面消息提交、QQ 通知结果分别沿用原有回执。

## 验证

单测覆盖活动读取、引用、翻页、空历史、失效历史及不同审批渠道。Bridge 测试覆盖首次提示与普通唤醒的差别、零会话、仅归档、用户中途创建会话、暂停和幂等。使用隔离目录中的同一手记验证跨会话，最终按项目检查入口运行 lint、类型检查和测试。自然措辞与模型选择属于观察型验证。
