## 轻量管理入口

以下是本需求拟实现的命令语义，尚不是已有能力：

| 动作 | 行为与副作用 |
|---|---|
| `status` / `inventory` | 只读配置与目录记录，输出最后统计和实时卷空间；不创建目录或安装依赖 |
| `inventory --scan` | 显式逐对象精确扫描，输出进度、统计时间和完整性；可取消，不触发构建或删除 |
| `configure` | 显式写入构建根、预算、低水位、自动回收范围；不迁移或清理旧目录 |
| `gc` | 默认输出回收计划；`--apply` 执行重新核验后的精确目标 |
| `pin` / `unpin` | 对明确对象设置或取消用户保留，记录理由；不改变构建身份 |
| `adopt` | 预览现有目录的归属与接管条件；显式 apply 后才登记可管理对象 |

所有入口支持稳定 JSON 输出，面向人的进度走 stderr，避免污染 JSON。现有 `package workspace-status` 与 `workspace-gc` 作为兼容入口委托同一实现，其默认清理范围仍是 package；统一入口可显式选择其他已登记类别。

包装入口优先使用已安装且版本符合项目要求的 Python 3.12（含可用的现有项目解释器）；只探测本机，不使用会自动下载解释器或同步依赖的启动方式。缺失时说明安装前提并退出。管理模块不导入 package `run.py`、产品运行模块或第三方库。

实际 package 构建仍可沿用当前 `uv run` 依赖准备，但在它之前先由轻量入口检查根目录、卷空间和所需回收。依赖安装本身可能写入的卷也要展示。版本状态等只读路由逐项验证导入闭包，不以名称假定其无副作用。

## 配置、控制目录与路径

### 稳定控制目录

控制目录独立于可变 build root，不复用产品用户数据 helper：

- Windows：`%LOCALAPPDATA%/agent-friend/build-control/`。
- macOS：`~/Library/Application Support/agent-friend-build/`。
- Linux：`$XDG_STATE_HOME/agent-friend-build/`，无设置时使用 `~/.local/state/agent-friend-build/`。

目录内分别保存配置、受管根索引、对象记录、锁及小型构建报告。配置、记录使用带 schema version 的 UTF-8 JSON；写入采用同目录临时文件加原子替换。未知 schema、损坏或缺失关键记录按不可自动清理处理，不能凭目录名恢复删除权限。

控制目录不允许被普通 CLI 的 `--state-dir` 改写。自动测试可注入隔离的控制目录；生产 CLI 不暴露可绕过同一账号锁域的第二套控制目录。

### 路径兼容

- 保留既有 package 显式参数和环境覆盖。解析顺序为：显式参数、对应既有环境变量、本机持久配置、现有默认值；计划输出每个值的来源。
- 持久配置给出统一 build root。其下按 package、dev、rust-check、runtime-regression 分区，再按仓库与 worktree 隔离。package 内继续保留现有 build-id 与 build-cache 相对布局。
- 未配置统一根时，package 保持既有默认路径；新接入的开发/测试构建使用平台对应的仓库外工程目录，全部通过同一 resolver 计算。
- 不自动选择 D 盘。切换配置只影响后续路径解析，不移动或删除旧目录。
- 构建实际采用显式覆盖目录时，将该根登记到稳定控制目录；状态查询不得因当前根变化而遗漏历史受管根。单纯预览参数不写登记。
- `CARGO_TARGET_DIR` 和回归入口 `--target-dir` 不能绕过管理。允许的仓库外覆盖必须被计划、校验、登记和保护；仓库内旧 target 只作历史只读对象，不自动接管删除。
- releases、symbols、Guide checkout、源码、虚拟环境和包管理器全局缓存不混入本期可删除对象；相关占用可提示但不推断清理权。

所有删除都校验规范化目标、受管根、对象标记与身份。拒绝目录穿越、根目录、源码根、用户资产、链接或 junction 跳转；安全边界检查失败时不递归删除。

## 对象与活动记录

受管对象是一个可独立保护和回收的目录，如某 worktree 的 Cargo/PyInstaller cache 或某次 build 工作区。最小记录包括：

- schema version、对象 ID、仓库公共 Git 目录身份、worktree 身份、类别、规范化路径和根 ID；
- 用途、创建时间、最近使用时间、当前状态、保留到期时间及用户 pin；
- 最近逻辑字节数、统计时间、完整性、统计时对应的对象代次；
- 活动操作 ID、持有者身份与必要的进程开始时间、关联构建/报告 ID。

根与对象目录放置可交叉验证的归属标记。索引是发现入口，目录标记是删除复核的一部分；两者不一致只读报告，不能自动修正后删除。

操作记录与对象记录分开：一次构建可同时占用 cache、build 和报告目录。父构建、smoke 子构建、dev harness 必须保持同一逻辑操作的保护关系。

### 生命周期

| 用途或事件 | 结果 |
|---|---|
| `runtime-verify` 成功 | 归档必要验证结果与输入身份后，立即删除本次大体积 build；复用缓存按全局策略保留 |
| 既有 `runtime` 成功 | 保持分步构建语义，进入 `awaiting-installer`，默认保留 48 小时 |
| `installer` / `all` 成功 | 先保证发布和报告归档完成，再删除本次 build；不会删除 release 或 symbols |
| smoke candidate | 进入 `awaiting-smoke`，默认保留 48 小时；矩阵期间延续保护，成功后按既有 candidate/baseline 契约回收 |
| 失败或正常中断 | 归档失败阶段与错误摘要，现场默认保留 48 小时，可显式 pin |
| 异常退出 | 不仅凭 PID 消失认定空闲；无法证明相关后代进程均已退出时保持受保护，输出需人工核实状态 |
| 删除失败 | 保留 `cleanup-failed` 状态和实际剩余路径；后续可重新核验并重试 |

新增 `runtime-verify` 表达仅验证用途，现有 `runtime` 的后续 `installer --reuse-build-id` 语义不变；package-release 的 runtime-only 路径迁移到新用途。续跑仍走现有源内容、Guide、profile 和 build identity 校验。

过期但未删除的续跑对象可以由一次明确续跑操作在锁内重新校验并保护；已删除对象返回明确不可续跑状态，不猜最近构建。用户 pin 无隐式失效时间，需显式 unpin；它计入预算，不能被容量压力覆盖。

报告归档先于删除，包括构建身份、Guide 来源、输入指纹、阶段结果、计时、错误及必要有界日志。原 `package-timings.json` 从易删除 build 中归档到控制目录的报告区；若必要证据写入失败则保留现场，不宣称生命周期完成。制品及正式矩阵报告沿用原有权威存放位置和校验，不创建冲突副本。

## 容量策略与盘点

### 初始默认值

| 策略 | 默认值 | 说明 |
|---|---|---|
| 受管缓存与工作区合计预算 | 80 GiB / 仓库 | 跨已登记根统计，受保护对象也计入总占用 |
| 卷空间低水位 | 60 GiB | 低于该值触发回收评估；不能降低既有构建硬门槛 |
| 可再生成 cache 闲置期 | 7 天 | 无空间压力时沿用既有保留习惯 |
| 分步续跑、smoke 等待和失败现场 | 48 小时 | 有活动操作时不因到期清理 |
| 自动回收 | 未配置时关闭 | 一次明确 configure 启用已登记类别后，在该范围内持续有效 |

这些是可配置默认值，不是对当前机器已有目录的删除授权。预算是准入和回收目标，不是假定外部进程不会继续写盘的绝对配额。

### 回收规则

1. 在标准构建开始前、结束后检查策略；查询、plan 和精确盘点均不自动删除。
2. 排除活动、有效等待/失败保留、pin、归属不明及不完整保护状态。
3. 无压力时回收已过期对象；出现容量或卷空间压力时，优先考虑已失去源码 worktree 的无保护 cache，再按过期、最近使用时间及稳定 ID 排序。不能因 worktree 被删就抹掉有效的 build 保留。
4. 容量压力的回收目标为回到 80 GiB 以内；卷压力只计算同卷对象的潜在释放。每次成功删除后重读实际可用空间，不把逻辑大小累加当作已释放物理字节。
5. 一次操作只使用已冻结并复核的精确目标。遇到状态变化或保护冲突就跳过，不扩大到未知目录。
6. 可清理对象耗尽后仍不满足准入条件，返回明确缺口、保护原因和人工可选动作，不自动换盘、取消 pin 或强杀进程。

快速盘点只读少量记录和卷状态。`bytes` 未知或过期时保留相应标志，不用零填充。精确扫描按对象遍历、不跟随链接，输出扫描进度；取消时只保留已完整扫描对象的结果，整体标为 incomplete。

构建持有对象保护时使历史统计失效；结束后刷新自身涉及的对象，避免每次重扫全仓库。需要容量准入但缺少可信统计时，由执行路径显式说明并补扫相关对象；快速查询不会隐式升级成完整扫描。仅凭 stale/unknown 数值不能宣称预算满足。

## 并发、回收与嵌套构建

使用稳定控制目录下的跨进程 OS 文件锁，不把存在 lock 文件等同于有活动进程。

- package 仓库级生命周期锁按公共 Git 目录身份确定，不随 state root 变化。
- 共享 release root 的操作使用按规范化实际根标识的锁；同一 installer-smoke 身份另有账号级 profile 锁，避免不同仓库副本互相覆盖隔离安装现场。
- 可回收对象使用精确对象锁；构建从使用前至子进程结束全程持有，GC 删除前非阻塞获取并重新验证。
- 多资源锁采用统一顺序。短期索引锁不在等待长任务锁时持有；GC 遇到占用就跳过，避免持有全局锁等待编译结束。
- 父子构建复用受校验的操作身份，不能仅靠环境变量布尔值绕过锁。父进程持有生命周期保护，子进程不能自行释放；明确根、工作树、profile、操作 ID 的对应关系。

长驻 dev 运行期间保留对应 target 保护，直至现有 runtime 生命周期确认结束。进程开始时间用于排除 PID 复用；异常退出且后代存活性不明时 fail closed。方案不授权终止用户或未知进程。

旧版本 runner 不认识新控制锁，过渡期需要持有兼容的旧 package 根锁并检查旧 runtime lease/活动证据。无法证明旧消费者空闲的对象不得自动接管。历史根只读发现不能成为跨版本并发安全的替代证明。

## 构建计划与多卷空间

计划模块由轻量管理入口和实际 runner 共用，输出：用途、解析后路径及来源、涉及卷、缓存/续跑对象、保护与回收候选、已有统计新鲜度、阶段空间需求、验证等级及未完成的重校验项。

计划不分配正式版本、不创建 build、不应用 Guide baseline、不下载契约模板，也不把未经实际验证的 smoke 报告标为可复用。重用现有纯计算的 profile/impact 逻辑，完整指纹和证据有效性继续由实际 preflight 校验。

实际执行持锁重算计划，输出最终决定。配置、源码、输入或保护状态改变时，不能继续执行旧删除清单。轻量查询和计划无需导入第三方构建模块；涉及正式构建的重依赖仅在执行阶段加载。

空间检查按实际卷分组，考虑 state、release/symbol、进程临时目录、依赖准备位置及 installer-smoke 安装空间。路径通过最近存在祖先解析所在卷；无法解析时阻塞，不按盘符字符串猜测。

- 既有 package 至少 40 GiB 的硬门槛保留，不因热缓存或新预算而降低。
- 同卷同时存活的不同产物按阶段峰值求和，避免各路径分别检查却复用同一份空闲空间；同一对象不重复计数。
- 暂无实测的构建增长使用保守估计并标注来源；已知 payload/installer 大小可作为后续阶段估算输入。
- 构建开始和关键大写入阶段检查余量。共享卷的本工具活动记录包含预计剩余写入需求，不能让两个准入操作重复承诺同一空间。
- 临时目录仅对当前子进程配置，不修改系统环境；无法重定向的安装器临时空间仍单独计入所在卷。
- 外部软件可能继续消耗磁盘；阶段复检失败保留错误与现场，不把事前通过写成整个构建一定有空间。

## 旧目录与配置迁移

本期不执行自动物理迁移。现有 package 布局、历史 workspace-state、Git 登记和 build identity 可作为识别证据；仅有目录名或最近修改时间不足以自动接管。

`adopt` 先输出 exact path、来源证据、类别、活动检查、体积口径和拟授予的管理能力；用户显式接管后在锁内重验并写归属标记。仓库内 target、未知独立编译目录、失去关键记录的缓存只展示为 unmanaged，保持原样。

新配置生效后的标准入口使用新路径；旧根留在发现列表。环境覆盖与持久配置冲突时明确显示优先级，不静默迁移、合并目录或将新根权限扩张到整个磁盘。

## Skill、规则与验证影响

package-release 保留查询、runtime-only、安装包、渠道和授权路由；runtime-only 使用验证用途，其余路径消费代码计划，不复制容量或目录算法。持久自动回收配置的授权只覆盖明确类别、路径边界和策略，不覆盖源码、成品或生产安装。

同步核对 `repo-directory-layout`、`cross-platform-dev`、`desktop-startup-default`、`frozen-runtime-packaging`、`windows-installer-integrity` 与受影响脚本说明。项目 `.cursor` 是修改源，生成 adapter 用现有同步和 doctor 流程更新，不手改 `.Codex` 副本。

本方案改变构建编排、路径和隔离验证资源保护，实际实现后按 diff 和 installer-contract 判定验证等级。涉及安装身份/矩阵互斥路径时需要 full-matrix；不得因主要目标是省空间而跳过机器给出的 floor。真实打包阶段再按 package-release 进入 Guide baseline 流程。本阶段不构建、不安装、不迁移。

验证安排（成功标准仍只定义在 requirement）：

| 范围 | 方法与关注点 |
|---|---|
| 配置与目录 | 临时目录 fixture 验证覆盖优先级、历史根发现、损坏 schema、跨平台默认、路径逃逸和 junction/symlink 拒绝 |
| 容量与时间 | 可控时间/卷空间验证 orphan、LRU、到期、pin、保护项超预算、未知统计和逻辑/物理差异 |

## 风险与执行顺序

主要风险是把状态记录误当成活动证明、改变路径后遗漏消费者、回收证据过早以及跨根锁迁移不完整。先实现纯管理与隔离测试，再接 package 生命周期和跨根锁，最后接开发/回归入口并同步指引；每一步都保留单一真相源。

不会为了“预算达标”删除受保护对象，也不会承诺未知第三方写入下的绝对磁盘配额。跨 worktree 共享可变 cache 留待后续，不在本期省略构建身份隔离。

实施阶段开始后创建 `progress.md`，逐项记录任务和 AC；当前方案确认不自动代表修改代码、迁移本机目录或启用真实缓存自动删除。
