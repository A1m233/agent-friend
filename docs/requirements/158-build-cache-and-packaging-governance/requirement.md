# 158 · 构建缓存与打包工作区治理

## 状态

已确认（Confirmed）

确认日期：2026-10-10。

## 背景

需求 055 已建立仓库外的打包目录、构建隔离、版本与制品治理。随着多个 coding agent 在多个 worktree 中连续执行开发检查、冻结验证和安装包构建，仅依靠按天过期的策略不足以控制短期空间增长。

2026-10-06 清理后，本机 C 盘可用空间约为 171 GiB。2026-10-09 调查发现，打包工作区从清理后保留的约 73.7 GiB 增至约 142.0 GiB，此外还存在独立回归测试与开发编译目录。目录逻辑大小不能直接等同于物理占用，调查也不是静止磁盘上的完整差量测量，具体证据与局限见 [evidence-index.md](./evidence-index.md)。

现有管理入口还存在两类操作成本：查询可能先初始化完整构建环境；盘点默认递归统计大量文件。运行时验证与等待继续生成安装包共用保留方式，也使完成任务后的中间产物继续占用空间。

## 目标

- 多 worktree 连续构建时，受管缓存增长受容量与空间策略约束，不依赖用户反复人工查找大目录。
- 根据验证、续跑、失败调查等用途管理产物，保留必要证据并及时回收可再生成的大文件。
- 统一查看打包、开发和专项回归构建目录，清楚展示归属、用途、体积统计时间、活动状态与可回收原因。
- 在新 worktree 中也能轻量查询，不因管理缓存而安装整套构建依赖。
- 支持持久配置构建存储位置，并保持跨磁盘的空间预检和并发保护有效。
- 让代码负责确定性构建计划与执行规则，skill 负责意图、授权边界和操作编排。

## 范围

### 包含

- 当前 package 工作区与编译缓存的容量预算、低水位、到期及最近使用策略。
- 已失去源码 worktree 的受管缓存、活动构建、待续跑构建和显式保留产物的识别与区别处理。
- 纯冻结验证、分步打包、完整打包、失败与中断后的保留和回收行为。
- 项目标准打包、开发、Rust 检查及专项 runtime 回归入口产生的构建目录的统一盘点和生命周期接入。
- 持久的本机构建根目录配置、多根目录可见性，以及旧目录的只读发现和显式接管边界。
- 轻量状态查询、快速盘点、可选精确扫描与可理解的构建计划。
- 构建工作区、制品输出、必要临时空间及安装器验证实际使用卷的空间预检。
- 不依赖可变构建根目录的并发保护，包括与同一制品库和隔离安装身份相关的互斥边界。
- 同步调整 package-release、直接相关规则、脚本说明与必要确定性测试。

### 不包含

- 跨 worktree 合并或共享可变编译缓存；本期保持必要构建隔离。
- 自动删除源码 worktree、Git 分支、未提交内容或来源不明的目录。
- 自动删除正式或本地测试安装包、私有 native symbols、用户数据、设置、凭据和产品日志。
- 自动迁移本机已有大目录，或擅自选择 D 盘等机器特定路径作为所有环境的固定约定。
- 降低 frozen capability smoke、installer matrix、身份校验、制品不可变性等现有可信性要求。
- 新增 CI/CD、远端缓存服务、安装包平台或产品界面。

## 需求

### R-1 · 有界且可解释的回收策略

- 在现有时间保留策略之外，支持受管缓存容量预算与所在卷的可用空间低水位。
- 用户一次配置并启用明确范围的自动回收后，标准入口能在策略规定的时机执行回收，无需每次重复确认同一范围。
- 回收优先考虑已失去源码 worktree 的可回收缓存，并结合最近使用和过期状态，避免频繁破坏仍有复用价值的缓存。
- 活动构建、有效续跑保留和显式保留产物不得被自动删除；识别不清时保留并说明原因。
- 受保护内容使预算无法满足时，应报告缺口及下一步，而不是为了满足预算扩大删除范围。
- 回收前提供可解释计划；执行时重新验证目标归属、活动状态和策略，执行后报告成功、跳过与失败项。

### R-2 · 按用途管理构建产物

- 纯冻结验证成功后，保留可复查的结果、输入身份和必要日志，及时回收无续跑用途的大体积中间产物。
- 分步构建准备继续生成安装包时，显式保留精确构建及其到期信息，使后续能继续既有构建。
- 失败、中断及进程异常退出后，能识别现场状态和恢复入口；失败大目录不应永久滞留。
- 清理失败需要可观察、可重试，不得将未完成的回收报告为成功。
- 清理与保留变化不得破坏 installer smoke 的 candidate、baseline 和证据复用契约。

### R-3 · 统一目录归属和持久配置

- 标准打包、开发、Rust 检查与专项回归入口生成的构建目录应具备可查询的归属与用途。
- 支持本机持久设置构建根目录，后续标准入口能一致采用；显式覆盖应可查询和追踪。
- 配置变化后，历史受管目录仍可发现，不因当前入口使用另一块盘而从盘点中消失。
- 既有目录须先盘点归类；只有能够证明归属、用途及安全边界的对象，才允许在明确授权后纳入管理。
- 新建可再生成的编译产物应遵守统一路径约定；本需求不顺带删除或搬迁已有源码目录内的产物。

### R-4 · 轻量查询与清晰计划

- 在没有项目虚拟环境或构建依赖的新 worktree 中，管理入口不得为了查询状态自动安装或同步构建依赖；基础执行工具缺失时给出明确提示。
- 默认快速盘点不遍历全部构建文件；未知或过期体积必须明确标识，不能当成零或最新值。
- 精确扫描是显式操作，支持进度与取消；取消后不返回伪完整结果。
- 构建计划应说明目标用途、实际目录和卷、复用与保留情况、所需验证、空间要求、回收动作及阻塞原因。
- 查询和计划操作不隐式构建、删除、发布或修改产品源码。

### R-5 · 多盘空间与并发正确性

- 在大体积写入前检查实际受影响卷；多个路径位于同一卷时应合并考虑需求。
- 空间不足时提供明确缺口和处理建议，不自动换盘、降低门槛或清理未获授权内容。
- 同一仓库的构建或清理不能通过切换构建根目录绕过既定互斥；不同操作共享制品库或隔离安装身份时也应正确协调。
- 回收与构建之间不得产生检查后被并发使用的误删窗口。

### R-6 · 收敛 skill 与代码职责

- 代码作为目录解析、策略、空间判断、活动识别、回收计划和构建计划的唯一可执行真相源。
- skill 根据查询、验证、续跑、测试包、发布等用户意图调用标准入口，解释结果和授权边界，不维护另一套计算与判定规则。
- 保持双平台管理入口语义一致；实际 installer 构建的平台限制继续遵循现有约定。
- 配置默认值、执行接口和内部实现留到技术方案阶段确定。

## 验收条件

- [x] AC-1：多个 worktree 连续生成受管缓存时，容量和低水位策略能触发可解释的有界回收；保护项超出预算时准确报告未满足状态。
- [x] AC-2：活动构建、有效续跑及显式保留对象不会被误删；计划后目标状态变化、路径逃逸或归属不明时安全停止或跳过。
- [x] AC-3：纯冻结验证成功后必要证据仍可复查，大体积临时目录按用途回收；分步构建可用精确身份继续，过期后给出明确状态。
- [x] AC-4：失败、正常中断与异常退出后能识别残留并恢复或回收；回收失败不会被误报为完成。
- [x] AC-5：打包、开发、Rust 检查与专项回归的标准入口均采用并登记适用目录；历史受管根可查询，来源不明旧目录不自动删除。
- [x] AC-6：没有项目虚拟环境的新 worktree 可执行轻量管理查询；不安装构建依赖，不创建项目虚拟环境，不触发构建或删除。
- [x] AC-7：快速盘点无需完整目录遍历；精确扫描可见进度、可取消，并明确统计时间、口径与完整性。
- [x] AC-8：构建根、输出、临时或验证目录分布在多个卷时正确预检；同卷需求不会被错误地独立视为均有足够空间。
- [x] AC-9：两个根目录或两个 worktree 并发构建、回收时互斥有效；同一制品库及隔离安装身份不因根目录不同而失去保护。
- [x] AC-10：构建计划与实际执行的用途、路径、验证和保留行为一致；skill、规则和脚本说明没有相互冲突的命令或策略。
- [x] AC-11：既有构建身份、渠道、Guide baseline 恢复、native symbols、安装验证及证据复用契约未回归；完成改动所需的项目检查与分级验证。
- [x] AC-12：形成包含环境与测量口径的前后验证证据，取得用户验收确认。
