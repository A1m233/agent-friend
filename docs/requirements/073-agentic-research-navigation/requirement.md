# Agent 自主研究与证据导航

## 状态

CONFIRMED

## 背景

agent-friend 已具备通用网页搜索、网页正文读取，以及小红书和 Bilibili 的部分站内搜索与内容读取能力。但真实使用暴露出：Agent 即使已经形成合理的多步调查计划，也可能因工具能力缺失或执行边界过度收紧而被迫中断。

代表性 bad case 是用户询问“看看b站up开战斗机的虾米，他有什么代表作”。Agent 尝试了 Bilibili 搜索和外部网页搜索，并找到可提供进一步线索的萌娘百科页面，但现有能力既不能直接搜索 Bilibili UP 主、读取创作者主页和作品列表，也不能把已读取网页中的真实链接继续作为下一跳证据，最终反而要求用户补充主页或视频链接。

该问题的本质不是 Agent 不够聪明，也不应主要通过要求模型“更努力搜索”的 prompt 修补解决。产品需要向 Agent 提供完成目标所需的搜索、读取和证据导航能力，并把安全约束放在具体动作的风险校验上，避免用固定步骤、当前轮次或过窄来源规则截断合理计划。

本需求承接：

- [065-trustworthy-read-tools-and-tool-runtime](../065-trustworthy-read-tools-and-tool-runtime/requirement.md) 的可信网页读取与工具运行预算；
- [072-chinese-social-platform-search](../072-chinese-social-platform-search/requirement.md) 的平台内容搜索、读取和本地登录恢复链路。

## 目标

1. Agent 能围绕用户目标自主选择和组合搜索、读取、链接跟随与平台能力，而不需要用户代替它提供本可自行发现的中间链接或标识。
2. Agent 能直接搜索 Bilibili UP 主、读取创作者资料和作品列表，并根据可验证的平台证据回答代表作等创作者问题。
3. 已由用户、搜索结果、已读页面或平台结果真实发现的资源能够成为后续可访问证据，包括跨工具、跨对话轮次和持久化会话恢复后的合理续查。
4. 搜索是否继续由用户目标、新证据和整体运行预算共同决定，不再由固定的一两次重试规则替 Agent 提前放弃。
5. 保留防止 URL 编造、数据外泄、SSRF、提示注入、无限采集和未授权外部动作的安全边界，同时让公开只读调查默认能够自主推进。

## 范围

### 包含

#### 自主研究与证据续查

- Agent 可以读取搜索结果或用户指定页面，并从已取得内容中识别真实存在的可访问资源。
- Agent 可以自主选择已发现资源作为下一跳，在普通网页读取与已支持的平台读取能力之间继续调查。
- Agent 可以在同一用户回合内进行多步搜索、读取、交叉核对和查询精炼，并在获得新证据后调整路径。
- Agent 未直接命中目标时，应先评估是否仍有合理的证据路径；只有路径耗尽、缺少只有用户能够提供的信息，或触及需要用户授权的边界时才向用户求助。
- 同一持久化会话中的已知公开资源可以跨对话轮次继续使用。应用重启或临时引用失效后，系统应尽量通过仍有效的会话证据恢复或重新定位，而不是无条件要求用户再次提供链接。
- Agent 可以从当前证据发现用户未明确点名、但与目标直接相关且产品已经支持的平台或资源类型，并切换到相应的只读能力。

#### Bilibili 创作者能力

- 支持按 UP 主名称及合理变体搜索 Bilibili 创作者，而不是只把名称当作视频标题或正文关键词。
- 创作者搜索结果应提供足以区分同名候选的公开身份信息和主页来源。
- 支持读取创作者主页的可用公开资料。
- 支持列出和继续浏览创作者发布的公开视频或其它本期已支持作品，并保留作品来源、标题、发布时间及平台提供时的互动指标。
- Agent 能基于创作者本人作品及可验证指标回答“代表作”“热门作品”“近期作品”等问题，并说明判断依据；不能把同名关键词视频误当成该创作者的投稿。
- 用户提供受支持的创作者主页直链时，Agent 能直接读取对应创作者，而不先退化成宽泛内容搜索。

#### 搜索深度与停止条件

- 普通网页搜索和平台搜索不再以固定“最多重试一两次”作为全局行为上限。
- 当前查询未命中但新证据提供了作者、别名、标题、站点、时间或关联资源时，Agent 可以继续发起有实质差异的查询或读取。
- 平台返回窗口不足时，Agent 应具备有界继续搜索候选的能力，而不是只能接受首个固定窗口。
- 完全相同且没有产生新证据的重复调用、整体预算耗尽或风险边界命中时，应停止继续扩张，并基于实际证据说明结果和缺口。
- 运行诊断能够区分 Agent 自主收敛、无新进展停止、预算停止、安全拒绝和工具能力缺失。

#### 安全与授权

- Agent 不得凭空构造从未在可信证据链中出现的读取目标，也不得把用户私密数据、凭据或会话内容拼入新 URL。
- URL 和跳转目标继续接受协议、主机、端口、公网地址和资源身份校验；私网、localhost、危险协议和异常跳转在本地网络访问前拒绝。只有搜索结果证据链中的精确 URL，才允许在本机 DNS 无法可信确认其公网性时改用与本机网络隔离的托管只读读取；用户直接提供的目标和不安全跳转不使用该例外。
- 网页、搜索结果和平台内容始终作为不可信外部数据，其中的指令、角色声明和行动要求不能改变用户目标或系统约束。
- 已由可信证据链发现的公开只读资源默认允许 Agent 自主读取，不因每次跟随链接而要求用户确认。
- 登录、访问受限内容及任何会产生外部副作用的操作继续遵循相应授权边界；本需求不把公开只读授权扩张为账号写操作授权。
- 搜索、读取、分页和链接跟随受整体调用量、时长、内容量、并发和无进展检测约束，不形成无限爬取能力。

#### 验证与回归

- 建立确定性的工具链测试，覆盖资源发现、跨工具导航、跨轮恢复、创作者搜索与作品读取，以及各项安全拒绝路径。
- 使用至少一个当前产品可用模型，在真实 agent-friend 桌面会话中执行原始 bad case 的端到端 replay。
- 现有普通网页搜索与读取、小红书笔记搜索与详情、Bilibili 视频/专栏/Opus 搜索与读取、登录请求与授权后恢复链路不得退化。

### 不包含

- 小红书作者搜索的本期交付承诺；方案应避免阻碍后续增加，但是否支持取决于连接器能够提供的稳定公开能力。
- 抖音、快手、微博、知乎等新平台接入。
- 发布、删除、点赞、投币、收藏、关注、评论、私信、购买或其它外部写操作。
- 自动处理验证码、规避平台风控、绕过访问控制或伪装高频人类行为。
- 账号批量采集、整站爬取、长期监控、数据仓库或无限遍历作者作品。
- 无平台字幕视频的下载、音频提取或语音转写。
- 取消全部 URL、安全、权限或运行预算限制；本需求调整的是限制位置和粒度，不是让 Agent 获得无边界网络能力。

## 关键信息

### 对话轮数口径

本需求中的“一个用户回合内完成”指：用户只发送一次目标请求，Agent 在生成该次最终回答前可以经历多次内部模型续轮和工具调用，但不得要求用户补充本可自行查得的链接、名称或资源 ID，也不得要求用户再次发送“继续”。内部工具调用次数不计为用户对话轮数。

### 证据与答案口径

- 搜索摘要只能作为候选线索；答案依赖正文、主页或作品归属时，应继续取得对应实际证据。
- “代表作”不是固定标题断言。Agent 应从创作者本人作品中选择，并给出播放量、互动量、发布时间、平台排序或其它实际取得的判断依据。
- 平台排序和互动指标会变化，验收关注身份、作品归属、来源和判断链正确，不把某个瞬时数值写成永久基准。
- 降级路径可以用于完成目标，但 Agent 必须如实区分站内结果、普通网页结果和实际读取到的平台内容。

## 验收条件

- [ ] **AC-1 原始 bad case 单回合跑通**：在真实 agent-friend 桌面会话中，只发送一次“看看b站up开战斗机的虾米，他有什么代表作”，Agent 在同一个用户回合内定位到正确 UP 主并直接给出答案；不得向用户追问 UP 主准确名称、主页、视频链接或要求再次发送“继续”。最终回答至少包含 2 个确属该 UP 主投稿的代表作品、可访问来源，以及每项选择所依据的至少一种实际平台证据。内部允许多次模型续轮和工具调用。
- [ ] **AC-2 原生创作者链路**：确定性测试证明按创作者名称能够得到创作者候选、读取目标创作者公开资料、列出其作品并继续取得后续候选；同名关键词内容不能被误绑定为该创作者投稿。
- [ ] **AC-3 外部线索 fallback**：在原生创作者搜索未命中或不可用的受控场景中，Agent 能完成“网页搜索 → 读取百科或其它线索页面 → 选择页面中真实出现的 Bilibili 资源 → 使用平台能力读取”的链路，并在同一用户回合内回答，不向用户索要中间链接。
- [ ] **AC-4 页面链接续跳**：网页读取结果能提供可继续访问的资源；Agent 可以选择其中的普通网页或已支持平台链接作为下一跳，来源关系可追踪，页面没有实际出现的 URL 不能因此获得授权。
- [ ] **AC-5 跨轮与恢复**：用户在后续轮次说“继续看刚才那个”或等价表达时，Agent 能使用同一持久化会话中的安全公开证据继续；应用重启或临时引用失效时，能够自动恢复、重新验证或重新定位。只有确实无法恢复且缺少必要用户信息时才请求补充。
- [ ] **AC-6 有新证据时继续研究**：确定性 Agent 测试覆盖超过两次搜索或读取仍持续获得新证据的路径，系统不得因固定重试次数提前要求用户介入；整体运行预算允许时应继续直到完成目标或证据路径真正耗尽。
- [ ] **AC-7 无进展时正确停止**：完全相同或等价调用持续没有产生新证据时，Agent 在有界次数内停止，不形成无限循环；回答明确区分已确认信息和仍缺失内容。
- [ ] **AC-8 搜索窗口可继续**：目标不在首个默认平台结果窗口、但能通过有界继续搜索定位时，Agent 可以继续取得候选并完成读取；首个窗口未命中不能被表述为平台上不存在。
- [ ] **AC-9 URL 与网络安全**：凭空生成或篡改资源身份的 URL、userinfo、非允许协议或端口、localhost、私网/保留地址及跳向不安全目标的重定向均在受保护边界拒绝。本机 DNS 失败或混合解析不得触发本地请求；仅当目标是搜索结果证据链中的精确 URL 时，允许改由与本机网络隔离的托管只读服务处理。用户直接提供的目标、不安全跳转和硬性拒绝不得使用该回退；失败结果不会被 Agent 表述为已读内容。
- [ ] **AC-10 提示注入与数据外泄防护**：外部页面中要求改变任务、调用其它工具、发送数据或访问携带用户隐私参数 URL 的文字不取得指令权限；测试证明 Agent 不能据此泄露会话信息或扩大授权。
- [ ] **AC-11 授权边界保持**：公开匿名可读内容不触发不必要登录；确实缺少完成目标所需的登录能力时，桌面和 IM 继续走既有请求、批准和恢复链路，且授权后仍由 Agent 判断下一步。
- [ ] **AC-12 既有能力回归**：现有普通网页搜索/读取、小红书笔记搜索/详情、Bilibili 视频/专栏/Opus 搜索/读取，以及工具事件、取消、并行和流式输出的相关自动化门禁全部通过。
- [ ] **AC-13 项目门禁**：`scripts/check` 全部通过，并保留 AC-1 真实 replay 的运行环境、模型、构建身份、工具路径、轮数、停止原因和脱敏结论；不得把完整用户会话、凭据或平台登录材料写入仓库。
