# 060 · 对话附件输入交互增强

## 状态

CONFIRMED

## 背景

059 已经打通图片、PDF、TXT 等附件从桌面对话输入到模型理解、会话持久化和历史展示的完整链路，并提供加号选择与拖放入口。但实际体验后，当前附件入口仍不如主流 Agent 对话产品顺手：用户不能把系统截图或复制的图片直接粘贴到输入框；拖放虽然已有基础处理，却缺少清晰、稳定的视觉反馈，用户不容易感知输入框可以接收文件；左下角加号的圆角方形外观也与输入区其余圆形动作按钮不协调。

ChatGPT 等主流产品已经把“选择文件、拖入输入区、粘贴剪贴板图片”作为互补的基础附件入口。Microsoft Cowork、Gemini 等产品还提供云端文件、代码目录或仓库等更重的输入方式。本需求优先补齐本地桌面对话中最高频、最低摩擦的输入动作，不扩张附件后端能力与外部账号集成。

## 目标

- 用户可以将系统截图或复制的图片直接粘贴到对话输入框，作为待发送附件。
- 用户可以把图片或受支持文件拖入输入框，并在拖入过程中获得清晰、稳定的可接收或禁止反馈。
- 加号选择、拖放和剪贴板粘贴共享一致的附件校验、上传、展示、失败处理与草稿保护行为。
- 输入框左下角的附件加号改为圆形按钮，与相邻动作入口保持协调。
- 普通文本编辑、文本粘贴、语音输入、发送和既有附件链路不因本次增强而回归。

## 范围

### 包含

#### 粘贴剪贴板图片与文件

- 当对话输入框处于可编辑状态时，用户可以粘贴系统截图、复制的图片或剪贴板中由系统暴露为文件的内容。
- 剪贴板中包含可用附件时，将附件加入当前待发送列表，并继续保留已经输入的文字和其他附件。
- 剪贴板只包含普通文本时，保持现有文本粘贴行为，不拦截、不改写文本。
- 剪贴板同时包含附件与其附带的文本表示时，不得把无意义的文件路径、图片占位文本或重复内容插入输入框。
- 一次粘贴多个可用附件时，按照剪贴板提供的顺序加入；超出当前模型数量、类型或大小限制的项目走现有明确提示。
- 平台没有向 WebView 暴露的剪贴板文件不要求绕过系统权限强行读取；系统截图和复制图片是本期必须保证的粘贴场景。

#### 可感知的文件拖放

- 图片、PDF、TXT 及当前模型允许的其他文件可以拖入对话输入框区域，复用既有附件能力。
- 文件进入输入框拖放热区后，输入区展示明确的高亮或覆盖提示，让用户知道松手会添加附件。
- 拖拽经过输入框内部子元素时，提示状态保持稳定，不闪烁或提前消失。
- 当前模型不支持附件、文件类型不支持或输入框暂不可用时，展示禁止操作反馈；松手后文件不进入草稿，并给出可理解的错误提示。
- 拖放多个文件时保持用户提供的顺序，并与加号选择、粘贴附件使用相同限制。
- 拖放热区限定在对话输入框组件，不把整个聊天消息区变成全局接收区域，避免用户移动文件经过窗口时误触。

#### 统一附件入口行为

- 加号选择、拖放和剪贴板粘贴统一遵守当前模型的附件能力、文件类型、单文件大小、总大小和单轮数量限制。
- 三种入口产生相同的待发送附件展示、上传进度、图片预览、移除和失败反馈。
- 任一附件添加或上传失败，不清空用户已有文字、其他有效附件或语音输入草稿。
- 上传中的附件、失败附件以及模型不兼容附件继续阻止发送，并沿用明确的修复提示。
- 输入框禁用、对话正在流式输出或模型能力尚未就绪时，粘贴和拖放不得绕过现有禁止状态。

#### 加号按钮外观

- 输入框左下角附件加号改为圆形图标按钮。
- 按钮继续保留现有点击区域、禁用态、悬停/聚焦反馈、键盘可操作性和无障碍名称。
- 外观与输入区相邻动作按钮协调，不改变加号打开系统文件选择器的既有语义。

#### 真实桌面端验收

- 在真实 Tauri 桌面端验证系统截图粘贴、复制图片粘贴、多附件拖入、拖入视觉反馈、禁止态和圆形加号外观。
- 验收同时覆盖普通文本粘贴、已有文字保留、附件移除和发送，确认既有输入能力没有回归。
- 浏览器预览不能替代本需求的桌面端视觉与交互结论。

### 不包含

- 不新增附件类型、模型能力、附件托管、Provider 上传、会话持久化或历史展示语义。
- 不把拖放热区扩展到整个聊天窗口或消息列表。
- 不接入云盘、最近文件、GitHub 仓库、代码目录或第三方内容源。
- 不增加应用内截图、拍照、扫描、图片标注或图片编辑能力；系统截图后粘贴覆盖本期快捷截图需求。
- 不引入绕过 WebView 平台能力的原生剪贴板文件读取能力。
- 不改变编辑重发场景目前不允许增删附件的边界。

## 验收标准

- **AC-1 系统截图粘贴**：在 Windows 真实 Tauri 桌面端截取屏幕后，聚焦输入框并粘贴，图片进入待发送附件列表且可以预览、移除和发送。
- **AC-2 复制图片粘贴**：从支持复制图片的应用复制图片后粘贴，图片作为单个附件加入，不向文本草稿插入路径、HTML 或无意义占位文本。
- **AC-3 普通文本粘贴不回归**：复制普通文本并粘贴，文本按原行为插入输入框，不创建附件。
- **AC-4 拖放反馈**：将一个或多个受支持文件拖入输入框时出现稳定、清晰的接收反馈；在内部元素之间移动不会闪烁，松手后附件按顺序加入。
- **AC-5 禁止与限制**：模型不支持附件、输入框禁用、流式输出中、文件不受支持或附件超限时，粘贴/拖放不能绕过限制，并显示明确反馈。
- **AC-6 草稿保护**：附件粘贴、拖放、上传失败或被拒绝时，已经输入的文字、语音草稿和其他有效附件保持不变。
- **AC-7 入口一致性**：同一组文件通过加号、拖放或剪贴板加入时，使用一致的能力校验、待发送展示、上传状态和错误提示。
- **AC-8 圆形加号**：附件加号在真实桌面端呈圆形，与相邻动作入口协调；点击、键盘聚焦、禁用态与无障碍名称正常。
- **AC-9 既有链路回归**：文字加附件、仅附件发送，图片预览、附件移除、历史消息展示以及普通发送行为继续正常。
- **AC-10 项目门禁**：受影响的自动化测试通过，`scripts/check` 全绿。
