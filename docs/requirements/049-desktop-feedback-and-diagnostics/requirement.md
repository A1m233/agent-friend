# 049 · 桌面反馈与本地诊断包导出

## 状态

CONFIRMED

修订：2026-09-05。初版已交付；本次确认新增“桌宠输入链离线证据”，其验收项单独列出，不继承初版的已完成状态。证据与局限见 [evidence-index.md](./evidence-index.md)。

## 背景

agent-friend 已经拥有统一文件日志、结构化会话事件流、设置中心和多个桌面入口，但用户遇到问题后仍需要自行寻找日志、描述环境并判断哪些会话与问题相关。排查方收到的信息经常不完整，也缺少问题发生时的应用版本、运行环境和上下文。

与此同时，会话、工具调用结果、模型凭据和记忆数据都可能包含敏感信息。不能为了方便排查就默认收集全部用户数据，也不能把“生成诊断包”隐式变成上传行为。

本需求提供统一的“反馈与诊断”能力：用户可以填写少量可选说明、按完整会话粒度选择相关会话，并在本机生成一个边界明确的 ZIP 诊断包。用户自行决定是否以及通过什么渠道分享该文件。

## 目标

完成后应达到：

- 用户能从桌宠 ActionBar、对话窗口和设置中心快速找到同一套反馈与诊断能力。
- 用户不填写任何表单字段、不选择任何会话，也能导出只包含基础诊断信息与有限日志的诊断包。
- 用户可以按完整会话粒度多选普通会话与已归档会话；从当前对话进入时，当前会话默认被选中。
- 只有用户主动选择的会话会进入诊断包，未选会话、完整记忆数据库和凭据不会进入。
- 诊断包只生成到本机，不被应用自动上传。
- 生成完成后，用户能直接打开压缩包所在目录；即使打开目录失败，文件和路径仍然可用。
- 设置窗口能被其他入口语义化定位到“帮助与反馈”，并为未来设置搜索复用同一套定位能力。

## 范围

### 包含

- 设置中心新增“帮助与反馈”分类，承载完整的反馈与诊断页面。
- 桌宠 ActionBar 新增直接的“反馈与诊断”按钮。
- 对话窗口右上角新增直接的“反馈问题”按钮；本期不先收进更多菜单。
- 三个入口汇聚到同一个设置页面，不各自维护独立表单或导出流程。
- 从对话窗口进入时默认选择当前打开且已持久化的会话；没有当前会话时不默认选择。
- 提供一个可选的问题描述输入，提示用户可写实际表现、期望表现和复现方式，但不拆成多个必填字段。
- 提供按完整会话粒度的多选器：
  - 普通会话和已归档会话均可选择；
  - 已归档会话有清晰标识；
  - 展示足够帮助辨认会话的信息，例如标题与最近活跃时间；
  - 用户可不选择任何会话。
- 在会话选择区域持续提示：选中的完整会话可能包含私人聊天、工具调用参数与结果，用户应只选择与问题相关的会话。
- 本地生成 ZIP 诊断包，包含：
  - 用户填写的问题描述（如有）；
  - 应用版本、构建与生成时间等应用信息；
  - 操作系统、架构、语言和时区等必要环境信息；
  - 不暴露凭据的运行配置摘要；
  - 可用于判断关键组件状态的健康信息；
  - 按固定、有大小上限的规则选取的近期日志；
  - 用户明确选择的完整会话事件流及必要会话元信息；
  - 一份说明实际收集内容、时间范围和收集失败项的清单。
- 对诊断内容执行凭据保护：即使内容来自用户选择的完整会话，也要过滤可明确识别的认证凭据。
- 生成成功后使用 Sonner 提示，并提供“打开所在目录”操作。
- 打开所在目录失败时，不把诊断包生成结果误报为失败；提示本地路径并支持复制。
- 设置中心提供统一的语义化定位能力：侧栏点击、ActionBar 入口和对话入口都通过同一定位边界进入目标分类；未来设置搜索可复用该能力。
- 为诊断包内容边界、会话选择、凭据过滤、大小限制、入口定位和导出结果补充自动化测试。

### 不包含

- 不自动上传诊断包，不建设上传 API、对象存储或 Diagnostic ID。
- 不建设反馈工单、状态跟踪、回复通知或运营后台。
- 不做“开始采集 → 用户复现 → 停止采集”的专项复现模式。
- 不做截图、录屏、桌面操作回放或 Session Replay。
- 不允许一键默认选择或导出全部会话。
- 不导出完整 memory 数据库、persona 资产、凭据文件、系统环境变量全集或原始设置文件。
- 不允许用户在应用内逐文件编辑 ZIP 内容；本期通过选择会话和明确的收集边界控制内容。
- 不实现设置搜索、设置项滚动定位或高亮效果；只建立可被未来搜索复用的设置分类定位边界。
- 不扩展为长期 DEBUG 或全量业务记录；允许按本需求新增有明确范围、频率、容量和隐私边界的桌宠输入诊断证据，不扩大其他日志生产方的内容采集。

## 行为要求

### 反馈入口与设置定位

- ActionBar 中提供独立按钮，点击后打开或聚焦设置窗口，并直接定位到“帮助与反馈”。
- 对话窗口右上角提供独立按钮，点击后打开或聚焦同一个页面，不要求用户先打开更多菜单。
- 设置侧栏底部提供“帮助与反馈”，并与通用、桌宠、语音、模型等功能设置形成清晰分组。
- 多个入口不得复制反馈表单或产生不同的诊断包规则。
- 设置窗口已打开时，再次从其他窗口进入应切换到目标分类，而不是只聚焦后停留在原分类。
- 无效或旧版本不认识的设置目标应安全降级到默认设置分类，不能使设置窗口空白。
- 设置定位以稳定的设置目标语义为边界，不依赖调用方操作设置页内部状态或 DOM；具体接口与文件结构在设计阶段确定。

### 表单与会话选择

- 问题描述为选填；空内容不阻止生成。
- 问题描述使用单一输入区域，不要求用户分别填写标题、实际表现、期望表现和复现步骤。
- 会话选择为选填；未选择会话时仍可生成诊断包。
- 从当前对话入口进入时，当前已持久化会话默认选中；用户可在生成前取消选择。
- 从 ActionBar 或设置侧栏进入时，不擅自选中会话。
- 会话选择器同时覆盖普通会话和已归档会话，并能让用户辨认归档状态。
- 未持久化的临时对话不应伪装成可导出的完整会话；页面应保持未选状态或明确说明其不可选。
- 选择完整会话表示包含该会话的完整事件范围，不按最近若干轮静默截断，也不省略工具调用事件；凭据过滤仍然生效。

### 数据最小化与隐私

- 未选择的会话不得进入诊断包，也不得只因当前处于某个会话就被后台隐式附加。
- 会话选择本身代表用户授权将该会话写入本地诊断包，不额外要求勾选形式化同意框；页面必须持续展示内容风险说明。
- 诊断包不得包含 API Key、Access Token、Refresh Token、Cookie、Authorization Header、IM Credential 等认证凭据。
- 配置内容采用允许字段边界，不得通过复制完整 settings、keyring、credential 文件或环境变量后再寄希望于事后脱敏。
- 日志和用户选择的会话仍需执行凭据兜底过滤；过滤不能改变未命中敏感内容时的事件顺序和排查语义。
- 设备用户名、绝对用户目录、IP 等可能识别用户的信息是否保留，应在设计阶段逐项给出必要性；无明确排查价值的字段默认不收集或匿名化。
- 完整 memory 数据库及其原文、全部 persona 资产和未选择会话始终排除。

### 日志与诊断内容

- 用户无需选择日志文件或日志时间范围。
- 应用按统一规则收集与本次排查相关的近期日志，并设置单文件、总大小或时间窗口上限，避免把整个长期日志目录打包。
- 当前日志目录中不存在某个预期日志时，仍应继续生成，并在收集清单中记录缺失或失败原因。
- 应用与系统信息应采用结构化、可稳定解析的格式，同时保留用户或排查方可阅读的内容说明。
- 健康信息只进行本地、低风险检查；不得为了生成诊断包调用真实 LLM、语音、搜索或其他可能计费的外部厂商 API。
- 诊断包必须能说明实际包含了哪些类别、选择了哪些会话、日志覆盖的大致范围以及哪些收集项失败。

### 本地导出结果

- 生成动作只写入用户本机；在生成前后均不得自动发起诊断包上传。
- ZIP 文件名应包含可辨认的产品名和生成时间，避免覆盖既有文件。
- 生成过程需要防止重复点击造成并发生成；完成、部分收集失败和整体生成失败应有不同结果。
- 非关键收集项失败时，尽可能生成包含其余信息的诊断包，并把失败项写进清单。
- ZIP 无法创建或写盘时，向用户展示可行动的失败信息，不显示成功 Toast。
- ZIP 生成成功后使用 Sonner 展示成功提示，主操作为“打开所在目录”。
- 打开目录失败时，文件仍视为生成成功；用户能看到并复制完整路径。

## 增量：桌宠输入链离线证据（2026-09-05）

### 背景与目标

桌宠曾出现 hover 不显示 ActionBar、点击与拖拽穿透的异常。已有现场观察确认了显示与光标换算使用不同缩放值，但没有确认引发不一致的原因。事后重启及开发环境对照未重现原触发，部分历史窗口事件已被轮转淘汰。不能要求用户保持故障现场、提前打开开发工具，或立即把设备交给排查方。

本次补足的是离线证据能力：产品默认在本地留下有界的关键事实，用户可以在故障恢复或重启后，通过原有入口导出保留范围内的证据。它不以修复原故障、自动判定根因或再次自然复现该故障为交付条件。

### 范围与行为

1. **无需预先准备。** 正常桌面运行默认启用轻量留证，不要求 DEBUG、dev、CDP、额外脚本或“开始采集→复现→停止”。基础关键状态历史不依赖系统先识别出异常，避免未知故障没有任何上下文。
2. **首批只覆盖桌宠输入链。** 能关联实际显示缩放与窗口几何、前端上报及其结果、原生实际使用的换算状态、命中/未命中理由、穿透切换请求与实际应用结果。正常未命中本身不能被误报为故障；无法取得的事实明确缺失，不用推断值代替。
3. **发生时身份可追溯。** 历史证据能区分不同进程和页面生命周期、不同异常及其先后关系，并保留可获取的发生时构建、WebView 与显示环境信息。导出时的当前状态单独标识，不覆盖或冒充发生时状态；无法精确绑定源码时明确身份缺口。
4. **有界且跨重启保留。** 在明确的保留期限和容量规则内，页面重载、应用/电脑重启、故障恢复及后续正常使用不能把已保留异常简单替换成当前正常快照。近期关键状态历史和可识别异常均有保留范围；多次异常可区分。过期、容量淘汰、截断与采集失败可见，不承诺无限期或无损保存。
5. **复用原诊断包。** 用户无需选择聊天会话或手选证据文件；现有反馈与诊断入口把可用历史证据纳入本地 ZIP。桌宠页面失联、卡住或未加载，但其他既有导出入口仍可用时，导出已落盘证据不要求恢复桌宠或重新复现；当前状态不可获取不阻止其余信息导出。
6. **覆盖范围可解释。** 排查方可区分“未采集”“不支持”“未覆盖该时间”“已截断/淘汰”“采集失败”“导出读取失败”和可用证据。生成 ZIP 成功不等于证据完整，当前正常也不等于历史异常不存在。旧版诊断包仍可读取，没有新证据能力不视为损坏。
7. **性能与隐私边界。** 只保留判定所需的状态变化、摘要与有限坐标样本，不持续记录 60 Hz 鼠标轨迹，不新增聊天正文、DOM 内容、其他应用标题、凭据、截图或录屏采集。长时间运行、频繁 hover/拖动、普通日志繁忙时仍受频率、容量和读取上限约束，采集/落盘失败不能阻塞输入或改变穿透行为。
8. **保持原授权边界。** 新证据仅在本机保存并随用户主动导出的诊断包分享，不新增上传、远端遥测或外部厂商请求。既有用户选择会话、附件和渲染截图的独立授权规则不变。

### 增量不包含

- 不修复当前 DPR/穿透问题，不因检测到疑似异常自动改缩放、重试操作、重启页面或应用。
- 不扩展为所有 UI 或所有业务行为的完整追踪，不建设键鼠记录、桌面回放、永久 DEBUG 或无限历史。
- 不新增反馈上传、工单、后台收包或云端分析服务。
- 不新增“整个应用已无法启动”时的独立救援导出工具；本次复用仍可使用的原有导出入口。
- 不把受控注入或离线 fixture 通过写成原故障已经自然复现或根因已确认。

### 增量验收标准

- [x] OFF-01：未打开任何调试开关或工具，桌面运行仍留下范围内的关键状态变化；即使未触发自动异常识别，也能导出保留范围内的基础历史。
- [x] OFF-02：已持久化的故障证据在页面重载、应用退出重启后仍可导出；可区分发生时与导出时的进程、版本和状态。突然中止造成的尾部缺口明确说明，不伪造完整性。电脑重启后的留存能力仍在产品范围内，但用户于2026-09-05明确豁免本轮电脑重启实测：未执行、不记为通过，不阻断本轮验收与合入。
- [x] OFF-03：故障恢复及随后正常启动/使用不覆盖仍在保留规则内的异常；多次异常可区分，过期和容量淘汰行为符合公开的证据覆盖说明。
- [x] OFF-04：使用确定性输入链 fixture，导出后可还原前端观察/上报、原生接收/应用及命中/穿透决定的对应关系；乱序、拒绝、丢失或缺少确认时准确保留不确定性，而不虚构完整顺序。
- [x] OFF-05：桌宠页面不可响应时，其他既有反馈入口仍可导出已落盘证据；不依赖现场 CDP，不为导出重新执行输入动作，不要求选择会话。
- [x] OFF-06：未采集、不支持、过期、截断、容量淘汰、写入/读取失败分别可辨；其他证据继续导出，新证据失败不造成整包不可用或假成功。
- [x] OFF-07：长时间运行及高频 hover/拖动的确定性压力验证满足设计中明确的频率、内存、磁盘和导出上限；慢盘、满盘、断连等情况不改变业务操作结果或造成可感知的交互阻塞。
- [x] OFF-08：隐私 fixture 证明新证据不包含持续鼠标轨迹、聊天、DOM/桌面内容、其他应用标题或凭据；不新增截图、自动上传、真实 LLM 或其他外部服务调用。
- [x] OFF-09：真实生产者生成的 ZIP 与机器契约、解析器和摘要一致；较旧诊断包仍可读，缺少新增证据与未知能力不会被静默误解释。
- [x] OFF-10：在真实桌面运行中完成一次“产生有界证据→应用重启→现有入口导出→离线解析”的端到端验证，并取得用户验收；该验证不依赖原偶发故障再次出现。电脑重启实测按OFF-02的用户豁免处理。

### 待方案明确

## 开放问题

- 近期日志采用“本次启动以来”、固定时间窗口、各文件尾部大小上限还是组合策略，在设计阶段结合当前三类日志轮转方式确定。
- 诊断包默认保存目录以及跨平台“打开所在目录”行为，在设计阶段结合现有 Tauri 能力确定。
- 设置定位目标是否只包含分类，还是同时预留设置项标识，在设计阶段以满足未来搜索但不过度设计为原则确定。
- 会话与日志的凭据过滤规则、误报处理和过滤后占位格式，需要在设计阶段结合现有事件 schema 与日志格式确定。
- 设备名、用户名、IP、绝对路径等环境字段的必要性需要逐项审查，不能整包复制系统信息。
