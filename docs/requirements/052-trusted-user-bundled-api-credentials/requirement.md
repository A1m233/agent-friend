# 052 · 可信用户内测包凭据预置

## 状态

CONFIRMED

## 背景

051 已经完成 Windows x64 完整运行时打包，安装版可以在没有 Python、uv、Node 或 Rust 的机器上启动。但现有打包流程会主动移除构建机上的 API 凭据，安装后的用户仍需手动在设置中录入 DeepSeek、Kimi、Tavily 和火山语音相关凭据，才能使用对应功能。

项目现阶段需要把安装包定向提供给少量、明确受信任的内测用户。这些用户不应被要求自行申请和配置一整套 provider 凭据；安装完成后应可直接使用文字对话、搜索和语音能力。

本需求明确接受一项限定条件下的风险：长期 API 凭据一旦到达用户设备，拥有该设备权限的用户就可能提取它们。“可信用户”是本期的信任边界，不代表凭据在技术上无法提取。

## 目标

- 默认打包仍生成不含任何用户 API 凭据的普通安装包。
- 仅在构建者显式选择可信内测分发时，生成预置项目当前 API 凭据的敏感安装包。
- 可信用户安装该包后，不需手动录入 provider 凭据，即可启动核心服务并使用文字对话、搜索和语音功能。
- 凭据明文不进入 Git、构建日志、诊断数据、非敏感产物清单或校验文件。
- 可信内测包始终被视为敏感产物，只能定向分发给已确认的可信用户。

## 范围

### 包含

- 为现有 Windows 安装包增加一个显式的“可信内测分发”构建能力。
- 默认、无额外选项的打包命令仍生成无凭据包，不因构建机已配置凭据而自动改变。
- 可信内测包覆盖当前凭据中心管理的完整凭据注册表：
  - DeepSeek。
  - Kimi。
  - Tavily。
  - 火山 RTC 与语音相关凭据。
- 构建前按现有运行时语义检查可信内测包所需凭据是否齐全；必需凭据缺失时明确失败，不产出功能不完整的“可信包”。仅服务于兼容鉴权方式的可选凭据允许未配置，例如旧版火山语音鉴权已可正常工作时，不强制要求新版 `VOLC_SPEECH_API_KEY`。
- 可信用户首次安装或覆盖升级后，对应凭据可被安装版运行时正常使用，无需用户手动录入。
- 用户仍可通过现有凭据管理界面覆盖或删除本机凭据；安装包不应在每次启动时强行覆盖用户后续操作。
- 凭据更新或失效后，本期通过重新生成并定向分发可信内测包处理。
- 保留现有凭据脱敏和诊断保护语义，对预置凭据同样生效。
- 为默认无凭据包、可信内测包、凭据缺失和覆盖升级补齐自动化测试与必要的安装态验证。

### 不包含

- 不改成默认生成含凭据安装包。
- 不把任何凭据明文提交到 Git、`.env.example`、测试 fixture 或需求 / 设计文档。
- 不包含 `VOICE_BRIDGE_PUBLIC_URL`、通话 token、room / call 状态等单次运行态数据。
- 不包含 QQ 或其他 IM 用户绑定凭据；这类凭据仍由各用户自行授权。
- 不建设账号体系、服务端代理、设备 allowlist、短期 token broker 或用量计费系统。
- 不为每个可信用户生成可独立撤销的凭据；本期用户共用构建者当前使用的凭据。
- 不承诺预置凭据对本机管理员、调试器或反向工程不可提取。
- 不建设远程凭据轮换或撤销能力；旧包在凭据失效后允许停止工作。
- 不扩展到 macOS、Linux、Windows ARM64 或 portable 包。

## 风险与信任边界

- 可信内测包本身是敏感文件；获得安装包的人应被视为可能获得其中凭据。
- 系统凭据库、加密包装或安装后删除临时文件只能减少意外泄露，不能将长期凭据变成不可提取。
- 本期信任边界依赖人工选择受信任接收者，并接受共享凭据可能带来的额度消耗和滥用风险。
- 如果安装包泄露或受信任用户范围变化，唯一保证有效的处置方式是在 provider 侧更换原凭据，然后重新打包和分发。

## 验收标准

- [ ] 不传入可信分发选项时，正式打包继续从子进程环境移除已知凭据，且产物不包含构建机凭据。
- [ ] 可信分发必须由构建者显式开启，其产物名称或同等元数据能与普通包清晰区分，避免误传。
- [ ] 可信分发构建在任一必需凭据缺失时 fail closed，错误仅列出缺失名称，不输出任何凭据值。
- [ ] 可选凭据未配置时仍可构建可信包；安装后对应功能必须通过当前已配置的兼容鉴权方式正常就绪。
- [ ] 可信用户在没有预先手动配置 provider 凭据的 Windows x64 环境中安装后，bridge 和 voice 运行时可正常就绪。
- [ ] 可信安装版能完成文字对话、Tavily 搜索和火山语音的真实调用；执行这些外部 API 验收前另行获得用户明确授权。
- [ ] 预置凭据不出现在 Git diff、构建日志、诊断压缩包、非敏感 inventory / release metadata 或 SHA-256 文件内容中。
- [ ] 可信包安装完成后，安装目录不保留可由普通文本搜索直接找到的凭据明文文件；本项不构成“凭据无法提取”的承诺。
- [ ] 用户在设置中覆盖或删除预置凭据后，应用重启不会自动恢复已被用户更改的预置值。
- [ ] 新版可信包覆盖升级时，可在不删除 sessions、memory、persona、settings 和其他用户数据的前提下补齐新凭据；如何处理用户已覆盖的凭据由设计阶段明确。
- [ ] 默认无凭据打包、可信打包、安装态导入、用户覆盖 / 删除保持和诊断脱敏有自动化测试或可重复的安装态 smoke 覆盖。
- [ ] 项目文档明确区分普通包与敏感的可信内测包，并说明泄露后需在 provider 侧更换凭据。

## 开放问题

- 凭据如何从构建机进入敏感产物、如何在首次安装时导入系统凭据库，由设计阶段在“不误入普通包”和“不在安装目录留明文”的约束下确定。
- 覆盖升级时，已有凭据、用户主动删除记录与新版预置值之间的优先级和迁移语义需在设计阶段确定。
- 可信包的命名、产物标识和误传防护方式需在设计阶段与现有 release 产物结构对齐。
