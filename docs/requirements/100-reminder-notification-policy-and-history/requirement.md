# 100 · Reminder 通知策略与统一会话历史

## 状态

CONFIRMED

## 1. 背景

Todo Reminder 当前在到期时根据桌面对话、IM 与桌宠的 presence 选择一个主要投递目的地，并让这个
出口选择同时影响提醒历史落在哪个会话。这样会把两个本应独立的问题耦合在一起：

- 这次到期提醒应持久化在哪个会话，作为后续恢复、搜索和投递的唯一事实；
- 除了会话历史之外，是否还应通过 QQ 或桌宠主动通知。

现有行为也因此出现了用户可见的不一致：

- 桌面对话路径会形成可见 Reminder 卡片和 Agent 增强回复；
- QQ 路径虽然保存了底层事件，但会从桌面对话历史与搜索投影中隐藏，稍后打开会话时看不到完整提醒轮；
- 桌宠只有临时气泡和 Todo occurrence，没有对应的会话历史；
- occurrence 只记录一组目的地结果，难以表达同一提醒向 QQ、桌宠分别投影后的状态。

本需求将“唯一会话历史”和“额外通知策略”拆开：每次 Reminder 到期时先确定一个正确会话，持久化
Reminder 卡片与 Agent 回复；随后再由持久化设置决定是否额外通知 QQ 与桌宠。

## 2. 目标

- 明确区分未来 Reminder 计划的创建与 Reminder occurrence 的实际到期。
- 每次到期时按固定策略确定唯一持久化会话，并让该次 occurrence 的历史归属在重试、重启后保持不变。
- 在正确会话中只持久化一份 Reminder 固定事实，并以它作为用户可见历史与通知投影的唯一事实源。
- 让 Reminder 卡片、对应的 Agent run 与 Agent 增强回复处于同一个正确会话和同一个提醒轮中。
- 提供持久化的“提醒发送方式”设置，只控制 QQ、桌宠的额外通知，不改变底层持久化方式。
- 分别追踪 QQ 与桌宠的投递结果，避免重复卡片、重复 Agent 生成、重复发送或跨会话污染。
- 不引入“判断是谁在使用哪个会话”的身份识别机制。

## 3. 核心概念与边界

### 3.1 创建 Reminder 是创建未来计划

- 创建 Reminder 表示保存一条将在未来触发的计划，不表示提醒已经发生，也不立即创建到期卡片或
  Agent 增强回复。
- 从某个会话创建 Reminder 时，保存该会话作为来源会话。来源会话只在到期时没有有效 IM 绑定可选时
  作为兜底，不预先锁定未来 occurrence 的持久化位置。
- Todo 与 Reminder 的计划、状态、修改、完成、取消和调度继续由统一 Todo 后端负责；它们不因来源
  会话或持久化会话而变成会话私有数据。
- 周期性 Reminder 的每次 occurrence 都在实际到期时独立选择持久化会话。上一轮的会话选择不锁定
  下一轮。

### 3.2 到期时确定唯一持久化会话

每次 occurrence 首次执行时，按以下顺序确定唯一持久化会话：

| 到期时状态 | 持久化会话 |
|---|---|
| 存在一个或多个指向现存会话的有效 IM 绑定 | 选择其中最新的 IM 绑定所对应的会话 |
| 候选 IM 会话有真实用户交互记录 | 以最近一次真实用户交互时间判断新旧 |
| 候选 IM 会话没有真实用户交互记录 | 以绑定最近创建或更新的时间作为新旧兜底 |
| 较新的绑定指向已不存在的会话 | 跳过该无效候选，继续选择下一个有效候选 |
| 没有有效 IM 绑定 | 使用创建 Reminder 时保存的来源会话 |
| 既没有有效 IM 绑定，来源会话也不存在 | 不写入任意其他会话，保留可诊断的失败状态 |

补充边界：

- IM 当前是否在线只影响能否发送 QQ 通知，不影响其绑定会话能否成为持久化会话。
- 某次 occurrence 一旦确定持久化会话，重试、重启、窗口切换、binding 更新和 presence 变化都不得
  将它迁移到别的会话。
- 该规则不区分会话由部署者还是实际接收提醒的人使用，也不推测人的身份。
- “最新 IM 绑定”只选出一个绑定及其会话，不向全部 IM 绑定或全部会话广播。

示例：Reminder 计划在会话 A 中创建；到期时存在绑定到会话 B、C 的 IM，且 C 更新。则这次
occurrence 的持久化会话为 C：Reminder 卡片与 Agent 回复都进入 C；A 只保留当初创建计划的对话，
B 不新增这次提醒内容。

### 3.3 唯一用户可见提醒事实

- Reminder 到期后，先在选定会话中持久化一份由 Todo、Reminder 与 occurrence 冻结事实形成的
  Reminder 记录。
- 该记录是会话卡片、QQ 固定提醒、桌宠气泡、历史恢复与搜索结果共同依赖的唯一用户可见事实。
- 同一 occurrence 无论是否额外通知 QQ 或桌宠，都只能在选定会话中形成一张逻辑 Reminder 卡片。
- 对话页不属于可由设置关闭的通知渠道。Reminder 一旦持久化，打开或恢复选定会话时始终应显示
  对应卡片与回复。
- 其他桌面对话、其他 IM 会话与其他 binding 不得出现这次 occurrence 的持久化卡片或 Agent 回复。
- Todo 后端继续是计划与领域状态的权威；选定会话中的记录是 occurrence 到期后用户可见内容与
  会话顺序的权威。两者职责不得互相替代。

### 3.4 Reminder 卡片与 Agent 回复属于同一个提醒轮

- 固定 Reminder 事实持久化后，系统像现有行为一样触发一次 Agent run 生成增强回复。
- Reminder 卡片、Agent run 与增强回复必须属于同一个选定会话，并按“卡片在前、回复在后”的顺序
  形成完整提醒轮。
- 同一 occurrence 只生成一轮 Agent 回复；QQ、桌宠投影不得各自启动额外生成。
- QQ 需要发送增强回复时，使用选定会话中同一轮已持久化的内容，不另外生成不同文本。
- 模型失败或回复为空不能撤销、隐藏或重复创建已经持久化的 Reminder 固定事实。
- 桌宠可以只展示固定提醒内容，不要求展示 Agent 增强回复；这不影响选定会话中的完整历史。

## 4. 提醒发送方式

### 4.1 设置只控制额外通知

设置中心提供持久化的“提醒发送方式”，默认值为“智能选择（推荐）”。无论选择哪种方式，第 3 节的
持久化会话选择、Reminder 卡片、Agent run 与增强回复行为都完全相同。

| 用户可见结果 | 智能选择（推荐） | 所有位置 |
|---|---|---|
| 选定会话中的 Reminder 卡片 | 始终持久化并可见 | 始终持久化并可见 |
| 同会话 Agent run 与增强回复 | 始终只执行并持久化一轮 | 始终只执行并持久化一轮 |
| QQ 通知 | 仅当现有智能 presence 策略判断应在 IM 提醒，且选定 binding 可发送时投递 | 选定 binding 可发送时始终投递 |
| 桌宠气泡 | 仅当现有智能 presence 策略判断应由桌宠提醒，且桌宠可用时展示 | 桌宠可用时始终展示 |
| 其他会话或其他 IM binding | 不写入、不发送 | 不写入、不发送 |

“所有位置”表示“唯一会话历史 + 选定 QQ binding + 桌宠”三个产品表面，不表示所有桌面对话、全部
QQ 联系人或全部 IM binding。

### 4.2 设置文案

设置项使用以下用户可见文案：

**提醒发送方式**

- **智能选择（推荐）**：根据你最近的使用情况，决定是否通过 QQ 或桌宠额外提醒。提醒始终会保存在
  对应会话中。
- **所有位置**：提醒保存在对应会话中，同时通过可用的 QQ 和桌宠通知。

文案不得宣称系统能够判断用户的物理位置或识别正在使用会话的人；当前能力只依据可验证的入口状态、
绑定关系与最近交互。

## 5. 持久历史与投递一致性

- 通过 QQ 额外通知的 Reminder，在稍后打开其选定会话时，必须恢复出与桌面当前打开该会话时相同的
  Reminder 卡片和 Agent 回复。
- 会话历史、全局会话搜索与诊断使用一致的 Reminder 可见性语义，不得出现底层事件存在、但用户在
  正确会话中永远无法恢复或搜索到的情况。
- QQ 与桌宠都只投影选定会话中的同一 occurrence 事实；重载、重连和重试不得增加重复卡片或重新生成
  Agent 回复。
- QQ 与桌宠分别记录待投递、成功、明确失败或结果不确定等状态。一个出口失败不得覆盖另一个出口的
  结果，也不得影响会话历史已经成功持久化的事实。
- 外部 IM 结果不确定时继续遵守避免重复发送的安全边界，但必须能与明确成功、明确失败及桌宠结果
  区分。
- 选定会话暂未在桌面打开、桌面正在查看其他会话或 IM 当前离线，都不能阻止 Reminder 卡片和 Agent
  回复进入选定会话。
- 所有额外通知出口都不可用时，会话历史仍正常形成；QQ、桌宠各自保留可诊断和可恢复的投递状态。

## 6. 兼容与异常边界

- 升级前已创建、尚未到期的 Reminder 在到期时使用相同的会话选择策略：优先最新有效 IM 绑定，
  没有时再使用能够明确恢复的来源会话。
- 无法恢复来源会话的旧 Reminder，如果到期时存在有效 IM 绑定，仍可使用该绑定会话；两者都不存在时
  不得静默写入当前桌面对话或最近活跃的任意会话。
- 某次 occurrence 已经选择持久化会话后，绑定被更新、解绑或重新绑定都不迁移该次历史；后续周期
  occurrence 重新按到期时状态选择。
- 选定会话归档但仍存在时继续保留事实归属；选定会话实际缺失时不得改写到其他会话，并保留可诊断
  状态。
- 任一额外通知失败都不得回滚 Todo、Reminder、occurrence 或已形成的会话历史。

## 7. 不包含

- 向所有桌面对话、所有会话、全部 QQ 联系人或全部 IM binding 广播。
- 区分部署者、使用者、家庭成员，或判断具体的人正在使用哪个会话。
- 为每个 Todo 建立会话所有权，或限制 Todo 的跨会话查询与管理。
- 每条 Reminder 单独配置发送方式、优先级、活跃阈值或自定义渠道组合。
- Windows 原生通知中心、操作系统级唤醒、跨设备推送保证、邮件或短信通知。
- 在本需求中增加 Reminder 卡片的完成、取消、编辑或稍后提醒操作。
- 依赖模型生成 Reminder 固定事实，或让各渠道分别生成不同的增强回复。

## 8. 验收条件

- [ ] 创建 Reminder 只保存未来计划与来源会话，不提前创建 occurrence 卡片或 Agent 回复。
- [ ] Reminder 在会话 A 创建；到期时 IM 分别绑定会话 B、C 且 C 更新，则这次 occurrence 的
  Reminder 卡片、Agent run 与增强回复只持久化在 C，A 与 B 不新增这次到期内容。
- [ ] 到期时没有有效 IM 绑定，则 occurrence 的完整提醒轮持久化在创建 Reminder 的来源会话。
- [ ] 选中的 IM 当前离线时，其绑定会话仍作为持久化会话；只有 QQ 发送结果受离线影响。
- [ ] 某次 occurrence 的持久化会话确定后，重试、重启、presence 变化和 binding 更新均不会将其迁移；
  周期 Reminder 的下一次 occurrence 会按新的到期时状态重新选择。
- [ ] 每次 occurrence 在选定会话中只形成一份可恢复的 Reminder 固定事实、一轮 Agent run 与一份
  增强回复，并按卡片在前、回复在后的顺序展示。
- [ ] 无论选择“智能选择”还是“所有位置”，选定会话中的 Reminder 卡片与 Agent 回复均始终持久化、
  可恢复并可被会话搜索找到。
- [ ] “智能选择”保持现有 presence 判断：根据结果决定是否额外通知选定 QQ binding 或桌宠，但不
  改变持久化会话和历史内容。
- [ ] “所有位置”在会话历史之外，向可发送的选定 QQ binding 投递并在桌宠可用时显示气泡；不会向
  其他会话或其他 binding 发送。
- [ ] QQ 使用与选定会话同一提醒轮的固定内容和 Agent 增强回复，不另行生成；桌宠只投影同一固定事实。
- [ ] QQ 与桌宠的成功、失败和不确定结果可以独立记录、查询和诊断；单个出口异常不影响另一个出口或
  已持久化的会话历史。
- [ ] 设置中心使用已确认的“提醒发送方式 / 智能选择（推荐） / 所有位置”文案，升级后默认智能选择，
  并在应用重启后保留用户选择。
- [ ] 没有有效 IM 绑定且来源会话缺失时，不写入任意当前或最近活跃会话；Todo 与调度事实保持完整，
  并提供可诊断状态。
- [ ] 重启恢复、重连、明确失败降级和 IM 结果不确定不会造成重复卡片、重复 Agent 回复或重复外部发送。
- [ ] 自动化测试覆盖到期会话选择、每次 occurrence 选择冻结、来源会话兜底、设置持久化、智能通知、
  所有位置通知、QQ 历史恢复、同会话提醒轮、逐出口结果和旧数据兼容；默认测试不调用真实 LLM 或
  外部付费服务。
- [ ] 项目统一检查脚本全部通过。
