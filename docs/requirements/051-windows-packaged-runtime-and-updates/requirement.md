# 051 · Windows 完整运行时打包与可升级安装

## 状态

CONFIRMED

## 背景

agent-friend 当前已经有桌面端构建入口，但产物仍依赖源码仓库和本机开发环境启动 Python 运行时服务，不能作为一个独立产品直接交给其他 Windows 用户使用。

第一批使用者是项目方信任的用户。现阶段的优先级是敏捷交付一个完整、可安装、可运行的 Windows 版本，让用户不需要理解项目结构、不需要安装开发依赖，也不需要执行命令行操作。项目当前没有更新服务器，因此第一版不建设应用内自动更新或发布源，而是通过人工发送新版安装程序完成后续升级。

## 目标

- 面向 Windows x64 提供可直接交付的正式安装程序。
- 用户设备无需预装 Python、uv、Node、pnpm、Rust 或项目源码，即可安装和启动 agent-friend。
- 安装包包含当前产品正常运行所需的完整运行时能力、依赖和资源，不因打包遗漏导致源码态可用而安装态不可用。
- 桌面端启动后自动启动并管理随包交付的后端服务，在后端就绪后进入正常使用状态。
- 用户拿到更高版本的安装程序后，可以直接覆盖升级现有安装，并保留已有用户数据、设置和系统凭据。
- 用户可以在设置中心决定是否在登录 Windows 后自动启动 agent-friend；启用后只呈现桌宠，不主动弹出其他功能窗口。
- 为未来接入应用内更新保留稳定边界，但不让尚不存在的服务器和发布基础设施阻塞本期交付。

## 范围

### 包含

#### Windows 安装交付

- 只交付 Windows x64 安装程序。
- 安装过程不要求用户手动安装语言运行时、包管理器、编译工具或项目依赖。
- 安装程序能够处理桌面应用运行所需的 Windows 系统组件；若需要联网获取系统组件，应由安装流程自动完成并给出明确状态。
- 安装完成后，用户通过正常的桌面应用入口启动 agent-friend，不需要进入源码目录或运行脚本。
- 打包产物具有明确的产品版本和可供人工核验的 SHA-256 校验值。
- Windows Authenticode 代码签名不作为首个可信用户版本的交付阻塞项；若本期已有可用证书，则应使用。无证书时需明确告知可信用户可能出现 SmartScreen 提示。

#### 完整产品运行闭包

安装包必须包含当前产品正常运行所需的全部生产运行时组成，而不是只包含桌面壳或两个服务入口。至少覆盖：

- Tauri 桌面壳、全部正式窗口和前端静态资源。
- agent 对话引擎，包括会话、persona、system prompt、工具调用、上下文管理和运行时调度能力。
- memory 能力，包括记忆写入、抽取、检索、历史召回，以及当前生产路径依赖的原生库、模型和 tokenizer 等资产。
- 当前生产使用的 LLM provider 与运行时配置能力。
- agent bridge 及其 AG-UI、OpenAI 兼容接口、push、session/persona/memory 管理接口和 IM/QQ 通道能力。
- voice bridge 及当前语音输入、语音通话和相关控制能力。
- 完整语音通话所需的 Windows cloudflared 运行时，以及在用户明确同意公网穿透后建立临时公网入口的能力。
- 系统 keyring、设置、用户数据路径、日志和诊断导出能力。
- 当前内置的 Live2D、Spine 等头像模型及其运行资源。
- 上述能力在 Windows x64 上运行所需的 Python 解释器、第三方 Python 包、原生动态库和其他不可缺少的运行依赖。

“全部打包”指完整的生产运行闭包，不包含仅供开发和评测使用的 `agent_eval`、`memory_eval`、benchmark、实验目录、测试 fixture、开发脚本或源码仓库本身。

#### 启动与运行状态

- 桌面端是随包后端服务的唯一生命周期所有者，用户不需要单独启动 agent bridge 或 voice bridge。
- 应用启动后自动拉起所需后端，并在界面中区分“正在初始化”“已就绪”和“启动失败”。
- 后端初始化可能需要一定时间；未就绪前不能让用户误以为请求已经可以正常处理。
- 应用正常退出时，应妥善停止由本次应用启动的后端进程，不遗留持续占用端口的孤儿进程。
- 后端异常退出时，沿用现有运行时服务托管能力给出准确状态和可恢复路径。
- 安装运行态不得依赖 `AGENT_FRIEND_REPO_ROOT`、仓库 `.env`、源码目录或系统中的 `uv` 命令。
- cloudflared 不在应用启动时静默运行；只有用户已经明确同意公网穿透并实际发起语音通话时，才建立本次应用运行期的临时公网入口。
- 临时公网 URL 只进入本次 voice bridge 运行态，不写入设置、用户数据、系统 keyring 或日志中的敏感上下文。
- 应用退出时应同时停止由应用启动的 cloudflared；穿透失败只影响完整语音通话，不能阻断文字对话和本地语音输入。

#### 手动覆盖升级

- 第一版通过人工方式向可信用户发送新版安装程序。
- 已安装用户可以直接运行更高版本安装程序完成覆盖升级，不需要先卸载旧版本。
- 覆盖升级不能创建两个互相独立的 agent-friend 安装实例。
- 桌面端、后端运行时、Python 依赖、原生依赖和内置资源作为同一个产品版本整体升级，不能留下前后端版本错配。
- 升级必须保留用户已有的 sessions、memory、personas、IM 数据、头像选择等用户资产。
- 升级必须保留桌面设置和系统 keyring 中已配置的凭据。
- 升级失败时应尽量保持旧版本仍可运行；至少不能主动删除用户数据或系统凭据，并应提供可行动的失败提示。
- 产品 identifier、安装身份、版本号和用户数据路径保持稳定，使未来版本能够识别并升级已有安装。

#### Windows 登录后自动启动

- 设置中心“通用”提供“登录 Windows 后自动启动 agent-friend”开关，默认关闭，由用户主动启用。
- 开关展示 Windows 当前真实启动项状态；用户通过 Windows 或其他工具修改启动项后，再次打开设置中心应反映实际状态。
- 启用后，用户下次登录 Windows 时启动当前已安装的 agent-friend，显示桌宠并正常拉起随包后端服务，但不主动弹出聊天窗、设置窗或其他功能窗口。
- 关闭后移除 agent-friend 对应的当前用户启动项；启用或关闭失败时，界面恢复实际状态并提供明确提示。
- 覆盖升级后，既有启动选择继续作用于同一个产品安装实例，不得指向已被替换的旧版本或产生重复启动项。
- 卸载后不得遗留指向已删除程序的失效启动项。
- 普通源码开发运行态不得默认把调试目录中的 executable 注册为 Windows 启动项，避免 worktree、分支或构建产物变化后留下无效入口。

#### 未来更新扩展边界

- 打包与发布流程应有稳定的版本输入和产物结构，后续接入应用内更新时不需要重做产品运行时打包。
- sidecar 与桌面端保持统一版本和统一发布单元，未来不能演变成互相独立、容易错配的更新链路。
- 后续可以在现有安装和版本边界上增加更新检查、下载、签名校验和重启安装能力。
- 本期不因为未来可能建设服务器而预先实现 updater plugin、更新 endpoint 或发布服务。

### 不包含

- macOS、Linux、Windows ARM64 或其他平台的安装包。
- portable 单文件免安装版本。
- 应用内自动或手动检查更新、后台下载更新、静默更新、强制更新。
- 更新服务器、发布源、对象存储、GitHub Releases 自动发布或灰度发布通道。
- 自动回滚、多版本共存和多更新通道。
- 项目方自建的语音回调服务器、Cloudflare Named Tunnel、固定域名或生产级 tunnel SLA。
- 强制取得 Windows Authenticode 证书；没有证书时允许面向已知可信用户进行首版交付。
- 把项目方的 DeepSeek、Kimi、Tavily、火山等长期 API 凭据写入安装包、默认配置或用户系统 keyring。
- 解决“可信用户无需配置 API 凭据即可直接使用”的授权与费用承担问题；该能力作为独立需求处理。
- 把 eval、benchmark、实验、测试和开发工具随生产安装包交付。
- 改变现有用户数据、设置、凭据和日志的系统标准路径约定。
- 把 agent-friend 实现为登录前运行的 Windows Service、计划任务或系统级后台服务。

## 验收标准

- [x] 能从项目标准脚本入口生成带明确版本号的 Windows x64 安装程序和 SHA-256 校验值。
- [ ] 在一台没有项目源码、Python、uv、Node、pnpm 和 Rust 的干净 Windows x64 环境中，可以完成安装并启动 agent-friend。（用户确认作为非阻塞后续验证项，不阻塞可信用户 beta 收尾。）
- [x] 安装后启动桌面端会自动启动所需后端；用户无需运行额外程序或命令。
- [x] 桌面端能够准确展示后端初始化、就绪和失败状态，不在后端未就绪时伪装成可用。
- [x] 安装运行态不读取源码仓库 `.env`，不依赖 `AGENT_FRIEND_REPO_ROOT` 或系统 `uv`。
- [x] 使用受控测试配置完成文字对话，证明 agent、provider、session、persona、prompt 和 tool 主链路已随包工作。
- [x] 在安装运行态完成记忆写入、应用重启后的记忆读取，以及当前生产检索模式的查询，证明 memory 代码、原生依赖和模型资产没有遗漏。
- [x] 在不触发真实外部 API 的测试条件下，证明 voice bridge、IM/QQ 装配和对应桌面入口没有因打包缺失模块或资源而启动失败。
- [x] 安装包包含经过版本与 SHA-256 校验的 Windows cloudflared，用户无需另行安装。
- [x] 未经用户明确同意公网穿透、或用户没有发起语音通话时，应用不会启动 cloudflared。
- [x] 用户同意并发起语音通话时，应用能够建立临时公网入口、把动态 URL 只注入本次 voice bridge，并在失败时给出可行动提示。
- [x] cloudflared 在应用退出时被回收；临时 URL 不被持久化。tunnel 不可用时，文字对话和本地语音输入仍可使用。
- [x] 内置 Live2D/Spine 头像资源在安装运行态可被发现和加载。
- [x] 日志、设置、diagnostics、sessions、memory、personas 等内容写入各自的系统标准目录，不写入安装目录。
- [x] 应用退出后，由应用启动的后端进程均被回收；再次启动不会因遗留进程或端口占用失败。
- [x] 在已有旧版本和测试用户数据的环境中运行更高版本安装程序，可以覆盖升级而不先卸载。
- [x] 覆盖升级后只保留一个产品安装实例，桌面端与后端均为新版本，原有 sessions、memory、personas、设置和系统 keyring 凭据仍然可用。
- [x] 安装或升级失败路径不会删除用户数据或系统凭据，并提供明确的失败信息。
- [x] 设置中心“通用”能够读取 Windows 当前真实启动项状态，并允许用户启用或关闭登录后自动启动；默认状态为关闭。
- [x] 启用后重新登录 Windows，agent-friend 自动启动、桌宠可见、随包后端正常进入就绪状态，聊天窗、设置窗和其他功能窗口不会主动弹出。
- [x] 关闭后重新登录 Windows，agent-friend 不会自动启动；通过系统侧修改启动项后，设置页能够反映实际状态。
- [x] 启动项启停失败时开关回到实际状态并显示可行动提示，不出现设置页与 Windows 状态长期不一致。
- [x] 覆盖升级保留用户的开机自启选择且不产生重复启动项；卸载后不遗留失效启动项。
- [x] 普通源码开发运行态不会默认注册调试 executable；真实启动项验收使用正式安装版完成。
- [x] 生产安装包不包含项目源码、开发脚本、eval、benchmark、实验目录、测试 fixture 或项目方长期 API secret。
- [x] 项目全量自动化门禁通过，并完成一次真实 Windows 安装态 smoke 验收。

## 关键信息

- 前序能力：
  - `docs/requirements/032-runtime-env-credential-config/`
  - `docs/requirements/036-desktop-runtime-config-management/`
  - `docs/requirements/037-avatar-model-assets-and-catalog/`
  - `docs/requirements/047-desktop-runtime-service-supervision/`
- 047 已完成源码开发态下的 Tauri 服务托管，但明确把 packaged sidecar 交付留给后续独立需求；051 承接该边界。
- memory 是 agent bridge 运行闭包中的产品能力，不是第三个需要用户单独启动的服务进程，但其代码、原生依赖和模型资产必须被显式纳入打包与验收。
- 完整语音通话还依赖 cloudflared。第一版允许把 Cloudflare Quick Tunnel 用于可信用户 beta，但必须明确它是外部临时服务、主要面向测试使用且没有生产 SLA；未来稳定公网入口不属于 051。
- 本需求的“更新”仅指人工获得新版安装程序后的覆盖升级，不代表应用具备发现或下载新版本的能力。
- 本需求中的“开机自启”指当前用户登录 Windows 后启动已安装应用，不是登录前运行的系统服务。
- 运行时 API 凭据共享将另立需求；051 不以嵌入长期 secret 的方式实现开箱即用。
