## 现状与责任边界

- `SummarizingContextManager` 在摘要异常、空摘要、结果超预算、熔断等分支调用 FIFO。FIFO 保持完整 user turn，但可能裁掉承接短输入所必需的上一轮。预算合法不代表任务连续。
- `Conversation._assemble_stream` 接受 build 后暂存 compaction、tool context edit 与模型消息；后续 rollout 支持 replacement history。必须在候选被接受前阻断破坏性降级，不能先提交再修补。
- `ContextCompactionUnavailableError` 已有 Bridge 的稳定可恢复错误映射；复用该通道和需求 132 的继续语义，不新增任务调度系统。
- `SessionQuerySnapshot.active_events` 是只读有效业务历史，排除已撤销分支和内部 rollout；查询缓存与文件新鲜度由 SessionStore 负责。
- `recall_past_chats` 只回答对话文字；`recover_tool_result` 按已知引用恢复结果或图像。缺少从当前会话发现原调用并读取参数的入口。

## 方案设计

### 1. 压缩提交边界

正常路径仍为：有效旧摘要折叠 → 可恢复的工具结果投影 → 预算检查 → 必要时生成新摘要 → 二次预算检查 → 候选交给既有提交链路。

摘要失败不允许通过删除完整历史轮次来继续主模型采样。区分两类变化：

- 已持久保留原结果、保留引用和事务身份的有界工具结果投影，继续沿用既有契约。
- 删除尚未由有效摘要覆盖的 user/assistant/tool 轮次，不作为摘要失败后的可接受候选。

所有 fallback 分支必须经过统一判定，不能仅处理临时网络异常而遗漏空摘要、unsupported 参数、熔断、summary result over budget 等分支。有界摘要输入缩减只作用于临时候选，不直接替换会话历史。

必要压缩未完成时抛出稳定的上下文不可继续错误，保留原业务事件、最后已提交 rollout、已接收用户输入及已完成工具结果；不产生新成功 compaction，不提交裁剪后的 replacement。保留失败原因与尝试次数供诊断，不把服务故障误报成用户输入过大。

固定系统输入本身超预算、当前不可拆输入超预算继续使用各自错误类型；取消继续传播，不转成摘要失败。配置不兼容要给出可行动原因，不承诺原样重试可恢复。

熔断只抑制当前运行内无效重复请求。后续明确继续/重试或模型配置变化允许重新评估，不能永久跳过摘要并持续报错；不得在多层重试中增加隐藏预算。

### 2. 暂停、继续与完成状态

执行前或工具续轮中的必要压缩失败，通过现有 Runtime/Bridge 错误链路结束本次尝试，保留可恢复状态。不会再请求主模型编造结束语，也不会回放已完成工具。

后续用户继续时，先从既有已提交历史组装与重新压缩，成功后才恢复模型执行与工具能力。模型尚不能取得合法上下文时，不通过一次额外模型调用决定“裁剪得是否安全”。

用户主动停止不触发自动续跑；结果未知的工具继续遵守既有对账语义。仅重新打开会话不会执行恢复后的业务动作。

本期不新增完成后压缩任务。已有完成结果与后续运行尝试分开：后来压缩失败不得回写或撤销先前完成终态；如果现有调用路径包含收尾整理，只处理整理本身的失败。

### 3. 摘要中的任务承接

调整现有内部摘要模板的“当前话题与未决事项”和“最近上下文”，明确保留当前目标、用户最新修正、已验证结果、剩余步骤、阻塞与必要证据引用。区分计划、尝试、成功、失败和未知，旧话题只作背景，不能覆盖最近目标。

摘要不保存可重新使用的权限凭据，不把旧 Skill 指令或历史授权提升为当前规则；工具参数不要求全部塞进摘要，可保留原调用引用后按需恢复。

仍服务陪伴与执行混合会话，不把普通聊天硬改为任务清单。复用内部摘要入口，不载入整套人格、不新增并行摘要状态库。模板版本随契约变化递增；不得谎称旧摘要包含新字段。

### 4. 原调用发现与读取

新增只读工具 `inspect_tool_calls`，只查询当前会话有效业务事件。宿主注入 session identity，模型不能传 session ID、文件路径或目录授权。目录为 `tools/builtin/tool_call_history/`，查询、配对与渲染分文件。

工具提供两个互斥模式：

| 模式 | 输入 | 返回 |
|---|---|---|
| `search` | 可选 `tool_name`、文字 `query`、分页 `cursor`；`limit` 默认 10、最大 20 | 最近优先的调用索引：`call_ref`、工具名、时间、参数短预览、已记录执行状态、`result_ref`、覆盖与下一页信息 |
| `read` | 搜索返回的 `call_ref`；`offset` 默认 0，`max_chars` 默认 6000、范围 500–12000 | 原请求参数的确定性 JSON 文本片段、是否完整、总长度、下一偏移、匹配结果引用和状态依据 |

`call_ref` 绑定原 `tool_call_request` 事件 UUID，仅在当前会话的有效事件集合解析，不接受 tool result UUID、scope 或 process ID。结果配对优先使用持久化事件级关联，再按现有同 run 调用关联兼容旧记录；多义时返回未知/关联冲突，禁止猜测。

参数长于预算时按片段读取并明确 `arguments_complete=false`；不输出看似可直接执行的残缺参数对象。完整读回也只是历史数据，重新执行必须按当前 schema、Skill 与权限事实重新校验。

执行状态严格来自原结果、checkpoint 或可信终态。没有结果不等于仍运行或尚未执行；使用 `unknown`。不从通用退出码推断业务成功，保留工具自己的语义结果与来源。

搜索对参数与结果文字作字面匹配，索引只回显有界摘要；默认不回传大结果。查原结果继续调用 `recover_tool_result(result_ref=...)`，图像恢复仍由其负责。`recall_past_chats` 不扩展成工具记录搜索，避免职责混淆。

查询复用 `query_session` 和取消检查，不调用完整 rollout loader、不直接扫描任意文件、不新增数据库。每页最多检查 2000 个候选调用；达到扫描或输出预算返回 coverage 与 cursor，不声称完整无命中。游标带查询条件和上界锚点，普通追加不让后续页混入新记录；分支重写、历史不可用或锚点失效返回明确错误，不能静默跳页。

恢复工具本身的调用默认不进入搜索候选，防止递归找回自己的输出。原始工具正文视为不可信历史数据，不作为指令注入；隐藏宿主参数及既有凭据脱敏契约继续生效。

### 5. 上下文装配和工具接入

在工具 factory 注册只读工具，通过现有 namespace/catalog 暴露；Conversation 注入当前 session 与取消控制，不让模型搬运宿主身份。description 分别说明发现调用、读取参数及读取结果的选择条件。

参数 schema 使用严格互斥分支和 `additionalProperties=false`，provider 投影沿用现有协议；不宣称 provider 支持未验证的 strict 模式。

更新 prompt consumer 清单与必要跨工具行为说明；字段手册只放工具 schema/description。已有历史引用和已提交事件兼容，不强制迁移老会话。

## 影响与风险

- 相比历史 FIFO 策略，必要摘要不可用时会更早暂停；这是保全任务上下文的行为改变，不能继续宣称所有摘要失败均可自动降级运行。
- 历史已被旧版本裁剪的会话不能靠新规则自动恢复完整 model transcript；有合法上下文时可恢复有效业务调用证据，不能伪称 exact continuation。
- 摘要内容质量仍受模型影响。宿主测试验证历史与执行边界，不能证明模型一定理解恢复证据。
- 只读查询缓存可能冷启动，保留取消与覆盖信息；不以截断搜索伪装完整查询。
- 权限、审批与执行所有权留在既有 owner。检索结果不携带新 capability，不触发游戏或其它外部副作用。
- 不新增运行依赖。实现时按实际导入、资源及 frozen capability 覆盖重新分类打包影响；新增能力若缺 frozen 高风险路径覆盖，按项目规则执行 runtime-only 验证，不自动生成安装包。

## 验证计划

1. fake 摘要临时错误、不可兼容参数、空结果、超预算及取消，覆盖全部失败入口；断言不提交有损 replacement、不采样主模型、不丢输入或原工具结果。
2. 明确重试及重启后恢复成功，断言旧动作不被宿主重放、用户输入仅追加一次；正常压缩与可恢复工具结果清理继续有效。
3. 旧话题 + 最近任务 + “继续”夹具检查模型可见输入与恢复边界；任务已完成后的失败不改完成状态。
4. 调用 search→read→recover result 契约测试，覆盖大参数、大结果、分页、空匹配、扫描上限、取消、缺失结果、多义关联、重写分支、跨会话引用和历史删除。
5. 过期 scope/Skill/审批恢复后仍被宿主拒绝；历史正文含指令不改变权限。核对最终 provider 工具定义与实际校验一致。
6. 按 agent_eval 治理设计真实事故及未参与实现的相邻行为场景；执行前读取对应规则/skill，真实模型验证授权单独核对，不运行游戏。
7. 通过 `scripts/check/run.ps1 --stage backend` 的受影响检查及最终完整 `scripts/check/run.ps1`。具体专项参数按标准 runner 能力选取，不绕过脚本约定；未运行项如实记录。
