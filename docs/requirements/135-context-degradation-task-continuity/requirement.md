# 135 · 上下文降级后的任务连续性与恢复

## 状态

CONFIRMED

确认日期：2026-09-19。

## 背景

两个真实长会话在摘要失败后分别裁掉 198 和 301 条模型历史消息。前者无法找回原成功工具调用，后者把“继续”接到无关旧话题。原始事件仍存在，但当前模型输入与可用恢复能力不足以承接原任务。

现有上下文预算保护、持久化恢复和任务中断恢复各有职责；本需求补齐它们之间的任务连续性，不把摘要服务故障直接归为模型能力，也不把请求满足窗口预算当作任务能够继续的充分条件。证据与局限见 [evidence-index.md](./evidence-index.md)。

## 目标

- 压缩失败不破坏可恢复的任务历史，不以缺失关键承接信息的历史静默继续原任务。
- 用户重试或说“继续”时，能够承接最近目标、已验证结果和剩余工作，而不是无关旧任务。
- 必要时找回当前会话的原工具调用与结果证据，减少用户手工重填参数。
- 区分执行前、执行中和完成后的整理失败，准确表达当前状态。

## 范围

### 包含

1. 压缩失败、历史裁剪与任务续接之间的行为边界；失败不覆盖已有可恢复历史，也不丢弃已经接收的用户输入。
2. 执行前或执行中缺少必要任务上下文时，先走有界恢复；无法恢复时明确暂停并说明缺口，不靠旧记忆猜测目标，不无限重试。
3. 已完成任务的后续整理失败不撤销已确认结果、不将已完成动作改判为未执行或失败。
4. 当前会话的历史工具调用支持有界发现与精确读取，能够取得必要参数、结果、执行状态和来源。大结果支持分页或引用，缺失和截断必须明确。
5. 恢复遵守当前有效会话分支与既有隐私边界；不能把已撤销分支、其他会话或硬删除内容作为当前可用执行事实。
6. 历史调用和授权事实不等于当前有效权限；Skill 激活、scope、审批及运行状态继续按当前宿主事实校验。
7. 区分已完成、未执行、仍在执行和执行状态未知；恢复不得由宿主自动重放业务副作用，未知状态先核实。
8. 共享引擎行为覆盖桌面、IM、语音等既有入口；保留持久化、恢复和可诊断性，明确上下文缺失及暂停原因。

### 不包含

- 通用工作流引擎、新的任务状态数据库或全量长期记忆重构。
- MAA 专用提示词、业务执行器、OCR 阈值和游戏操作修复。
- 通用参数校验错误提示优化、诊断包采集完整性及 Windows 文件共享冲突修复。
- 全局放宽权限、恢复过期授权、自动切换模型或无限重试。
- 任意模型在所有场景下绝不串话的保证，或外部业务副作用的 exactly-once 承诺。

## 验收条件

- [ ] **AC-01 失败历史保全**：模拟摘要临时失败及重试耗尽，原可恢复历史与已接收输入保留；失败候选不被当作成功压缩结果提交，重试不重复追加用户输入。
- [ ] **AC-02 继续原任务**：包含旧话题、最近任务及短输入“继续”的回归场景中，缺失关键历史时先恢复或明确暂停，不静默进入无关旧任务。
- [ ] **AC-03 阶段边界**：分别覆盖执行前、工具续轮中及已完成后的压缩失败；前两者不在缺失必要信息时继续业务，后者不撤销完成结果。
- [ ] **AC-04 原调用恢复**：原成功调用离开当前模型窗口后，模型可用的入口能够发现并读取其参数、状态和结果引用；不要求用户提供原始内部 ID 或重新抄写调用。
- [ ] **AC-05 有界读取**：大结果分页、截断、无命中、记录缺失及引用失效有明确语义；检索不会无界注入历史，读取失败不会伪装为证据不存在。
- [ ] **AC-06 权限与来源**：恢复历史不会使过期 scope、旧审批或旧 Skill 激活重新有效；不能越过当前会话或有效分支边界，历史内容不能授予新权限。
- [ ] **AC-07 防重放与未知状态**：已完成、未开始、仍运行及状态未知均有验证；恢复操作无业务副作用，不自动重放原调用，也不把未知当作未执行。
- [ ] **AC-08 重新加载与入口一致性**：暂停后重新加载会话仍可恢复同一任务证据；共享入口不会重复生成动作或矛盾终态，已有取消语义保持不变。
- [ ] **AC-09 证据与验证**：两个事故用脱敏场景覆盖，并加入无关旧话题、权限过期和大结果等相邻场景；确定性测试验证宿主机制，真实模型行为验证单独记录授权与局限，不以 fake 通过冒充行为验证。
- [ ] **AC-10 项目门禁**：受影响测试及 `scripts/check` 全绿；用户确认验收完成。未运行的真实模型或多入口验证如实保留缺口。
