# 本地图像读取与多模态工具结果

## 状态
CONFIRMED

## 背景

当前产品已支持用户图片附件与模型路由能力声明，但 Agent 的工具结果仍以文本为主。Agent 在任务中遇到本地图片时，缺少把图片交给当前模型直接观察的工具。不同模型是否具备视觉能力、不同协议是否支持图像工具结果，需要分别确认，不能仅凭附件输入可用就声明工具看图可用。

## 目标

- Agent 能主动读取用户指定或任务中发现的本地图片，并基于真实图像继续推理。
- 相同工具面跨已验证的模型路由工作；不支持时给出明确、可行动的原因。
- 图片读取、内容表达、会话历史与 provider 协议职责解耦，新增 provider 适配不要求修改图片工具核心逻辑。
- 看图能力在历史恢复、模型切换和上下文管理中保持来源与状态可信。

## 范围

### 包含

- 本地图片读取工具，沿用现有文件权限与工具执行治理。
- 多模态工具结果的表达、模型输入投递及必要的持久化与历史投影支持。
- 区分模型视觉能力与协议图像工具结果支持，形成明确的路由支持矩阵。
- 非图像、损坏图片、大小限制、权限拒绝、资产失效与能力不支持的错误行为。
- 历史恢复、切换模型、上下文压缩后的图像可用性及降级状态表达。
- 不同协议适配的确定性验证，以及旧文本工具、用户附件的兼容性验证。

### 不包含

- 自动调用其他视觉模型代读、OCR 服务或跨模型代理推理。
- 图片生成、编辑、桌面截图与远程 URL 图片下载工具。
- 对未经验证的全部模型或兼容 API 承诺支持。
- 为未来音视频或任意二进制内容预建完整插件框架。

## 关键信息

- 沿用 [项目技术栈决策](../../decisions/0002-incubation-tech-stack/README.md)。
- 本需求衔接既有用户附件、文件访问治理、工具结果保留、会话恢复及模型路由能力；具体接口和模块落位在 design.md 确认。
- 已确认：首期按已验证路由交付。支持用户图片但不支持原生图像工具结果的路由，须先核实投递方式，再决定支持或明确拒绝。
- 真实模型验证遵守逐次调用授权；确定性测试不能替代真实视觉效果结论。

## 验收条件

- [x] AC-1：支持的路由上，Agent 可以调用本地图像读取工具取得真实图像输入，并继续回答图像相关问题；工具本身不调用其他模型。
- [x] AC-2：工具沿用既有文件权限；越权、无效路径、非图像、损坏或超限图片被明确拒绝，失败不被呈现为成功看图。
- [x] AC-3：支持矩阵区分视觉能力和图像工具结果投递能力；不同协议适配有确定性契约证据，不支持的路由有可行动错误。
- [x] AC-4：工具结果中的图片保持工具来源和调用关联，不被误认作用户新指令；图片资产不依赖原文件一直存在才能恢复已保存结果。
- [x] AC-5：恢复会话、切换模型与上下文压缩后，图像保留或降级符合已确认策略；不能读取时不声称仍看得到原图，不发送无效图像请求。
- [x] AC-6：图片数据不会作为大段 Base64 文本进入普通模型文本、日志或展示；图像资源使用受控限制，不绕过现有上下文治理。
- [x] AC-7：既有文本工具、用户附件和旧会话保持兼容；工具核心不依赖厂商名称或厂商 wire schema，新增适配通过对应边界接入。
- [x] AC-8：受影响自动化验证与项目检查通过；真实视觉观察及冻结 runtime 验证按实际影响执行并记录，未执行项明确标注。
