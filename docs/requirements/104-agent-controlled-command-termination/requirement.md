# 104 · Agent 可控的受治理命令终止

## 状态

CONFIRMED

## 背景

需求 085 已为 agent-friend 建立受治理的通用本地命令运行时：普通命令可以保持到终态，交互式命令可以返回当前 run 内有效的进程句柄并继续接收输入；用户也可以从桌面界面取消仍在运行的命令。底层 `CommandRuntime` 已能精确终止归属匹配的进程并清理进程树。

当前模型可见能力仍缺少同等的显式终止入口。Agent 面对一个需要放弃的 streaming 进程时，只能尝试通过 `write_stdin` 写入 Ctrl-C 等控制字符，或结束整个 run 等待宿主统一清理。控制字符依赖模型、Provider 和进程交互语义共同正确；即使写入成功，也只表示输入已送达，不保证进程已经退出。

2026-08-23 的一次真实本地任务中，模型三次把 Ctrl-C 错误表达成字面量 `\\u0003`，三次结果都明确显示原进程仍为 `running`，随后却准备在另一个执行上下文启动替代命令。现有日志没有证明两个 MaaCore 实例实际重叠执行，但这条链路暴露出一个通用缺口：Agent 没有可靠办法主动结束自己仍然持有的命令、取得权威终态，再在同一 run 内安全恢复任务。

本需求补齐这个模型可见的进程生命周期能力。它不通过全局 gate 猜测重复命令，也不为某个业务程序增加专用逻辑；Agent 只能对当前 run 已拥有的受治理进程请求终止，并继续服从既有授权、所有权、终态和进程树清理契约。

## 目标

- Agent 可以显式请求终止当前 run 内自己启动且仍受治理的命令，不依赖构造 Ctrl-C 或其它控制字节。
- 终止请求复用原命令已经批准的受治理生命周期，不增加文件、网络、桌面会话或宿主权限，也不重复要求用户批准同一命令的收尾动作。
- 终止结果形成权威、唯一且可区分的进程终态；模型、历史记录、实时协议、日志和桌面 UI 对是否已经终止保持一致。
- 终止成功后，Agent 可以在同一 run 内基于该终态继续判断、解释结果或请求执行替代路径；替代命令仍按自身能力和副作用重新审批。
- 未知、失效、跨 run、跨会话或已经终结的进程句柄具有稳定、可行动且不会误伤其它进程的结果。
- 用真实 bad case 的脱敏行为契约和确定性进程夹具固定“先取得旧进程终态，再启动替代路径”的边界。

## 范围

### 包含

#### 模型可见的精确终止能力

- Agent 可以引用当前 run 中由受治理命令运行时返回的进程句柄，请求结束该精确进程及其受治理子进程树。
- 终止能力只接受当前 Tool 运行上下文拥有的进程句柄；模型不能提交任意 PID、宿主进程名称、其它 run 的句柄或自行构造的内部标识符。
- 终止操作属于原命令生命周期的收缩动作，沿用原命令的 session、run、工具调用、授权和审计边界，不产生新的文件、网络或执行级别授权。
- 终止原命令不授权任何替代命令。Agent 后续请求的新命令继续经过现有规范化、权限校验和一次性审批。

#### 终态与同一 run 内恢复

- 终止请求不能只表示“已发送信号”。运行时必须返回能够判断原进程是否已经进入终态的结构化结果，并保留终止时间、原因和必要的有界输出。
- 成功终止后释放当前 run 对该进程的活跃句柄，清理受治理进程树，并避免 run 收尾阶段把同一进程再次表现为另一种冲突终态。
- 如果运行时无法确认终止或失去对进程的可靠观察，结果必须保守地区分运行时失联、清理失败或状态未知，不能冒充已取消。
- Agent 收到可信终态后可以在同一 run 内继续使用其它工具或请求新的命令；没有可信终态时，不应把替代命令描述为安全接管。

#### 错误恢复与重复调用

- 未知、过期和归属不匹配的进程句柄在执行终止前失败关闭，并明确指出正确句柄应来自当前 run 的哪类结果。
- 对已经结束或已被终止的进程再次请求终止时，返回稳定且无新增副作用的结果；不能错误终止后来复用系统 PID 的其它进程。
- 模型可见错误应区分参数错误、所有权错误、进程已终结、终止失败和运行时失联，并给出继续等待、停止重试或基于现有终态继续判断的准确方向。

#### 跨层一致性与可观测性

- 模型实际收到的工具定义能够清楚区分“写入交互输入 / 等待输出”和“结束进程”，且参数结构机械排除歧义调用。
- 终止请求、目标受治理句柄、规范化原因、最终状态和错误码可以在 trace、会话工具活动和诊断信息中关联，但不记录无关命令输出或敏感环境。
- 现有桌面用户取消、run 取消、超时、Bridge 关闭和 run 收尾清理继续使用同一底层终止语义；不同入口不会把同一进程投影成相互冲突的结果。
- 命令活动 UI 能准确显示 Agent 主动终止后的最终状态，不把它显示成自然退出、仍在运行或普通工具失败。

#### 验证与回归

- 使用确定性本地进程覆盖正常终止、子进程树清理、重复终止、已自然退出、跨 run/会话拒绝、运行时失联和终止后同一 run 继续执行。
- 核对至少一个实际 Provider 最终收到的模型可见工具 schema，确保名称、字段、互斥关系和说明没有在投影过程中丢失或变形。
- 将本次真实事故固化为脱敏行为回归：原进程仍为 `running` 且任务需要切换执行路径时，契约要求 Agent 先使用显式终止能力并取得终态，不再依赖字面控制字符或直接启动替代命令；真实模型结果作为概率性观察保留，不用单一模型的一次通过与否替代确定性能力验收。
- Windows 冻结运行时的命令 capability smoke 覆盖模型工具到现有进程终止和进程树清理的完整链路；源码形态在 Windows、macOS 和 Linux 保持相同的模型可见契约与结果语义。

### 不包含

- 不允许 Agent 终止任意宿主 PID、按进程名批量结束程序、扫描用户进程或管理非当前 run 启动的命令。
- 不增加全局“同一时间只能运行一个命令”的 gate，不阻止合法的多会话或多进程并发。
- 不根据命令字符串、业务名称或参数猜测两个命令是否重复，也不自动拦截所谓“相同任务”。
- 不把字面量 `\\u0003`、`Ctrl-C` 文本或其它猜测性输入自动改写成终止操作。
- 不增加 MAA、MuMu、账号切换或其它具体业务程序的专用逻辑、专用锁或专用审批。
- 不重新设计桌面的用户取消入口、命令审批卡片或完整终端 UI；只保证新增 Agent 入口产生的终态能由现有命令活动正确表达。
- 不提供 detach、应用退出后继续运行的 daemon、跨 run 进程接管或持久进程管理。
- 不改变现有命令的文件、网络、Skill binding、`sandboxed` / `host_user` 和一次性授权规则。
- 不因本需求调整默认模型、Provider 支持范围或为特定弱模型增加专用 prompt 补丁。
- 不承诺任一具体概率模型都能从隐式“切换执行路径”表述稳定推导出主动终止；该类真实 eval 失败必须保留并人工复核，但不以追加业务词、全局 gate 或特定模型 prompt 补丁换取单例通过。

## 关键信息

- 前置能力：[`085-governed-local-command-runtime`](../085-governed-local-command-runtime/requirement.md)。085 继续拥有通用命令执行、用户取消、run 取消、超时、底层终止和进程树清理；本需求只补模型侧主动终止并继续当前 run 的能力。
- 相邻能力：[`095-resilient-agent-run-recovery`](../095-resilient-agent-run-recovery/requirement.md)。095 继续拥有通用 Agent run 的错误恢复和终止语义，不负责新增命令工具的领域能力。
- 原命令授权覆盖其必要的受治理终止与清理；该覆盖不外推到任何新命令或更宽能力。
- 需求只承诺可理解、可审计、可验证的终止能力，不在本阶段锁定独立工具还是现有交互工具的互斥扩展；具体工具形态在技术方案阶段对照主流 Agent 实践后确认。
- 本需求的证据入口为 [evidence-index.md](./evidence-index.md)。完整本地会话、手机号、私人日志和原始模型上下文不进入仓库。

## 验收条件

- [ ] **AC-1 模型可见终止能力**：模型实际收到的工具集合包含清楚、无歧义的受治理进程终止能力；它只引用当前 run 的受治理进程句柄，不要求构造 Ctrl-C、PID 或宿主进程名称。
- [ ] **AC-2 所有权与授权边界**：当前 run 的活跃进程可以终止；未知、伪造、跨 run 和跨会话句柄在副作用前失败关闭。终止复用原命令生命周期且不新增审批、文件、网络或执行级别授权，后续新命令仍独立审批。
- [ ] **AC-3 权威终态与进程树清理**：终止一个含子进程的 streaming 命令后，运行时形成唯一的 Agent 主动终止终态，句柄被释放，受治理进程树无残留，run 收尾不会覆盖或分叉该终态。
- [ ] **AC-4 同一 run 内继续执行**：Agent 取得可信终态后，可以在同一 run 内继续调用其它工具或请求一条替代命令并完成任务；终止前后的工具调用、审批和结果保持可追溯。
- [ ] **AC-5 重复与竞态安全**：已自然退出、已终止、终止过程中同时退出和重复终止都得到稳定、无新增副作用的结果，不会误伤后来出现的其它进程。
- [ ] **AC-6 失败与失联不冒充成功**：底层拒绝、清理失败、运行时断开或终态无法确认时，模型、历史、实时协议和 UI 一致显示准确失败或未知状态，并给出与实际可恢复性相符的下一步。
- [ ] **AC-7 既有取消入口兼容**：桌面用户取消、run 取消、命令超时、Bridge drain 和 run 收尾继续正确清理进程；新增 Agent 入口不改变既有命令授权、streaming 输入、输出预算和多会话并发行为。
- [ ] **AC-8 Provider 契约与行为回归**：Provider 最终 schema 契约测试通过；确定性行为契约固定“原进程仍运行时先终止并取得终态，再选择替代路径”，真实模型证据覆盖显式精确终止成功、正常等待、已退出与多句柄隔离，并如实保留隐式意图选路失败及人工归因；单一概率模型通过不作为确定性能力的合入门槛。
- [ ] **AC-9 跨平台与项目门禁**：源码契约测试覆盖 Windows、macOS 和 Linux 共同语义；Windows 冻结 runtime capability smoke 通过模型工具到真实进程清理链路，项目 `scripts/check` 全绿。
