# 工具结果上下文保留策略

## 状态

CONFIRMED

## 背景

[issue 040](../../issues/040-long-session-tool-result-compaction/README.md) 已为长会话增加陈旧工具结果清理和按引用恢复能力，但最初以问题修复交付，缺少独立需求对保护窗口的用户可见行为和验收边界进行约束。

现有策略把“全局最近 4 条工具结果”和“当前轮结果”取并集。当前轮包含并行工具调用时会占用最近结果名额，导致往期保护数量随当前轮结果数变化；按单条结果计数也可能拆散同一次并行工具调用的完整证据组。

## 目标

- 当前用户轮产生的工具结果不与历史保护窗口竞争名额。
- 往期保护窗口以完整工具调用批次为单位，避免拆散同一次并行调用的结果。
- 在压缩收益、近期上下文连续性和旧结果可恢复性之间形成稳定、可测试的行为契约。

## 范围

### 包含

- 低水位清理始终保护当前用户轮内的全部工具结果。
- 在当前轮之外，保护最近 3 个完整工具调用批次的全部结果。
- 无法关联到工具调用批次的历史结果按单条独立批次处理，保证旧数据仍有确定性行为。
- pinned、状态变更型及无法安全恢复的结果继续独立保护，不占用近期批次数量。
- 旧的可恢复结果仍可被批量清成稳定占位符，并通过原始结果引用恢复。
- 为当前轮、并行批次、旧事件兼容和 pinned 行为补充自动化回归覆盖。

### 不包含

- 改变单条巨大工具结果的模型视图长度上限。
- 改变全局摘要、FIFO 硬边界或紧急兜底策略。
- 修改原始 session event、工具协议或恢复工具的公开接口。
- 引入按工具类型配置不同历史窗口或用户可配置项。

## 关键信息

- “工具调用批次”指同一条 assistant 消息发起的一组工具调用；并行调用产生的多个结果属于同一批。
- “保护”仅表示不参与陈旧结果的低水位占位清理；单条结果仍服从既有长度上限和系统硬边界。
- 已落盘的旧清理 checkpoint 继续稳定生效，不自动恢复已经清理的模型视图正文；原始结果仍保留并可按引用读取。

## 验收条件

- [x] 当前轮产生任意多条工具结果时，这些结果均不被低水位清理。
- [x] 当前轮之外最近 3 个完整工具调用批次均被保护，且当前轮结果不占用这 3 个名额。
- [x] 同一次并行工具调用的多个结果作为一个完整批次共同保护。
- [x] 无法关联 assistant 工具调用的旧结果按单条批次获得确定性的最近窗口保护。
- [x] pinned 和不可恢复结果继续保护，陈旧 recoverable 结果仍能清理并恢复。
- [x] 原始事件、单条结果上限、全局摘要和紧急兜底行为不发生回归。
- [x] 项目完整检查门禁通过。
