# 122 · 会话本地加载与运行态复用治理技术方案

## 状态

CONFIRMED

## 需求文档

[requirement.md](./requirement.md)

## 现状与边界

执行入口在 start_conversation 查询驻留状态前调用 open，造成重复完整加载。只读查询有进程缓存，但未命中时解析完整 JSONL；active 接口仍返回全部有效事件。冷恢复需要验证完整 rollout 提交链，不能将末尾 commit 当成独立可信检查点。

## 方案

### 执行准备

由 SessionManager 提供统一的执行用会话获取入口，先复用有效驻留 Session，再在未驻留时完整加载。open 保留完整读取语义，供调试和显式历史读取使用。AG-UI 的附件模型校验、SessionBridge 和后台 conversation_factory 使用执行入口；装配 Conversation 前优先选择权威驻留 Session，避免使用过期配置。

复用继续依赖现有跨进程 writer lease 和 scheduler 的会话执行／修改互斥。源文件变化必须可识别，不能将不一致的驻留状态静默视为有效。失败、取消和释放必须保持原有恢复边界。

### 历史展示

在只读查询边界提供按页的有效事件读取，维护可增量更新的可见投影，保留完整读取接口用于兼容。分页使用稳定事件位置和版本边界；不能在每页请求中重复读取、投影并序列化全部历史。前端先取最新页，再按需读取旧页，去重并保留滚动锚点；rewrite／失效需要重新同步，普通增量不替换整段可见历史。

### 冷恢复

保持完整 JSONL 与 rollout 校验语义，先实现流式读取、减少完整 bytes／splitlines 副本和累计历史容器复制；保留取消检查与损坏恢复判断。无效提交、缺失引用及截断不得静默通过。本轮不直接新增独立恢复检查点协议。

以固定样本比较读取、解析和恢复成本。若仍不达标，需求不收尾；在本需求内提出进一步恢复加速及其兼容边界，经确认后推进。

### 控制与观测

取消仍由 scheduler 的已受理 run handle 处理，不依赖历史加载。全局协调锁不得覆盖文件解析或恢复工作；文件读写及通知 SQLite 锁分别验证。阶段观测区分受理、驻留复用／冷加载、解析、恢复、记忆检索和上下文准备，provider 等待不混入本地指标。

## 影响分析

保留现有历史格式与完整读取能力，不新增运行时依赖；当前属于 standard 打包影响。分页不得改变工具结果组合、重写可见性、引用及运行中事件排序；模型／权限来自权威状态。需复核需求 121 后续合入的模型配置接口。

验证按需求 AC 执行：确定性测试先固定机制，真实桌面 CDP 再验证交互；真实 LLM 请求另按本次预算授权。纯本地与 fake 验证不请求外部模型。
