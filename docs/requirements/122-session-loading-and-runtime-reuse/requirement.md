# 122 · 会话本地加载与运行态复用治理

## 状态

CONFIRMED

## 背景

需求 120 已完成会话交互与持久化的阶段性治理，但用户继续对话后，仍观察到明显的本地加载等待。后续调查发现，发送入口先完整加载会话，再在建立对话时检查驻留运行态，存在已有可复用状态却重复读盘的路径。单次改进或冷启动测试不足以证明连续使用体验达标。

本需求承接这些遗漏，整体治理本地加载和执行准备。用户明确指出目标是应用自身的等待；LLM provider 接收请求后的生成耗时不属于本次性能目标。

## 目标

- 已加载会话连续使用时复用有效状态，消除无必要的完整历史读取与运行态重建。
- 分别治理首次恢复、重复打开及连续发送，避免历史增长导致每次操作重复承担历史处理成本。
- 会话展示、发送、取消及设置修改具备稳定响应；后台工作不能引入无法解释的加载阻塞。
- 以分阶段证据、固定样本和真实桌面验证判断效果，同时保证历史、权限、恢复和持久化正确性。

## 范围

### 包含

- 两条可见消息的极短会话、普通会话和长会话的首次打开、重复切换、缓存后重开及向上翻阅。
- 同进程内连续多轮发送、准备中取消、执行中取消和取消后继续；重启后的首次恢复单独治理。
- 模型与思考强度切换的反馈、保存和后续生效。
- 桌面对话以及共享会话运行态的其他入口；通知、记忆等后台任务与前台操作的竞争。
- 会话读取、解析、恢复、上下文准备、记忆检索、渲染与排队／锁等待的分阶段计时及重复工作的识别。
- 驻留状态的生命周期、失效与持久化一致性；异常文件、重启、并发和取消时的安全恢复。
- JSONL 文件锁和通知 SQLite 锁的独立回归验证。

### 边界

- 不以 provider 生成速度或 provider prompt cache 命中率解释本地加载是否达标。准备期间发生的外部依赖等待也必须单独标记。
- 不通过隐藏加载提示、提前显示完成、跳过恢复校验、丢弃历史或削弱权限与持久化保证获得性能数字。
- 不预定替换存储技术栈或大幅升级依赖。先查根因和兼容性，再确认具体方案。
- 需求 120 的已完成记录作为历史保留；本需求独立验证遗漏和回归，不自动关闭历史 issue。

## 验收条件

- [ ] AC-1：盘点所有相关入口的本地加载链路，明确展示读取、执行恢复及后台工作的调用与等待关系；能够说明每段本地耗时，不能把未归因的时间统一归为冷恢复。
- [ ] AC-2：有效驻留状态下，连续多轮发送不重复完整读取历史或重建运行态。通过可断言的调用／读取计数验证，并覆盖共享执行入口；只有失效或确需恢复时才进入对应路径，原因可观测。
- [ ] AC-3：分别验证进程冷启动、首次打开、已驻留重开与历史持续增长；给出固定样本下的前后对比、重复次数、分布和最大值。冷恢复自身的瓶颈得到定位与治理，不以暖路径优化替代。
- [ ] AC-4：使用真实 Tauri WebView CDP 验证极短、普通和长会话的打开、切换、向上翻阅、模型／思考切换、发送、取消及取消后继续；覆盖空闲和后台工作并发状态。无新增滚动抽动、错误状态或设置不生效。
- [ ] AC-5：会话文件与通知数据库的锁分别定位并验证；相关读取、后台任务和工具结果写入并发时，无本需求涉及根因造成的锁超时、结果丢失或运行失败。仅延长超时或增加重试不能通过。
- [ ] AC-6：复用、失效、冷恢复和取消不改变会话内容、模型配置、权限、工具结果及恢复语义；覆盖文件变更／损坏、运行态释放和重启等边界，防止陈旧状态、重复副作用及资源泄漏。
- [ ] AC-7：可断言行为有自动化回归覆盖，项目 scripts/check 通过；向用户回报实际改善、未复现、未验证和残余问题，由用户确认体验验收完成。

## 性能判定与工作约定

- AC-2 的暖路径不重复全量读取／重建、锁治理及正确性为硬门槛。
- 具体毫秒指标先按固定样本测量，再明确阈值及是否作为门槛；不得自行把历史讨论中的 300 ms／1 秒变成新硬指标，也不得凭单次变快宣布通过。
- 测量区分操作受理、本地准备和真正发出模型请求的边界；并行阶段不可简单相加，provider 等待不混入本地指标。
- 沿用用户对这些 bad case 的 CDP 验证授权，dev 可保留用于后续调试；真实外部 LLM 调用仍须按本次执行范围单独授权，历史已结束的调用预算不复用。
- 方案形成前及关键实现过程中充分核对成熟产品的现成实践，保留来源、版本、适用边界和采用判断于证据索引。具体参考分析不混入需求或技术方案正文。
- 需求确认后进入方案调查；技术方案另行确认后，按明确的实现授权推进代码修改。
