## 背景与目标

本地文件链接解析出现长时间等待和失败变灰。调查发现，解析一个有效绝对路径之前会完整加载所属会话；同类做法也存在于提醒、附件、工具结果恢复、模型配置、会话管理、通知及指定消息校验中。

已有轻量配置、历史分页、执行准备和索引能力，但调用方仍可通过通用读取获得全部历史，再自行筛选少量信息。部分测试只禁止完整原始会话加载，未约束全部业务历史的构造和缓存缺失后的扫描成本。

本需求统一会话读取的用途、责任边界和成本约束，使调用方按实际所需信息使用公共能力。集中管理必要的完整读取，并通过自动化检查阻止轻量操作重新依赖无必要的全量加载。此前的诊断事实和局限见 [evidence-index.md](./evidence-index.md)。

## 需求

### 1. 按用途统一提供读取能力

| 读取方式 | 服务的信息需求 | 必须守住的边界 |
| --- | --- | --- |
| 轻量状态读取 | 存在性、会话身份、标题、当前配置和版本等 | 不加载历史正文，不恢复模型执行上下文。 |
| 定点读取 | 指定消息、工具结果、附件引用或某次运行结果 | 按标识取得所需记录，支持同一请求的批量读取，保留来源和有效性校验。 |
| 范围读取 | 最近回合、历史分页、搜索结果等 | 明确范围、数量和续页方式；请求少量内容不能先构造全部历史再切片。 |
| 执行恢复 | 准备或继续真正的 Agent 执行 | 由执行入口负责，沿用执行所有权和恢复契约，复用仍有效的准备或驻留状态。 |
| 维护与完整读取 | 完整导出、索引修复、垃圾回收和完整性校验等 | 明确用途、范围和调用方，可取消并控制资源占用，不成为普通小查询的隐含前置操作。 |

五类是调用方可理解的能力边界。具体接口、类型、实现和模块组织在技术方案中确定，沿用现有存储和领域边界。

### 2. 覆盖现有入口并完成迁移

- 对桌面、IM、语音、主动活动、提醒、定时任务、CLI 和后台维护中的会话读取建立可复查清单。从业务入口追踪实际读取，同时从底层完整读取反查调用方。
- 覆盖直接调用、封装与别名、兼容回退、缓存失效、先全读再分页、重复读取，以及写入或状态更新时附带的历史读取。
- 前期查出的链接、附件、工具结果恢复、配置与标题、会话管理、审批重试、通知、消息校验和搜索全部纳入核对；新增发现按同一标准处理。
- 每项生产调用明确归属于一种读取方式，给出迁移结果或保留完整读取的必要理由。不能只迁移已复现的界面路径。
- 调用方通过公共能力获取所需结果，避免在各自模块重复实现日志解析、历史投影、索引修复和完整加载后的过滤。

### 3. 成本约束覆盖冷路径

- 小查询不得因缓存为空、索引缺失或失效、服务重启、锁竞争而悄悄升级为完整历史加载、完整投影或执行恢复。
- 旧数据由产品自动兼容，不要求用户手工迁移，也不要求预先处理全部旧会话。无法直接定位时的首次补齐范围、正确性和成本必须在方案中明确，并单独验证。
- 已取得且仍有效的数据应可复用；正常重启、后续追加及分页访问不应反复付出相同的全量补齐成本。
- 大正文、完整搜索和维护所必需的工作量单独计量，不用返回条数少掩盖处理量大，也不把必要成本包装成固定时延承诺。
- 记录可定位调用方的读取方式、范围、处理量、耗时和回退原因；不记录不必要的会话正文或敏感内容。

### 4. 保持数据与行为正确

- 当前有效历史、原始审计记录和模型恢复材料的用途保持清楚。历史编辑、失活记录、压缩及并发追加不得导致读取过期内容或漏掉所需结果。
- 保留附件和工具结果的会话归属、来源绑定、权限与完整性校验，不能为了省读取取消这些条件。
- 身份、配置、历史页和执行状态绑定正确的会话与版本。并发写入或数据变化时，迟到结果不得用于错误目标。
- 执行恢复、租约、取消及防止重复执行的契约保持有效。读取优化不能新增模型调用、工具执行或用户数据修改。
- 失败应如实表达；无法完成读取不能被当作目标不存在、查询为空或已经完成。原始链接场景纳入回归验证。

### 5. 自动化阻止重新引入

- 自动识别未经治理的完整读取调用，以及业务层绕过公共入口自行读日志或重建历史的做法。
- 定点与小范围操作验证实际访问和处理范围，不能仅断言没有调用某个方法名。
- 固定请求结果，逐级增加无关历史，分别检查热缓存、冷缓存、旧格式和索引异常路径的工作量与耗时。
- 新增消费者能够复用已定义能力和相应测试，不需要再复制一套“轻量读取”实现。

## 范围边界

- 本期治理会话数据的读取及其必要派生视图、调用方和测试；保留当前存储体系和用户历史。
- 全文搜索、执行恢复、完整导出和维护仍可完成其真实需要的工作，按各自读取契约约束。
- 不改变模型可见内容、人格、记忆含义、文件链接的打开方式，也不借此重构无关存储业务。
- 具体性能预算、旧数据首次补齐策略和必要的兼容接口处置在方案阶段确定。

## 验收条件

以下勾选表示工程验证完成；最终用户验收状态见 progress.md。

- [x] **AC-01 · 统一能力。** 五类读取有清楚的公共入口、适用范围和责任源，调用方不再自行拼接完整历史读取流程。
- [x] **AC-02 · 调用方闭环。** 生产调用清单覆盖主要入口及底层反查；每项有迁移结果或必要全量读取理由，前期与补充排查均有归属。
- [x] **AC-03 · 小查询工作量。** 链接、存在性、配置、指定消息或结果等操作，不因增加无关历史而构造完整原始或业务历史；缓存缺失与异常路径同样验证。
- [x] **AC-04 · 范围与批量。** 分页、范围及批量查询按声明范围读取；连续分页或读取同一结果的不同片段不重复加载全部历史。
- [x] **AC-05 · 自动兼容。** 旧数据、缺失或失效索引可在产品内自动处理；首次与再次访问分别记录，补齐中断后可恢复，未访问会话不被无条件全量处理。
- [x] **AC-06 · 正确性。** 历史改写、失活消息、压缩、并发追加和删除后的结果准确；附件、工具结果及跨会话引用保留完整的归属和权限验证。
- [x] **AC-07 · 执行与维护。** 正式执行继续遵守所有权和恢复语义，复用有效状态；维护及完整导出可取消、资源使用受控，普通查询不等待无关全量维护。
- [x] **AC-08 · 诊断与失败。** 能从观测区分读取方式、来源、工作量和回退原因；错误不被伪装成不存在或空结果，链接原始场景有对应回归。
- [x] **AC-09 · 防回归。** 新增绕过入口或不必要完整读取能被自动化门禁发现；测试同时覆盖原始历史、全部业务历史和兼容回退。
- [x] **AC-10 · 证据。** 固定样例与增长测试记录源码、环境、读取量和耗时；区分代码证明、隔离验证和真实运行结果，未验证项如实保留。
