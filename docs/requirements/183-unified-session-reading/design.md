## 统一责任与接口

在 `agent.sessions.reading` 集中普通读取。通过 store 装配的共享 reader 对外提供三组明确能力：

- 状态：存在性、身份、当前配置、单条摘要和源版本；返回小型结果，不携带完整历史。
- 定点：消息 ID、运行 ID、工具调用/结果/证据引用、附件引用及字符片段；批量 ID 在同一版本读取。
- 范围：有界事件/消息/工具页、回合窗口、正文检索和来源区间；限定记录种类、方向及范围，完整搜索使用流式迭代。

执行恢复继续归 SessionManager 与既有 execution loader，完整导出、索引补齐、垃圾回收和恢复维护由显式维护操作负责。完整读取记录用途、版本、字节和事件成本。普通 reader 不通过缺失能力的 fallback 调用 load/query/load_execution；不支持的 store 明确失败或提供自己的有界实现。

普通消费者不接触日志解析、业务索引重建或原始 Session 装配。对模型公开的工具参数、描述和结果含义保持既有契约；如确需改变模型可见错误或输出约束，另按提示词与工具契约流程对齐。

## 数据与索引

- JSONL 仍是权威日志，复用 `.business`、配置和活动时间等既有派生视图；不引入运行时依赖或另一套业务事实存储。
- 定点和范围读取在版本一致的短读事务中执行，只读取目标正文。为 run、tool/evidence 和附件归属建立必要的定位索引；来源、失活状态和配对冲突由公共查询维护。
- 存在性和静态身份不需要业务索引。当前配置复用轻量配置视图；管理元数据保持独立 owner，合并时保留其版本语义。
- 首次旧数据补齐以一个会话为范围，流式构建可复用索引，不先创建完整 SessionQuerySnapshot，不物化 rollout 历史。缺失、异常、源文件替换分别观察，不启动全库迁移。
- 同会话补齐合并，支持取消和有限等待；原日志不因派生视图失败改变。补齐发布绑定来源版本，源变化时不发布旧结果。正常追加增量维护，历史改写按失活 ID 更新派生记录，避免读取全部正文再重建。
- 对明确需要整体完整性证据的来源/工具历史，沿用现有损坏诊断，不以只验证局部冒充全局可信。首次验证成本单列，后续使用匹配版本的证明。
- 部分旧日志首次定位仍可能线性扫描，这是已确认的自动兼容边界；需要记录成本并持久化复用，不承诺任意旧日志首次常数耗时。

## 消费者迁移

以 R-01 至 R-27 为核对表。先实现公共能力和成本测试，再迁移链接、配置、管理操作及通知；随后迁移附件、结果/调用历史、来源、引用验证、IM/语音、定时与主动活动；最后收口搜索、召回、维护和兼容接口。

附件授权和提醒去重分别保留“有效引用”与“原始事件已存在”的区别。编辑重发、续接和执行准备保留版本竞争检测及租约。语音空会话清理改读必要判断，读取失败仍跳过删除。完整历史兼容接口归完整读取用途，不再由普通业务调用。

全文匹配与记忆检索继续使用原有匹配、排序、角色和范围规则，缩小字段读取和内存保留，不通过仅检索最近记录改变结果。公开文本投影保持原有 owner。

## 验证和防回归

- 架构门禁检查普通消费者直接使用完整读取、原始日志迭代及兼容回退；完整读取例外精确到责任模块与用途。
- 对定点和范围操作固定目标，增长无关历史，检查记录访问、物化数量及数据库指令量。分别覆盖正常追加、冷启动、缺失/过期/损坏索引、历史改写、取消和并发修改。
- 历史与工具等价性测试覆盖跨会话拒绝、失活引用、原始去重、配对冲突、分页游标、源版本改变和错误不冒充空结果。
- 复用项目测试/检查与 session-latency 入口；按影响计划执行 backend/frontend 阶段。语音 HTTP 契约通过本地 fake 覆盖，不调用真实模型或外部语音服务。
- 此实现计划仅使用现有 Python/SQLite 能力，冻结影响预计为 standard；实现完成后按实际 diff 复核。
- 不默认启动桌面或生成安装包。前端如涉及可见交互，真实桌面视觉验收继续按用户授权执行。
