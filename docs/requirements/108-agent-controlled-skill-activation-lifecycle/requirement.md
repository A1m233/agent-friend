# Agent 可控的 Skill 激活生命周期

## 状态

ARCHIVED

## 封存说明

- 本需求曾完成需求范围确认，但在技术设计阶段确认其真实改动面同时涉及 Skill catalog、激活状态、完整包快照、文件读取 scope、命令执行绑定、安装结果协议、会话生命周期和行为评测，交付重量明显高于最初体感。
- 2026-08-29 用户决定停止当前交付并封存调研。本文保留当时确认的产品目标与验收口径，**不表示这些行为已经实现，也不再覆盖需求 076、088 的现行运行时契约**。
- 当前产品仍保持需求 076、088 已实现的语义：用户轮开始后发生的 Skill 内容变化只在后续用户轮重新发现或激活。
- 未来若重新启动本需求，应以届时的代码、上游 Agent 产品行为和安全边界重新复核范围；不得直接把本文或配套的封存候选方案当作当前实现指令。

## 背景

agent-friend 已支持在会话中发现、选择和激活 Skill，也支持通过 builtin `skill-installer` 安装或更新 GitHub Skill。当前运行时为了保证单轮执行一致性，会在用户轮开始时冻结 Skill catalog 和内容版本；如果 Agent 在同一轮先更新某个 Skill、再尝试激活它，激活入口会因为磁盘版本已经不同于轮初版本而拒绝本次加载，并要求等到下一用户轮。

这会把一个连续、已获用户授权的任务人为拆成两轮。例如用户要求“更新 Skill，然后按新版继续执行”，Agent 已成功更新 Skill，却只能请用户再发一条消息才能继续。更新动作真实成功，但用户目标没有在原轮闭环，产品表现也容易被理解为 Agent 没有真正掌控 Skill 的激活时机。

现有约束保护了“已经开始使用的指令不能在执行中途漂移”，但冻结点过早。系统需要区分用于发现候选的 catalog 与已经为当前任务绑定的 Skill：catalog 可以保持稳定，Skill 则应在首次激活时绑定当前有效版本，并在绑定后保持本轮一致。

## 目标

- 让 Agent 在同一用户轮内完成“安装或更新 Skill → 激活该 Skill → 按其指引继续任务”的连续闭环，不要求用户发送无业务含义的额外消息。
- 将 Skill 内容的稳定边界从“用户轮开始”调整为“该 Skill 在本轮首次成功激活”，同时保留轮内确定性。
- 确保一次激活绑定的是完整 Skill 包的同一内容版本，避免说明、引用资源和可执行资源来自不同版本。
- 保持 Skill 发现、显式选择、隐式选择、权限、授权和副作用控制之间的既有边界；允许 Agent 激活不等于允许 Skill 绕过治理。
- 对更新、安装、重复激活、激活后再次变更和真实失败形成清楚、可诊断、可回归的产品契约。

## 范围

### 包含

#### Catalog 与首次激活分离

- 用户轮开始时的 model-visible catalog 继续承担候选发现和语义选择职责，不因本需求把所有 Skill 正文预先装入上下文。
- 对轮初 catalog 中已经存在的 Skill，Agent 在本轮首次激活时以该稳定身份解析当前有效定义；仅因内容在轮内发生了合法更新，不得拒绝激活。
- 首次激活必须重新核对目标仍然存在、有效、可读、可调用且身份未被其它 Skill 冒用；“使用当前版本”不表示跳过校验或来源边界。
- 调用方预选、用户可信显式选择和 Agent 隐式选择继续汇入同一套真实激活路径，不形成只对某个入口生效的特殊行为。

#### 同轮安装或更新后继续任务

- Agent 成功更新轮初已知 Skill 后，可以在同一用户轮激活更新后的有效版本并继续执行原任务。
- Agent 成功安装轮初不存在的 Skill 后，如果安装结果提供了可验证的精确 Skill 身份和入口，Agent 可以在同一用户轮显式激活该 Skill 并继续任务。
- 新安装 Skill 的同轮激活只接受本轮受支持安装流程刚刚产生的可信结果；不能凭一个未发现、未安装或来源不明的名称任意扩大当前可用 Skill 集合。
- 安装或更新没有成功时，Agent 不得把候选内容当作已安装或已激活版本继续执行，也不得声称任务已经按新 Skill 完成。

#### 首次激活后的轮内版本绑定

- Skill 在本轮首次成功激活时形成明确的内容版本绑定；同一 Skill 在本轮后续再次被选择或读取时复用该绑定，不重新切换到磁盘上的其它版本。
- 绑定覆盖完成任务可能使用的整个 Skill 包，包括 `SKILL.md`、引用资料、脚本、资产及其它包内资源；同一轮不能出现说明来自一个版本、资源或命令来自另一个版本的混合状态。
- Skill 已经激活后又被更新、删除、替换或修改，不改变本轮已经绑定的内容；变化从下一用户轮的发现或首次激活开始生效。
- 轮内绑定不把 Skill 提升为永久规则。下一用户轮重新选择同一 Skill 时，应按当时的有效内容形成新的绑定。
- 已经进入会话历史的 Skill 正文不因磁盘变化或新绑定而被回写、篡改或冒充成另一版本。

#### 权限、授权与副作用边界

- Skill 激活只提供指令与受约束的包内资源身份，不自动执行脚本、命令或其它副作用操作。
- Skill 的隐式调用策略、工具权限、命令授权、文件和网络范围、外部写入、付费调用及其它既有门禁继续独立生效。
- 新安装或更新后的 Skill 必须先通过现有安装、来源、内容和格式校验；本需求不为候选 Skill 增加信任豁免。
- Skill 被禁用、隐式调用被禁止、调用方无权使用或任务需要额外授权时，系统应按原有治理路径拒绝、询问或降级，不能因为“本轮刚安装或更新”而绕过。

#### 用户可见状态与错误语义

- Agent 应让用户看到本轮实际使用的 Skill，以及安装、更新、激活或继续执行中真正发生的失败；不能把 catalog 中存在、文件已下载或更新命令成功等同于激活成功。
- “轮内内容发生合法更新”不再作为需要下一用户轮重试的错误。
- 目标不存在、身份不可信、内容无效、不可读、被禁用、权限不允许或无法形成完整一致绑定时，激活仍明确失败，并提供足以区分原因的诊断。
- 如果失败不阻止采用不依赖该 Skill 的安全方案，Agent 可以如实说明后降级继续；不得为了避免报错而偷偷使用未绑定或混合版本。

#### 回归与兼容

- 桌面聊天、普通 OpenAI-compatible 会话入口以及其它复用统一 Agent Skill 运行时的调用路径保持一致的首次激活和轮内绑定语义。
- 调用方在用户轮开始前已结构化选择的 Skill 继续能够正常装配，不因本需求退化。
- 既有 catalog 热更新、会话历史、上下文压缩、Skill 更新安全门禁和命令运行治理保持兼容。
- 截图对应的“同轮更新成功后，激活返回 `skill_changed_during_turn`，要求用户再发一条消息”真实 bad case 应固化为可重复行为回归。

### 不包含

- 后台自动检查或自动更新 Skill、批量更新、Skill 商店、推荐、发布或远程目录能力。
- 未经用户请求或既有治理授权自动安装 Skill。
- 仅凭任意名称、路径或模型自报结果加载轮初未知且本轮未由可信安装流程产生的 Skill。
- 在同一轮已经绑定 Skill 后热切换到新版本，或提供面向用户的“强制重载当前 Skill”能力。
- 把已激活 Skill 永久固定到整个会话、Persona、长期记忆或不可压缩 system 规则。
- 为 Skill 新增绕过公共工具治理的私有文件读取、命令执行、网络访问或副作用权限。
- Skill 历史版本列表、长期版本缓存、用户主动版本选择、回滚、diff 或三方合并。
- 新增或改造桌面端 Skill 管理 UI。
- 改变 GitHub Skill 安装、更新、同源校验、本地修改冲突和接管规则本身。

## 关键信息

- “轮初 catalog”是供模型发现和选择候选的有界元数据视图，不是本轮所有 Skill 内容的永久版本锁。
- “首次激活”是目标 Skill 在当前用户轮第一次通过统一结构化入口完成身份、有效性、权限和内容核对，并产生真实成功状态的时刻。
- “当前有效版本”是首次激活时能够由目标稳定身份解析、通过现有校验与调用策略、并可形成完整包绑定的版本；不是路径上碰巧存在的任意文件。
- “轮内绑定”只保证当前用户轮中同一 Skill 的指令和包内资源一致，不改变历史消息，也不阻止下一用户轮使用更新后的内容。
- “可信安装结果”必须来自本轮受支持安装流程的真实成功结果，并足以精确指向实际安装的 Skill；具体携带字段和传递方式由技术方案确定。
- 更新发生在首次激活之前时，本轮使用更新后的版本；更新发生在首次激活之后时，本轮继续使用已绑定版本，下一用户轮再使用更新后的版本。
- 本需求废止需求 076 与需求 088 中“轮内任何内容变化都必须等下一用户轮才能激活”的旧口径，但保留它们关于 catalog 渐进披露、历史不可篡改、更新安全和已激活内容稳定的其它约束。

## 验收条件

- [ ] **AC-1 更新后同轮首次激活**：用户在一条消息中要求更新轮初已知 Skill 并按新版继续任务；更新成功后，Agent 在同一用户轮首次激活更新后的有效版本并继续执行，不返回 `skill_changed_during_turn`，也不要求用户发送额外消息。
- [ ] **AC-2 Catalog 与内容版本解耦**：轮初 catalog 保持用于候选发现的稳定元数据视图；目标内容版本与轮初记录不同不会单独导致首次激活失败，首次激活仍完整执行当前身份、有效性、可读性和调用策略检查。
- [ ] **AC-3 完整包一致绑定**：首次激活后，本轮读取到的 `SKILL.md`、引用资料、脚本、资产和命令所用 Skill 资源均来自同一内容版本；测试能够识别并阻止混合版本。
- [ ] **AC-4 激活后变更隔离**：Skill 已在本轮激活后再次更新、修改、替换或删除，本轮重复选择和后续资源使用仍保持原绑定；下一用户轮重新激活时使用当时的当前有效版本，历史正文不被改写。
- [ ] **AC-5 本轮重复激活稳定**：同一 Skill 在一个用户轮内被多次选择或读取时复用首次成功绑定，不因磁盘变化切换版本，也不制造互相冲突的激活状态。
- [ ] **AC-6 新安装后同轮显式激活**：本轮受支持安装流程成功安装轮初不存在的 Skill 并返回可信精确身份后，Agent 可以在同一轮显式激活并使用它；无需重启应用、Agent、会话或增加用户消息。
- [ ] **AC-7 未知身份不扩权**：没有轮初候选或本轮可信安装结果时，模型提交任意名称、路径或伪造安装结果不能激活未知 Skill，也不能取得其内容或资源。
- [ ] **AC-8 真实失败保持失败**：目标不存在、身份不匹配、安装或更新未成功、内容无效或不可读、Skill 被禁用、隐式调用不允许、权限被拒绝或无法形成完整一致绑定时，系统返回可区分的真实失败，Agent 不声称已经激活或按该 Skill 完成任务。
- [ ] **AC-9 治理边界不回归**：同轮安装、更新或激活不会自动执行 Skill 脚本，不会绕过工具、命令、文件、网络、外部写入、付费调用或其它既有授权门禁，也不会弱化 GitHub Skill 的来源和冲突校验。
- [ ] **AC-10 跨入口与既有选择兼容**：桌面聊天、普通 OpenAI-compatible 入口和统一运行时调用路径遵循相同绑定语义；轮前结构化选择、用户可信显式选择、Agent 隐式选择及禁止隐式调用的既有行为继续通过回归。
- [ ] **AC-11 后续轮刷新**：首次激活前的合法变更可以在当前轮绑定；首次激活后的变更从后续用户轮生效。catalog watcher、上下文历史和压缩后再次激活仍能取得正确版本。
- [ ] **AC-12 Bad case 行为回归**：截图对应真实会话被固化为 agent eval 或等价行为契约；原始“更新成功后要求用户再发一条消息”回答失败，同轮真实激活并继续任务的回答通过，删除、禁用、非法内容和未知身份对照保持失败。
- [ ] **AC-13 自动化门禁**：首次激活、可信安装结果、轮内重复激活、完整包绑定、激活后变更、历史隔离、错误分层、权限保持及既有 Skill 回归具有确定性测试，项目完整检查门禁通过。
