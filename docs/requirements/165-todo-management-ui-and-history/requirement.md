# 165 · Todo 管理界面与操作历史

## 状态

CONFIRMED

## 背景

070 已提供 Todo、提醒、Agent 管理工具及后端管理接口，桌面端目前主要通过对话和只读提醒卡片呈现待办。用户缺少集中查看、直接编辑和改变待办状态的独立界面。

引入人工直接操作后，同一待办可以由用户和 Agent 交替修改。现有创建来源不足以回答每次编辑或状态变化由谁执行、何时发生、具体改了什么，需要将操作历史与管理界面一并补齐。

## 目标

- 用户可以通过独立管理界面完成常用待办操作，无需每次回到对话。
- 用户能够追溯每次变更的执行者、发生时间、操作内容及修改前后值。
- 人工操作和 Agent 操作使用一致的待办事实，发生并发修改时不静默覆盖。

## 范围

### R-1 独立入口与列表

- 桌面主界面的左侧导航增加“待办”入口，与“定时任务”并列，在主内容区展示管理页面。
- 桌宠操作栏提供“待办”按钮，直接打开主窗口的待办管理页。
- 默认显示待办中，支持切换已完成、已取消、全部，并支持搜索。
- 列表显示标题、提醒摘要、创建时间、最近操作人及时间；选中条目可查看详情及创建时间。
- 搜索、筛选和分页位置固定，列表内容独立滚动；点击选中及后台刷新不使条目抽动，选中反馈保持稳定。
- 详情包含待办内容、状态、提醒设置及操作历史；历史细节不挤占列表的主要信息。

### R-2 新建与编辑

- 用户可以新建待办，编辑标题、描述，添加、修改或移除提醒。
- 提醒编辑支持现有能力范围内的提醒时间与重复规则，不另行扩展调度能力。
- 人工管理和对话管理修改同一份待办；重新打开页面或应用后仍能看到已保存的结果。
- 保存失败时明确反馈，不把未保存内容显示为已成功修改。

### R-3 状态管理

- 支持完成、取消和重新打开待办；完成和取消保留待办及其历史。
- 完成或取消后停用相关提醒，沿用既有生命周期规则。
- 重新打开不自动恢复旧提醒，界面明确告知，需要时由用户重新设置或启用。
- 状态改变应能从列表和详情辨认，不依赖对话中的自然语言回复判断是否成功。

### R-4 操作来源与历史

- 从本能力上线起，每次创建、内容编辑、状态改变，以及提醒的新增、修改、移除均保留可追溯记录。
- 每条记录展示执行者、时间、操作内容；编辑和状态变更能够查看修改前后的值。
- 执行者按真实执行链路区分：用户在管理页直接操作显示“你”；Agent 调用管理工具执行显示“Agent”；系统自动发生的业务变化显示“系统”；没有可靠来源的历史数据显示“来源未知”。
- 用户在聊天中要求 Agent 修改待办，实际工具执行仍归为“Agent”。执行者标识不用于推断其是否自主决策，也不意味着获得额外授权。
- Agent 操作关联执行时的会话，具备有效关联时可查看会话；关联不可用时如实说明，不影响已有历史的查看。
- 操作来源由实际执行链路确定，不依赖模型自报或从对话文案推断。
- 变更与对应历史保持一致，不能出现已修改却没有历史，或失败操作显示为已成功变更。
- 后续修改不覆盖既有历史；旧数据保留实际可知信息，不补造上线前的操作过程和执行者。
- 系统记录描述用户可理解的业务变化，普通后台扫描、重试等运行过程不充当人工或 Agent 操作。

### R-5 并发与 Agent 可见信息

- 用户正在编辑时，若待办被其他操作修改，保存时明确提示冲突并保留未保存输入，允许查看最新内容后再处理，不能静默覆盖。
- Agent 管理入口同样受到版本冲突约束；后续查询能够获取最新状态和可靠的操作来源。
- 管理页能获取人工或 Agent 已保存的最新变更，刷新后状态和历史一致。
- 人工修改本身不自动唤醒 Agent，也不被包装成新的用户对话指令。

## 不包含

- 日历、看板、协作分派或多用户权限体系。
- 不可恢复的硬删除、任意历史版本回滚及完整任务执行系统。
- 根据来源自动禁止 Agent 修改、推断用户意图或新增审批策略。
- 新增重复规则类型、改变现有提醒投递策略或把 Todo 与定时任务合并。
- 补造既有待办的完整历史。

## 验收条件

- [ ] **AC-1**：可从独立“待办”入口查看列表、切换状态、搜索并打开详情；列表包含提醒摘要及最近操作来源。
- [ ] **AC-2**：可新建并编辑待办标题、描述、提醒时间与现有重复规则，也可添加和移除提醒；成功结果在重新打开页面或应用后保持一致。
- [ ] **AC-3**：完成、取消、重新打开行为正确；完成或取消停用提醒，重新打开不自动恢复旧提醒且有明确说明。
- [ ] **AC-4**：人工创建或修改、Agent 工具创建或修改、状态变化及提醒变更均有对应历史，能辨认执行者、时间和修改前后内容。
- [ ] **AC-5**：聊天委托 Agent 操作仍标识为 Agent，并关联可用的来源会话；来源不由模型参数或普通文本伪造。
- [ ] **AC-6**：系统业务变化与人工、Agent 操作可区分；缺少来源的旧记录如实显示未知，既有内容和状态保持可用，不生成虚构历史。
- [ ] **AC-7**：失败或冲突不会留下成功变更记录；成功变更与对应历史同时保留，后续编辑不覆盖先前历史。
- [ ] **AC-8**：人工编辑与 Agent 修改交错时，冲突不静默覆盖且保留人工输入；Agent 重新查询可获得最新状态及可靠来源。
- [ ] **AC-9**：人工直接修改不自动触发 Agent 对话；列表、详情和历史在刷新后反映同一份已保存事实。
- [ ] **AC-10**：核心行为有自动化验证，项目统一检查通过；桌面视觉验收方式在实施阶段按项目规则确认，最终交付由用户验收。
