## 状态

## 背景

现有对话展示已具备连续工具活动分组、逐轮执行过程收纳和无阶段消息的展示兜底，但这些能力使用不同的资格条件。自定义连接可能实际返回阶段标签，却因该轮的预设模式无法进入原生展示，也无法进入无阶段兜底，导致结束后的过程没有自动收起。

相关既有需求为 [091](../091-compact-tool-call-activity/requirement.md)、[115](../115-assistant-phase-execution-disclosure/requirement.md)、[118](../118-long-session-query-and-cancellation/requirement.md) 和 [121](../121-model-connections-and-custom-models/requirement.md)。本需求统一其交叉处的展示契约，保留消息和运行事实的完整性。

## 目标

- 内置与自定义连接、有阶段、无阶段和部分阶段的模型，使用一致的执行过程收纳体验。
- 每条消息的阶段语义、工具状态、整轮生命周期和用户展开选择各自有明确含义。
- 阶段数据缺失或不完整时，已结束的工具过程仍可合理收纳，正文与必要交互保持可达。
- 实时显示、历史加载、重连、模型切换和编辑重发保持一致，便于后续继续扩展模型接入。

## 范围

### 包含

- 统一桌面对话的执行过程资格判断、内容归组、默认展开与收起规则。
- 保留连续工具活动及详情、逐轮计时入口、当前活动尾部和现有交互入口。
- 接纳实际收到的合法消息阶段，解除预设 native / legacy 模式对展示的排他性限制。
- 保留无阶段、部分阶段、旧会话与异常状态的兼容能力。
- 核对能力声明、阶段提示词、消息身份、阶段校验和展示的职责；调整展示时保护模型调用与下游业务。
- 补充确定性回归，验证实时、历史和恢复路径的一致性。

### 不包含

- 上下文摘要压缩、Responses compact 接口或模型上下文预算调整。
- 解析正文中的自然语言、XML 或 marker 来猜测原生阶段。
- 为折叠效果改写历史阶段、伪造 final_answer，或把展示推断回传模型。
- 因缺少 final_answer 自动续跑模型、重试生成或再次执行工具。
- 新增用户必须配置的阶段能力开关，或为 CPA 单独编写界面分支。
- 重新设计工具卡片、规划阶段系统或 IM、语音、桌宠的阶段视觉。
- 批量改写旧会话或跨进程持久化用户手动展开选择。

## 功能要求

### 1. 统一事实与展示边界

- commentary、final_answer 与未知阶段保留各自含义；commentary 是用户可见过程文字，不是隐藏推理。
- 支持 Responses 不等于每条消息都有可靠阶段。实际收到的合法标签不能因为连接属于自定义或预设为 legacy 而被忽略。
- 单条消息完成、阶段标签、工具完成和整轮终态分别表达；阶段不能替代运行结果。
- 展示的默认收起只表达过程被收纳，不声明任务目标已经达成。
- 同一组有效消息和运行事实适用同一套展示规则，不按当前供应商、模型名称或连接类别分叉。

### 2. 过程与正文的可见性

- 保留当前连续工具分组、内部时序、详情访问及逐轮展开入口，不跨轮合并过程。
- 阶段完整且一致时，按其原生含义区分过程文字与最终回答。
- 无阶段和部分阶段时，允许依据可靠的消息顺序与运行终态做展示兜底；兜底不改变原始正文和阶段。
- 对只有 commentary、没有 final_answer 的正常结束轮次，允许收起已结束的工具过程；末尾完整正文保持在外，不把它标成最终回答。
- 没有正文、消息顺序不可信或阶段冲突时，不能虚构收尾回答；保护用户需要看到的文本和异常。
- 只有直接回答、没有过程内容时，不创建空的折叠区域。

### 3. 生命周期与用户控制

- 运行中默认保持当前活动可见；模型消息或某个工具完成不能让整轮看起来已经结束。
- 正常结束后，在可靠边界内自动收起过程；仍在运行的工具不得被作为已结束过程处理。
- 失败、取消、中断、不完整或无法确认终态时，保守展示，运行结果和异常信息保持可见。
- 文件和命令授权、停止等现有 Dock 操作，以及仍需处理的平台登录等交互，持续可达。
- 现有工具失败、警告和中性活动摘要的语义保持；单个工具失败不等同于整轮失败。
- 用户手动展开或收起优先于自动默认值，后续流式更新不得反复覆盖选择。
- 搜索和引用导航命中折叠内内容时先展开再定位；复制、选择引用和原消息关联保持完整。

### 4. 历史与下游兼容

- 历史展示由相应轮次自己的有效产品事件决定，不查当前模型配置重新解释过去。
- 保留原始消息身份、逻辑顺序、阶段完成更新和编辑重发的有效分支边界。
- 实时流、推送、历史加载与重连对同一有效事件序列产生一致结果。
- 旧会话缺少阶段字段时继续可读；缺少可信运行身份或终态时不虚构事实。
- 展示更新不改变模型回放、记忆、搜索、上下文摘要、IM、语音、桌宠及内部结构化生成原有的正文消费契约。
- 阶段提示词是否启用与界面是否可折叠分开处理，不为修复界面静默改变所有模型的生成行为。

## 验收条件

- [x] AC-01：内置和自定义连接在相同消息、工具与运行事实下产生相同展示，不受旧模式标签阻断。
- [x] AC-02：完整原生阶段按语义展示；流式阶段更新在结束后、历史恢复后保持一致。
- [x] AC-03：无阶段正常结束轮次保持展示兜底；末尾逻辑正文及其全部片段留在外，不误用迟到片段。
- [x] AC-04：自定义连接返回部分阶段或只有 commentary 时，正常结束后的工具过程可收起，末尾正文可见，原始阶段保持不变。
- [x] AC-05：运行中、等待操作、失败、取消、不完整、阶段冲突及不可信旧终态不会隐藏必要活动、交互或异常，也不制造最终回答。
- [x] AC-06：连续工具、交错正文、多个 assistant item、空正文、工具尾部和纯直答均保持顺序、身份及正确的非空折叠边界。
- [x] AC-07：手动开关、搜索定位、复制、引用与滚动跟随不回归；现有授权和停止入口保持可达。
- [x] AC-08：实时、推送、历史、重连、切换模型和编辑重发对有效事件序列产生一致结果；无需批量迁移旧会话。
- [x] AC-09：模型回放保留原始阶段和正文；记忆、搜索、IM、语音、桌宠及内部生成不因展示兜底改变文本消费或触发额外调用。
- [x] AC-10：上述行为有确定性回归覆盖，项目检查通过；真实桌面视觉验收按用户后续授权执行，未执行时明确记录。
