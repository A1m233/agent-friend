## 现状与边界

消息已经携带真实 phase、逻辑 mid 与 itemIndex；产品事件投影保存逐 run 终态。展示分别经过连续工具分组、执行区策略和展开控件。当前 stores/assistantPhase 中的 native 门禁与页面的 inferred 分支互斥，导致合法部分阶段数据无法收纳。

## 统一策略

1. 在 executionDisclosurePolicy 中一次读取消息身份、原始 phase、工具顺序、阶段校验及 run 终态，返回过程正文 ID 集合、保留正文 ID、默认收起与诊断来源。executionSections 只按这个结果分区，不按来源再走两套分类。
2. 诊断来源 native / inferred / mixed / none 仅解释依据，不是供应商模式；阶段完整时 native，完全无阶段时 inferred，部分阶段时 mixed。
3. 按逻辑 mid 的首次出现识别正文顺序，保留所有同 mid 片段。缺 ID、同 ID 阶段冲突、已记录 conflict 或 final 后仍有工具/其它阶段等不可信事实保守展示。
4. 显式 final 始终可见；没有 final 时保留末尾非空逻辑正文。末尾正文开始后仍有工具时，不把它作为收尾边界自动收起。
5. 明确 commentary 可以进入过程，但无 final 时保留末尾正文。混合阶段中的 unknown 保持区外；完全无阶段只在可信正常终态下，按既有顺序规则收纳末尾正文之外的文本。
6. 自动收起需要可信 run ID、正常终态、非空收尾边界、没有仍运行工具/可见运行错误或阶段冲突；显式 pending 阶段状态未完成时不自动收起。missing_final 本身不再阻断展示兜底，也不伪造 final。
7. 运行中允许工具过程与已知过程文字参与统一手动开关，默认展开；未知正文保留。异常终态保守展开，不让手动状态隐藏整轮错误。无正文、缺 run 身份或旧终态不可信时不制造收尾区域。
