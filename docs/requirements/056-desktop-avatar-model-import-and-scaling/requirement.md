# 056 · Desktop Avatar Model Import and Scaling

## 状态

CONFIRMED

## 背景

037 已经建立桌宠模型资源目录与 avatar model catalog，038 已经把 Spine 3.8 的明日方舟小人接入正式 pet runtime，040 则补齐了内置模型安装、设置页模型选择与跨窗口持久化。当前用户已经可以在设置页切换 Hiyori 与首批内置 Ark Spine 模型，但模型能力仍停留在“使用应用预置清单”：

- 用户不能把自己已有的明日方舟 Spine 3.8 模型放入用户模型目录并直接使用。
- 设置页没有打开用户模型目录的入口，模型目录变化也不会被运行中的应用自动发现。
- runtime 虽然已经按可见边界归一化模型尺寸，但不同模型的身体比例、武器、披风、尾巴与 idle 姿态不同，归一化后仍可能产生明显的视觉大小差异。
- 当前 normal / mini 只有固定的 `1.0 / 0.5` 比例，用户不能按自己的桌面空间和使用习惯调整模型大小或缩小模式比例。

本需求聚焦两个直接面向用户的能力：让用户通过受管理目录自行加入 Spine 3.8 模型，以及在现有“桌宠”设置页调整当前模型大小和缩小模式比例。它不扩展成完整模型编辑器、模型市场或多版本 Spine 平台。

## 目标

- 复用现有“桌宠”设置页，为用户提供打开 Spine 3.8 模型目录的入口。
- 用户把完整模型文件夹放入目录后，应用自动发现并更新模型列表，不要求手动刷新或重启。
- 第一阶段明确支持 Spine 3.8 二进制模型目录，优先覆盖明日方舟常见的 `.skel + .atlas + 一张或多张贴图` 结构。
- 只有完整且可读取的模型才进入可选列表；复制中的半成品或损坏模型不影响已有可用模型。
- 用户可以为每个模型独立调整显示大小，以修正自动归一化后的主观视觉差异。
- 用户可以全局调整 mini 模式相对于 normal 模式的缩小比例。
- 保持现有模型选择、内置模型安装、拖拽、贴边、ActionBar、气泡锚点与跨窗口设置同步能力不退化。

## 范围

### 包含

#### 复用现有桌宠设置页

- 继续使用现有设置中心“桌宠”分类和 `AvatarModelPanel`，不新增平行的模型管理分类或独立模型管理窗口。
- 当前模型选择继续来自 installed avatar model catalog；内置模型与有效的用户模型出现在同一选择入口中。
- 设置页在现有模型选择基础上增加：
  - 当前模型的“模型大小”调整。
  - 全局“缩小模式比例”调整。
  - “打开 Spine 3.8 模型目录”入口。
  - 用户模型发现、加载或校验异常的可理解状态提示。

#### Spine 3.8 用户模型目录

- 应用提供一个固定、受管理的 Spine 3.8 用户模型目录，并能从设置页直接打开。
- 用户通过操作系统文件管理器自行复制、更新或移除模型文件夹；应用不要求用户选择任意散文件路径。
- 目录遵循“一层子目录代表一个模型”的基本约定。
- 每个模型目录至少需要包含：
  - 一个 Spine 3.8 二进制 `.skel` 骨骼文件。
  - 一个与模型对应的 `.atlas` 文件。
  - atlas 实际引用的一张或多张贴图。
- 用户模型继续使用稳定模型 ID 参与选择和设置关联；调用方不以任意绝对路径作为模型身份。
- 用户导入资源仍属于用户本地资产，应用不将其视为可随产品分发的内置素材。

#### 自动发现与目录变化

- 应用运行期间自动感知用户模型目录中的新增、修改、重命名和移除，不要求用户点击“刷新模型”或重启应用。
- 批量复制一个模型产生的连续文件变化应被视为一次目录更新过程，不能让模型列表在复制期间反复闪烁或暴露半状态。
- 新模型只有在必要文件齐全且能够被 Spine 3.8 runtime 读取后，才进入可选模型列表。
- 新模型复制尚未完成、文件暂时不可读或 atlas 引用资源缺失时：
  - 不作为可选模型发布。
  - 不影响其他已安装模型继续使用。
  - 设置页提供可理解的异常或等待状态。
- 已经可用的用户模型被原地更新时，在新版本完成校验前不得用半成品 catalog 状态覆盖上一份可用记录。
- 用户移除模型目录后，模型列表自动更新；如果移除的是当前模型，桌宠稳定回退到默认 Hiyori，并保留可排查信息。
- 目录变化没有导致有效 catalog 变化时，不应让设置页或 pet 窗发生无意义的重复刷新。

#### 当前模型独立缩放

- 设置页为当前选中模型提供连续的“模型大小”调整，而不是只增加若干固定尺寸档位。
- 模型大小按稳定模型 ID 独立保存，适用于内置模型和用户模型。
- 初次使用某个模型时默认值为 `100%`，表示使用 runtime 自动归一化后的标准大小。
- 切换模型时恢复该模型上次保存的大小；调整一个模型不改变其他模型的大小。
- 提供恢复当前模型默认大小的能力。
- 调整模型大小时，pet 窗实时反映变化，不要求重新选择模型或重启应用。
- 用户模型大小作为自动归一化后的修正比例，不替代现有模型 bounds / fit 归一化能力。

#### 全局缩小模式比例

- 用户可以设置 mini 模式相对于 normal 模式的缩小比例。
- 缩小模式比例是全局桌宠行为偏好，不按模型分别保存。
- 默认值保持当前行为的 `50%`，已有用户升级后不发生视觉突变。
- 当桌宠已经处于 mini 模式时，调整比例应实时反映到桌宠。
- 缩小比例需要限制在安全可用范围内，避免桌宠小到无法识别或交互；具体上下限由技术方案和桌面视觉验证确定。
- 最终显示效果遵循以下用户语义：
  - normal 模式使用“自动归一化 × 当前模型大小”。
  - mini 模式在 normal 结果之上再乘“缩小模式比例”。

#### 用户可见稳定性

- 模型缩放、mini 比例变化和用户模型自动发现不能破坏现有：
  - normal / mini 切换与贴边、恢复位置。
  - 桌宠拖拽和跨屏行为。
  - ActionBar 相对模型定位与交互。
  - bubble anchor / conversation owner 跟随。
  - alpha hit-test 与鼠标穿透。
- 用户模型不可用或失效时，错误应被限制在该模型，不得导致设置窗口或 pet 窗整体崩溃。

### 不包含

- 不新增独立模型管理窗口或设置导航分类。
- 不提供应用内删除、重命名、移动或复制模型文件的操作。
- 不提供 ZIP / 压缩模型包导入与解压。
- 不提供 Live2D 用户模型导入。
- 不支持 Spine 4.0 / 4.1 / 4.2 / 4.3 或其他非 3.8 runtime 数据。
- 不支持 Spine 3.8 JSON skeleton；本期只支持二进制 `.skel`。
- 不提供用户编辑 idle / thinking / speaking / tap / drag 等动作映射的 UI。
- 不做模型预览编辑器、动画调试器、皮肤编辑器、模型下载、模型市场或远程 catalog。
- 不新增模型授权审核或版权判定能力；用户负责确保本地资源的使用符合其授权条件。
- 不重新设计 037 的 avatar model backend contract，也不重做 038 已有 Spine 3.8 renderer。

## 关键约束

- 用户模型资产继续落在项目统一的 avatar model 用户数据目录，路径入口以 `frontend/src-tauri/src/paths.rs` 为准；不得开放任意本地目录作为正式 runtime 资源根。
- settings 只承载当前模型选择、模型大小和缩小比例等轻量偏好，不保存模型大文件或任意散路径。
- 文件变化只是触发模型目录重新评估的信号，用户可见 catalog 必须以完整扫描和校验后的稳定结果为准。
- 自动发现能力必须独立于设置窗口是否打开，不能把模型目录监听生命周期绑定到某个 React 页面。
- 文件监听与目录扫描需要覆盖 Windows、macOS 和 Linux，并遵守项目跨平台开发约定。
- Spine 3.8 与其他 major / minor runtime 数据不兼容；不把“能找到 `.skel` 文件”误判为“模型可用”。
- 用户模型目录内的路径解析必须受目录边界约束，不能通过相对路径、符号链接或等价机制读取模型根之外的文件。

- [x] 用户模型能够被正式 pet runtime 加载并显示，至少能选择一个可用初始动画；缺少自定义动作映射时沿用现有安全 fallback。

## 开放问题

- “模型大小”和“缩小模式比例”的具体滑杆范围、步长与展示格式，需要在技术方案和桌面视觉验证阶段结合可交互下限确定。
- 用户模型稳定 ID 与轻量 metadata 的具体落盘形式，需要在技术方案阶段在中央 catalog 与模型目录 sidecar 之间选择；无论采用哪种形式，用户可见身份都不能依赖任意绝对路径。
- 模型目录存在多个 `.skel` 或多个可能的 `.atlas` 组合时，本期是整体判为无法自动识别，还是在符合明确同名规则时选取唯一组合，需要在技术方案阶段收敛。
- 用户原地覆盖一个正在使用的模型时，runtime 何时重载以及失败后如何保持上一份可用模型，需要在技术方案阶段结合当前资源缓存行为确定。
