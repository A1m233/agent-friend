# 内置表格与 Word Skills 及基础处理

## 状态

CONFIRMED

## 背景

151 已支持任意附件进入会话工作目录，由 Agent 按需读取。文件托管不等于格式理解：当前产品内置 PDF 与图片处理能力，但缺少 Excel、Word、PowerPoint 的完整使用指导和执行依赖。

用户确认优先原样引入 OpenAI 的公开 Skills，再补齐 AF 的执行环境，沿用 139 的接入方式。本期收窄为表格与 Word 的结构化读取和基础创建、编辑，不先自行设计专用解析工具，也不把新格式逻辑放回附件接收链路。

## 目标

- 为表格与 Word 提供可实际使用的内置 Skill，优先解决附件已经落盘却无法理解内容的问题。
- 保留所选上游 Skill 的完整内容，由产品提供本期基础处理所需的依赖和执行能力；完整资源导入不等于全部上游工作流均已交付。
- 从用户上传或明确授权的文件出发，按需读取和处理，并取得可核对的真实结果。
- 普通用户无需安装 Codex、系统 Python、Node.js 或 Microsoft Office 才能使用已交付的基础能力。
- 文件托管、Skill 指导、执行环境、权限与模型视觉能力保持解耦。

## 范围

### 包含

- 核对 OpenAI 上游 Skill 的可用来源、固定版本、许可证、引用文件和依赖，区分公开版本与当前 Codex 专属运行包。
- 引入公开历史版本的 spreadsheet 与 doc 两项 Skill，不因文件名相同就宣称与当前 Codex 能力完全等价。
- 原样保留上游 SKILL.md、脚本、引用文档、metadata、资源和许可证，记录精确版本与文件内容身份。
- 补齐基础处理的产品内置 Python 依赖，复用现有运行入口、只读共享资源和会话隔离。
- 表格支持 XLSX、CSV、TSV 的结构化读取与基础创建、编辑；读取工作表、单元格值和公式，按任务限定范围，保留公式表达式并区分缓存结果与当前计算结果。
- Word 支持 DOCX 正文段落和表格的结构化读取，以及基础创建、编辑；不承诺还原所有复杂文档结构或排版。
- 让 Agent 能发现和使用相应 Skill，衔接当前会话文件并取得可核对的实际内容；需要视觉检查或公式重算时说明本期能力限制。
- 大文件按任务范围处理；正确区分读取范围、公式与缓存结果、提取内容与视觉观察，不把部分证据表述为完整理解。
- 依赖缺失、损坏、不支持格式、加密文件和权限不足时如实反馈，不以其他环境偶然可用掩盖产品缺口。
- 现有命令审批、沙箱、取消、进程清理、工作目录和用户数据边界继续适用。
- Windows x64 产品基线与打包验证；源码及脚本保持现有跨平台约定，未实机验证平台单独标注。

### 不包含

- PowerPoint Skill、PPTX 处理、受管 Node.js、LibreOffice 及新增字体工具链。
- Office 页面渲染、视觉排版验收、公式重新计算和图表图片导出；上游资源中的相关脚本仍原样保留，但不能标记为本期已提供能力。
- 复制来源或分发条件未确认的 Codex 专属运行包，或要求用户借用 Codex 安装目录。
- 重新编写一套平行的 Office 解析协议、格式工具注册框架或独立权限通道。
- 静默裁剪或修改上游 Skill；确需兼容修改时，说明具体不兼容点并重新确认。
- 默认获得云端 Google Docs/Sheets/Slides、在线 Excel 或用户 Office 应用的控制能力。
- 保证所有旧 Office 格式、宏、外部链接、嵌入对象和复杂排版均兼容；不因支持现代文件格式就外推到全部 Office 功能。
- 在用户只要求读取时改写原件，或因文件内容包含指令就自动执行其中的宏、脚本或联网请求。

## 验收条件

- [x] AC-1：选定 Skill 全部文件与固定上游版本一致，来源、许可证及内容摘要可追溯。
- [x] AC-2：Skill 在真实产品中可发现、可激活；相关任务能使用正确能力，不会只依赖模型猜测安装路径。
- [x] AC-3：不借用 Codex 或系统开发环境，完成各 Skill 已声明交付范围内的最小真实文件工作流。
- [x] AC-4：XLSX 多工作表、公式与缓存边界、CSV/TSV，以及 DOCX 段落和表格均有代表性读取样本与可核对结果；基础创建、编辑的输出可重新打开并核对内容，读取请求不改写原件。
- [x] AC-5：工作流能衔接会话附件与已有文件授权，原件保护、会话隔离和按需投递语义不退化。
- [x] AC-6：宿主能力说明明确本期不提供 Office 渲染和公式重算；Skill 原文与宿主能力说明保持分离，失败和限制如实反馈，不能以空输出或退出码替代文件结果检查。
- [x] AC-7：依赖来源、版本、完整性、许可证、离线基线和会话生命周期受治理；不污染用户全局环境。
- [x] AC-8：确定性验证覆盖基础读写、损坏或加密等失败边界及执行环境治理；既有 PDF 能力不退化，项目检查与适用的 frozen runtime 验证通过，真实模型验证另行授权。
- [ ] AC-9：用户确认实际能力与限制后验收完成，相关用户说明同步进入既定 Guide 发布流程。
