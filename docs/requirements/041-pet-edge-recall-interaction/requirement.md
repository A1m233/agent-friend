# 041 · 桌宠边缘召回交互

> Pet Edge Recall Interaction
>
> 将桌宠 ActionBar 里的"隐藏桌宠"重新设计为"收起到边缘"：桌宠不再直接从桌面消失，而是进入一个低打扰、可发现的 mini 展示。用户从大模型点击入口时，同一桌宠形象等比例缩小并移动到屏幕边缘；用户从小模型点击入口时，恢复桌宠大小。既有点击、拖拽、tap reaction、命中判定等交互链路保持复用；系统托盘继续保留完全隐藏/显示的兜底能力。

## 1. 背景

### 1.1 现状

- [需求 019](../019-pet-actionbar-rework-and-settings-shell/) 在桌宠 ActionBar 中新增了"隐藏桌宠"按钮，点击后调用 `hide_pet`，直接把 `pet` 窗口整体 `hide()`。
- 隐藏后，桌面上没有任何可点击或可 hover 的召回痕迹；用户只能通过系统托盘菜单"显示/隐藏桌宠"找回。
- 这个体验缺口已登记为 [issue 013](../../issues/013-pet-recall-from-desktop/)：它不是代码 bug，而是桌宠隐藏 / 召回交互未设计完整。
- 同类桌宠调研里，Clawd on Desk / Clyde 等产品有 mini mode / edge mode：桌宠靠边缩小或藏在边缘，hover 或点击即可召回；NekoAI 等产品也把托盘 / 右键菜单作为兜底控制，而不是唯一桌面召回路径。本仓库既有 [`desktop-pet-form-factor`](../../explorations/desktop-pet-form-factor/) 和 [`desktop-completeness`](../../explorations/desktop-completeness/) 探索也把隐藏、右键、托盘、尺寸切换列为桌宠标准交互的一部分。

### 1.2 这次要做什么

本需求新增一个桌宠可见性状态：**边缘召回态**。

用户在正常显示态下点击 ActionBar 的收起按钮后，桌宠不会完全消失，而是：

- 使用同一个桌宠形象；
- 等比例缩小到低打扰尺寸；
- 移动到屏幕边缘或角落附近；
- 保持桌面可见、可点击、可 hover；
- 保留既有桌宠交互逻辑，作为"我还在这里，可以随时叫回来"的召回入口。

系统托盘菜单继续保留完全隐藏/显示能力，用于用户确实希望桌面上不留下任何桌宠痕迹的场景。

### 1.3 设计共识

- **不是独立召回点**：边缘召回态不换成独立图标、不新造一套召回 UI；它仍是桌宠形象本身，只是换成 mini 尺寸并移动到边缘。
- **尺寸状态与贴边行为解耦**：使用正常尺寸还是 mini 尺寸是用户偏好，走 settings 持久化；移动到边缘是从正常尺寸切到 mini 尺寸时的一次性行为，不作为独立状态持久化。
- **模式拆分保留**：前端仍应能区分正常显示态与边缘召回态，方便后续扩展 mini 动画、贴边吸附、低打扰气泡等能力。
- **ActionBar 自适应与状态解耦**：ActionBar 是否横排 / 竖排只取决于桌宠是否靠近屏幕边缘，不取决于当前是否为边缘召回态。用户把正常态桌宠拖到边缘时，也应自然得到竖向 ActionBar。
- **托盘完全隐藏不改语义**：ActionBar 的收起到边缘与托盘的完全隐藏是两种不同能力，不互相替代。

## 3. 非目标（Out of Scope）

- 不做右键菜单。
- 不做全局热键召回。
- 不做桌宠位置持久化。
- 不做新的独立召回窗口。
- 不新增托盘菜单复杂项，如勿扰、尺寸 S/M/L、persona 切换。
- 不调整语音通话、模型资源管理、Live2D 调试器主线能力。
- 不要求边缘召回态接入专属 mini 动画；本期只要求同一形象缩放与贴边。
- 不重做 pet overlay / passthrough 底座；应沿用现有整屏 transparent overlay 与 hit-test 机制。

## 4. 核心需求详述

### 4.1 状态语义

- **R-4.1.1 正常尺寸态**：桌宠以正常尺寸显示，保持现有 hover ActionBar、点击、拖拽、气泡跟随等行为。
- **R-4.1.2 mini 尺寸态**：桌宠以缩小比例显示。用户从正常尺寸切到 mini 尺寸时，桌宠应移动到屏幕边缘或角落附近；它仍是桌面可见元素，不等同于窗口 hidden。
- **R-4.1.3 完全隐藏态**：`pet` 窗口整体隐藏，桌面上不保留桌宠形象或召回点；该状态由托盘菜单触发和恢复。
- **R-4.1.4 状态边界**：ActionBar 入口只负责正常显示态 ↔ 边缘召回态；托盘菜单负责完全隐藏 / 显示兜底。

### 4.2 ActionBar 收起入口

- **R-4.2.1 入口语义**：ActionBar 原 `EyeOff` / "隐藏桌宠"入口改为尺寸切换语义：正常尺寸下 tooltip 为"缩小桌宠并移动到边上"，mini 尺寸下 tooltip 为"恢复桌宠大小"。
- **R-4.2.2 点击行为**：正常尺寸下点击该入口后，切到 mini 尺寸并移动到边缘；mini 尺寸下点击该入口后，恢复正常尺寸。
- **R-4.2.3 不调用完全隐藏**：该入口不应再直接调用 Rust `hide_pet` 把 `pet` 窗口整体隐藏。
- **R-4.2.4 mini 尺寸态操作**：mini 尺寸态下应有恢复正常尺寸的入口；该入口可以在 ActionBar 中提供，也可以通过点击桌宠触发，具体由 design 决定。

### 4.3 边缘召回态展示

- **R-4.3.1 同一形象**：边缘召回态使用当前选中的同一个桌宠形象，不替换成单独图标或静态元素。
- **R-4.3.2 等比例缩小**：形象应按统一比例缩小，保持原本宽高比例与透明轮廓关系。
- **R-4.3.3 进入时贴边**：从正常显示态进入边缘召回态时，桌宠应移动到屏幕边缘或角落附近。贴哪条边 / 哪个角应基于当前桌宠位置和屏幕边界计算，让移动方向符合用户预期。
- **R-4.3.4 保持可见**：边缘召回态不能完全离屏；应保留足够可见面积，让用户知道桌宠仍在桌面上。
- **R-4.3.5 后续拖动**：用户在 mini 尺寸态拖动桌宠后，仍保持 mini 尺寸，直到用户主动恢复正常尺寸；不要求持续吸附或锁在边缘。

### 4.4 交互复用

- **R-4.4.1 点击 / tap reaction**：边缘召回态下，点击桌宠仍应走当前形象 runtime 的点击反应链路；不为边缘召回态另造点击逻辑。
- **R-4.4.2 拖拽**：边缘召回态下，拖拽仍应沿用现有拖拽机制；拖拽时不应因为缩放导致 pointer 丢失或穿透错误。
- **R-4.4.3 hit-test**：边缘召回态下仍应沿用现有 alpha hit-test / 矩形 fallback 机制；透明区域继续穿透到底层桌面。
- **R-4.4.4 bubble 锚点**：若桌宠气泡出现，应继续跟随当前形象的位置；不得残留在进入边缘召回前的旧位置。
- **R-4.4.5 运行状态**：thinking / speaking / error / idle 等状态驱动不因进入边缘召回态而中断。

### 4.5 恢复正常尺寸

- **R-4.5.1 可发现入口**：mini 尺寸态必须提供从桌面直接恢复正常尺寸的入口，不要求用户去托盘菜单。
- **R-4.5.2 恢复尺寸**：恢复后，桌宠回到正常尺寸。
- **R-4.5.3 恢复位置**：恢复时应以当前小模型位置为参考，并做屏幕边界约束，避免恢复后形象跑出屏幕。
- **R-4.5.4 状态保留**：恢复正常尺寸后，当前 avatar runtime、pet phase、选中模型、气泡订阅等状态不应重置。

### 4.6 ActionBar 自适应布局

- **R-4.6.1 状态无关**：ActionBar 横向 / 竖向布局不读取桌宠可见性状态，只根据当前 sprite 与 viewport 的空间关系决定。
- **R-4.6.2 默认横向**：桌宠远离屏幕边缘时，ActionBar 保持当前横向 chip 形态。
- **R-4.6.3 靠边竖向**：桌宠靠近屏幕左 / 右 / 上 / 下边缘导致横向 ActionBar 空间不足或体验拥挤时，ActionBar 自动切换为竖向排列。
- **R-4.6.4 贴边可用**：竖向 ActionBar 不应溢出屏幕；按钮 tooltip、hover、点击命中、分页或溢出策略需保持可用。
- **R-4.6.5 既有 hover gate 保留**：ActionBar 仍默认隐藏，鼠标进入桌宠或 ActionBar group 后显示，离开后渐隐；不因横竖布局变化破坏现有 hover gate。

### 4.7 托盘兜底

- **R-4.7.1 完全隐藏**：托盘菜单"显示/隐藏桌宠"继续允许用户把 `pet` 窗口整体隐藏。
- **R-4.7.2 显示恢复**：从托盘菜单恢复显示时，应进入一个用户可理解的桌宠可见状态；不得恢复到无可见形象、无召回入口的中间态。是否强制恢复正常显示不在需求侧锁死，由 design 结合持久化语义确定。
- **R-4.7.3 兜底不替代召回**：托盘菜单是兜底路径，边缘召回态的桌面直接恢复路径是本需求的主路径。

### 4.8 尺寸偏好持久化

- **R-4.8.1 持久化内容**：用户当前选择的形象尺寸应持久化，至少区分正常尺寸与 mini 尺寸。
- **R-4.8.2 重启一致性**：应用重启后，桌宠应恢复到用户上次选择的形象尺寸；若上次已经是 mini 尺寸，重启后保持 mini 尺寸，但不因上次曾移动到边缘而再次自动贴边。
- **R-4.8.3 使用现有 settings 通路**：持久化应沿用项目现有桌面端 settings 体系（前端 `useSetting` / Rust `settings.rs` / `settings.json`），不新增 `localStorage`、零散 JSON 文件或 ad-hoc 存储。
- **R-4.8.4 位置持久化不在本期**：本期只要求持久化尺寸偏好；贴边状态与边缘召回态的精确屏幕位置均不做任意拖拽位置记忆。

## 5. 使用约束

- **前端 UI 约束**：`frontend-ui-conventions` 生效。新增交互件优先复用 `components/ui/` 封装件；颜色、尺寸、圆角、阴影、动效等视觉 token 不得散写硬编码。
- **持久化约束**：尺寸偏好持久化必须沿用现有 settings 架构：前端类型在 `frontend/src/lib/settings/` 扩展，Rust 类型与 `set_setting` 分支在 `frontend/src-tauri/src/settings.rs` 扩展，落盘路径继续由 `paths::settings_store_path()` 管理。贴边位置 / 吸附状态不进入 settings。
- **视觉验收约束**：本需求直接影响 Tauri 桌面 pet 窗、透明 overlay、hover、拖拽、边缘布局，验收时必须按 `frontend-visual-verification` / `desktop-visual-inspection` 使用真实桌面端观察，不能只用 Vite web 预览下结论。
- **测试约束**：缩放比例、贴边位置、ActionBar 横竖布局判定、屏幕边界 clamp 等可断言逻辑应抽成纯函数并配单测。纯视觉体感和真实桌面窗口行为用手动验收记录补充。
- **改动范围约束**：优先局限在 pet 页面 / avatar surface profile / ActionBar / Rust hide-show bridge 的最小必要改动；避免触碰语音、模型资源、Live2D 调试器等并行主线。
- **真实 LLM 调用授权**：本需求不需要调用真实 LLM；如验收时临时触发 agent 对话或 push 行为，应使用既有 dev/mock 路径，真实 LLM 另行授权。

## 6. 验收标准

- **AC-1 ActionBar 收起入口语义**：正常尺寸下入口 tooltip 为"缩小桌宠并移动到边上"；mini 尺寸下入口 tooltip 为"恢复桌宠大小"。
- **AC-2 mini 展示**：从正常尺寸切到 mini 尺寸后，同一桌宠形象等比例缩小并移动到屏幕边缘或角落附近，保持足够可见面积。
- **AC-3 桌面直接恢复**：用户不通过系统托盘，仅从桌面上的 mini 尺寸态即可恢复正常尺寸。
- **AC-4 交互复用**：mini 尺寸态下点击 / tap reaction / 拖拽 / hover / 透明区穿透仍可用，不出现缩小后点击不到、拖拽断裂或整屏拦截鼠标的问题。
- **AC-5 恢复行为**：恢复正常尺寸后，位置基于当前小模型位置合理 clamp，avatar runtime / pet phase / 当前模型不重置。
- **AC-6 ActionBar 横竖自适应**：桌宠远离边缘时 ActionBar 横向显示；桌宠靠近边缘时 ActionBar 自动竖向显示。该行为在正常显示态和边缘召回态都成立。
- **AC-7 既有路径零退化**：打开对话、打开设置、语音通话入口、IM 接入、dev 按钮、托盘显示/隐藏、bubble 跟随、Live2D/Spine 渲染不因本需求退化。
- **AC-8 尺寸偏好持久化**：用户切换到 mini 尺寸后重启应用，桌宠仍以 mini 尺寸出现；若上次只是贴边，重启后不应因此自动贴边。
- **AC-9 issue 013 闭环**：本需求验收完成后，`docs/issues/013-pet-recall-from-desktop/README.md` 状态改为 `resolved`，并写明由需求 041 / 对应 commit 修复。
- **AC-10 自动化门禁**：相关纯函数单测通过，`./scripts/check` 全绿。
- **AC-11 真实桌面验收**：至少在当前开发平台完成真实 Tauri 桌面端观察，记录边缘召回、恢复、靠边竖向 ActionBar、托盘完全隐藏/显示、重启后展示状态一致性的验证结果。

## 7. 已知风险与监测项

| # | 风险 / 监测项 | 处理 |
| --- | --- | --- |
| 1 | Live2D 与 Spine 两套 avatar surface 的缩放入口不同，可能导致实现范围扩大 | design 阶段先梳理共同 profile 边界；若无法一次覆盖两者，必须明确降级策略和验收影响 |
| 2 | 尺寸变化后 alpha hit-test 与 cursor 坐标可能出现偏差 | 缩放 / spriteScreen / hit-test 坐标链路必须配单测或真实桌面验证，尤其关注 mixed DPR |
| 3 | ActionBar 竖向布局可能与当前 carousel / TooltipButton 结构冲突 | design 阶段优先把横竖布局判定和布局计算抽成纯函数，避免在 JSX 中堆条件 |
| 4 | mini 尺寸态的 bubble 显示可能遮挡屏幕边缘或旧位置残留 | 本期只要求锚点跟随当前小模型；复杂低打扰 bubble 策略后续单独设计 |
| 5 | 从托盘显示时恢复正常尺寸还是 mini 尺寸可能影响用户预期 | 本期要求恢复到用户选择的持久化尺寸；贴边位置不由 settings 冷启动恢复 |
| 6 | settings 扩展会影响启动注入脚本和跨窗口同步 | 沿用既有 `Settings` 类型、默认值、`set_setting` 和 `settings://changed` 机制，并补对应测试 |
