# 自定义提醒声音

## 状态

CONFIRMED

## 背景

目前「设置 → 通知」提供气泡提示音开关，音源仅有「默认」。用户希望使用自己的音频作为提醒声音。需求 117 已建立统一气泡通知与播放时机，本需求在这条链路上增加自定义音源。

## 目标

用户可以在通知设置中导入本地音频，试听、替换或恢复默认；应用保存导入的音频，重启以及原文件移动或删除后仍可使用。

## 范围

### 包含

- 所有气泡通知共用一个音源，包括经现有通知链路展示的待办提醒、会话新回复、需要处理与异常结束。
- 支持导入 MP3、WAV 本地音频，并展示当前音源名称。
- 音频上限为 10 MiB、30 秒；超过限制明确拒绝。关闭自动提示音后仍可主动试听。
- 支持主动试听、替换自定义音源与恢复默认。
- 音源与开关持久化，沿用现有跨窗口设置同步。
- 导入音频随应用备份与迁移保存，避免音源配置与文件分离。
- 导入取消或失败不覆盖原有可用配置；失败时向用户说明原因。
- 保留现有通知响铃资格、去重、静默补位与声音开关语义；声音播放失败不阻塞气泡展示。

### 不包含

- 按通知类型、会话或单个待办分别配置声音。
- 在线音源库、音频生成、录音与剪辑。
- 修改通知触发条件或通知内容生成。

## 关键信息

- 既有通知需求：[117-unified-notifications](../117-unified-notifications/requirement.md)。
- 设置入口为「设置 → 通知」，自定义音源取代当前仅展示「默认」的固定音源项。
- 本需求不改变项目级技术栈；具体播放、校验与保存方案由 design.md 承载。
- 真实桌面端视觉验收与听感验证尚未执行，是否由 Agent 启动桌面端验收需另行确认。

## 验收条件

- [x] AC-1：能够从通知设置导入有效的 MP3 与 WAV，并显示选中的音源名称。
- [x] AC-2：可以试听当前音源、替换音源并恢复默认；试听不产生通知或消耗真实通知的播放资格。
- [x] AC-3：设置生效后，新展示且具备响铃资格的气泡统一使用当前音源，已有静默补位与去重行为保持不变。
- [x] AC-4：关闭气泡提示音后，真实通知不播放声音且气泡仍正常展示；重新开启后使用保存的音源。
- [x] AC-5：重启应用后配置与导入音频仍有效；移动或删除原始文件不影响已导入音源。
- [x] AC-6：取消选择、无效或不支持的音频、读取或保存失败不会覆盖原有可用配置；失败有明确反馈。
- [x] AC-7：设置跨窗口生效，播放失败不影响通知正常展示。
- [x] AC-8：旧设置可继续读取，未配置自定义音源的用户保持原有默认行为。
