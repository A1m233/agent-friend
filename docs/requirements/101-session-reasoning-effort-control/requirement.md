# 101 · 会话推理强度控制

## 状态

CONFIRMED

## 背景

agent-friend 已支持在桌面对话输入区查看并切换当前会话模型，但当前前端没有与模型配套的推理强度控制。用户选择 DeepSeek、Kimi 或 OpenRouter 下的不同模型后，只能接受项目或厂商当前默认的 thinking / reasoning 行为，无法在响应速度、token 消耗与复杂任务质量之间主动取舍，也无法从界面判断某个模型的推理能力是可关闭、可分档还是固定开启。

不同 provider 和模型的推理控制语义并不统一：有的模型支持关闭以及多个 effort 档位，有的只支持开关，有的强制推理且不可调整；部分模型在工具循环或后续轮次中还要求原样回传不可见的 reasoning 状态。若前端对所有模型硬套同一组“低 / 中 / 高”，或后端只透传一个通用字符串，可能产生无效选项、静默降级、请求失败或工具调用后的上下文断裂。

本需求在需求 061 已落地的会话模型选择基础上，引入模型能力驱动的会话级推理强度控制。交互采用单入口级联菜单：用户从同一个紧凑入口分别展开“模型”和“推理强度”子菜单；切换模型后，推理强度区域立即切换为目标模型真实支持的档位与默认值。

## 目标

- 用户可以在桌面对话输入区附近同时看见当前模型与当前推理强度，并在不离开会话的情况下调整。
- 模型和推理强度通过同一个紧凑入口组织为清楚的级联菜单，避免并排增加多个长期占位的控制件。
- 每个模型只展示自身真实支持的推理选项；可关闭、可分档、固定开启和不支持推理的模型都有准确且可理解的状态。
- 新会话 pending 配置和已有会话 effective 配置同时包含模型与推理强度；变更只影响当前会话，不修改全局默认模型或形成跨会话偏好。
- 一次完整 Agent run 冻结模型与推理配置，工具循环、重试、继续执行和诊断始终使用同一份有效配置。
- provider 要求的不可见 reasoning 状态能够安全回放，不向用户暴露原始思维链，也不污染普通聊天、搜索、记忆或日志。
- 当前架构为未来增加“按模型记住偏好”保留清楚扩展边界，但本期不实现该偏好能力。

## 范围

### 包含

#### 单入口级联交互

- 沿用当前输入区附近的模型选择入口，将其扩展为展示“当前模型 + 当前推理强度”的紧凑配置入口。
- 打开入口后，一级菜单至少包含“模型”和“推理强度”两项；每项展示当前值，并可通过级联子菜单查看和选择候选值。
- 指针 hover 或键盘焦点进入“模型”或“推理强度”一级项时，对应子菜单立即在右侧展开；点击一级项也只负责展开或保持对应子菜单，不关闭整个菜单。
- “模型”子菜单继续按 provider 组织当前统一模型目录中的可选模型，保留长名称可读性、当前项标记和键盘可达性。
- “推理强度”子菜单只展示当前模型真实支持的选项，并清楚标记当前有效值。
- 选择目标模型后，一级菜单中的模型值、推理强度摘要和推理强度子菜单立即切换到目标模型对应的能力集合。
- 选择具体模型或推理强度后，根菜单与当前子菜单保持打开；用户可以连续比较和调整，只有再次点击入口、点击菜单外部或按 Escape 才关闭整组菜单。
- 当前推理值不被目标模型支持时，不沿用无效值；使用目标模型在统一目录中声明的产品默认值，并让界面显示最终有效值。
- 模型固定开启推理时，界面明确显示“固定开启”或等价状态，不提供虚假的可点击档位；不支持推理时显示“不支持”或等价说明。
- 模型或推理强度变更成功后，入口显示后端确认的最终配置，并通过轻量、无障碍可感知的反馈说明下一条回复将使用该配置。
- 正常聊天时间线不插入模型或推理强度切换分割线，不伪造 user / assistant 消息。
- 截图中出现的“速度”等其他运行参数不属于本需求，本期级联入口只覆盖模型与推理强度。

#### QQ 尾随菜单

- QQ 每轮回复继续尾随统一“菜单”按钮；打开后同时显示当前绑定会话、当前模型和当前推理强度。
- 主菜单第一排为“切换模型 / 调整推理强度”，第二排为“切换会话”；推理入口只展示当前模型在统一能力目录中声明的有效 preset，并标记当前值，档位较多时分页展示。
- QQ 切换模型时，目标模型与其目录默认推理强度作为一个原子配置提交，成功反馈同时回显最终模型和推理强度。
- QQ 单独调整推理强度时，只修改当前绑定会话，下一轮回复开始生效；与桌面端共享同一 session effective config，不形成第二份 IM 偏好。
- 固定开启或不支持调节的模型只展示真实状态和返回入口，不提供虚假的可点击档位。
- 会话忙、目标配置无效或目标会话不存在时保持原配置，并返回可理解的失败说明；交互事件不进入 Agent 对话正文。

#### 模型能力驱动的有效选项

- 可选模型、用户可见名称、provider、推理控制形态、有效档位、产品默认值、是否允许关闭和是否固定，来自后端统一模型能力目录。
- 前端不得按模型名、provider 名或字符串前缀维护第二份推理能力判断表。
- 后端是目标组合能否提交的最终权威；前端目录用于准确呈现和提前约束，不能绕过后端校验。
- 产品层允许使用统一、易理解的展示词汇，但不得把厂商不支持的档位伪装成可用能力。
- 当厂商只支持开关时，界面只提供开关语义；当厂商支持离散 effort 档位时，只展示有效档位；当厂商要求固定推理时，不提供关闭入口。
- 目录或运行时无法确认目标模型推理能力时，默认不允许提交猜测参数，并向用户说明该配置暂不可用。
- 厂商能力后续变化时，应能通过统一模型目录和 provider 适配更新，而不要求重写会话 UI 的业务判断。

#### 新会话与已有会话状态

- 新会话尚未首次发送时，同时持有 pending model 和 pending reasoning configuration。
- 新会话初始模型沿用设置页默认聊天模型；初始推理强度使用该模型在统一目录中声明的产品默认值。
- 用户在首次发送前切换模型或推理强度，只改变当前待创建会话，不修改设置页全局默认模型。
- 新会话首次发送必须使用界面当前展示的完整 pending 配置，不能在发送时重新读取默认值后静默覆盖用户选择。
- 已有会话持久化当前有效模型与推理强度；切换会话、重启应用或重新打开历史后恢复各自配置。
- 本期不跨会话记忆“某个模型上次使用的推理强度”，也不在设置页增加按模型偏好。切换到目标模型时使用目标模型的产品默认值，之后用户可以在当前会话继续调整。
- 会话状态、目录默认值和未来可选的按模型偏好保持分层，后续增加偏好时不需要破坏现有会话事件和运行快照语义。
- 旧会话没有推理配置时仍可打开，并按当前模型的产品默认值获得确定、可见的有效配置。

#### 原子变更与并发一致性

- 切换模型时，目标模型及其最终推理配置作为一个有效组合进行校验和提交；不能出现模型已经切换但推理配置仍停留在旧模型非法值的中间状态。
- 单独调整推理强度时，只有后端确认目标配置受支持并成功保存后，前端才展示为当前有效值。
- 目标组合不受支持、凭据缺失、会话忙、会话不存在、目录过期或网络失败时，原有效配置保持不变。
- 快速连续切换模型或推理强度时，较早请求的迟到响应不得覆盖用户最后一次有效选择。
- 用户切换 session、删除或归档 session、后台刷新详情时，旧 session 的迟到响应不得污染当前界面。
- 配置提交期间不能发送新消息；提交成功后的第一次发送使用最终确认配置，提交失败后的发送继续使用原配置。
- 正在生成、历史加载、编辑重发或执行其他互斥操作时，级联入口展示明确禁用态和原因。

#### 完整 Agent run 内冻结配置

- 一次 Agent run 从接受用户输入开始，到完成、失败或取消为止，冻结模型、推理强度以及由二者派生的 provider 调用配置。
- 冻结范围覆盖首次模型请求、流式响应、工具请求、工具结果、工具循环后续模型请求、上游重试、工具结果继续执行、上下文压缩和该 run 的诊断记录。
- run 进行期间，桌面端、IM、CLI、会话 API 或其他入口都不能让同一 run 中途改变模型或推理强度。
- 每轮实际 assistant 输出和诊断元数据能够识别该 run 真正使用的模型与标准化推理配置，但不记录原始 reasoning 正文。
- 编辑并重新发送最近用户消息时，重发 run 使用提交时的当前有效配置，完成后不会把会话配置意外回退到历史值。

#### Provider 映射与 reasoning continuation

- 产品侧使用 provider-agnostic 的推理配置表达用户意图，由 provider 层映射为 DeepSeek、Kimi、OpenRouter 等目标协议的合法参数。
- 不支持某档位的 provider 不得静默接受后改成不可见的其他值；若存在明确、已登记的等价映射，界面和诊断应以最终有效档位为准。
- 启用推理后，普通无工具回复、多步工具调用、并行工具调用、上游重试和继续执行均能按目标 provider 契约工作。
- provider 要求在工具循环或后续轮次回传 reasoning 时，系统保留并原样回放所需的 opaque continuation；不得只保留一个“正在推理”的布尔状态后丢弃协议必需内容。
- opaque continuation 不作为普通 assistant 正文展示，不进入标题生成、会话搜索、memory 抽取或用户可见导出，也不得在普通日志和错误详情中输出原始内容。
- provider 不要求跨轮保留时，不因为统一抽象而无限积累 reasoning 状态；具体生命周期服从目标模型能力与最小保留原则。
- reasoning continuation 缺失、损坏或与目标 provider 不兼容时，返回稳定、可区分且不泄露敏感内容的错误，不用关闭推理或切换模型掩盖问题。

#### 反馈与可解释性

- 用户能从入口直接看出当前模型和推理强度，不需要打开设置页或根据响应耗时猜测。
- 切换成功使用短暂反馈说明下一条回复将使用的模型与推理强度；不打断正常阅读。
- 固定开启、不支持、暂不可用、会话忙、凭据缺失和 provider 拒绝配置等状态提供明确说明及可执行恢复方向。
- 缺少 provider 凭据时沿用现有“模型与凭据”设置入口，不新增第二套凭据管理界面。
- 错误信息不暴露 API key、本地绝对路径、厂商原始敏感响应、opaque continuation 或内部堆栈。

#### 真实桌面端验收

- 在真实 Tauri 桌面端验证级联入口的位置、展开方向、模型子菜单、推理强度子菜单、当前值摘要和层级切换。
- 验收覆盖长模型名称、多 provider、可关闭模型、多档模型、固定开启模型、不支持推理模型和能力目录不可用状态。
- 验收覆盖键盘导航、焦点恢复、菜单边界、禁用态、快速连续选择、成功反馈和失败反馈。
- 浏览器或 Vite 预览只能辅助开发，不能替代真实桌面 WebView 下的视觉与交互结论。

### 不包含

- 不实现跨会话或全局的“按模型记住上次推理强度”偏好。
- 不在设置页新增默认推理强度、按 provider 默认值或偏好管理界面。
- 不调整记忆模型的推理强度；本期只覆盖桌面与 QQ 共同使用的聊天会话模型。
- 不提供连续滑杆、任意数值或 reasoning token budget 输入，只使用目标模型声明的离散控制能力。
- 不展示、搜索、复制或导出原始 chain-of-thought / reasoning_content。
- 不把推理强度等同于回答长度、verbosity、速度档、service tier 或模型版本；这些维度不随本需求一并引入。
- 不新增模型、provider、凭据存储方案或独立模型管理页。
- 不重做需求 061 的模型切换协调、附件兼容或现有 composer 布局；只在其边界上扩展完整模型运行配置。
- 不要求所有模型拥有相同档位，也不为界面对齐而向厂商发送无效参数。

## 关键约束

- 模型与推理强度共同构成会话级运行配置；全局默认模型、目录产品默认值和未来偏好是不同层级，不能混为一个可变全局状态。
- 统一模型能力目录是前后端展示、校验和 provider 适配的事实源；目录必须表达真实差异，而不是只有一个模糊的“支持推理”布尔值。
- 级联菜单负责组织和呈现，不拥有 provider 判断；业务状态继续由会话 store 和后端会话领域状态持有。
- 一次 run 使用不可变配置快照；不能只冻结显示用字符串，而让底层 client 或 call options 在工具循环中变化。
- 原始 reasoning 内容属于 provider 协议状态，不属于用户可见聊天内容；必要回放与隐私最小化必须同时满足。
- 真实 LLM 验收若需执行，继续遵守 `llm-api-confirm`；自动化测试优先使用 fake / mock 固定映射、冻结和 replay 机制。

## 验收标准

- [ ] **AC-1 级联入口**：真实 Tauri 桌面端的输入区附近只有一个紧凑配置入口；一级菜单展示“模型”和“推理强度”当前值，hover 或键盘焦点立即在右侧展开对应子菜单，点击一级项不会关闭菜单。
- [ ] **AC-2 模型联动**：选择不同模型后，根菜单保持打开，推理强度摘要和子菜单立即切换为目标模型的真实档位；旧模型的非法档位不会残留，用户可以继续调整强度。
- [ ] **AC-3 差异化能力**：可开关、多档、固定开启、不支持推理和能力未知的模型分别呈现正确状态，用户无法提交无效选项。
- [ ] **AC-4 新会话 pending 配置**：首次发送前选择模型和推理强度后，第一轮实际使用该完整配置，且不修改全局默认模型或其他会话。
- [ ] **AC-5 已有会话恢复**：已有会话成功变更后，下一轮使用目标配置；切换会话、重启应用或重新打开历史后恢复各自有效配置。
- [ ] **AC-6 无跨会话偏好**：同一模型在不同新会话中仍从目录产品默认值开始，不沿用其他会话上次选择；现有数据边界没有把未来偏好写死进会话状态。
- [ ] **AC-7 旧会话兼容**：没有推理配置的历史会话可正常打开、显示确定的默认值并继续对话，无需破坏性迁移。
- [ ] **AC-8 原子提交**：模型切换与目标默认推理配置以有效组合提交；不支持、缺凭据、会话忙或网络失败时原配置保持不变。
- [ ] **AC-9 乱序与发送竞争**：快速连续选择、切换 session 和后台刷新产生乱序响应时，最终界面与后端当前 session 一致；配置提交期间不能发送。
- [ ] **AC-10 run 内冻结**：包含至少一次工具调用和后续模型请求的完整 run 中，并发变更模型或推理强度不会改变本 run 任一调用、上下文预算或诊断配置。
- [ ] **AC-11 Provider 映射**：DeepSeek、Kimi 和 OpenRouter 的可调模型收到各自合法参数，固定或不支持模型不收到无效控制字段，最终有效档位可被诊断但不泄露 reasoning 正文。
- [ ] **AC-12 工具循环 replay**：启用推理后，多步工具调用和继续执行能够按 provider 契约原样回放必需的 opaque continuation，不因缺失 reasoning 状态返回协议错误。
- [ ] **AC-13 reasoning 隐私边界**：原始 reasoning 不出现在聊天正文、会话搜索、标题、memory、普通日志、错误提示或前端事件中；仅内容为空的推理活动状态可以继续用于进度反馈。
- [ ] **AC-14 编辑重发与失败恢复**：编辑重发使用提交时的当前有效配置；取消、重试或 provider 错误不会让会话配置回退或留下模型与推理强度不匹配的状态。
- [ ] **AC-15 桌面交互质量**：级联菜单的 hover 展开、右侧定位、选择后保持打开、长名称、焦点、键盘导航、固定态、禁用态和成功 / 失败反馈在真实桌面 WebView 下正常；点击外部、再次点击入口和 Escape 可以可靠关闭。
- [ ] **AC-16 自动化与门禁**：目录能力、fallback、session 投影、run snapshot、provider 映射、opaque replay、API/store 竞态和前端级联状态具有自动化覆盖，`scripts/check` 全绿。
- [ ] **AC-17 QQ 尾随菜单**：QQ 每轮回复的尾随菜单打开后显示当前模型与推理强度；可调模型能从能力目录分页选择有效 preset，切模型反馈回显目标默认强度，固定/不支持模型保持只读；所有变更只影响绑定会话下一轮且服从 busy 锁。
