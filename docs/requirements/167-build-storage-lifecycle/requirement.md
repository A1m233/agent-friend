# 167 · 构建存储生命周期与测试制品保留

## 状态

已确认（Confirmed），确认日期：2026-10-28。

## 背景

需求 055 和 158 已建立仓库外制品目录、受管构建存储、容量与空间策略，以及运行和保留保护。后续本机调查发现，历史未纳管目录仍占据较大空间，本地测试安装包持续累积；只报告当前安全清理候选，不能解释完整的构建相关占用。

本需求承接现有治理能力，补齐目录发现、结束状态与保留策略。历史测量、代码依据和局限见 [evidence-index.md](./evidence-index.md)。目录逻辑字节不等于可实际回收空间，也不能据当前快照推断某次构建造成了全部增长。

## 目标

- 在同一管理流程内解释已管理、未管理、受保护和可回收的构建相关占用。
- 正常结束后及时解除活动保护，按用途保留可再生目录和必要证据。
- 为本地测试安装包提供可配置、显式启用的保留与淘汰能力。
- 复用既有打包和存储管理机制，保持可追溯性、并发安全和构建验证可信性。

## 范围

### 包含

- 已知构建根、历史打包目录及显式指定根的发现、分类和容量说明。
- 历史目录的接管预览、归属验证、显式纳管和后续既有回收策略衔接。
- 成功、正常停止、取消、失败和退出状态未确认时的生命周期处理。
- 大体积构建中间产物与必要诊断证据的区别保留。
- 本地测试制品的数量、期限、固定保留、清理预览和执行结果。
- 标准打包、开发及检查入口与既有管理入口的衔接，相关规则、skill、脚本说明与测试的一致性。

### 不包含

- 跨 worktree 共享可变编译缓存、引入 sccache、远端缓存或新的 CI/CD。
- 自动删除源码 worktree、Git 分支、未提交内容或来源不明目录。
- 自动删除正式发布包、native symbols、用户数据、设置、凭据或产品日志。
- 自动迁移已有目录或把本机 D 盘设为跨机器默认路径。
- 降低冻结验证、安装器验证、构建身份与制品不可变性要求。
- 将本需求的文档或实现授权视为对本机历史文件的一次性删除授权。

## 需求

### R-1 · 完整、可解释的盘点

- 汇总受管目录和已知范围内的未管目录，说明归属、类别、活动状态、保护原因和接管资格。
- 报告覆盖的根、未覆盖或不可访问范围、测量时间和完整性；未知容量不得计作零。
- 区分逻辑容量、估计可回收量和执行后实际卷可用空间变化，避免重叠目录重复计数。
- 保留轻量查询和显式精确扫描两种能力；扫描可取消，不因查询安装构建依赖或实施删除。

### R-2 · 历史目录显式纳管

- 基于已有归属证据提供接管计划，展示目标、识别依据和保护状态。
- 接管必须由用户显式执行；不能仅凭目录名、时间戳或 worktree 已消失判断可以删除。
- 缺少可靠凭据、存在异常链接或归属冲突时保留目录，明确说明缺口。原工作区凭据缺失时，允许通过可交叉核验的 Cargo 编译记录确认纯编译缓存的归属；该路径须显式选择、保存证据，不补造原始凭据。
- 接管后进入现有管理和回收流程；不维护第二套删除策略。活动状态未确认前保持保护。

### R-3 · 结束状态与保留用途一致

- 成功、正常停止、用户取消、真实失败及子进程状态未确认应可区分。
- 只有确认关联进程已结束，才能解除活动保护；不能仅依据父进程 PID 消失进行回收。
- 正常停止不应被统一记录为失败，重复对账不得无理由重新延长保留期限。
- 无续跑用途的大体积临时目录可按策略回收；可复用缓存继续受容量、空间和最近使用策略管理。
- 失败与取消留下必要日志、输入身份、结果和复查信息；完整现场允许短期保留及显式固定保留。
- 证据保存失败、清理部分失败和状态不确定必须可观察、可重试，不得报告为完成。

### R-4 · 本地测试制品保留

- 本地测试包支持可配置的数量、期限和固定保留，策略默认不自动启用。
- 新策略启用前展示影响范围；启用后按明确范围执行，不要求每次重复授权。
- 历史测试包先盘点和预览，再显式纳入策略，不因启用新策略被追溯自动删除。
- 正式制品、必要符号、正在生成或验收依赖的制品保持保护；来源或依赖关系不确定时保留。
- 删除前提供精确制品身份、原因和范围，执行时重新验证状态；状态变化或并发使用时跳过并说明。
- 删除测试包后仍可追溯其构建身份、原始校验信息和删除结果，且不会被查询误报为仍可使用。
- 本地测试包淘汰属于制品管理，不扩展通用缓存 GC 的删除权限。

### R-5 · 复用与跨入口一致性

- 复用现有路径解析、存储登记、锁、身份校验、容量策略、制品验证及执行入口。
- 同步相关规则与 skill 的职责描述，代码继续是策略计算与执行的唯一真相源。
- 双平台管理入口保持语义一致；Windows 安装包构建的平台边界保持不变。
- 配置默认值、命令参数和内部数据结构在技术方案中确定。

## 验收条件

- [x] AC-1：混合受管、历史未管、缺少凭据和不可访问目录时，盘点正确展示覆盖范围、分类、容量口径和缺口，无重复汇总或伪完整结果。
- [x] AC-2：有效历史目录可显式纳管；归属冲突、凭据不足、链接异常和活动状态不明时拒绝危险操作。
- [x] AC-3：成功、正常停止、取消、失败与异常退出分别验证；确认停止后保护正确释放，重复对账不无故续期，未确认子进程继续受保护。
- [x] AC-4：中间目录按用途回收后，必要证据仍可读取；证据保存失败与部分删除失败可复查、可重试。
- [x] AC-5：测试制品数量、期限、固定保留和显式启用行为可断言；历史制品未纳入前不会自动删除。
- [x] AC-6：正式包、符号、验收依赖和活动制品不被误删；计划后状态变化、并发发布和路径异常触发保护。
- [x] AC-7：删除后保留构建与删除记录，制品查询不把已删除文件当作有效候选。
- [x] AC-8：现有缓存策略、构建隔离、跨盘预检、制品身份与验证证据复用契约无回归；标准入口、规则、skill 与文档一致。
- [x] AC-9：完成项目检查和受影响验证，提供前后证据及局限，并取得用户验收确认。
