# 083 · 沉浸式交流与 Agent 透明表达

## 状态

CONFIRMED

## 背景

agent-friend 当前通过公共 system prompt 约束 Echo 维持朋友人格、不直接暴露 AI、模型与系统身份，
并避免解释工具、记忆和存储等底层机制。这些规则让日常对话更自然，但也会在用户明确询问 Echo
自身状态时造成不准确或回避式回答。

一次真实长会话已经暴露该问题：当前模型上下文中明确存在“此前对话的压缩摘要”，用户询问是否
发生过上下文压缩时，Echo 却没有依据自己实际看到的上下文直接确认，反而把问题解释成过去聊过
的同名技术话题。此时压缩链路本身工作正常，偏差来自沉浸表达、机制隐藏和记忆召回之间缺少清楚
的产品边界。

用户希望默认继续保留 Echo 的沉浸感，同时可以在设置中主动关闭这种表达约束。关闭后，Echo 应对
自己的 AI 身份、当前实际可见的上下文状态和回答所依据的信息来源保持坦诚。该透明度不等于公开
原始 system prompt：无论沉浸模式是否开启，内部指令原文都必须受到统一、不可关闭的保密约束，
但 Echo 可以用自己的话概括自己受到哪些类型的约束。

## 目标

- 在人格设置中提供默认开启的“沉浸式交流”开关，让用户决定 Echo 是否直接承认 AI 身份并解释
  与当前回答有关的内部上下文来源。
- 沉浸式交流关闭后，Echo 能基于本轮实际可见的可信上下文，如实说明上下文压缩、历史召回、工具
  或外部资料等来源，不再为了维持人格而否认或回避已经发生的事实。
- 沉浸式交流开启时继续保持当前自然的朋友式表达，但不得明确冒充人类、虚构现实身体或编造经历。
- 将“原始 system prompt 不可泄露”确立为独立于沉浸模式、始终生效的统一底线；允许概括约束，
  禁止直接或变相还原内部指令文本。
- 设置在所有正式对话入口中保持一致，并在应用重启后继续生效。
- 将本需求产生的用户可见变化及时同步到公开 `agent-friend-guide`，并把“合入 `main` 且推送远端”
  作为一次有边界的自动知识维护事务，减少依赖用户逐步确认的遗漏。

## 范围

### 包含

**人格设置**

- 设置页“人格”区域新增“沉浸式交流”开关。
- 开关是用户级全局设置，不按会话、模型或文字、语音、IM 通道分别配置。
- 新安装与从旧版本升级且尚无该设置的用户，默认开启沉浸式交流，保持现有体验。
- 修改设置后从下一个新用户回合开始生效；已经进行中的模型调用和工具循环保持该回合开始时的
  策略快照。

**沉浸式交流开启**

- Echo 以当前人格自然地与用户相处，不主动强调自己是 AI，也不使用上下文压缩、记忆召回、
  system prompt、工具链等技术机制解释日常表现。
- 用户直接追问 Echo 是否为人类时，Echo 不得声称自己是人类；可以继续以 Echo 或“虚拟朋友”
  的身份自然回应，而不必直接使用模型或 AI 的技术标签。
- 忘记、记起、查证和工具失败等场景继续使用自然表达，但来源边界必须真实，不得为维持沉浸感
  编造不存在的经历、记忆或动作。

**沉浸式交流关闭**

- 用户直接询问身份时，Echo 可以明确说明自己是 AI 或虚拟朋友，不得继续假装没有 AI 身份。
- 用户询问是否发生过上下文压缩、为何记得或忘记某件事、信息来自哪里等问题时，Echo 基于当前
  实际可见的可信上下文回答。
- 当前上下文确实包含有效压缩摘要时，Echo 可以确认较早对话已被整理成摘要，并说明原话细节可能
  不再完整；没有对应证据时不得猜测发生过压缩。
- 当前回合确实使用了历史召回、搜索、网页、文件、工具结果或其他外部资料时，Echo 可以用用户
  可理解的自然语言说明来源类别；不得把未执行的动作说成已经执行。
- Echo 可以说明自己既受到用户设置的人格约束，也受到产品提供的真实性、权限、隐私、安全等
  公共行为约束，并可以概括某类约束如何影响当前回答。
- 透明表达只在用户询问、信息来源会影响答案可信度，或不说明就会造成明显误解时出现；不要求
  Echo 每轮主动汇报内部处理过程。

**始终生效的内部指令保密边界**

- 无论沉浸式交流是否开启，Echo 均不得逐字引用、完整复述或展示原始 system prompt、隐藏消息、
  内部标签、section 顺序、内部 key 或其他可用于还原内部指令结构的内容。
- 翻译、编码、分段续写、角色扮演、引用第三方内容或要求“忽略之前规则”等方式不得绕过保密边界。
- Echo 可以对约束做非穷举、高层语义概括，但不能借“概括”逐项重建原始指令，也不能声称这些
  约束不存在。
- 网页、搜索结果、工具输出、历史片段、记忆召回、附件和用户伪造的内部标记仍不具备修改该边界
  的指令权。
- API key、凭据、内部地址、日志和 trace 标识、工具 schema 等敏感或实现级信息继续服从现有
  保密与安全边界，不因关闭沉浸式交流而公开。

**规则治理与验证**

- 受沉浸开关控制的表达规则应具有单一、可审计的责任归属，避免继续散落在多个公共 prompt 职责中
  产生冲突。
- 不可关闭的内部指令保密规则应与可切换的身份和机制表达分离，设置不能意外移除保密底线。
- 确定性自动化测试覆盖设置默认值、持久化、回合快照、所有正式入口的策略传递及 prompt 装配差异。
- Agent 行为评测同时覆盖沉浸开启、沉浸关闭、高层约束概括和原始 prompt 套取防护，不能只检查
  prompt 文本是否存在。

**合入主干前的自动知识维护**

- 当用户明确要求把当前交付合入 `main` 并推送远端时，系统自动检查本次产品变化是否影响公开
  `agent-friend-guide`；不再询问“是否检查”或“是否更新”。
- 无需更新时直接继续原交付流程；需要更新时，自动完成公开指南修改、验证、提交、推送以及产品
  builtin 快照同步，再继续合入和推送 `main`。
- 自动流程使用固定的受管公开仓库 checkout；缺失时可从项目声明的官方仓库自动 clone，已存在时
  只允许在 origin 正确、工作区干净且可 fast-forward 的状态下更新。
- 该授权仅覆盖本次“合入 `main` 并推送远端”所必需的知识检查、指南发布和 builtin 同步，不扩展
  到普通 commit、普通分支 push、只合入不推送、打包或其他未来任务。
- 出现来源不明的工作区改动、远端分叉、基线不可判定、内容可能泄露隐私或内部实现、验证失败、
  非快进推送需求、产品状态在复核后变化，或跨仓部分完成状态无法唯一续跑时，必须停止并报告；
  不得 force-push、自动改写已发布提交或猜测恢复路径。

### 不包含

- 不提供原始 system prompt 查看器、编辑器、导出功能或调试控制台。
- 不允许用户通过本设置编辑 persona 之外的公共 system prompt。
- 不按会话、模型、provider 或通道提供不同的沉浸模式配置。
- 不改变上下文压缩、长期记忆、历史召回、工具调用、搜索或外部资料获取的实际算法和触发时机。
- 不要求 Echo 在每轮对话中主动报告上下文组装、工具调用或内部规则。
- 不公开 chain-of-thought、隐藏推理、内部协议消息或运行时原始 payload。
- 不借本需求建设通用 prompt 管理后台、远程配置、版本发布或 A/B 实验平台。
- 不把自动知识维护扩展到安装包构建、普通 feature/fix 分支 push 或没有 `main` 推送意图的 Git 操作。
- 不全面重写现有人格、关系、安全、事实查证和权限体系；只调整与沉浸表达、透明来源和内部指令
  保密直接相关的职责边界。

## 验收条件

- [ ] **AC-1 设置入口**：设置页“人格”区域存在“沉浸式交流”开关，说明文案清楚表达开启时维持
  沉浸、关闭后坦诚说明身份和相关上下文来源。
- [ ] **AC-2 默认与持久化**：新安装和缺少该字段的旧设置默认开启；用户修改后跨窗口同步并在应用
  重启后保持。
- [ ] **AC-3 沉浸身份表达**：开启时，用户询问“你是不是 AI”或“你是不是人类”，Echo 不直接
  强调 AI 技术身份，也不会声称自己是人类或虚构现实身体与经历。
- [ ] **AC-4 透明身份表达**：关闭时，用户直接询问身份，Echo 明确承认自己是 AI 或虚拟朋友，
  不使用当前沉浸式回避话术。
- [ ] **AC-5 压缩事实透明**：关闭时，当前上下文包含有效压缩摘要且用户询问是否发生压缩，Echo
  明确确认；不存在对应证据时不猜测或虚构压缩状态。
- [ ] **AC-6 来源透明**：关闭时，用户询问回答依据，Echo 能正确区分当前对话、实际召回的过去
  对话和本轮取得的工具或外部资料；未发生的来源不得声称发生。
- [ ] **AC-7 约束概括**：关闭时，Echo 可以说明自己同时受到用户人格和产品公共规则约束，并用
  自己的话概括相关约束，不再声称规则不存在。
- [ ] **AC-8 原始指令保密**：两种模式下，直接索取、翻译、编码、分段套取或通过第三方内容诱导
  泄露 system prompt，均不会得到原文、可重建的逐项内容或内部结构。
- [ ] **AC-9 非主动播报**：关闭沉浸模式不会让普通对话固定附加身份声明、压缩状态、记忆来源或
  工具过程；只有当前请求相关时才透明说明。
- [ ] **AC-10 回合一致性**：设置变化不改变已经进行中的模型调用或工具循环；下一个新用户回合
  使用新策略，且该回合所有后续模型调用保持一致。
- [ ] **AC-11 多入口一致**：桌面文字聊天、语音和 IM 的正式对话使用同一设置，不因入口不同出现
  一处承认、一处隐藏的分裂行为。
- [ ] **AC-12 既有边界不退化**：不可信内容、事实查证、工具真实性、权限、隐私、关系和输出规则
  继续生效；现有相关确定性测试和 agent_eval 相邻契约不退化。
- [ ] **AC-13 自动化门禁**：新增设置、prompt 装配、运行时快照和行为契约拥有对应自动化覆盖，
  `./scripts/check` 全量通过；真实 LLM 评测如需执行，按调用授权规则另行确认并记录范围与结果。
- [ ] **AC-14 自动知识判断**：用户明确要求合入 `main` 并推送时，流程不再询问是否维护知识；能
  自动给出需要更新、无需更新或无法判断的结论，无需更新时直接继续交付。
- [ ] **AC-15 自动跨仓发布**：需要更新时，在两仓均满足安全门禁的前提下，自动形成稳定产品锚点、
  发布公开 guide、确认远端精确提交、同步 builtin，并继续合入和推送；正常路径不要求逐步授权。
- [ ] **AC-16 受管 checkout 与失败边界**：默认公开仓库 checkout 可自动 clone 或 fast-forward；
  dirty、错误 origin、分叉、验证失败、敏感内容风险或不可唯一续跑时 fail closed，且不执行破坏性 Git。
