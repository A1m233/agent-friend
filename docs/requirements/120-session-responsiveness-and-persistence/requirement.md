# 120 · 会话操作响应与持久化可靠性治理

## 状态

CONFIRMED

## 背景

issue [062](../../issues/062-notification-full-load-and-session-lock-timeout/README.md) 记录了长会话读写竞争导致工具结果持久化失败，issue [063](../../issues/063-long-session-cold-restore-latency/README.md) 记录了本地冷准备耗时约一分钟。用户还报告模型与思考强度切换明显等待，以及仅两条可见消息、无需滚动的会话切换也需一秒以上，且此前没有这种体验。

这些问题需要覆盖普通会话与长会话的独立治理，不能仅用历史体积解释，也不能以局部查询优化代表全链路通过。

## 目标

- 定位并解决日常会话操作的性能回归，区分操作反馈、本地准备、模型首输出及实际完成。
- 定位并解决会话文件与通知数据库的锁问题，保证执行结果持久化和恢复正确。
- 用真实桌面操作和可复查的分阶段证据向用户回报改进效果及残余问题。

## 范围

### 包含

- 极短会话（两条可见消息）、普通会话和长会话的首次打开、重复切换、缓存后重开。
- 模型与思考强度切换的响应、持久保存和后续生效。
- 发送受理、本地会话准备、冷恢复，以及准备中和执行中的取消、取消后继续。
- 通知刷新、多通知校验、会话读取与工具结果写入并发。
- JSONL 会话文件锁和通知 SQLite 锁分别定位、修复和验证。
- 重复全量读取、恢复中的累计历史处理、内部恢复记录增长及其影响。
- 性能回归版本与调用路径调查、分阶段观测和修复前后比较。

### 边界

- 模型生成、记忆检索和本地会话操作分别计时，不能互相代替归因。
- 保持已有会话兼容、恢复校验、授权状态和工具结果完整性；不能通过跳过正确性保证获得性能数字。
- 不是默认更换持久化技术栈；具体方案在调查后另行确认。

## 验收条件

- [x] AC-1：通过真实 Tauri WebView CDP 操作观测两条消息会话、普通和长会话的打开与切换；区分首次与重复操作、空闲与后台长会话执行场景，报告样本数量和延迟分布。
- [x] AC-2：通过真实桌面操作验证模型与思考强度切换，报告反馈与完成耗时，并交叉核对持久化和后续生效。
- [x] AC-3：观测发送受理、本地准备、冷恢复和取消；准备中与执行中取消后均可继续，状态与持久化一致。
- [x] AC-4：JSONL 写锁超时的持锁调用方、长持锁原因和失败链路得到证据确认并完成修复；大会话、通知刷新、多通知校验及工具结果写入并发验证中，无该根因导致的写锁超时、结果丢失或运行失败。仅增大超时或增加重试不能通过。
- [x] AC-5：通知 SQLite 锁错误独立定位、修复和验证；不得与 JSONL 文件锁混同，也不得以其中一项通过替代另一项。
- [x] AC-6：验证取消后继续、重启恢复、历史兼容及相关授权与损坏恢复语义；可断言机制有自动化覆盖，项目 scripts/check 全绿。
- [x] AC-7：回报修复前后各类操作的实际耗时、阶段归因、回归调查结论、未复现和未验证项，由用户确认体验是否达标。

### 性能判定口径

300 ms 的普通操作 P95、1 秒的后台停止耗时仅作为早期讨论参考，**不作为当前验收硬门槛**。必须实际观测并向用户回报，再由用户判断效果。长会话冷恢复也必须观测和回报，不预设未经验证的数值门槛。锁问题定位与解决、持久化正确性和对应并发验证仍为硬门槛。

## 工作约定

- 用户已授权由 agent 使用项目 CDP 流程执行上述 bad case 的真实桌面验证；dev 启动后保留供后续调试。
- 方案形成前、实现过程中及验证时充分核对已有成熟实践；来源与适用性分析归入证据记录，避免把猜测当作实现事实。
- 外部 LLM 的真实执行继续遵守逐次或有界工作流授权，CDP 授权本身不扩大调用量。
- 需求确认后进入方案调查；具体方案另行展示并确认。最终验收完成由用户确认。
