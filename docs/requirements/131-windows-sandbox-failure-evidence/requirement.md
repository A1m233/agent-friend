# Windows 沙箱失败现场与诊断包按轮次采集

## 状态

CONFIRMED

## 背景

[issue 066](../../issues/066-windows-sandbox-field-recovery/README.md) 的客户在已有修复后的构建中仍遇到沙箱初始化失败。2026-09-14 提供的新诊断包保留了 `helper_incomplete`，但不足以解释助手成功退出后初始化完整性检查未通过的具体原因。用户随后手动点击修复，因此导出时的 ready 不能证明自动恢复或此前没有失败。

现有证据在底层错误采集、失败状态快照、独立留存和修复关联上存在缺口。客户不应反复升级、复现、记时间或在修复前临时启用调试，才能提供可用证据。

用户另反馈长会话诊断包可超过 100 MB，生成和传递耗时较长。本次诊断包的单份会话 JSON 未压缩体积约 502 MiB，超过现有解析器的 64 MiB 单 JSON 消费上限。需要允许仅采集所选会话最近 X 轮，并从采集源头减少不必要的数据处理。

## 目标

- 在正常使用中自动保留沙箱失败现场，使一份导出包可以区分本需求列出的主要故障类别及失败边界。
- 修复、重启及后续正常使用后，仍可在约定保留范围内追溯原始失败与恢复过程。
- 客户可选择采集所选会话最近 X 轮，减少长会话反馈所需的等待、包体积和传输成本。
- 未采集、不可获取或无法归属的证据必须明确标注，不把证据缺失解释为操作成功。

## 范围

### 包含

1. Windows 沙箱首次初始化、命令前刷新、文件访问准备、助手启动与加载、状态校验、手动修复和实际执行探针的证据盘点与补齐。
2. 当次失败的阶段、可取得的原生错误与退出结果、实际执行组件及构建身份、相关状态检查结果。
3. 独立故障留存、失败与后续修复关联、跨重启保留，以及采集失败、并发归属、截断和淘汰的明确说明。
4. 诊断导出及消费者同步支持上述证据；Bridge 不可用时仍可读取已持久化的故障证据。
5. 在诊断导出界面提供最近 X 轮与完整会话的采集范围选择；同一次导出的轮次限制分别应用于每个所选会话。
6. 最近 X 轮以会话的逻辑对话轮次计数，不以单条消息或工具调用计数；保留选中轮次内的调用、结果和失败证据。运行中、重写、压缩及不足 X 轮的边界必须有明确语义与验证。
7. 只收集所选范围涉及的附件候选；附件原件仍服从用户的独立选择。范围外引用必须标明，不得为了引用自动带回全部历史。
8. 系统级沙箱故障证据不受所选会话轮次裁剪影响；导出包明确标注请求范围、实际范围及证据缺口。
9. 从会话读取、序列化、传输到归档的处理成本验证，以及诊断包的安全解析与兼容性验证。

### 不包含

- 不预先指定缺失 DLL、杀毒软件或用户操作为根因，也不承诺对系统未提供的信息给出具体模块结论。
- 不以扩大权限、关闭沙箱或自动重放客户业务命令替代恢复。
- 不扫描客户全盘、不导出密码、凭据、完整环境或无关私人内容。
- 不因本需求完成自动关闭 issue 066；该 issue 的客户现场修复与验收仍按原关闭条件处理。
- 不全面重构会话存储或所有诊断证据族；仅调整满足本需求所必需的边界。

## 验收条件

- [ ] AC-1：形成覆盖初始化、命令前刷新、文件访问准备、助手加载、状态校验、修复与探针的故障矩阵；每类列出证据源、可区分结果及无法观察的边界。
- [ ] AC-2：覆盖启动失败、超时、非零退出、成功退出但状态无效，以及账户／权限／状态写入等底层错误；消费者可仅凭导出包定位到已验证的阶段与原因类别，不能仅返回泛化的 unknown 或 helper_incomplete。
- [ ] AC-3：能区分状态缺失、不可读、解析失败和版本不匹配；未知或取证失败必须显式标注；不得泄漏敏感状态内容。
- [ ] AC-4：失败后手动修复、进程重启及大量正常事件均不能在约定预算内覆盖独立故障证据；修复开始、路径、探针和结果可关联到原事故，历史失败不会被当前 ready 替代。
- [ ] AC-5：并发请求、跨进程／构建、错误报告残留及采集时状态变化有相应验证；无法唯一归属时明确报告，不错误拼接因果链。
- [ ] AC-6：Bridge 不可用时仍能导出已持久化事故；采集不可用、写入失败、截断、淘汰和未知尾部均有可消费的缺口标记。
- [ ] AC-7：用户可选择最近 X 轮或完整会话；X 无效时有明确校验，多会话分别应用范围，不足 X 轮正确处理。
- [ ] AC-8：轮次裁剪保留范围内完整诊断语义，覆盖工具请求／结果、运行中轮次、重写和压缩边界；包含范围可追溯，范围外内容不会被嵌套快照或附件收集重新带入。
- [ ] AC-9：最近 X 轮模式不先生成或跨进程传输完整会话再裁剪；使用长会话对照记录读取量、序列化／传输量、包大小和导出耗时，达到方案确认的指标。冷启动或索引重建等例外必须单独记录。
- [ ] AC-10：不选择会话、超大单轮及完整会话模式都有明确行为；核心故障证据的导出和解析不依赖巨大会话成功；不能只提高解析器内存上限处理大包。
- [ ] AC-11：生产者、机器契约、消费者及真实 ZIP 契约测试同步更新；旧包仍可读，裁剪范围不会被误解为完整历史。
- [ ] AC-12：完成 Windows 10／11 相关真实验证和项目要求的检查；未具备的环境明确记为未验证，不能以开发机结果代替。新增 UI 按用户选择进行视觉验收；最终完成由用户确认。
