## 现状

执行态、通用查询快照、模型历史和记忆召回属于不同数据边界。执行态驻留不能保证查询缓存命中。当前 source order 和历史检索在 miss 时读取、解码完整 JSONL；其内容远多于召回需要的对话正文。

既有 run_latency 能看到队列、会话准备、召回总计及模型请求阶段，但召回前的历史、Skill、工具证据、用户接纳和 rollout 提交缺少分段。旧日志中的等待不能只靠静态代码推断。

## M0：观测与离线基线（本次实现范围）

### 观测边界

- 复用 `agent/latency.py`，增加阶段计时 helper：记录固定阶段名、run/session 关联、起止单调时间、wall/thread CPU 时长、状态与异常类型；不记录输入、模型消息、工具参数、异常正文和路径。遥测失败不能改变业务结果。
- 阶段包含历史 reconcile/未完成事务修复、模型与 prompt 快照、引用检查、模型历史快照、摘要/业务召回边界、Skill 解析/激活、工具证据、业务消息持久化、accepted rollout commit、记忆召回及请求准备。保留既有日志事件，新增信息不改变执行顺序或重试策略。
- 复用已有 session file/query 观测区分读取、解析、锁、fsync 与缓存维护。离线报告关联本次运行采集的记录，不把嵌套阶段时长简单相加；已有无法关联到 run 的日志不强行关联。
- 桌面发送服务记录 service ready、请求编码与收到 HTTP response 的分段。后端从路由接收开始贯穿 scheduler 的时间线。客户端/后端只按 run id 关联，不相减不同进程单调时钟；客户端起点是进入发送服务，不冒充物理点击时刻。
- 错误、取消阶段也必须闭合；不为日志而吞掉取消或异常。provider fake 到达只是应用层请求边界，不是厂商收包或网络 RTT。

### 离线测量

扩展现有 `scripts/session-latency/run.*` 的 `offline` 子命令；两端参数一致。只接受明确提供的 fixture，复制到独立临时数据目录后才运行会产生持久化的真实 SessionManager / Conversation 路径。用户原件与既有运行实例不参与写入。

网络连接在子进程中拒绝；LLM 使用 fake，允许完成本地轮次以测量下一轮自然状态。记忆检索使用真实 service、source order 和 session history；未提供的结构化记忆库、Skill、附件、桌面 IPC、模型厂商投影必须在报告中列为降级，不能冒充完整安装版基线。默认不加载用户配置或自动探测原始数据。

报告包括源码/测量脚本身份、fixture 摘要、测量条件、每轮首个 fake 请求前时间、分阶段时长、查询命中/重建和文件读取指标、内存（平台可用时）。原始采样保留，不用最佳值替代分布；warm、交替会话、重新加载分别标记。初次载入与发送前时间分别报告。

## M1：轻量召回投影（已授权实施）

1. 在原始 JSONL 之外维护可重建的轻量 SQLite 对话投影，只保存召回所需正文、来源顺序、有效性和过滤字段。当前会话顺序读取也使用该投影；不依赖完整业务快照常驻。
2. 原始事件持久化成功后再更新派生投影；源版本、编辑、删除、文件替换或模式不匹配时更新、失效或重建。不得把派生更新失败反馈为原消息未保存，不能静默返回过期内容。首次构建、重建、取消及跨进程一致性按下述边界实现。
3. 保留当前子串匹配、轮次聚合、过滤、排序和跨会话覆盖语义，暂不引入 FTS/BM25。派生数据体积、驻留内存及首次构建成本分别验证。
4. 活跃会话仍受原有驻留保护，闲置预算不扩展为全应用上限；不以复制多个完整快照获得表面上的速度。

### 所有权与读取边界

在 `sessions/recall/` 内实现轻量快照与派生持久化，由 `JsonlSessionStore` 提供读取能力，`NotifyingSessionStore` 透传；非 JSONL store 通过现有 query 能力构建同形快照。`SessionHistorySource` 与 source order 共用此入口，普通历史分页、执行恢复和模型 journal 继续使用各自原有入口。

派生文件位于 store 的用户会话根下 `.recall/`，按 session id 的稳定摘要分文件，使用标准库 SQLite。每个会话只保留当前投影：源版本、原始事件计数、诊断和活动时间；有效完整对话的原始正文、UUID、原始位置、时间及 persona；业务事件 UUID 到原始位置的轻量映射；编辑 marker 的失效 UUID。位置映射用于当前轮定位，不保存对应工具载荷。模式版本不兼容时重建，不迁移原始历史，也不支持旧程序读取新派生格式。

读取先确认原始文件存在、来源版本匹配，再读取一份独立快照。重建沿用完整流式读取与损坏校验，扫描过程中只积累轻量字段；消费到末尾通过校验后才能发布。首次构建与重建不占用 SQLite 写事务或原始文件长期读锁。同进程同会话合并构建，其他会话与原始追加可以继续；发布前再核对来源版本。并发追加时可返回已固定的完整前缀，新查询必须重新核对版本，不把旧构建标记成新版本。

### 增量更新、失败与生命周期

- JSONL fsync 成功并释放文件写锁之后才维护投影。仅在投影源版本等于本次追加前版本、原始边界完整且来源没有再变化时更新；对话追加、位置计数、编辑失效及来源版本在同一 SQLite 事务内提交。rollout 追加只推进版本和计数，不复制载荷。
- 投影不存在时不在写路径首次构建；版本衔接不上、损坏尾部或维护失败时保留可判定为失效的状态，由读取重建。不推测外部变更只是追加，不用文件大小增加代替来源校验。
- 数据库连接短期持有并及时关闭；会话级派生文件锁只覆盖数据库操作，等待可取消。写后维护不等待长时间竞争；竞争或 SQLite 故障不改变原始保存结果。损坏或模式不匹配的派生库在排除并发使用后重建；无法持久化时用经校验的轻量流式读取完成本次查询并记录降级，不返回过期结果。
- 删除原始会话后清理其派生文件；即使清理失败也不能再检索该会话。归档保持现有管理语义，不新增归档检索过滤。没有常驻跨会话完整快照、后台同步队列或旧投影版本累积。

### 召回语义与验证

沿用既有整轮分组、casefold 子串匹配、短词处理、过滤、排序、跨会话覆盖及来源定位。当前轮优先用宿主注入的稳定事件 UUID 定位，避免将精简执行态下标与原始事件位置混用；旧的数值边界只用于既有调用方兼容。隐藏边界不进入模型工具 schema。

确定性验证覆盖新旧投影候选等价、连续/交替查询不重扫、重启复用、追加与编辑、替换/截断/删除、旧数据、损坏与模式失效、取消及并发发布。故障注入验证“原始成功、派生失败”不会造成重复写入。沿用 M0 固定样本和离线入口比较读取行为、延迟、进程内存及派生磁盘成本；不设置耗时达标阈值。

工具事务恢复保留现有行为及观测，本轮不为进一步压缩耗时重构该链路。没有新的依赖、动态资源或原生加载方式，按 standard 分类验证，不主动打包。

## 验证与推进边界

- M0 先以合成样本验证测量装置，再运行现有固定 A/B 长会话副本；确认每个降级条件和首次 provider 边界。
- 单次隔离阶段探针不证明旧安装版约 9.2 秒的根因。实际测量不能覆盖的入口、环境或功能列为剩余缺口。
- M0 基线用于定位重复工作和评估后续方案。性能方案围绕正常热发送不反复完整扫描、未变化状态可复用、变化后正确更新及失效可恢复来细化；补齐持久投影细节并确认后，按实现授权推进。
- 延迟、内存和磁盘成本继续按相同条件比较，用来识别回退、解释取舍；不设置固定秒数或分位数门槛，不为达到某个数值扩大缓存、跳过恢复、降低召回语义或增加无依据的架构复杂度。首次构建、正常更新与异常重建分别观察。
- 本次是业务观测和开发脚本，无新运行依赖或冻结资源，按 standard 验证；不构建安装包、不调用外部模型、不自动做桌面视觉验收。
