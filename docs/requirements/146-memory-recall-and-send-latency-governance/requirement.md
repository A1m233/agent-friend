# 146 记忆召回与发送延迟治理

## 状态

CONFIRMED

## 背景

用户在已有长会话中连续发送消息，每次都要等待十秒以上才到模型上游。145 已降低执行会话恢复时的内存占用，但这不能证明正常热会话的发送等待已解决。

既有诊断观察到一次热会话运行在本地准备打开 provider stream 前耗时约 28.2 秒，其中自动召回约 18.3 秒：召回范围准备约 11.0 秒、结构化记忆来源约 47 毫秒、历史会话检索约 7.1 秒。召回前另有约 9.2 秒缺少细分证据。该日志边界不是用户点击时间，也不等于上游服务器收到请求；不能把全部耗时归为数据库召回或网络。

固定长会话样本还复现了查询缓存互相淘汰：同一会话重复查询可以命中，访问另一大会话后再次访问会重新扫描。执行会话仍在内存中，并不能阻止这条查询路径重建。

既有证据见 [145 发送延迟诊断](../145-session-memory-and-storage-governance/evidence/20260930-send-latency-diagnosis.json)；历史日志与当前代码复现的身份、范围和局限分别保留，不能混写为同一版本的整条发送测量。

## 目标

1. 说明从用户发送到本地发起上游请求之间，哪些阶段在等待、为什么等待，区分本地准备与上游响应时间。
2. 消除长会话正常连续发送中由重复历史读取、查询重建及跨会话缓存干扰造成的持续等待。
3. 在改善发送延迟的同时保留召回语义、数据安全和 145 的内存治理边界，不能仅以扩大缓存或减少召回内容作为成功依据。
4. 形成可重复、可比较的分阶段验证，覆盖长会话增长与多会话交替使用。

## 范围

### 包含

- 盘点 UI 接收、排队、会话准备、用户消息持久化、配置与上下文准备、召回范围准备、结构化记忆检索、历史会话读取、上下文装配和 provider 请求准备；说明各阶段调用关系和耗时边界。
- 查明既有日志中召回前未归因的等待；证据不足时保留未知，不用相邻阶段的名称代替归因。
- 优化自动记忆召回与其共享会话查询能力；检查对显式历史检索、当前会话来源顺序及其他消费者的影响。
- 验证正常连续发送、交替使用多条长会话、冷启动或重新加载、新会话、历史追加、编辑、取消，以及并发读写下的行为。
- 分别报告各阶段延迟、扫描与缓存行为、内存和额外磁盘成本；固定样本、运行版本、冷热条件和测量方法。

### 不包含

- 模型供应商的服务端排队、推理速度或公网质量优化；可独立观测，不把它们纳入本地优化收益。
- 重做记忆抽取策略、人格或产品交互；不以关闭召回、缩小既有可见来源或静默跳过检索替代性能修复。
- 为兼容而支持低版本程序读取高版本写入的数据。
- 自动修改用户原始会话、清理用户数据、发布安装包或默认调用计费模型。

## 必须保持的行为

- 当前打开、正在加载或执行对话的会话不计入闲置会话回收预算；该豁免不等于允许历史查询副本和派生数据无界增长。
- 新版本可读取旧格式数据；升级与派生数据维护失败不能损坏原始历史。向旧版本回退不在兼容承诺内。
- 召回遵守当前有效历史、轮次边界、发言人、人格、时间和会话范围；编辑、归档及删除后的结果与既有契约一致，不恢复失效或已删除的内容。
- 取消必须可传播，不因后台查询、重建或持久化留下重复执行及不可解释的半完成状态。
- 诊断只记录必要的耗时、计数和脱敏关联信息，不新增聊天正文、凭据或完整模型输入的常规日志。

## 验收条件

- [ ] AC-01：完整发送链路具有明确的观测边界；可区分 UI 接收、后端排队、本地准备和 provider 请求边界，串并行阶段不重复相加；既有约 9.2 秒间隔有可复查的归因或明确的剩余证据缺口。
- [ ] AC-02：固定长会话样本的正常热发送不再因另一条大会话的检索而反复完整扫描原始历史；提供连续发送及多会话交替场景证据，不能只测同一查询连续命中。
- [ ] AC-03：基线和候选使用一致的样本、输入与条件，报告冷、热延迟分布及各阶段贡献；补齐基线后，在实现前将经确认的量化目标回写本需求，不以单次最佳结果代替验收。
- [ ] AC-04：召回来源、有效顺序、轮次排除、发言人与人格/时间/会话过滤、排序和来源定位具有确定性回归验证；任何结果差异均解释并确认，不静默接受语义退化。
- [ ] AC-05：覆盖追加、编辑、归档/删除、取消、并发访问、旧数据与派生数据失效场景；故障不破坏原始数据，不返回已失效的历史。
- [ ] AC-06：分别报告活跃会话与闲置派生状态的内存、持久化空间和维护代价；多会话重复访问不能引入无界增长，不以总体平均掩盖单条长会话回退。
- [ ] AC-07：项目规定检查通过；核心机制用 fake/mock 或离线回放验证，真实模型与真实桌面验证按相应授权执行；用户确认验收后才关闭需求。

## 开放问题

- 未归因间隔的主要成本及与查询扫描的关系，需进一步取证。
- 量化延迟目标、样本规模与允许的冷启动/维护成本，需先取得完整基线，再在方案确认时一并确定。
- 当前会话与跨会话检索适合复用哪些现有投影，哪些需要独立持久化，属于技术方案阶段，不在需求中预定算法或存储结构。
