# 工具执行治理

## 状态

CONFIRMED

## 背景

长会话中，一次“保留最后两个 Todo，其余全部完成”的用户意图被展开为 10 次独立 `todo_manage` 调用。工具执行本身耗时很短，但多次调用产生了重复请求和大段结果文本，并在上下文接近阈值时放大了后续压缩与模型续写成本。

这个案例反映的不是“所有工具都缺少批量接口”，而是项目尚未形成统一的多项操作治理原则：哪些操作属于一个原生业务动作，哪些独立调用应由运行时并行，哪些复杂流程应交给程序化编排，以及哪些敏感写入必须保留清晰的逐项授权和顺序边界。

与此同时，需求 075 已实现旧工具结果的占位清理、原始结果保留和按引用恢复，但工具注册表仍默认把未声明策略的结果视为 `pinned`。这使可安全恢复的普通工具结果无法自然参与既有的上下文治理。

## 目标

- 建立可复用的工具多项操作分类原则，避免以“可能多次调用”为由机械地给所有工具增加批量接口。
- 让业务上属于同一个动作的多目标操作使用原生批量能力，并以 Todo 作为首个完整落地。
- 让独立只读操作优先利用运行时并行，复杂 fan-out/fan-in 优先使用程序化编排。
- 保持敏感写入的授权、冲突、顺序和部分成功边界清晰可见。
- 将工具结果保留策略调整为默认 `recoverable`，只有确有必要的工具显式声明 `pinned`。
- 降低多次工具调用带来的上下文体积、模型续写和压缩成本，同时保留逐项错误与 revision 语义。

## 范围

### 包含

- 建立并应用以下工具执行分类：
  - 业务上属于一个动作的多项操作使用原生 batch。
  - 彼此独立的只读调用由运行时并行。
  - 复杂 fan-out/fan-in 由程序化编排完成。
  - 涉及授权、冲突或顺序依赖的敏感写入保留明确边界，不因调用次数多而自动批量化。
- 盘点现有内置工具，并使其多项操作策略、执行方式和结果保留策略具有明确、可审查的归属。
- 为 Todo 的同类多目标变更提供原生批量能力：
  - 单项与多项使用同一种调用形态，不增加仅用于切换批量模式的 `batch` 字段。
  - 一次调用只表达一种 Todo 操作，不在同一批次中混装创建、更新、完成等异构动作。
  - 每个输入项具有独立的 revision 校验、成功结果或错误结果。
  - 批量结果保持输入顺序，并避免为每一项重复返回不必要的完整 Todo 内容。
- 将未显式声明结果保留策略的工具默认归类为 `recoverable`。
- 对必须常驻模型上下文的结果显式声明 `pinned`，并保留理由清晰的例外集合。
- 保留“未注册结果恢复能力时按 `pinned` 处理”的既有安全兜底。
- 为本需求新增的批量契约、默认分类和显式例外补充针对性自动化测试。

### 不包含

- 不要求所有工具统一增加数组参数或原生 batch。
- 不因可能发生多次调用而直接改造文件 stat/read、文件 write/apply_patch/create_directory、web fetch 或 social read 的公开输入结构。
- 不改变需求 075 已确定的当前轮保护、最近 3 个历史工具批次保护、原始结果保留、占位清理或恢复接口。
- 不重新建设需求 075 已覆盖的整套工具结果恢复回归测试。
- 不在本需求中引入通用工作流引擎、全局工具 DSL 或任意异构操作编排协议。
- 不以真实 LLM 调用作为确定性验收前提。

## 治理原则

### 原生业务批量

当多个目标共同构成一次用户意图、共享一种业务动作，并且调用方需要逐项结果时，工具应提供原生批量能力。批量接口应表达领域动作，而不是暴露底层循环或把任意工具调用包装成通用 batch。

### 运行时并行

彼此没有数据依赖、权限边界一致且可独立失败的只读调用，应优先由运行时并行执行。是否进一步提供原生数组接口，由真实调用频率、结果聚合需求和 schema 清晰度决定。

### 程序化编排

需要动态 fan-out、条件分支、结果聚合或多阶段处理的任务，应优先进入程序化编排，而不是持续扩大单个工具 schema。

### 敏感写入边界

写入操作只有在授权范围、冲突处理、执行顺序和部分成功语义都能清楚定义时才适合原生批量。无法满足这些条件时，应保持逐项调用或显式串行。

### 结果保留

是否 `pinned` 由结果能否通过原始事件安全恢复、以及它是否承担不可丢失的授权或控制证据决定，不再仅由工具是否改变状态决定。可恢复的状态变更结果也可以是 `recoverable`。

## 验收条件

- [x] 已形成统一的工具多项操作分类，并完成现有内置工具盘点；每个工具的原生 batch、运行时并行、程序化编排或显式串行归属可被审查。
- [x] Todo 的同类多目标变更可在一次工具调用中完成；单项调用使用相同形态，且无需额外 `batch` 模式字段。
- [x] Todo 批量调用按输入顺序返回逐项结果，每项包含可识别的成功状态与 revision，或结构化错误；单项失败不会遮蔽其他项的结果。
- [x] Todo 批量成功结果只返回后续推理所需信息，不为每一项重复注入无关的完整内容。
- [x] “完成 10 个 Todo”可通过确定性测试证明只需要一次工具调用完成，并保留全部逐项结果语义。
- [x] 未显式声明保留策略的工具在存在恢复入口时默认为 `recoverable`。
- [x] 明确列为 `pinned` 的工具继续受到保护；未注册恢复入口时，既有自动 pin 兜底继续生效。
- [x] 需求 075 的既有恢复、保护窗口和原始事件测试继续通过；本需求只新增覆盖变化边界所必需的测试。
- [x] 文件写入、patch、目录创建等敏感写入不会因为本需求被无条件批量化。
- [x] 项目完整检查门禁通过，且验收过程不依赖真实 LLM 调用。
