# 统一通知管理、桌宠气泡布局与提示音

## 状态

CONFIRMED

需求编号：117。分支：`feature/117-unified-notifications`。

## 背景

目前主动消息、Todo 到期提醒、会话运行状态与审批状态分别由不同入口处理，缺少统一的提示规则。普通会话产生新结果、需要用户介入或异常结束时，用户离开对应会话后容易错过变化。

Todo 到期已经会触发目标会话中的完整 Agent 回复，但桌宠短提醒仍使用固定文案。用户希望桌宠像当前角色一样自然地提醒自己，同时让通知方式可以演进，不与业务入口绑定。

桌宠气泡和 actionbar 目前分别定位，存在互相覆盖的场景。通知增加后，还需要让提示音与气泡实际展示一致，并提供独立声音开关及后续音源扩展空间。

## 目标

1. 在统一位置管理需要提示的事件、打扰策略、重复处理及展示渠道。
2. 会话结果、需要介入、异常结束和 Todo 到期的桌宠通知使用简短自然文案，保持角色口吻，并优先保证响应速度。
3. 原有 Todo 会话事实与完整 Agent 回复继续保留；新增通知生成是独立的额外调用。
4. 桌宠、actionbar 与气泡共同避让屏幕边缘，保持清晰、稳定、互不遮挡的空间关系。
5. 提示音跟随新气泡实际展示，支持关闭，且未来可选择或自定义音源。
6. 通知使用当前本地人格与相关记忆保持连续性；实际发出后，由确定性代码记住这次通知行为，不为写入调用记忆抽取模型。

## 范围

### 包含

- 统一通知触发、抑制、去重、排队、失效处理与渠道分发。
- 会话一轮完成、明确等待用户介入、失败或确认的意外中断、Todo 到期。
- 共享的通知短文案生成能力，以及与原有 Todo Agent 回复并存的接入。
- 默认对话模型、最低可用思考档位和最小足够上下文的通知生成策略。
- 当前本地人格的直接复用、通知前的相关记忆召回，以及实际通知后的确定性 episodic 写入。
- 桌宠气泡作为本期主要新增提示渠道；现有通知渠道行为的兼容与未来系统通知的扩展边界。
- 设置页中的通知策略、气泡提示音开关和默认音源呈现。
- actionbar 与气泡共同定位，以及气泡首次展示时的声音播放。

### 不包含

- 用通知短文案替换 Todo 原有会话 Agent 回复、工具行为或确定性提醒事实。
- 本期新增操作系统通知渠道、用户上传音频、音频编辑或多个可选预设。
- 为通知新增一套独立模型选择设置；通知跟随当前默认对话模型。
- 为了生成通知而执行业务工具、重跑任务或在原会话发起新的工作回合。
- 仅凭普通文本中的问句、关键词或短暂连接中断推断任务已阻塞或失败。

## 需求

### R-1 提示事件与打扰策略

| 场景 | 用户可见行为 |
| --- | --- |
| 一轮完成并产生新结果 | 可提醒用户查看该会话，不将一条普通流式增量或中间输出当作完成 |
| 等待审批或明确需要用户输入 | 提示需要用户介入，并能返回对应会话处理 |
| 失败或确认的意外中断 | 准确说明任务未正常完成，不将失败表述为成功 |
| Todo 到期 | 按既有提醒归属与通知策略接入统一桌宠提示 |
| 用户主动停止 | 默认不额外提示，不与意外中断混淆 |

- 会话完成提示支持关闭、未查看对应会话时提示、始终提示；默认使用未查看对应会话时提示。
- 需要介入与异常提示有各自开关。当前会话已经清晰呈现的状态，不应通过多个入口重复打扰。
- 原有 Todo 的通知归属、智能选择与会话留痕继续有效，统一通知接入不能改变其目标会话或收件人。
- 一次事件只生成一条有效通知；重复推送、重连、历史恢复、文案补全不能重复弹出。
- 多个会话产生的有效通知可以排队，不能沿用“新消息覆盖旧消息”而丢失待处理事项。
- 等待介入的事项已经解决、任务已经取消或提示已经过期时，尚未展示的通知应失效。
- 点击通知可进入对应会话；目标已不可用时给出明确反馈，不导航至无关会话。

### R-2 自然文案与可靠性

- 本期新增通知使用共享的 LLM 短文案生成能力，表达简短、自然，保留角色口吻。
- 气泡明确标出来源名称：会话通知使用真实会话名称，Todo使用待办名称，不能只泛称“有个会话”。正文报事件状态，由 LLM 结合事件、人格与背景自主决定是否补充必要行动提示或自然的角色反应；不设置默认句数，不强制追加，不要求凑到目标字数。
- 新回复提醒承担报信职责，不继续回答原任务，不把原会话的答案、步骤、建议或解释压缩成摘要。确实需要用户处理时可点明待确认事项，详细内容留在原会话。
- 文案依据真实事件，不虚构结果、原因、执行动作或用户需要批准的事项。
- 事件身份、完成状态、权限状态、目标会话与可执行动作不能由模型改写。
- 先判断是否需要通知，再生成文案；已关闭、被抑制或已重复的通知不消耗额外模型调用。
- 原有 Todo 会话 Agent 回复及其上下文、工具能力、留痕继续保留。用户接受通知生成带来的额外调用成本。
- 同一个 Todo 到期事件不得同时展示旧固定气泡和新自然文案气泡，造成重复提醒。
- 通知生成失败、超时或返回无效内容时，使用简短事实文案兜底；不能因此丢失到期、介入或异常提醒。
- 通知生成与播放失败不能触发递归通知，也不能阻塞或改变原任务的执行结果。

### R-3 模型、上下文与响应速度

- 通知使用设置页当前选择的默认对话模型，不使用来源会话可能单独配置的模型或思考档位。
- 默认对话模型变更后，后续通知应使用新配置，无需用户重启应用。
- 使用模型实际支持的最低可用思考档位，不向不支持该参数的模型发送非法配置，不擅自替换为其他模型。
- 使用最小足够的提示词与事件上下文，包含有边界的相关记忆召回，不复制完整会话历史、工具描述、Skill 或普通工作回合的全部 system prompt。
- 使用当次本地正常对话正在使用的 `persona.md` 正文作为唯一人格事实源，沿用同一个人格读取入口；不维护另一份通知人格，不额外生成或缓存人格摘要替代原文。
- 记忆用于补充用户、关系和相关事件上下文，不作为第二份人格定义覆盖当前本地人格。
- 正常路径每条独立通知至多新增一次短文案生成；重连、重新展示、渠道投递与播放声音不得重新生成。
- 为通知生成设置有限等待时间；用生成耗时、输入规模和实际配置验证速度目标，不在未经实测时宣称固定时延已达标。

### R-4 桌宠组合布局

- 默认从下到上依次为桌宠、actionbar、气泡，气泡不覆盖 actionbar。
- 靠近显示器左右边缘时，actionbar 优先在桌宠朝屏幕内部的一侧竖排，即使没有气泡；离开边缘回到中央后恢复上方排列。
- 空间不足而切换到左侧或右侧时，整体遵循“桌宠 → actionbar → 气泡”的向外顺序，actionbar 位于桌宠与气泡之间。
- 共同依据形象所在显示器的可用空间、形象尺寸、操作栏尺寸与气泡内容安排位置。
- 气泡堆叠、长文展开、正常或 mini 形态、不同形象和缩放比例下保持可读与可操作。
- 多条消息中关闭一条时，退出与剩余消息补位连续完成；回收窗口空间不能再造成一次跳变。快速连续关闭及更高消息补位仍保持队列顺序。
- 拖动及跨显示器移动时同步跟随，不因独立的换边规则产生重叠或跳到另一显示器。
- actionbar 的 hover 显隐不能造成不必要的气泡跳动，其按钮提示也应保持可读。
- actionbar 记住用户当前停留的分页，隐藏后重新显示、刷新或重启后恢复；横竖切换或可用页数变化时恢复到有效页，初始化不能覆盖用户选择。
- 鼠标在 actionbar 内滚动时支持翻页，向下/向右进入下一页、向上/向左返回上一页；同一段连续滚动避免跳过多页，首末页不循环。
- actionbar 的 tooltip 始终朝组合布局的外侧：上方朝上、左侧朝左、右侧朝右；不能自动翻回桌宠一侧，也不能被气泡覆盖。
- 空间不足时通过整体换边、限制可见内容或排队处理，不能通过遮挡操作栏或将交互控件放到屏幕外解决。

### R-5 提示音与设置

- 设置导航提供独立的“通知”页，与“通用”平级，集中放置会话新回复、需要处理、异常结束、提示音和待办提醒发送方式。
- 设置页提供独立的气泡提示音开关，初版默认开启；关闭声音后气泡仍正常展示。
- 初版音源的用户可见名称为“默认”，不使用“系统默认”。Windows 上使用系统消息提示音。
- 声音开关与音源选择有独立演进空间，以后可增加预设选择或用户自定义音频，不改变通知业务的触发条件。
- 每条新气泡首次实际可见时至多播放一次；窗口已经打开时展示的新气泡同样适用。
- 用户关闭气泡后，从等待队列补位的消息静默展示；连续关闭和刷新后恢复这些补位消息也不补响。关闭后独立新到达的通知继续遵守正常提示音规则。
- 通知被抑制、尚在排队或最终未展示时不播放声音。
- 同一通知的展开、尺寸变化、重新定位、文本更新、重复推送或重连恢复不重播声音。
- 声音失败不阻塞气泡，不反复重试补播，不产生额外用户通知。
- Windows 默认音源遵循系统声音方案及系统声音音量；其他平台保持明确的兼容行为，不因缺少 Windows 音源而报错。

### R-6 通知记忆的读取与写入

- 通知生成前召回与本次事项相关的既有记忆，查询主题来自真实事件与关联任务，而不是生成后的通知文案。
- 复用现有记忆召回入口与检索语义，不为通知另建召回策略或增加专用检索参数；在技术方案中明确 query 来源与通知上下文的装配预算。
- 召回不额外调用生成式 LLM 改写 query，不等待原会话的记忆抽取或索引回填完成；记忆不可用时仍能依事件事实生成或展示通知。
- 实际发出通知后，使用特殊的确定性写入路径生成一条 episodic，记录“发出了这条通知”这一事实。
- 记忆至少能解释通知发生的时间、相关事项、实际渠道及发送的内容；正文由代码基于通知事实生成，不交给 extractor、reconciler 的模型抽取链路处理。
- 对桌宠渠道，“已发出”以气泡实际展示的确认作为依据；仅生成文案、入队、推送到前端或尝试打开窗口不算已经通知。
- 该记忆只证明通知已发出或已展示，不声称用户已经看到、理解、同意或完成了被提醒事项。
- 使用稳定通知身份去重，重复展示回执、重连和补写不能产生重复 episodic，也不能通过重复写入恢复已经失活的同一条记忆。
- 确定性写入沿用现有 episodic 存储与检索能力，保留明确来源；不将通知伪装成普通用户或助手对话再交给记忆抽取。
- 写入失败只影响记忆投影，不能重发通知、重播声音或改变原任务状态；补写需要再次核对其实际投递事实。
- 后续普通对话能够召回已经发出的通知；通知生成自身不注入“已发出通知”这一来源的 episodic，避免反复引用自己的通知记录。

## 验收条件

- [x] AC-1：完成、需要介入、异常结束与 Todo 到期均由统一通知策略处理，手动停止和中间输出不会误报。
- [x] AC-2：通知开关与查看状态能影响展示；被抑制事件不调用通知 LLM，原会话结果和 Todo 留痕继续存在。
- [x] AC-3：Todo 原有完整 Agent 回复不受影响，新增自然文案气泡不会与旧固定气泡重复出现。
- [x] AC-4：通知调用使用最新默认对话模型与其最低可用思考档位，不沿用来源会话配置，不修改正常对话模型配置。
- [x] AC-5：通知直接使用当前本地人格正文，并注入预算内的相关记忆；一次事件不因投递、重连或播放而重复生成。
- [x] AC-6：超时、空结果、调用错误和不可用配置均能安全兜底；通知不会递归触发自身，也不改变原任务状态。
- [x] AC-7：通知可排队、去重和失效，返回对应会话；已解决的介入事项不会延迟弹出过期提示。
- [x] AC-8：桌宠中央、边缘、角落及左右换位时，气泡与 actionbar 均保持约定的外侧顺序与可操作性。
- [x] AC-9：长文、多条气泡、actionbar 显隐、持续拖动、mini 形态与不同缩放的多显示器场景覆盖组合布局边界。
- [x] AC-10：提示音开关持久化且跨窗口生效，音源名称为“默认”；关闭声音不影响气泡。
- [x] AC-11：首次实际展示播放一次，排队未展示不播放；关闭引起的队列补位静默，连续关闭和刷新恢复不补响；独立新通知不漏播，重复推送、展开及定位变化不重播。
- [x] AC-12：Windows 默认消息提示音经实机验证；播放不可用或失败不阻塞通知，其他平台保持兼容。
- [x] AC-13：通知生成机制有确定性验证，实际文案和速度在取得本次真实 LLM 调用授权后观察验证；未执行的真实调用或桌面验收不能记为通过。
- [x] AC-14：项目检查通过，用户确认验收完成。
- [x] AC-15：四类通知复用现有召回，query 有明确事实来源且不额外调用改写模型；通知上下文排除“已发出通知”的 episodic，普通对话仍能召回；记忆读取失败不阻塞通知，原有对话召回行为不变。
- [x] AC-16：仅实际发出的通知产生确定性 episodic；被抑制、排队未展示或取消的通知不会被记成已经提醒。
- [x] AC-17：episodic 保留通知时间、事项、渠道和实际内容，可被普通对话召回；不推断已读、不经过 extractor，也不重复送入普通对话抽取路径。
- [x] AC-18：重复回执、补写、重连不重复入库，已失活记忆不被重新激活；记忆写入失败不导致通知或声音重放。
