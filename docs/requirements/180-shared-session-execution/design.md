# 180 · 普通聊天与内心活动共用会话执行入口 · 技术方案

## 状态

CONFIRMED，2026-11-21。行为和验收条件见[需求文档](requirement.md)。

## 执行边界

`Conversation` 负责一次带工具会话从准备到收尾的整个生命周期。普通请求沿用原有接纳、编辑、附件、重复提交和继续任务的语义。自主唤醒仍是持久内心会话上的一次系统事件。两种来源共用历史协调、工具事务修复、当轮 Skill 目录、模型请求装配、工具执行、压缩、取消和资源释放。公开的聊天、提醒和调度入口保持兼容。

唤醒服务继续拥有时机、暂停、变化快照和投递；会话引擎负责执行。活动简报以宿主来源进入模型上下文，工具的“用户当前输入”只取真人输入。内心活动可以按当前目录隐式加载 Skill；历史中出现过的名字、用户授权和旧文件作用域均须按现有规则核验。保留无工具系统轮，以及提醒、外部授权续跑各自原有的能力范围。

## 首个模型请求

用户输入与有实质变化的会话预览可作为召回线索。唤醒侧复用已经读取的变化快照，从有新增业务消息的条目选取有界的正文预览，排除首次全量盘点、仅投递/展示状态变化和 AF 自己主动投递的内容。线索只供检索，不作为当轮用户原话或工具授权。缺少线索时利用已有内心历史；AF 仍可调用历史工具。目录、记忆正文和来源标记沿用已有资源。通过假模型捕获基线及独立候选的完整请求，核对差异后再接入正式入口。

首个请求发送前修复已有历史中未配对的工具事务。同步已有结果，或按既有协议标明中断与未知执行状态。系统触发事实在首次上下文构建前落盘，保持压缩指纹和恢复边界一致。工具续轮继续执行相同的历史与预算契约。

## 请求重试与收尾

提供方使用公共的有限重试配置。自主模型包装保留用量记录、暂停和取消检查，并透传调用方的重试上限。重试发生在同一模型请求内；已经完成的命令和分享继续依靠各自的已执行事实及投递回执。结束、异常和取消统一释放当轮 Skill、命令及会话运行状态。自主活动状态、下次唤醒和静默通知继续由既有观察者处理。

## 验证

在隔离数据目录中使用脚本化模型，走普通聊天入口和自然唤醒入口。分别检查模型实际收到的目录与记忆、技能绑定脚本的执行结果、历史修复事实、重试和取消。复用图片回看、定时任务、提醒、授权续跑与自主投递的现有测试。MAA 案例保留空变化清单和原约定，执行端使用替身，观察允许、拒绝和副作用计数。真实设备和模型行为验证与确定性机制验证分别记录。
