# 180 · 普通聊天与内心活动共用会话执行入口

## 状态

CONFIRMED，2026-11-21。

## 背景与目标

11 月 21 日，用户和 AF 约好跳过当天的方舟定时任务，观察 AF 能否在五点左右自然醒来后自行执行。AF 在 16:58 醒来，从方舟会话找回了约定，随后把“两号都没跑”的结果发回原会话。该轮有读取 Skill 和执行命令的工具，却没有本轮可加载的 Skill 目录。离线对照中，给两个入口相同的有效 Skill ID，普通聊天加载成功，内心活动返回 `skill_snapshot_unavailable`。

这次 16:58 唤醒的会话变化清单为空。AF 仍能接着已有历史想起约定，并主动读取方舟会话。复现时应保留这项条件，以便区分“记得约定”和“能够执行”。

同一组对照还发现，遇到上轮工具调用缺失结果时，普通聊天能补记“执行结果未知”并继续，内心活动在请求模型前就失败了。单独用干净会话验证时，只有普通聊天在首轮自动查询相关记忆。

本需求让普通聊天与自然唤醒通过同一个入口执行一次会话。通用能力接入一次，两边都能使用。自主陪伴仍然负责唤醒时机、暂停、授权和成果分享。内心会话的只读展示、活动来源和投递语义沿用[自主陪伴设计](../169-autonomous-companionship/design.md)。

## 需求

1. **技能与工具。** 两种回合在相同模型、配置、已安装 Skill 和权限条件下，能发现、加载并使用同样的通用能力，包括执行当前已激活 Skill 的脚本、生成和查看图片。每轮按当前目录、权限和实际工具结果判断可用性。新接入的通用能力应自然覆盖两种回合。
2. **历史与故障恢复。** 两种回合都能从已有会话历史开始或继续，遵循共同的上下文压缩、工具结果修复、有限重试和取消规则。遇到旧回合中断，优先采用已有的执行结果；只有执行结果确实无法核实时，才记为未知。恢复过程防止重复执行可能已经生效的操作。
3. **按线索召回。** 普通聊天可用当前用户输入召回相关记忆；自然唤醒可用简报里确有内容变化的线索找回相关约定。唤醒缺少新线索时，AF 可以沿已有内心历史继续，也可以安静结束。时间戳、投递状态等例行更新本身无需触发一遍全简报检索。
4. **来源、权限与分享。** 会话记录和长期记忆保留谁发起了这一轮。历史消息、记忆与唤醒预览供 AF 参考，实际执行遵守当轮自主权限、暂停与取消状态。内心独白默认只在活动页可见；AF 决定分享并实际投递后，目标会话或 IM 才出现对应消息。

## 验收条件

- [x] **AC-01 · 自主执行方舟约定。** 在隔离环境重放“两点的定时任务跳过，五点左右自然醒来再跑”。保留之前的内心历史和可供读取的方舟会话，在会话变化清单为空时自然唤醒。AF 能找回约定，发现并加载 `maa-daily`，调用其脚本。用可观察的替身验证允许执行和明确拒绝两种结果，回报与实际执行一致。自主活动期间原定时任务的配置和触发次数保持原值。
- [x] **AC-02 · 新能力只接入一次。** 在公共目录新增一个与 MAA 无关的测试 Skill，在两个入口分别发现、激活并执行同一无副作用脚本。再在支持图像的模型配置下检查两个入口都能生成并回看同一张测试图片；在不支持相关能力的配置下，两边都如实反映限制。
- [x] **AC-03 · 旧历史能够继续。** 两种入口各自打开具有相同中断记录的既有会话。已落盘的工具结果能恢复到下一次模型请求；缺少结果时，模型收到“执行结果未知”，本轮能继续，旧操作的实际执行次数不增加。
- [x] **AC-04 · 有界重试与取消。** 给两种回合注入同类可恢复的模型故障，观察到相同的重试条件和上限。主动取消后终止等待及后续尝试，自主活动暂停后也会终止。恢复前已执行的工具或已投递的分享各只发生一次。
- [x] **AC-05 · 有、无线索的唤醒。** 在同一份隔离记忆中写入相关约定和无关旧事。带相关会话变化的唤醒与普通聊天均能得到相关约定。只有例行状态变化的唤醒可沿本会话历史继续或结束，不因整份简报而自动带入无关旧事。
- [x] **AC-06 · 自主行为可追溯。** 同一段来自历史的文字作为唤醒线索时，会话与记忆均保留其来源。权限拒绝能阻止动作；暂停联系后不向外投递；单纯完成内心活动不触发普通回复通知。允许分享时，能从投递记录核对目标和结果。
- [x] **AC-07 · 现有入口兼容。** 核对普通聊天的附件、编辑重发与继续任务，原有定时任务、提醒和外部授权后续跑，以及显式关闭工具的静默系统轮。每个入口继续遵守已约定的输入、工具权限和输出去向。
