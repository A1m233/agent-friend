> IM Conversation Control Surface

## 1. 背景

当前 QQ IM 接入会为一个 QQ 聊天默认绑定一个 Agent 会话，用户无法在绑定时选择已有会话，也无法在 QQ 中切换会话或模型。这使 QQ 通道可以继续对话，却缺少桌面对话页已有的基本控制能力。

QQ 官方“快捷菜单”需要机器人所有者前往 QQ 开放平台手工配置。agent-friend 由每个用户连接自己的 QQ 机器人，不能把这种额外配置成本转嫁给用户。同时，命令式交互需要记忆语法，不适合作为面向普通用户的主入口。

因此，本需求要在不增加 QQ 开放平台手工配置、不要求用户记住命令的前提下，为支持消息按钮的 QQ 机器人补充清晰、可发现的会话与模型控制入口。

## 2. 目标

1. 让用户在 QQ 首次绑定时，能明确选择创建独立会话或继续已有会话。
2. 让用户无需记忆命令，即可从每次正常助手回复中打开 QQ 控制菜单。
3. 支持在 QQ 中切换后续消息对应的 Agent 会话，以及切换当前绑定会话的模型。
4. 保持 Agent 会话为对话内容的唯一事实来源，同时尊重 QQ 自身无法替换历史消息的连续聊天形态。
5. 对不支持消息按钮的 QQ 机器人安全降级，不把手工开通、后台配置或命令学习转化为用户负担。

## 3. 范围

### 3.1 包含

- QQ 首次绑定 Agent 会话时的双路径选择：创建独立会话，或从最近会话中选择。
- 在最近会话列表中默认选中上次活跃的桌面会话，并使用“上次活跃会话”标签明确标识。
- 每次正常完成的助手回复下方都附带一个 `☰ 菜单` 按钮。
- 点击 `☰ 菜单` 后打开临时控制面板，本期提供“切换会话”和“切换模型”。
- 会话切换后，QQ 后续消息转入新绑定的 Agent 会话。
- 模型切换作用于当前绑定的 Agent 会话，并与桌面对话页看到的会话状态保持一致。
- 切换会话后在 QQ 中给出简短确认，包含足以识别目标会话的信息和最近助手回复预览。
- QQ 普通用户消息和助手回复进入当前绑定的 Agent 会话；菜单、选项面板、切换确认、超时和错误等 QQ 控制消息不进入 Agent 会话。
- QQ 发起的助手回合正在生成时，禁止切换会话或模型，并向用户说明原因。
- 系统自行识别当前 QQ 机器人是否可使用所需的消息按钮能力，并根据结果展示或隐藏 QQ 内控制入口。
- 保留现有 `im:qq:*` 自动创建会话及其历史数据，不要求迁移或重建。

### 3.2 不包含

- 要求用户前往 QQ 开放平台手工创建或配置快捷菜单。
- 将 QQ 官方“快捷菜单”作为本期交互入口。
- 使用 slash command、文本命令、特定符号或自然语言意图触发会话与模型切换。
- 为不支持消息按钮的机器人引导申请资格、人工开通或额外后台配置。
- 切换会话时迁移、复制、合并或重写旧会话内容。
- 将目标 Agent 会话的完整历史回放到 QQ，或替换 QQ 客户端已有消息记录。
- 将 QQ 聊天拆分成多个可见的子会话、话题或线程。
- 把本期控制面板扩展成通用的 QQ 机器人功能中心。
- 建设由 agent-friend 统一托管、为多个用户转发消息的公共 QQ 机器人。

## 4. 核心需求

### 4.1 首次绑定

- **R-1.1 双路径绑定**：首次为 QQ 聊天绑定 Agent 会话时，必须同时提供“创建独立会话”和“选择最近会话”两种选择，不得在用户无感知的情况下只执行默认绑定。
- **R-1.2 上次活跃会话默认值**：最近会话列表默认选中上次活跃的桌面会话，并显示“上次活跃会话”标签；用户仍可改选其他最近会话。
- **R-1.3 明确完成绑定**：绑定完成后，用户能够确认 QQ 后续消息将进入哪个 Agent 会话。

### 4.2 QQ 菜单入口

- **R-2.1 每次回复可达**：每次正常完成的助手回复都必须附带且只附带一个 `☰ 菜单` 按钮，使用户始终可从最新回复进入控制面板。
- **R-2.2 文案语义**：`☰ 菜单` 是消息按钮的用户可见文案，表示展开更多操作；它不代表、不依赖 QQ 官方需后台手工配置的“快捷菜单”。
- **R-2.3 控制消息不递归**：菜单面板、切换确认、超时、错误和其他控制消息不继续附带 `☰ 菜单`，避免控制交互层层嵌套。
- **R-2.4 当期菜单范围**：打开菜单后，当期只需提供切换会话和切换模型两项能力。

### 4.3 会话切换与历史语义

- **R-3.1 后续路由**：切换会话只改变 QQ 后续普通消息的 Agent 会话归属，不改变已发送消息的归属。
- **R-3.2 QQ 时间线连续**：QQ 客户端保持原有的单聊天时间线；系统不尝试在切换时清空、替换或重放 QQ 历史。
- **R-3.3 Agent 会话归属**：切换前的普通 QQ 对话留在原 Agent 会话；切换后的普通 QQ 对话进入新 Agent 会话，不进行跨会话迁移、复制或合并。
- **R-3.4 切换确认**：切换成功后必须发送简短确认，让用户知道后续对话已切换。确认内容应包含会话标题、当前模型、最近活动时间和最近一条助手回复的简短预览，但不展示完整历史。
- **R-3.5 运行中保护**：QQ 发起的助手回合尚未结束时，不得切换会话或模型；拒绝操作时应说明需等待当前回复完成。

### 4.4 模型切换

- **R-4.1 会话级模型**：QQ 中的模型切换作用于当前绑定的 Agent 会话，不建立 QQ 独有的模型副本或隐藏覆盖。
- **R-4.2 状态一致**：从 QQ 或桌面端切换模型后，另一个入口应能看到同一会话的最新模型状态。
- **R-4.3 结果反馈**：QQ 中的模型切换必须给出成功或失败反馈，失败时不得留下看似已切换的错误状态。

### 4.5 消息边界

- **R-5.1 普通对话入库**：QQ 用户发送的普通对话和对应助手回复必须进入当前绑定的 Agent 会话，使桌面端继续打开该会话时能看到同一段对话。
- **R-5.2 QQ 控制消息隔离**：QQ 菜单、按钮选择、切换确认、超时和错误等通道级控制消息不得进入 Agent 会话、不得被组装为后续模型上下文。
- **R-5.3 既有数据保留**：已存在的 `im:qq:*` 自动创建会话及历史数据必须继续可用；上线本能力不要求历史迁移。

### 4.6 能力限制与降级

- **R-6.1 无手工配置**：使用 QQ 内控制入口不得以用户手工配置快捷菜单、手工填写按钮模板或额外开通流程为前提。
- **R-6.2 能力自检**：系统应自行判断或从实际结果可靠得知当前 QQ 机器人是否可使用所需的消息按钮，不要求用户理解 QQ 能力开通状态。
- **R-6.3 安全降级**：当按钮能力不可用时，QQ 保持普通对话能力，会话与模型继续在桌面端管理；不得自动降级为命令或自然语言意图交互。
- **R-6.4 可理解状态**：当 QQ 内控制入口不可用时，桌面端应让用户知道 QQ 仍可正常聊天，但会话和模型需在桌面端管理。

## 5. 验收标准

- **AC-1**：新连接的 QQ 聊天首次绑定时，同时看到“创建独立会话”和“选择最近会话”；最近会话中默认选中上次活跃的桌面会话并显示“上次活跃会话”标签。
- **AC-2**：用户完成绑定后，QQ 的后续普通对话进入所选 Agent 会话，桌面端打开同一会话可见。
- **AC-3**：当前 QQ 机器人支持所需消息按钮时，每次正常助手回复下方都且只有一个 `☰ 菜单` 按钮；控制消息和错误消息不继续附带该按钮。
- **AC-4**：点击 `☰ 菜单` 可打开控制面板，面板当期只提供切换会话和切换模型，无需用户输入命令。
- **AC-5**：从 QQ 切换会话后，切换前的消息仍属于原 Agent 会话，切换后的消息属于新 Agent 会话，QQ 已有消息时间线不被改写或重放。
- **AC-6**：会话切换成功后，QQ 显示目标会话的标题、当前模型、最近活动时间和最近助手回复短预览，但不回放完历史。
- **AC-7**：从 QQ 切换当前会话的模型后，桌面端可见同一模型状态；从桌面端再次切换后，QQ 菜单展示的状态与之一致。
- **AC-8**：QQ 回合正在生成时尝试切换会话或模型，操作被拒绝且给出明确提示；当前回复仍完整落入原会话。
- **AC-9**：QQ 普通对话进入 Agent 会话，而菜单、切换确认、超时和错误等控制消息不出现在桌面会话历史中，也不进入后续模型上下文。
- **AC-10**：既有 `im:qq:*` 会话及历史在升级后仍可继续使用，无需迁移；新菜单能力不改写其历史。
- **AC-11**：当当前 QQ 机器人不支持所需消息按钮时，QQ 仍可正常聊天，不出现命令或自然语言降级入口；桌面端明确告知会话和模型需在桌面端管理。
- **AC-12**：完成上述交互不需要用户前往 QQ 开放平台手工配置快捷菜单、按钮模板或额外开通流程。
- **AC-13**：项目规定的自动化门禁全部通过，既有 QQ 消息收发、会话恢复、桌面会话和模型切换行为不退化。

## 6. 依赖与约束

- QQ 内可点击菜单受当前 QQ 机器人实际具备的消息按钮能力约束；本需求不以用户手工申请或配置能力为成功前提。
- Agent 会话仍是用户与助手普通对话内容的唯一事实来源；QQ 只是其中一个消息入口和展示时间线。
- 桌面端保留完整的会话与模型管理能力，QQ 不承担完整会话管理器的职责。
- 目标会话在桌面端产生的新消息不需要主动补发到 QQ；QQ 只展示通过 QQ 通道实际发送的消息与必要的控制反馈。
