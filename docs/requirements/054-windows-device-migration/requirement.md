# 054 · Windows 设备一次性迁移

## 状态

CONFIRMED

## 背景

agent-friend 的用户资产当前分布在会话、长期记忆、人格、桌面设置、系统凭据存储、IM 绑定和用户模型目录等多个位置。用户更换电脑时，即使在新设备重新安装应用，也无法仅靠复制某一个目录继续原来的使用状态；API 密钥、QQ 绑定和设备相关状态还具有不同的安全与恢复边界。

本项目暂不建设用户账号、云端存储或多设备持续同步。用户需要的是一次性换机能力：在仍可使用旧电脑时生成一个可自行携带的迁移包，通过 U 盘、个人网盘或其他文件传输方式带到新电脑，在新安装中恢复原来的 agent-friend。

迁移完成后的核心体验不是“文件复制成功”，而是用户仍面对同一个认识自己、记得过去、保持原有人格和偏好的朋友；同时，私人会话、长期记忆和外部服务凭据不能因迁移包泄露而直接暴露。

## 目标

- 提供不依赖账号或项目云服务的 Windows 设备一次性迁移能力。
- 用户能够在旧电脑生成单个可携带的迁移包，并在新电脑完成导入和恢复。
- 完整迁移不可重建的用户资产，使历史会话、长期记忆、人格、偏好和用户模型在新设备继续可用。
- 将 API 密钥纳入完整迁移，正常情况下不要求用户在新设备重新输入。
- 尽最大可能恢复 QQ 绑定；第三方平台拒绝旧授权时，明确引导用户重新扫码，不静默丢失。
- 对迁移包中的私人数据和敏感凭据提供完整保护，文件被单独取得时不能直接读取内容。
- 新设备已有数据时不做复杂合并，仅在用户充分知情、已有可靠回滚备份的前提下整体替换。
- 迁移失败不得破坏新设备原有数据，不得留下半新半旧的混合状态。

## 范围

### 包含

#### 迁移入口与基本流程

- 旧电脑提供“迁移到新设备”入口，生成一个由用户自行携带的迁移包。
- 新电脑提供“从旧设备恢复”入口，允许用户选择迁移包并完成导入。
- 第一版正式支持和验收 Windows 到 Windows 的迁移。
- 迁移过程不要求用户注册或登录 agent-friend 账号，不依赖 agent-friend 云服务。
- 迁移包是一次性设备迁移载体，不承担多设备持续同步或自动备份职责。
- 导出和导入期间应清楚展示当前阶段、完成结果以及用户接下来需要执行的动作。

#### 用户资产迁移

完整迁移至少覆盖以下不可重建或具有用户价值的数据：

- 历史会话、消息事件、会话元信息及维持历史可读性所需的数据。
- 长期记忆及维持现有记忆检索、事实版本和来源关系所需的数据。
- 当前人格正文、人格内部状态和关系连续性所需的数据。
- 用户可见的持久设置，包括主题、当前聊天与记忆模型选择、当前桌宠模型选择等。
- API 密钥和其他由应用管理的长期运行凭据。
- QQ 等已支持 IM 通道的绑定凭据和恢复绑定所需的数据。
- 用户自行导入、创建或修改的桌宠模型及其 catalog、metadata 和资源文件。
- 其他已经明确归类为用户资产、且无法由安装包或新设备运行时安全重建的数据。

迁移后，已有会话和记忆的稳定标识及相互引用应保持有效；不能因为换机导致同一段历史变成无法访问的新副本。

#### 模型资产边界

- 在线 LLM 不存在需要搬运的本地模型文件；迁移其 provider、model 选择和对应 API 密钥。
- 安装包自带、能够在新设备自动安装或修复的内置桌宠模型不进入迁移包；新设备安装后应自动恢复这些资源。
- 安装包自带的记忆检索模型及其他只读运行资源不进入迁移包，也不要求用户在迁移后手动下载。
- 用户自行新增的模型属于用户资产，必须随完整迁移包恢复。
- 如果迁移包选择的内置模型在新设备暂时不可用，应用应先完成内置资源恢复，再决定是否需要 fallback；不能因为没有搬运可重建资源而永久丢失用户选择。

#### 迁移包保护与迁移码

- 完整迁移包必须整体受到加密和完整性保护；不得以普通明文压缩包承载私人内容或凭据。
- 迁移码由应用自动生成，用户不需要自行设计新密码。
- 迁移码应具备足够强度，能够抵抗持有迁移包后的离线猜测；不得使用短数字验证码代替。
- 迁移码不写入迁移包、不随包生成同目录明文文件、不上传到 agent-friend 服务，也不作为长期账号密码保存。
- 导出完成后，应允许用户查看并以可理解的方式转移迁移码，同时明确提示迁移码需要与迁移包分开保管。
- 导入时必须同时持有有效迁移包和迁移码；错误迁移码不得泄露包内数据，也不得改动本机现有数据。
- 导入成功后提示用户删除不再需要的迁移包并妥善处理迁移码。

#### API 密钥与 QQ 绑定

- 完整迁移必须包含应用当前管理的 API 密钥和长期服务凭据。
- “应用当前管理”仅指用户通过 agent-friend 正常界面写入系统凭证管理器的凭据；开发或特殊启动环境中的进程环境变量、`.env` 与 `legacy-dotenv` 不参与盘点、导出或恢复。
- 导入成功后，凭据应进入新电脑对应的安全凭据存储；不得作为普通设置明文长期保存。
- 正常且仍有效的 API 密钥在新电脑无需重新输入即可继续使用。
- QQ 绑定应尽最大可能迁移并适配新电脑的本地保护环境，不能直接复制一份只能由旧电脑解开的密文后宣称成功。
- QQ 平台或其他第三方服务拒绝已有授权、令牌已过期或要求重新认证时，应用应把该项标记为需要用户处理，并提供重新扫码或重新绑定入口。
- 第三方重认证属于可解释的部分恢复结果，不影响已经成功恢复的会话、记忆、人格等本地数据。
- 迁移结果不得把“本地凭据文件已写入”误报成“第三方绑定已恢复可用”。

#### 导入前检查

任何本地数据替换开始前，至少完成以下检查：

- 迁移包属于受支持的 agent-friend 迁移格式，且未被破坏或篡改。
- 用户提供的迁移码可以正确解开迁移包。
- 迁移包的数据版本与当前应用兼容。
- 新设备具备完成恢复和创建回滚备份所需的磁盘空间与文件访问条件。
- 包内必需数据完整，不存在已知会导致恢复后无法启动或无法读取核心用户资产的问题。
- 应用当前没有会使一致恢复无法完成的活跃操作；必要时明确要求用户结束相关操作。

任一检查未通过时，不得改动现有用户数据，并应给出具体、可执行的处理建议。

#### 空数据区恢复

- 新设备尚未产生有效用户数据时，迁移包可以直接恢复到当前用户数据区。
- 应用安装产生的默认设置、默认人格占位或可重建内置资源不应被误判为需要危险替换的用户数据。
- 恢复完成后，应用重新加载迁入的数据和凭据，并逐类验证关键资产可读、关键设置可用。

#### 已有数据区整体替换

- 新设备已经存在有效用户数据时，第一版不尝试自动合并两套数据。
- 应用必须明确告知用户将执行整体替换，并展示受影响的数据摘要，例如现有会话、记忆、人格、用户模型和已配置凭据。
- 风险说明必须明确：当前设备已有数据会被迁移包内容替换，迁移包导出后两台设备继续产生的变化不会自动合并。
- 替换确认复用项目统一的危险操作 double-check 交互，确认按钮使用危险操作样式，并在可见倒计时结束前保持不可用。
- 用户取消、关闭弹窗或倒计时尚未结束时，不得开始创建破坏性替换动作。
- 任何破坏性写入前必须成功创建一份可验证的本机回滚备份；备份失败时终止替换。
- 替换必须作为完整操作对用户呈现：任一步骤失败时自动恢复原状态，不留下部分使用旧数据、部分使用新数据的状态。

#### 本机回滚备份

- 每次整体替换前创建一份带时间信息的本机回滚备份，系统只保留最近一份有效备份。
- 回滚备份覆盖恢复替换前完整状态所需的数据和凭据。
- 回滚备份仅服务当前 Windows 用户和当前设备上的撤销操作，不作为跨设备迁移包使用。
- 回滚备份不会按时间自动删除；下一次破坏性操作生成并验证新备份后，以明确可见的轮换流程替换上一份备份，不得在新备份尚未验证时删除旧备份。
- 设置中心展示当前这一份回滚备份，至少展示创建时间、来源说明和占用空间，并提供恢复与删除入口。
- 用户删除回滚备份前必须经过危险操作二次确认。
- 恢复回滚备份前，先为当前状态创建并验证新的备份，再将它轮换为最近备份，避免恢复操作本身造成不可撤回的数据丢失。
- 磁盘空间不足以创建并验证新备份时，阻止迁移或恢复；应用不得先删除当前有效备份来腾出空间。

#### 迁移执行与失败恢复

- 迁移开始后，应暂时阻止会改变相关用户数据的并发操作，避免导入过程中继续产生新写入。
- 迁移包内容应先在隔离位置完成恢复和校验，再替换当前有效数据；不得直接在生产数据上逐文件覆盖。
- 替换前后的有效数据边界必须清楚，应用崩溃、进程退出或单项写入失败后仍能够判断并恢复到一致状态。
- 替换失败时自动回滚，并向用户说明失败阶段、原数据是否已恢复以及可采取的下一步。
- 替换成功后重新加载或重启受影响的本地服务，不能要求用户自行猜测哪些进程需要重启。

#### 结果报告

- 导入完成后逐类展示恢复结果，至少区分成功、无需迁移、需要用户处理和失败。
- 会话、长期记忆、人格、设置、用户模型、API 密钥和 QQ 绑定应有独立结果，不使用单一“导入成功”掩盖部分失败。
- 需要重新授权系统权限、重新扫码 QQ 或处理不兼容用户模型时，结果页提供明确入口或说明。
- 迁移完成后应能确认核心本地资产可读；不能只依据文件存在判断成功。

#### 版本兼容

- 迁移包记录生成它所需的应用与数据版本信息。
- 新设备应用版本过旧、无法理解迁移包时，应提示用户先升级，不尝试降级解释或冒险写入。
- 新版本应用应为已发布的旧迁移格式提供明确兼容或迁移路径；无法兼容时必须在写入前阻止并说明原因。
- 第一版不承诺把新版本生成的数据倒灌到旧版本应用。

#### 设备相关状态处理

- Windows 系统权限不随迁移包直接恢复；新设备应按照当前统一权限流程重新检测和申请。
- 开机启动等由当前 Windows 环境控制的系统集成不直接照搬，必要时在导入结果中提示用户重新确认。
- 窗口绝对坐标、尺寸、桌宠屏幕锚点等依赖显示器布局的状态不原样迁移，应在新设备安全重建或使用合理默认值。
- IM 临时 resume token、临时公网地址、进行中的通话、请求和其他短生命周期连接状态不迁移。

### 不包含

- 不建设 agent-friend 账号、云端存储、云备份或云同步。
- 不做两台设备之间的持续同步、冲突检测或双向同步。
- 不合并新设备和迁移包中的两套会话、记忆、人格、设置、凭据或模型数据。
- 不支持或验收 Windows 与 macOS、Linux 之间的跨平台迁移。
- 不迁移日志、诊断包、缓存、临时文件、运行中任务或其他可安全重建的数据。
- 不迁移进程环境变量、`.env`、`legacy-dotenv` 或其他不由正常桌面界面管理的外部配置。
- 不重复携带安装包已经提供且能在新设备自动修复的内置模型和只读运行资源。
- 不在本需求中实现用户模型导入向导、模型市场或远程模型下载；只要求未来由用户新增的模型进入迁移资产边界。
- 不承诺绕过 QQ 或其他第三方平台强制实施的重新认证、安全校验或授权失效策略。
- 不在需求阶段锁定迁移包内部结构、加密算法、迁移码显示格式、备份文件布局或事务实现；这些由 `design.md` 在安全与现状调研后确定。

## 验收标准

- [ ] 用户可以在旧 Windows 电脑生成单个迁移包，并在新 Windows 电脑选择该文件完成恢复，全程不需要 agent-friend 账号或项目云服务。
- [ ] 应用自动生成足够安全的一次性迁移码；迁移码不进入迁移包、不生成同目录明文副本，也不被长期保存为账号密码。
- [ ] 迁移包中的私人内容、API 密钥和 QQ 凭据不能被普通解压或直接读取；迁移包损坏、被篡改或迁移码错误时，导入在任何本地写入前失败。
- [ ] 空数据区导入后，旧电脑的历史会话、长期记忆、人格与关系状态、持久设置和模型选择在新电脑继续可用。
- [ ] 正常有效的 API 密钥迁移到新电脑的安全凭据存储，无需用户重新输入即可被相应能力使用。
- [ ] 仍被 QQ 平台接受的绑定在新电脑恢复可用；平台拒绝旧授权时，该项明确标记为需要重新扫码，并提供恢复入口。
- [ ] 用户自行新增的桌宠模型及其 metadata、catalog 和资源文件能够恢复；安装包自带模型不进入迁移包，且在新设备无需用户手动下载即可重建。
- [ ] 迁移包不重复携带安装包自带的记忆检索模型；新设备安装后记忆检索仍可使用。
- [ ] 应用能够区分只有默认占位数据的新安装和已经存在有效用户数据的安装，前者不会被误导进入危险替换流程。
- [ ] 已有数据区导入时明确展示将被替换的数据摘要和风险，并使用项目统一危险操作弹窗；倒计时结束前无法确认替换。
- [ ] 已有数据区的任何破坏性写入前，系统已成功创建并验证完整本机回滚备份；备份失败时原数据不变且迁移终止。
- [ ] 系统只保留最近一份有效回滚备份且不按时间自动删除；设置中心可查看创建时间、来源和大小，并可主动恢复或经二次确认后删除。
- [ ] 下一次覆盖或恢复前先创建并验证新备份，再轮换旧备份；空间不足时阻止操作，不先删除当前有效备份。
- [ ] 导入内容在隔离位置恢复和验证后才替换有效数据；模拟任一步骤失败或进程中断时，不会留下半新半旧状态，原数据能够自动恢复。
- [ ] 导入完成后逐类展示会话、记忆、人格、设置、用户模型、API 密钥和 QQ 绑定的结果，需要用户处理的项目不会被整体成功状态掩盖。
- [ ] 当前应用版本无法理解迁移包时，在写入前阻止导入并提示升级；不尝试把新版本数据写入不兼容的旧版本。
- [ ] 系统权限、开机启动、窗口与桌宠坐标、日志、缓存、临时连接状态不会被错误地当作可直接恢复的跨设备用户资产。
- [ ] 核心导出、校验、空区恢复、已有数据替换、凭据迁移、失败回滚和备份生命周期具有自动化测试覆盖。
- [ ] 项目全量门禁通过。
