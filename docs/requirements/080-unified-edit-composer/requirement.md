# 080 · 统一编辑 Composer

> Unified Edit Composer

## 状态

CONFIRMED

## 背景

需求 035 已支持编辑并重新发送当前会话最后一条用户消息，但现有交互会在消息位置渲染第二个输入框，同时保留底部 Composer。底部 Composer 虽然仍然可见，其输入、附件、模型和语音等操作却在编辑期间被禁用，容易让用户误以为界面卡住，也让同一页面出现两个竞争输入焦点。

现有编辑框只承载文字，底部 Composer 才承载完整的发送能力。这使用户在编辑包含附件的消息、切换本轮模型或使用语音输入时遇到不一致行为，也增加了两套输入状态长期漂移的风险。

本需求把底部 Composer 收敛为对话页唯一输入源。编辑历史消息时不改变消息气泡为输入框，而是在 Composer 顶部显示明确的编辑状态，并把原消息内容回填到同一输入区域中。

## 目标

- 对话页在普通发送和编辑重发场景中始终只有一个可输入的 Composer。
- 编辑状态清楚可见，同时保持输入框、附件入口、模型选择器、语音输入和发送按钮的既有布局与操作习惯。
- 编辑稿能够完整承载原消息的文字和附件，并支持继续修改、增删附件和语音输入。
- 普通草稿与编辑稿相互隔离；取消或提交编辑后，用户原本尚未发送的普通草稿能够完整恢复。
- 编辑期间允许切换会话模型，并继续遵守会话级模型和完整 Agent run 内模型冻结语义。
- 继续复用需求 035 已确认的编辑重发、活跃历史和后续上下文语义，不引入完整的历史分支管理界面。

## 范围

### 包含

#### 单一 Composer 与编辑状态栏

- 点击当前会话最后一条可编辑用户消息的编辑入口后，消息本身保持只读展示，不在消息位置出现第二个输入框。
- 原消息位置显示轻量、只读的编辑提示，明确说明“正在编辑这条消息，请在下方输入框修改”，建立触发位置与底部 Composer 之间的空间联系。
- 点击原消息位置的编辑提示后，焦点回到底部 Composer；原消息提示不提供输入、提交或取消操作。
- 底部 Composer 进入编辑状态，并在输入框边框外、紧邻输入框上方显示一条独立状态栏；状态栏左右轻微内收、与输入框无间隙衔接但不叠压输入框，上方状态栏移除底部圆角，输入框保持原有完整圆角，明确提示用户正在编辑之前的消息。
- 状态栏提供足以识别目标消息的简短摘要，以及唯一、清晰的关闭入口；关闭状态栏即取消编辑。
- 编辑状态栏属于 Composer 的状态提示，不重排附件、模型、语音输入和发送按钮，也不在消息气泡或发送区域重复增加同等级的取消按钮。
- 进入编辑状态后，输入焦点移到底部 Composer；用户无需再次点击即可修改内容。

#### 普通草稿与编辑稿隔离

- 进入编辑前，完整保留当前会话尚未发送的普通文字草稿和附件草稿。
- 编辑稿以目标用户消息的文字和附件为初始内容，不与普通草稿混合。
- 用户取消编辑后，目标消息和当前对话不发生变化，不发起编辑重发请求，并完整恢复进入编辑前的普通草稿。
- 编辑重发请求被接受并退出编辑状态后，恢复此前普通草稿，使用户可以在本轮回复完成后继续原本尚未发送的输入。
- 编辑重发在提交前被拒绝或未被接受时，保留编辑状态和编辑稿，允许用户修正、重试或主动取消，不用重新录入内容。
- 编辑重发等待本地 Bridge 接受期间，状态栏展示持续、可感知的提交进度，例如 spinner 与“正在提交修改…”，并阻止重复提交；不得让界面停留在无反馈的禁用态。
- 编辑状态与草稿只能作用于其所属会话；切换会话、刷新或迟到的异步结果不得把一个会话的编辑稿写入另一个会话。

#### 编辑文字与附件

- 编辑稿回填目标消息的原文字与原附件；原附件在 Composer 中具有与普通附件一致的可识别展示。
- 用户可以删除原附件，也可以通过既有选择、拖放或粘贴入口添加新附件。
- 重新发送时，以编辑稿中最终保留的文字和附件集替换当前活跃视图中的原用户消息。
- 当文字为空但至少存在一个可发送附件时允许重新发送；文字和附件均为空时不可提交。
- 附件上传未完成、上传失败或与当前模型不兼容时，沿用普通 Composer 的明确反馈并阻止提交，不静默删除、替换或忽略附件。
- 取消编辑不得把编辑期间新增、删除或失败的附件状态带入此前普通草稿，也不得改变原历史消息。

#### 编辑期间的会话级模型切换

- 编辑状态下模型选择器保持可用，用户可以选择本次重新生成所使用的模型。
- 模型切换继续是会话级设置；切换成功后即成为当前会话的有效模型，即使随后取消编辑也不回滚。
- 模型切换请求进行期间给出明确状态反馈并阻止重新发送，直到切换成功或失败，避免用户误以为已经使用目标模型。
- 切换失败时保留原有效模型和完整编辑稿，并提供可操作的失败反馈。
- 若目标模型与编辑稿附件不兼容，附件继续显示，重新发送被阻止，并提示用户移除不兼容附件或切回兼容模型。
- 编辑重发请求被接受后，该完整 Agent run 冻结使用当时已确认的会话模型；运行期间继续禁止切换模型。

#### 编辑期间的语音输入

- Composer 的语音输入在编辑状态下保持可用，识别结果写入当前编辑稿，而不是普通草稿。
- 语音输入按钮、录音状态和错误反馈沿用普通 Composer 的既有交互，不增加语音通话入口或新的语音模式。
- 进入、取消或提交编辑时，尚未完成的语音识别结果不得跨越草稿边界，污染已恢复的普通草稿或其它会话。

#### 编辑重发与运行状态

- 编辑提交继续遵循需求 035 的活跃历史语义：原用户消息及其后续旧回复退出当前活跃视图，修改后的用户消息触发新的回复。
- 提交后沿用普通发送和现有编辑重发的流式展示、错误反馈与停止回答能力；用户点击停止后，在后端确认终态前持续显示“取消中”及 loading，避免无反馈的禁用或卡顿感。
- 用户主动停止属于正常的中断终态，不得显示红色错误或复用运行失败文案。取消确认后，对应 assistant 轮以中性状态提示“已停止回答”；已有部分内容时保留内容并在其下方显示提示，尚未生成内容时也保留可识别的停止状态。
- 主动停止提示属于对应 assistant 轮的持久状态；服务端会话刷新、重新打开会话或流式终态与取消请求竞态不得让提示闪现后消失。
- 模型、网络、协议或运行时异常继续使用明确的错误反馈；不得因修正主动停止语义而把真正失败降级为中性停止提示。
- 回复运行期间 Composer 的冲突操作继续按现有规则禁用并给出原因，不因统一输入框而允许并发提交或运行中切换模型。
- 刷新、重新打开会话和继续发送消息时，活跃历史、附件、有效模型及上下文与编辑后的结果保持一致。

### 不包含

- 编辑任意历史用户消息；本期仍只支持当前会话最后一条符合条件的用户消息。
- 编辑 assistant 消息、仅重新生成 assistant 回复，或同时编辑多条消息。
- 查看、切换、命名、比较或删除旧分支的历史分支管理 UI。
- 撤销编辑目标之前已经产生的工具外部副作用。
- 新增附件类型、上传渠道、模型能力或附件预览能力；编辑态复用普通 Composer 已有能力。
- 新增模型、provider、全局默认模型修改入口或单次消息临时模型；模型选择继续遵循需求 061 的会话级语义。
- 新增语音通话能力或改变现有语音输入服务。
- 重做底部 Composer 的整体视觉风格、按钮顺序或普通发送交互。
- 编辑、发送或其它对话操作的键盘快捷键；快捷键体系留待独立需求统一规划。

## 关键信息

### 与需求 035 的关系

- 保留需求 035 对可编辑消息、编辑重发、活跃历史、后续上下文、失败恢复和持久化一致性的要求。
- 本需求替代需求 035 中“消息位置切换为内联输入区”“内联编辑区单独提供取消和发送按钮”以及底部、内联两种编辑位置并存的 UI 要求。
- 需求 035 中为两种位置复用 Sender 的目标，改由“底部 Composer 是唯一输入源”实现；不再保留独立的消息内编辑 Sender。

### 与需求 061 的关系

- 保留需求 061 的会话模型持久化、切换原子性、附件兼容性、切换请求期间禁止发送，以及完整 Agent run 内模型冻结要求。
- 本需求替代需求 061 中“编辑重发期间禁用模型选择器”的要求：编辑草稿期间允许切换，编辑重发 run 被接受后仍然禁用。
- 编辑期间成功切换模型属于正常会话状态变化，不属于可随取消编辑回滚的草稿内容。

## 验收条件

- [ ] **AC-1 单一输入源与原地提示**：进入编辑状态后，消息列表中不出现可输入的内联编辑框，页面只有底部 Composer 可以输入和提交；原消息位置显示“正在编辑这条消息，请在下方输入框修改”的只读提示。
- [ ] **AC-2 编辑状态栏**：Composer 输入框边框外、紧邻输入框上方显示包含编辑提示、目标消息摘要和单一关闭入口的独立状态栏；状态栏左右轻微内收、与输入框无间隙衔接但不叠压输入框，上方状态栏没有底部圆角，输入框保持原有完整圆角；附件、模型、语音和发送按钮保持既有位置与视觉层级。
- [ ] **AC-3 内容回填与聚焦**：点击最后一条可编辑用户消息后，底部 Composer 获得焦点并回填该消息的文字和原附件；点击原消息位置的提示能够再次聚焦 Composer。
- [ ] **AC-4 取消与草稿恢复**：用户修改文字、删除原附件或新增附件后，通过状态栏关闭入口取消，原消息与对话不变、无编辑重发请求，进入编辑前的普通文字和附件草稿完整恢复。
- [ ] **AC-5 编辑附件集**：用户可以保留或删除原附件并添加新附件；重新发送后的活跃用户消息准确包含编辑稿最终的文字与附件集。文字和附件均为空时不能发送，只有附件时可以发送。
- [ ] **AC-6 附件状态与兼容性**：附件仍在上传、上传失败或与当前模型不兼容时，提交被阻止并给出明确提示；附件不会被静默删除、替换或忽略。
- [ ] **AC-7 编辑时切换模型**：编辑状态下能够成功切换会话模型，切换期间不能提交；重新发送使用已确认的新模型，取消编辑后该模型仍保持为会话有效模型。
- [ ] **AC-8 模型切换失败**：模型切换失败时保留原模型、编辑状态和完整编辑稿，并给出明确失败反馈；迟到响应不得覆盖用户最后一次有效选择。
- [ ] **AC-9 语音输入编辑稿**：编辑状态下可使用现有语音输入，识别文本只写入编辑稿；取消、提交或切换会话后，迟到的识别结果不会污染普通草稿或其它会话。
- [ ] **AC-10 提交反馈、主动停止与普通草稿恢复**：等待编辑重发请求被接受时，状态栏持续显示 spinner 与明确提交文案并阻止重复提交；请求未被接受时保留编辑稿，请求被接受并退出编辑状态后恢复此前普通草稿。用户停止新回复时，“取消中”持续到后端确认；确认后已有部分内容继续保留、无内容时仍保留对应 assistant 停止状态，并以中性“已停止回答”提示收尾，不出现红色错误且刷新后不消失。
- [ ] **AC-11 活跃历史一致性**：重新发送后，旧用户消息及后续旧回复退出当前活跃视图；刷新、重新打开和继续对话均使用编辑后的文字、附件、有效模型和上下文。
- [ ] **AC-12 状态互斥**：历史加载、回复运行、取消回答、模型切换及其它不能安全编辑或提交的状态具有正确禁用与原因提示，不出现重复提交或并发 run。
- [ ] **AC-13 会话隔离**：从编辑状态切换到其它会话再返回时，不发生编辑稿、普通草稿、附件、模型状态或异步结果串会话。
- [ ] **AC-14 回归与视觉验收**：普通发送、草稿附件、模型切换、语音输入、编辑重发和停止回答的自动化回归通过；真实桌面端确认编辑状态栏在常见窗口宽度、长消息摘要和多附件场景下不挤压或重排 Composer 既有按钮。

## 开放问题 / 待 design.md 决策

- 编辑稿与普通草稿如何分层持有，才能复用 Composer 能力并避免会话切换、提交失败和异步附件结果相互污染。
- 已发送附件如何转换为可编辑附件项，并在保留、删除和新增混合场景下表达最终附件集与资源生命周期。
- Composer 状态栏与原消息提示的摘要截断、长内容展示、焦点转移和视觉层级如何协调，并避免形成两个同等级的操作中心。
- 编辑重发请求在哪个已确认边界退出编辑状态、恢复普通草稿，以及请求失败或运行取消时如何与现有 run 状态校准。
- 语音识别、附件上传和模型切换的迟到结果如何绑定当前会话与当前草稿模式，避免跨模式写入。
