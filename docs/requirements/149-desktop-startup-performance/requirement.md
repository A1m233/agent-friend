# 149 · 启动加载时间证据采集

## 状态

CONFIRMED — 2026-10-04 用户确认收窄范围，并授权补齐采集与安装态验证。

## 背景与目标

用户反馈 Windows 安装版启动缓慢。历史日志只证明进程启动到桌宠可见约 84 秒，缺少足以归因的分段证据。此前局部 helper 校验耗时不能代替这次实际启动，也不能证明其根因。

本需求的交付目标是：每次启动自动留下可关联、可导出的加载时间线，发生慢启动时能判断主要卡在哪一段。历史观测与本次验证均保留在[证据索引](./evidence-index.md)。

## 范围

自动记录壳初始化、实例检查、设置、安装校验、WebView 构建、后端启动与身份就绪，以及聊天界面可输入的主要时间点。普通启动中的安装校验保留文件数量、读取规模和细分耗时；失败时保留部分证据。

区分窗口可见、后端就绪、界面准备好和真实操作完成。正常与失败/中断启动的记录可通过后续诊断包取回，缺失、轮转、未完成阶段如实显示。测量不改变启动顺序、完整性与身份校验，不记录会话正文、凭据和逐文件私有路径。

提供日常无需整包的源码/局部验证入口；最终由匹配制品的隔离安装态验证采集闭环。本期不承诺启动提速、优化算法、性能阈值、复现历史 84 秒、外部模型请求或 Python 内部全面细分。共享代码保持跨平台兼容，真实安装证据首先覆盖 Windows。不得覆盖 production 做故障注入。

## 验收条件

- [x] AC-1：实际启动自动产生分段时间线，各阶段可关联同一进程和构建身份；嵌套不相加，缺失不记为零。
- [x] AC-2：普通安装态启动能采到 payload metadata/read/hash 与文件/字节计数；失败可追溯部分数据，原完整性规则不退化。
- [x] AC-3：记录真实聊天页面初始化和可输入终点，与窗口可见和后端就绪分开；未完成保留缺口，不声称完成首次模型请求。
- [x] AC-4：真实隔离安装启动并导出诊断包，能恢复正常时间线和失败/中断运行的未完成阶段，消费者兼容旧包。
- [x] AC-5：证据绑定精确源码/构建/运行身份，保留原始结果、失败、覆盖范围和局限；helper、mock、源码测试与安装态结论分开。
- [x] AC-6：受影响自动化测试与项目检查通过，安装验证达到机器分类 floor；用户查看最终结果后明确要求合入主干并推送，确认验收完成。
