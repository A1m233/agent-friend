# Semantic 多对多变更图

## 状态
CONFIRMED

## 背景

普通 Semantic 当前以单条 `add` 或单条旧记忆到单条新记忆的 `supersede` 表达更新。该模型无法完整表示一条纠正同时推翻多条重复或相互重叠的旧事实，也无法表示一条宽泛事实被拆成多条更准确事实。即使连续提交多次单目标操作，也缺少共同的原子边界和完整的变更关系，可能留下部分旧事实继续生效或产生不可解释的历史谱系。

Semantic 的变化本质上不只是新增与替换，还包括在保留历史证据的前提下撤回已不再可信的事实。系统需要用统一的变更语义覆盖新增、事实撤回、修正、合并与拆分，同时避免把事实撤回与隐私意义上的遗忘混为一谈。

## 目标

- 让一次抽取能够以统一的 Semantic 变更集表达新增、事实撤回及多对多修正。
- 让同一次变更涉及的所有旧事实失效和新事实写入原子生效，不产生半完成状态。
- 保留旧事实、新事实及其变更关系，使诊断能够还原“哪些事实为何被撤回、哪些事实由此产生”。
- 让每个被撤回的旧事实和每个新写入的普通 Semantic 都带有可观察的语义理由。
- 兼容并保留现有 Semantic supersede 历史，不因数据模型升级丢失既有谱系。

## 范围

### 包含

- 将普通 Semantic 的新增、事实撤回和修正统一为同一种变更集能力：
  - 没有旧事实、产生新事实时表示新增；
  - 旧事实失效、没有确定的新事实时表示事实撤回；
  - 旧事实失效并产生新事实时表示修正；
  - 同一变更可包含任意数量的旧事实和新事实，以表达合并、拆分及其组合。
- 一个抽取结果可以包含多个彼此独立的 Semantic 变更；每个变更保留自身的语义边界和精确的新旧事实关系，不默认将所有新旧事实两两关联。
- 同一条旧事实可以参与产生多条新事实，多条旧事实也可以共同被一条或多条新事实取代。
- 每条旧事实的撤回都必须提供理由，说明为什么该事实不应继续有效。
- 每条新事实继续提供理由，说明为什么应作为普通 Semantic 保存且不属于 Core Profile。
- 整个抽取提交维持原子性；任一引用无效、不可见、已失效、跨作用域或结构不合法时，不写入部分变更。
- 变更历史可通过存储、服务接口、日志或诊断数据完整追溯，包括变更边界、新旧事实成员、理由、来源和时间。
- 迁移现有单目标 supersede 关系并保持历史查询含义。
- 使用通用化场景覆盖重复错误事实、一项纠正推翻多条事实、多条事实合并为一条、一条事实拆成多条以及只撤回不补充新事实。

### 不包含

- 隐私意义上的 forget、软删除、物理删除或数据擦除。用户要求“忘掉某事”仍由独立的遗忘能力处理，不等同于事实撤回。
- Core Profile 的字段化 `add`、`replace`、`remove` 协议；Core 继续使用字段基数与作用域约束。
- 在 Memory Inspector 中展示完整 Semantic 变更谱系。本期只保证诊断可追溯。
- 对现有普通 Semantic 做确定性语义去重、自动纠错或推测性历史修复。
- 使用特定真实账号、人物或本次问题原话作为专用规则；评测与提示示例必须保持通用。

## 关键信息

- “事实撤回”表示旧事实不再作为当前有效事实参与召回，但其历史、来源和撤回理由仍然保留。
- “修改”不得原地覆盖旧 Semantic；它由旧事实失效与新事实产生共同表达。
- 多对多指同一原子变更中可包含多个旧事实和多个新事实，并保留精确的变更边界；不要求所有旧事实与所有新事实形成无差别的笛卡尔积关系。
- Extractor 的具体输出字段、分组结构与版本协议在技术方案阶段确认，本需求只约束行为语义。
- 本需求延续现有 Core-first 抽取顺序、普通 Semantic 历史预算和严格短引用原则。

## 验收条件

- [ ] AC-1：Extractor 能在统一的 Semantic 变更模型中表达新增、只撤回旧事实以及旧事实到新事实的修正，不再依赖互不相容的单目标 `add` / `supersede` 能力边界。
- [ ] AC-2：一次变更可以原子地让多条旧 Semantic 失效并写入一条新 Semantic；所有旧事实均不再参与当前记忆召回。
- [ ] AC-3：一次变更可以原子地让一条旧 Semantic 失效并写入多条新 Semantic；历史中能够确认这些新事实属于同一次拆分。
- [ ] AC-4：一次变更可以同时包含多条旧 Semantic 和多条新 Semantic，并保留精确的变更边界；多个独立变更不会被错误合并成一个全连接关系。
- [ ] AC-5：用户否定旧事实但没有提供替代事实时，系统能够撤回旧事实且不虚构新 Semantic；该行为不会触发隐私删除。
- [ ] AC-6：每个旧事实引用都有非空撤回理由，每条新 Semantic 都有非空分类理由；缺失理由时整批拒绝且可诊断。
- [ ] AC-7：任一目标引用不可见、无效、跨作用域或提交时已失效，整个抽取提交回滚，不产生部分失效、部分新增或静默降级。
- [ ] AC-8：现有单目标 supersede 历史完成兼容迁移，旧事实、新事实、来源、有效期和已有关系均不丢失。
- [ ] AC-9：诊断信息能够还原每个 Semantic 变更的旧事实成员、新事实成员、逐项理由、来源、提交结果和失败原因；本期无需 Inspector UI 展示谱系。
- [ ] AC-10：普通自动召回和显式搜索只返回当前有效事实；历史查询仍能访问被撤回或取代的旧事实及其变更关系。
- [ ] AC-11：Core Profile 的更新语义、作用域和现有协议不受本需求影响，进入 Core 的信息不会因 Semantic 变更模型而双写。
- [ ] AC-12：机制性测试覆盖新增、撤回、一对多、多对一、多对多、重复旧事实、并发失效回滚及旧数据迁移；LLM 评测使用通用示例验证模型能够稳定输出合法且语义正确的变更。
