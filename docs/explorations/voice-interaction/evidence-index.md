## 当前综合判断

1. 当前火山 CustomLLM 已连接自己的 agent_bridge；主要供应商耦合集中在语音传输、控制和事件适配（E-001）。
2. 声网、腾讯 TRTC、阿里云 IMS、Deepgram 有自有模型接入能力；LiveKit/Pipecat 提供可控编排路径。官方能力可查，项目中的实际体验与迁移成本尚未验证（E-002）。
3. 历史记录支持曾出现约 8 秒的后端可见回答等待，但不足以证明当前 TTFT、客户端首响或上下文长度的因果贡献（E-003）。
4. 候选实践包括后台摘要、按需上下文、缓存复用、提前生成，以及把快速对话与慢任务的上下文分开。它们是待比较的方向，没有确定最优方案或 token 预算（E-004～E-009）。

## 未决问题与决策影响

| 问题 | 最有区分力的后续证据 | 当前影响 |
|---|---|---|
| 当前主要慢在何处？ | 同一轮的 endpointing、context build、模型首文本、TTS 和客户端播音时间 | 不能把历史约 8 秒全部归因给模型或上下文 |
| 裁剪能省多少 TTFT？ | 固定模型与输入任务，比较上下文体积；分开冷缓存、热缓存和推理模式 | 未批准裁剪阈值 |
| 哪些信息必须留在语音上下文？ | 连续追问、改口、取消、引用旧约定、工具执行期间插话的质量验证 | 不直接照搬固定 N 轮 |
| 是否需要快速对话 / 慢任务分层？ | 单 Agent 优化后能否兼顾首句有效回答与任务正确性 | 保留为候选，不预先增加第二模型 |
| 换供应商是否有收益？ | 使用相同 Agent 与语音输入的端到端比较 | 声网 / 腾讯 / LiveKit 为优先比较方向，不是采购决定 |
